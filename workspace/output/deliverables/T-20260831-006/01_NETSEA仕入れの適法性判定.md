## ① NETSEA で仕入れた商品を Amazon で転売してよいか

### 1-1. 会員規約本体に販路制限は無い（＝原則 OK）

バイヤー会員規約全文（`agent_output/T-20260831-005/legal/netsea_buyer_agreement_20260831.txt`、49,614字）を全文検索。

| 検索語 | ヒット |
|---|---|
| 転売 / 販路 / 再販 / 販売先 / 販売方法 / ネット販売 / 販売不可 | **0件** |
| モール | 3件（いずれも「モールクーポン」＝NETSEA自社クーポンの名称。販路の意味ではない） |

第15条は「バイヤー会員は…商品等を**購入することができます**」とだけ定め、購入後の処分に条件を付けていません。第7条（禁止事項）にも販路に関する号はありません。

> **明文が無い＝禁止されていない。** 会員規約のレベルでは、Amazon で売ることは制限されていません。
> 出典：https://www.netsea.jp/agreement/statement （2024-08-20施行／2025-04-01改訂版施行・2026-08-31 当職確認）

### 1-2. ただしサプライヤーが個別に販路制限を掛けられる。仕組みは3層ある

スーパーデリバリー第6条と同種の仕組みが、NETSEA にも**別の形で存在します**。むしろ NETSEA のほうが機械可読で扱いやすい。

#### 【第1層】商品ページの可否テーブル（○／✕ で明示）

商品詳細ページに `colAvailableInfo` という表があり、**5項目が ○ / ✕ で表示されます**。

| 表示項目 | 意味 | Amazon 販売への効き方 |
|---|---|---|
| 消費者直送 | エンドユーザーへの直送可否 | 無在庫でやるなら必須 |
| 画像転載 | サプライヤー画像の転用可否 | **✕ なら Amazon 出品画像に使えない** |
| **ネット販売** | **ネットショップでの販売可否** | **✕ なら Amazon 販売は不可** |
| ネットオークション | オークション形式での販売可否 | Amazon は該当しない（後述の注意あり） |
| 消費者向け商品説明 | 説明文の転用可否 | ✕ なら商品説明を自作する必要 |

**実測サンプル**（https://www.netsea.jp/shop/357136/4901070130801 ／ハリマ共和物産・2026-08-31 取得）：

```html
<tr><th>消費者直送</th>       <td><i class="fa-regular fa-circle"></i></td></tr>  ← ○
<tr><th>画像転載</th>         <td><i class="fa-regular fa-circle"></i></td></tr>  ← ○
<tr><th>ネット販売</th>       <td><i class="fa-regular fa-circle"></i></td></tr>  ← ○
<tr><th>ネットオークション</th><td><i class="fa-solid fa-xmark"></i></td></tr>    ← ✕
<tr><th>消費者向け商品説明</th><td><i class="fa-regular fa-circle"></i></td></tr>  ← ○
```

**このテーブルはログイン不要で読めます**（卸価格だけが会員限定）。

#### 【第2層】API のフラグ（＝タカシが機械判定できる）

第1層と同じ情報が Buyer API のレスポンスに載ります。**公式スキーマの定義**（https://api.netsea.jp/docs/buyer/schemas/items.json ／2026-08-31 取得）：

| フィールド | 公式 description | 値 |
|---|---|---|
| `deal_net_shop_flag` | ネット販売可 | `Y` 可 / `N` 不可 |
| `deal_net_auction_flag` | ネットオークション可 | `Y` 可 / `N` 不可 |
| `image_copy_flag` | 画像転載可 | `Y` 可 / `N` 不可 |
| `direct_send_flag` | 商品配送可 | `Y` 可 / `N` 不可 |
| `net_bulk_order_flag` | CSVダイレクト注文可 | `Y` 可 / `N` 不可 |

**→ 実装上の必須ガード（タカシへ）**

```
候補として採用してよい条件： deal_net_shop_flag == "Y"
Amazon 画像に流用してよい条件： image_copy_flag == "Y"
```

`deal_net_shop_flag == "N"` の商品は、**利益が出ても候補リストに載せてはいけません。**フィルタではなく除外です。

#### 【第3層】サプライヤーの自由記述「販売条件」（**API では取れない**）

商品ページには「販売条件／支払方法／送料／返品条件」というタブがあり、NETSEA 自身が
**「出展企業毎に異なりますので、必ずご確認ください」**と注記しています。

実測サンプル（同商品の「販売条件」原文・抜粋）：

> ■販売について】
> ・**直接のお取引はお断りしております。NETSEAを通してのご購入をお願いします。**
> ・**『定価販売』『売価厳守』等の記載のある商品の販売価格は記載を遵守して下さい。**

**ここに「Amazon 不可」「モール不可」が書かれうる。**そして**この自由記述テキストは API の商品スキーマに含まれていません**（`items.json` の全フィールドを確認済み。`delivery_terms`＝出荷条件はあるが、販売条件の自由記述は無い）。

> **結論：API だけで自動判定を完結させることはできません。**
> API で `deal_net_shop_flag == "Y"` に絞り、**発注前に商品ページの「販売条件」を人が読む**。この二段構えが唯一の安全な運用です。

#### 【前段の関門】取引申請の承認制

サプライヤー会員規約 第7条1項（https://supplier.netsea.jp/agreement/statement ／2026-08-31 取得）：

> 会員は、当社所定の方法で選択する**自己の取引対象バイヤーに該当しないバイヤーからは取引申請を受けることができない**ものとします。

同2項：

> 会員は、**取引申請の承諾をいつでも撤回できる**ものとします。

**→ サプライヤーは相手を選べるし、後から切れます。**「今買えている」は「明日も買える」を意味しません。**単一サプライヤー依存の SKU 構成は撤退リスクが高い。**

### 1-3. 「売価厳守」条項の扱い（当職の警告）

上記サンプルの「『定価販売』『売価厳守』等の記載のある商品の販売価格は記載を遵守して下さい」は、
売り手側から見れば**再販売価格の拘束**（独占禁止法2条9項4号・不公正な取引方法）に触れうる類型です。
ただし**当社は買い手であり、違反の主体ではありません。**当社にとっての問題は法違反ではなく実務です。

| 選択肢 | 帰結 |
|---|---|
| 従う | Amazon の価格競争でカートを取れない。値下げ不能な SKU を抱える |
| 従わない | 契約違反 → 取引申請の承諾撤回（サプライヤー規約7条2項）→ **仕入れ経路が消える** |

**→ 「売価厳守」表記のある商品は、Amazon 販売の候補から外すのが合理的です。**利益計算の前に落としてください。

## ② 第24条1項（バイヤー情報の公開）のリスク評価

### 2-1. 条文（原文）

バイヤー会員規約 第24条1項・2項：

> 1 バイヤー会員の法人の名称又は事業者の氏名、住所、電話番号、代表者及び担当者の氏名は、**ウェブサイト上で公開されます。**
> 2 バイヤー会員のNETSEAの利用履歴は、当社が定める期間、**ウェブサイト上で公開されます。**

同 第18条2項：

> 当社は、取引申請に係るサプライヤー会員に対して、取引申請に係る**バイヤー会員の情報を提供することができます。**

サプライヤー会員規約 第7条3項（裏側の対応条文）：

> 当社は、会員が取引申請を承諾した場合、**当該会員の登録情報をバイヤーに対し提供することができる**ものとします。

### 2-2. 実画面で確かめたこと（2026-08-31・非ログインで確認）

| 確認先 | 結果 |
|---|---|
| 公開のバイヤー名簿ページ | **見つからない。**サイトマップ（https://www.netsea.jp/sitemap）にバイヤー一覧に相当するページは無い（`/shop`＝サプライヤー一覧はある） |
| サプライヤーレビュー一覧（https://www.netsea.jp/shop/order_review/357136 ／79件） | 表示されるのは**業種（例：小売業・卸売業／その他）・注文日時・レビュー日時・注文商品名・過去1年間の購入回数**のみ。**事業者名・住所・電話番号は表示されていない** |
| 同上の1件 | レビュー本文に投稿者自身が「日向澤 合同会社 代表」と**自分で書いている**例あり（システムの自動表示ではない） |

### 2-3. 当職の評価

**条文（24条1項）と実装（実画面）が一致していません。**条文は「ウェブサイト上で公開」と広く書いてありますが、
不特定多数に氏名・住所を晒す実装は確認できませんでした。**実態は「取引申請したサプライヤーに対して開示される」**（18条2項）と読むのが自然です。

しかし**明文主義の立場からは、これで安心とは言えません。**

| 軸 | 評価 |
|---|---|
| 発生確率 | 中。条文は現に「公開されます」と書いてあり、NETSEA は仕様をいつでも変更できる（第2条：規約の一方的変更） |
| 影響度 | 大。自宅住所は一度出ると回収できない |
| **不可逆性** | **極大。住所の露出は取り消せない** |

> **不可逆性が極大なので、確率が中でもアラートを上げます。**「たぶん公開されていない」で放置してはいけません。

### 2-4. 対処（優先順）

| # | 対処 | 実行者 | 備考 |
|---|---|---|---|
| 1 | **現在の登録内容を実確認する**（マイページ > 登録情報変更） | **秘書カズヨ**（社長にログインの一手を依頼） | 何が入っているか分からないまま議論しても意味がない |
| 2 | 住所を**自宅以外**に変更できるか確認 | 秘書 | バーチャルオフィス／私書箱／レンタル事務所。**ただし第17条3項2号「日本国内に営業所又は居所を有しないとき」は入会拒否事由**。実体のない住所は登録事項の虚偽（第20条）にあたるおそれがあり、当職は推奨しません |
| 3 | 屋号「Satoy Select」で**事業者氏名**欄を置き換えられるか確認 | 秘書 | 24条1項は「法人の名称**又は**事業者の氏名」。個人事業主は氏名側になる可能性が高い。**屋号で代替できるかは実画面依存＝要確認** |
| 4 | 開示先が「取引申請したサプライヤーのみ」かを NETSEA サポートへ書面照会 | 秘書 →（第三者連絡＝§4.1）社長承認 | **これが唯一の確定手段。**当職の判定はここまでが限界 |

> **社長へお伝えいただきたいこと（そのまま使えます）**
> 「NETSEA の規約には『事業者の氏名・住所・電話番号はウェブサイト上で公開されます』と明記されています。
> 現に公開名簿は見当たりませんが、規約上はいつでもそうできる建て付けです。
> 個人事業主の登録住所＝自宅であれば、露出は取り消せません。
> 続ける前に、①今の登録内容の確認、②住所の変更可否、③開示先の書面確認、の3つを済ませることを推奨します。」

**なお、既に登録済みである以上、上記は「これから同意するか」ではなく「既に負っているリスクの棚卸し」です。**
判断が出るまで NETSEA の利用を止める必要はありません（停止しても既登録情報は残ります）。**退会（第26条）が唯一の遮断手段**ですが、それは仕入れ計画の全否定なので、当職は推奨しません。

## ③ 仕入れ商品の法的な注意点（転売者＝当社が負う義務）

### 3-1. 前提：NETSEA 仕入れは「輸入」ではない ＝ ここが有利

当社が NETSEA から国内サプライヤーを通じて仕入れる限り、**当社は輸入者ではありません。**
これにより、直輸入（並行輸入・中国仕入れ）で負う重い義務の大半を回避できます。

**製造物責任法 第2条3項**（「製造業者等」の定義）：
1号 業として**製造、加工又は輸入した者** / 2号 **自ら製造業者として氏名・商号・商標等を表示した者**、または製造業者と誤認させる表示をした者 / 3号 実質的な製造業者と認めうる表示をした者

> **NETSEA 品をそのまま売る限り、当社は PL 法上の「製造業者等」に当たりません。**（1号にも2号にも該当しない）
> **ただし OEM・自社ラベル貼付をした瞬間に2号で責任を負います。**③OEM 路線と混ぜないこと。
> 出典：https://hourei.net/law/406AC0000000085 （2026-08-31 確認）

### 3-2. 転売者にも義務が生じる法律（**ここが本題**）

| 法律 | 当社（非輸入・転売者）の義務 | 根拠 | 実務での効き方 |
|---|---|---|---|
| **電気用品安全法** | **PSE マーク等の表示が付されていない電気用品を、販売・販売目的で陳列してはならない**（第27条）。違反は**1年以下の拘禁刑または100万円以下の罰金**（第57条） | 電安法27条／METI「電気用品安全法の概要」 https://www.meti.go.jp/policy/consumer/seian/denan/act_outline.html | **届出は不要。ただし「マークの確認義務」は転売者にもある。**家電・PC・AV機器・照明・ACアダプタ付き商品を仕入れるなら**現物のPSE表示を必ず確認** |
| **酒税法（酒類販売業免許）** | 酒類を販売するには**酒類販売業免許**が必要。一般消費者に売るなら**一般酒類小売業免許** | 酒税法9条／NETSEA公式 https://www.netsea.jp/help/manual/liquor_purchasing.html | **NETSEA 側でゲートされている。**免許確認済みバイヤーしか酒類カテゴリを仕入れられない。公式に「仕入れた商品は、酒税法に則り、所持する免許の区分にて認められた品目、販売先に対して販売を行ってください」と明記。**免許なしなら酒類カテゴリは触らない** |

### 3-3. 古物営業法 — 「NETSEA は卸だから不要」は**正しくない**

既存メモリ `knowledge_kobutsusho_license` の判定基準（要否は「新品か」ではなく「**一度消費者の手に渡ったか**」）は正しく、
**NETSEA のサプライヤーがメーカー・卸である限り、古物商許可は不要**です。

**しかし NETSEA には中古品が実在します。**

実測（https://www.netsea.jp/search/?keyword=中古 ／2026-08-31・非ログイン）：
- **「中古」でヒット 212 件**
- 例：「**中古**vintage アクセサリーかわいい ダックスフント ブローチ コサージュ ピン」

古物営業法2条1項の「古物」＝①一度使用された物品、②**使用されない物品で使用のために取引されたもの**、③これらに幾分の手入れをしたもの。
これを**売買する営業**は許可が必要（同2条2項1号）。

> **判定：NETSEA 仕入れ一般には古物商許可は不要。ただし中古・ヴィンテージ・リユース品を1点でも扱うなら必要。**
> **運用ルール（守れば安全）：** 商品名・説明に「中古」「ヴィンテージ」「USED」「リユース」「アウトレット（返品再生品）」を含む商品は、**許可取得まで仕入れ候補から除外する。**
> 許可は手数料19,000円・審査約40日。②メーカー仕入れ・③OEM では不要ですが、**①電脳せどり・④無在庫を将来やるなら必須**です。先行取得は依然として合理的、という前回結論は維持します。

### 3-4. 並行輸入品・真贋 — 日本店が停止中の今、最も危ない論点

| リスク | 評価 |
|---|---|
| 発生確率 | 中。NETSEA には正規卸も並行輸入業者も混在する。サプライヤー名だけでは判別できない |
| 影響度 | 極大。Amazon の知財クレームは**アカウント停止**に直結 |

**具体的な危険の所在（実測）：**
サンプルで見たサプライヤー（ハリマ共和物産／19,058商品）は、**TSUBAKI・ギャツビー・ルシード・スクラビングバブル**等の**大手ブランド品**を扱っています。
これらは Amazon 上で**ブランドゲート／出品制限の対象になりやすい**カテゴリです。

**当社が取るべき防御：**

1. **請求書を必ず確保する。** ただし——

   > **【重要な落とし穴】** NETSEA からダウンロードできる納品書・請求書には、公式ヘルプに
   > **「ダウンロードできる書類は、社内管理用としてご利用ください」**と明記されています。
   > 出典：https://www.netsea.jp/help/manual/invoice.html （2026-08-31 確認）
   >
   > **→ Amazon の出品制限解除／真贋調査に提出する請求書としてそのまま通る保証はありません。**
   > 同ページは「書式や項目の変更が必要な場合は、各サプライヤーへご相談ください。**書類発行を行っていない場合もございます**ので、事前にお確かめの上お取引をお願いします」とも書いています。
   >
   > **運用ルール：ブランド品・ゲート対象商品を仕入れる前に、「サプライヤー発行の正式請求書をもらえるか」を取引申請の段階で確認する。**

3. **真贋リスクの高いカテゴリを避ける。** ブランド化粧品・ブランドアパレル・アクセサリ・キャラクターグッズ。
4. **サプライヤーレビューを読む。** 公開されており（例：https://www.netsea.jp/shop/order_review/357136 ）、ログイン不要で読めます。**発注前の一次情報として有用です。**

## ④ 未解決の論点 — API 第8条2「加工」（**グレー。原則 NO の対象**）

### 4-1. 何が問題か

API 利用規約 第8条2：

> APIユーザーは本ライセンスの使用により得た情報を**加工する場合、事前に当社に書面による承諾を得る**ものとします。

タカシが設計しているパイプライン（NETSEA の卸価格 × Keepa の相場 → 利益計算 → 候補リスト生成）は、
**文言上「加工」に読める余地があります。**「加工」の定義は規約内になく、NETSEA の公開文書にも見当たりません（2026-08-31 時点で当職が確認した範囲）。

### 4-2. 当職の判定

| 用途 | 判定 | 理由 |
|---|---|---|
| API データを**自社内**で読み、仕入れ判断のために計算する | **可と解する。**ただし断定はしない | 第2条が「APIユーザー自身の便益をはかる**商用目的**に使用することを認める」と明記。仕入れ判断は商用目的そのもの。これを禁じると API の存在意義が消える |
| 加工結果を**外部に公開・第三者提供する** | **明確に NO** | 第15条（秘密保持）・第5条3。**書面承諾なしに例外なし** |
| 加工結果を**公開 GitHub リポジトリに commit する** | **明確に NO** | 上に同じ。§5 参照 |

**グレーゾーンなので、3点セットを付します（当職の行動原則4）。**

| | |
|---|---|
| **リスクシナリオ** | NETSEA が「利益計算＝加工」と主張。第12条により**催告なく API 提供を解除**。第10条により**取得済みデータ・加工物の廃棄**を要求される |
| **発生時の対応策** | ①API 停止に耐える設計にする（キャッシュ済みデータで当面回る）②書面承諾を求める照会を先に出す（**第三者連絡＝§4.1。社長承認が必要**）③廃棄要求に応じられるよう、NETSEA 由来データを1箇所に隔離しておく |
| **撤退条件** | NETSEA から「加工にあたる」旨の通知が来たら、**その時点でパイプラインを停止**し、手動の目視仕入れに切り替える。争わない |

### 4-3. 直ちに実行すべき歯止め（タカシへ）

1. NETSEA 由来データは **`agent_output/` 配下の1ディレクトリに隔離**する（廃棄要求に1コマンドで応じられる状態）
2. **`deliverables/` に NETSEA の卸価格・商品名を出さない。**成果物に出すのは「ASIN・想定利益・仕入れ先＝NETSEA」までとし、**卸価格の生値は出さない**
3. 既存の `adapters/netsea.py` の `assert_procurement_use()` に加え、**出力先が deliverables かどうかのガード**を入れる

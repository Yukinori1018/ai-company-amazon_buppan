## Part 2: タケシ（プランナー）— 戦略立案

### Plan: 何を作るかの決定

#### 大方針

> **「副業初心者の社長が、月¥8,700 で ADD×ONE 同等以上の精度で『買うべき商品』を判断できる**ツール」**

#### 論点ごとの決定（A/B/C 採択）

| 論点 | 選択 | 理由 |
|---|---|---|
| L1: 仕入れ先 | **A（Yahoo!＋楽天のみ）** | ToS リスク回避が最優先。ヤフオク/メルカリは v0.2 以降に物理的体験から学んで判断 |
| L2: 自動巡回 | **A（なし）** | 朝野氏的「60点の行動を量産」は手動でも十分。自動化は仕入れ習慣が定着してから |
| L3: プリセット | **A（なし）** | 社長の好みが固まっていない＝プリセットの作りようがない。1件検索を磨く |
| L4: 中古対応 | **A（なし）** | 初心者は新品から。中古は判断軸が増えて学習コストが上がる |
| L5: 利益計算 | **C（FBA + 自己発送 + MSS）** | **当社最大の差別化**。物販ナレッジ１ Part3 の朝野コンサルの核心をツール化 |
| L6: デプロイ | **A（localhost）** | 1人専用なら最小構成で十分。慣れたら拡張 |

#### MVP の説明可能性

社長に「このツールは何ができますか？」と問われたら：

> 「JAN コードを1つ入れるだけで、楽天と Yahoo!ショッピングで最安値を探し、Amazon で売った時の利益を **FBA／自己発送／マーケットプレイス配送サービスの3パターン全て** で計算し、原石／要検討／除外の3段階で判定します。**他のツールは大体FBA計算しか出さないので、ここが当社の独自部分です**」

#### 撤退条件（重要）

以下のいずれかが起きたら、ツール開発は中断・撤退する：

1. **Keepa API のレート制限で実用に耐えない**（Phase 1 で実証）
2. **Yahoo!/楽天 の商品マッチング精度が < 30%**（JAN 入力でヒットしない物が大半）
3. **開発期間が予定の3倍を超えた**（Phase 1〜4 で 5セッションを予定）
4. **ハジメ ROI 試算で「半年使っても元が取れない」が確定**

撤退時の代替：Keepa 単体（€19/月）+ 手動スプレッドシート計算で運用継続。

### Do: 実行命令（タカシへ）

1. 本概要書（01_tool-overview.md）＋ 本ログ（03）＋ モック（02）を社長に見せる
2. 社長の OK が出たら Phase 1（API 接続検証）を着手
3. Phase 1 完了時点で Keepa API 課金が必要 → §4.1 該当のため社長承認を取り直す
4. 並行して、ハジメに ROI 試算、ハルオに API ToS 最終確認を発注

### Check（次セッション以降）

Phase 1 完了時に以下を Check：
- レート制限実測値
- マッチング精度実測値
- 想定通りに作れそうか / 撤退条件にかかるか

### Act（仮想）

マサル（シミュレーター）と連携して、本格実装前に「Phase 1 で何が起きうるか」のプレモーテムを1回入れる。撤退条件の磨き込み。

## Part 3: 三者統合（カズヨ・サトル・タケシ・タカシ）

### 強み（このツールが既存ツールを上回るポイント）

1. **物販ナレッジ１の朝野コンサル知見をロジック化**：FBA 一辺倒で利益判定して捨てていた商品が、自己発送 + MSS に切り替えると黒字化することを**自動で可視化**
2. **副業初心者の社長専用UI**：カズヨが社長プロファイルに合わせて文言設計可能（「これは原石です」「この商品は仕入れ基準を緩めれば狙えます」等）
3. **ToS クリーン**：朝野推奨ツール群より法務リスクが低い → 長期運用前提でアカウント停止リスクなし
4. **改修自由度**：気に入らなければ翌セッションで直せる

### 弱み（既存ツールに劣る・カバー必要）

1. **カテゴリプリセット未実装**：ADD×ONE の「宝の地図」のような探索しやすさは v0.2 以降
2. **ヤフオク・メルカリ非対応**：中古せどりの一大ソースが未カバー
3. **自動巡回なし**：仕入れチャンスを逃すリスク

### 想定アンチパターン（マサル仮想プレモーテム）

- ❌ 完璧主義で v0.1 にいろいろ詰め込む → v0.2 に回す勇気
- ❌ 朝野推奨ポイポイポケットを真似て自動スクレイピング実装 → 公式 API のみで突き通す
- ❌ Keepa の料金を抑えるため低位プランで開始 → API 機能が制限される → Power-User 一択

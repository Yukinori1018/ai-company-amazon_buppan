0. 本書の前提（最初に読んでください）

0-1. ゴールは「今すぐ売る」ではありません

Amazon 日本店（Satoy Select）は現在停止中です（T-20260826-004、ケース 21912948521 が Work in progress／2026-09-06 時点）。

「全力でカートを取りに行く」は、販売口が復活しないと物理的に実行できません。

したがって本書のゴールは 「アカウント復活までに仕込みを終える」 ことです。今できるのは次の3つです。

今できる今できない
経路の選定・観測の開始（兆しのログを貯める）出品・カート獲得・広告
仕入れ先の特定・見積り取得・取引口座の開設準備FBA 納品
大口プラン切替の準備（切替は初回FBA納品プランの直前）—

先行逃げ切りは「兆しを見つけてから在庫が FBA に着くまでの日数」で勝負が決まります。 その日数を作る作業（取引口座の開設、仕入れ先との関係づくり）は、停止中の今こそ進められます。

0-2. 適法性の現在地

2026-08-31 の法務ハルオ判定で、YouTube Data API / X API / TikTok Research API / Instagram は現時点すべて NO です（出典：workspace/output/deliverables/T-20260831-005/07_本丸経路と卸サービスの適法性判定.md §0 #5・#6-d）。理由は「Do not aggregate API Data」明記と30暦日保存制限、制裁が Google アカウント単位に及ぶこと。

ただしこの判定は「API 経由の機械的収集・保存」についてのものです。 人が画面を見る／公開ランキングを読む／公開の集計サービスを使う／RSS・検索経由で取る、が可かは未判定（ハルオへ照会中）。

本書は API を使わない経路を優先して厚く並べています。API 前提の案は F群にまとめ、現時点 NO と明記しました。

0-3. 事実と推測の分離

  • 事実 … 本書で URL と HTTP ステータスを添えたものは、2026-09-06 に当職が実際に取得して確認した値です。
  • 推測 … リードタイムの日数、仕入れ実在性の記号はすべて推測です。実測値はまだ1件もありません。社長のフィードバック「仕入れ値・送料・経費が推定で不正確＝最大のボトルネック」を踏まえ、推測は推測と明示し、Phase 2 で実測に置き換える方針です。

0-4. この分野の構造（27本を見る前の1枚）

速さと独占は両立しません。 これが本書の最大の発見です。

兆しが出た時点で商品はどこにあるか仕入れ経路リードタイム独占の余地
SNSでバズった商品既に国内小売に流通済み小売買付／既存卸短い（5〜12日）ほぼゼロ（メーカーは既に売れており、実績ゼロの新規に独占を渡す理由がない）
クラファン・展示会の商品まだ一般販売前メーカー直交渉長い（30〜180日）最大（売り方が分からないメーカーほど渡す）

社長の2つのアイデア（①地元で有名→独占、②SNSでバズり→先行逃げ切り）は、同じ探索ではなく、正反対の設計を要求します。混ぜて1本のスキームにすると、どちらも成立しません。

→ どちらを先に立てるかは戦略判断です。ここから先はタケシ（プランナー）の領分です。

記号の定義：

  • 空欄は作りません。未調査は「未調査」、該当なしは「該当なし」と書きます。

3. リードタイムの内訳（全経路共通の計算式）

先行逃げ切りの勝敗はここで決まります。 以下はすべて推測であり、実測値は1件もありません。Phase 2 で1件でも実測してください。

T = t1（検知）+ t2（商品特定・JAN確定）+ t3（仕入れ経路の確保）
  + t4（発注→着荷）+ t5（検品・ラベル）+ t6（FBA発送→受領反映）
工程小売買付既存卸メーカー直（新規）クラファン
t1 検知0〜1日0〜1日0〜1日0〜1日
t2 商品特定0〜1日0〜1日0〜1日0日
t3 経路確保0日0〜2日7〜30日（与信・口座開設）交渉次第
t4 発注→着荷1〜3日2〜5日7〜14日90〜180日
t5 検品・ラベル1〜2日1〜2日1〜2日1〜2日

合計5〜12日6〜15日19〜53日95〜188日

ここから導かれること（事実ではなく構造の指摘）

  1. t3（メーカーとの取引口座開設）が全体の最大の律速です。 そしてこれはアカウント停止中の今、先に済ませられます。 兆しが出てから口座を開こうとする設計は、先行逃げ切りとして成立しません。

#論点選択肢
1速度型（A/D群）と独占型（B/C群）のどちらを先に立てるかA: 速度型を先（実績づくり優先・利益率5%でも可という2026-08-31 の社長方針に合致）／B: 独占型を先（本丸に直結・ただし成果が出るまで2〜6ヶ月）／C: 並行（社長の時間が最大の制約）
2速度型は在庫リスクを取れるかD1（テレビ紹介）等は最短4〜8日だが、外すと在庫が丸ごと残ります。実績ゼロ・資金限定の現状で何円まで賭けられるかは経理ハジメの領分
3食品を扱うか食材は社長の関心が高いが、食品衛生法・食品表示法・FBA要期限管理（賞味期限60日／45日で販売不可）で難度が一段上がる。ハルオ判定が要る
4有料サービス（E2 セラースプライト 約13,998円/月）を契約するか§4.1（金銭）。当職は契約しません。契約前に Keepa との機能重複の実測を推奨
5人力の観測にどれだけ社長の時間を使うかA3・A10・D2 は自動化できません。社長の手がボトルネックである以上、人力経路は最大1本に絞るべき（推測・確度：中）

6. 当職の推奨（列挙の中で「まず実測すべき3本」）

戦略の順位付けではなく、「Phase 2 で数字を1本出す価値が最も高い3本」として挙げます。判断は社長とタケシへ。

順経路理由
1A7 楽天市場ランキングAPI費用ゼロ・既存App ID・最大1000位×ジャンル・自動化可能・API規約の壁が最も低い。「楽天上位1000件のうち Amazon に ASIN が無い商品は何件か」を Keepa で実測できる。この1数字が出れば、経路の価値が定量で確定します
2C1 ふるさと納税ランキング社長の「地元で有名な商品を独占」に最も直結。事業者名が公開＝到達可能。「返礼品ランキング上位100件のうち Amazon 未出品は何件か」を実測できる
3B3 クラファン終了後・一般販売移行期速度と独占のバランスが最良（30〜60日）。「支援1,000万円超の終了案件のうち Amazon に ASIN が無いものは何件か」を実測できる

3本に共通する選定理由：どれも「Keepa で ASIN 不在を実測でき、数字が1本出る」経路です。推測で語らずに済みます。

D1（テレビ紹介・最短4〜8日）を推奨に入れなかった理由は、速いが独占余地ゼロ・在庫リスク最大で、アカウント停止中の今は検証すらできないためです。復活後に単独で再評価してください。

### 3-4. 【実測④】出展社名で Keepa を引いたときの当たり方（N=26）

ギフトショー出展社から無作為抽出（seed=20260831）し、Keepa Product Search（`/search&type=product&domain=5`・10トークン/回）を実行。
**当初 N=40 で計画し、時間制約により N=26 で打ち切りました。** 生データは `03_keepa検証_ギフトショー出展社サンプル.csv`。

| 指標 | 実測 |
|---|---|
| サンプル数 | **26**（計画40・打ち切り） |
| 検索ヒット1件以上 | 12（**46.2%**） |
| ヒット0件 | 14（53.8%） |
| **`brand` または `manufacturer` が社名と一致（strict）** | **6（23.1%）** |
| 社名が海外表記（CO.,LTD／LIMITED／INC 等）のもの | 8件 → **8件すべてヒット0** |
| **社名が国内表記のもの** | 18件 → **strict一致 6件（33.3%）** |

**読み方（事実と推測を分けます）**

- 事実：**国内表記の出展社は、社名で引くだけでも3社に1社（6/18）が Amazon 上に自社ブランド商品を持っていた。**
- 事実：**海外表記の8社はすべてヒット0。** 「日本語での商談が前提」という社長条件と、Amazon不在という結果が一致しています。実測①で見た海外セクション約15%は、二重の意味で対象外。
- **この 33.3% は下限です。** 判定は「社名と brand/manufacturer の部分一致」で行っており、**社名とブランド名が違うメーカーは全部 NO に落ちています**（例：「播州織」はヒット20件だがブランドは Cottonroll／HaTaKaKe 等で NO 判定）。実際の Amazon 進出率はこれより高い。
- 推測（確度：中）：残り約2/3の中には「Amazonに出していない国内メーカー」が相当数含まれる。**相乗りではなく新規カタログ作成になる**ため、初回の1社としては 33.3% 側から選ぶのが安全。

**結論（手順への含意）：社名検索は「粗い足切り」には使えるが、「その社の商品が売れているか」の判定には使えない。**
ヒット件数は商品タイトルの部分一致であって製造元の一致ではありません（例：「播州織」20件、「ジェッカ ブロック」20件、いずれも strict NO）。
→ **検証の入力は「会社名」ではなく「ブランド名」または「JAN」。** 展示会で現物・カタログを取る意味はここにあります（§4）。

## 4. Keepa を「検証役」として使う手順

前提：**手元にあるのは「メーカー名」であって「ASIN」ではない。** 実測④のとおり、社名からのテキスト検索は当たりません。したがって手順は「識別子をどう手に入れるか」から始まります。

### ステップ0：入力の質を上げる（ここが成否を決める）

| 入力 | 入手先 | 検証の確度 |
|---|---|---|
| **JAN（EAN13）** | 展示会でもらうカタログ／卸サイトの商品ページ／メーカー公式サイトの製品ページ | **最高**（1トークンで確定） |
| ブランド名 | 出展社の公式サイト・Gift Net の商品情報 | 中（表記ゆれで落ちる） |
| 会社名のみ | 出展社リスト | **低（使えない）** |

### ステップ1：JAN がある場合（推奨）

```
GET https://api.keepa.com/product?key=<KEY>&domain=5&code=<JAN13>&stats=90
```
- `domain=5` = amazon.co.jp
- **1トークン/件**（実測）
- 返り値が空 → **Amazon にカタログが存在しない**＝新規出品（相乗りではない）になる

### ステップ2：JAN が無い場合

```
GET https://api.keepa.com/search?key=<KEY>&domain=5&type=product&term=<ブランド名>
```
- 10トークン/回
- **返ってきた商品の `brand` / `manufacturer` が対象メーカーと一致するものだけを採用する。** タイトル一致で拾うと汚染される（実測④）

### ステップ3：売れているかの判定（既存の社内基準に接続）

| 見る値 | 意味 | 注意 |
|---|---|---|
| `stats.salesRankDrops30` | 直近30日のランク下落回数＝**概算の販売個数** | 個数そのものではない。カテゴリ間比較は不可 |
| `stats.current[3]`（SALES） | 現在のカテゴリランク | **BSRは売上ではなく個数ベースの相対順位**（社内メモ `reference_keepa_reading_pitfalls`） |
| `stats.current[18]`（BUY_BOX） | 現在のカート価格 | `offers` を付けないと BuyBox/評価/レビュー数は更新されない |
| 出品者数 | 相乗り競合の数 | **`COUNT_NEW` を出品者数と誤読した事故が過去にある**（`knowledge_verify_field_semantics_not_names`）。フィールド定義まで遡ること |

### ステップ4：「仕入れられるか」を先に判定する（社長条件のゲート）

Keepa を叩く前に、次のゲートで落とすほうが安上がりです。

| ゲート | 落とす条件 |
|---|---|
| 言語 | 出展社リストの海外セクション（実測で約15%）は除外 |
| 規模 | 法人番号／gBizINFO で従業員300人超を除外 |
| カテゴリ | DVD/CD/本/ゲーム/音楽は除外（チケット確定事項） |
| 取引形態 | 「小売のみ・卸不可」と明記している先は除外 |

### 判定結果の意味づけ（3分岐）

| Keepaの結果 | 意味 | 打ち手 |
|---|---|---|
| ASIN あり・ランク動く | **売れている。相乗り or 卸交渉の対象** | 出品者数と価格推移で利益を計算 |
| ASIN あり・ランクほぼ動かない | 需要が薄い | 見送り |
| **ASIN なし** | Amazon 未展開。**競合ゼロだが需要も未証明** | 新規カタログ作成が必要。初心者には重い。楽天/Yahoo での実売を代替指標にする |

**理由（すべて実測に基づく）**

3. **相手が「新規取引先を探しに来ている」側。** 実績ゼロの個人事業主に対する門前払い確率が構造的に最も低い経路。

6. Amazon 日本店が停止中でも**この作業は一切止まらない**。停止期間を仕込みに使える。

**着手前に社長の判断が要ること（＝タケシ／カズヨへ）**

- 来場するのか、リストだけで机上に留めるのか（来場には事前登録が必要。**事前登録＝規約同意で §4.1**）
- 論点3（PDFのCSV化・保管）の法務判断
- 2,353社をどう絞るのか（＝どの軸で優先順位をつけるか）は**戦略判断であり、ここから先はタケシの領分です。** 私からは「絞る材料」として、国内/海外・小間サイズ（＝出展コスト＝企業規模の代理指標）・カテゴリの3つが出展社リストから取れることだけ申し添えます。

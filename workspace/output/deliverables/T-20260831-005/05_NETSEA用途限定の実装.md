「注意」という言葉は使っていません。**金額を書きました。**

**(b) `discover_from_netsea()` の位置づけを明記**

`discovery/pipeline.py` の関数名が `discovery`（発見）なので、一番誤読されやすい箇所です。
docstring に次を書きました。

> あれは「NETSEA 内で買う商品」を探す関数であって、「外で口説くメーカー」を探す関数ではありません。出力の使い道に注意。

法務判定でも「NETSEA 内で完結する仕入れは問題ありません」とされており、関数自体は適法です。
**危ないのは出力の行き先**なので、そこを名指ししました。

**(c) `list_suppliers()` の docstring に警告**

この戻り値だけが社名を持ちます。名簿化の入口なので、メソッド単体でも警告が読めるようにしました。

**(d) 実行時ガード（コードで止める）**

```python
PURPOSE_PROCUREMENT = "procurement"   # NETSEA 内で完結する仕入れ実務 → OK
PURPOSE_DISCOVERY   = "discovery"     # メーカー/サプライヤーの発掘 → 規約違反

class NetseaUsageError(RuntimeError): ...
def assert_procurement_use(purpose: str) -> None: ...
```

NETSEA 由来データを新しい出力先へ流す処理を書くときは、その入口で `assert_procurement_use()` を呼びます。
`"discovery"` を渡すと `NetseaUsageError` が飛んで止まります。

既存の呼び出し側は一切変えていません（引数必須化はしていない）。
**既存を壊してまで強制する価値は今はない**という判断です（YAGNI）。止めたいのは「これから書かれるコード」です。

- CI/フックには**まだ組み込んでいません**。まず手で回して有用性を確かめる段階です（組み込みは秘書経由でご相談）。

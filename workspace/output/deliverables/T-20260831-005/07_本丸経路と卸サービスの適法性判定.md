## 1-4. 判定 — 3段階に割る

`/craft/0103/` を実取得して、ページに何が載っているかを確認しました（HTTP 200）。載っているものを2つに分けます。

| ページ上の要素 | 著作物性 | 扱い |
|---|---|---|
| 工芸品名・よみがな・分類・主な製品・主要製造地域・指定年月日 | **なし（事実）** | 取得・社内保持 **可** |
| **■産地組合：組合名・〒・住所・TEL・FAX** | **なし（事実）** | 取得・社内保持 **可** |
| 「特徴」「作り方」「技術・技法・原材料」の説明文 | **あり（言語の著作物）** | **取得しない・保存しない** |
| 写真・動画・イラスト | **あり** | **取得しない・保存しない** |

### 段階1：取得して社内の候補リストに保持する → **可**

根拠：
- **抽出対象が事実であること。** 著作権法2条1項1号は著作物を「思想又は感情を創作的に表現したもの」と定義します。組合名・住所・電話番号はこれに当たりません。**事実そのものに著作権は発生しません。**
- **クロール時にページ全体が一時的に複製される点は、著作権法30条の4第2号（情報解析の用に供する場合）で足ります。** ただし同条は「**その必要と認められる限度において**」であり、ただし書で「著作権者の利益を不当に害することとなる場合は、この限りでない」と制限されます。**だから「特徴」「作り方」は保存しない**という条件が要ります。
- **編集著作物（12条）の問題も生じません。** 244品目という選択は経済産業大臣の指定（伝産法）によって決まっており、協会の選択・配列の創作性ではありません。タウンページDB事件（東京地判平12.3.17）が分類体系に創作性を認めたのとは事情が異なります。**ただし原文まで当たっていない引用であり、これは推測（確度：中）です。**

### 段階2：PUBLIC リポ・Web・外部配布に載せる → **不可**

根拠は3つ重なります。**1つでも当たれば不可です。**

| 根拠 | 内容 |
|---|---|
| 著作権法21条・23条1項 | 「特徴」「作り方」「写真」を含む形での再公開は複製権・公衆送信権の侵害 |
| サイト規約の明示 | 「複製、転用、販売することはできません」＝**著作権者が許諾していないことが明文で宣言されている** |
| **個人情報保護法27条** | **244品目の産地組合には、屋号のみの個人事業主・個人経営の工房が混じります。** その事業情報は個人情報です。PUBLIC リポへの commit は第三者提供に当たり得る |

> **本リポジトリは PUBLIC で、30分ごとに自動 push されます。** commit した瞬間に世界へ公開されます。**組合の住所・TEL を含むファイルは `deliverables/` にも `agent_output/` にも置かないでください。**

### 段階3：そこで知った組合を手がかりに、自分で一次情報を取りに行く → **可・推奨**

kougeihin.jp で「羽越しな布の産地組合が山形県鶴岡市にある」と知り、**組合の自社サイト・公式資料から改めて連絡先を取る**。この経路が最も安全です。**最終的な社内リストは、可能な限りこの経路で作った値に置き換えてください。**

## 2-2. 第14条 原文

> **第１４条（商品データ等の利用許諾の範囲）**
> １　APIユーザーは、APIを通じて取得した本商品に関するデータ（商品情報、価格、在庫等を含みます。以下「本データ」といいます。）を、**APIユーザー自身が本サービスにより本商品を仕入れ、又は販売する目的の範囲においてのみ**利用することができます。
> ２　APIユーザーは、本データを、前項の目的に必要な範囲で、**APIユーザーが運営するウェブサイト、システムその他の媒体に表示することができます。**ただし、APIユーザーは、本データを第三者に**再配布し、提供し、開示し、又は販売してはならない**ものとします。
> ３　APIユーザーは、本データを常に最新の内容に更新して利用するものとし、orosyが本サイト上の情報を変更した場合には、速やかにこれに合わせるものとします。

## 2-3. 「その他の媒体」に Amazon は入るか — **入りません。しかし経路は死にません**

### (1) 文言解釈

「**APIユーザーが運営する**ウェブサイト、システムその他の媒体」——「APIユーザーが運営する」が3語すべてに係ります。**Amazon の商品ページを運営しているのは Amazon であって当社ではありません。**

> 明文主義で読みます。「出品者だから自分の媒体だ」は、書かれていないことを都合よく補う読み方です。**採りません。**

### (2) それでも経路が成立する理由 — **設問の立て方が違います**

**問うべきは「Amazon に表示してよいか」ではなく「そもそも orosy の本データを Amazon に表示する必要があるか」です。答えは No です。**

| 出品の型 | Amazon に置くもの | orosy の本データを表示するか | 判定 |
|---|---|---|---|
| **既存 ASIN への相乗り出品**（JAN でカタログに一致） | **自分が決めた販売価格・在庫数・コンディション・SKU** のみ | **しない。** 商品名・説明・画像はすでにある Amazon カタログのもの。価格は自分の意思決定であって orosy の卸価格ではない | **第14条2項の問題が発生しない → 可** |
| **新規 ASIN を作る**（orosy の商品名・説明文・画像を使う） | orosy の商品情報そのもの | **する** | **不可。** 第14条2項（自社の媒体に限る）＋**第28条2項**（写真その他のコンテンツの複製・転載・改変・二次利用の禁止）に抵触 |

**そして orosy の掲載20万点は、JAN が付いた既製品です。相乗り出品が基本形になります。したがって「今・数を打つ」用途では第14条2項は障害になりません。**

### (3) 実装ルール（そのままエンジニアへ）

```
可：  JAN・buyer_price・retail_price・stock_qty・order_unit を社内DBに保持し、
      利益計算・仕入判断に使う（第14条1項「仕入れ、又は販売する目的の範囲」に該当）
可：  自社の管理画面・自社サイトに本データを表示する（第14条2項）
可：  JAN で Amazon カタログを引き当て、既存 ASIN に相乗り出品する
不可：orosy の商品名・説明文・スペック文・画像を Amazon の商品ページに入れる
不可：本データを PUBLIC リポに commit する（＝第14条2項ただし書「第三者に…開示」に該当）
```

> **第6条（当サイトにおける会員と出展者の関係）**

## 5. YouTube Data API `search.list` — **NO**

### 5-1. 決定的な条文2つ（`https://developers.google.com/youtube/terms/developer-policies`・最終更新 2026-06-24）

**(1) データ集約の禁止（III.E）**

> **Data Aggregation**
> **Do not aggregate API Data** except that you may only aggregate API Data relating to YouTube channels that are under the same content owner as recognized by YouTube pursuant to content licensing agreement(s) between YouTube and such content owner. Such aggregated API Data must only be viewable by that content owner.

**「複数チャンネルの情報を集めて一覧にする」——これがまさに aggregate です。** 例外は「同一コンテンツオーナー配下のチャンネル」に限られ、当社は該当しません。**「EC が弱いメーカーを探すために数千チャンネルを集めてリスト化する」は、文言上この禁止に真正面から当たります。**

**(2) 非認可データの保存は30暦日まで（III.E.4.d）**

> API Clients may temporarily store limited amounts of **Non-Authorized Data** for as long as is necessary for the purposes of the API Client but **not longer than 30 calendar days.** … after 30 calendar days, the API Client must either **delete or refresh** the stored data.
> （同 c）**an API Client must not store statistics retrieved as Non-Authorized Data for more than 30 days.** For example, an API Client must not store the subscriber count for a YouTube channel for more than 30 days without authorization from the channel owner.

OAuth なしで `search.list` / `channels.list` から取るチャンネル名・概要欄・登録者数は、すべて **Non-Authorized Data** です。**永続的な候補リストとして保持することは規約違反です。**

**(3) スクレイピング禁止（III.E）**

> **Scraping**
> You and your API Clients must not … directly or indirectly, **scrape YouTube Applications or Google Applications, or obtain scraped YouTube data or content.**

**API を使わずに YouTube を直接スクレイピングする代替案も、同時に潰れています。**

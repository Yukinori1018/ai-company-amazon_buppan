## 6. 窓口の採取（14 残作業3・4／サトル・2026-10-05〜）

各社の公式サイトから、電話・問い合わせフォーム・公表メール・「営業お断り」等の記載を採っています。**社名と連絡先はシート『メーカー連絡先台帳_Amazon物販事業』の「名簿拡張_窓口」タブ（非公開）にだけ書き、この文書には件数だけを書きます**（13 §3-1）。「名簿拡張」タブの「窓口」列には判定の要約が入ります（14b が作り直しても `15_contacts/contacts_*.csv` から戻すよう 14b に1関数を足しました）。

**やり方（13 §3 の守り方）**

| 条件 | 守り方 |
|---|---|
| 連絡先は各社の公式サイトから | 公式サイトの会社概要・特商法・問い合わせ・取引案内ページだけを取得（1社最大9ページ）。展示会・DB・検索結果の要約に出た値は転記しない |
| 公表アドレスのみ／「広告メールお断り」併記はメールに回さない | 自社サイトに載ったアドレスだけを採る。「営業・勧誘・売り込みお断り」等の原文を列に残し、該当社はメール可否を「×（フォームか電話へ）」にする |
| RX の詳細ページは巡回しない | RX のサイトには一度もアクセスしていない。公式サイトの特定は gBizINFO の登録URL → ドメイン推測（トップに社名があるかで検証）→ Web 検索（1社1回まで）の順 |
| 名簿を PUBLIC リポに置かない | 作業ファイルは `agent_output/T-20260929-001/15_contacts/`（Git 管理外）。リポにはこの件数欄だけ |
| 連絡しない | 送信・フォーム投稿・電話は一切していない |

**判定の意味**：「窓口あり」＝電話・フォーム・公表メールのどれかが公式サイトで取れた／「紐付け要確認」＝同名複数から推測で選んだ・短い社名で一致しただけ等／「要目視」＝公式は当たったが連絡先を機械で抽出できなかった（JS 描画など）／「公式未特定」＝推定ドメインと検索1回で当たらなかった。

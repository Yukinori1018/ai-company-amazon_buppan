## 選び方ガイドのグレードアップ（2026-08-26）

社長ご指示「アニメーションや動画を使って選び方ガイドをグレードアップして下さい」への回答。
**入れたのは「読んで分かりにくいことを、見れば分かるようにするもの」だけです。** 飾りの動きは入れていません。

### まな板の記事

1. **解説動画（13秒・音声なし・92KB）** — 記事が「最も多い失敗」と書いている「調理台を測らずに買う」を動画化。測る2か所 → 大きすぎるとどうなるか → 奥行き−5cm で収まる、の順。
   **実写素材は使っていません。**ブランド色だけで図版から自動生成しました（`scripts` は使い捨てのため同梱していません。再生成が必要なら作り直します）。
2. **刃あたりの実演** — 素材のタブを切り替えると、包丁の沈み込み・刃に返る衝撃・傷の残り方が変わります。**比較表の該当列も同時にハイライト**されます。
   沈み込みの量は記事の「硬め／やわらかい」を可視化した模式図で、**実測値ではない旨をページに明記**しています。
3. **吸水の実演** — 4素材に水滴を落とすと、木だけが吸い込み、他ははじきます。

### 詰め替えボトルの記事

1. **中身×材質の相性マトリクス** — 入れるものを選ぶと、4材質の可否が切り替わります。
   **記事に書かれていない組み合わせは「—」にして、推測で埋めていません**（その旨もページに明記）。
2. **ポンプ4形式の実演** — プッシュ／泡／スプレー／ワンタッチの「出かた」を並べて比較。

### 全記事共通

- 読み進みバー（金の細線）／目次のスクロールスパイ／`<details>` の FAQ
- **アニメーションは画面内にあるときだけ動かす**（電池とCPUを無駄に使わない）
- **`prefers-reduced-motion: reduce` では自動再生しない。**ただし「▶ 再生」ボタンで自分で動かせる
- **止めていても素材差が分かる**（刃は沈み込んだ位置で静止する）。動きが見えない人にも情報が届く
- **JS が動かなくても、表と文章で内容はすべて読める**

## お問い合わせフォームの仕組み（2026-08-26 追記）

**公開版のフォームは Google フォーム方式で、すでに稼働しています。**（2026-08-23 に着弾確認済み／T-20260817-006）

見た目は当サイトの自前デザインのまま、`<form action="https://docs.google.com/forms/d/e/{FORM_ID}/formResponse" method="POST" target="formSink">` で
Google フォームへ直接 POST する構成です。`fill.py` が公開フォームの HTML から項目ID（`entry.xxxxx`）を自動で読み取って埋め込みます。
送信は非表示 iframe が受け取るため画面遷移が起きず、読み込み完了を合図に「送信しました」に差し替わります。
項目IDが読めなかった場合は Google フォームの iframe 埋め込みへ自動でフォールバックします。

**モックのフォームも、同じ送信先・同じ項目IDに接続しました。** つまりお試し送信も本番のお問い合わせと同じ場所に届きます。
テストと分かるよう、お名前欄に「テスト」と入れてください。

> ⚠️ **注意**: この Google フォームの送信先URLは、すでに公開リポジトリ内のファイル
> （`workspace/tickets/done/T-20260817-006_shiire-credibility-prep.md`）に平文で入っています。
> 公開サイトの HTML にも出ているため新たな漏えいではありませんが、**GitHub を巡回するスパムの標的になりやすい**ため、

## 本番グレードアップに転用できる知見（この実験の本体）

社長ご指示の目的は「AI で高品質な HP を作れるかの検証」。**以下がこの回で確かめられた再現可能な知見。**

### 1. 「AIで量産した感」の正体は3つしかない

実験前後を比べると、素人臭さは装飾の不足ではなく**この3点**から出ていた。逆に言えば、この3つを外すだけで印象は変わる。

1. **純白 `#FFFFFF` の地色。** ブラウザ既定色そのままは「未設定」に見える。`#FAF8F4` 程度の温かい紙色にするだけで印刷物の質感が出る
2. **OS 標準ゴシックのみ。** 日本語サイトは書体で9割決まる。**見出しを明朝にするのが最も費用対効果が高い**（Zen Old Mincho は Google Fonts で無料）
3. **カードの均等並べ。** 全要素が同じ大きさの箱に入っていると情報の軽重が消え、テンプレートに見える。**セクション番号＋罫線の誌面型**に変えると階層が立つ

### 2. 金（アクセント色）は「面」で使うと安くなる

現行版は金をボタンや見出しに面で使っていた。**面で使う金はメッキに見える。**
v1 では金をヘアライン・下線・セクション番号に限定し、面で使うのは CTA ボタン1つだけにした。**使用面積を減らすほど高く見える**という逆説。

### 3. 余白は「量」ではなく「可変」で設計する

固定 px の余白は、スマホで詰まりすぎ・PC で間延びする。`clamp(72px, 10vw, 132px)` のように**画面幅に連動させる**。
「デザインに投資している感」の実体は、装飾ではなく**余白の総量**。

### 4. 写真は1枚で実在感が決まる

イラストとプレースホルダだけのページは、どれだけ整えても「まだ作っている途中の何か」に見える。
**写真を1枚入れた瞬間に「実在する会社」に変わる。** 選定基準は [CREDITS.md](CREDITS.md) に4条件で明文化した（低彩度・他社ロゴなし・CG不可・人物顔なし）。

### 5. 動きは「足す」より「削る」

入れたのは「画面に入ったら一度だけフェードイン」だけ。パララックス・スクロール追従は入れていない。
**B2B サイトで動きが多いのは、信用のマイナス**（読ませたい情報が読めなくなる）。`prefers-reduced-motion` の尊重は実装コスト数行。

### 6. 作業手順として効いたこと

- **公開版を1バイトも触らずに別ディレクトリで作る。** 「戻せる」保証があるから思い切った変更ができる（今回 git diff で無変更を証明した）
- **文章を先に確定させ、見た目は後。** コピーが決まっていない状態で装飾を始めると、必ず作り直しになる
- **3幅（375/768/1440）で必ず実機確認する。** 今回、縦位置写真をモバイルで横長に潰して主題が切れる不具合を1件、グリッドの自動配置ミスを1件、この確認で潰した

### 7. アニメーションは「装飾」ではなく「説明」に使うと効く

今回入れた動きは、どれも**文章では伝わりにくい差**を扱っている（刃の沈み込み／水の吸い方／中身と材質の可否）。
逆に、スクロールで要素が飛んでくるような装飾は1つも入れていない。B2B の信用が目的なら、**動きの数ではなく「その動きが何を説明しているか」**で判断する。

実装上の3原則:
- **画面外では止める。** IntersectionObserver で `run` クラスを付け外しするだけ
- **止まっていても情報が残る形にする。** 静止状態が「結果」を示していれば、動きが見えない人にも届く
- **`prefers-reduced-motion` は「無効化」でなく「自動再生しない」に。**手動の再生ボタンを残すと、見たい人は見られる

### 8. 動画は「実写がなくても」作れる

実写素材ゼロで、図版から13秒の解説動画を生成した（ブランド色のみ・音声なし・92KB）。
**Web の説明動画に必要なのは撮影ではなく「動きで示すべき情報があるか」**。
ただし商品そのものの質感・大きさ・手触りは実写でしか伝わらないので、**両方を使い分ける**のが正解。

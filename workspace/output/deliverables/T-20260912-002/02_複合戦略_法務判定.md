### 1-2. H2 卸（NETSEA）の請求書で Amazon のブランドゲートを解除 — 条件付き可

問い：サプライヤー発行の請求書を Amazon に提出する行為は「サプライヤー情報の第三者提供」に当たるか。

当たりません。理由は3つ。

1. 請求書は、サプライヤーが当社との売買のために当社宛に発行した取引書類です。買主が自分の仕入れを第三者に証明するために使うのは、書類の通常の用途です。会員規約7条2項3号「利用者の権利の行使の範囲を超えて、本サービスの情報を利用すること」の「本サービスの情報」は NETSEA が提供する情報（商品・卸価格・サプライヤー一覧等）を指し、サプライヤー自身が当社に交付した書類は含みません。
2. 7条1項3号「本サービスを利用する他の者の情報の収集を目的とする行為」にも当たりません。目的は自社の仕入れ証明であり、サプライヤー情報の収集ではありません（9/12 判定と同じ）。
3. API 利用規約15条1項の秘密保持は「本規約において提供された相手方の一切の情報」が対象で、API 経由で取得した情報の話です。請求書は API で取得しません。

条件（9/12 判定 `T-20260912-001/04` の手順をそのまま適用）：
- 依頼は NETSEA の「問合せ」機能内で行う（7条2項5号）。外で頼めば書類目的でも違反。
- 依頼文に用途（Amazon 出品申請の仕入れ証明）を書く。サプライヤーが用途を知って発行すれば、第三者提供の議論は消える。
- 掛け払いを選ばない（GMO が請求書を出すので卸の請求書にならない）。カードか振込。
- PDF は無加工で提出する。数量・日付の変更依頼は私文書偽造・Amazon の即時停止。
- 10点以上・180日以内・購入者名と住所の記載（`knowledge_listing_restrictions_ungating`）。ダウンロード納品書は「社内管理用」なので使わない。

Amazon 側の注意：受理は Amazon の裁量で、法律論では決まりません。「卸の請求書なら通る」と保証はできません。虚偽書類の提出だけが致命傷です。

§4.1：問合せの送信＝第三者連絡。ゲート申請の提出＝Amazon 側への書き込み（当職の暫定運用で社長が実施）。

### 1-6. A1 非食品セット組み（独自 JAN・新規 ASIN） — 条件付き可

| 論点 | 判定 | 根拠・条件 |
|---|---|---|
| 真正品を組み合わせて1つの商品として売る | 可 | 適法に仕入れた真正品の再販売に商標権は及ばない（消尽。国内流通品についての確立した解釈。判例原文は未確認・確度中）。商品名に各メーカー名を記載するのは出所の説明であって自社商標としての使用ではない |
| セットの名称・パッケージ | 条件 | メーカー公式セットと誤認させない（不競法2条1項1号・商標法37条1号）。メーカーの商品画像・説明文を無断で使わない（著作権法21条・23条）。自分で撮影する |

### 1-7. SP-API 開発者登録 — 条件付き可（登録可・実装前の整備が条件）

### 2-2. YouTube Data API「30日以内・非集約」— NO を維持。RSS も不可

- Developer Policies III.E「Do not aggregate API Data except … under the same content owner」。複数チャンネルを1枚の表にする行為は文言上 aggregate。狭く読む余地はあるが、グレーは NO。
- 「1チャンネルずつ照会して30日以内に削除」は III.E.4 の文言に沿う。だがそれは人が画面を見るのと同じ価値しかなく、III.D（認証停止後の新規 Google アカウントによる回避も禁止）で Google アカウントを賭ける。成果物カタログ（Drive）が乗るアカウントを賭ける合理性がない。
- チャンネル RSS（`/feeds/videos.xml`）：`https://www.youtube.com/robots.txt` の `User-agent: *` ブロックに `Disallow: /feeds/videos.xml`（2026-09-13 取得）。YouTube 利用規約は robots.txt に従う公開検索エンジン以外の自動化手段を禁じている。RSS リーダーによる定期取得は自動化された手段。サトル③ 2-F の「RSS は Data API 外で可」は誤りとして訂正します。
- 残る使い方：人が YouTube の画面を見る（9/6 判定のまま可）。

### 2-3. 楽天ウェブサービス API（アフィリエイト目的）— 不可を維持

- 3条：アフィリエイト報酬を得る目的で使うなら楽天アフィリエイト経由でリンクを作り、パートナー規約に従う。これは「アフィリエイト目的なら使ってよい」という許諾。
- 10条1項(4)「To gain income by using the Web Services in ways other than Rakuten Affiliate」、(6)「To provide services using Web Services that competes or may compete against the Group」、(7)「Regarding the information obtained through the Web Services … using them for purposes other than those determined separately by the Company」、(9) 不特定多数と共有できる場所への保存。
- サトル③ 2-I は「見て知ったことを別の商売に使うことまで縛るかは文言から一義に決まらない」とするが、(7) は「取得した情報の目的外使用」を明文で禁じています。楽天のランキング API で得た情報を Amazon 仕入れの判断に使う行為は、アフィリエイトを実運用していても (7) の目的外使用であり、その結果 Amazon で収益を得れば (4) にも当たる。決まります。
- 残る使い方：人が楽天市場の画面を見る（可）。Nint 等の推計サービス（規約未読・要判定）。
- 既存の `rakuten_shopping.py`・`yahoo_shopping.py` は停止推奨のまま（9/6 判定 §V）。

### 2-4. Google トレンド CSV の PUBLIC 可否 — 条件付き可に変更

- 公式ヘルプ「トレンドのデータのエクスポート、埋め込み、引用を行う」（2026-09-13 取得）：「Google トレンドの情報の使用には、Google 利用規約が適用されます。Google トレンドのデータを再利用する場合は、情報が Google に帰属することを引用によって示してください。例：…『データソース: Google トレンド（https://www.google.com/trends）』を追加します」。
- Google 利用規約（2026-09-13 取得）：「ユーザーは Google のコンテンツを本規約およびサービス固有の追加規約で許可される範囲内で使用できます」。ヘルプは規約ではないが、Google 自身が再利用の条件を示した文書であり、これに従う再公開を後から違反と主張することはできない（矛盾行為の禁止）。
- 9/6 判定「再公開の許諾を確認できず→社内限定」は、この文書で解消。条件付き可に変更します。

## 3. #31「NO のまま使う」を社長判断に残す場合の整理

推奨も禁止もしません。判定は「規約違反か」と「実害」を分けます。発生確率はすべて推測です。

| 経路 | 規約違反か | 実害の型 | 制裁の単位 | 不可逆性 | ID 分離 |
|---|---|---|---|---|---|
| Amazon 公開ページの自動取得 | 違反（利用規約 643006・BSA §3） | 出品アカウント停止・売上金留保。関連アカウントへ波及 | Amazon 出品アカウント | 極大（事業の全損。9/12 まで停止していた前歴） | 不可能（出品者として紐づく） |

| X スクレイピング | 違反（ToS「in any form, for any purpose」） | X アカウント停止 | X アカウント | 低 | 可 |
| Instagram／TikTok スクレイピング | 違反（robots.txt 宣言・ToS §5） | アカウント停止 | 各 SNS アカウント | 低 | 可 |
| ふるさとチョイス自動取得 | 違反（12条1項(12)） | 差止・損害賠償 | サイト ID | 低 | 可 |
| 楽天 API を Amazon 仕入れ目的で | 違反（10条1項(4)(7)） | App ID 停止・楽天会員 ID 制裁 | 楽天 ID | 中 | 可（楽天は当社の販路でない） |
| Yahoo! サイトの自動取得 | 違反（共通利用規約 §14） | 差止＋「得た利益相当額を請求する権利」 | Yahoo! ID＋金銭 | 中（金銭請求は ID を分けても消えない） | ID は可・金銭は不可 |

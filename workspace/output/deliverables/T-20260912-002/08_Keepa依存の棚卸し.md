# 08 Keepa 依存の棚卸し（タカシ・2026-09-14）

論点③「Keepa を必要な月だけの API にする（10/4 の更新前に解約）」の判断材料です。解約・停止は何も実行していません。

## 結論

- Keepa API を呼ぶ社内ツールは、用途で束ねると10系統あります（うち1系統は取得済みデータを読むだけ）。定常ジョブは list-builder の1本だけで、8/31 から STOP で止まっています。
- 今日の消費は0です（2026-09-14 10:06 実測：残高 1,200/1,200・消費 0・補充 20/分・トラッキングによる減速 0）。
- 解約しても、自動で壊れるものはありません。困るのは手動の3つです。出品当日のカート価格での再計算、打診先メーカーの Amazon 検証、需要先行スキャン（T-1 型）。
- 10/3 までに済ませる抽出（T-3・S-3）は合計 約1.4万〜2.2万 token、20/分で約12〜18時間です。残り19日の供給（約55万 token）の4%以下なので、間に合います。
- 公式の仕様では、解約しても支払済みの期間の終わりまで API は動きます（[plans-tokens](https://keepa.com/api-docs/plans-tokens.html)）。早めに解約しても 10/3 までの抽出は削られません。期間が切れた後は再開できず、使うときは新規契約になります。

## 4. 10/3 までに済ませる抽出の見積り

| 抽出 | 中身 | token | 所要時間（20/分・初めの1,200を含む） | 期限 |
|---|---|---|---|---|
| T-3（タカシ） | T-1 の打診母数 1,394 ASIN に product＋`buybox=1`（3 token/ASIN）。ブランドストアは product の `brandStoreName` で取れる（api-docs で確認。1,000ページの閲覧は要らない）。カートを持つ出品者の名前は seller（1 token/ID・重複を除いて最大700と推測） | 約4,200＋最大700＝約4,900 | 約3時間 | 9/21 |
| S-3（サトル） | 展示会の残り952社に `/search` を1回ずつ（10 token/社。T-20260906-005 の実測で 249→239） | 9,520 | 約7時間（夜1晩） | 9/28 |
| S-3 の追加（任意） | 実在した社（推測 約340社）に #2 と同じ検証（約21 token/社） | 約7,100 | 約6時間 | 9/28 |
| 合計 | | 約1.4万〜2.2万 | 約12〜18時間 | |

- T-3 の見積りは、タケシの置き値（0〜1,400）より多くなります。カートの持ち主の履歴を取る `buybox=1` が +2 token/ASIN かかるためです。
- 供給は、9/14〜10/3 の19日で約55万 token（28,800/日）です。今は誰も使っていません。
- 間に合います。制約は token ではなく、Mac が起きているか・誰が走らせるかです。2本を同時に走らせると同じ残高を取り合うので、順番に走らせます。
- 余った 50万 token 超で、ほかに取っておくものがあるかは戦略側の判断です（例：T-1 の子 ASIN 約7,000件＝約7,000 token、第2の展示会名簿の検証）。期間が切れると、新規契約でしか取れません。

## 5. 社長の判断に添える事実

- 解約はダッシュボードからいつでもでき、支払済みの期間（9/4〜10/4）の終わりまで使えます（公式）。終わる時刻までは確認していないので、抽出は 10/2 までに終える前提にします。
- 解約を忘れると、10/4 に €49 が自動で引き落とされます。
- 期間が切れた後は再開できず、補給月は新規契約です（プランと料金はその時点のもの）。
- 解約と `launchctl` の操作は、§4.1 と常設設定の変更に当たります。タカシは実行していません。

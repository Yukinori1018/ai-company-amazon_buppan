1-2. H2 卸（NETSEA）の請求書で Amazon のブランドゲートを解除 — 条件付き可

問い：サプライヤー発行の請求書を Amazon に提出する行為は「サプライヤー情報の第三者提供」に当たるか。

当たりません。理由は3つ。

  1. 請求書は、サプライヤーが当社との売買のために当社宛に発行した取引書類です。買主が自分の仕入れを第三者に証明するために使うのは、書類の通常の用途です。会員規約7条2項3号「利用者の権利の行使の範囲を超えて、本サービスの情報を利用すること」の「本サービスの情報」は NETSEA が提供する情報（商品・卸価格・サプライヤー一覧等）を指し、サプライヤー自身が当社に交付した書類は含みません。
  2. 7条1項3号「本サービスを利用する他の者の情報の収集を目的とする行為」にも当たりません。目的は自社の仕入れ証明であり、サプライヤー情報の収集ではありません（9/12 判定と同じ）。
  3. API 利用規約15条1項の秘密保持は「本規約において提供された相手方の一切の情報」が対象で、API 経由で取得した情報の話です。請求書は API で取得しません。

条件（9/12 判定 T-20260912-001/04 の手順をそのまま適用）：

  • 依頼は NETSEA の「問合せ」機能内で行う（7条2項5号）。外で頼めば書類目的でも違反。
  • 依頼文に用途（Amazon 出品申請の仕入れ証明）を書く。サプライヤーが用途を知って発行すれば、第三者提供の議論は消える。
  • 掛け払いを選ばない（GMO が請求書を出すので卸の請求書にならない）。カードか振込。
  • PDF は無加工で提出する。数量・日付の変更依頼は私文書偽造・Amazon の即時停止。
  • 10点以上・180日以内・購入者名と住所の記載（knowledge_listing_restrictions_ungating）。ダウンロード納品書は「社内管理用」なので使わない。

Amazon 側の注意：受理は Amazon の裁量で、法律論では決まりません。「卸の請求書なら通る」と保証はできません。虚偽書類の提出だけが致命傷です。

§4.1：問合せの送信＝第三者連絡。ゲート申請の提出＝Amazon 側への書き込み（当職の暫定運用で社長が実施）。

一次：AUP・DPP はセラーセントラルの静的ページで取得できました（sellercentral.amazon.com/mws/static/policy?documentType=AUP|DPP&locale=en_US。ログイン不要）。developer-docs は当職には 403。登録要件はサトル取得の一次を引きます。

論点判定根拠
当社の用途（自社出品の価格・出品者数・ゲート・手数料の取得）範囲内AUP 1.1「Use the Amazon Services API only to perform acceptable Amazon activities, and only for Authorized Users who have authorized you」。Private developer は自分が Authorized User。getItemOffers・getListingsRestrictions・getMyFeesEstimate は Amazon が出品者向けに用意した機能
PUBLIC リポに生データ不可AUP 4.6「Do not disclose Information, individually labelled or aggregated, to … any outside parties」。Information の定義は「any information that is exposed through the Amazon Services API, Amazon Portals or Amazon's public-facing websites. This data can be public or non-public」＝公開情報でも対象
PUBLIC リポに集計値・派生物不可同 4.6 の「or aggregated」が明文。Keepa と違い「統計なら白」が使えない。当社の判断結果（選んだ ASIN・自分の価格）は当社の意思決定であり Information ではないが、ASIN の羅列は Keepa 判定と同じしきい値運用（20件）に揃える
Amazon の事業に関する洞察不可AUP 4.5「Do not promote, publish or share insights about Amazon's business. Do not use insights about Amazon's business for your own business purposes」。当社が Amazon 全体の傾向を成果物に書く行為が当たり得る。個別 ASIN の価格・出品者数は「Amazon's business」ではない（当職の読み・確度中）
DPP §1 の安全管理義務全部かかるDPP は「all systems that store, process, or otherwise handle data vended and retrieved from the Amazon Services API」に適用。§1（PII 不問）：ネットワーク保護・端末保護（15分ロック・個人端末制限）・アクセス権の四半期レビュー・MFA・12文字以上のパスワード方針・API キーの暗号化と年次ローテーション・TLS1.2・リスク評価の年次見直し・インシデント対応計画（半年ごと見直し・24時間以内に security@amazon.com へ通知）・30日以内の削除・データ出所のタグ付け。§3：12ヶ月の記録保存と Amazon の監査権
PII申請しないRestricted roles（PII）を申請しなければ §2（暗号化・DLP・年次ペネトレーションテスト・地理的に分離したバックアップ）はかからない。当社の用途に PII は不要
違反時の制裁API アクセスの停止・終了AUP 冒頭「Failure to comply with this AUP may result in suspension or termination of Amazon Services API access in accordance with the Solution Provider Portal Agreement」。出品アカウントへの波及は AUP・DPP に明文なし。SPPA 本文は未取得（§4）
AI での処理未確認BSA 4.2（二次：Amazon の素材で AI/ML モデルを開発・改善することの禁止）。取得データを Claude に読ませて判断させる行為が「モデルの開発・改善」に当たるかは一次未取得で判定できない。AUP 2.4 は AI 利用の明示を求める

判定：登録は §4.1（規約同意3本）で社長の一手。同意する前に、IT にDPP §1 を満たす最小構成（MFA・ディスク暗号化・鍵はキーチェーン・専用 DB・アクセス記録・削除手順の1枚）を作らせること。「登録だけ先に」は、同意した瞬間から DPP §1 の義務を負うので、「実装は後」でも整備は先です。

代替（登録しない場合）：ゲート判定は目視、手数料は料金シミュレーター、価格・出品者数は Keepa。失うのは公式値の精度と自動化だけ。

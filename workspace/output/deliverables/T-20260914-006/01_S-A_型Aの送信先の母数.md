## 1. 条件と件数（Product Finder・domain=5）

型A の3基準（EC STARs 実践者の選び方）: Amazon 本体が売っていない（`current_AMAZON=-1`）・FBA の出品者2以上（`offerCountFBA≥2`）・売れ筋ランク5万位以内（`current_SALES≤50000`）。T-1 と同じくメディア13ルートとアダルトを除く。

| 条件 | ASIN |
|---|---:|
| 本体なし・ランク5万以内（メディア除外） | 546万 |
| ＋規制3（ドラッグ・ビューティー・食品）除外 | 493万 |
| 　＋新品オファー2以上（参考） | 63.1万 |
| 　＋**FBA オファー2以上＝3基準** | **7.69万** |
| 　　└ うち単品（バリエーションなし） | 2.29万 |
| 　　└ うち2,000〜8,000円（T-1 の価格帯・参考） | 3.12万 |
| 3基準で規制3を戻した場合 | 9.59万 |

- Finder の件数は近似（百の位で丸め）。桁として読む。
- ランク5万以内でも ASIN が数百万あるのは、バリエーションの子が親のランクを共有するため（単品だけなら上限 31ルート×5万）。
- `offerCountFBA` は公式の定義で「FBA オファーの本数」（`product-finder.html`）。出品者数ではない（同じ出品者が複数出すことは FBA では稀＝推測）。
- `offerCountFBA_gte=100000` で0件になり、フィルタが効いていることを確かめた（綴り違いは無視されるため）。
- `offerCountFBA` の値がある ASIN は 493万中 493万（`_gte=0`）。値の欠けによる取りこぼしではない。FBA 1以上は168万。ただし各 ASIN の値がいつ時点かは確かめていない。

## 3. 標本の取り方と推定の方法

| 項目 | 内容 |
|---|---|
| 標本 | 一覧 75,574 ASIN からルート別の比例配分で 2,499件（乱数固定 seed=20260916） |
| 取得 | product（`offers` なし・1 token/件）。手元の raw でブランドストアまで分かる47件は取り直さない |
| 区分 | T-1 と同じ関数（`t1_classify.row` の区分＝国内/海外ブランド/中国系OEM/同疑い/代理店/ブランド不明/版元、大手＝gBiz L1/L2 または既知リスト） |
| ストア | `brandStoreName` の空/非空（T-3 で S-1 の目視と 25/25 一致） |
| メーカー単位 | 1本でもストアありならストアあり（ブランド登録は社でするため） |

メーカー数は ASIN 数に比例しない（同じ社の ASIN が標本に何本も入る）。そこで2通りで幅を出す。

- 上限＝標本の社数 × 一覧 ÷ 標本（ASIN に比例。社の重なりを無視するので多めに出る）
- 推定＝標本を 1/4・1/2・全部と間引いて社数の伸び方を測り、その伸び率のまま一覧の大きさまで延ばす（伸びが鈍る分だけ少なく出る）

## 6. 注意と、母数を足すなら

| 注意 | 向き |
|---|---|
| k はブランド名の完全一致で数えた。1社が複数ブランドを持つと社数を多めに、表記揺れがあると k を少なめ＝社数を多めに見る | 多め |
| 目視は部分標本の100件だけ。区分関数の漏れ（大手リストに無い大手・日本語名義の海外ブランド）は、この率で全体にあると置いた | 幅 |
| ストアが無くても本人が出品している社がある（T-3 の途中データでストアなし ASIN の約2%） | 少し多め |
| `offerCountFBA` は FBA オファーの本数で、各 ASIN の値がいつ時点かは未確認 | 不明 |
| 1ブランドだけ Finder で k=0（索引の更新ずれ）。平均から外した | 小 |
| T-1 の打診母数・展示会・NETSEA との重なりは引いていない（T-1 の打診母数のうち一覧に入るのは299社・うちストアなし196社） | — |

母数を足す手（件数は Finder の近似）:

- 規制3（ドラッグ・ビューティー・食品）を戻す: ASIN 7.69万→9.59万（+25%）。薬機法・食品表示の確認が要る
- ランクを10万位まで広げる: 未計測（推測：ASIN は2倍前後）。型A の「5万以内」から外れる
- 区分関数の大手リストに今回の大手を足してから、同じ手順を回し直す（一覧は保存済み。標本の product も保存済みで、再分類は0 token）

## 2. 前回（2026-08-31）が 1,200件で止まった本当の理由

**トークンが尽きたのではありません。生きているのに死んだと判定していました。**

`TokenBudget.wait_if_needed()` は「残高がしきい値を下回っている間」を枯渇とみなし、
60分続いたら停止していました。ところが**長時間ジョブでは「待つ→撃つ→また待つ」が正常な定常状態**で、
残高はほぼ常にしきい値を下回ります。結果、620件を正常に処理しながら
`!! トークンが 60 分回復しません。停止します` と記録して終了していました。

修正: 枯渇の定義を「**1件も進まないまま**時間が過ぎた」に変えました。
トークンを実際に消費できた時点（＝バッチが通った時点）でタイマーを解除します。

あわせて、しきい値が**下がらなくなる**バグ（`min_before_batch` を書き換えていた）も直しました。
1回コストが跳ねただけで以後ずっと余計に待つ挙動で、50時間走ると効きます。

回帰テストを2本追加（`tests/test_token_budget.py`）。既存を含め **95件すべて green**。

## 5. A-2 予算5万円フィルタ（実装済み・稼働中）

`budget_filter.py`。スキャン本体とは別スクリプトです（予算はその日の都合で変わるため、混ぜない）。

### 通す条件

| # | 条件 | 実装 |
|---|---|---|
| 1 | 1SKU の仕入れ額が **5,000〜10,000円** | 最小発注額(税込)×口数 がこのレンジに収まる口数を採る |
| 2 | 1口が 10,000円超のものは除外 | 1SKU で枠を食い潰すため |
| 3 | 利益率 **5%以上**（赤字不可） | 社長決定 2026-09-04 |
| 4 | FBA **大型を除外** | 小型／標準／不明は残す（不明を「駄目」にしない） |
| 5 | 「要確認」行を除外 | 入数の読み落とし疑いなど、儲かると言い切れない行を候補に混ぜない |
| 6 | ネット販売可（`deal_net_shop_flag=Y`）| 法務ハルオ判定（フィルタではなく除外） |

### 「最小発注額」列についての注意（誤読しやすい）

CSV の `最小発注額(税込)` は NETSEA の `set_price` ＝ **その商品を1口買うときの金額**です。
**サプライヤーの最低仕入れ金額ではありません。** 後者は Buyer API に存在せず、
API 経由では取得できません（空欄にしてあります）。
依頼文の「最小発注額が5万円を超えるサプライヤーは除外」は、この列では判定できないため、
**1SKU の仕入れ額が上限10,000円を超えるものを落とす**という形で実装しました。

### 送料無料ライン — 推測ではなく実データを取りました

NETSEA Buyer API の **`GET /tariffs`**（送料一覧）を叩けることを確認し、
アダプタに `list_tariffs()` を実装しました（公式スキーマを実取得して確認）。

| フィールド | 意味 |
|---|---|
| `gradual_flag` | 段階設定を使うか |
| `gradual_border_price` | 段階の切り替え金額 |
| `prices[].price1` / `price2` | 切り替え金額**未満** / **以上** の送料（都道府県別） |

⚠️ **「`gradual_border_price` = 送料無料ライン」ではありません。**
`price2` が **0** のときだけ「その金額以上で送料無料」です。正の値なら「安くなる」だけです。
この読み違えは初回仕入れの採算を直接壊すので、判定は `price2` を見て行っています。

取得できなかった社は**空欄＋理由**（「この社に設定が無い」/「対象都道府県外」/「未取得」を区別）。

> 送料の目安は**届け先を東京都**として出しています。社長の住所は使っていません（本リポは PUBLIC）。
> 実額は発注時に届け先で確定します。

### 動作確認（走行中の暫定データ 200件に対して）

```
入力: 200件（Keepa 検証済みの行のみ）
予算50,000円の制約を通過: 1件
    赤字 … 110件
    利益率が計算できていない（Amazon未出品・価格なし等） … 83件
    要確認（入数など未確定のため利益を保証できない） … 4件
    利益率が 5.0% 未満 … 2件

```

送料無料ラインが実データで返ってくることも確認済み（例：ある社は「20,000円以上で 770円 → 0円」。
候補が 9,984円ぶんしか無いので「あと 10,016円 必要」と出ます）。
**これが5万円運用で一番効く数字**です。

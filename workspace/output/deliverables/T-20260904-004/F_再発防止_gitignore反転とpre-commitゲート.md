## ② ホワイトリスト運用（既定＝載せない）

`.gitignore` の冒頭を `*` にし、ディレクトリだけ降りられるように `!*/` を置き、
**追跡してよいファイルを `!ファイル名` で55行明示**した。書き忘れは「公開されない」側に落ちる。

新しいファイルを追跡させたいときは `!ファイル名` を1行足す。足す前に
「これは卸値（会員限定の取引条件）を含まないか」を確認すること。

**適用は T-20260904-004 の1フォルダのみ。**他チケットへの横展開は影響範囲が読めないので別チケット。

## ③ pre-commit ゲート

`.githooks/pre-commit`。`git config core.hooksPath .githooks` で有効化済み。
`.claude/scripts/github-sync.sh` は 30分ごとに `git commit` を呼ぶので、**自動同期にも効く**。

`core.hooksPath` はローカル設定であり、新しい clone・worktree・クラウドセッションでは
未設定＝ゲートが効かない。そこで `.claude/hooks/session-start.sh` に**毎セッション冪等に
張り直す3行**を足した（「フックを置いた」は「フックが動いた」の証拠にならない）。

### 検知の仕様

| 対象 | 走査するか | しきい値 |
|---|---|---|
| **新規に index へ入るファイルだけ**（`--diff-filter=AC`） | する | — |
| 追跡済みファイルの編集 | **しない** | — |
| `.csv .tsv .json .html .htm .xml .txt` | する | **1行でも止める** |
| `.md` | 「行データらしい行」（`\|` 始まり／カンマ3つ以上）だけを見る | **6行以上で止める** |
| `.py .sh` その他・バイナリ | しない | — |

検知語（法務指定＋タカシが追加したもの）:
`netsea.jp/shop/` / `卸値` / **`卸価格`** / **`卸価`** / `仕入れ先:` / **`仕入れ先：`（全角コロン）** / **`仕入値`** / **`仕入れ値`**
（太字がタカシの追加分。表記ゆれの吸収）

### 誤検知を避ける設計

- 追跡済み `.md` の編集では発火しない（解説文を直すたびに止まる運用は壊れる）
- `.md` は解説文と貼り付けた行データを区別する。既存の法務判定 `E_` は行データらしい行に「卸値」が
  **5行**出るが、これは正当な引用なので通す必要がある。しきい値6はこの実測から決めた
- **限界**: `.md` に5行以下の小さな貼り付けをすると素通りする。`.md` は二次的な網であり、
  一次防御はホワイトリスト `.gitignore` の方

### バイパス（正当なケースは必ず出る）

```
git commit --no-verify                       # 1回だけ通す
ALLOW_WHOLESALE_DATA=1 git commit -m "..."   # 環境変数で通す
git config --unset core.hooksPath            # 恒久的に外す
```
この3つはフック自身のエラーメッセージにも印字される。

### 壊れたときに commit 不能にならないか

検査本体はサブシェルで動かし、**検知したときだけ**中止する（fail-open）。
非 git ディレクトリで実行するなど検査が失敗したケースでは、警告を出して commit を通すことを実測で確認した。

# Phase 2 実装要件チェックリスト（タカシ＝IT エンジニア向け）

> 法務担当ハルオ作成 / 2026-05-25
> 出典: 本ディレクトリ `01_official-api-tos.md` / `02_affiliate-asp-tos.md`
> 目的: Sato-Scope Phase 2（実 API 接続）で**法務クリーンを保つために必ず組み込む実装要件**を一覧化。

---

## A. 必須実装（これがないと規約違反。Phase 2 のブロッカー）

| # | 要件 | 対象 API | 根拠 | 受け入れ基準 |
|---|---|---|---|---|
| ✅A1 | **楽天ブランドクレジット（バッジ）を楽天データ表示エリアに表示** | 楽天市場 商品検索 API | 楽天は「API を使う全アプリにブランドクレジット表示が必須」。HTML スニペット改変禁止 | 楽天提供の3パターンから1つを選び、**提供 HTML をそのまま**埋め込み。改変しない |
| ✅A2 | **Yahoo! クレジット表示を Yahoo! データ表示エリアに表示** | Yahoo!ショッピング Web API | クレジット表示ガイドライン同意が前提。非公開ツールの免除が明文化されていない＝安全側で表示 | Yahoo! 指定のクレジット表記（ロゴ or テキスト）を表示 |
| ✅A3 | **楽天の価格キャッシュは24時間以内**に保つ／価格表示は最低週1回更新 | 楽天市場 商品検索 API | 「価格・在庫情報は24時間までキャッシュ可」「価格表示時は週1回以上更新」 | SQLite に価格を保存しても、**表示は探すたびに再取得**（実質キャッシュ無効化）が最も安全。長期保存値をそのまま表示しない |
| ✅A4 | **各行に楽天/Yahoo! の商品ページへのリンクを設置** | 楽天・Yahoo! | 楽天 API は「商品紹介＋商品ページへのリンク」目的を許可。リンクで「紹介」体裁を維持 | v0.2 設計の「元 URL リンクボタン」を必ず実装（既に設計済み） |
| ✅A5 | **データ取得経路は公式 API に一本化。アフィリエイト ASP のデータフィードは使わない** | 全体 | アフィリエイト ASP（楽天アフィリエイト/A8/もしも/バリューコマース等）は紹介リンク設置以外の目的での利用が NG | アダプタは `keepa.py`/`yahoo.py`/`rakuten.py`（ウェブサービス API）のみ。ASP データフィードのアダプタは作らない |
| ✅A6 | **楽天データは「楽天ウェブサービス 商品検索 API（ApplicationID）」から取得。楽天アフィリエイト規約に踏み込まない** | 楽天 | 楽天アフィリエイト規約は「リンク設置以外の目的での商品データ利用」を禁止。データ取得を API 側に寄せる | 取得は ApplicationID（商品検索 API）経由。アフィリエイト ID はリンク導線のオプションに留め、データ取得経路にしない |
| ✅A7 | **Yahoo! は「商品検索 API（v3）」のみ使用。「出店 API」は使わない** | Yahoo! | 出店 API は「提供情報を一切保持しない」と明記。混同するとデータ保存自体が違反になる | アダプタは商品検索 v3 のみ。出店系エンドポイントを叩かない |

## B. レート制限・再試行（安定運用 & 規約遵守）

| # | 要件 | 対象 API | 具体値 | 実装指針 |
|---|---|---|---|---|
| B1 | Yahoo! レート制限を守る | Yahoo!ショッピング v3 | **1日 50,000 req/アプリID・1分 30 req** | リクエスト間隔 **最短2秒**。1分30件を超えないトークンバケット or スリープ制御 |
| B2 | Keepa トークン消費を管理 | Keepa（€49 Power-User） | 約**22トークン/分**・トークンは**60分で失効**・クォータ**毎時5%補充** | レスポンスの `tokensLeft`/`refillRate`/`refillIn` を見て、不足時は `refillIn`(ms) 待ってから再試行。バーストで使い切らない |
| B3 | 楽天リクエスト間隔 | 楽天 商品検索 API | 公式の明示は薄いが**1秒1リクエスト目安** | 連続呼び出し時は **1秒間隔**でスリープ。429 受信時は指数バックオフ（1s→2s→4s） |
| B4 | 共通リトライ方針 | 全 API | — | 429/5xx は指数バックオフで最大3回。それ以上は失敗としてログ。**スクレイピング的な高頻度連打をしない** |

## C. データ保存（SQLite）の扱い

| # | 要件 | 根拠 | 実装指針 |
|---|---|---|---|
| C1 | 楽天の価格・在庫値は24時間超で「古い値」として扱う | 楽天キャッシュ規約 | お気に入り保存時に取得時刻を記録。再表示時に24時間超なら再取得 or 「要再取得」表示 |
| C2 | Keepa データの自己利用保存は OK。**外部公開・再配信・転売をしない** | Keepa（単一主体利用・redistribution 不可） | SQLite はローカル限定。クラウド同期で第三者に開かない |
| C3 | Yahoo! は商品検索（公開 API）データの表示用保存は可。出店 API データは保存しない | Yahoo!（出店APIは保持禁止） | A7 と同じく出店 API を使わなければ問題なし |
| C4 | 全データは**社長1名のローカル/1人用デプロイに閉じる**。他ユーザーに開かない | Keepa 単一主体利用・各 ASP の共有禁止 | Basic 認証1人分。公開エンドポイントにデータ API を生やさない |

## D. やってはいけないこと（NG リスト）

| # | NG 行為 | 根拠 |
|---|---|---|
| D1 | アフィリエイト ASP（楽天アフィリエイト/A8/もしも/バリューコマース/afb/アクセストレード）のデータフィードを仕入れ判断に使う | リンク設置以外の目的での利用禁止／非公開メディア不可／計測タグ無し利用は不正 |
| D2 | 楽天バッジ・Yahoo! クレジットの HTML/画像を改変して表示 | 改変は規約違反＝API アクセス無効化 |
| D3 | 取得データを蓄積して外部公開・再配信・転売（独自データベース化の公開） | Keepa redistribution 不可／楽天は紹介目的外の複製禁止 |
| D4 | Keepa サブスクを社長以外と共有 | サブスク共有は account termination |
| D5 | 価格を24時間超の古いキャッシュのまま「現在価格」として表示し続ける | 楽天キャッシュ規約（週1更新義務） |
| D6 | Yahoo! 出店 API を叩いてストア向けデータを取得・保存 | 出店 API は「提供情報を一切保持しない」 |
| D7 | スクレイピング（公式 API 以外で楽天/Yahoo!/Amazon から取得） | 各社 ToS でスクレイピング禁止。Sato-Scope は公式 API のみが大前提 |

## E. 推奨（必須ではないがリスク低減）

| # | 推奨 | 理由 |
|---|---|---|
| E1 | データ各値に出所（楽天/Yahoo!/Keepa）と取得時刻を併記 | 出所の透明化＝紛争時の防御。楽天の「1時間に1回未満更新なら更新時刻併記」要件も満たす |
| E2 | 各 API の規約 URL と取得日を README かフッターに記載 | 監査可能性。社内法務トレーサビリティ |
| E3 | API キー/ApplicationID/ClientID は `.env`（Git 管理外） | 既にタカシの技術スタック案に記載済み。継続 |

## F. Phase 2 着手前の「人間による最終確認」事項（ハルオから社長/タカシへ）

本日（2026-05-25）、楽天・Yahoo!・Keepa の公式 ToS ページは外部アクセスが 403 で制限され、検索スニペット由来の確認に留まった条文があります。**Phase 2 着手時に、契約者本人がログイン後・同意画面で以下を1回ずつ確認してください**（結論は変わらない見込みだが明文主義のため）:

1. **Keepa**: ログイン後 `keepa.com/#!api` の Terms & Conditions 全文、特に "redistribution" 条項の文言
2. **楽天**: ApplicationID 登録時の利用規約・クレジット表示ガイドラインの最新文言
3. **Yahoo!**: アプリID登録時の「クレジット表示ガイドライン」「クレジット掲出位置のルール」全文

# Sato-Scope ToS 最終確認 — 総括（T-20260522-005 ＋ T-20260522-003）

> 法務担当ハルオ作成 / 2026-05-25
> 2チケット（公式 API ToS／アフィリエイト ASP データ二次利用 ToS）を1箇所に統合。
> 対象: Sato-Scope（社長個人専用・非公開・SQLite ローカル保存・内部表示のみ）Phase 2 着手前の法務クリーン最終確認。

---

## 1. 結論: Phase 2 は「条件付き GO」

**公式 API（Keepa／楽天市場 商品検索 API／Yahoo!ショッピング Web API）でデータを取得する限り、Phase 2 は法務的に進めて問題ありません。** ただし下記の必須対応（特にクレジット表記とキャッシュ期限）を Phase 2 実装に組み込むことが GO の条件です。

**法務上のブロッカー（=これがないと違反になる）は2点**:
1. **楽天ブランドクレジット（バッジ）と Yahoo! クレジットの表示**（個人専用でも免除規定が確認できないため安全側で実装）
2. **楽天の価格キャッシュ24時間ルール／週1更新**

これらは実装で対応可能であり、Phase 2 の進行を止める性質のブロッカーではありません。→ **GO 判断。**

## 3. 楽天統合問題への回答（社長の最重要論点）

**Q: Sato-Scope が楽天データを使うなら、どちらの規約が適用されるか／クレジット表記やアフィリエイトリンクの義務があるか。**

**A:**
- **適用規約 = 楽天ウェブサービス（商品検索 API）の利用規約。** 楽天アフィリエイト規約には踏み込まないのが安全。
- **クレジット表記（楽天バッジ）= 必須。** API を使う全アプリに義務。個人専用でも表示する。
- **アフィリエイトリンク設置 = 必須ではない。** ただし API は「商品ページへのリンク」を想定しているため、各行に楽天商品ページへのリンク（通常リンクで可）を置く。
- **なぜアフィリエイト規約を避けるか**: 楽天アフィリエイトは「リンク作成用コンテンツをアフィリエイトリンク設置**以外**の目的で使えない」と明記。仕入れ判断目的での利用は目的外＝違反になるため、データ取得は商品検索 API 経由に一本化する。

詳細は `01_official-api-tos.md` §4。

## 4. アフィリエイト ASP は使えるか

**結論: 使わない（使えない）。** 商品データ取得は公式 API で代替する。

| ASP | 判定 |
|---|---|
| 楽天アフィリエイト | 🔴 NG（リンク設置以外の目的での利用を明確に禁止） |
| バリューコマース | 🔴 NG（計測タグ無し利用は不正＝提携解除） |
| もしもアフィリエイト | 🔴 NG 寄り（非公開・パスワード保護メディアを明確に不適切と規定） |
| A8.net | 🔴 NG 寄り（広告掲載メディアでの紹介が前提、紹介目的逸脱） |
| afb／アクセストレード | 🟡 未確認（打ち切り済み・結論に影響なし） |

打ち切り条件「3社で明確判定」は達成（楽天アフィリエイト＝NG、バリューコマース＝NG、もしも・A8＝NG 寄りの計4社）。ASP は構造的に「公開メディアでの紹介＋アフィリエイト報酬」が前提で、非公開・個人専用・紹介目的でない Sato-Scope はその前提を満たさない。詳細は `02_affiliate-asp-tos.md`。

## 5. タカシ（IT）への必須実装要件 Top 3

1. **楽天ブランドクレジット（バッジ）＋ Yahoo! クレジットを表示**（HTML 改変禁止）— これがないと両 API が規約違反。
2. **楽天の価格は24時間以内のキャッシュに限定／表示は探すたび再取得**（週1更新義務の確実な充足）。
3. **データ取得は公式 API（Keepa/楽天ウェブサービス/Yahoo! 商品検索 v3）に一本化。アフィリエイト ASP のデータフィードは一切使わない。Yahoo! は出店 API を使わない。**

完全なチェックリストは `03_implementation-requirements.md`。

## 6. 残課題（人間による最終確認）

本日（2026-05-25）、楽天・Yahoo!・Keepa の公式 ToS ページは外部アクセスが 403 で制限され、一部条文は検索スニペット由来の確認に留まりました。**結論は変わらない見込み**ですが、明文主義のため Phase 2 着手時に契約者本人がログイン後・同意画面で各社 ToS 全文（特に Keepa の "redistribution" 条項、楽天/Yahoo! のクレジット表示ガイドライン）を1回確認してください。詳細は `03_implementation-requirements.md` §F。

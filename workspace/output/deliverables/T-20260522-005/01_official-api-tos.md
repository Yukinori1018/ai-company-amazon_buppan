## 1. Keepa API（Power-User Plan €49/月）

### 1.1. 判定

| 項目 | 判定 | 根拠 |
|---|---|---|
| 個人専用ツール内利用 | ✅ **OK** | 有料プランの商用利用は明示的に許可。社内・個人ツールでの利用は redistribution に当たらない |
| データ二次配信（個人ツール内表示） | ✅ **OK** | Sato-Scope は取得データを「自分のツール内」で表示するのみ。第三者への再配信・公開・転売をしない限り規約範囲内 |
| クレジット表記 | **不要** | Keepa はバッジ/バナー表示義務を課していない（楽天・Yahoo!と異なる）。ただし公開する場合はデータ出所明記が望ましい |
| データのローカル保存（SQLite） | ✅ **OK** | 自己利用目的のキャッシュ・保存は許容。**ただし「データを公開・再配信する形での蓄積データベース化」は NG** |
| レート制限 | トークン制 | プランごとに「毎分生成されるトークン数」が決まる。€49 の Power-User は概ね **22トークン/分**。トークンは生成から **60分で失効**。クォータは **毎時5%補充**。1トークン＝1商品/カテゴリ/セラーのデータ取得に相当 |
| 違反時ペナルティ | アカウント停止 / API キー無効化 | サブスク共有違反等で account termination |

### 1.2. 該当条文・根拠（抜粋）

- **サブスクリプションの単一主体利用**:
  > "Keepa explicitly prohibits subscription sharing, with each subscription intended for use by a single individual or business entity, and violating this policy may result in account termination."
  → Sato-Scope は社長1名のみが使う＝**単一主体での利用に完全合致**。共有しない限り問題なし。

- **トークン/クォータ制（大規模スクレイピング防止）**:
  > "The paid plan uses a quota system to determine the volume of data that can be requested daily, which prevents large-scale data scraping ... Tokens expire 60 minutes after generation. Each token can request data for a seller, category, or product."
  > "refillRate: Number of tokens generated per minute ... quota replenishes at a rate of 5% every hour."

### 1.3. 法務コメント（ハルオ）

Keepa は **3 API の中で最もクリーン**です。理由は明快で、(1) 有料プランで商用利用が明示許可、(2) Sato-Scope は社長1名の単一主体利用でサブスク共有がなく、(3) 取得データを外部公開・再配信せず内部表示に留めるため。
唯一の論点は「取得データを蓄積して独自データベースとして公開・転売する」行為で、これは規約違反になりますが、**Sato-Scope の設計（内部表示・お気に入りローカル保存のみ）はこれに該当しません**。SQLite への保存は「自分が後で見返すためのキャッシュ」であり適法と判断します。

> ⚠️ 未確認・要直接確認: Keepa の Terms and Conditions 全文（Scribd 掲載 PDF）は本日アクセス制限により逐条確認できず。上記はトークン制・サブスク共有禁止・データ利用の各要点を複数二次情報から突合した結論です。**Phase 2 着手前に、契約者本人（社長 or タカシ）が keepa.com/#!api のログイン後ページで T&C 全文を1回確認すること**を推奨します（特に "redistribution" 条項の文言）。

## 2. 楽天市場 商品検索 API（楽天ウェブサービス）

> ⚠️ **本 API は最重要論点（§楽天統合問題）あり。** 楽天は「楽天ウェブサービス（商品検索 API）」と「楽天アフィリエイト」が連動しており、適用規約とクレジット表記義務の切り分けが Phase 2 実装に直結する。詳細は §4 と `02_affiliate-asp-tos.md` を参照。

### 2.1. 判定

| 項目 | 判定 | 根拠 |
|---|---|---|
| 個人専用ツール内利用 | 🟡 **条件付き OK** | API 規約上、取得情報は「自分のソフトウェア上で商品を紹介し、楽天の該当商品ページへリンクする」目的で利用可。内部ツールでの価格表示・参照はこの範囲に収まると解釈できるが、**「商品を紹介する」目的の延長**として運用する前提 |
| クレジット表記 | **🔴 ブランドクレジット（バッジ）表示が必須** | **API を使う全アプリにブランドクレジット表示が義務**。個人専用・非公開ツールでも免除規定は確認できず＝**安全側で表示する** |
| データのローカル保存（SQLite） | 🟡 **期間制限あり** | 価格情報・在庫情報は **24時間**、その他情報は **3ヶ月** までキャッシュ可。価格を表示する場合 **最低週1回（1時間に1回未満なら更新時刻の併記が必要）** 新鮮なデータに更新が必要 |
| アフィリエイトリンク義務 | グレー（API 規約上は紹介リンクの設置を想定） | API 規約は「該当商品ページへのリンク」を想定。アフィリエイト ID の付与は必須ではないが、楽天は API 利用をアフィリエイト導線とセットで想定している（§4） |
| 違反時ペナルティ | API アクセス無効化 | クレジット改変・要件不履行で「access to the Rakuten Web Services APIs may be disabled」 |

### 2.2. 該当条文・根拠（抜粋）

- **データ利用範囲（紹介＋リンク目的に限定）**:
  > "The information returned by Rakuten Webservice APIs can be used to introduce products on your software and provide a link to the corresponding product page within Rakuten. **Any reproduction or modification of information obtained from the API other than for this purpose is prohibited.**"
  → 「商品を紹介し、楽天の商品ページへリンクする」目的**以外**の複製・改変は禁止。Sato-Scope の「価格を表示して仕入れ判断に使う」は、この「紹介」目的の枠内かが論点（§2.3）。

- **クレジット表記（全アプリ必須）**:
  > "if you are using the Rakuten API in your app, you must give credit by displaying one of their badges, which is required for **all apps** that use the Rakuten API."
  > "Use the provided HTML source code as is, and modified HTML is not permissible ... If the HTML source code or images have been modified or these requirements are in any other way not met, **access to the Rakuten Web Services APIs may be disabled.**"
  → バッジは**改変禁止**・提供 HTML そのまま使用。3パターンから選択可。

- **キャッシュ保存期間**:
  > 「デベロッパーは商品の価格情報および販売可能情報については **24時間**、その他の情報については **3か月間** の期間であれば、データをキャッシュする目的で楽天グループの知的財産を格納することができる」
  > 「価格情報または販売可能情報を表示する場合、情報を **少なくとも1週間に1回**、各APIから新たに取得した情報に刷新し、再表示しなければならない」
  > 「1時間に1回以上データを更新しない場合は、価格情報または在庫情報等の情報に隣接した位置に更新時刻・日時を記載しなければならない」

### 2.3. 法務コメント（ハルオ）— グレー部分の明示

**「価格を仕入れ判断に使う」ことの可否はグレーです。** 楽天 API 規約の文言は「商品を introduce（紹介）し、商品ページへリンクする」目的を許可しています。Sato-Scope は最終的に各行に楽天の元 URL リンクボタンを置く設計（v0.2）なので「紹介＋リンク」の体裁は満たしますが、主目的が「仕入れ判断」である点は規約が明示的に想定する用途ではありません。

ただし、**Sato-Scope が社長個人専用・非公開で、取得した楽天商品を楽天の商品ページへリンクする導線を持つ限り、規約違反として摘発されるリスクは低い**と評価します（影響度: 中／発生確率: 低／不可逆性: 低＝最悪でも API キー無効化で復旧可能）。理由は、楽天が嫌うのは「データの大量複製・外部再配信・楽天を介さない競合データベース化」であり、Sato-Scope はそのいずれにも当たらないためです。

**防御策（必須）**:
1. **楽天ブランドクレジット（バッジ）を Sato-Scope の楽天データ表示箇所に表示する**（HTML スニペット改変禁止）。これは免除規定が確認できない以上、個人専用でも入れる。
2. **価格キャッシュは24時間以内**に保つ（SQLite に保存しても、表示時は週1回以上＝実質は探すたびに再取得が安全）。
3. 各行に**楽天の商品ページへのリンクを設置**し「紹介＋リンク」の体裁を維持する（v0.2 設計と整合）。

## 3. Yahoo!ショッピング Web API（商品検索 v3）

### 3.1. 判定

| 項目 | 判定 | 根拠 |
|---|---|---|
| 個人専用ツール内利用 | 🟡 **条件付き OK** | 商品検索 v3 で JAN・キーワード・カテゴリ等から商品情報を取得し JSON で利用可。非営利・営利問わず利用自体は可だが、**API そのものの「販売・頒布」は事前の書面許諾なしに禁止**（Sato-Scope は API を売らないので該当しない） |
| クレジット表記 | **🔴 クレジット表示が必須** | 「Yahoo!デベロッパーネットワークの API を利用して作成されたアプリケーションにはクレジットを表示する必要がある」。「公開する場合」が前提だが、**個人専用＝非公開での免除は明文化されていない**ためグレー。安全側で表示する |
| データのローカル保存（SQLite） | 🟡 **グレー（明示薄）** | 商品検索（公開 API）側に明示的な保存禁止条項は確認できず。表示用の一時キャッシュは許容と解釈。**ただし「出店 API（ストア向け）」側は「LINEヤフーから提供を受ける情報を一切保持しない」と明記**があり、利用する API を取り違えないこと（Sato-Scope は出店 API ではなく商品検索 API を使う） |
| レート制限 | **1日 50,000 リクエスト/アプリID・1分 30 リクエスト** | 超過時はアプリID追加で対応。推奨再試行間隔は 1分30リクエスト＝**最短2秒間隔**を目安 |
| 違反時ペナルティ | アプリ停止 / 利用制限 | 1年以上未使用アプリは削除されうる |

### 3.2. 該当条文・根拠（抜粋）

- **API の販売・頒布禁止**:
  > 「利用者は営利目的または金銭的利得等の有無を問わず、LINE ヤフーの事前の明示的な書面による許諾を得ることなく **本件APIを販売、頒布してはなりません。**」
  → 禁止対象は「API の販売・頒布」。Sato-Scope は API 自体を売らない／配らないので**該当しない**。

- **クレジット表示**:
  > "When publishing applications or sites that use Yahoo! Developer Network APIs, you must agree to the 'Credit Display Guidelines' and 'Credit Placement Rules.'"
  → 「publishing（公開する）アプリ・サイト」が文言上の前提。個人専用・非公開ツールが対象外かは明文化されておらず**グレー**。

- **出店 API 側のデータ保持禁止（※Sato-Scope は非該当だが取り違え注意）**:
  > 「利用者は、ショッピング出店APIおよびテスト環境APIの利用に伴いLINE ヤフーから提供を受ける情報について、別途LINE ヤフーが保管を指示する情報を除き、一切保持しないものとします。」

- **レート制限**:
  > 「商品検索（v3）API のリクエスト上限は、1アプリケーションIDごとに1日50,000回」「1分間で30リクエストの利用制限」

### 3.3. 法務コメント（ハルオ）— グレー部分の明示

**「クレジット表示は公開アプリのみ義務か、非公開の個人ツールも義務か」がグレーです。** 規約の文言は "publishing applications or sites" と公開を前提にしていますが、非公開ツールを明示的に免除する条項はありません。**明文主義の原則に立てば「書かれていない＝免除されているとは断定できない」ため、安全側でクレジット表示を入れます。** コスト（テキスト一行 or ロゴ表示）に対してリスク回避効果が大きく、入れない理由がありません。

データ保存については、商品検索 API（公開 API）側に明示的な保存禁止は確認できませんでした。表示・お気に入り用の SQLite 保存は許容範囲と判断しますが、**「保管しない」と明記された出店 API（ストア運営者向け）と混同しないこと**が実装上の絶対条件です。Sato-Scope は仕入れ候補を探す＝**商品検索 API のみ**を使い、出店 API は使わない設計を厳守してください。

> ⚠️ 未確認・要直接確認: Yahoo!デベロッパーネットワークの「クレジット表示ガイドライン」「クレジット掲出位置のルール」「ガイドライン」本文は本日アクセス制限（403）で逐条確認できず。上記は公式ページの検索スニペット由来。**アプリID登録時にガイドライン同意画面で全文確認すること。**

## 4. 【最重要】楽天統合問題 — 商品検索 API 規約 vs 楽天アフィリエイト規約

社長の問い「Sato-Scope が楽天データを使うなら、どちらの規約が適用されるか／クレジット表記やアフィリエイトリンクの義務があるか」への法務回答。

### 4.1. 結論

- **Sato-Scope が使うべきは「楽天市場 商品検索 API（楽天ウェブサービス）」であり、その API 利用規約が適用される。**
- **楽天アフィリエイト規約は、アフィリエイトリンクを設置して報酬を得る場合に追加適用される。Sato-Scope はアフィリエイト報酬目的ではないため、楽天アフィリエイト規約の「リンク作成用コンテンツの目的外利用禁止」条項に踏み込まないのが安全。**
- **義務の整理**:
  - **クレジット表記（楽天バッジ）= 必須**（API 規約上、全アプリに義務）。これは Phase 2 で必ず実装する。
  - **アフィリエイトリンク設置 = 必須ではない**。ただし楽天 API は「商品ページへのリンク」を想定しているため、**通常リンク（アフィリエイト ID なし）または楽天アフィリエイトリンク**のいずれかを各行に置くこと。

### 4.2. なぜ楽天アフィリエイト規約に踏み込まない方が安全か（条文根拠）

楽天アフィリエイトのパートナー規約には以下の制限がある:
> 「パートナーはリンク作成用コンテンツを、本規約に基づく本サービス利用のための**アフィリエイトリンク設置以外の目的に使用することはできない**」

→ もし Sato-Scope が楽天アフィリエイト経由でデータ（リンク作成用コンテンツ＝商品情報）を取得すると、それを「仕入れ判断」という**アフィリエイトリンク設置以外の目的**に使う形になり、規約違反の構図になります。
→ **したがって、楽天データは「楽天ウェブサービス（商品検索 API）」から取得し、商品検索 API 規約の枠内（紹介＋リンク＋ブランドクレジット）で運用するのが正解。** 楽天アフィリエイトを併用するなら「報酬導線として通常のアフィリエイトリンクを各行に置く」程度に留め、データ取得は商品検索 API 経由に一本化する。

### 4.3. タカシ（実装）への帰結

1. 楽天データ取得は **楽天ウェブサービス 商品検索 API（ApplicationID 利用）** に一本化。アフィリエイト ID は「リンクの導線」としてオプション付与は可だが、データ取得経路をアフィリエイト側にしない。
2. **楽天ブランドクレジット（バッジ）を楽天データ表示エリアに必ず表示**（改変禁止・提供 HTML そのまま）。
3. 価格キャッシュは24時間以内。各行に楽天商品ページへのリンクを設置。

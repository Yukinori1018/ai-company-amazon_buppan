# 候補リスト常時稼働ジョブ — 運用書

社長が何も言わなくても、候補リストとメーカー名寄せが毎日増えていく仕組みです。

---

## 止め方（迷ったらこれ）

```
bash ".claude/scripts/list-builder.sh" stop
```

次のバッチの切れ目（最長3分）で安全に止まります。**CSV は1行も失いません。**
再開は `start`。

| したいこと | コマンド |
|---|---|
| 止める | `bash .claude/scripts/list-builder.sh stop` |
| 再開する | `bash .claude/scripts/list-builder.sh start` |
| 今どうなっているか見る | `bash .claude/scripts/list-builder.sh status` |
| 常駐そのものを外す | `launchctl bootout gui/$(id -u)/com.aicompany.amazon-buppan.list-builder` |

## 何が起きるか

| | |
|---|---|
| 走り方 | 6時間×4回/日。落ちても Mac を再起動しても launchd が戻す |
| 積み上がる量 | **1日 約3,300件・候補 約2,500件**（Keepa 20トークン/分が上限。実装では速くならない） |
| 探索の残り | 母集団 **約48,700件** − 取得済 1,800件 → **残り約14日で掘り切る** |
| 掘り切った後 | 7日クールダウン → 再訪。**新規は激減する**（1日50〜130件の見込み・未実測） |
| Keepa 課金 | **追加課金なし**（下の §課金 参照） |
| ディスク | 1日 約3MB（生レスポンスの保存はやめたので）。以前は1日1GB |
| Git | 巨大CSVとHTMLは追跡しない。載せるのは名寄せCSVと日次サマリだけ |

## 自分で止まる条件

「壊れたまま回り続ける」のが一番まずいので、異常時は自分から止まって `ALERT.md` を書きます。

| # | 条件 | 動作 |
|---|---|---|
| S2 | 1セッションで新規候補0件なのにトークン3,000超 | 停止 + ALERT |
| S3 | 直近100リクエストの API エラー率 > 20% | 停止 + ALERT。**「掘り切りました」とは書かない** |
| S5 | スキャナが5回連続で異常終了 | 停止 + ALERT（プロセスは exit 0。再起動ループにしない） |
| S6 | ディスク空き < 50GB / `v14/` > 20GB | 走らない + ALERT |
| S7 | Git 追跡ファイルが 40MB 超 | 走らない + ALERT（GitHub の100MB上限の手前で止める） |
| S8 | 二重起動 | 後発が即終了（flock） |
| S9 | `STOP` ファイル | 安全停止 |
| S10 | 心拍が10分止まった | 子プロセスを強制終了 + ALERT |
| — | トークンが240分回復しない | セッション終了 + ALERT |

**ALERT.md が在る間は走りません。** 人が中身を見て消すまで待ちます。

---

## 「掘り切りました」と書いてよい条件（最重要）

Keepa がエラーを返したのを「母数を掘り尽くした」と記録すると、**キー失効もプラン切れも
Keepa 障害も、全部「正常終了」に見えます。** night-shift のジョブが14日間・814回 exit 127 で
死に続けても誰も気づかなかったのと同じ形です。

そこで Finder が空を返したときは、必ず2つを区別します。

- `totalResults` が整数で返っている → **本当に掘り切った**。掘り切り済みとして記録
- API が失敗した / レスポンスが壊れている → **障害**。掘り切り扱いにせず ALERT を書いて停止

テストで固定してあります（`test_api_failure_is_never_recorded_as_exhaustion`）。

## 課金（確認済み・2026-08-31）

Keepa 公式 `keepa.com/api-docs/plans-tokens.html` を実機で確認しました。

- プランは**月額前払いの定額**で、違いは「1分あたり何トークン生成されるか」だけ
- 公式の記述：プランの総量を誤って使い切ることはできない（トークンバケットのため）
- トークンが尽きたら **HTTP 429**（`You are out of tokens.`）。**課金は発生しない**
- 従量課金・超過料金の項目は存在しない。請求が動くのは**プラン変更・追加契約だけ**（どちらもダッシュボードでの明示操作）

→ **24時間回しても追加費用は1円も発生しません。**CLAUDE.md §4.1（金銭）には該当しません。

**未確認が1つ**：2026年3月に導入された「データクォータ（毎時5%回復）」は
**Keepa Pro（ブラウザUI）側の制限**で、API（`api.keepa.com`）は別勘定という理解です
（社内メモ `knowledge_keepa_operation_umizou` で2026-08-17に訂正済み）。
api-docs 側にクォータの記述は見当たりませんでしたが、**常時稼働での実測はまだありません。**

## 構成

```
.claude/scripts/list-builder.sh                 launchd の入口 + stop/start/status
~/Library/LaunchAgents/com.aicompany.amazon-buppan.list-builder.plist
T-20260831-002/
  always_on.py        常駐ループ（ガード・セッション管理・心拍監視）
  cycle_state.py      周回とクールダウンの純ロジック（テスト対象）
  daily_rollup.py     日次ロールアップ（0トークン）
  test_*.py           25本
  state/              実行時状態（Git 追跡外）
  daily/              日次メトリクス（Git 追跡）
T-20260817-005/
  scan_v14.py         スキャナ本体。データは v14/ に積まれ続ける
```

Mac を入れ替えたら：plist を `~/Library/LaunchAgents/` にコピー →
`~/.config/ai-company-amazon-buppan/keepa.env` に Keepa キーを置く →
`bash .claude/scripts/list-builder.sh preflight` で依存チェック → `launchctl load`。

## 2. 手順（夜間タスクと朝の人手に分ける）

### 夜間タスクでやる（無人・公開ページだけ）

1. NETSEA のトップを1回取得する
   ```
   curl -s -o netsea.html -w "%{http_code}\n" https://www.netsea.jp/
   ```
   - 503：本文から「第N報」と更新日時を抜き出し、前日と比べる。変化があれば朝の報告に1行
   - 200：**復旧の候補**。API の疎通はこの時点では打たない（朝に人が確認してから）
   - 再試行はしない。1日1回で足りる
2. SynaBiz のお知らせを1回取得し、NETSEA の見出しが増えたかを見る
3. 結果を `agent_output/T-20260920-003/supplier_master/status_<YYYYMMDD>.json` に書く（ステータス・第N報・取得時刻）

### 朝、秘書が社長の Chrome でやる（人が在席）

4. Gmail（1018 はコネクタ、satoyselect はブラウザ）で前日以降の SD・卸売ドットコム・卸問屋.com からのメールを見る
5. SD にログインした状態で、申請中の8社の商品一覧を1社1ページずつ開き、値段が出たかを見る。**間隔3秒以上・1社1回**
6. 変化があった社だけ、`supplier_master_20261011.csv` の「取引状態」「卸価格が見えるか」と確認日を書き換える
7. 承認が出た社は、その日のうちに次へ回す：
   - SD：値段を `sd_price_manual_20261010.csv` に足し、`ledger_refresh.py` を再実行（タカシの手順）
   - NETSEA 復旧：GO 2件（ヤザワ）と UNKNOWN 35行の卸の画面を見直す。§3.3-11 に従い、**当たるはずの JAN で API の疎通を確かめてから**「0件」を信じる
   - 卸売ドットコム：台帳のカネイシ286行を JAN で引けるか、まず数件で試す

## 3. 止める条件と再開の条件（§3.3-31「止めた」には再開を書く）

| 状況 | どうするか | 再開 |
|---|---|---|
| SD が 429 を返した | その日の SD 確認を打ち切る | 翌日、間隔を倍にして再開（3→6→12秒） |
| NETSEA が 200 だが API がエラー | API を叩き続けない。エラーの code と message を記録 | 翌日もう一度1回 |
| 審査のメールが7営業日を過ぎても来ない | ログインを1回試して状態を見る | 結果を秘書に報告。問い合わせは §4.1 なので秘書経由で社長判断 |

🔴 してはいけないこと：通信の指紋を偽装する手段を使う（§3.3-14）。SD・直販サイトのログイン後の画面を無人で取得する。審査や承認の催促を自分から送る（§3.3-15・§4.1）。

## 4. どの実践者の型か（§3.3-27）

新しい型ではない。**卸の取引申請は「申請→1〜3営業日で承認メール→承認先から仕入れ」**が SD 公式の案内どおりの流れで、それを毎日1回の確認に置き直しただけ。NETSEA の告知を毎日見る手順は、運営が告知ページで「定期的にご確認ください」と案内している（第4報）。

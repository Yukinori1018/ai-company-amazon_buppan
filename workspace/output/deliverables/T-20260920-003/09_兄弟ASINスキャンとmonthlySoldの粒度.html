1. monthlySold の粒度検証（問い1）

一次情報

Keepa 公式（Keepa 自身が保守する product object の構造定義）より、monthlySold の説明を原文のまま：

> "How often this product was bought in the past month. This field represents the bought past month metric found on Amazon search result pages. It is not an estimate. null if it has no value. Most ASINs do not have this value set. The value is variation specific."

同じ定義ファイルから対照として：

> salesRanks — "Contains subcategory rank histories. Each key represents the categoryId of the rank with the history in the corresponding value."
> salesRankReference — "The category node id of the main sales rank."

ランク側の定義には「variation specific」に相当する記述がありません。 monthlySold だけが明示的にバリエーション固有だと言っています。列名から推測せず定義に遡った結果、2つのフィールドで粒度が違うことが分かりました。

あわせて monthlySold は Amazon の検索結果に出る「先月N点購入」そのもので、Keepa の推計値ではありません（"It is not an estimate."）。

  1. monthlySold が入っているのは6件で、その値は 200 / 200 / 100 / 100 / 50 / 50 の3水準に割れました → ASIN 単位。合算なら全員同じ値になります。値が入っているのは上の表で最終更新が 2026-09 のもの（シナモロール・クロミ・ハローキティ 174459・ポムポムプリン・マイウィートピアノ・ハンギョドン）で、ASIN と値の対応は完全版にあります。

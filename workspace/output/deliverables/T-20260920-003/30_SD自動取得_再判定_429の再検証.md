## 1. 結論

### 🔴 指紋説は反証されました。**逆転が観測されました。**

**同一 URL に対し、12秒あけて投げた2回で、先に投げた `urllib` が 200、後に投げた `curl` が 429 でした。**
サトルの観測（`urllib`=429 / `curl`=200）と**向きが逆**です。したがって429は**クライアントの性質では決まっていません。**

### したがって①②③の結論は維持します。加えて、前回引いた線すら楽観的でした。

| 案 | 前回 | 今回 | 変化 |
|---|---|---|---|
| ① 種語100語・約700回 | 不可 | **不可（維持）** | 根拠が「429=125回」から「**12秒間隔でも429**」に入れ替わり、より厳しくなった |
| ② 種語1,000語・約7,000回 | 不可 | **不可（維持）** | 同上＋無人運転 |
| ③ 2,175社・数万回 | 不可 | **不可（維持）** | ただしタカシの理解に**1点の誤り**があります（§4-1） |
| ④ ログイン済みブラウザ 1ページ/秒 | 不可 | **不可（維持）** | タカシの指摘どおり、指紋説が正しくても成り立ちます |
| **レーンB（Amazon 起点・1 JAN=1リクエスト）** | 1日30回・間隔10秒・人の在席下 | **緩めません。むしろ `HTTP 429 を受けた直後の追加アクセス` に当たるため、C の照会まで全面停止を推奨** | ← 唯一の実質的な変更 |

**タカシの読み（1〜4で維持される）は結論として正しいです。ただし1と2は「独立に立つ足」ではありません。**本体は**3（第10条の非対称）**です。1・2・4の射程を §4 で正確に切り分けます。

## 2. 私が自分で検算しました（www.superdelivery.com へ計7リクエスト・うち診断4）

**依頼文にあった「返ってきた数字を検算しなかったことが根」という指摘を、そのまま自分に当てました。**

| # | クライアント | URL | 結果 |
|---|---|---|---|
| 1 | curl | `/robots.txt` | 200 |
| 2 | curl | `/p/contents/guide/rules.jsp` | 200 |
| 3 | curl | `/p/contents/guide/sitemap.jsp` | 200 |
| **4** | **urllib** | `/p/contents/guide/rules.jsp` | **200** ← 指紋説なら429のはず |
| **5** | **curl**（#4 の直後） | 同上 | **200** |
| **6** | **urllib** | `/p/do/dpsl/dcc/204961/` | **200** ← 指紋説なら429のはず |
| **7** | **curl**（#6 の **12秒後**・**同一URL**） | 同上 | **🔴 429** |

### 読み取れること（3点）

1. 🔴 **指紋説は反証（確度：高）。**`urllib` は静的ページ（#4）でも動的ページ（#6）でも200を返しました。**Python の標準ライブラリだから弾かれる、という説明は成り立ちません。**
2. 🔴 **429 は「短時間内の連続アクセス」で出ています（確度：中）。**#6→#7 は同一 URL・12秒間隔で、**後に投げた方だけが429**。整合する説明はレート／クォータ側です。
3. 🔴 **`Crawl-delay: 10` を守っても429は出ます。**#6→#7 の間隔は12秒でした。**前回引いた「間隔10.0秒」という線は、実測に照らして十分ではありません。**

### サトルの実験が間違った理由 — 順序を入れ替えていません

サトルの観測は「`urllib`=429 / `curl`=200 を3回連続で再現」です。**3回とも `urllib` → `curl` の順で投げているなら、再現されたのは「クライアントの違い」ではなく「順序の効果」です。**後攻が429を引くなら、`urllib` が常に先攻なら `urllib` が常に429になります。

**対照実験に必要だったのは、UA やヘッダを揃えることではなく、順序を入れ替えることでした。**
**これが「返ってきた数字を検算しなかった」の3件目です**（1件目：429 を握りつぶす実装／2件目：除外カテゴリID を推測で書いた／3件目：これ）。**共通の型は「1つの説明が付いた時点で止めている」ことです。反証側の1手を打つまでは、説明は仮説です。**

### 私が確定できていないこと（正直に書きます）

- **各方向 n=1 です。**#7 の429が偶然（別の要因）である可能性は排除できていません。
- **「2.5秒間隔で161社ぶん安定して200」という実績と整合しません。**整合しうる仮説は (a) クォータが IP の累積や時間帯で動く (b) `/p/do/dpsl/dcc/` と一覧系でしきい値が違う (c) Cookie／セッションの有無が効く、など複数あり、**当社はどれも確定できません。**
- 🔴 **これ以上の検証は、私自身が「429 を受けた直後に追加アクセスする」ことになるため、ここで止めました。**前回自分が書いた条件6（429 を1回引いたら停止）を、法務が最初に破るわけにはいきません。**確定手段は照会（§6）だけです。**

## 4. タカシの4つの足 — 射程を正確に切ります

### 足1：`/p/do/dpsl/` — 🔴 **理解に誤りがあります。ここは正確にしてください**

> 「`/p/do/dpsl/` は SD が名指しクローラに全面 Disallow した唯一のパス。**これ単独で不可だと理解しました**」

**「これ単独で不可」は誤りです。**robots.txt を条文どおり読みます。

| User-agent | `/p/do/dpsl/` |
|---|---|
| `meta-externalagent` / `meta-webindexer` | **全面 Disallow** |
| `*`（当社） | **クエリの組み合わせだけ Disallow**（`as=` `br=` `ed=` `so=pricedown` `exw=`）。**パスそのものは Disallow されていません** |

停止した2本が叩いていた URL を実装で確認しました。

- `sd_dealer_terms.py` → `/p/do/dpsl/dcc/<dealer_id>/`
- `sd_dealer_index.py` → `/p/do/dpsl/<dealer_id>/` と `/p/do/dpsl/<dealer_id>/all/<pg>/`

**いずれもクエリを持たないので、`*` に対する Disallow に一致しません。robots.txt 違反ではありません。**

**不可なのは「このパス」ではなく「このパス × 網羅」です。**SD が名指しクローラに閉じたのは、**サイトを機械で網羅索引化する者**に対してです。2,176社を全社走るのは、その用途と一致します。
→ **正しい線：発注候補に挙がった1社の `dcc` ページを、人が在席して開くのは可。**パス単位で塞ぐと、私が §6-A で推奨した「出展者ゲート（発注直前に1社読む）」まで自分で塞いでしまいます。**そこは塞がないでください。**

**足1は ③ に対しては決定的です。①② に対しては効きません（①②は `/p/do/psl/?word=` と `/p/r/pd_p/` を使うため）。**

### 足2：`Crawl-delay: 10` に対して 2.5秒（4倍速）— **これは「不可」の根拠ではなく「数値の出所」です**

`Crawl-delay: 10` は `meta-externalagent` と `PetalBot` 宛です。**`*` には Crawl-delay が付いていません。当社を直接拘束する数値ではありません。**
位置づけは「**SD が示した唯一の数値だから、そこに揃えるのが最も説明しやすい**」であり、それ自体が禁止規範ではありません。
**そして §2 の実測で、10秒でも足りない可能性が出ました。**足2は「4倍速だったから違反」ではなく「**当社は正しい数値を知らない**」という結論に変わります。

### 足3：第10条(2)(5) の非対称 — 🔴 **これが本体です。事実関係に一切依存しません**

**429 が何だったかに関係なく、この足だけで①②③は止まります。**

- 第10条(2)「会員として不適切な行為」・(5)「その他やむを得ない事由」は**規約違反を要件にしていません**。SD の裁量で、**予告なく即時に**利用停止・登録抹消ができます。
- 第11条1項で**賠償責任も否定**されています。**争う足場がありません。**
- 当社は **2026-11-30 の利用停止条件**を背負っています。
- **失うもの：SD の 2,176社（NETSEA 承認済み220社の約10倍）と、11/30 までの時間。得るもの：数日ぶんの索引作業の短縮。**この非対称が本件の核です。

**タカシの読みは正しく、かつ足3が唯一、私の検算結果にも指紋説にも依存しません。**ここを結論の土台にしてください。

### 足4：Librahack と同一速度域 — **④には効きます。2.5秒の走行には直接は効きません**

- ④（1ページ/秒 × 2,176ページ）は同事件（約1秒間隔で逮捕・20日勾留・起訴猶予）と**同一速度域**です。**効きます。**
- 2.5秒間隔（24件/分）は同事件の**2.4倍遅い**ので、速度単独では同列に置けません。**過大に評価しないでください。**

## 5. 🔴 ここに新しい線を引きます — TLS 指紋の偽装は不可

指紋説が出た以上、次に必ず出る選択肢を先に塞ぎます。

| 手段 | 判定 |
|---|---|
| `urllib` → `curl` に替える | **可**（今回それは原因でもありませんでした）。curl は特殊な道具ではなく、「別の普通のクライアントを使った」と説明できます |
| 🔴 **TLS/JA3 指紋を偽装する**（`curl-impersonate`・`tls-client`・指紋を真似るヘッドレスブラウザ等） | **不可。例外なし** |

**理由：説明の余地がゼロだからです。**「弾かれたので、弾かれないように見せかけた」以外の説明が立ちません。相手の検知措置を無効化する目的で作られた道具を使った記録は、第10条(2) の認定において④と同等以上に不利に働きます。**速度や総量を落としても正当化されません。**

**タカシの指摘3は完全に正しいです。**「記録を読む第三者は指紋の話を知りません」──これは指紋偽装にも、`SDX.terms()` にも、そのまま当てはまります。

### そして、その対策は「今、記録を正しく残すこと」です

後から「当社は拒否を迂回していない」と言うための唯一の材料は、**その時点で残した診断の記録**です。

- 429 を受けた → 指紋説を立てた → **順序を入れ替えて反証された** → 止めた
- この時系列がチケットに残っていることが証拠になります。**本判定書と §2 の7リクエストの表を、その記録として残します。**
- **サトルの「対処後、2.5秒間隔で安定」という記述は、チケット上で訂正してください。**「対処によって通った」という記述が残ると、後から読む第三者には「弾かれたので回避した」と読めます。**事実は「原因は特定できておらず、通った理由も不明」です。**

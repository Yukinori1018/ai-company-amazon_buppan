## 1. 結論

### 🔴 ①②③は、提案された形のいずれも不可です。線を引く前に、前提が崩れています。

**2026-09-30、SD は当社に `HTTP 429 Too Many Requests` を返しました。**累計125リクエストの時点で、**4秒間隔・64秒バックオフでも復帰しませんでした**（チケット 1890行・1938行）。

429 は「Too Many Requests」＝**相手が「お前の要求量は多すぎる」と明示的に述べた通信**です。**規約に自動取得の禁止条項が無いことは、もはや論点ではありません。**当社は SD 本人から、当社の取得量について直接の意思表示を受け取りました。**これを受け取った後に総量を5倍・50倍にする行為は、「禁止と知らずにやった」という最大の防御を自ら捨てる行為です。**

| 案 | 規模 | 判定 | 理由 |
|---|---|---|---|
| **①** | 種語100語・約700回 | **不可（提案された形では）** | 429 が出た水準（1日125回）の **5.6倍**。§5 に縮小案あり |
| **②** | 種語1,000語・約7,000回 | **不可** | 同 **56倍**。無人・連続。429 の解除条件が不明なまま夜間に回すのは制御不能 |
| **③** | 取引企業2,175社・数万回 | **不可** | 同 上。加えて `/p/do/dpsl/`（企業内検索）は SD が名指しクローラに全面 Disallow した唯一のパス |
| **④**（依頼外・チケット1890行） | **ログイン済みブラウザの同一オリジン iframe で 2,176社を1ページ/秒** | **🔴 不可。3案より悪い。§7 で単独に論じます** | **429 を回避する目的で経路を替える行為**＋**会員アカウントの使用**＋**1リクエスト/秒** |

### 進める道はあります（§5・§6）

- **1日30リクエストまで・間隔10秒以上・人の在席下**の「レーンB（Amazon 起点・1 JAN = 1 リクエスト）」は、3点セット付きで**条件つき可**とします。索引づくり（レーンA）は不可です。
- **2,176社の Amazon 可否を先に全部確定する必要はありません。**発注する社だけを、発注の直前に人が読む（既存の「出展者ゲート」設計）。これが最短かつ唯一安全な道です（§6-A）。
- **SD への照会**（429 の解除条件・許容頻度・データ提供の有無）が本件の本筋です。**§4.1 該当（第三者連絡）なので実行しません。**社長承認を取る材料を §6-C に整えました。

## 2. 規約の実測（2026-09-30 取得・全文確認済み）

### 2.1 会員規約に「自動取得の禁止」は無い — が、これは白ではありません

会員規約（`https://www.superdelivery.com/p/contents/guide/rules.jsp`・改訂 2023.9.1・全17条）の全文に対し
`自動` `ロボット` `BOT` `クロー` `スクレ` `プログラム` `収集` `データベース` `名簿` `競業` `過度` `負荷` `サーバ` `アクセス` `情報取得`
を全文検索しました。**自動取得・取得量・アクセス頻度を制約する条項は1つもありません。**該当したのは第6条2項・第9条・第17条だけです。

したがって本件の論点は「禁止されているか」ではなく、**「どこから第10条が発動するか」**です。ここを取り違えると「明文禁止が無いから可」という誤った結論になります。

### 2.2 危険な条項は第10条 — 白紙委任です

> **第10条（会員規約違反等について）** （1）会員につき本規約違反がある、（2）**会員として不適切な行為がある**、（3）…（5）**その他やむを得ない事由があると当社が判断した場合**、当社は、**直ちに**、又は一定の予告期間の後に、会員の当サイト利用を停止し、又は会員登録を抹消することができます。当社は、…**何ら責任を負うものではありません。**

- (2) と (5) は**規約違反を要件にしていません。**SD の裁量判断だけで、**予告なく・即時に**利用停止・登録抹消ができます。
- 第11条1項で**抹消による損害の賠償責任も否定**されています。**争う足場がありません。**
- つまり本件のリスクは「訴えられるか」ではなく「**黙って切られるか**」です。**発生確率は低い／影響度は大／不可逆性は最大**の類型で、当社の3軸評価では最もアラートを上げるべき形です。

**当社は既に 2026-11-30 の利用停止条件（サイトオープン未確認）を背負っています。**停止事由を自分から1つ増やす行為は、単独で見た確率が低くても取るべきではありません。

### 2.3 第17条（著作権等）— 社内利用は可・外部発信は不可

> **第17条1項** 当サイト（当サイトにおける出展者個別の画面を含みます）に掲載されている画像・文章・マーク・標章等**一切の情報**（その全部か一部かを問いません）を、当社の**事前の同意なく、他のサイトに複製・転用又は発信することを禁じます。
> **第17条3項** **他のサイトが、当サイトとのリンクを貼る場合には、当社の事前の同意を要する**ものとします。

- 禁止の対象は「**他のサイトに**複製・転用又は発信」です。**社内の非公開台帳（Googleシート）・`agent_output/` への保存は「他のサイトへの発信」に当たりません。**自社の仕入れ判断に使うだけなら第17条1項に触れません。**タカシの理解（論点2）は正しいです。**
- **PUBLIC リポへの commit は「発信」に当たります。**従来どおり不可。
- **3項は新しい根拠です。**SD の商品ページ URL を PUBLIC リポの成果物に書かないルール（CLAUDE.md §3.2）は、これまで NETSEA 側の条項を横引きしていましたが、**SD については第17条3項が直接の明文根拠**になります。リンクは事前同意が要る、と SD 自身が書いています。

### 2.4 「非ログインで取ったから会員規約の外」という主張は採れません

タカシの見立て（論点1）は正しいです。第1条2項は「会員は、本規約、当社の定める購入方法**その他当社が必要に応じて定める規定・規則・条件等に従い**、当サービスを利用する」と定めており、義務の主体は会員です。**非ログインでの取得は、会員である当社の行為であることを変えません。**会員は非会員より軽い義務を負うわけではなく、**重い義務を負います**（第10条の停止権の対象になるのは会員だけです）。
→ **2026-09-14 の判定（登録前・手作業規模）は、そのままでは今の当社に使えません。**

**通知はサイト掲載のみ・掲載した瞬間に有効・アクセスしたら同意扱い。**②のような数夜にわたる無人運転では、**知らないうちに禁止条項が追加され、それに同意したことにされる**経路が開いています。

## 3. robots.txt の意思表示（2026-09-30 実測）

`https://www.superdelivery.com/robots.txt` の構造は次のとおりです。

| User-agent | 検索パス `/p/do/psl/` | 企業内検索 `/p/do/dpsl/` | Crawl-delay |
|---|---|---|---|
| `*`（当社がここ） | **許可**（絞り込み `as=` `br=` `ed=` `so=pricedown` `exw=`、`/p/prelogin/wishlist/search.do` 等は Disallow） | 絞り込み組み合わせのみ Disallow | **指定なし** |
| `meta-externalagent` / `meta-webindexer` | **全面 Disallow** | **全面 Disallow** | **10** |
| `PetalBot` | 主要カテゴリ配下を Disallow | 絞り込みを Disallow | **10** |

商品ページ `/p/r/pd_p/` に Disallow 指定はありません。**タカシの遵守状況（許可パスのみ・禁止パス未取得）は robots.txt に照らして正しいです。**

読み取れる SD の意思表示はこうです。

> **一般の利用者が検索の素 URL を開くことは許す。しかし「サイトを機械で網羅的に索引化する者」には、検索パスそのものを使わせない。**

- 当社の UA は `*` ですが、**総量と継続時間を上げるほど、挙動は `meta-externalagent` の側へ寄ります。**
- **③が使う `/p/do/dpsl/`（企業内検索）は、SD が名指しクローラに対し「全面 Disallow」とした唯一のパスです。**当社の UA が `*` であることは、この意思表示を回避する理由になりません。
- **SD が数値で示した唯一の基準は `Crawl-delay: 10` です。**明文主義に従い、無人・機械的な取得はこの数字に合わせます。前回（2026-09-14）の判定にも「当社も10秒に合わせる」と書いてあります。**現行実装の 2.0 秒は、この条件を満たしていません。**

## 4. 決定的な事実 — 429 は「相手の意思表示」です

### 4.1 何が起きたか

| 項目 | 実績（2026-09-30・チケット1890/1938行） |
|---|---|
| 429 が出た累計 | **125リクエスト**（間隔2秒） |
| 復帰の試み | **4秒間隔・64秒バックオフでも復帰せず** |
| 解除条件 | **不明**（時間か IP か会員か、解除の窓が何分・何時間・何日かを当社は知りません） |

### 4.2 なぜこれが判定を変えるのか

1. **「禁止と知らなかった」という防御が消えます。**規約に明文が無いことを根拠に「禁止されていない」と主張する余地は、429 を受け取った時点で失われました。**相手は当社の取得量について直接、拒否を通知しました。**
2. **故意の評価が変わります。**§4.3 の刑事リスクにおいて、Librahack 事件の行為者には「相手が拒んでいるという通知」がありませんでした。**当社にはあります。**429 の後に総量を上げた記録は、後から見て最も不利な証跡になります。
3. **第10条(2)「会員として不適切な行為」の評価が変わります。**「レート制限を受けた後も継続した」は、SD の裁量判断において決定的な材料です。
4. **解除条件が分からないまま無人運転はできません。**②は夜間に4時間〜20時間回す案です。**429 が出たら即停止する実装（タカシが修正済み）が正しく動いても、429 を1回引いた時点でその夜は終わります。**費用対効果の点でも成立しません。

### 4.3 刑事リスク — 岡崎市立中央図書館事件（Librahack、2010年）

公開ページの取得であっても、**偽計業務妨害（刑法233条）・電子計算機損壊等業務妨害（234条の2）**の立件例があります。同事件では**約1秒間隔**でアクセスするプログラムを書いた者が2010年5月に逮捕され、**20日間勾留**の後に**起訴猶予**となりました。事後の検証で、真因は図書館側システムの不具合であったとされています。

**攻撃の意図が無く、真因が相手側にあっても、逮捕・勾留は起きています。**発生確率は極小ですが、不可逆性は最大級です。
**そして本件では、当社は既に 429 という拒否の通知を受けています。**この状態で1リクエスト/秒の走行（§7 の④）を選ぶことは、同事件の行為者より不利な立場を自ら作ることになります。

### 4.4 民事 — データベースの複製（翼システム事件）

JAN・メーカー品番・上代・入り数は**事実データであり著作物ではありません**。データベースとしての著作物性（著作権法12条の2）も、商品カタログ型では創作性が否定される類型です（東京地判 平成13年5月25日・自動車整備業用データベース＝翼システム事件）。

ただし同判決は、**当該データベースを大量に複製して競合販売した行為に、民法709条の一般不法行為を認めています。**当社は (a) 内部の仕入れ判断にのみ使い (b) 再配布・販売をせず (c) SD と競合しない、という3点でこの要件を満たしません。**§5 の縮小案は不法行為を構成しません。**
逆に言えば、**外部へ出した瞬間に第17条1項違反と709条の射程に同時に入ります。**PUBLIC リポ禁止のルールはここでも裏打ちされます。

### 4.5 当たらない法令（過大に脅さないために明示します）

- **不正アクセス禁止法**：不該当。当社は認証を突破・回避していません。自社の正当な ID でログインした領域を自動で読むことも、同法の「アクセス制御機能による制限を免れる」には当たりません。**§7 の④を不可とする理由は、同法ではなく契約（第10条）と刑法233条／234条の2です。**
- **著作権法（画像）**：画像を1枚も取っていないため論点が立ちません。**この自主規制は維持してください**（SD は「購入前の画像転載禁止」を商品ページに明記しています）。

## 5. 進めてよい範囲（条件つき可）— レーンB のみ・1日30回

索引づくり（レーンA・種語で広く当てる）は**不可**です。429 の水準に対して規模が過大で、かつ「網羅的索引化」という SD が名指しで拒んでいる用途と目的語が一致します。

**Amazon 起点の突合（レーンB・1 JAN = 1リクエスト）に限り、次の全条件のもとで可とします。**

| # | 条件 | 数値／実装 |
|---|---|---|
| 1 | **1日の総リクエスト数** | **30回まで**（429 が出た 125 の 4分の1未満）。日付キーの**永続カウンタ**をファイルに持ち、プロセスが変わっても積算する |
| 2 | **間隔** | **10.0 秒以上**（SD が示した唯一の数値 `Crawl-delay: 10`）。`SLEEP_SEC` は呼び出し側から必ず明示的に渡す |
| 3 | **実行時間帯** | **人が在席していて、すぐ止められる時間帯のみ。**夜間自走・`/loop` からの実行は禁止 |
| 4 | 1回の実行上限 | 30回（`DEFAULT_FETCH_CAP` を引数で上書き） |
| 5 | 🔴 **停止トリガ** | **429 / 403 / 5xx / タイムアウト／応答時間がセッション中央値の3倍を超えた → 即時全停止。自動再試行しない。バックオフもしない。**（タカシが実装済みの `Fetcher.RateLimited` ＋終了コード2 は法務上も正しい修正です） |
| 6 | 🔴 **429 を1回引いたら** | **7日間、SD への自動取得を全面停止。**8日目以降に再開する場合は1日10回から。**2回目の429が出たら、§6-C の照会をするまで再開しない** |
| 7 | 🔴 **実行前の差分検知** | 冒頭で `robots.txt` と会員規約ページを取得・保存し、**前回とのハッシュ差分があれば実行せず停止**（第3条＝掲載即時・利用で同意への対策） |
| 8 | 🔴 **User-Agent に当社を名乗る** | 現行 `Mozilla/5.0 (T-20260920-003 manual-scale lookup)` は当社を特定できません。例：`SatoySelect-lookup/1.0 (SD member 3166793; contact: satoyselect@gmail.com)` |
| 9 | robots.txt の遵守を機械化 | Disallow を**パーサで当てる**。許可判定を通らない URL は組み立てない（数百回規模で目視はもたない） |
| 10 | 取得項目 | **画像ゼロ・卸価格ゼロを維持。**生 HTML の保存は `agent_output/` のみ・**90日で削除** |
| 11 | 公開 | SD 由来の値・**商品 URL** を PUBLIC リポに書かない（第17条1項＋**3項**）。出展企業名は社内台帳と社長報告まで |

### 条件8について — 隠れるより名乗ってください

## 7. 依頼外ですが黙って通せません — ログイン済みブラウザで 2,176社を1ページ/秒（`SDX.terms()`）

チケット1890行・1926行に次の記載があります。

> 🔴 SD は HTTP からの連続取得を 429 で止める（4秒間隔・64秒バックオフでも復帰せず／2026-09-30 実測）。**大量スキャンはログイン済みブラウザの同一オリジン iframe で回すのが唯一の道**（カズヨ実測で1ページ約1秒）。
> **2,176社の取引条件は1社も取れていない。**SD が HTTP からの連続取得を 429 で止めるため。**ブラウザ（`SDX.terms()`）で回してください。所要約40分の見込み。**

### 🔴 法務判定：不可。①②③より悪い案です。実行しないでください。

理由を4つ、重い順に述べます。

1. **「429 を回避する目的で経路を替えた」という事実が記録に残ります。**
   チケットの記述そのものが、**HTTP が 429 で止められたことを理由にブラウザ経路を選んだ**と述べています。これは技術的な工夫ではなく、**相手が明示した拒否を別の入口で迂回する行為**です。第10条(2)「会員として不適切な行為」の認定において、これ以上に分かりやすい材料はありません。**当社の側が、自分の手で「意図的だった」という証拠を作ります。**

2. **会員アカウントを使います。**
   非ログインの取得は、最悪でも IP 単位の遮断で済む可能性があります。**ログイン済みセッションからの走行は、当社の会員 ID に直接紐づきます。**SD は第10条により**予告なく即時に**利用停止・登録抹消でき、第11条1項により**賠償責任を負いません。**当社は 2026-11-30 の停止条件を既に背負っています。**不可逆性が最大の経路を、最も不利なタイミングで選ぶことになります。**

3. **1リクエスト/秒 × 2,176ページは、Librahack 事件と同一の速度域です。**
   同事件は約1秒間隔で逮捕・20日勾留に至りました。**しかも同事件の行為者は、相手からの拒否通知を受けていません。当社は受けています。**「429 を受けた後、1秒間隔で2,176ページを40分で走った」という事実関係は、故意の評価において当社に不利にしか働きません。

4. **取得物の扱いが、非ログインより厳しくなります。**
   当社の公開判定ルール（`knowledge_public_page_terms_rule_and_leak_detection.md`）は「**非ログイン表示を取得当日に実測**」を第1の足にしています。**ログイン後の領域から取った情報は、この足が立ちません。**第17条1項の「当サイトに掲載されている一切の情報」そのものであり、社内台帳に留める運用が今より厳格に要求されます。

**なお、不正アクセス禁止法には当たりません**（自社の正当な ID です）。**過大に脅すつもりはありません。**止める理由は契約（第10条）と刑法233条／234条の2、そして不可逆性です。

### 代替（`SDX.terms()` を捨てる必要はありません）

`SDX.terms()` の実装自体は価値があります。**使い方を変えてください。**

| 変更前 | 変更後 |
|---|---|
| 2,176社を1ページ/秒で40分・無人 | **発注候補に挙がった社だけ**を、**人が在席している画面で、1社ずつ**。**間隔は最低3秒**、**1セッション20社まで**、**1日50社まで** |
| 母数を先に全部確定する | §6-A の出展者ゲート。**発注の直前に1社読む** |

この形なら「会員が自分の取引先の取引条件を、自分のブラウザで確認している」という、**説明に一切の無理が無い行為**になります。

## 1. 結論

### 条件つき可です。Amazon 起点で JAN を1件ずつ照会する形に限ります。会員登録（社長の一手）は不要です。

| 案 | 判定 | 理由 |
|---|---|---|
| **B. Amazon 起点・1 JAN＝1リクエストで商品ページを読む** | **条件つき可**（§5 の数値） | 非会員なので契約上の制約がない。robots.txt なし。規約に取得・転載・秘密保持の条項なし。相手からの拒否応答もまだ受けていない |
| A. 国分の全商品（約1.6万点）を網羅して索引にする | **非ログインでは経路が存在しない**（判定の対象外） | 非ログインのカテゴリー一覧には商品が1件も出ない（2026-10-12 実測）。網羅するなら隠れた検索 API を使うことになり、それは C で不可 |
| C. 検索窓の裏の外部検索サービス（別ホスト）や推測した検索引数を機械で叩く | **不可** | 運営者が違う第三者ホストで、規約を読めていない。画面に出ていない経路を推測して叩くと、記録上は「迂回」に読める |
| D. ログインした状態のセッションで回す（会員登録後） | **不可** | 値段も JAN も非ログインで見えるので、ログインする理由がない。ログインすると会員 ID に直接紐づく（SD 判定29 §7 と同じ） |
| E. TLS/JA3 の偽装（`curl-impersonate` 等） | **不可（例外なし）** | CLAUDE.md §3.3-14 |

### 社長の一手は要りません

- 必要な情報（商品名・JAN・ケース入数・バラ入数・値段）は**非ログインの商品ページに出ています**（2026-10-12 実測）。照合のために会員になる必要はありません。
- 会員登録が要るのは**実際に買うとき**だけです。登録は §4.1（規約への同意）なので、従来どおり社長判断です。

### 事実の訂正（チケット3412行）

チケット3412行に「国分ネット卸は非ログインで卸値が見えず（実測）」とあります。**これは商品ページについては事実と違いました。**2026-10-12 に商品ページを1件、非ログインで開いたところ、`販売価格(税抜)`・`販売価格バラ(税抜)`・`推奨売価(税抜)`・`JANコード`・`サイズ(バラ)`・`賞味期限` が表示されていました。**値段が出ないのはカテゴリー一覧の方**です（一覧には商品そのものが出ない）。一覧を見て「見えない」と判断したものと推測します（推測です）。

## 4. 本件で本当に守るもの — 「登録を断られること」

規約がない以上、**訴えられる・会員資格を消されるという筋は、登録前の今はほぼ立ちません。**本件で失いうるものは次の3つで、重い順に並べます。

| # | 失うもの | 確率 | 影響 | 不可逆性 |
|---|---|---|---|---|
| 1 | **会員登録を断られる**（第3条2項「当社が不適切と判断した場合」）。理由は示されない | 低 | 中（国分は NETSEA 内の店舗でも買えるので、経路が全部消えるわけではない） | **高**（断られた後に覆す手段がない） |
| 2 | IP 単位で遮断される | 低 | 小〜中（照会が止まる） | 中 |
| 3 | 業務妨害の嫌疑（刑法233条・234条の2。Librahack 事件＝約1秒間隔で逮捕・20日勾留・起訴猶予） | 極小 | 最大 | 最大 |

**1が「確率は低いが戻せない」型なので、アラートを上げます。**ただし止める理由にはなりません。対策は「相手から見て、取引先候補が商品を確かめている以上に見えない量と速さにとどめる」ことで、§5 の数値はそのために置いています。

**当たらない法令（過大に脅さないために書きます）**

- **不正アクセス禁止法**：不該当。認証を突破・回避しません（非ログインの公開ページだけ）。
- **著作権法**：JAN・商品名・入数・値段は事実で、著作物ではありません。データベースの著作物性も、商品カタログ型では否定される類型です（翼システム事件・東京地判平13.5.25）。**ただし商品説明文と画像は著作物になりうるので取りません。**
- **民法709条**（同事件）：大量に複製して競合販売した場合に不法行為が認められた。当社は①社内の仕入れ判断にだけ使い②再配布せず③国分と競合しない、の3点で外れます。**外部へ出した瞬間に射程に入ります。**

## 5. 進めてよい範囲（条件つき可）— Amazon 起点・1 JAN＝1リクエスト

**照会する JAN は、当社が既に持っている Amazon 側の JAN（Keepa のキャッシュ・商品判定台帳・メーカー連絡先台帳の代表商品）に限ります。**国分の商品を網羅するための JAN の総当たり（連番や推測の JAN を作って引く）は不可です。

| # | 条件 | 数値／実装 |
|---|---|---|
| 1 | **間隔** | **10.0秒以上**（相手が数値を示していないため当社既定。Librahack の約1秒の10倍）。同時接続は1 |
| 2 | **1日の総リクエスト数** | **開始時 500回/日**。日付キーの**永続カウンタ**でプロセスをまたいで積算する（10秒×500回＝約83分） |
| 3 | **段階的な引き上げ**（§3.3-18 の「安全側から近づく」） | 停止トリガ（条件6）が**14日連続で一度も出なければ 1,000回/日**、さらに14日出なければ **2,000回/日**（10秒間隔で約5.6時間）。**2,000回/日を本判定の天井**とし、それ以上は再判定 |
| 4 | **実行の時間帯・在席** | **無人・夜間の実行を可とします**（SD と違い、拒否応答も会員契約もないため）。ただし**条件6の停止トリガが実装済みであること**が前提。実装前は在席時のみ |
| 5 | **照会の順番** | Amazon で売れている順（kz 再現値・monthlySold・ランクの順）に並べる。日次の上限に当たっても、**売れている JAN から先に済む**ようにする。上限は「調査の上限」ではなく「1日の速さ」であり、翌日は続きから再開する（§3.3-34） |
| 6 | 🔴 **停止トリガ** | **403／429／5xx／タイムアウト30秒／応答時間がその日の中央値の3倍超／CAPTCHA・ログイン要求・アクセス制限の画面** → **その日は即時打ち切り。同じ日には再試行しない。** |
| 7 | 🔴 **停止後の再開**（§3.3-18 の自動バックオフ） | 翌日、**間隔を2倍（10→20→40秒）・1日の回数を半分**にして再開。7日間トリガが出なければ1段戻す。**7日以内に2回目**が出たら7日間停止。**3回目**が出たら国分への自動照会は打ち切り、秘書に報告（**国分には連絡しない**＝§3.3-15） |
| 8 | **同じ JAN の再取得** | 7日に1回まで。**発注直前の値段の取り直し（§3.3-26）は別枠で可**（人が在席して1件ずつ） |
| 9 | **規約の変更検知** | 実行の冒頭で `agreement.aspx` と `robots.txt` を取得し、前回とのハッシュが違えば**その日は実行せず秘書に報告** |
| 10 | 🔴 **User-Agent で名乗る** | 例：`SatoySelect-lookup/1.0 (wholesale catalog check; contact: satoyselect@gmail.com)`。ブラウザを装う UA は使わない |
| 11 | **取る項目** | 商品名・JAN・ケース入数／バラ入数・値段（税抜・バラ・推奨売価）・サイズ・賞味期限・取り寄せ表示の有無。**画像・商品説明文は取らない。**酒類カテゴリーは照会しない |
| 12 | **置き場所と公開** | 値段は `agent_output/` と社内のスプレッドシートだけ。**PUBLIC リポには値段も商品ページの URL も書かない**（§7 の出所台帳で機械的に止める）。生 HTML は `agent_output/` に置き、**90日で整理**（削除は §4.1 なので、整理は秘書の承認を経る） |

| 14 | **空ページの判定** | 存在しない JAN も 200 で返る。**「無し」の判定はページの中身（商品名・JAN 欄が空）で行い、「無し」と「取得失敗」を別の結果として返す**（§3.3-11。失敗を「無し」に畳まない） |

## 10. 実装担当への申し送り

1. **非ログインの商品ページを JAN で引く形だけを実装してください。**検索窓の裏の外部サービスや検索引数の推測はしないでください。
2. **条件2（永続カウンタ）・6（停止トリガ）・7（自動バックオフ）・9（規約の変更検知）・10（名乗る UA）・14（「無し」と「失敗」を分ける）を先に入れてください。**この6つが入るまでは、無人では動かさないでください。
3. 照会する JAN は**売れている順**に並べてください。
4. 値段の列は `agent_output/` と社内シートにだけ書いてください。§7 の台帳登録が済むまでは、成果物に国分の値段を書かないでください。

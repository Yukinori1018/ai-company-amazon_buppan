# ログイン延命と「切れた」検知（T-20260920-003 / 2026-10-12）

社長指示：「何回かログインが切れて私にお願いしたが、そうならないような工夫をあなたでやって。最初の設定は私も手伝う」

## 仕組み（1行）

社長の Chrome に「延命ウィンドウ」を1枚置き、その中のタブを launchd が10分ごとに見て、期限の来たサイトだけ読み込み直す。ログイン画面に飛ばされていたら `ALERT_<サイト>.txt` を書き、Mac の通知を出す。

| ファイル | 役割 |
|---|---|
| `login_keepalive.py` | 本体。純ロジック（判定・間隔）と Chrome 操作（AppleScript）を分けてある |
| `sites.json` | 対象サイト・URL・間隔・「切れた」と判定する URL。**間隔はここだけ直せばよい** |
| `keepalive_window.html` | 延命ウィンドウの1枚目のタブ。ウィンドウを見分ける印＋社長向けの説明 |
| `test_login_keepalive.py` | `python3 test_login_keepalive.py` |
| `com.aicompany.amazon-buppan.login-keepalive.plist` | `~/Library/LaunchAgents/` に置いたものの写し |
| `/.claude/scripts/login-keepalive.sh` | 入口（`setup` / `check` / `status` / `stop` / `start`） |

状態・ALERT は `workspace/output/agent_output/T-20260920-003/login_watch/`（gitignore）。秘書は朝に `STATUS.md` と `ALERT_*.txt` を見る。

**扱わないもの**：パスワード・Cookie・認証情報。ログインの入力は自動化しない（社長の一手）。延命ウィンドウ以外のタブの URL・タイトルは読まない（AppleScript 側で1枚目のタブの印だけ見て絞る）。URL のクエリはログに残さない。

## サイト別：切れる原因／対策／社長が最初に1回やること

| サイト | 切れる原因（分かったこと） | この仕組みの対策 | 社長が最初に1回やること |
|---|---|---|---|

| amazon.co.jp（購入側） | 通常は長期保持。Cookie 削除・別ブラウザで切れる | 30分ごとに再読込（アカウントサービス） | ログイン時に「ログインしたままにする」にチェック（10/12 時点ではログイン中） |
| Gmail（satoyselect） | Google は長期保持。`u/1` の並びがずれると別アカウントが開く | 3時間ごと。タイトルで別アカウントを検知 | なし（10/12 時点で正常） |
| スーパーデリバリー | ログイン画面に「保持」のチェック欄が無い。寿命は未公表 | 1時間ごと・7〜24時＝1日17回（§3.3-18 の30回以内）。エラー時は間隔を自動で2倍 | 延命ウィンドウの SD のタブでログイン（10/12 時点で切れている） |

| Shopee・Lazada・Payoneer | 未開設 | `sites.json` に `enabled:false` で用意済み | 開設したら秘書に言う（URL を実画面で確かめて有効化） |

### Chrome と Mac 側（全サイト共通・1回だけ）

| 確認すること | 場所 | なぜ |
|---|---|---|
| 起動時に「前回開いていたページを開く」 | Chrome 設定 > 起動時 | これ以外だと Chrome を閉じたときにセッション Cookie ごと消える＝全サイト一斉に切れる |
| 「すべてのウィンドウを閉じるときにサイトデータを削除する」が**オフ** | Chrome 設定 > プライバシーとセキュリティ > サードパーティ Cookie（サイトデータ） | オンだと毎回全部消える |
| 延命ウィンドウを閉じない（最小化は可） | — | 閉じると延命が止まる（ALERT_window が出る） |
| スリープさせない（電源アダプタ接続時「ディスプレイがオフのときに自動でスリープさせない」） | システム設定 > バッテリー（または省エネルギー） | スリープ中は launchd も Chrome も止まり、夜の間に切れる。**これは社長の判断**（電気代・発熱とのトレードオフ） |
| 初回に「"python3"（または "bash"）が "Google Chrome" を制御しようとしています」が出たら「OK」 | 画面のダイアログ | 10/12 の launchd 実行では出ずに通った。出た場合だけ |

秘書は Chrome の設定画面を社長と一緒に開いて確認してよいが、Cookie の中身は読まない。

## 運用

```bash
.claude/scripts/login-keepalive.sh status   # 状態
.claude/scripts/login-keepalive.sh setup    # 延命ウィンドウが無ければ作り、全サイトを今すぐ確認
.claude/scripts/login-keepalive.sh check    # 全サイトを今すぐ確認（社長がログインし直した直後に）
.claude/scripts/login-keepalive.sh stop     # 一時停止（start で再開）
launchctl print gui/$(id -u)/com.aicompany.amazon-buppan.login-keepalive | grep -E "runs|last exit"
```

- 延命ウィンドウを社長が閉じた場合、**勝手に出し直さない**（10分ごとに窓が出てきて邪魔になるため）。作り直すのは `setup` のときと Chrome が再起動したときだけ。
- `ALERT` の「最後に OK だった時刻」と検知時刻の差が、そのサイトのセッションの実際の寿命。延命しても切れるサイトは `every_min` を縮める（SD は §3.3-18 の1日30回以内で）。
- 社長がログインし直すと、次の巡回で ALERT は `resolved/` へ移る（削除はしない）。

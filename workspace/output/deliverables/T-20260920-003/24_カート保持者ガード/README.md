# 発注前カート保持者ガード（cart_guard）

**CLAUDE.md §3.3 の3点チェックを、人間の目視に依存せず機械で回すツールです。**
入力は ASIN のリスト、出力は **GO / NO-GO / UNKNOWN** の3値と、その根拠。

- チケット: T-20260920-003
- 作成: 2026-09-30 / IT エンジニア タカシ
- 作った理由: 2026-09-30、商品ページの `#merchant-info` という **1つの要素だけ**を読んで
  「販売元＝第三者」と判定し、**Amazon 本体がカートを持つ ASIN（B0FVL8QST6）を12点発注させた**。
  社長の指示は「そのほかの商品では絶対このようなことがないようにしてくれよ」。

---

## 0. このツールが守っている3つの約束

1. **1つの根拠で GO を出さない。** カート保持者は独立した3つの根拠を突き合わせ、
   **2本以上が一致して初めて** PASS。1本でも「Amazon 本体」を指したら、多数決を取らずに即 NO-GO。
2. **判定不能は NO-GO ではなく UNKNOWN。** そして **UNKNOWN は GO ではない**。
   「データが無い＝安全」という誤りを構造的に潰してあります（fail-closed）。
3. **オファー一覧が打ち切られていたら UNKNOWN。** `offers=20` では21件目以降が返りません。
   「返ってきた20件に本体が居ない」は「本体が居ない」ではない、と扱います。

## 1. 使い方

```bash
cd workspace/output/deliverables/T-20260920-003/24_カート保持者ガード

# ASIN を直接（結果は標準出力）
python3 cart_guard.py B0DJNX12KZ B0FN3NWKYZ

# CSV から（既定の列名は asin。--asin-column で変更）
python3 cart_guard.py --csv ../../../agent_output/T-20260920-003/候補.csv --asin-column ASIN \
  --out-csv ../../../agent_output/T-20260920-003/判定.csv

# 投げる前にトークン消費だけ見る
python3 cart_guard.py --csv 候補.csv --dry-run

# 生レスポンスを保存 → あとからトークン0で何度でも再判定
python3 cart_guard.py B0DJNX12KZ --save-raw raw.json
python3 cart_guard.py --from-json raw.json

# ロジックのテスト（ネットワーク・トークンを使いません）
python3 test_verdict.py
```

**終了コード**は GO 以外が1件でもあれば `1`。`python3 cart_guard.py ... && 次の処理` の形で、
NO-GO/UNKNOWN が混ざったまま後続処理へ進むのを止められます。

### ファイル構成

| ファイル | 役割 |
|---|---|
| `verdict.py` | **判定ロジック（純関数）**。Keepa を知らない。全分岐がテスト可能 |
| `keepa_client.py` | Keepa API ラッパー。差し替え（SP-API 等）はここだけ直せば済む |
| `cart_guard.py` | CLI。入出力と表示だけ |
| `test_verdict.py` | 15件のテスト。`python3 test_verdict.py` |

APIキーは `KEEPA_API_KEY` 環境変数、無ければ `~/.config/ai-company-amazon-buppan/keepa.env`。
**リポジトリには置きません**（このリポは PUBLIC）。

## 2. 3点チェックの中身と判定基準

### チェック1: カートの販売元（誰がいまカートを持っているか）

独立した3根拠 ＋ 期間統計の4本立て。Amazon.co.jp 本体のセラーID は `AN1VRQENFRJN5`。

| 根拠 | 取得元 |
|---|---|
| A | `stats.buyBoxIsAmazon`（Keepa が直接くれる真偽値） |
| B | `stats.buyBoxSellerId`（セラーIDそのもの） |
| C | `buyBoxSellerIdHistory` の最終エントリ |
| D | `buyBoxStats` — 統計期間中に本体がカートを何%取ったか |

- A〜C の**どれか1本でも本体**を指したら **FAIL**（多数決にしない）
- D で本体の獲得率が **1%以上**なら **FAIL**（いま第三者でも、本体が出入りしている棚）
- 既知の根拠が **2本未満**、または根拠どうしが**食い違ったら UNKNOWN**
- 3本一致で第三者のときだけ PASS

### チェック2: Amazon 本体の在庫履歴

`outOfStockPercentage365[0]`（本体の365日在庫切れ率）を使います。
**スナップショットの `availabilityAmazon` は使いません**（既知の罠：候補が93%過大になる）。

| 条件 | 判定 |
|---|---|
| 本体の年間在庫率が **2%超** | FAIL |
| 直近90日の本体在庫率が **1%超** | FAIL（現役の本体棚） |
| 年間在庫率が 0%超 2%以下 | PASS（要注意の警告つき） |
| 年間在庫率 0% | PASS |
| 値が取れない（`-1`／欠落） | **UNKNOWN** |

### チェック3: 出品一覧の実数

`liveOffersOrder` で**いま生きているオファーだけ**に絞り、新品（`condition` 0/1）を数えます。
同一セラーの重複出品（FBA＋自己発送）は出品者としては1つに畳みます。

- ライブの新品オファーに **本体が混ざっていたら FAIL**
- `stats.current[COUNT_NEW]` が取得上限を超えていたら **UNKNOWN**（一覧が打ち切られている）
- PASS のときは **本数 / 出品者数 / FBA・自己発送の内訳**を出します

### 総合判定

| 3点の状態 | 総合 |
|---|---|
| 1つでも FAIL | **NO-GO**（調べた結果、駄目だと分かった） |
| FAIL は無いが1つでも UNKNOWN | **UNKNOWN**（調べきれていない。**GO ではない**） |
| 3点すべて PASS | **GO** |

## 3. トークン消費（実測 2026-09-30）

1リクエストに `stats=365` `history=1` `buybox=1` `offers=20` を付けています。4つとも
3点チェックのどれかに必要で、外すとそのチェックが UNKNOWN になります。

| 実測 | 消費 | 1 ASIN あたり |
|---|---|---|
| 2 ASIN | 12 | 6.0 |
| 3 ASIN | 16 | 5.3 |

**見積りは 1 ASIN = 6 トークン**（上振れ側を取る）。契約プランの回復は **20 トークン/分**
（＝1分で約3 ASIN、1時間で約200 ASIN、1日で約4,800 ASIN）。

| 件数 | 消費見積り | 回復にかかる時間 |
|---|---|---|
| 10 | 60 | 3分 |
| 100 | 600 | 30分 |
| 500 | 3,000 | 2時間30分 |

`--dry-run` で投げる前に見積りが出ます。`--save-raw` で保存しておけば、判定基準を変えて
**何度再判定してもトークンは 0**（`--from-json`）。基準を触るときは必ずこれを使ってください。

> `offers` を外すと 1〜2 トークン/ASIN まで落ちますが、チェック3が UNKNOWN になるので
> §3.3 の用途では外せません。**広く絞り込むのは既存の抽出スクリプトで行い、
> このツールは「発注直前の最後の関門」として絞り込んだ候補にだけ当ててください。**

## 5. このツールが**やらないこと**（重要）

- **実画面の確認は代替しません。** CLAUDE.md §3.3 は「社長の Chrome（キーゾン入り）で
  実画面を見る。API だけで済ませない」と定めています。このツールは §3.3 の①②③を
  機械で当てる部分だけを担当します。**GO が出ても、発注直前の実画面確認は残ります。**
- **採算は見ません。**「売れる棚か」だけを判定します。利益は経理（ハジメ）の担当。
- **出品制限（ゲート）は見ません。** 別の確認です。
- **書き込み系の API を一切呼びません。**発注も申請も行いません（§4.1）。

## 6. 出力の置き場（PUBLIC リポの注意）

出力には Keepa の**履歴由来の値**（在庫切れ率・カート交代の統計）が入ります。これは
成果物08「Keepa 由来データの公開基準」の **B クラス＝非公開**です。

そのため `--out-csv` `--out-json` `--save-raw` が `workspace/output/deliverables/` や
`workspace/tickets/` を指していると、**ツールが実行前に止めます**。
出力先は `workspace/output/agent_output/<ticket_id>/` にしてください。

## 7. 既知の制約

1. **Keepa の更新遅延。** カート保持者は Keepa がその ASIN を最後に巡回した時点の値です。
   発注の直前に実画面を見る理由がここにあります。
2. **`offers=20` の上限。** 出品者が多い棚は UNKNOWN になります。必要なら `--offers 50`
   （トークンは増えます）。ただし出品者20社超の棚は、そもそも §3.2 の競合基準で落ちるはずです。
3. **本体が「これから出てくる」ことは予測できません。** 履歴に本体が居ない棚でも、
   売れ始めれば本体が入ってきます。これは判定ではなく監視の仕事です（未実装）。
4. **バリエーション（親子）は見ていません。** 親の family で本体が居るケースは、
   子 ASIN 単位のこの判定では拾えません。§3.2 の販売数と同じ注意が要ります。

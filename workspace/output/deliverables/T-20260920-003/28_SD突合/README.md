## 0. 先に伝えるべきこと（発注内容に1点だけ異論があります）

依頼は「2,175社の商品を列挙してシートに積む」でした。**列挙そのものは可能ですが、これだけでは判定に届きません。**理由は3つ、いずれも実測です。

| # | 事実 | 出典 |
|---|---|---|
| 1 | **一覧ページに JAN が無い。**`/p/do/dpsl/<dealer_id>/all/<pg>/` の HTML に「JAN」は0件。JAN は**商品ページ**にしか出ない | 2026-09-30 実測（丸進 102452 の1ページ目・HTML 全文検索） |
| 2 | **SD 商品ページの JAN 記載率は 71%（27/38）。**29% は JAN が無く、Amazon と機械で突合できない | 2026-09-20 実測（27_卸サイト横断調査） |
| 3 | **仕入れ先起点の探索は歩留まり 15%。**「卸にあるものが Amazon で売れているか」を問うと実測で85%が「市場が無い」で落ちた | CLAUDE.md §3.3-9（2026-09-30・N=55） |

**当社の商品規模**：SD 全体で 2,213,533商品／3,446社 → 1社平均642点。**2,175社なら約140万点**。一覧ページは120点/ページなので**約11,600ページ**。1ページ2.2秒でも約7時間、JAN を取るなら**140万ページ**で現実的ではありません。

### そこで、2本立てにしました

| レーン | 向き | 何をするか | 誰が回すか | 規模 |
|---|---|---|---|---|
| **A：索引レーン**（依頼どおり） | 仕入れ先 → 商品 | 2,175社の商品を**商品名＋商品コード＋卸価格**で列挙してシートに積む。**JAN は取らない**（一覧に無いので） | 索引の骨（商品名・コード）は `sd_dealer_index.py` が**非ログインの HTTP** で。**卸価格の上書きだけ**カズヨがブラウザで | 約11,600ページ |
| **B：突合レーン**（本筋・§3.3-9） | **Amazon → 卸** | Amazon で売れている ASIN の JAN を `sd_jan_lookup.py` に投げ、**SD に在るか／どの企業が持つか**を1リクエストで判定 | **非ログインの HTTP だけで完結**（ログイン不要） | **1 JAN = 1 リクエスト** |

**B は A の 1/100 のコストで、判定に直結します。**A を止める必要はありません（棚の全体像と企業の得意分野が見えるのは資産です）が、**「次の1件を決める」のは B です。**どちらを先に回すかはカズヨの判断でお願いします。

## 1. ファイル

## 3. 罠（先に踏んでおきました）

| 罠 | 対処 |
|---|---|
| **www は連続取得で Cloudflare に落ちる**（2026-09-20 に190件で失敗・2秒間隔でも復帰せず） | `sd_dealer_index.py` は `Just a moment` を検知したら**その場で保存して終了**。間隔は既定2.2秒。日を分ける前提で書いてあります |
| 一覧ページに JAN が無い | 上記 §0。JAN は商品ページか JAN 検索で |
| `?pg=` と `/all/<pg>/` の混在 | 正規は `/all/<pg>/`。`?pg=` も同じ結果だが将来変わりうる |
| **商品コードと品番は別物** | URL に出るのは `product_code`（例 13421612）。品番（メーカー型番）は商品ページ内 |
| 卸の「1個」と Amazon の「1個」が違う | 一覧に出る卸価格は**1点の値段**。「1セット（N点）」が最小ロット。**原価＝卸単価 × Amazon 側のセット数**（CLAUDE.md §3.3-7） |
| **卸価格・卸率・卸サイトの商品URLは PUBLIC リポに書けない** | シートと `agent_output/` のみ。本フォルダのコードにも実額は埋め込みません |

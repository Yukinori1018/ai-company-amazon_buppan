## 5. 🔴 今日いちばん大事な発見：**python の urllib は 429 で全部弾かれる。curl は 200 を返す。**

**2026-09-30 実測。**同じ URL・同じ User-Agent・同じヘッダで、**urllib は 429 / curl は 200**。curl を3回連続で叩いても 200 のままでした。

| クライアント | 結果 |
|---|---|
| `curl -sL --compressed -A <UA>` | **200**（3回連続で再現） |
| python `urllib.request`（最小ヘッダ） | **429** |
| python `urllib.request`（Accept / Accept-Language / Sec-Fetch-* まで揃えたブラウザ同等ヘッダ） | **429** |

**原因は TLS フィンガープリント（JA3）による判定と推測（確度：中）。**ヘッダを揃えても直らないので、判定はヘッダより手前で行われています。`requests` / `httpx` も同じ TLS スタックなので同様に弾かれる見込みです。

> **これを「レート制限」と読み違えて半日を失いかけました。**
> 8→16→32→64秒のバックオフを入れても復帰しないのは、待てば直る種類の 429 ではなかったからです。
> **対処：HTTP クライアントは `curl` をサブプロセスで呼ぶ。**`_fetch.py` に切り出して3本のスクリプトが共有しています。

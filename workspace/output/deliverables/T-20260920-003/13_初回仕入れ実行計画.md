## 0. 結論（先に読む3行）

1. **カズヨの推奨（3SKU・各10点・5万円）は方向として正しい。ただし SKU の中身と発注の順序は変えるべきです。** 買う前に決まっていない変数が2つ（卸値・ゲート）あり、**SKU を先に決めてから卸値を見る順序だと、高い確率で「全部落ちる」で終わります**。順序を逆にします（卸値を見てから SKU を決める）。
2. **推奨は B 案：グンゼ2SKU × 各12点 ＋ キャラクター品2SKU（30日で売り切れる量）＝ 発注 約4.2万円・総支出 約4.6万円。** 期待値は **＋7,900円**（楽観+30,000 / 中央+11,000 / 悲観▲12,000）。**現金リターンを目的にしてはいけない規模**です。取りに行くのは上の3つ。
3. **最悪ケース（出品できずに処分）でも現金の減りは約2.5万円。運転資金200万円に対して1.2%で、予備25万円には一切触りません。** この発注で資金条件が壊れることは構造上ありません。だから**迷うべきは「いくら賭けるか」ではなく「何を確かめる順序か」**です。

### 結論を1行にすると

> **この棚の利益は「供給が薄いことで価格が上代を超えている」ことから出ています。だから儲かるし、だから壊れやすい。** 1SKU に厚く入れず、価格を2,500円より上に置かず、30〜60日で売り切る量だけ入れる。

成果物 **04 §「最大の減点はバリエーション」** は、月間販売数を家族合計と読み、
「1バリエーションは月8個 → 出品者2社と分けて月2.7個 → 初回10点で消化3.7ヶ月」と結論していました。
**この減点は消えます。** 成果物 **09 §1** が Keepa 公式の構造定義（`monthlySold` — *"The value is variation specific."*）を一次で取り、
**同一家族の兄弟で値が割れる**ことを実データで確認済みです（本件の候補でも、同じ家族の3兄弟が 200／100／100 に割れています）。

| | 04 の前提（誤） | 訂正後（09） |
|---|---|---|
| 月100個の意味 | 12サイズ・色の合計 | **その ASIN 単体の実数（Amazon 公表値・推計ではない）** |
| 1ASIN の月販 | 約8個 | **100個以上** |

### 訂正② 販売手数料は**税抜表示**なので ×1.1 が乗ります

公式料金ページの注記：「**販売手数料のみが税抜きで計算され**、その他のすべての手数料には適用される税金が含まれます」。

1点あたり **15〜35円** 不利側に動きます。本計画の表はすべて ×1.1 で計上済み。

服&ファッション小物の販売手数料は **750円超〜2,500円以下 8.4%／2,500円超〜3,000円以下 12.4%**。

## 2. 判定式（SKU ごとの「原価上限」の作り方）

社長の既定（利益率20%以上・粗利額500円以上）を、**1点あたりの原価上限（税込）**に翻訳します。これが発注の合否そのものです。

```
原価上限(税込) = min(
    中央想定売値 × 0.80 − 販売手数料(税込) − FBA配送代行 − 62円 ,
    中央想定売値 − 500円
)
  ・中央想定売値 = 現在価格 × 0.85（新規参入は相場を下げる方に効くため保守側に置く）
  ・62円 = FBA納品送料25 ＋ ラベル貼付・梱包32 ＋ 保管5（成果物 10 の仮定を踏襲）
  ・免税事業者なので卸価格は必ず ×1.1 して原価に入れる
```

**丸進で既に分かっている1点の実測は「卸率67%（上代比・税抜）」**（成果物 07／実額は SD 会員規約17条1項により非掲載）。
これを税込に直すと **上代の73.7%**。つまり丸進の条件が67%で一定なら、通過の必要条件は

> **上代 ≤ 中央想定売値 × 0.64** ＝ **Amazon の中央想定売値が上代の1.56倍以上あること**

肌着は通常 Amazon 実売が上代を下回るので、**この条件を満たすのは「供給が薄くて価格が上代を超えている棚」だけ**です。
候補56件がまさにその状態（Amazon 本体不在・出品者1〜2社）であり、**それがこのレーンの利益の源泉**です。同時に**それが最大の脆さ**です。

## 5. 予算配分 — 5万円は「妥当。ただし上限を6万円に置く」

| 費目 | 金額 | 備考 |
|---|---|---|
| 商品代（B案・原価上限で買った場合） | 約42,000円 | 実際の卸値が上限より安ければ点数を増やす（下記ルール） |
| SD 3,000円OFFクーポン | **▲3,000円** | **2026-09-30 前後で失効**。初回の6%に相当 |
| 丸進 送料 | **0円** | 本州・**〔SD会員限定の取引条件のため非公開〕。B案は条件を満たす |
| FBA ラベル貼付（Amazon 代行 22円/点・38点） | 約840円 | 自分で貼らないための費用。社長の物理作業を減らす |
| FBA 納品送料（1箱・ヤマト） | 約1,500円 | 集荷を使う |
| 検品（案X＝社長宅の場合） | 0円 | 案Y（外注）なら +6,000〜9,000円 |
| **総支出** | **約41,300円**（案X）／**約48,000円**（案Y） | 上限 **6万円** |

**予算を増やすべきか減らすべきか** → **増やす必要はありません。減らす理由もありません。**
理由：**この段階でのボトルネックは資金ではなく「原価上限を通る SKU の数」**です。運転資金200万円に対して4〜6万円は3%で、
仮に倍にしても期待値は倍になりません（**通る SKU がなければ金額を積めない**）。
**卸値が上限より安かった場合だけ、同じ SKU の点数を増やして 6万円まで使ってよい**——これが正しい使い方です。

> **点数の増やし方（発注時のルール）**：実卸値が原価上限の80%以下だった SKU は、**60日取り分まで**点数を増やす。
> 90%以下なら 30日取り分まで。90%超（＝ぎりぎり通過）なら **10点で止める**。

## 9. 失敗したらどうなるか（最悪ケースの現金）

§4 の「悲観」よりさらに下、**確率5%前後の最悪ケース**を置きます。**定義**：発注は済んだ／日本ストアが再開しない、またはゲート解除が通らず出品できない／在庫を Amazon 以外で処分。

| 項目 | 金額 |
|---|---|
| 商品代（B案・クーポン適用後） | ▲39,000円 |
| ラベル・納品送料（納品まで進んだ場合のみ発生） | ▲2,300円 |
| 在庫の処分回収（定番肌着中心・回収率40%と仮定） | ＋16,000円 |
| **現金の純減** | **約▲25,000円**（納品前に止まった場合は **約▲23,000円**） |

- **運転資金200万円に対して 1.2%。予備25万円には触りません**（200万 − 2.5万 ＝ 197.5万）。
- **12ヶ月累計キャッシュ＞0（中央）の設計条件も崩しません**。中央シナリオでは+11,000円のプラス寄与です。
- **最も痛い失敗は現金ではなく時間**です。①が通らず10/10 に発注中止となった場合、**11/30 の SD 条件に間に合わせる余裕が消えます**。
  ですから §7 の①②を**9/24〜9/27 に必ず終わらせる**。ここだけが本当のクリティカルパスです。

## 11. やらないこと（全方位は戦略ではない）

1. **新規 ASIN を作らない。** セット組成・GS1 事業者コードの取得（27,500円＋**自宅住所が公開される**）・製品コード免除申請は**今期やりません**。既存 ASIN への相乗りだけで56件の棚があります。
2. **丸進以外の SD 出展企業を今周は開拓しない。** 1周目は1社に集中し、卸 → 検品 → FBA → 販売の1本を完走させる。判明48社の35%が Amazon 不可という事実（成果物 01）の前で、社数を増やしても通らない相手が増えるだけです。
3. **低単価品を追わない。** **粗利額500円未満は入口で落とす**（ハンカチ・歯ブラシ・シール単品）。ホーム&キッチン／文房具（販売手数料15.4%）の1,000円台は構造的に通りません。
4. **価格を2,500円より上に置かない**（服&ファッション小物）。上振れ相場を取りに行かず、手数料の崖の手前で止める。
5. **1SKU に厚く入れない。** この棚の利益は供給が薄いことから出ています。**自分の在庫で前提を壊すのが、この計画で最も起こりやすい失敗**です。

## 12. マサル（シミュレーター）に検証してほしい3点

1. **「供給が薄い棚に自分が入ると価格が崩れる」の崩れ方。** 出品者2社の棚に3社目として入り、在庫12点を投入したときの価格と消化の推移。私は中央想定売値を現在価格の85%に置きましたが、**この係数が0.7だと B案は中央でも赤字**になります（原価上限が約200円下がる）。ここが計画の最大の感度です。
2. **§7 の②（請求書の名義）が「ラクーン名義のみ」だった世界。** ゲート解除の目的が消えたとき、B案の点数（12点×2）は正当化できるか。A案に落とすべきか、そもそも発注をやめるべきか。
3. **11/30 の SD 条件に間に合わない確率。** 本人確認 → 審査 → 再開 → 納品 → 反映の各段に遅延を入れたとき、**11/30 に出品が見えている確率**。ここが50%を割るなら、**発注より先に「SD へ 11/30 条件の照会」を社長承認で出す**順序に組み替えるべきです。

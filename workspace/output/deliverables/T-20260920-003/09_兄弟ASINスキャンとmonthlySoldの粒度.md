## 1. `monthlySold` の粒度検証（問い1）

### 一次情報

Keepa 公式（Keepa 自身が保守する product object の構造定義）より、`monthlySold` の説明を原文のまま：

> "How often this product was bought in the past month. This field represents the bought past month metric found on Amazon search result pages. **It is not an estimate.** null if it has no value. Most ASINs do not have this value set. **The value is variation specific.**"

同じ定義ファイルから対照として：

> `salesRanks` — "Contains subcategory rank histories. Each key represents the categoryId of the rank with the history in the corresponding value."
> `salesRankReference` — "The category node id of the main sales rank."

**ランク側の定義には「variation specific」に相当する記述がありません。** `monthlySold` だけが明示的にバリエーション固有だと言っています。列名から推測せず定義に遡った結果、**2つのフィールドで粒度が違う**ことが分かりました。

あわせて **`monthlySold` は Amazon の検索結果に出る「先月N点購入」そのもの**で、Keepa の推計値ではありません（"It is not an estimate."）。

## 3. 唯一の候補 B0C1JBSF87（マイメロディ 304981）の精査

問い2の「本体がいない兄弟を名指し」に対する答えは**この1件**です（304832 は 07 で判定済み）。

### 現況

| 項目 | 値 |
|---|---|
| Amazon 本体 | **なし**（2026年夏に撤退。時期の詳細は完全版） |
| カート | **成立していない** |
| 稼働オファー | 3社・**全員 FBA・新品** |
| 着地価格 | 1,683 円（最安）／1,700 円／1,980 円 |
| 月間販売数 | **表示なし**（2026年夏に消滅＝月50個未満） |
| 紹介料率 | 12%（実効 12.42%）／ FBA 配送代行 420 円 |
| EAN / 品番 | 4550337304983 / 304981 |
| Amazon 登録日 | 2023-04-06 |

**Amazon 本体が抜けた直後に最安価格が跳ね上がり、同時に月間販売数の表示が消えました。値上げした結果売れなくなった、という順序です**（時系列は完全版）。

3社とも FBA なのにカートが付かないのは、**Amazon が価格が相場から乖離していると判断している**ときに起きる状態です（推定）。07 の 304832 はカートが1,280円で付いており、そちらは乖離していません。

### 採算（出典：Keepa API 2026-09-20 取得の紹介料率と FBA 手数料）

**ケースA：今の最安 1,683 円で売れたら**

```
売値 1,683 − 販売手数料 12.42%（209円）− FBA 配送代行 420円 = 手残り 1,054 円
```

**ケースB：Amazon 本体が1,045円で戻ってきたら**

```
売値 1,045 − 販売手数料 12.42%（130円）− FBA 配送代行 420円 = 手残り  495 円
```

**丸進の卸条件はケースAの手残りには収まりますが、ケースBでは赤字になります**（具体的な取引条件は SD 会員規約17条1項によりここには記載しません。完全版を参照）。

**見送りを推奨します。** ケースAの数字は良いのですが、成立条件が2つとも怪しいです。

1. **月50個未満しか売れていない。** 以前は月数百個売れていた商品が、1,683円になった途端に表示が消えました。**この価格では需要がない**と実データが言っています。回転上限6ヶ月（既定）を満たせる確証がありません。
2. **Amazon 本体は2026年夏まで11ヶ月以上ずっといました。** 戻る前提で考えるべきで、戻ればケースBになります。しかも本体は在庫を持てば即カートを取ります。

`feedback_first_purchase_must_expect_success`（1件目は成功する気でやる）に照らすと、根拠が「本体がいない」という消極条件だけです。

## 4. 全体の結論

**SD 丸進 × サンリオ ミニマスコットホルダー（このファミリー全体）は成立しません。**

| 観点 | 事実 |
|---|---|
| 本体の支配 | 20件中 **16件でカート保持**、うち単品13件が1,100円 / 1,045円固定 |
| 本体がいない2件 | どちらも月間販売数の表示が消滅（月50個未満）。本体撤退後に値上げして売れなくなった |
| セット3件 | 本体のまとめ買いページ。単価×個数で完全一致。参入余地なし |
| 価格の天井 | **1,100円**。手残りは **550〜575円**（紹介料10〜12%・FBA 415〜420円を引いた後） |
| 丸進の条件 | **この手残りを上回るため、どの兄弟でも赤字**（金額は完全版） |

**損益分岐の卸率は売値の約50〜52%です。** 仕入れ値がカート価格の半分を超えたら、**Amazon 側を見るまでもなく落とせます。** この1行が丸進のカテゴリ選定にそのまま使えます。

### 次に見るべきもの（提案）

1. **SD 側で「卸率が売値の52%以下」を先に絞る。** Amazon 側を見る前に SD でフィルタすれば、Keepa のトークンを使わずに候補を落とせます。**契約が 10/3 までなので、トークンは「絞った後の検証」だけに使う**のが正しい順序です。
2. **Amazon 本体の有無を最初の門にする。** 今回のスキャンで、本体がいる ASIN は例外なく価格が固定されていました。`availabilityAmazon` は `offers` なし（**1トークン/ASIN**）で取れるので、**100件を100トークンで一次スクリーニングできます**。
3. **ランクは門に使わない。** family 共有で無意味です。使うのは **`monthlySold` の実値のみ**（`feedback_volume_sellers_only` の「入口は monthlySold、ドロップ数で代替しない」に**「ランクも代替にしない」**を足す形）。

## 判定は GO / NO-GO / UNKNOWN の3値

**UNKNOWN を GO に畳みません。**「調べれば分かる」と「調べて駄目だった」を混ぜると、次に何をすればいいのかが分からなくなります。

| # | チェック | 落ち方 |
|---|---|---|
| 1 | カートの販売元（独立3根拠の一致） | 本体なら FAIL／根拠が1本 or 食い違いなら UNKNOWN |
| 2 | 本体の365日在庫履歴（`outOfStockPercentage365`） | 在庫率が高ければ FAIL |
| 3 | 出品一覧の実数（ライブの新品オファー） | 本体が混ざれば FAIL／一覧が打ち切られていれば UNKNOWN |
| **5** | **メーカー直販・ブランド公式**（新規） | セラー名がブランド名を含めば FAIL／「公式」を名乗るが一致しない・オファー1社ならUNKNOWN |
| **単位** | **Amazon 側のセット数** | 個数が読めないセット品は UNKNOWN（原価の倍率が確定できない） |
| **仕入れ** | **卸の商品ページが特定済みか**（§3.3-6） | `購入先URL` が未確認なら UNKNOWN |
| **品目** | **賞味期限管理が要るカテゴリか** | ドラッグストア／食品・飲料／サプリは UNKNOWN＋「要期限管理」 |
| 採算 | 赤字・**実質赤字**・**手残りが誤差幅未満**・回転6ヶ月超 | 赤字は FAIL、誤差幅未満は UNKNOWN |

**落とすのはこの3つだけです**（2026-09-30 カズヨ訂正 / CLAUDE.md §3.1）:
①カート保持者が Amazon 本体 ②カート保持者がメーカー本人／ブランド公式 ③今の価格と今の卸値で1個あたり赤字。

⚠️ **月販（`monthlySold`）を GO/NO-GO のフィルタに使いません。**列には出しますが、それだけでは落としません。
`monthlySold` は月50個未満だと Amazon が表示しないだけで、「売れていない」ではありません
（社長が発注を決めた B0DJNX12KZ はキーゾン実測で月10個）。社長は条件を緩めています
──「最初は入口を多く持ちたい。利益が少なくても、量を増やせば、何とかなる可能性があるかもしれない。
やった後で評価し、継続判断を行う」（2026-09-30）。

1つでも FAIL → NO-GO、FAIL が無く UNKNOWN が残る → UNKNOWN、全部 PASS → GO。

### 仕入れが実在するかの段（§3.3-6）

**卸サイトの商品ページ URL が特定できていない行は GO にしません。**URL が無い＝在庫・入り数・卸値のどれも裏が取れていない、という意味です。

2026-09-30、利益率64.7%で断トツだった B0015XNJMW（オリヒロ 玉葱エキス粒 600粒）は、
§3.3 の3点（カート＝第三者・本体不在・キーゾン平均10個/月）を**通過**しましたが、
**Amazon の JAN 2本が NETSEA に1件も存在せず、仕入れ自体がありませんでした**。
私は「内容量の不一致を疑え」と申し送りましたが、疑うべきは**その前段の「買う先があるか」**でした。

**賞味期限管理が要るカテゴリ**（ドラッグストア／食品・飲料／サプリメント／栄養補助食品／酒類）は、
FBA の残存期間要件（60日以上で納品・45日で販売不可）と混合在庫の制約、
さらにカテゴリー型ゲート（ブランド申請では開かない）が絡むため、**UNKNOWN＋「要期限管理」**にします。初回の SKU には使いません。

### 手残りが誤差幅を下回る行は GO にしない

**誤差幅 = 売価 × 7% + 200円。**これを下回る手残りは「儲かる」でも「損する」でもなく**読み切れていない**ので、UNKNOWN にします。

| 項 | 根拠 |
|---|---|
| 売価 × 5% | BuyBox 価格の振れ。Keepa の値は取得時点のスナップショット |
| 売価 × 1.4% | 販売手数料の読みの差（Keepa の率を税抜とみて ×1.1 するか否か） |
| ＋200円 | 保管料・納品送料・梱包資材の 206円は**商品台帳 L001 という1点の観測**を全商品に当てている。大型・重量物では数倍になるので、全額を誤差と見る |

売価に比例させたのは、**高額品ほど誤差が大きい**からです。売価26,800円のソファカバーの手残り355円は、
誤差幅2,076円の中に埋もれています（利益率2.1%）。一方 3,900円の商品の手残り645円は誤差幅473円を超えます。
**固定の±300円では高額品を取りこぼし、低額品を通しすぎます。**

NO-GO ではなく UNKNOWN にしているのは、**人が実額（送料・サイズ区分・今の売価）を詰めれば GO になりうる**からです。

### 単位を揃える段（`set_count.py`）

**卸サイトは「1点あたり」で売り、Amazon は「N点セット」で売ります。**突き合わせる前に単位を揃えます。

2026-09-30、カズヨが実画面で発見。B0DJNX12KZ は Amazon 側が **【2点セット】…×2点セット**、
NETSEA 側は **1点920円（税抜）**。私は原価1,012円/個として**利益率33.3%・GO** と出しましたが、
正しい原価は **2,024円/個**で **手残り ▲227円/個**。損益分岐売価3,194円に対し売価2,980円。
**手数料をゼロにしても+278円**しか残らず、どう組んでも黒字になりません。バリエーション7種も全部「2点セット」系で単品版の ASIN はありません。

- 商品名の `【N点セット】` `×N点セット` `N個セット` `N枚組` `Nパック` `N袋` `セット数:Npcs` `ペアセット` を読み、**原価 = 卸単価 × N**
- **読めないときは 1 と決め打たず None → UNKNOWN**（人が見る）。1 にすると原価をN分の1に見誤ります
- 複数の読みが食い違ったら None（黙って片方を採らない）
- `set_num`（NETSEA の最小発注ロットの倍数）とは**別の概念**。`amazon_set_count` は**原価の倍率**、`set_num` は**発注数の丸め**
- 数えない語を持っています: 「600粒」「420ml」「幅30×奥行30」は個数ではない／「ヘッドセット」「簡単組立」「富士パックス販売」はセット品ではない

### チェック5（メーカー直販）の作り

`maker_direct.py`。Keepa の `/seller` でカート保持者の**名前**を引き、ブランド名・メーカー名と突き合わせます。

- 名前がブランド／メーカー名を含む → **FAIL**（`サンワサプライ直営【サンワダイレクト】`・`マーナ公式 アマゾン店`・`SOLCION公式ストア`）
- 「公式」「直営」を名乗るが、ブランド名との一致は取れない → **UNKNOWN**（人が実画面で見る）
- 新品オファーが1社だけ → **UNKNOWN**（「オファーが少ない」は有利の証拠ではなく、メーカーが1社で売っているサインのことがある）
- セラー名が取れない → **UNKNOWN**（「名前が無いから直販ではない」は 9/30 の事故と同型）

比較は法人格（株式会社・Co.,Ltd. 等）と記号を落として NFKC で畳んでから。短い英字の鍵（`ISM`）は完全一致のみ（`PRISM` に当てない）。

## 供給の蛇口 — `discover.py`（A案）

```bash
python3 discover.py --shops 20 --tokens 250     # 前回の続きのサプライヤーから
```

NETSEA の承認済みサプライヤー（**実測220社**）を少しずつスキャンし、0トークンで絞ってから Keepa に投げます。
スキャン済みのサプライヤーは `agent_output/T-20260920-003/pipeline/discovered.json` に記録され、
**次回は続きから**走ります。見つけた候補はそのまま `candidate_pipeline.py` のプールに入ります。

**0トークンで落とすもの**（NETSEA 側）: ネットショップ販売不可（`deal_net_shop_flag != 'Y'`）・JAN 無し・卸値無し。
**1トークン/コードで当てるもの**（Keepa `code` 逆引き）: JAN → ASIN。**ハズレの JAN は実質無料**。
1つの JAN に複数 ASIN がぶら下がったら、**売れ筋ランクが付いていて一番上位のもの**を採ります（最初の1件はただのくじ引き）。

## 既知の制約（正直に）

- **NETSEA の `set[].price` は「1個の値段」、`set_num` は「最小発注ロットの倍数」**として扱っています。人が実額で検算した3行（B0DJNX12KZ・B0FN3NWKYZ・B0171AC6PI）に合わせた解釈です。**一度これを割ってしまい、卸率1.5%・利益率71% という嘘の数字を台帳に書きました**（同じ実行で直しています）。JAN が同一でも入り数の違う口があると原価を読み違えます。**発注の直前は人が卸サイトで単価を見てください**
- **JAN 突合でしか卸値を当てられません。**JAN が無い候補は採算が計算できず UNKNOWN になります
- **キーゾンの列（平均月販・過去1〜3ヶ月）は埋めません。**Keepa の `monthlySold` を「平均月販」の欄に入れ、出所を明記しています。キーゾンは人が画面で見るものです
- **ゲート（出品許可）は判定しません。**全件「未確認」
- 赤字判定は「今の Amazon 価格」基準です。価格が戻れば成立する棚もありますが、**戻る前提の提案はしません**
- **`1個粗利` は成果物22・23 と同じ定義**（販売手数料＋FBA配送代行＋原価を引いたもの）で、保管料・納品送料・梱包資材を**含みません**。それらは `profit.OTHER_UNIT_COSTS_YEN = 206`（台帳 L001 実測）として別に持ち、**手残りがマイナスなら「実質赤字」で NO-GO**にします。シートの `1個粗利` 列は22・23 と揃えるため粗利のまま入れています
- `--asins` で ASIN を直接指定しても、**プールの卸値・手数料は引き継ぎます**。引き継がないと採算が計算できず、GO だった行を UNKNOWN で上書きします（9/30 に一度やりました）
- **内容量は `判定理由` の先頭に `【内容量 600粒】` の形で書いています。**台帳は32列固定（条件付き書式が列位置に紐づく）なので列を増やさず、人が最初に読む欄に置きました。列を1本増やす判断が出れば移します
- **セット数は商品名からの読み取りで、実物の確認ではありません。**「中身の量が違う」型のずれ（卸は300粒・Amazon は600粒 など）は**商品名では見抜けません**。`set_count.py` が拾えるのは「N点まとめ売り」だけです。**発注の直前は人が卸サイトと Amazon の両方で内容量を見てください**
- 販売手数料は **Keepa の率 ×1.1**（税抜表示とみなす）で計算しています。当リポの既定（成果物22・23、商品台帳 L001）に合わせた**いちばん保守的な**読みで、税抜のまま見る場合より手数料が1割高く出ます

- イシュー: 法務NOとされた情報取得経路について、NO の射程はどこまでか／同じ目的を適法に達成する手段は何か／NO のまま使った場合の実害の型と公開事例は何か——を事実として並べ、タケシと社長が選べる状態にする

## 0. 結論（先に5行）

1. 社内で NO とされた経路は 21 本。うち「NO」の決め手が条文で確定しているのは 11 本、「規約本文が読めない＝未確認（着手不可）」が 6 本、「条件付き可・要ハルオ判定」が 4 本。**NO の名宛人は例外なく「自動化された手段」または「API 契約者」**で、人が見る行為を禁じた条文は 1 本も無い（§1）。
2. Amazon 機械取得 NO の正面の代替は **SP-API（出品者自身の公式 API）**。大口要件は 9/12 の切替で満たしている。出品者数・カート価格・出品制限（ゲート）・手数料見積が公式に取れる。費用 0 円（第三者開発者向けの年 1,400 ドル課金は 2026-05 に撤回）。開発者登録＝規約同意 3 本で §4.1（§2-A）。
3. 需要の兆し（検索ボリューム）は **ブランド登録が前提**（Brand Analytics／商品機会エクスプローラー）。商標がない当社は、セラースプライト（月 13,998 円・契約決定済み未申込）か Keepa（契約済み）が代替（§2-D）。
4. SNS API は**費用構造が変わった**。X API は 2026-09 時点で定額プランが消え従量課金（投稿読取 1 件 0.005 ドル・月 300 万件上限）。Instagram Graph API はハルオ判定時「仕様非公開」だったが、公式に仕様が公開されている（ハッシュタグ検索 7 日 30 個まで・ビジネスアカウント要）。YouTube Data API は「30 日超の保存」と「複数チャンネルの集約」が禁止のまま（§2-E〜H）。
5. NO のまま使った場合の実害は、**訴訟ではなくプラットフォームの一存によるアカウント停止**（Amazon BSA §3 "if we determine"）。米国の公開判例は公開データのスクレイピングで事業者側が負け続けている（X・Meta とも 2024 に敗訴）が、当社の Amazon 出品アカウントの生死は裁判の勝敗と無関係に決まる（§3）。

- 社内に**時間の実測は無い**。T-20260906-006/01 の設計は「登録者 50 万人超の 10〜20 チャンネルを、新着から 24 時間以内に人が見て商品を特定」。社長の §4.1 一手の週上限は「週 5 件・50 分」がタケシの置き値（03 #9）。
- 試算（推測・確度低）：Amazon ベストセラー/急上昇の一覧 1 ページ（50 件）を「商品名・価格・出品者数（一覧上の表示のみ）」で流し見＝約 10 分。X/TikTok のトレンド上位 20 タグの確認＝約 5 分。週 30 分で「Amazon 2 カテゴリ＋SNS 2 本」が上限。**数字は Keepa に落とすので、目視の役目は「候補の発見」に限る**のが社内の既定（`knowledge_trend_sourcing_routes_jp` §5）。
- 目視の限界（事実）：出品者数・価格は「その時点」しか取れず、履歴も比較もできない。Amazon の目視は「1 商品ずつ、間を空けて」の条件付き（ハルオ 9/6）。

実装した条件

selection_rules.py（テスト11件つき）。パイプラインに入っていなかったものを1箇所にまとめました。

1. 蛍光灯を除外。ただし LED を含むものは残す

順番が命なので、先に LED かどうかを見てから蛍光灯を判定しています。

if not is_led(text):            # ★先に LED を見る
    for k in ("蛍光灯", "蛍光ランプ", "蛍光管", "グロー球", "点灯管", "安定器"):
        ...除外

直管 を無条件に落とす条件は書いていません。 テストで固定してあります
（test_直管を無条件に落とす条件を書いていない）。ご指摘のとおり、
それを書くと残すと決めた LED 蛍光灯まで消えます。

2. Amazon 本体ありを除外

Keepa の availability_amazon を使いました。列名から意味を推測せず、実データで確認しています。

availability_amazonパイプラインの「Amazon本体の有無」件数
-1なし10,292
0 / 2 / 3 / 4あり9,572

-1 だけが「本体なし」で、それ以外は全部「あり」という対応が全行で一致しました。

3. 知財ブランドはフラグのみ（除外しない）

ポケモン・サンリオ・ディズニー等。除外していません。「ゲート確認の対象」という印だけです。
50件中1件に付いています。

4. #1 電気用品を法務 v2 に置き換え

語彙をこちらに写経していません。 T-20260908-001/04_pse_rule_v2.py を読み込んで動かしています
（写経すると、法務が仕様を直したときに実装だけ古いまま黙って動き続けるため）。
テストで固定してあります（test_法務の語彙を写経していない）。

  • HARD → 除外（1A/1B/1C/1D/1E）
  • REVIEW → 除外しない。「PSE要書類確認」の印を立てて候補に残す
  • PASS → 何もしない（乾電池駆動など。v1 が誤って落としていた類型）

「通過＝発注可」にはしていません。 requires_document_check を立て、
CSV に「要書類確認(通過≠発注可)」列と法務の確認文（review_note）を出しています。
50件中3件が該当です。

直管形LEDを機械で判定していません。 電安法の対象/対象外が同じ商品名に混在して
判別できない、という法務の申し送りどおり、REVIEW で候補に残し、判断は人間の現物確認に委ねています。

4. 論点への回答

論点1「仕入れられそう」の操作的定義

社長の確定条件（従業員300人以下）を軸に、次の4条件のANDと定義します。

#条件判定材料判定力コスト
1日本に実体がある法人Keepa manufacturer／ブランド名の日本語＋JAN 45/49中（単体では不足）0円・取得済
2従業員300人以下 または 資本金3億円以下gBizINFO REST API v2（法人名の部分一致検索・従業員数・資本金あり）高。ここが決定打0円。トークン申請＝社長の手が1回要る
3中国系OEMでないCNスコア（本書 §3-1）中〜高0円・取得済
4第三者に卸しているブランド自社出品を除いた実セラー数≧2低（§論点5）0円・取得済

条件2を機械判定できるのは「日本語の商号が取れている会社」だけです。 メインレーン345社は全社が該当（日本語シグナルありが通過条件のため）。英字レーン201社は商号が引けないため gBizINFO が原理的に効きません（サトルの実測：英字526社への商号検索は不可）。この非対称性は設計として受け入れ、レーンを分けます。

従業員数が取れない会社をどうするか（私の設計判断）：落としません。 規模=不明 としてメインレーンに残し、末尾にソートします。理由は §論点7（母数が足りない）。落とした場合の実測影響は gBizINFO 実行後でないと出せないため、現時点では未測定です。

論点2 中国系ブランドの判定

§3-1 のとおり。要点は「セラー名だけでは足りない」こと。 OTTOCAST のように日本の転売業者しか並んでいない中国系ブランドが実在します。逆に S1（ブランド自社出品）は適合率86.1%と最も強力です。中国系ブランドは自分で日本にストアを出すため、これが構造的なシグナルになります。

誤検出の実例（CNスコア≧1 で誤って引っかかった16社）： BOS（クリロン化成・日本のSME）が S1 で発火しました。BOS-SHOP【メーカー公式】 という自社ストアを持っているためです。日本のSMEも自社ストアを出すので、S1単独では落とせません。 よって CNスコア≧1 は「除外」ではなく「英字レーンへの振り分け」に使います。CNスコア≧3（適合率100%）だけを確定除外にします。

論点3 大企業・版元の除外

  • 版元＝カテゴリで落とす。 適合率91.8%・再現率97.8%。名前を見る必要はありません。
  • 大企業＝gBizINFO の従業員数でしか落とせません。 現物で確認したとおり、メインレーンの最上位には依然として BANDAI・パナソニック・タカラトミー・東芝・富士フイルム・アイリスオーヤマ・バッファロー・CASIO が並びます。これらは全社、日本語商号が取れているので gBizINFO で必ず解決します。 社長の条件は、残った唯一の欠陥にぴったり合った道具です。
  • 残る穴（正直に）：外資の日本法人は従業員数が300人以下になり得ます。 ベンキュージャパン、アンカー・ジャパン、ツヴィリング J.A. ヘンケルスジャパン、マイヤージャパン、Implus Japan などです。従業員数フィルタを抜けます。 対策は「資本金が親会社100%出資の外資系」を別途フラグする（gBizINFO の 資本金＋法人番号の設立年で部分的に可）ですが、完全には解けません。人手確認の対象として残します。

論点4 カテゴリの適合性 → 母集団から外します

社長の指示どおり、Finder 条件から落とします。副次効果としてKeepaトークンが30.3%浮きます（候補プール3,575件中1,083件がメディア系）。

論点5 「卸してくれる証拠」の再定義

現行の「実セラー数≧2」の欠陥は、社長のご指摘どおりです。ただし修正の効果は小さいというのが実測結果でした。

定義メインレーン345社での該当評価
現行：実セラー数≧2100%ゲートとして機能していない
W1：ブランド自社出品を除く第三者セラー≧298.9%採用。 効果は小さいが、「ブランド自身しか売っていない」偽陽性を確実に消す
W2：+屋号型セラー≧159.7%不採用。適合率を下げる（§3-2）
W3：+屋号型セラー≧228.0%不採用。母数を7割削って適合率が上がらない

結論：セラー名から「メーカーが卸している証拠」を取り出す道は、ほぼ行き止まりです。 決定的な証拠はメーカー自身のサイトにある「卸・お取引・代理店募集」ページであって、Amazon 側のデータには無い。これは Keepa の抽出条件ではなく、Phase C の HP 巡回（T-20260831-001 でサトルが道筋を作った領域）で埋める項目として設計を移します。

論点6 リストの単位 → メーカー起点に組み替えます

実測が決定的でした。メインレーン345社の「1社あたりSKU数」は中央値1・平均1.76。 2SKU以上は97社しかありません。

これは商品起点で探しているから当然です。Finder が拾った1商品からメーカーを逆引きしているので、そのメーカーの他の商品は見えていません。メーカー仕入れの経済は「1回の交渉 → 複数SKU」で成り立つので、この構造では交渉1回あたりの見返りが最小になります。

設計変更：2段構えにします。

  1. Discovery（商品起点・現行どおり） — Product Finder で母集団をスキャンし、メーカーを発見する
  2. Expansion（メーカー起点・新規） — レーン判定を通過したメーカーだけ、ブランド名で Keepa を再検索して全SKUを列挙する

Expansion は通過メーカーにしか撃たないので、メディア除外で浮いた30%のトークンで十分賄えます。SKU100への効き方が根本的に変わります（§7）。

論点7 母数最大化との整合 — 矛盾しません。むしろ逆です

社長ご自身が今回、答えを言い切っておられます。

「いらない情報も含んで母数を増やしたら、リスト化の意味がないでしょ。母数を増やすのが第一目的でない。欲しい情報の母数を増やすのが目的。」（2026-08-31）

2026-08-24 の「厳選top100は的外れ」と、今回の「精度を上げろ」は同じことを言っています。増やす対象が「行数」から「連絡できるメーカー数」に定義され直しただけです。カズヨの理解（「母数は落とさず、使えないものを混ぜるな」）はこの線で正しい。ただしもう一段深い問題があります。

  • メーカー仕入れの標準稼働は 月530件の問い合わせ（EC STARs の実績値。HP整備で返信率46%→66.5%、合格ラインは返信率30%）
  • 現行パイプラインの実効母数は累計200社。月次ではなく累計です
  • 必要量の 3/8 しかありません

つまり、今のリストは「多すぎる」のではなく「圧倒的に足りない」。 1,254 という数字は見かけの母数で、そこから社長が連絡できるのは200社だけ。精度を上げる作業は、絞る作業ではなく「本当の母数がいくつなのかを可視化する作業」です。

したがって「やること」は絞ることではなく、以下2点で「欲しい情報の母数」を増やすことです。

  1. 浮いた30%のトークンを、中小メーカーが濃いカテゴリの深掘りに再投資する（メディアを叩くのをやめる）
  2. 除外は捨てない。レーンに分けて残す（英字レーン201社、法人化で開く149社は別ファイルで保持）

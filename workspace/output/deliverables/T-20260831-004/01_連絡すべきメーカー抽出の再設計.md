## 4. 新しい抽出設計

### 4-1. 母集団定義（`scan_v14.py` の変更点）

Finder の除外カテゴリに、再販/版元系の**ルートカテゴリIDを6つ足す**だけです。ID は v14 の生データから実測しました（推測ではありません）。

```python
# scan_v14.py L171 を差し替え
EXCLUDE_ROOT_CATEGORIES = [
    160384011,   # ドラッグストア（現行）
    52374051,    # ビューティー（現行）
    57239051,    # 食品・飲料（現行）
    # --- T-20260831-004 で追加。版元・取次を通す商流のため個人事業主が入れない ---
    561958,      # DVD
    561956,      # ミュージック
    465392,      # 本
    52033011,    # 洋書
    637394,      # ゲーム
    637392,      # PCソフト
]
```

効果：**入口の1,247社から333社（商品965件・全体の36.6%）が消えます。** ここに社長の時間を1秒も使わせません。

### 4-2. 判定ゲート（適用順・この順番に意味があります）

| 順 | ゲート | 条件 | 必要なAPI | 落ちる数 |
|---|---|---|---|---:|
| G0 | Finder | 現行の価格帯・ドロップ数・ランク条件（変更なし）＋上記カテゴリ除外 | Finder | ─ |
| G1 | カテゴリ | ルートカテゴリが再販/版元系でない | product（1トークン） | 333社 |
| **G2** | **日本実体（S級）** | JAN45/49 **or** メーカー名に日本語 **or** manufacturer（社名らしい）に日本語 **or** 日本法人格 — **1つでもあれば通す** | product（1トークン） | 485社 |
| G3 | 海外確定 | G2がゼロ、かつ 中国企業表記/ピンインセラー → 除外 | product | (485の内数27社) |
| **G4** | **卸証拠** | **独立セラー2社以上** かつ **うち国内事業者1社以上** | offers（6.5トークン） | 55社 |
| G5 | 規模 | 従業員300人以下（gBizINFO） | gBizINFO | 187社 |
| G6 | 実体 | メーカー名が商品名・作品名・PBでない | ルール | 24社 |

**G2 を offers の前に置くのが要点です。** 現行は全商品に offers（6.5トークン）を掛けてから捨てています。

| | トークン | 同じ予算で見られる商品数 |
|---|---:|---:|
| 現行（全件に offers） | 2,100件 × 7.5 = 15,750 | 1.00倍 |
| 新順序（G1/G2 通過分だけ offers） | 2,100 + 785 × 6.5 = 7,202 | **2.19倍** |

実測：raw/ の2,100商品のうち **62.6%（1,315件）は offers を掛けずに落とせます**。
**除外すると件数が減る、のではありません。同じ予算で母数が2.19倍になります。**

### 4-3. 「卸してくれる証拠」の再定義（現行の最大の欠陥）

現行：`distinct sellerId >= 2` → **転売業者同士でも、ブランド自身の別名ストアでも通ります。**

実測した自演：**401件（実セラー2以上のうち)**

| メーカー | 現行の実セラー数 | セラー名一覧 | 実態 |
|---|---:|---|---|
| Ailewu | 4 | AilewuDirect / AILEWU メーカー直営店 / AILEWU 直営店 / Ailewu Direct | 全部同一ブランドの直営 |
| Yaizk | 2 | Yaizk-DQ [メーカー直営＆品質保証] / Yaizk-MW[メーカー直営＆品質保証] | 同上 |
| THREEKEY | 2 | Threekey-Office / Threekey Direct | 同上 |
| ZVZHM | 2 | Z-公式直営店 / ZVZHM-JP公式直営店 | 同上 |
| Tibnozt | 3 | Tibnozt（ティブノズト）公式ストア / Tibnozt OFFICIAL / Tibnozt Shop | 同上 |

新定義：

```python
def independent_sellers(brand_norm, sellers):
    """卸証拠に数えてよいセラーだけを返す。"""
    out = []
    for x in sellers:
        if SELLER_ID.match(x.strip()):  continue   # Keepaが名前を解決できていない
        if DIRECT_SHOP.search(x):       continue   # 直営/公式ストア/正規販売店を名乗る
        n = nrm(x)
        if brand_norm and len(brand_norm) >= 3 and (brand_norm in n or n in brand_norm):
            continue                               # ブランド名を冠する系列店
        out.append(x)
    return out

def jp_sellers(sellers):
    """国内事業者と判定できるセラー（かな表記 or 日本法人格 or インボイス登録）。"""
    return [x for x in sellers if KANA.search(x) or JP_CORP.search(x) or INVOICE.search(x)]

# 合格条件
wholesale_ok = len(independent_sellers(...)) >= 2 and len(jp_sellers(independent)) >= 1
```

**「国内事業者1社以上」を足したのが肝です。** 独立セラーが2社いても両方海外なら、社長は同じ商流に入れません。

### 4-4. スコアリング（ゲートを通った後の並べ替え）

ゲートは足切り、スコアは順番付け。混ぜません。

| 指標 | 重み | 理由 |
|---|---:|---|
| 該当商品数 | ×3 | 1社で複数SKU取れる＝SKU100への効率が最も高い |
| S級シグナル数（0〜4） | ×2 | 連絡先に辿り着ける確度そのもの |
| 国内独立セラー数 | ×2 | 卸ルートの太さ |
| 日本法人格が明示 | +3 | 商談相手が特定できる |
| インボイス登録セラーあり | +1 | 国内商流が課税事業者で回っている |
| ブランド名が無意味英字列 | −2 | ゲートでは使わない。順位だけ下げる |
| EAN が 690-699（中国） | −1 | 製造地。所在ではないので減点に留める |

### 推奨：**A と C を並走。B は社長の承認が取れ次第 C に合流**

理由：

1. **Aは今日始められて0円。** 163社は既にあります。社長の手が止まる理由がありません。
2. **Cを同時に回さないと、明日また同じ品質の行が積まれます。** 常時稼働ジョブは今も動いていて、13.1%の歩留まりで行を増やし続けています。
3. **Bは待ち時間がゼロコストではありません。** 承認が下りるまで、Cの規模ゲートだけが手判定のまま残ります。ただしBが無くてもAとCは動きます。

### 会社KPI（月商800万・利益率20%・SKU100）への接続

| 会社KPI | 本設計の効き方 |
|---|---|
| SKU 100 | 連絡候補163社の該当商品数は**中央値1・平均1.69・最大21**（2件以上ある社は44社）。**Amazonで既に売れている商品だけを数えた下限**で、メーカーの取扱全点はこれより多い。取引開始10社で30SKUを狙える |

## 0. 結論

1. 今の母数（NETSEA×Keepa 26,942件）をこれ以上掘っても、1周目の商品は出てきません。フィルタは積集合なので、どの順番で当てても残るのは同じ1件（プリジアプロ）です。ゲートを最初に当てれば無駄な作業は減りますが、商品は増えません。
2. ゲートの無い棚には誰でも入れます。取り分（月販見込÷(出品者数+1)）が薄いのはそのためで、偶然ではありません。1周目の勝ち筋は「鍵を取りに行く側」、つまりゲート解除かメーカー直にあります。
3. 推奨は次の組み合わせです。
   - A: 生き残り12件から1ブランドに絞り、ゲート解除を取りに行く。発注の前に3営業日の入口審査を置く
   - B: 本丸の第一陣20社への連絡を今週から並行で始める
   - C（別のネット卸で母数を作り直す）はやりません
4. 卸レーンは SKU100 の供給源になりません。この母数でゲートの向こうにいる候補は12件で、全部解除できても12 SKU が上限です。卸は1周目を完走するための手段に留めます。

## 1. お客様の Preference 構造（出発点）

| 問い | 答え（この商材群の場合） |
|---|---|
| 誰が | 日用品・消耗品を Amazon で買う一般消費者 |
| なぜ | 同じ商品を、早く・安く・手間なく受け取るため |
| いつ | 使い切り・切らしたとき（リピート型） |
| どれだけ | 商品ごとに決まっている。売り手が増やせる量ではない |
| 誰から買うか | 決めていない。購入の約8割がカート経由で、出品者はほぼ見ていない |

**ここから言えること。**お客様は売り手を選ばないので、動かせるのは次の3つだけです。

| 動かせるもの | 中身 |
|---|---|
| ① 棚に立てるか | 出品できるか（ゲート） |
| ② カートに乗れるか | 大口プラン・FBA・価格 |
| ③ 取り分 | 需要 ÷ (出品者数+1)。需要が決まっている以上、ここが唯一の「どれだけ売れるか」 |

①と③は逆向きに動きます。

| 棚の種類 | 立てるか | 取り分 | 今回の実測 |
|---|---|---|---|
| ゲートなし | 誰でも立てる | 薄い（競合が自由に入る） | 生き残り1件。取り分は月1個に届かない |
| ゲートあり | 鍵が要る | 守られる（競合が入りにくい） | 生き残り12件 |
| 独占（本丸） | メーカーが決める | 需要の全部 | Keepa 起点では届かない |

## 2. 何が詰まったのか（事実の整理）

| 段階 | 残り | 主な落選理由 |
|---|---:|---|
| 母数 | 26,942 | NETSEA 承認済みサプライヤー × Keepa |
| カート検証 | 3,309 | カート最終獲得が古い・不在率が高い |
| 利益・入数・除外条件 | 50 | Amazon 本体が出品 1,602件（53%）・赤字・入数不明・電気用品 |
| 最小ロットで回転6ヶ月・10万円以内 | 22 | 卸の最小ロットが大きい |
| 生産終了チェック | 13（現行） | 利益率の上位ほど終売品が混ざる |
| 出品ゲート（実機） | **1** | 13件中12件が「このブランドには出品許可が必要です」 |
| 取り分 | **0** | 残った1件は出品者5・月販見込が小さく、取り分は月1個未満。純利益もほぼゼロ |

### 並べ替えでは解けない理由

各条件は「満たす／満たさない」の二値なので、最後に残る集合は条件の積集合です。当てる順番では変わりません。

- ゲートを先に当てても、残るのは同じ1件
- 変わるのは作業量だけ。今回で言えば、生産終了チェックと発注セット組成の大半をやらずに済んだ
- 商品を増やすには、条件を緩めるか母数を変えるかしかない。回転6ヶ月は社長の固定ルールなので緩めない。残る手は母数を変えること、またはゲートを「落選理由」から「取りに行く対象」に変えること

### SKU100 に対する上限

- この母数で、ゲートの向こうにいる候補は12件
- 全部解除できても最大12 SKU。取り分の条件を足せばさらに減る
- 卸レーン単独では SKU100 の12%にしか届かない

## 3. 案 A／B／C

### 案A: ゲート解除を取りに行く（NETSEA 内・既存の12件から1ブランド）

**段階ラベル: 今（実績づくり）。ゲート解除の手順は本丸でもそのまま使う。**

**中身。**生き残り12件（供給・回転・予算を通過済みで、ゲートだけで落ちたもの）から1ブランドに絞ります。そのブランドを10点以上仕入れ、NETSEA の請求書で出品許可を申請します。

**なぜ筋が良いか**
- 供給・回転・最小ロットの審査を通過済みで、残る壁はゲートだけ
- ゲートの内側は競合が入りにくい。取り分が守られる棚です

**入口審査（発注の前に必ず通す。通らなければ発注しない）**

| # | 条件 | 誰が・どうやって | 期間 |
|---|---|---|---|
| A-0 | 申請画面の要件を読む（受付停止か、請求書を求めるか、他の書類か） | カズヨのブラウザ作業。読むだけで送信しない。画面を開くこと自体が申請になるなら止める | 1日 |
| A-1 | 取り分の中央値が月6個以上。10点（最小ロットのほうが大きければそちら）で回転6ヶ月以内。1ブランドの仕入れが5万円以内 | 既存データの再計算（IT タカシ）。新しい観測は作らない | 1〜2日 |
| A-2 | NETSEA の請求書が Amazon の4要件を満たすか。4要件は、出品者の氏名と住所／卸またはメーカーの名称と住所／180日以内／10点以上 | サトル（§8 の S1） | 2〜3日 |
| A-3 | そのブランドでの申請の通過・却下の事例 | サトル（S1 に含める） | 同上 |

> 取り分「月6個以上」はタケシの提案値で、社長の確定値ではありません。
> 理由: 需要の推定は外れる幅が大きく、悲観側では中央値の約0.3倍になります（memory `knowledge_demand_estimation_limits`・Amazon にいない商品での実測。Amazon にいる商品はもっと狭いはずなので、安全側の仮定です）。中央値が6なら、悲観側でも月1.8個売れて、10点が5.6ヶ月で捌けます。つまり悲観シナリオでも回転上限の6ヶ月を守れる線です。

**中身。**T-20260906-005 で確定した第一陣20社（ギフトショー出展社・TEL またはフォームの実URLつき・20社中17社は Amazon にブランドの実在を確認済み）に連絡します。1周目は、Amazon に商品があって取り分の根拠が取れるメーカーだけに絞ります。

- 独占への入口になる。値崩れや相乗りに困っているメーカーほど話が通る（memory `project_strategy_core_offline_makers`）

### 案C: 別のネット卸で母数を作り直し、ゲートを最初に当てる

**段階ラベル: 今（実績づくり）。ただし構造は NETSEA と同じ。**

**中身。**卸問屋.com や国分ネット卸など、社長が入会要件を満たす卸に登録します（規約同意＝§4.1）。Keepa で母数を作り直し、今度はゲートを最初に当てます。ゲートを大量に判定するには SP-API の `getListingsRestrictions` を使う必要があり、リポジトリには認証情報がありません（開発者登録＝規約同意が要る）。

**想定リターン（確率はタケシの推測）**

| 項目 | 楽観（20%） | 中央値 | 悲観（20%） | 期待値 |
|---|---:|---:|---:|---:|
| 取り分・回転・ゲートを全部通る商品数 | 3件 | 1件 | 0件 | 約1件 |
| 6週以内に完走する | 20% | 10% | 3% | **約11%** |
| 完走までの日数（成功時） | 40日 | 50日 | 70日 | 約52日 |

根拠: NETSEA の26,942件で、ゲートなしの生き残りは1件、取り分の合格は0件。ゲートは商品（ブランド）に付く性質で、卸を替えても変わりません。国内ブランド品が主力の卸なら同じ結果になる見込みです。ゲートなしの棚が多い卸（例: 中国輸入品が主体のグッズステーション）は、取り分が薄いか、他社のブランド登録ページに相乗りするリスクがあります。

**撤退条件**: 新しい母数で、取り分と回転の両方を通るゲートなし商品が3件未満 → 即終了

**失敗しても学べること**: ほぼ無し。「ゲートなしの棚は取り分が薄い」は今回すでに学んでいます。

**推奨しない理由**: 期待値が3案で最も低く、学びも重複します。登録（§4.1）とトークン消費と2週間を使って、NETSEA と同じ構造をもう一度確かめるだけになります。

## 4. 推奨と配分

**推奨: A と B を順序付きで同時に始める。C はやらない。**

| | 案A | 案B |
|---|---|---|
| 役割 | 1周目の最短路（ゲートが開けば45日前後） | 1周目の保険であり、本丸の立ち上げ |
| 予算 | 最大5万円（1ブランド・10点以上） | 残り5万円 |
| 社長の手 | 発注承認・申請の送信・大口の切り替え | 連絡の送信（20通）・発注承認 |
| 始める日 | 入口審査は今日から（0円） | ゲートの事前チェックは今日から（0円）。送信は3〜5日後 |

| 見通し（タケシの推測） | 値 |
|---|---|
| どちらか一方でも9週以内に完走する確率 | 約58%（1 − 0.75 × 0.56） |
| Aだけ | 約25% |
| Bだけ | 約44% |

A と B は失敗の原因が独立しています。Aは NETSEA の請求書、Bはメーカーの返信で決まります。

**全方位ではない理由。**どちらも「鍵を取りに行く」という同じ勝ち筋の2つの入口で、学びも共有されます。Aで得た申請の実務はBでそのまま使います。捨てるのは「鍵の要らない棚で戦う」側（案C・NETSEA の深掘り）です。

**Aの入口審査で0ブランドだった場合**: Aは発注しないで終えます（損失0円）。10万円はすべてBに回します。

## 5. やらないこと

| やらないこと | 理由 |
|---|---|
| NETSEA 母数（26,942件）の深掘り・条件を組み替えた再スキャン | 積集合なので順番を変えても商品は増えない。回転6ヶ月は固定ルール |
| プリジアプロの採用 | 取り分が月1個に届かない＝社長ルール「取り分が月数個しかない商品は候補にしない」に該当 |
| 1周目のための SP-API 構築 | 新しい観測系の作り込みに当たる。規約同意も要る。AとBは母数が12件と20社なのでブラウザの目視で足りる |
| 案C（別のネット卸で同型のスキャン） | §3 のとおり |
| 入口審査を通っていないのに、申請用の在庫を買う | ダメ元の検証発注になる（社長ルール「成功する気でやる」） |
| Amazon にいないメーカーの商品を1周目に入れる | 売れる根拠が類似商品からの推定しかなく、外れ幅は13倍。2周目以降に回す |

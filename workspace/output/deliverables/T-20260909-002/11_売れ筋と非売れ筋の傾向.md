# 11 売れ筋と非売れ筋の傾向（公開版）

T-20260909-002 / タカシ / 2026-09-15。傾向と判定ルールだけをまとめた版です。ASIN ごとの値・卸値・件数の明細は `out/11_売れ筋と非売れ筋の傾向.md`（Git 追跡外）にあります。

## 結論

| 問い | 答え |
|---|---|
| NETSEA プールに月100以上はあるか | 約2割 |
| そのうち利益が出るもの | ごく一部（約6%）。食品とドラッグストアに偏り、特定の問屋1社に集中 |
| 売れ筋が利益にならない理由 | 卸値が Amazon 価格に近いため。利益マイナスの約9割は、卸値が Amazon 価格の70%以上 |
| 売れ筋の特徴 | 安い（3,000円以下）、消耗品（ドラッグストア・ビューティー・食品）、評価件数が多い、出品歴が短い |
| 売れ筋の弱点 | オファー数が多い、Amazon 本体が多い、値下がり中が約2倍、価格の振れが大きい、約4分の3に季節の波 |
| 非売れ筋の特徴 | 8,000円超、本・楽器・ゲーム・工具・家具、出品歴が長い |
| 類似商品の探し方 | 同じ JAN の単品とセットを先に見る。同ブランドであることは、売れる根拠としては弱い |

月100以上を入口の条件にするのは正しいと判断します。ただし、NETSEA の卸値ではほとんど利益が出ないので、卸値の安い仕入れ先（SD・メーカー直）と組み合わせることが前提です。

## データと定義

- **monthlySold**（Keepa の product-object、公式 api-docs）：Amazon の検索結果に出る「過去1か月に購入」の数値そのもので、推定値ではありません。「100+」のように区切った下限値で、バリエーション単位です。
- 2026-04 以降は50未満の値が出ていません。そのため「月10未満」は観測できず、「公表なし」を非売れ筋として扱いました。
- ドロップ数は使っていません。これは観測回数であって、販売数ではないためです。
- 「新品オファー数」はオファーの本数で、セラーの数ではありません。セラーの数は、生存オファーの sellerId の重複なし数で数えました。
- ブランド登録とゲートの有無は、手元のデータでは判定できません（未計測）。

## 判定ルール（案）

1. **需要の入口**：monthlySold の現在値が100以上（子は子自身の値）。公表なしは除外します。月50は保留とし、直近12か月のうち月100以上だった月が6か月以上なら残します。
2. **卸値の足切り**：卸値（税込）が Amazon 価格の70%以上なら、利益計算の前に落とします。
3. **定番か季節か**：12か月のうち10か月以上が月100以上なら定番です。それ以外は季節品として扱い、ピークの月の値で発注量を決めません。
4. **値崩れ中は保留**：現在価格が90日平均の95%未満、またはオファー数が90日平均より増えている場合です。
5. **Amazon 本体がいれば除外**（既存ルールのとおり）。売れ筋ではこれで候補が約半分になります。
6. **類似商品は同じ JAN から**：同ブランドは、卸に照会する理由にはなっても、売れる根拠にはしません。

## 類似商品の逆引き

1. 売れ筋 ASIN の JAN を卸で照合します。まとめ売り ASIN の場合は、単品の JAN で見ます。
2. 卸に出ているブランドの売れ筋のうち、卸のカタログに無い型番を、同じサプライヤーに照会します（外部への連絡なので、社長承認が要ります）。
3. バリエーションの兄弟の数字は流用しません（monthlySold は子の単位です）。

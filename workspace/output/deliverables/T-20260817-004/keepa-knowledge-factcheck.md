|---|---|---|
| 何 | ブラウザの Product Finder / Product Viewer | プログラムからのJSON取得 |
| 制限 | **データ使用量クォータ**（毎時5%回復・0%で停止） | **トークン**（20/分） |
| 当社の抽出スクリプトが使うのは | — | **✅ こちら** |

当社の `shiire_scan_v3.py` は `api.keepa.com` を叩いており、**Proのクォータとは無関係**。しかも Pro 側ですら公式記載の1日上限は Product Viewer 36,000商品/日で小さくありません。**現在進めている「当社基準に該当するメーカーをスプレッドシートへ抽出」する設計に影響はありません。**

### どれだけ抽出できるか（API €49プラン・20トークン/分）

```
20トークン/分 → 1,200/時 → 28,800/日 → 約892,800/月
※未使用トークンは生成60分で失効（＝貯金上限1,200。実測ログの「残1200」がこれ）
```

| 処理 | 消費 | 実効スループット |
|---|---|---|
| Product Finder 1クエリ（50件/ページ） | 約10トークン | ほぼ無視できる |
| **商品詳細（価格/ランク/ドロップ/出品者/月販/JAN）** | **約1トークン/ASIN** | **約1,200件/時** |

→ **一晩8時間で約9,600件、24時間フルで約28,800件。**

実績：T-20260803-001 で **4,446件を一晩で完走**／T-20260705-002 で **メーカー台帳3,282社・売れ筋7,840件**を生成済み。規模的に余裕があります。

### 「AIで抽出できないのか」への答え

**抽出そのものはAIにやらせません。** Keepa API ＋ スクリプト（決定論的・数字が正確）が担当し、AIは「判定の要約・優先順位づけ・文章化」だけを担います。ここを逆にすると、社長が8/10にご指摘された「**AIリサーチの数字が不正確で訂正作業に潰される**」の再発になります。

⚠️ 当社未検証・要確認：2026年3月のAmazon BSA改定で「Agent Policy」が新設され、Amazonデータのスクレイピング／AI学習が明示的に禁止された、という報告があります。**Keepa API 経由は正規ライセンスなので問題ありません**が、「トークン節約のために直接スクレイピング」という逃げ道は取らない方針とします。

## 結論を3行で

1. **料金が失効していました。** 動画の「月19€・年189€」は **2026年3月1日の改定で 月29€・年290€（+52%）** に。Keepa公式ページで実機確認済み。年 約53,500円の固定費。

3. **中身そのものは信頼できます。** ただし当社の本線は②メーカー仕入れなので**全面採用はせず、3点だけ取り込む**のが妥当と判断しました。

## 2. そのまま使える中身（訂正なし）

### 2-1. 推奨初期設定 — 「初期設定のままだと利益商品を見逃す」は本当

| 設定 | 推奨値 | 理由 |
|---|---|---|
| チャートの期間 | **3ヶ月**（初期値は1ヶ月） | 1ヶ月だと売れ行きの判断材料が足りない |
| クローズアップビュー | オフ | 急な値動きで軸が伸縮して読みにくい |
| 極端な価格を無視する | オフ | オンだと**廃盤品の高騰が「外れ値」として消える**＝一番おいしい波形が見えない |
| トラッキング対象期間 | 10年（最長） | 短期だと監視が切れて廃盤・高騰を見逃す |
| 通知済アラートの再有効化 | **7日 → 1日** | 7日では再通知が遅くチャンスを逃す |
| デフォルトの表示方法 | 「ボタン」→ **Keepaボックス** | 商品ページを開いた瞬間に波形が自動展開 |
| Keepaボックスの幅 | ウィンドウ全体 | 波形が大きく見える |
| 販売者ページの在庫数表示 | はい | **ライバルの保有在庫数が見える** |

### 2-2. 仕入れ個数の決め方 — 当社の②メーカー仕入れでも有効

```
自分の月間販売ペース ＝ 月間販売個数 ÷（出品者数 ＋ 1人）
原則：1ヶ月以内に売り切れる個数だけ仕入れる
```

当社の「消化月数」基準（T-20260817-002 段1）と**まったく同じ思想**。閾値が違うだけ（せどりは資金回転が命で1ヶ月／当社はロットがある分3ヶ月）。

### 2-3. 知財クレームを見抜く5サイン（当社にも直結）

1. 出品者に「**〇〇公式**」「株式会社〇〇（正規店）」がいる
2. 出品者グラフが**突然垂直に落下**（＝一斉通報・削除の跡）
3. 出品者が**常に1人**（相乗りしてもすぐ排除されている）
4. 価格が一切ブレず**完全に水平**（メーカーの価格統制）
5. ドラッグストア・コスメ・ヘアケア・サプリメント等の**規約が厳しいカテゴリ**

> これは**出品制限（ゲート）とは別軸**。ゲートは「Amazonが入口で止める」、知財クレームは「**権利者が後から通報して消しにくる**」。ゲート側は T-20260817-003 が担当。
> 当社の②メーカー仕入れは**メーカーから直接買う**ためこのリスクは構造的に低く、むしろ将来は自分が権利者側になる。相乗り候補を見るときの警戒サインとして使う。

### 2-4. 危険波形4つ／お宝波形3つ

| | パターン | 読み方 |
|---|---|---|
| 危険① | 超低回転 | ギザギザして見えても **月間販売数＜出品者数** なら数ヶ月滞留し値崩れ |
| 危険② | 出品者急増 | 短期間で30人超＝供給過多で価格暴落。※「30人」は経験則 |
| 危険③ | 知財リスク | 上記5サイン |
| 危険④ | ノーブランド品カタログの罠 | ブランド品なのに「ノーブランド品」でカタログ化され、**相乗り出品がエラーになる** |
| お宝① | 出品者ゼロ期間 | 過去に売れた実績があれば自分だけが出品者＝**強気の価格設定ができる** |
| お宝② | ランキング非表示 | Keepa側のデータ欠落。サブカテゴリ表示や過去履歴から売れ行きを推定 |
| お宝③ | 季節商品 | 1年／全期間の波形で「毎年この時期に動く」を確認し、**シーズン外の底値で仕込む** |

## 3. 当社への適用 — 全面採用はしません

この動画は**①電脳せどり・店舗せどり向け**。当社の方針（2026-08）では **①はホールド、本線は②メーカー仕入れ**。したがって**全面採用はせず**、①②どちらでも効く次の3点だけ取り込みます。

| | 取り込むもの | 組み込み先 |
|---|---|---|
| **a** | 推奨初期設定（特に期間3ヶ月／極端な価格を無視オフ／Keepaボックス自動表示） | Keepa操作ガイド（T-20260811-001）へ追記 |
| **b** | 知財クレームを見抜く5サイン | 仕入れ方針 段3（目視チェック）へ追加 |
| **c** | 仕入れ数量＝月販÷(出品者+1)で「売り切れる分だけ」 | 既存の消化月数基準と統合（考え方の裏づけ） |

**見送り**: Product Finderの「値上がり商品を拾う」レシピ（プレミア狙い＝①寄り）、店舗巡回前提の回収ルート設計。②が軌道に乗るまで保留。

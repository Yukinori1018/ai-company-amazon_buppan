## 列の読み方

| 列 | 意味 |
|---|---|
| `preset` | A=1,500〜8,000円×ドロップ10以上 / B=8,000〜20,000円×ドロップ4以上 |
| `月間ドロップ数` | Keepa の salesRankDrops30。BSR が急落した回数＝推定販売件数。**この列が抽出軸** |
| `月間販売数` | Amazon 実データ（"◯◯+個購入"）。**月50個以上の商品にしか出ない**ので空欄が普通。裏取り用 |
| `過去1年最安値` | Keepa stats(365日)の**新品最安（NEW）の最小値**。値下げ耐性の基準になる最悪値 |
| `損益分岐仕入れ値` | v1.3 の式そのまま＝`過去1年最安値 × 0.65 − 外注費`。**メーカーへの提示上限** |
| `損益分岐仕入れ値_精緻` | 検算用。`過去1年最安値 − 販売手数料(カテゴリ実料率) − FBA配送代行 − 外注費` |
| `仕入れ掛け率上限%` | 損益分岐仕入れ値 ÷ 現BuyBox価格。**目安40%を切ると現実の卸値では買えない**ことが多い |
| `想定月販` | `月間ドロップ数 ÷ (出品者数 + 1)`（自分が相乗りした後の取り分） |
| `消化月数` | `初回ロット10個 ÷ 想定月販`。**3.0以下が段1のGO** |
| `消化月数_ロット5` | 本家の最小ロット5個で計算した参考値 |
| `規模フラグ` | 大手/海外ブランドの疑い。**除外はしていません**（下記「正直な注意」参照） |
| `出品制限チェック` | **空欄。社長がセラセンでワンクリック解除を試して埋める欄**（段3・加点扱い） |

## 判定ロジック（v1.3 準拠）

```
段0 機械   : Amazon本体不在 / 出品者2〜6 / ランク30万位以内 / レビュー5〜300
             / バリエーション1〜3 / 追跡180日以上 / 除外4カテゴリ / FBA標準サイズ以内
段1 回転   : 消化月数 = 10個 ÷ (ドロップ数 ÷ (出品者数+1)) ≦ 3ヶ月
段2 値下げ : 損益分岐仕入れ値 = 過去1年最安値 × 0.65 − 外注費 > 0
段3 出品制限: 加点扱い。機械では判定できないため CSV は空欄（社長の手作業）
判定 = 段0・段1・段2 をすべて通過 → GO
```

## 正直な注意（数字は飾っていません）

0. **top100 の 70% が家電・PC周辺に偏りました。うち21件はリチウム電池・電源系です。**
   これは条件の欠陥ではなく、「回転の速い順」に並べた必然の結果です（回転が速いのはこの棚）。
   ただしこの帯は **①PSE ②FBA危険物（SDS提出・納品制限） ③初期不良/返品率→ODR直結** の
   三重リスクを抱えます。v1.1 で「国内メーカー仕入れならPSEはメーカー取得済み」と整理しましたが、
   **top100 に並ぶブランドの多くは海外（主に中国）ブランドで、この前提が効きません**。
   カテゴリ分散をかけるかどうかは社長判断です（`カテゴリ`列でフィルタするだけで作り直せます）。
1. **大手ブランドが混じります。** v1.3 の「レビュー5〜300＝あまり有名でない」という機械化は、
   **発売直後の大手SKU**を素通しします（実際に Anker / UGREEN / BANDAI / タカラトミー等が残りました）。
   除外は社長判断の領域なので**フラグを立てるに留めています**。`規模フラグ=中小候補` で絞るとメーカー直取引の現実味が上がります。
2. **「仕入れられる」は保証していません。** このリストが示すのは「Amazon 側で売れていて、相乗りの取り分が残り、
   最安値まで落ちても黒字にできる仕入れ値が存在する」ところまでです。
   実際に卸してもらえるか（＝メーカーが個人事業主に卸すか、最低ロット、掛け率）は**問い合わせないと分かりません**。
   `仕入れ掛け率上限%` が低い商品は、条件を満たしていても実務上ほぼ買えません。
3. **月間ドロップ数は推定値**です。まとめ買いを1件と数えるため高回転品では過小評価されます
   （狙っている低〜中回転帯では問題になりません＝v1.1 で確認済）。
4. **出品制限は未チェック**です。発注前に必ずワンクリック解除を試してください（在庫ゼロでも押せる・無料・即時）。

## 再実行のしかた

```bash
cd workspace/output/deliverables/T-20260817-005
python3 scan_v13.py                       # 続きから（既存CSVのASINはスキップ）
python3 scan_v13.py --target-a 5000 --target-b 3000   # 母集団を広げる
python3 scan_v13.py --from-raw            # 条件を変えて再集計（★トークン消費0）
```

閾値は `scan_v13.py` 冒頭の定数ブロック（`PRESETS` / `LOT_SIZE` / `GROSS_KEEP_RATE` /
`OUTSOURCE_COST` など）だけを直せば変えられます。条件を触ったら `--from-raw` で
再集計すれば、Keepa のトークンを1つも使わずに結果を作り直せます。

住民税（2026年分）黒字なら出る2027-06・08（普通徴収の第1・2期。第3・4期は10月・翌1月）入れる。給与天引き（特別徴収）なら事業の口座からは出ない
個人事業税ほぼ出ない2027-08・11入れる。事業所得290万円以下は0円
予定納税出ない2027-07・11条件判定だけ入れる（2026年分の所得税額15万円以上で発動）
消費税出ない—2026・2027年は免税（基準期間の売上なし）。2027年の課税売上が1,000万円を超えると2029年から課税。2028年の判定（特定期間＝2027年1〜6月）は給与支払額でもでき、給与0なら免税（税理士確認）
輸入消費税中国輸入だけ出る通関時原価に含める。免税事業者は控除できない
国保・国民年金増えない—勤務先の社会保険のまま
2027年分の所得税・住民税・事業税12ヶ月の外2028-03〜窓の外。after_window_tax に見込みを出す（テスト1で約19万、テスト2で約155万）

注意点：

  • 12ヶ月累計キャッシュは、2027年分の税を払う前の値です。利益の大きい案ほど2028年に大きく出ていきます。
  • 在庫は経費になりません。仕入れ先行で現金が減っていても、利益には税がかかります。これは黒字倒産を悪化させる向きに働きます。
  • 青色65万円控除の条件は、複式簿記と電子申告です。会計ソフトは前回の段階2に入れてあります。
  • 税の数字はすべて推定です。限界税率20.42%（給与の課税所得330〜695万円の帯）は仮定で、税理士確認を推奨します。

8. マサルへの渡し方

```

import importlib.util

spec = importlib.util.spec_from_file_location("cf", ".../T-20260914-003/00_cf_base.py")

cf = importlib.util.module_from_spec(spec); spec.loader.exec_module(cf)

lane = cf.preset("メーカー直", margin=0.18, turnover_m=2)

res = cf.simulate(cf.Config(), cf.reinvest(lane, cap=[取り分から出した月別上限]))

res["cum_cash"], res["thin_cash"], res["thin_month"]

```

1. 案の経路ごとに preset を上書きする（利益率・回転月数・リードタイム・売れ残り率）

2. 需要は cap（月別の仕入れ上限）で入れる。モデル自身は需要を知らない

3. 固定費の段階と一回払い（商標・GS1・版代）を Config に入れる

4. 3シナリオは経路の値を変えて作る（利益率・回転・リード・売れ残り率・留保ストレス）。乱数は不要

5. 判定は cum_cash（実質・>0）と thin_cash（≥25万）。窓の外の税は after_window_tax を併記する

限界：

  • 価格の下落とカート獲得率は利益率に含めて表現します。
  • 日数は暦日で数え、土日の銀行休業は無視しています。
  • 税の限界税率は一定と置いています。
  • python3 00_cf_base.py の全出力には約4分かかります。--quick を付けると §1〜3 だけを数秒で出します。

#論点選択肢推奨と理由
1「12ヶ月で現金が増える」を何で測るかA 実質現金（現金−未払）／B 純資産（在庫込み）／C 実質現金から翌年の税の見込みを引くA を設計条件にし、C を悲観側に併記。社長の言葉は「現金」で、B は在庫が売れる前提を含むため

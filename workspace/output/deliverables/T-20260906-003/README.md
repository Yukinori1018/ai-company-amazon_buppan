# T-20260906-003 — 母数を新条件で引き直す（夜間自走）

## 何をしているか

母数 26,942 件に、T-20260906-002 で決めた条件を当てて候補を引き直します。

| # | 条件 | どこで判定するか |
|---|---|---|
| ① | ドロップ数 ≧ 5（社長裁可） | **ローカル**（既存キャッシュ `keepa_facts.jsonl`）＝無料 |
| ⓠ | 30日の観測回数 ≧ 20 | API 1段目（1 token/件） |
| ② | カート最終獲得が30日以内 | API 2段目（約6.5 token/件） |
| ③ | 直近30日のカート不在率 ≦ 0.30 | API 2段目 |
| ④ | 子ASINはランク由来の数字を単独の根拠にしない | 運用上の禁止事項（②に吸収されるため独立実装しない） |

**①をローカルで先に当てるので、API を掛ける対象は 26,942 → 9,219 に落ちます。**

## ファイル

| ファイル | 役割 |
|---|---|
| `verify_pool.py` | 本体。チェックポイント・スロットル・停止条件を持つ |
| `run_overnight.sh` | 監督ループ。worker が落ちたら続きから起こし直す |
| `summarize.py` | **朝の報告用。走行中でもいつでも打てる** |
| `com.aicompany.pool-verify.plist` | launchd 用（**未導入**。§導入したい場合 参照） |
| `stats_進捗.csv` | 集計値のみ（Git 追跡） |
| `out/` | 行データ・ログ（**Git 追跡外**） |

## 使い方

```
python3 summarize.py          # 今どこまで進んだか
tail -f out/run.log           # 走行ログ
cat out/heartbeat.json        # 生死（20分以上古かったら止まっている）
touch STOP                    # 安全停止（書き出し済みの行は全部残る）
rm STOP && ./run_overnight.sh # 再開（続きから。全件やり直しはしない）
```

## 設計の要点

- **チェックポイントは `out/verified.jsonl`。** 1件ずつ追記し、再起動時はこれを読んで飛ばす。
  順序は必ず「取得 → 評価 → 書き出し → 済み印」。逆にすると、落ちたときに
  行が無いのに二度と拾われない。
- **ブロック単位で①→②③まで通し切る。** 全件①を先に回すと、一番使いたい上位の候補が
  最後まで②③未検証で残る。朝の時点で未完走でも「上位から順に完全に検証済み」になる。
- **利益率の高い順に処理する。** 完走しない前提の設計。
- **トークンは貯められない（上限1,200・補充20/分）。** スループットは実装ではなく
  補充レートで決まる。1件あたり約7.3トークン ＝ **約164件/h**。9,219件の完走には約55時間。
  **11時間の走行で届くのは上位約1,800件。**
- **枯渇しても異常終了しない。** 下限バッファ150を残して待機し、回復したら自動で再開する
  （他の作業がトークン切れの巻き添えにならないように）。

## launchd で常駐させたい場合（未導入）

`com.aicompany.pool-verify.plist` を置いてありますが、**導入していません**。
LaunchAgent の登録は常設の設定変更なので、社長の許可なく行いません。導入するなら:

```
cp com.aicompany.pool-verify.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.aicompany.pool-verify.plist
launchctl list | grep pool-verify     # 2列目の終了コードが 0 であることを見る
```

現在は `nohup ./run_overnight.sh &` で走らせています（Mac がスリープすると止まりますが、
起こせば `./run_overnight.sh` で続きから再開できます）。

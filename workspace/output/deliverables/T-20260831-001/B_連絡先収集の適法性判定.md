## 1. 判定の前提

1. **本チケットの目的は「連絡先を集めるところまで」**。実連絡・見積依頼は §4.1（第三者連絡）でスコープ外。
2. **当社は Amazon 日本店アカウントが停止中**。Amazon 側規約への違反の上乗せは、事業の存続そのものを失う。よって Amazon 関連は他手段より一段厳しく判定した。
3. **このリポジトリは PUBLIC で、30分ごとに自動 push される**。「commit した瞬間に全世界へ公衆送信」が既定値である。これを前提に、第三者DB由来データと個人事業主の連絡先の格納先を判定した。
4. 822社には**個人事業主・屋号のみのブランドが混在する**（依頼元の申告）。法人前提の設計は不可。

- 取れる: 法人基本情報（商号・所在地・法人番号）、**自社プロフィール登録企業は企業HP URL** を持つことがある、届出・認定・補助金・調達・特許情報

## 4. メーカー公式サイトの自動アクセス — **条件付き可**

ここが本件の主戦場です。**著作権よりも、業務妨害罪と各社規約が本丸**です。

### 4-1. 著作権法上の評価 → **問題は小さい**

| 論点 | 判断 | 根拠 |
|---|---|---|
| 電話番号・住所・会社名そのもの | **著作物でない**。創作性のない事実・データ | 著作権法2条1項1号の「思想又は感情を創作的に表現したもの」に当たらない |
| HTML の一時取得・解析 | **適法** | 30条の4第2号「**情報解析**（多数の著作物その他の大量の情報から…抽出し、比較、分類その他の解析を行うこと）の用に供する場合」は「その必要と認められる限度において、いずれの方法によるかを問わず、利用することができる」 |
| 30条の4 のただし書 | 抵触しない | 「著作権者の利益を不当に害することとなる場合」＝有償のデータベース著作物を代替する等。**連絡先の抽出は該当しない** |
| 47条の5（軽微利用） | **援用しない** | 同条は「検索結果の提供」「解析結果の提供」を**外部に提供する**行為に付随する軽微利用の規定。当社は社内利用なので**30条の4だけで足りる**。47条の5は1項柱書で「**政令で定める基準に従って行う者に限る**」と主体を絞っており、無理に乗せると逆にリスクになる |

> **依頼にあった「47条の5の射程」への回答**: 本件は 47条の5 の射程に入れる必要がありません。社内利用なら 30条の4第2号で説明が完結します。将来「集めた連絡先を外部に見せるサービス」に発展させる場合に初めて 47条の5 の主体要件（政令基準）を検討してください。

### 4-2. 刑事リスク → **ここが本丸**

| 条文 | 内容 | 法定刑 |
|---|---|---|
| 刑法233条（偽計業務妨害） | 「偽計を用いて…その業務を妨害した者」 | 3年以下の拘禁刑 or 50万円以下の罰金 |
| 刑法234条の2（電子計算機損壊等業務妨害） | 「電子計算機に…使用目的に反する動作をさせて、人の業務を妨害した者」 | 5年以下の拘禁刑 or 100万円以下の罰金。**未遂も処罰** |

**岡崎市立中央図書館事件（Librahack事件・2010年）の教訓**

- 蔵書検索システムに対し **1秒に1回・1日1時間程度**のアクセスを行った男性が、偽計業務妨害の疑いで**逮捕、21日間勾留、起訴猶予**。
- 真因は**図書館側システムの不具合**だった。それでも身柄拘束は起きた。
- **教訓は「技術的に妥当な速度でも、相手が『攻撃された』と申告すれば逮捕され得る」**。当社の場合、逮捕されなくても「メーカーから抗議を受けた事実」だけで、これから取引を申し込む相手との関係が終わります。**不可逆性が極めて高い。**

→ よって速度は「技術的に許される限界」ではなく「**相手が絶対に気づかない水準**」に設定します。

### 4-3. robots.txt の扱い

- robots.txt そのものに**法的拘束力はありません**（法令上の根拠がない）。
- しかし ①サイト運営者の明示の意思表示であり、②これを無視した事実は業務妨害の「故意」認定や民事の不法行為評価で**明確に不利に働きます**。
- 明文主義の立場から: **robots.txt に従わない理由が当社に一つもない**。従います。

### 4-4. 実装制約（そのままコードへ）

```
# --- アクセス制御 ---
RESPECT_ROBOTS_TXT      = True        # 取得前に必ず robots.txt を取得しパース
                                      # Disallow パスは踏まない。取得失敗時は「許可なし」と扱う
USER_AGENT              = "SatoySelectBot/1.0 (+mailto:<当社連絡先>) — 仕入先調査目的"
                                      # 実在の連絡先を書く。ブラウザUAの詐称はしない
CRAWL_DELAY_MIN_SEC     = 3.0         # 同一ホストへの最小間隔。robots.txt の Crawl-delay が
                                      # これより大きければそちらを採用（大きい方を取る）
MAX_CONCURRENCY_PER_HOST= 1
MAX_GLOBAL_CONCURRENCY  = 4           # 異なるホストへの並列は4まで
MAX_PAGES_PER_COMPANY   = 10
MAX_DEPTH               = 2           # トップから2階層まで
TIMEOUT_SEC             = 20
ACCESS_WINDOW           = "09:00-23:00 JST"  # 深夜の無人大量アクセスは避ける（誤検知を招く）

# --- 停止条件（ここが一番大事） ---
ON_HTTP_429_503         = 当該ホストを即時打ち切り。同ホストへの再訪は7日以上あける
ON_HTTP_403             = 当該ホストを即時打ち切り。再訪しない（拒否の意思表示）
ON_5XX_TWICE            = 当該ホストを即時打ち切り
ON_CAPTCHA_OR_WAF       = 即時打ち切り。**回避を試みない**（不正アクセス禁止法・規約違反の領域）
GLOBAL_ERROR_RATE_STOP  = 直近100リクエストの5xx率が20%を超えたらジョブ全体を停止

# --- 取得対象の限定 ---
ALLOW_PATH_HINTS        = ["company","about","corporate","kaisha","gaiyo","profile",
                           "contact","inquiry","otoiawase","toiawase","support",
                           "tokushoho","law","legal","privacy"]
                          # トップ＋上記に該当するリンクのみ辿る。商品ページ・ブログは辿らない
DENY                    = ログイン必須ページ / 会員ページ / 有料ページ / フォームのPOST送信
                          # 「取得」であって「送信」はしない。問い合わせフォームは
                          #  URL を記録するだけで、絶対に送信しない（§4.1 第三者連絡）

# --- 保存 ---
STORE                   = 抽出項目（電話 / フォームURL / メール / 所在地 / 商号）
                        + 出典URL + 取得日時(UTC) + HTTPステータス
DO_NOT_STORE            = HTML全文の恒久保存。キャッシュは agent_output/ に7日で自動削除
REVISIT_INTERVAL_DAYS   = 30          # 同一URLの再取得は30日あける（冪等・再開可能）
```

### 4-5. 各社サイトの利用規約

- サイトによっては規約に「ロボット・自動収集の禁止」を置いています。**規約がある以上、明文が優先します。**
- 全822社の規約を人力で読むのは不可能。**折衷案として、以下を実装すること。**

```
TOS_KEYWORD_SCAN = 取得した各ページ本文に対し、以下の語を検索。
                   ヒットしたら当該ドメインを即時ブラックリスト化し、以後アクセスしない。
  ["クローリング", "クロール", "スクレイピング", "自動収集", "自動取得",
   "ロボット", "自動化されたプログラム", "データマイニング", "無断複製", "無断転載"]
                   ※ ヒット＝即NGではないが、**個別に人が読むまで止める**のが明文主義。
                   ヒット件数は多くないはずなので、その分だけハルオが読む。
```

### リスク（3軸）

| 軸 | 評価 |
|---|---|
| 発生確率 | 中（速度制御を誤ると容易に発生） |
| 影響度 | **大**（抗議・アクセス遮断・最悪は刑事） |
| 不可逆性 | **高**（これから取引を申し込む相手に嫌われる。関係は戻らない） |

→ **確率が低くても止める類の話ではなく、確率が中で影響が大。速度制御は交渉不可の絶対条件。**

## 5. Amazon 商品ページ／ブランドストアの自動取得 — **不可**

### 5-1. 決定的根拠（一次情報・当社が今日取得）

**Amazon.co.jp 利用規約**（更新日: 2025年9月1日 / 確認日: 2026-08-31 / `https://www.amazon.co.jp/gp/help/customer/display.html?nodeId=643006`）
「利用許可およびサイトへのアクセス」より、原文のまま:

> 「本規約およびサービス規約の遵守を条件とし、アマゾンまたはコンテンツ提供者は、アマゾンサービスを**限定的、非独占的、非商業的および個人的に利用する権利**をお客様に許諾します（譲渡およびサブライセンス不可）。この利用許可には、アマゾンサービスまたはそのコンテンツの**転売および商業目的での利用、製品リスト、解説、価格などの収集と利用**、アマゾンサービスまたはそのコンテンツの二次的利用、第三者のために行うアカウント情報のダウンロードとコピーやその他の利用、**データマイニング、ロボットなどのデータ収集・抽出ツールの使用は、一切含まれません**。」

> 「アマゾンサービスまたはそのいかなる部分も、アマゾンからの書面による明示的な承諾を得ていない限り、**商業目的のために、複製、複写、コピー、販売、再販、アクセス、その他の利用はできません**。」

**これ以上議論の余地はありません。**「商業目的でのアクセス」自体が許諾外です。当社の目的は完全に商業目的です。

### 5-2. 補強根拠

## 8. 収集した連絡先の「保有」— 個人情報保護法

### 8-1. 法人情報は個人情報か → **原則ノー。ただし例外が3つある**

個人情報保護法2条1項:
> 「この法律において『個人情報』とは、**生存する個人に関する情報**であって…**特定の個人を識別することができるもの**…をいう。」

個人情報保護委員会ガイドライン（通則編）:
> 「**法人その他の団体は『個人』に該当しないため、法人等の団体そのものに関する情報は『個人情報』に該当しない**」（ただし「役員、従業員等に関する情報は個人情報に該当する」）

| 収集する項目 | 個人情報か | 理由 |
|---|---|---|
| 商号・法人番号・本店所在地 | **× 非該当** | 法人そのものの情報 |
| 代表電話番号 | **× 非該当** | 同上 |
| 問い合わせフォームURL | **× 非該当** | 同上 |
| `info@` `contact@` 等の組織アドレス | **× 非該当** | 特定個人を識別しない |
| **代表者氏名・役員氏名** | **○ 該当** | ガイドライン明記 |
| **`yamada@` `t.suzuki@` 等の個人名入りアドレス** | **○ 該当し得る** | 商号と併せて特定個人を識別しうる |
| **個人事業主・屋号のみのブランドの情報一式** | **○ 該当** | 事業情報がそのまま個人の情報になる |

### 8-2. 822社に個人事業主が混ざる → **全体を個人情報として扱う**

822社を1件ずつ「法人か個人事業主か」判定してから扱いを分けるのは、実務上破綻します。
**判定を待たず、データセット全体に個人情報の取扱いルールを適用してください。** これが最も安全で、かつ最も安い方法です。

### 9-1. 当社の営業メールは「特定電子メール」に当たる

法2条2号: 送信者（**営利を目的とする団体**及び営業を営む場合における個人）が「自己又は他人の営業につき広告又は宣伝を行うための手段として送信をする電子メール」。
→ 当社からメーカーへの仕入れ打診メールは、自己の営業の宣伝を含む以上、**該当します**。

### 9-2. オプトイン原則と、当社が乗るべき例外

法3条1項（**原文**）:
> 送信者は、次に掲げる者**以外の者に対し、特定電子メールの送信をしてはならない**。
> 一　あらかじめ…同意する旨を…通知した者
> 二　…総務省令・内閣府令で定めるところにより自己の電子メールアドレスを送信者…に対し通知した者
> 三　…当該特定電子メールを手段とする広告又は宣伝に係る**営業を営む者と取引関係にある者**
> 四　…総務省令・内閣府令で定めるところにより**自己の電子メールアドレスを公表している団体又は個人（個人にあっては、営業を営む者に限る。）**

**当社が乗るのは第4号です。**

施行規則3条（**原文**）:
> （自己の電子メールアドレスの公表の方法）
> 第三条　法第三条第一項第四号の規定による自己の電子メールアドレスの公表の方法は、**自己の電子メールアドレスをインターネットを利用して公衆が閲覧することができる状態に置く方法**とする。
> **ただし、自己の電子メールアドレスと併せて特定電子メールの送信をしないように求める旨の文言をインターネットを利用して公衆が閲覧することができる状態に置いたときは、この限りではない。**

### 9-3. これが収集フェーズに与える制約 —— ★ここが依頼の核心

**「送れないアドレス」は集める段階で分別できます。** 以下を必ず実装してください。

```

                      後から探し直せない設計は不可）

email_optout_notice : bool。**同一ページ内に下記のいずれかの語があれば true**

                       "DM", "ダイレクトメール", "特定電子メール", "お断り", "ご遠慮",

                      ※ 法的には4号で送信可でも、**実務上は送信対象から外す**。
```

| 拒否リンクは所定の位置に | 規則7条1項2号 | 「受信拒否の通知先」表示の**直前または直後** |
| 送信者の**住所**を表示 | 規則9条2号 | 省略不可 |
| 苦情・問合せ窓口（電話 or メール or URL） | 規則9条3号 | 省略不可 |
| 拒否通知を受けたら送信禁止 | 法3条3項 | **サプレッションリストを必ず実装**。手運用は不可 |
| 送信者情報を偽らない | 法5条 | From/Return-Path の詐称禁止 |

**罰則（不可逆性の評価に使うこと）**

| 条 | 対象 | 罰 |
|---|---|---|
| 34条2号 | 措置命令（法7条）違反 | **1年以下の拘禁刑** または100万円以下の罰金 |
| 37条1号 | 上記の**法人両罰** | **3000万円以下の罰金** |
| 34条1号 | 送信者情報を偽った送信（法5条違反） | 1年以下の拘禁刑 または100万円以下の罰金 |

→ 措置命令は総務大臣・内閣総理大臣が出します。**いきなり刑罰ではなく命令が先**ですが、命令を受けた事実が公表される時点で信用毀損は不可逆です。

### 9-5. 判定

- **収集: 条件付き可**（上記4列の実装が条件）
- **送信: §4.1 該当。社長承認なしに1通も送らない**（外部発信・第三者連絡の両方に該当）

## 11. 社長判断が必要な論点（秘書カズヨへ）

法務は判断材料を出す係です。以下は**私が決めてはいけない事項**なので、A/B/C にして渡します。

### 論点① 連絡先の実データを PUBLIC リポに置くか

| 案 | 内容 | 評価 |
|---|---|---|
| **A（法務推奨）** | 実データは限定共有の Google スプレッドシートのみ。リポには統計とリンクのみ | 個人事業主混在の27条リスクと、商用DB規約の「公衆送信禁止」の両方を同時に消せる。CLAUDE.md §6 の例外扱いが必要 |
| B | 実データを deliverables に commit（現行ルール通り） | 運用は単純。ただし個人事業主の氏名・住所・電話が全世界に公開される。**削除には force push（§4.1）が要る＝不可逆** |
| C | 個人事業主を除いた法人のみを commit、個人分は別管理 | 理屈は通るが、判定コストが高く、判定ミスが即漏洩になる |

→ **推奨は A。** 影響度が大きく不可逆なので、運用の単純さより安全を取るべきです。

### 論点② 各種API・サービスの利用申請（＝規約への同意）

| 対象 | 費用 | §4.1 該当 |
|---|---|---|
| 国税庁 法人番号 Web-API のアプリケーションID発行届出 | 無料 | **該当（法的拘束＝利用規約への同意）** |
| gBizINFO REST API の利用申請 | 無料 | **該当（同上）** |
| Google Cloud / Vertex AI Search | 有料 | **該当（金銭＋法的拘束）** |
| Musubu 等の商用DB | 有料 | **該当（金銭＋法的拘束）**。加えて論点①の解決が前提 |

→ **無料であっても規約同意は法的拘束です。ハルオもタカシも実行しません。** 社長の一手が要ります。
→ ただし国税庁・gBizINFO の2つは**規約内容を精査済みで、当社に不利な条項はありません**（禁止事項は「大量アクセス禁止」「ID共有禁止」「申告目的の範囲内」の3点のみ、金銭債務なし、いつでも離脱可）。**承認して差し支えない、と法務は判断します。**

### 論点③ 検索APIをどうするか

Custom Search JSON API が新規停止しているため、**「検索で公式HPを探す」設計は当面成立しません。** Phase C の設計をタカシに戻す必要があるか、秘書のご判断を仰ぎます。

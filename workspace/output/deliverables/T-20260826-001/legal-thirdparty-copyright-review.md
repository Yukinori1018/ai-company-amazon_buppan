### 2.1 PDF（`パーフェクトマニュアルサンプル_EC-STARs-Lab.pdf`）

#### (1) 著作物性 — 争う余地はない

文章・図表・レイアウトからなる編集物であり、**著作権法2条1項1号**の「思想又は感情を創作的に表現したもの」に当たります。**10条1項1号**（言語の著作物）＋図表部分は同項6号（図形の著作物）。著作者は EC STARs Lab.／中西恒太氏（法人著作なら15条1項）。

#### (2) 当社が行っている行為

| 行為 | 該当条文 | 当社の状況 |
|---|---|---|
| ファイルを GitHub のサーバに置いた | **21条（複製権）** | 該当。commit `1bf015a` 以降 |

**「まだ誰もダウンロードしていない」は抗弁になりません。**送信可能化は、アップロードした時点で完成する侵害です（受信者の存在を要件としない）。fork 0件という事実は損害額の議論には効きますが、侵害の成否には効きません。

#### (3) 私的複製（30条1項）— **適用されません**

30条1項が許すのは「**個人的に又は家庭内その他これに準ずる限られた範囲内**において使用することを目的とする」複製です。

- 社長が自分の PC にダウンロードして読む段階までは、30条1項の範囲内と評価できます。
- しかし**世界中から取得可能な公開リポジトリに置く行為は、定義上「限られた範囲」ではありません。**
- さらに **49条1項1号**により、30条1項で作成した複製物を公衆に提示した場合は「**複製を行ったものとみなす**」＝私的複製の免罪符が遡って消えます。

**結論：私的複製の範囲を明確に超えています。**

#### (4) 引用（32条1項）— **要件を1つも満たしません**

32条1項は「公表された著作物は、引用して利用することができる。この場合において、その引用は、**公正な慣行に合致**するものであり、かつ、**報道、批評、研究その他の引用の目的上正当な範囲内**で行なわれるものでなければならない」と定めます。

## 4. 依頼事項③：対応の選択肢（A/B/C/D ＋推奨）

### 前提として押さえるべき技術的事実

1. **Git 履歴は消えない。**`git rm` しても、`.gitignore` に足しても、**過去のコミットに blob として残り、GitHub 上で URL 直打ちで取得できます。**「最新版から消えた」は「公開が止まった」を意味しません。
2. **外部ミラーはまだ無い（§1 #8）。**今なら履歴除去に意味があります。
3. **`github-sync.sh` は force push をしない設計**なので、履歴を書き換えても自動同期は追随できず、**必ず人間の手当てが要ります**（分岐を検知したら停止する設計＝安全側に倒れる）。

### A案：現状維持（依頼書の (c)）

| | |
|---|---|
| 作業 | なし |
| 残存リスク | **Tier 1 の侵害状態が継続。**DMCA 1通でリポジトリ全体が無効化されうる。30分ごとの自動同期も止まる |
| コスト | ゼロ |
| **判定** | **不可。**「グレーは原則 NO」以前に、Tier 1 は黒に近い。**採用しません** |

### B案：`.gitignore` へ移して追跡から外す（依頼書の (a)）

| | |
|---|---|

| 残存リスク | **履歴に残り、公開され続ける。**コミットハッシュを知る者（GitHub のコード検索・イベント API を辿れば誰でも到達可能）は今後もダウンロードできる。**根本解決にならない** |
| コスト | 低 |

### C案：履歴から完全に消す（依頼書の (b)）

| | |
|---|---|
| 作業 | `git filter-repo`（または BFG）で対象パスを全履歴から除去 → **force push** → GitHub サポートへキャッシュ purge 依頼 → 全 worktree の再クローン |

| 残存リスク | ①**全コミットハッシュが変わる**ため、成果物カタログ CSV の blob URL・チケット本文のコミット参照・`docs/` 内のリンクが一斉に切れる（当社は blob URL をカタログに使用中）。②他 worktree・他デバイスのクローンとの整合を人間が取り直す必要がある。③GitHub 側のキャッシュ・PR・Gist に残る可能性（本件は PR 0件なので影響小）。④**既にダウンロードされた分は回収不能** |

### D案：リポジトリを Private 化（当職からの追加提案）

| | |
|---|---|
| 作業 | GitHub の設定を1回変更するだけ。**5分。履歴・Issue・カタログの blob URL・ローカルの全 worktree に一切影響しない**（所有者である社長は従来どおり閲覧可） |
| 効果 | **HEAD も全履歴も、Tier 1〜3 のすべてが即座に外から見えなくなる**。DMCA・クレームの窓が閉じる |
| 残存リスク | 既にダウンロードされた分は回収不能（これはどの案でも同じ）。GitHub Pages 未使用のため対外影響なし（`gh api .../pages` が 404 ＝ 2026-08-24 確認済み） |
| **可逆性** | **完全に可逆。**いつでも PUBLIC に戻せる |
| **判定** | **推奨。可逆な1操作で、不可逆なリスクを止められる** |

### 推奨：**D → C → B の順で、段階的に**

```
即時   D  リポジトリを Private 化（5分・可逆・社長の1操作）
        └ 出血を止める。ここまでは今日中に終わる

次に   C  Tier 1・Tier 2 を履歴から除去（§4.1 承認 → ケンジが実行）
        └ Private のまま安全に作業できる。カタログ URL の張り直しもこの中で

最後   B  .gitignore ＋ 受入基準を整備し、リポ外の素材置き場へ移す
        └ 再発防止。ここまで終われば PUBLIC 復帰も検討可能
```

**社長が PUBLIC 継続を強く望まれる場合の代替（B'）**

社長は 2026-08-24・08-26 に PUBLIC 継続をご判断済みですが、**そのご判断は「自社の事業情報を見せてよいか」についてのものであり、第三者著作物は判断材料に入っていませんでした。**したがって、この点だけを切り出して再判断いただく必要があります。

PUBLIC を維持するなら、**C を「先に」実行するほかありません**（B だけでは履歴が残り、公開状態が続くため）。この場合、**出血を止められるまでに半日〜1日かかります。**その間、侵害状態が継続することをご了解いただく必要があります。**当職は、この待ち時間を許容する合理的理由を見出せません。**

### 「評価 -1%」（Dataタブ Buy Box統計の評価列）

- **❓公式に定義なし。**Buy Box統計の per-seller オブジェクト（`buyBoxStats`）に評価の項目は存在せず（フィールドは `avgNewOfferCount` / `avgPrice` / `isFBA` / `lastSeen` / `percentageWon` の5つのみ）、拡張機能が出品者データから合成して表示している列だと考えられます。
- **推測：「データなし」を表す -1 がそのまま％として描画されている（確度：高）。** 根拠は、Keepa API 全体で **-1 = データなし** が一貫した約束事であること（大原則③）、および Seller Object の rating が「新規アカウントには評価が無い場合がある」と明記されていること。
- **ただし公式の断定はできません。**当社の従来解釈「データなしとみられる」は**据え置きが妥当**です。判断には使わないでください。

### ⚠ 2026-02-23 の価格定義変更（当社ナレッジ全体に影響）

> 公式原文：「NEW, USED, COLLECTIBLE, REFURBISHED の時系列について、**2026年2月23日より前の記録は「最安の出品価格（listing price）」、2026年2月23日以降の記録は「最安の着地価格（landing price＝出品価格＋送料）」**を表す」（product-object.html / changelog.html）

**つまり「新品最安値」という同じ列の中で、2026-02-23 を境に意味が変わっています。**過去1年の最安値を取ると、前半は送料抜き・後半は送料込みの混在データになります。FBA/プライム品は送料0なので実害は小さいですが、**FBM主体の安価な商品では過去と現在を単純比較できません**。

## 10. 補足：Keepa 公式 MCP サーバの存在（社長のご懸念に直接効きます）

社長のご懸念「**keepa を読み込む AI が用語の意味を履き違えている**」に対して、公式に用意された手段が2026年時点で存在します。

- **公式 MCP サーバ `https://keepa.com/mcp`**（`api-docs/mcp.html`）。Keepa が**ホスト型サービスとして自ら運用**。インストール不要。
- 認証は**既存の API アクセスキー**（Bearer）。**新規契約・追加課金は不要**で、消費するのは**現在契約中のプランのトークン**。
- **Claude Code 向けのセットアップコマンドが公式に記載されています**（1行）。
- 公式説明：「**応答はプログラム向けではなく言語モデル向けに整形されている**。コードを書くなら REST API を直接使え」「各ツールの説明にトークン単価が書かれ、各応答に残高が付くので、接続したアシスタントは自分で支出をペース配分する」。
- **注意（公式明記）**：「APIキーは秘密。**キーを埋め込んだ設定ファイル（例：チェックインされた `.mcp.json`）を共有リポジトリにコミットしてはならない**。キーを持つ者は誰でもあなたのトークンを使える」。

> **ここから先は当社の設定変更＝サトルの領分外です。** 導入可否・キーの取り扱い（当社リポジトリの `.mcp.json` は Git 追跡下にあります）は、**カズヨ経由でタケシ（プランナー）／ITエンジニアと社長判断**にお回しください。事実として「公式手段が存在し、追加課金は発生しない」ところまでが本調査の範囲です。

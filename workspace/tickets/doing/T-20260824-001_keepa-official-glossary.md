# 概要

社長指示（2026-08-24）：

> 「keepaの使い方の説明書みたいなものはないのか？ 私やkeepaを読み込むAIが、書かれている用語の意味を履き違えてしまっている可能性がある為、正確な用語の意味の解釈が必要。まずは公式の方から探って、調査して下さい。」

## 背景（なぜ今これが必要か）

当社の既存Keepaナレッジは **一次情報（公式）を土台にしていない**。

| 既存資産 | 実際の出典 |
|---|---|
| T-20260811-001 Keepa使い方マニュアル 第2版 | 社長提供スクショ6枚の**画面観察** |
| T-20260817-004 Keepa実務ナレッジ | **第三者YouTube動画** + keepa.com Proページの部分的実機確認 |
| memory: knowledge_keepa_operation_umizou / reference_keepa_reading_pitfalls | 上記 + 社長レクチャー |

結果として、**意味を断定できないまま「要確認」で放置されているラベルが最低3件**ある
（「BUY BOX の平均売上数」「購入ボックス切り替えの所有者」「評価 -1%」／T-20260811-001 README）。
また日本語UIの訳語が原語（英語）と1対1で対応していない疑いがあり、
**AIがスキャンスクリプトやシート列名を解釈する際の誤読リスク**に直結する（T-20260803-001 / T-20260817-005 の判定基準に影響）。

## ゴール

1. **公式ドキュメントが存在するか／どこにあるかを確定させる**（存在しないなら「存在しない」と確定させることも成果）
2. 公式が定義している **Keepa用語の正確な意味**を、原語（英語）と日本語UI表記の対応付きで一覧化する
3. 当社の既存ナレッジ・スクリプト・シート列名との **突合と誤りの指摘**

## 調査範囲（公式優先・この順で）

- keepa.com 本体のヘルプ／マニュアル／FAQ／チュートリアル該当ページ
- Keepa 公式フォーラム（keepa.com のディスカッション）— Keepaは公式ドキュメントをフォーラムで配っている可能性が高い
- Keepa API ドキュメント（Product object の各フィールド定義。当社スクリプトが直接叩いている先＝最も定義が厳密）
- Chrome拡張／Keepa Box 内のヘルプ・ツールチップ（?アイコン等）
- Keepa 公式YouTube／公式ブログ
- 日本語UIと英語UIの表記突合（**表示言語をEnglishに切り替えて原語ラベルを取る**。T-20260817-004で「次にKeepaを開く回のついで」とされていた宿題）

第三者の解説記事・動画は**参考としてのみ**扱い、公式と区別して明記する。

## 制約

- §4.1 該当操作（課金・契約・外部発信）は一切行わない。**閲覧と記録のみ**。
- ログインが必要な画面に当たったら止めて、カズヨ経由で社長に1手だけ依頼する（§4.4）。
- 公式で確認できなかったものは「不明」と書く。**推測で埋めない**（T-20260811-001で確立した方針）。

## 現在地（2026-08-24 サトル）

- **イシュー**：「当社（社長＋スキャンスクリプトを読むAI）がKeepaの用語を、公式定義と食い違って解釈している箇所はどこか」。使い方の習得ではなく**定義の確定**が問い。
- **調査スコープ**：keepa.com公式（ヘルプ/FAQ/フォーラム/APIドキュメント/公式ブログ/公式YouTube）＋当社既存ナレッジ4本＋scan_v13.py のフィールド解釈。第三者情報は「参考」として区別のみ、定義には採用しない。
- **打ち切り条件**：(1) 公式ドキュメントの所在が確定した時点、(2) API Product object の全フィールド定義を取得した時点、(3) 未確定3ラベルについて「公式に定義があるか／ないか」を確定した時点。これ以上は推測になるため、公式に記述が無い語は「不明」で確定させ、実機確認が要るものはカズヨへブラウザ依頼リストとして渡す。

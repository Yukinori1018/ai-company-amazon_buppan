## 要件

社長から「`_inbox_社長共有` に共有したファイルが整理されていない。最初はきちんと運用されていたが今はできていない。原因究明と改善を」との指摘。
未処理ファイルが 22件（xlsx 1 / PNG 21、2026-08-09〜08-12）滞留している状態を解消し、**二度と滞留しない仕組み**を作る。

## 秘書の初期調査（カズヨ / 2026-08-21）

現時点で判明している構造的な原因候補：

1. **`.gitignore` 対象（`.gitignore:24`）** — inbox 配下の増減が Git 差分に出ない。
   既存フックはすべてリポ内ファイルの変更を検知して動くため、**inbox だけ検知の死角**になっている。
2. **ルールが CLAUDE.md にも agents/ 配下にも一切ない** — 記述は `_inbox_社長共有/README.txt`（社長向けの使い方説明）だけ。
   エージェント側の「誰が・いつ・どう処理するか」という責務定義がゼロ。
3. **プル型トリガー依存** — README.txt の運用は「社長がチャットで『フォルダに入れた』と伝える」が起点。
   社長が言い忘れる／チャットに画像を直接貼る運用に変わると、フォルダは永久に処理されない。
4. **マリエの定常責務リストに未登録** — 成果物カタログ同期・Notion 同期は定常責務化されているが、inbox 棚卸しは入っていない。
5. **処理済みの行き先が未定義** — README.txt は「移動されることがある」とだけ。archive/ 等の受け皿がないため、
   処理しても元ファイルの扱いに毎回迷う → 放置が既定行動になる。

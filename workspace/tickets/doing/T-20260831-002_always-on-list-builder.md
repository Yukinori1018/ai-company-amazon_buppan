## 依頼（社長・2026-08-31）

> 「これも私が継続的にあなたに指示を出し続けなくても、あなたの方で、毎日リストを取得していけるような仕組みを考えて、それを実行して下さい。一応暴走しないように、12時間という区切りをつけましたが、大きな意図はありません。言うなれば、常にリスト化していって欲しいです。トークンの上限が来たら、そのまま止まり続けず、ある起点をきっかけにリスト化を再開するような仕組みを作って下さい。hookやループ機能を使うと良いかもしれません（絶対使ってという意味ではありません。ただの提案です）。」

**12時間の上限は社長の意図ではない**（暴走防止の仮置き）。撤廃してよい。

## 現状の限界

| 事実 | 数字 |
|---|---|
| v14 の最終走行 | 2026-08-25 01:30 に **12時間で自動停止**。以後6日間止まったまま |
| 積み上がった量 | 処理1,800商品 → 候補1,520件 / メーカー822社 |
| 停止理由 | `--max-hours 12`（`scan_v14.py` の `MAX_HOURS_DEFAULT`）。トークン枯渇ではなく**時間で切っている** |
| Keepa トークン | 上限1,200・補充20/分。**貯め込めないので「速く回す」意味がなく、「長く回す」ほど積み上がる** |

つまり現状は「走らせれば積み上がるのに、走っていない」状態。**社長が毎回起動を指示しないと動かない**のが本質的な欠陥。

## ゴール

**社長が何も言わなくても、毎日リストが増え続けている。** 具体的には：

1. **時間で止まらない** — トークンが尽きたら止まらずに待ち、補充されたら続行する
2. **落ちても勝手に戻る** — Mac の再起動・スリープ復帰・電源断・クラッシュから無人で復帰する
3. **母数が枯れない** — 同じ検索条件を回し続けて新規ゼロになる事態を防ぐ（後述）
4. **毎日の増分が見える** — 社長がセッションを開いたら「昨日 +◯件・累計◯件・メーカー◯社」が目に入る
5. **暴走しない** — 止め方が1つ用意されていて、異常時は自分で止まる

## 設計上の最大の論点：母数の枯渇

同じ Product Finder 条件を回し続けると、`seen_asins.txt` で全部弾かれ、**トークンだけ消費して新規0件**になります。ここが一番の設計課題です。

- カテゴリ × ランク帯 × 価格帯などで**シャードの網**を作り、巡回する（`shard_cursors.json` が既にある。設計を確認して活かすこと）
- 網を1周したら、**一定期間後に再訪**する（新商品が入るため、再訪自体は無駄ではない）。再訪間隔は設定値に
- **「新規獲得率」を毎日記録**し、下がってきたらログで警告する。枯れているのに回し続けるのが最悪

## 実装の指針（縛りではなく出発点。より良い案があれば根拠つきで採用可）

- **常駐は launchd**。同一リポに手本が2つある：`~/Library/LaunchAgents/com.aicompany.amazon-buppan.github-sync.plist`（30分間隔・稼働中）と `com.aicompany.amazon-buppan.night-shift.plist`
  - ⚠️ **night-shift のジョブは現在 exit 127 で失敗しています**（`launchctl list` で確認済）。同じ轍を踏まないよう、なぜ失敗しているかを先に確認すること。ついでに直せるなら直す
  - `KeepAlive` / `RunAtLoad` を使えば、落ちても再起動しても自動で戻る
- スキャナ側は既に**冪等・再開可能**（`seen_asins.txt` / `shard_cursors.json` / 逐次保存）。ここは活かす
- 日次ロールアップ（増分集計・メーカー名寄せ再生成・HTML再生成）を1本のジョブに
- 社長への可視化は `.claude/hooks/session-start.sh` に1行足すのが最も確実（既にリマインダーの仕組みがある）

## 暴走防止（社長の懸念に直接答えること）

| リスク | 対策 |
|---|---|
| 止められなくなる | `STOP` ファイル1つで止まる導線を維持。**止め方を README の一番上に書く** |
| ディスクを食い潰す | `raw/` `raw_offers/` の肥大に上限。古いものは圧縮 or 削除。ログはローテート |
| 壊れたまま回り続ける | 連続エラー・新規獲得ゼロが続いたら自動停止し、次セッションで報告 |
| **課金が発生する** | Keepa は月額固定・トークンは契約上限内という理解だが、**超過課金の有無を公式で確認すること**。従量課金が1円でも発生する設計なら §4.1（金銭）＝実行前に社長承認 |
| リポジトリを汚す | 生成物のコミット方針を決める。30分ごとの github-sync が全部拾って push する（**このリポは PUBLIC**）。巨大CSVを毎日コミットしない工夫を |

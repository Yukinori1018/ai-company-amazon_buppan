## 発端

社長が T-20260904-004 の `03_初回仕入れ_発注セットと全体まとめ.html` を成果物カタログから探したが見つからなかった。
「以前も見たい資料がカタログになかったことがある」との指摘。あわせてカタログの使い勝手について3点の不満。

## 原因（カズヨが特定・2026-09-09）

**① フォルダ内 `.gitignore` の「全除外＋許可リスト」方式**
`workspace/output/deliverables/T-20260904-004/.gitignore:50` が `*` で全ファイルを除外し、その下に `!ファイル名` を1行ずつ書いて許可する設計（T-20260904-004 の F_再発防止_gitignore反転 由来）。
9/6 に生成された `03_...html` は許可リストへの追記が漏れており git 追跡外。
→ GitHub に上がらない → カタログにも載らない。**新しい成果物は黙って消えるのが既定**という構造。
同型の `.gitignore` が deliverables 配下の 8 チケットフォルダに存在。

**② カタログの GitHub リンクが作業ブランチ固定**
全226行が `blob/claude/nighttime-work-checkin-iTWEa/...`。main には T-20260904-004 フォルダ自体が無い（main と 316 コミット差）。ブランチ削除でリンク全滅。

**③ blob URL は HTML を描画しない**（クリックしても GitHub の画面が出るだけでダウンロードが必要）

**④ タイトル列に付番が無い**（`01_` `02_` `03_` が落ちており社長が特定できない）

**⑤ 追記運用そのものが破綻**
git 追跡済みなのにカタログ未記載のファイルが 248 件（T-20260831-004:52 / T-20260831-001:41 / T-20260904-004:27 / T-20260804-001:24 ほか）。
「成果物が出るたびマリエが手で1行追記する」運用は積み残しが常態化している。

## 社長の決定（2026-09-09・その2で上書き）

**運用は今まで通り Google スプレッドシート。HTML 版カタログは作らない。**
シート内のリンクをクリックしたらローカルの実ファイルが開くこと、が要件。

技術的制約: Google スプレッドシートのハイパーリンクは `file://` を受け付けない（`=HYPERLINK("file:///...")` は無効扱い、通ってもブラウザ側がブロックする）。
→ **ローカル常駐の軽量 HTTP サーバを置き、`http://localhost:<port>/...` のリンクにする。** 実体はローカルファイルなので社長の要件（ローカルを叩く）を満たす。Mac ログイン時に自動起動し、社長の操作は不要にする。

（当初は file:// + HTML 版カタログで決定していたが、上記の制約により 2026-09-09 に方式を差し替え）

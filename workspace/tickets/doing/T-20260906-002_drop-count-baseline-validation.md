## 背景（社長の指摘から）

T-20260904-004 の抽出パイプラインは、S5「回転（30日で1個以上売れている）」を **Keepa の salesRankDrops30 ≧ 1** で判定し、45件を落として32SKUを通した。

ところが 2026-09-06、社長の指摘で次が判明した。

対象 ASIN **B0015L0RGK**（ナカバヤシ PHS-101CM・メーカー生産終了・T-20260906-001）について、
30日／90日／180日／365日のドロップ数を「月あたり」に割り直すと、**4期間ともほぼ同じ値になる**。

- 365日窓は大半が **Amazon在庫あり・BuyBox ¥2,039〜2,109** の時期
- 90日窓・30日窓は **供給停止後**（Amazon の最終 BuyBox 獲得は 2026/06/29、現在は第三者FBM 1件が ¥3,176・カート資格なし）

**Amazon が52%のカートを持って売っていた時期と、誰も買えない現在とで、月あたりのドロップ率が変わっていない。**
販売を測っているならレジーム変化で必ず落ちる。落ちていない＝**この帯のドロップはランキングの相対変動（ノイズ）に支配されている疑いが濃い**。

※ 実数は Keepa 固有の加工値のため本ファイルには書かない。Keepa Box の Data ＞ 製品詳細
（「売れ筋ランキング - 過去◯日間の減少」）で誰でも再確認できる。

公式定義（`keepa.com/api-docs/statistics-object.html`）も
`salesRankDrops30` = "The count of sales rank drops (from a high to a low value) … **considered to indicate sales**"
であり、Keepa 自身が代理指標としか言っていない。**閾値の記載はない。**

これが正しければ、**S5 は「売れていない商品」を素通ししている**。発注セット8SKU どころか、通過した32SKU 全部が疑わしい。生産終了の件よりこちらのほうが根が深い。

## やること

### 1. 対照実験（最優先・これだけで結論が出る可能性が高い）

Keepa API の stats で、以下のドロップ数（30/90/180/365日）を取得して並べる。

- **B0015L0RGK** — 生産終了・カート不在・実売ほぼ無いと推定
- **B001MS8HRW**（PHH-101CM・現行・Amazonが11点在庫・¥1,355）— 確実に売れている
- **B0G5DGWVGM**（PHH-101CM ×2・現行・Amazon 5点在庫・¥2,710）

**同水準なら14はノイズ。兄弟品が明確に多ければ実売が含まれる。**

### 2. ランク帯別ベースラインの実測

`shiire_list_3000.csv` / 親チケットの母数 26,942件 から、カテゴリ（少なくとも 文房具・オフィス用品）× ランク帯（#1千未満 / 1千〜1万 / 1万〜3万 / 3万〜10万 / 10万〜50万 / 50万超）ごとに、**ドロップ数の分布**を出す。

- 「売れている」ことが別根拠で確からしい群（Amazon本体が在庫・オファー多数・レビュー増加あり）と、
- 「死んでいる」ことが確からしい群（生産終了・在庫切れ長期・オファー0〜1）
  を分けて分布を比較する。

**知りたいのは「ドロップ数がいくつ以上なら実売と言えるのか」の閾値。推測ではなく分布で出すこと。**

### 3. 交差検証に使える独立指標を探す

ドロップ数以外に実売を裏取りできるものを、取得可能性込みで洗い出す：
`COUNT_REVIEWS` の増分／`月間販売数`（Amazon の「過去1か月で〇点購入されました」= Keepa の該当フィールド）／`outOfStockPercentage` の推移／`totalOfferCount` の減少／`RATING` 更新。
**※ `offers` パラメータを付けないと BuyBox・オファー数・RATING・COUNT_REVIEWS は更新されない**（既知。memory: reference_keepa_official_docs）。

### 4. S5 フィルタの再設計案

上の結果をもとに、S5 を差し替える案を出す。単一閾値でなく複合条件になる想定。
**「直さない」という結論も可**。その場合は、なぜ現行で十分かをデータで示すこと。

## 完了報告

社長の指摘は正しく、しかも原因まで特定できました。

**`salesRankDrops30` は「Keepa がその商品を何回ランクを見に行ったか」を測っています。**
観測回数とドロップ数の相関は **0.991**、上限に対する充填率の中央値は **0.48**。
0.5 という値は「ランダムに揺れる系列を離散サンプリングしたとき前回より下がっていた割合」＝コイン投げです。
月 2,500 点規模が売れている商品群でも、ドロップ数の平均は1桁でした。

対照実験（3検体）では、指摘どおり生産終了品と現行品の月あたりドロップ率がほぼ同じでした。
理由は2つあり、**3検体は同じ親 ASIN の兄弟で、ランキング履歴の値が文字どおり同一**でした。
**死んだ子 ASIN は、生きている兄弟の売上でドロップします。閾値をいくら上げても検出できません。**

現行 S5（`>= 1`）は、死んでいる疑いのある商品の **65%** を通します。事実上フィルタとして働いていません。
弁別力が最大になるのは 10 前後（死に通過 11%）ですが、それでも兄弟問題には無力なので、
**閾値の調整では直りません。指標を差し替える必要があります。**

代替は既に手元にあります。売れ筋ランキング自体が、Amazon 公表の月間販売数に対して
順位相関 **-0.519**（符号も正しい）。ドロップ数は **-0.334（符号が逆）**。
**ランクのほうが強く、取得コストは同じです。**

### 妥協点・確度

- 層化抽出は文房具・オフィス用品 300 件、機構の検証は 50 件。**相関 0.991 は 50 件でも動きませんが、
  ランク帯の閾値をカテゴリ横断で確定するには追加で約 1,000 トークン（約1時間）が要ります。**
- レビュー件数の増分は今回測れていません（`offers`/`rating` 必須でトークン単価が 1→7 になるため）。
  最終候補の絞り込み段階でだけ使う指標という位置づけにしました。

### 社長判断が必要な論点

S5 の直し方が A/B/C。**推奨は A、ただし今夜は B を先に打つのが安全**です（詳細は成果物 §5）。

- **A: 抽出軸をランク＋Amazon公表販売数に付け替える**（推奨・パイプライン改修）
- **B: 32 SKU の再検査だけ手で当てる**（応急処置・約30分・発注セットを守る）
- **C: ドロップ数の閾値を 1 → 10 に上げる**（**非推奨**。兄弟問題に無力で、指標の意味は直らない）

トークンは実測で約 700 消費、残り約 700（回復 20/分）。

### 完了報告（追補）

**X = 10。ただし単独では使えません。「Keepa が30日で20回以上観測している」ゲートとセットでのみ意味を持ちます。**
標本内に、**ドロップ数 0 で月4万点売れている商品**が実在しました（Keepa が2回しか見ていないため）。
観測回数を見ずに足切りすると、カテゴリ最上位の商品から先に削れます。

**そして①だけでは今回の失敗を防げません。失敗SKUのドロップ数は 14 で、X=10 を超えています。**
落としたのは **②カート最終獲得日（70日前）と③不在率（100%）**でした。**②が主役、①は補助**です。

**32SKU バックテスト: 新条件で残るのは 5 件。失敗SKUは確実に落ちます。**
落ち方の内訳は ①-b 19件 / ①-a（観測不足＝判定不能）5件 / ② 11件 / ③ 5件。
「①だけで大半が落ちるなら②③は後回しにできるか」への答えは **できません**。
①だけなら8件残りますが、**その8件に失敗SKUが含まれます。**

②③④はすべて Keepa API で取得可能（`offers=20&buybox=1`）。`lastBuyBoxUpdate` は存在せず
`buyBoxSellerIdHistory` から自前計算します。**単価は 1 → 約6トークン（実測 32件=191）なので2段構えが必須。**
全件に offers を当てると16万トークン・6日かかります。

### 設計上の指摘

- **④は独立したフィルタになりません。②に吸収されます。** 厳しく実装したら32件中0件になりました。
  「ランク由来の数字を単独の根拠にしない」という運用上の禁止事項として残すのが正しい形です。
- **「BuyBox が親子問題を破れる唯一の軸」は少し違います。** オファー数・在庫切れ率・公表販売数も子単位で独立
  （対照実験で3兄弟が別々の値を持っていた）。ただし**この候補プールで使えるのは BuyBox だけ**なので、
  結論としてのご判断は正しいです。理由が違うだけです。
- **私の A 案が不採用で正しかったことを実証しました。** ②③を通った19件のうち、Amazon 公表の販売数が
  取れたものは **0 件**。候補プールは公表販売数が存在しない帯に丸ごと入っており、A 案は動きません。

### 妥協点・確度

- **X=10 の較正は外挿です。** 正解ラベル（Amazon 公表販売数）が存在する帯で較正しましたが、
  実際の候補プールはその下の帯にあります。②③で「生きている」と確認できた19件のうち14件が X=10 で落ちており、
  **この帯では厳しすぎる可能性があります。推測として申告します。**
  初回の1周で実売が取れたら、その実績で測り直すのが唯一の正攻法です。
- **5件は既存の発注セット（9/6/8 SKU）をどれも組み直せない件数です。** 条件の問題ではなく、
  上流の母数26,942件を新条件で引き直す必要があるということです。

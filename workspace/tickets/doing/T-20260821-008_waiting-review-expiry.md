## 完了報告

### CLAUDE.md §6 に書いたこと

waiting の該当例5つはそのまま残し、その直後に2ブロック追加しました。

**レビュー待ちの期限**
> 上記のうち **「納品物の社長レビュー待ち」に限り**、`next_check_at` を過ぎても社長の反応が無ければ、**秘書が done にしてよいかを判定します**。自動では done になりません。判定するのは秘書であり、**確認が取れなければ done にしない**。

**期限が適用されないもの（時間の経過で可決されることはありません）**
> - **§4.1 該当の承認待ち**（金銭・契約・外部発信・不可逆な削除・第三者連絡）— **社長が承認するまで、何日経っても未承認です。**
> - **社長自身の手作業待ち**（アカウント開設・API キー取得など）— 社長が手を動かすまで進みません。

あわせて done の定義を「社長が確認済み、**または秘書が上記の期限判定で done にしたもの**（判定者と根拠をチケットに残す）」に更新しました。

### ticket-management.md に書いたこと（§レビュー待ちの期限判定）

- **対象** — 「納品物の社長レビュー待ち」だけ
- **対象外を表で3種**（§4.1 承認待ち／社長の手作業待ち／社長へ判断を仰いでいるもの）。`requires_approval: true` は**入口で除外**する運用を明記
- **判定手順5項目** — ①成果物が実在するか（実際に開く）②後続チケットで既に使われているか ③社長が別の場で言及していないか ④社長の判断・手作業が残っていないか ⑤**①〜③のいずれも確認できなければ done にしない**
- **記録の型** — 判定者と根拠を1行。2026-08-21 の棚卸しでカズヨが使った形をそのまま踏襲

### 文章上の判断（3点）

1. **§4.1 の除外は「否定形の規則」でなく「状態の断言」で書きました。** 「期限切れで自動可決されない」より「**社長が承認するまで、何日経っても未承認です**」のほうが破りにくいためです。ご指示のとおり「原則として」「基本的に」等は使っておらず、**grep で混入0件を確認**しています。

2. **裁量を与える文は、動作主を主語に立てました。** 「期限切れで done になる」と書くと主語が消えて、放置が承認に化けます。「**秘書が done にしてよいかを判定します**」なら、誰かが手を動かさない限り何も起きません。「自動では done になりません」も併記しました。

3. **判定手順の最後を「確認できなければ done にしない」で締めました。** 同じ内容でも既定値がどちらに倒れているかで運用結果が変わります。忙しいときはリストの最後だけ読まれるため、そこに既定値を置いています。

### 分量

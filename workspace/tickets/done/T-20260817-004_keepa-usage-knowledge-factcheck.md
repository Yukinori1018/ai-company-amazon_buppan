## 当社への適用（カズヨの判断）

本線は②メーカー仕入れ、①電脳/店舗せどりはホールド中のため**全面採用はしない**。ただし以下3点は②でも共通で有効なので取り込む：

- (a) 波形の読み方（特に出品者数の推移を最重要指標に置く）
- (b) 知財クレームを見抜く5サイン（出品制限＝[[knowledge_listing_restrictions_ungating]]とは別軸のリスク）
- (c) 仕入れ数量＝`月間販売個数 ÷（出品者数＋1）`で「1ヶ月以内に売り切れる分だけ」→ T-20260817-002 の消化月数基準と同思想

## 社長回答（2026-08-17）→ 全件クローズ

### 回答内容

1. **Keepa契約** → 表示は €29 だが、社長は **API も利用のため €49/月**。※€49単独か €29+€49=€78 の別建てかは請求明細で要確認。
2. **未確認3点** → 社長が実画面スクショを提供し**全解決**。
   - **月間販売数＝黄色**（動画が正解）。第2段「カテゴリ別販売ランキング」枠内。
   - **出品者数（新品アイテム数）＝第3段**（評価と同枠）、色は青紫。動画の「紫」でほぼ合致。
   - 当社旧記録「紫＝新品」も誤りではない。**「新品」(第1段)と「新品アイテム数」(第3段)が別パネルで似た青紫**なのが混乱の正体 → **凡例ラベル＋パネル位置で判断**が正。
   - 構造の発見: **Keepaのグラフは3段構成**（①価格＋総合ランク ②カテゴリ別ランク＋月間販売数 ③評価・アイテム数）。当社ガイドに欠けていた点。
   - スクショはサブカテゴリ順位の罠の実例（メイン#187 vs サブ#4×2）＋↘31ドロップ/月。
3. **(a)(b)(c) の組み込み → Go**。加えて社長指示「**Amazonが出品している商品は除外が無難**」→ 仕入れ方針v1.3の足切りに**既に反映済み**（`current_AMAZON_gte=-1 & lte=-1`）。よって動画の利益波形②「Amazon本体あり攻略」は**当社不採用**と明文化。

### ⚠️ カズヨの訂正（重要）

初版で「クォータ導入により**製品ファインダーの大量抽出はもうできない／当社の夜間スキャン設計に効いてくる**」と書いたのは**誤り**。社長のご質問（スプレッドシートへのメーカー抽出設計はできなくなるのか）で発覚。

- **Pro €29 のクォータ＝ブラウザUI専用**。当社の抽出は **Keepa API €49（20トークン/分）という別勘定**（`shiire_scan_v3.py` は `api.keepa.com`）。**影響なし**。
- **抽出可能量**: 20トークン/分＝1,200/時＝28,800/日＝約892,800/月。トークンは生成60分で失効（貯金上限1,200）。Product Finder 1クエリ(50件/頁)≈10トークン、**商品詳細≈1トークン/ASIN → 約1,200件/時**。一晩8hで約9,600件、24hで約28,800件。実績＝4,446件を一晩で完走（T-20260803-001）／メーカー台帳3,282社・売れ筋7,840件（T-20260705-002）。
- **抽出はAIにやらせない**方針を明文化（API＋スクリプト＝決定論的。AIは判定要約と優先順位づけのみ）。トークン節約目的のスクレイピングも不採用（Amazon BSA改定でAIエージェント規制強化の報告あり・当社未検証）。

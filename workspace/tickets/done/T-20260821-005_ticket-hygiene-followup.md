**2. 「Notion 同期が大量に走る」は杞憂でした（書き込み0件）**

`next_check_at` と `related_tickets` は **Notion に存在しないリポジトリ専用フィールド**です

→ 今後の一括改名では**「そのキーは Notion のどの列にマップされるか」を先に確認**すれば、見積りが正確になります。

**3. 追加で `parent:` → `parent_ticket:` のドリフトを発見（4枚）**

`related` と同型です。うち2枚（T-20260817-007 / T-20260527-002）は**実在の親を持ちながら正式キーで書かれておらず**、
親子関係が機械から見えていませんでした。ただし**Notion 側には既に正しい親が入っており、ローカルだけがずれていました**。
「ファイルが真実」は「ファイルが常に新しい」という意味ではない、という学びです。

**4. Labels は追加できました。ただし語彙そのものが散らかっています**

- 技術的に可能（`ALTER COLUMN "Labels" SET MULTI_SELECT(...)`）。**⚠️`SET` は選択肢を丸ごと置換する**ので、
  事前に「Labels 使用カード＝0件」を確認し、既存の「まとめ」を必ず含めて実行しました。非破壊です。
- **ただし 87枚に対してラベルが160種**あり、うち約100種が1枚だけの使い捨てタグです。
  そのまま鏡にすると160選択肢のプルダウンになりフィルタとして機能しないため、
  **3枚以上で使われている28種＋「まとめ」だけ**を追加しました。
- **残り約130種は保留です。** 語彙を整理してから同期するか、諦めるか、カズヨのご判断をお願いします。
  なお `infra` と `infrastructure` のように**中身が同じ表記ゆれ**も混じっています（今回は両方追加）。

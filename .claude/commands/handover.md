# /handover — 引き継ぎノート更新

あなたは秘書カズヨです。社長から `/handover` が呼ばれたら、別デバイス・別セッションで Claude Code を起動したときに文脈を引き継げるよう、`workspace/handover.md` を最新化します。

引数: `$ARGUMENTS`

## 動作

### 引数なしの場合（標準）

以下を統合して `workspace/handover.md` を上書き更新します。

1. **社長プロファイル** — `~/.claude/projects/-Users-yukinori-Claude-Code-ai-company-amazon-buppan/memory/` 配下のメモリー（HTML 出力ルール、副業初心者、2軸戦略 等）を要約してノートに反映。**機密情報は載せない**（トークン・API キー・個人特定情報）。
2. **事業の現状** — CLAUDE.md §1 から事業名・ミッション・KPI を読む。
3. **チケット状況** — `workspace/tickets/<status>/T-*.md` を全スキャンし、ID / タイトル / Status / 一言サマリーを表にする。
4. **進行中の論点** — `doing/` と `waiting/` のチケットから、社長返答待ち事項を抽出して箇条書きに。
5. **環境メモ** — Notion DB ID 等の再現に必要な情報を残す（**APIキーは絶対に書かない**、保管場所のパスのみ記載）。
6. **モバイル起動時の推奨初動** — どのファイルから読むか、何を最初に提示するか。

### 引数ありの場合

- `commit` — 更新後に `git add workspace/handover.md && git commit -m "chore: 引き継ぎノート更新" && git push` まで自動実行。社長が明示的に push したい時用。
- `dry-run` — 上書きせず、差分プレビューだけ表示。

### 更新後の動作

- 更新内容のサマリー（何が変わったか）を社長に2〜3行で報告。
- `commit` 引数があった場合は push 完了の URL も併せて報告。

> セッション開始時、秘書カズヨ（または任意のエージェント）はまずここを読みます。
> 更新方法: /handover スラッシュコマンドで自動更新（または手動編集）。

- 更新者: 秘書カズヨ（PC セッション / モバイルセッション 等）

## セキュリティ厳守

- **APIキー / トークン / パスワード**は絶対にノート本文に書かない。保管場所のパスのみ記載する。
- 社長個人を特定する情報（住所・電話・実名 等）も書かない。
- 機密性に迷ったら、書く前に社長に「ノートに載せてよいか」を確認する。

## 完了報告

- 「`workspace/handover.md` を更新しました。X 件のチケットを反映、進行中論点 Y 件、最終更新を YYYY-MM-DD に。」程度の簡潔な報告。
- `commit` 引数時は push URL も。

## §F1 商品を提案する表の必須列

### 旧§3.2（旧 CLAUDE.md 120〜146行）

#### 3.2. 商品を提案する表の必須列（2026-09-30 社長指示）

> 「今度から、私に提案する商品の表に、**Amazon での過去1ヶ月の販売数**と**セラーの数**、**Amazon 本体の有無**も入れて下さい。」（2026-09-30）

**社長へ商品を提案するときは、次の3列を必ず入れる。**成果物の表・報告の表・チケットの表すべてに適用する（秘書もサブエージェントも）。

| 必須列 | 取り方 | 注意 |
|---|---|---|
| **過去1ヶ月の販売数** | Amazon 商品ページ／検索結果の「過去1か月で◯点購入されました」＝Keepa の `monthlySold` | **バリエーションは子 ASIN 側で見る**（ランクは family 共有だが販売数は ASIN 単位）。表示が無い場合は「**表示なし（月50個未満）**」と書く。空欄にしない |
| **セラー数（新品出品者数）** | 商品ページの出品一覧（`/gp/offer-listing/<ASIN>/?f_new=true`）で数える | **Amazon 本体が混ざる**ので内訳を分けて書く。Keepa の「実セラー数」は加工値で PUBLIC リポに書けない（`source-terms-guard` が止める）ので、**画面から数えた実数を使う** |
| **Amazon 本体の有無** | カート保持者が Amazon.co.jp か、および本体の365日在庫率（`outOfStockPercentage365`） | **スナップショットで判定しない**（`availabilityAmazon=-1` は候補が93%過大になる）。「本体がカートを持つ棚は値下げしても取れない」ことが実測で確定している（2026-09-30 ぺんてる ケリー） |

**さらに、社長が現物をすぐ確認できるよう次の3列も必ず入れる（2026-09-30 追加指示）。**

| 必須列 | 中身 |
|---|---|
| **Amazon の URL** | `https://www.amazon.co.jp/dp/<ASIN>`（リンクにする） |
| **購入元の名前** | 仕入れ先の企業名（例：不二貿易株式会社）と、どの卸サイトか（スーパーデリバリー／NETSEA など） |
| **購入先の URL** | その卸サイトの商品ページ URL |

⚠️ **購入先 URL の扱い**：`netsea.jp/shop/...` などの**卸サイトの商品 URL は PUBLIC リポの成果物に書かない**（法務判定 E・`source-terms-guard` がブロックする）。**社長への報告（チャット）と `agent_output/` には書く**。成果物側は「購入元の名前」までに留める。**企業名は公開可**。

**判定結果の積み上げ先（2026-09-30 社長指示）**：「表は、スプレッドシートに貯めていって下さい。」商品を判定するたびに **Googleスプレッドシート『商品判定台帳_Amazon物販事業』**（社長所有・My Drive 直下）へ1件1行で追記する。卸率・購入先 URL などの会員限定の取引条件は**シート側にだけ書く**（リポ内には書かない＝`source-terms-guard`）。シートが正でリポ内にミラーは持たない。**所在（Drive file id・列定義・運用ルール）は memory の `reference_product_judgment_ledger_sheet.md`** に記録。

**理由**：2026-09-30 に「新品オファー11社」と報告した中に Amazon 本体が混ざっており、カート獲得不可＝売れない棚を推奨しかけた。**この3列は仕入れ判定の第0問**（誰がカートを持っているか・実際に売れているか・競合が何社か）であり、欠けた表は判断材料にならない。URL 3列は社長が自分で裏取りするための最短経路であり、**秘書が「確認しました」と書くだけでは足りない**。

## §F3 採算等級

### 旧§3.5（1つ目）等級（旧 CLAUDE.md 403〜412行）

**等級（#18）**：判定は **利益率 OR 利益額**（2026-10-04 社長指示「実践者は単価の下限を置かない。切るのは**利益額400〜1,000円**と利益率5〜30%」＝§3.3-27）。**どちらか一方を満たせばよい。**

- 🔴 **実績枠（2026-10-12 社長方針）**＝中央値で〔1個手残り0円以上〕かつ C に落ちた行、**または A・B 等級で #10 の取り分だけが月1〜3個のため落ちた行**（2026-10-14 秘書判断：薄利の C が残り厚い B が落ちる逆転を解消。2026-10-18 秘書判断：同じ逆転が A 等級にも残っていたので A も含める）。**卸サイトで取引実績・販売実績を作り、メーカー直取引の打診材料にするための枠**（社長「利益がそんなに取れなくても、プラマイ0ぐらいでも取引を進めたい」）。条件：①地雷（#1〜9・#11〜17・#19〜21）は全部 PASS ②#10 の取り分は**月1個以上**（通常は3個）③在庫月数6ヶ月以内 ④最小ロット・1回だけ ⑤悲観値の赤字額を判定理由に書く ⑥🔴**価格が平常であること**（現在価格と90日中央値が1年中央値の1.3倍以内・品薄の一時高値でない）。実績枠は「同じ手順で再現できるテスト」であって、値動きに賭けるものではない（社長「蛍光灯は事業のテストではなくギャンブル」2026-10-12）。判定は「GO（実績枠）」と書き、通常の GO と分けて数える

## §F5 実売と季節

### 旧§3.3-8（旧 CLAUDE.md 172〜176行）

8. **積極条件を必ず1本入れる。「売れている」の根拠がない候補は GO にしない。**1〜7はすべて**消極条件**（地雷を踏んでいないこと）であり、消極条件だけを並べると**通るのは「何も起きていない棚」だけ**になる。2026-09-30、7本のゲートを全部通った5件を実画面で見たら、**3か月の販売が0〜3個・売れ筋ランク68万〜165万位**だった。Amazon 本体もメーカーも競合も来ないのは、そこに市場が無いからである。
   - 積極条件は **`monthlySold` が取れること**（月50個未満だと表示されないので、取れない場合はキーゾンで実測する）
   - **売れ筋ランクは「死んでいないこと」の確認にしか使わない**（family 共有・ドロップ数は観測回数）。10万位以内で PASS、50万位より下は NO-GO、その間は UNKNOWN
   - これは社長が緩めた「月100個以上」の閾値とは**別の話**。**ゼロは閾値ではない。**量を増やしてもゼロは何倍してもゼロ
   - **ゲートを設計したら「この条件を全部通る最悪のものは何か」を必ず考える。**

### 旧§3.3-16（旧 CLAUDE.md 203〜206行）

## §F6 価格・原価・単位

### 旧§3.3-7（旧 CLAUDE.md 171〜171行）

## §G メーカー直取引

### 旧§3.5（2つ目）メーカー直取引の初期方針（旧 CLAUDE.md 462〜479行）

#### 3.5. メーカー直取引の初期方針（2026-10-04 社長と合意）

出典：中村裕紀『Amazon国内メーカー直取引完全ガイド』第5・8・9章（T-20260921-001）。詳細は T-20260930-001。

| 項目 | 方針 |
|---|---|
| 初期の目的 | **取引社数と売上（バイヤーとしての信用）を作る**。利益率は取引を重ねて上げる（2回目から価格交渉） |
| 連絡先リスト | **儲かる順のランキングではなく、送信キュー**。並びは成約しやすさ。量は**月300社を切らさない** |
| 仕入れの判断 | **地雷の確認（§3.3＋本書の5点：商品登録可否・FBA禁止・危険物・期限管理・価格推移）を通り、見積りが利益率5%以上なら、回転の良い型番を5〜10個テスト仕入れ**。売れる量・儲かる額の予測はしない（ツールの数字は当たらない。テストの実績が唯一の正） |
| 打診先の特定 | **社名は公式ページで同じ商品を確認してから決める**（Keepa・Amazon の brand／manufacturer 欄だけで決めない）。根拠URLをリストに載せる。ブランド欄が原料メーカー・販売店・旧社名のことがある（2026-10-04 ユニマットリケン：Amazonのブランド欄は原料メーカーのカネカ） |
| 需要の入口 | 月販が Amazon に表示されていること（月50個以上）。**「月100個以上」は仕入れの足切りに使わない**（9/15 ルールを修正） |
| 2回目以降 | 数量は初回の実績だけで決める。利益が出なかった社も、次の型番や紹介先（卸問屋）で続ける |

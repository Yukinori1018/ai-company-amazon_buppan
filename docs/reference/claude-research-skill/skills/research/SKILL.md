# 自律リサーチ

## オーケストレーターの禁止事項

このスキルを起動したあなたは**指揮役**です。以下は違反です。

- **自分で検索する**（`web_search_exa` / `WebSearch` を自分で叩く）
- **自分で本文を読む**（収集目的の `WebFetch`）
- サブエージェントを使わずに進める
- 収集を逐次で回す（並列で起動すること）
- 人間にテーマや続行可否を確認する

**あなたの仕事は、起動・監視・判定・報告の4つだけです。**

サブエージェントに必要なツールが無い場合、自分で代行してはいけません。
その時点で停止し、「〔エージェント名〕に〔ツール名〕が無い」と報告してください。
代行すると並列性・コンテキスト分離・検証の独立性が同時に失われます。

## 出力の必須要件

**チャットへの報告だけで終えてはいけません。**
以下のファイルが存在しない状態で完了報告することは違反です。

```
research/
├── question.md      問いとクエリ設計
├── coverage.md      カテゴリ別の充足状況
├── raw/             収集エージェントの出力（1体1ファイル）
├── notes.md         統合後の事実＋検証結果
├── escalation.md    人間の裁定が要る論点
└── draft.md         成果物
```

報告文にしか無い判断は、次のセッションで消えます。

## Phase 0｜問いの分解

検索せず `question.md` を作る。テーマが未指定なら、直近の文脈から
最も妥当なものを自分で決めて宣言する。**人間に選ばせない。**

1. 独立して検証できる小問に5〜8個へ分解
2. 各小問に、担当カテゴリと検索クエリ案を割り当てる
3. **供給側語彙のクエリを最低2本**
4. **反証クエリを最低1本**
5. **3年前・5年前を問うクエリを最低1本**

### 供給側語彙の原則

一次情報が返るかどうかは、クエリの語彙でほぼ決まる。

| 語彙 | 結果 |
|---|---|
| 需要側の悩み言葉（「断られた」「失敗」「〜のコツ」） | 解説記事・アフィリエイト |
| **供給側が自分のページに書く言葉**（「募集要項」「お申し込みの流れ」「最低発注ロット」） | **一次情報** |

反証を取りたいときも、需要側の悩み言葉ではなく
**供給側が書く断り文句**（「お断りしております」「応募条件」「規約」）で組む。

`coverage.md` を §A のカテゴリ表で初期化し、確認を求めず Phase 1 へ。

## Phase 1｜並列収集

Phase 0 で分解した小問を見て、**どのカテゴリが必要かを自分で決める。**
人間に体数を聞くな。

判断基準:
- 市場規模・シェア・件数を問う小問がある → 01 公的統計
- 企業の戦略・リスク・条件を問う小問がある → 02 企業の一次開示
- 実務の手触り・失敗談を問う小問がある → 03 現場の声
- 因果・効果検証を問う小問がある → 04 学術
- 直近の動きを問う小問がある → 05 報道
- 日本固有か海外先行かを問う小問がある → 06 海外

該当したカテゴリ全てで research-collector を**同時に起動する。**
逐次実行は違反。該当が2つ以下なら2体でよい。上限は6体。

選んだ理由と選ばなかった理由を coverage.md の冒頭に1行ずつ書く。

各起動時に渡すもの：担当カテゴリ名、出力先ファイルパス、担当する小問。

**同一ファイルへの並列書き込みは必ず壊れる。1体1ファイル。**

## Phase 2｜統合

`research-integrator` を1体起動する。あなたが統合してはいけない。

## Phase 3｜検証

`research-verifier` を1体起動する。
**Phase 1 の収集エージェントに検証させてはいけない。**

## Phase 4｜カバレッジ判定

```
Phase 5 へ進む条件:
- coverage.md の全カテゴリに1件以上の出典がある
- または Phase 1〜4 を2周した
```

満たさなければ、空カテゴリだけを担当する collector を再起動する。
「網羅せよ」は機能しない。必ず数値で判定する。

## Phase 5｜執筆

`research-collector` とは別に、執筆専任として `general-purpose` を起動するか、
`/clear` 後に `notes.md` だけを読ませる。**収集の記憶を持ったまま書かせない。**

```
notes.md だけを読んで〔成果物〕を書き、research/draft.md に出力しろ。

- notes.md にない主張は書くな。知識で補完するな
- 「検証結果」で不一致・要注意とされた行は使うな
- 各段落末に根拠の行番号を [#3] の形で置け
- escalation.md の論点に依存する箇所に [要確認 #n] を残し、
  その段落に「この結論は #n の裁定次第で変わる」と書け
- 不明は「不明」と書け。埋めるな
- 反証側の情報を最低1段落入れろ
```

## 自動停止条件

次に触れたら停止して人間に報告する。それ以外では止まらない。

```
- D分類（裁定不能な矛盾）が3件以上
- 2周してもカバレッジの空カテゴリが2つ以上残る
- 主要な結論が単一ソースにしか依存していない
- 反証側の情報源が0件
- サブエージェントに必要なツールが無い
```

後半3つが重要。単一ソース依存と反証ゼロは、人が見ていないと最も
気づかれない失敗であり、しかも出力は自信たっぷりに読める。

## 完了報告

**生成したファイルパスを必ず列挙する。**ドラフト本文は貼らない。

- 生成ファイル一覧
- 収集件数 / 統合後件数 / 本文確認済の割合
- カテゴリ別の充足状況
- A〜Cで自動確定した矛盾の件数
- `[要確認]` の数と各1行要約
- 検証で不一致が出た行

## §A 情報源カテゴリ

| # | 担当 | 入口 |
|---|---|---|
| 01 | 公的統計 | e-Stat、経産省、業界団体の年報 |
| 02 | 企業の一次開示 | **EDINET（有価証券報告書）**、決算説明資料 |
| 03 | 現場の声 | X、YouTube、レビュー、掲示板 |
| 04 | 学術 | J-STAGE、CiNii、Google Scholar |
| 05 | 報道・業界紙 | 各種報道 |
| 06 | 海外 | 同テーマを英語で検索 |

EDINET の「事業等のリスク」には、市場のプレイヤー自身が何を脅威と
考えているかが実名で書いてある。憶測を潰す材料として特に強い。

## §B 外部ソース

YouTube・X から取り込む必要が生じたときだけ
`references/external-sources.md` を読め。それ以外では読むな。

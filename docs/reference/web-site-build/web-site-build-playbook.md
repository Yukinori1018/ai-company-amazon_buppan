## ⚠️ 当社向けの重要注記（読み飛ばさないこと）

**この手順書のデフォルトの見た目は「ポップ／カジュアルなポートフォリオ調」です。**
配色（paprika/sun/leaf 等の高彩度パレット）・フォント（Zen Maru Gothic 900 の丸ゴシック見出し）・リソグラフ風の質感は、**個人ポートフォリオ向けのトーン**であり、そのまま流用してはいけません。

**Satoy Select は、メーカー・卸から信用を得るための B2B 会社サイトです。** 取引先が「この会社と組んで大丈夫か」を判断する場です。したがって：

- **配色・トーンはそのまま使わず、「堅実な企業サイト」向けに翻案する。** 低彩度・寒色/ニュートラル基調、明朝またはオーソドックスなゴシック、装飾を抑えた余白設計。ポップさより「信頼・誠実・整然」を優先する。
- **この手順書から流用するのは「工程の分け方」と「進め方の規律」であって、見た目の指定ではない。** 具体的には後述の「全体の原則」（素材→文章→構造→装飾→動きの順／1フェーズ1セッション／フェーズごと commit／範囲を切って修正指示）が当社にとっての本体価値。
- パレット・フォント・質感の各指定は、案件ごとに当社のブランド方針へ置き換えてから CLAUDE.md に書く。

> Satoy Select サイトの既存の決定事項（住所は掲載・電話は非公開・メールはフォーム化・「開店準備中」を明示 等）は
> `agents/content_creator/memory/satoy-select-site-handover.md` に別途あるため、本手順書と必ず併読すること。
> 手順書の「連絡先セクション」等の一般論より、案件固有の決定事項が優先する。

# ポートフォリオサイト制作手順書（Claude Code 用）

素材集めから公開までを 6 セッションに分割する。
**1 セッション = 1 フェーズ**。終わったら `/clear` して次へ進む。
各フェーズの「貼る文」をそのまま Claude Code に貼れば動く。

---

## セッション 0：土台をつくる

```bash
mkdir -p ~/projects/portfolio && cd ~/projects/portfolio
git init
mkdir -p assets/raw assets/img docs
npm init -y
npm install -D sharp
```

**貼る文：**

> このディレクトリで、ポップ／カジュアルなトーンの1ページ完結ポートフォリオサイトを作る。
> まず `CLAUDE.md` を作成してほしい。中身は以下を必ず含めること。
>
> - 配色：paprika `#FF4B33` / sun `#FFC22E` / leaf `#12B886` / ink `#16143A` / paper `#FFF3DE`。この5色以外は使わない
> - フォント：見出し Zen Maru Gothic 900、本文 Zen Kaku Gothic New 500、ラベル Space Mono 700
> - 実装ルール：HTML/CSS/JSの素のコード。ビルドツール・CSSフレームワークは使わない。アニメーションは GSAP のみ許可
> - 画像は必ず `assets/img/` 配下のWebPを参照する。外部URLの直リンク禁止
> - 必ず守ること：モバイル対応、キーボードフォーカスの可視化、`prefers-reduced-motion` の尊重
> - 指示がない箇所を勝手に足さない。変更は指示された範囲だけ行う
>
> 作成後、`.gitignore`（node_modules, .DS_Store, assets/raw）も用意して commit して。

---

## セッション 1：必要な素材を洗い出す

先に「何が要るか」を確定させる。ここを飛ばすと素材集めが無駄打ちになる。

**貼る文：**

> サイトの構成案を `docs/STRUCTURE.md` に書き出してほしい。セクションは
> ①ヒーロー ②つくったもの（3件） ③じぶんについて ④連絡先 とする。
>
> あわせて `docs/ASSET_LIST.md` を作成し、必要な画像を表形式で列挙して。
> 列は：ファイル名 / 用途 / 推奨サイズ(px) / 縦横比 / 入手方法（自分で撮影・スクショ・フリー素材・AI生成）/ 代替テキスト案。
>
> ヒーローの背景、各実績カードのサムネイル3枚、OGP画像、favicon は必ず含めること。
> 実績のサムネイルは「自作アプリの画面キャプチャ」を想定して、推奨サイズを指定して。

---

## セッション 2：素材を集める・作る

### 2-1. AI生成用のプロンプトを書かせる

**貼る文：**

> `docs/ASSET_LIST.md` のうち「AI生成」に分類した画像について、
> 画像生成AI（Midjourney / FLUX / ChatGPT Images）に貼れる英語プロンプトを
> `docs/IMAGE_PROMPTS.md` にまとめて。
>
> 条件：CLAUDE.md の5色パレットを英語の色指定で反映する／リソグラフ印刷風のフラットな質感／
> 文字は入れない／被写体を中央に寄せず余白を残す（テキストを重ねるため）／アスペクト比の指定も付ける。
> 各プロンプトに、生成後どのファイル名で保存するかを明記すること。

生成した画像は `assets/raw/` にそのまま放り込む。ファイル名は指示どおりに。

### 2-2. フリー素材を使う場合

Unsplash / Pexels / o-dan からダウンロードして、同じく `assets/raw/` へ。
**ライセンス表記が必要なものは `docs/CREDITS.md` に記録する**ようClaude Codeに指示する。

### 2-3. 画面キャプチャ

自作アプリのスクショは、ブラウザ幅 1440px で撮る。撮ったら `assets/raw/` へ。

### 2-4. 最適化を任せる

**貼る文：**

> `assets/raw/` の画像を sharp を使って一括処理するスクリプト `scripts/optimize.mjs` を書いて実行して。
> 処理内容：`docs/ASSET_LIST.md` の推奨サイズにリサイズ → WebP変換（quality 82）→ `assets/img/` に出力。
> あわせて 2x（Retina用）も出力し、`@2x` サフィックスを付ける。
> 実行後、生成されたファイル一覧とファイルサイズを表で報告して。
> favicon と OGP（1200x630）も生成すること。

**ここで commit。** 素材が確定してから初めてコードを書き始める。

---

## セッション 3：文章を確定させる

デザインが安っぽく見える原因の大半はコピー。先に文字を決める。

**貼る文：**

> `docs/COPY.md` に全セクションの文言を書き出して。ルールは以下。
>
> - 一人称の語りで、ですます調。誇張表現と抽象的な形容詞（「革新的」「唯一無二」等）は使わない
> - ヒーローの見出しは20文字以内。何をしている人かが一読で分かること
> - 実績3件は「何を作ったか」「なぜ作ったか」「今どうなっているか」の3文構成
> - ボタンの文言は、押した後に起きることをそのまま書く
>
> 内容が分からない箇所は仮で書かず、`【要記入：〜】` と明示すること。

→ `【要記入】` を自分で埋めてから次へ。

---

## セッション 4：静的な状態まで実装

**アニメーションはまだ入れない。**

**貼る文：**

> `docs/STRUCTURE.md` と `docs/COPY.md` と `assets/img/` の画像を使って、
> `index.html` と `css/style.css` を実装して。現時点ではアニメーションは一切入れない。
>
> - 画像は `<picture>` で WebP と 2x を出し分け、`width`/`height` を明記（レイアウトシフト防止）
> - ファーストビュー以外の画像は `loading="lazy"`
> - セクション間の余白は CSS変数で一元管理する
> - 375px / 768px / 1440px の3幅で破綻しないこと
>
> 完成したらローカルサーバを立てて、3つの幅でスクリーンショットを撮り、自己レビューして報告して。

修正指示は**範囲を切って**出す。悪い例「全体をもっとおしゃれに」／良い例「ヒーローの見出しと本文の間の余白を1.5倍にして、本文の最大幅を46文字分に制限して」。

**納得したところで commit。**

---

## セッション 5：動きを足す

**貼る文：**

> GSAP と ScrollTrigger を CDN から読み込み、`js/motion.js` に以下だけ実装して。
>
> 1. ページ読み込み時：ヒーローの見出し → 本文 → ボタン の順に、下から12pxのフェードイン（0.1秒差）
> 2. 各セクション：画面に入ったら一度だけフェードイン。カードは0.08秒ずつずらす
> 3. 実績カード：ホバーで浮き上がる（transformのみ、0.2秒）
>
> 制約：`prefers-reduced-motion: reduce` の場合は全アニメーションを無効化し、要素は最初から表示された状態にする。
> スクロール量に追従する演出（パララックス、ピン留め）は今回は入れない。
> 実装後、動きが過剰でないか自己評価して報告して。

やりすぎたら「2番だけ残して他を削除して」と戻す。**動きは足すより削る方が効く。**

---

## セッション 6：仕上げと公開

**貼る文：**

> 公開前チェックをして、問題があれば修正して。
>
> 1. `<head>` に title / description / OGP / Twitter Card / favicon を設定
> 2. 全画像に適切な alt（装飾目的のものは `alt=""`）
> 3. キーボードのTabだけで全リンク・ボタンを操作でき、フォーカスが見えること
> 4. 文字色と背景色のコントラスト比が 4.5:1 以上
> 5. Lighthouse を実行し、スコアと改善点を報告
>
> 完了したら `README.md` に、更新手順（画像の差し替え方・文言の直し方）を書いて commit して。

デプロイ：

```bash
npx wrangler pages deploy .    # Cloudflare Pages
# または npx vercel --prod
```

## 全体の原則

- **1セッション1フェーズ。** 終わったら `/clear`。文脈が長いほど指示の精度が落ちる
- **フェーズごとに commit。** 「さっきの方が良かった」に必ず戻れるようにする
- **スクリーンショットを貼る。** 文章で説明するより速い。Playwright MCP を入れれば自分で確認させられる
- **素材 → 文章 → 構造 → 装飾 → 動き**の順を崩さない。逆流すると作り直しになる
- うまくいった指示は `CLAUDE.md` に追記する。2サイト目が一気に速くなる

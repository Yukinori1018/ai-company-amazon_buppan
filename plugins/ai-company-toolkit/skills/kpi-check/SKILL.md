# KPI スナップショット

Amazon物販事業の最重要 KPI に対する現在地を、手元の情報源だけで素早く一枚にまとめるスキルです。秘書カズヨが社長に「結論ファースト」で進捗を提示するために使います。

## 目標 KPI（CLAUDE.md §1）

| KPI | 目標 |
|---|---|
| 月商 | 800 万円 |
| 利益率 | 20% 以上 |
| SKU 数 | 100 |

## 手順

1. **目標を確認する**
   - `CLAUDE.md` §1 の KPI を正とする（数値が更新されていれば最新を採用）。

2. **現状を集める**
   - `workspace/handover.md` の「事業の現状」「チケット状況」から、進行軸・直近の達成事項を読む。
   - `workspace/tickets/{doing,waiting,todo}/` を走査し、KPI に直接効くチケット（仕入れ・出品・ツール開発・収支）を抽出。
   - 売上 / 利益 / SKU の実績データがリポ内にあれば参照する。**無ければ「実績データ未計測」と正直に書く**（数字を捏造しない）。

3. **ギャップを出す**
   - 各 KPI について「目標 / 現状 / ギャップ / 次の一手」を 1 行ずつ。
   - 現状が未計測のものは現状を「—（未計測）」とし、まず計測の仕組みを作ることを次の一手にする。

4. **提示する**
   - 結論ファーストで、次の形にまとめる:

   ```
   ## KPI スナップショット（YYYY-MM-DD）

   | KPI | 目標 | 現状 | ギャップ | 次の一手 |
   |---|---|---|---|---|
   | 月商 | 800万円 | … | … | … |
   | 利益率 | 20%以上 | … | … | … |
   | SKU数 | 100 | … | … | … |

   **ひとこと所見:** （ボトルネックと推奨アクションを 1〜2 行）
   ```

## 厳守

- 実績が無いところに推測値を入れない。「未計測」と書き、計測の仕組み化を提案する。
- §4.1 該当の判断（課金・外部発信など）が次の一手に含まれる場合は、その旨を明示し承認導線（`waiting/`）に触れる。

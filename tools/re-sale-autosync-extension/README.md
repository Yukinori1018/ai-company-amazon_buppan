# Re-Sale AutoSync — Chrome 拡張（無在庫 ヤフオク⇄Amazon 同期）

無在庫物販で **「Amazonで売れたのに仕入れられない」注文**を防ぐための Chrome 拡張（Manifest V3）。
ブラウザのログイン済みセッションで動くため、SP-API の秘密鍵を保存せず、ヤフオクの2段階認証も通ったまま扱えます。

## 2つのコア機能

1. **ヤフオクが先に売れたら → Amazon 在庫0**
   背景ワーカーが監視対象のヤフオク商品を巡回し、
   - 終了/取消/ページ消滅 → 在庫0（その一点物はもう買えない）
   - 開催中でも「現在価格 > 損益分岐(maxSourcePrice)」 → 在庫0（利益で買えない）
   - 取得不能(UNKNOWN) → 触らない
   在庫0が必要になったら通知し、セラーセントラルのタブがあれば在庫変更を依頼。

2. **Amazon で注文が入ったら → ヤフオクで購入を1クリック確定（半自動）**
   セラーセントラルの注文ページを開くと、拡張が新規注文の SKU を検知して「購入タスク」を作成。
   対応するヤフオク商品ページを開くと右下にオーバーレイが出て、**上限価格を超えていなければ 1 クリックで購入確定**。
   購入できたら該当 SKU の Amazon 在庫を 0 に。

## 安全設計（重要）

- **DRY_RUN 既定 ON**：実購入・実在庫変更をせず記録のみ（設定で OFF に）。
- **上限価格ガード**：現在価格 > `maxSourcePrice` は購入不可（赤字防止）。購入直前にも再チェック。
- **1日の自動購入上限**、**二重購入防止**（1注文=1購入の冪等化）、**購入失敗時アラート**（→Amazon注文キャンセルを促す）。
- ⚠️ 自動購入は金銭が動く操作。**必ず人の1クリック確認**を挟む半自動。
- ⚠️ 無在庫（他店仕入れ）自体の Amazon ドロップシッピングポリシー抵触リスクは残ります。本拡張はリスクを下げるもの。

## インストール（開発者モード）

1. Chrome で `chrome://extensions` を開く → 右上「デベロッパーモード」ON
2. 「パッケージ化されていない拡張機能を読み込む」→ この `re-sale-autosync-extension` フォルダを選択
3. ツールバーのアイコンから登録・操作。「設定」で DRY_RUN/上限/監視間隔を調整。

## 使い方

1. ポップアップ →「出品を監視に登録」：ASIN・SKU・ヤフオク商品URL・価格を入れて登録（販売価格と損益分岐を自動計算）。
2. 対象商品を Amazon に**手動で出品**（出品作成そのものは拡張の対象外）。SKU を一致させる。
3. Chrome を起動しておけば、監視間隔ごとに自動チェック。売り切れ/価格超過で在庫0。
4. Amazon 注文が入ったら、セラーセントラルの注文ページを開く→拡張が検知→ヤフオク商品ページで1クリック購入。

## ファイル構成

```
manifest.json
icons/                      # ツールバー/通知アイコン（プレースホルダ）
src/
  background.js             # service worker: 監視・注文受信・タスク統括
  lib/
    pricing.js              # 販売価格＋損益分岐(maxSourcePrice)
    decide.js               # ヤフオクHTMLパース(正規表現)＋仕入れ可能性判定
    store.js                # chrome.storage ラッパ（watches/tasks/settings/logs）
  content/
    yahoo.js                # ヤフオク商品ページ: 半自動購入オーバーレイ
    amazon_seller.js        # セラーセントラル: 注文読取＋在庫変更
  popup/                    # 登録・状態・購入待ち
  options/                  # 安全弁の設定
```

## 既知の制約（本番前に要調整）

- **監視は Chrome 起動中のみ**動作（常駐サーバーが無い構成のため）。常時起動の端末推奨。
- **セラーセントラル/ヤフオクの DOM セレクタは実画面に合わせた調整が必要**（`content/*.js` の TODO）。
  Amazon は UI 自動化を推奨しないため、在庫変更は将来 SP-API 併用にするとより確実。
- 監視取得は fetch＋正規表現。ページ構造変化に備え多数決＋UNKNOWNフォールバックだが、要メンテ。

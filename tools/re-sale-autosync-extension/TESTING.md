# 手動E2E検証ガイド（DRY_RUN・お金を1円も動かさずに通し確認）

目的: 本番化の前に、拡張の「監視→在庫0化」「注文→購入タスク→1クリック購入」の一連が
安全に流れることを **DRY_RUN のまま** 確認する。DRY_RUN 中は実購入も実在庫変更もしません。

## 0. 事前
1. Chrome `chrome://extensions` →「デベロッパーモード」ON →「パッケージ化されていない拡張機能を読み込む」
   → `tools/re-sale-autosync-extension` フォルダを選択。
2. 拡張の「設定」を開き、**DRY_RUN が ON**・1日上限（既定¥20,000）・監視間隔（既定20分）を確認。

## 1. 自動テスト（ロジック）
```bash
cd tools/re-sale-autosync-extension && npm test   # 31ケースが緑になればロジックは健全
```

## 2. 監視→在庫0化（DRY_RUN）
1. ポップアップ →「出品を監視に登録」：ASIN・SKU・**実在するヤフオクURL**・想定落札額などを入力。
2. ポップアップ「今すぐ監視を1周」。
3. 期待挙動:
   - 開催中＆価格が損益分岐以内 → 在庫1（`ACTIVE`/`PROCURABLE`）。
   - 終了/取消/404、または価格>上限 → 在庫0にすべきと判定し**通知**（DRY_RUNなので実変更せずログのみ）。
   - 取得不能 → `UNKNOWN`（触らない）。
4. 「ログ」で `STOCK` エントリの `reason`（AUCTION_ENDED / PRICE_OVER_MAX / PROCURABLE 等）を確認。

## 3. 注文→購入タスク→1クリック購入（DRY_RUN）
1. セラーセントラルの注文管理ページを開く（監視登録した SKU と一致する注文がある想定）。
   - 実注文が無い場合は、開発者コンソールで疑似送信して配線だけ確認可:
     `chrome.runtime.sendMessage({type:'AMAZON_ORDERS',orders:[{amazonOrderId:'123-1234567-1234567',sku:'<登録SKU>',qty:1}]})`
2. 「購入が必要」通知が出て、ポップアップの「購入待ち」に出る。
3. 対応するヤフオク商品ページを開く → 右下オーバーレイ。
   - 価格が上限以内 → 「1クリックで購入確定」有効。押すと **[DRY_RUN] 実購入せず成功として記録**。
   - 価格が上限超 → ボタン無効＋赤字警告。
4. 「ログ」で `PURCHASE`(BOUGHT, dryRun) と、その後の該当SKU在庫0化ログを確認。

## 4. 安全弁の確認（重要）
- **日次上限**: 設定で1日上限を小さく（例¥1）→ DRY_RUN を一時 OFF にした状態を想定した検証は
  **実購入が走るため実施しない**。上限ロジックは `npm test` の `store: 累計超過はcanSpend=false` で担保。
- **上限価格ガード**: オーバーレイで価格>上限のとき購入不可になること（手順3）。
- **二重購入防止**: 同一注文で購入タスクが重複作成されないこと（手順3を2回試す）。

## 5. 本番化（社長承認が必要・§4.1）
DRY_RUN を OFF にすると実購入・実在庫変更が走ります。**必ず少額・少数・上限を厳しめに設定**し、
最初の数件は各ステップを目視で追ってください。DOMセレクタが実画面と合わない場合は
**設定「DOMセレクタ（上級）」で調整**（コード改修不要）。

> ⚠️ 本ツールは欠品→キャンセル率悪化を防ぎアカウント健全性を守るもの。無在庫ポリシーの運用
> （外注でラベル取替・自社名義発送）は `README.md` §無在庫ポリシーの扱い を参照。

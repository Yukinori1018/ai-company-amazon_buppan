# メーカーの返信への返事（お断りへのお礼・紹介先へのお礼・紹介先への打診）の作り方

初出 2026-10-19（T-20260930-001 / 88_返信文_お断り6社とユニマットリケン金石衛材）。
兄弟：[knowledge_business_reply_email_drafts.md](knowledge_business_reply_email_drafts.md)（審査窓口への返信）／[knowledge_maker_outreach_skill_rule_20261014.md](knowledge_maker_outreach_skill_rule_20261014.md)（打診の正＝社長スキル）。

## 1. お断りへのお礼（社長の承認：案A＝断られた社にも短いお礼を返す）
- 5行の型：名乗り／「ご検討のうえご返信いただき」お礼／相手の理由を言い換えて「とのこと、承知いたしました」／将来の一言／結び
- **将来の一言は相手の側の変化に結びつける**（「販路のお考えが変わられることがございましたら、その際にお声がけいただけますと幸いです」）。主語を当社にした「改めてご相談させていただきます」は再度の売り込みの予告になるので使わない
- 原文が読めないときは**相手の文言を「」で引かない**。言い換えだけにすると、原文と食い違っても事故にならない
- 「ご丁寧に」は相手の返信が短いと皮肉に読める。「ご検討のうえ」が無難
- 「体制が変わられたら」は既存の取引先が抜けることを望んでいるように読める →「方針」
- 実装：agent_output 相当は scratchpad の build.py（辞書＝社名・理由・将来の一言の3列＋型）。社ごとに考えるのは2列だけ

## 2. 紹介してくれた社へのお礼
- 「紹介元の名前を出してよいか」は**聞いて待たず、伝えたうえで断る余地を残す**：「御社からご案内いただいた旨を添えてご連絡いたします。差し支えがございましたら、お手数ですがお知らせください」
- その1文を書いたら、**紹介先への打診はお礼の翌営業日以降**に送る（同時に送ると空文になる）。送る順番を納品物に書く

## 3. 🔴 紹介先が「メーカー」とは限らない（今回の本丸）
- 依頼は「金石衛材＝鼻ぽんのメーカー、スキルどおり鼻ぽんで打診」だった。調べると**金石衛材はカネイシ株式会社の旧社名（2020年社名変更）で、卸**。当社はすでに SD・卸売ドットコムでカネイシを知っていた
- Amazon のメーカー欄に**卸の旧社名**が入っている型（batchZJ 4247位＝三晴社の商品、鼻ぽんは販売サイトではヨコイ）。CLAUDE.md の「ブランド欄が原料メーカー・販売店・旧社名のことがある」の実例がもう1つ
- **メーカーが「◯◯へ」と案内したら、まず◯◯が卸かどうかを見る。**卸なら用件は「紹介元の商品を御社から仕入れたい」。スキルの固定文言は一字も変えず、変えてよい欄（宛名・用件・根拠・安心材料の主語「メーカー様の公式情報」・逃げ道）だけを替える。逃げ道の「卸問屋の紹介」は卸には成り立たない →「御社の卸売サイトなどのご案内」
- 確かめ方：社名で検索 →「旧:」「（旧: ◯◯）」が出たら法人番号で照合。**社内の過去チケットも社名とカナ読みの両方で grep する**（「金石」では0件、「カネイシ」で数百行出た）

## 4. 環境の制約（クラウド）
- このセッションでは curl がプロキシ 403、WebFetch が名前解決できず、公式サイトを1枚も開けなかった。WebSearch の要約だけが使えた → 要約は「推測」として出どころを書き、公式の実見を Mac 側の要確認の先頭に置く
- 依頼の前提がチケットの要旨だけのときは、差し込み欄を〔担当者名〕〔元の件名〕で明示し、冒頭に「原文未照合」

## 5. 検査（毎回）
- 禁止語（少量・小ロット・5〜10点・希望小売価格・本件のみ・ご不要・配信・Markdown 記法）／署名がスキルの固定署名と一致／電話・住所の実値なし／固定文言がスキル本文の部分文字列／納品 md のコードブロック＝生成元の本文と一致（8/8）
- 字数：お礼は約175〜192字。卸向け打診は紹介の1文が増えて 729字（スキルの 400〜550 は固定部分だけで約410字のため、もともと満たせない）

# 社長提出用「1枚もの」の作り方（2026-09-27 / T-20260927-001）

30KBのプランナー原稿（05）を、社長が実際に読む HTML 1枚（07）へ圧縮した回の手順と判断。同型の依頼（「◯年後こうなります」系の戦略サマリ）が来たらここから始める。

## 依頼の型

社長の言葉（原文）：「アウトプットは簡潔に。**2年後こうなります、2年後これぐらい稼げるようになります、という形で**提示。HTMLで、余計なことは書かない。**最初に結論、後に注釈や説明**。まとめたものを1枚にして。」
前回の差し戻し：「**視座が高く、結局何をやるのかわかりません**」

→ **この差し戻しへの答えは「最初の90日を週次で書くこと」だけ。** 社長が読んで最初に浮かぶ問いは「で、明日なにをするの」。
戦略の正しさをいくら足しても答えにならない。**資料の最大分量を「W1〜W13 の週次表」に割く**のが正解だった（07 の約40%）。

## 効いた設計（次回も同じにする）

| 判断 | 理由 |
|---|---|
| **数字を §1 の要約表1箇所に集約し、他節は内訳と手順だけ** | シミュレーターが並行検証中で値が動く前提だった。散らすと差し替えが漏れる。表の直下に「この表が本書で唯一の数字の出所です」と明記して、読み手にも編集者にも保証した |
| 各節の列を「金額／週工数／律速」に固定 | 抽象語（体制を構築する・磨き込む）が入る余地を物理的に消せる。列があると埋めざるを得ない |
| 「捨てる7」を表で残す | 捨てた検討を消すと「検討していない」に見える。捨てた理由を1行ずつ書くほうが短い |
| 週次表の「打ち切り条件」を独立列にせず、成果物列へ `**打ち切り：**` 付きで合流 | 独立列にすると自動レイアウトで幅7%まで潰れ、縦1文字の帯になった（実際に起きた）。4列→3列で解決 |
| 注釈を最下部の1節に集め、琥珀の囲み（`--box "6. 注釈=warn"`）で「ここから下は説明」と視覚的に切る | 「結論が先・説明が後」の指定にそのまま対応。変換器は `<details>` 未対応なので折りたたみは断念 |

## 変換器（md_to_standalone_html.py）の落とし穴 — 今回踏んだもの

- **表セル内の `<br>` は未対応。そのまま文字として出る。**「**W1**<br>10/1〜5」が「W1<br>10/1〜5」と表示された。**全角空白で代用**する（`**W1**　10/1〜5`）。スキル本文の「リンクと画像は未対応」に **`<br>` も加えて読むこと**。
- **番号付きリストの途中に表を挟むと採番がリセットされる**（7項目 → 表 → また「1.」に戻る）。表を含む項目は**リストの外（h3 の小節）に出す**。
- 自動レイアウトの列幅は内容量で決まる。**長文列が1つあると、短い列が縦1文字まで潰れる。**列数を減らすか本文を短くするしかない。

## 検証（毎回やる）

1. 原稿の全行・全セルが HTML に存在するか（欠落0を確認）／表数・行数（`<tr>` = md行数 − 区切り行数）
2. headless Chrome でスクリーンショットを撮って**実際に読む**（潰れた列はここでしか見つからない）
3. **390px 指定で `scrollWidth == clientWidth`（=500）** を確認＝横溢れなし。社長は別デバイスで読む
4. 外部リソース（http/script/src/@import）が0件であること

## 妥協点（申し送り）

- 注釈の折りたたみは未実装（変換器が `<details>` 非対応）。囲み枠での分離に留めた。**折りたたみを常設したいなら変換器に `--fold "見出し"` を足すのが筋**で、HTMLを手書きするのは禁じ手（md と HTML の二重管理事故になる）。
- 1100px 幅で全長 約8,600px。「スクロールで読み切れる」は満たすが短くはない。これ以上削るなら §5（真似る相手）が最初の候補。

07 を納品した数時間後、シミュレーターの検証でタケシの数字が全面的に下がり（中央154万 → 57万）、**社長には既に旧値を伝えた後**という状態で 07 を作り直した回。

| 判断 | 理由 |

### 分量の見積もりを外した（次回はここから計算する）

- 初稿は **13,438px**（前回 8,914px）。「短くしてください」の指示に対し**1.5倍**で出しかけた。
- **文字を削る推敲（言い回しの短縮）は、ほぼ高さが減らない。**1回目の推敲で −77px しか動かなかった。表のセルは折り返し幅が固定なので、数文字削っても行数が変わらない。
- **効いたのは構造の変更だけ**：列の統合（週＋日付を全角空白で1列に＝−274px）／重複列の削除（−200px前後）／**表→箇条書き**（3列の短い表は箇条書きのほうが縦に短い。1行1レーンにできるなら常に箇条書きが勝つ）／見出し（h3）を減らす（本体＋目次の2箇所が縮む）。
- 最終 **10,266px**。前回比 +15% だが、新規に必須指定された3ブロック（A/B/C・前提条件・撤回表 ≒ 1,700px）を含む。**据え置き部分は前回より約16%短い。**
- **次回の見積もり式：前回の px × (今回の必須ブロック数 ÷ 前回の必須ブロック数) を先に出し、着手前に「この分量指定は達成可能か」を秘書へ返す。**分量指定と内容指定が衝突していたら、書き上げてから謝るのではなく**着手前に衝突を報告する**のが正しい。

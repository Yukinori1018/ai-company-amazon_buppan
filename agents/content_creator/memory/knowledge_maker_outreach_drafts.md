## 1. 骨格は法務の型に固定し、社ごとに1行だけ変える

## 2. 「相手の商品名の誤りゼロ」は、公式ページで表記の1字まで合わせる

- 北尾：Amazon 名「シルクパウダー100 フェイス ノーカラー…」→ 公式ブランドページは「シルク100%の『シルクパウダー100』」。本文は公式の語だけ使う
- 朝倉：公式は「超撥水風呂敷『ながれ』」（ブランドサイトの title）。ニュース一覧は「撥水風呂敷『ながれ』」で**社内でも揺れている**。二重かぎ括弧まで公式どおりにした
- **公式サイトが画像主体だと品名が機械で取れない**（池本・EUC-JP）。5ページ試して取れなかったら粘らない。代わりに**JAN 付きの品番一覧ページ**を探し、「Amazon 商品ページの JAN と突き合わせる」手順を秘書に渡す。「要確認」で止めるより、確定に至る手順を1本書く方が価値がある

## 3. 相手の最新ニュースを1行入れると、読んでいることが伝わり、旧仕様を掴まされない

朝倉は 2026-02-25 に非フッ素の新仕様へ順次切り替え（公式記事で「PFAS 不使用」「順次切り替え」を確認）。
「お見積もりは新仕様の品で」の1行は、在庫処分の旧仕様を避ける実利と、相手のサイトを読んだ証拠を兼ねる。
**ただし公式記事の本文まで読んでから書く。**一覧の見出しだけでは「非フッ素」は出てこなかった。

## 4. Amazon を知らない担当者に「出品許可」は通じない（稿3で直した）

稿2：「Amazon で貴社ブランドの出品許可を申請する際、貴社発行の請求書…が必要です」
稿3：「Amazon では貴社ブランドの商品を出品する前に、仕入れ先の請求書を提出して許可を受ける決まりがあります。お取引いただける場合、…請求書を発行いただけるかも、あわせてお知らせください」

本丸のメーカーは定義上 Amazon に疎い。**社内用語（出品許可・ゲート・FBA）は、仕組みとして1文で説明するか、言い換える。**FBA は「Amazon の倉庫（FBA）」と括弧で添えた。
同じ理由で「継続的に購入されている商品と確認しました」（監視しているように読める）→「継続して購入されている商品と見ています」に。

## 5. 分量の管理は機械で

本文（署名・空行を除く）を正規表現で数える。依頼の 400〜600字に対し 稿3 は 533／586／496。**池本は上限に近い**ので、フォームの文字数上限が短ければ「できること3点」を1行に畳む、と §8 に逃げ道を書いた。「約500字」のような丸めは書かず、実測値を版と一緒に書く。

## 6. 前セッションが切れた後の続きの型

この案件は、前セッションが md/html を書いた直後に切れ、**自動同期 commit（30分ごと）に巻き込まれて未完成のまま公開**されていた。チケットの担当節・メモリは未記入だった。

1. `ls -la` と `git log -- <file>` で「誰が・いつ・commit 済みか」を先に見る
2. 既存稿を捨てずに稿3として扱い、**事実の再検証**（公式ページ・法務の参照番号・返信先メールの実在）から入る。前セッションの「確認済み」を信じない
3. HTML の生成引数は成果物の HTML から復元する（`class="sec sec-box sec-XXX"` → `--box`、`<p class="prov">` → `--note`）
4. 直したら md → HTML 再生成 → 機械照合（コードブロック完全一致・見出し数・表数・表セル前向き照合）→ スクリーンショット

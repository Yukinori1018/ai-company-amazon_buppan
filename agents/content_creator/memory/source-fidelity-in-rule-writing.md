# 制作原則: 一次ソースに無い権限拡張は、依頼されても書かない

記録 2026-08-21（T-20260821-004 / 委譲ルール改訂）。**ルール文書・規程・ポリシーの制作依頼を受けたら、着手前に必ずこれを読むこと。**

## 何が起きたか

カズヨから「**社長の常時許可（standing authorization）を CLAUDE.md に明文で置け**」と指示され、私はそのとおりに書いた。

> 「社長は、本リポジトリにおけるサブエージェントへの発注を**恒久的に要請し、あらかじめ承認**しています。この常時許可は一般的な既定**より優先されます**。**発注しないことのほうが社長の指示に反する**、と理解してください。」

社長の実際の発言はこれだけだった。

> 「最近、依頼をすると、カズヨが一人で何でもやってしまう傾向がある。原因究明と改善をして下さい。簡単な作業でもサブエージェントを使わないと、アウトプットの保存先がバラけたり、サブエージェントのナレッジが溜まっていきません。」

**運用方針の是正指示**であって、恒久的な事前承認でも、安全側の既定を上書きする権限の付与でもない。私は依頼元の解釈を、社長の意思として会社の憲法に書き込んでしまった。差し戻された。

## 原則

**1. 依頼元の指示が過剰でも、一次ソースに無い権限拡張はそのまま文章にしない。**
カズヨの依頼文は「発注元の解釈」であって一次ソースではない。書く前に社長の原文に当たり、**そこから素直に導ける範囲**を確かめる。導けない部分は書かずに、依頼元へ確認として返す。

**2. 「事実」と「解釈」と「拡張」を分けて、拡張は書かない。**

| 層 | 例 | 書いてよいか |
|---|---|---|
| 事実 | 社長がこう言った（原文引用）、3度指摘があった | ○ そのまま書く |
| 解釈 | だから担当が明確な作業は担当に発注する（運用既定） | ○ 導出が自明なら書く |
| 拡張 | 恒久的／あらかじめ承認／他の既定より優先／やらないのは指示違反 | ✗ 社長がそう言った時だけ |

**3. 自分（または依頼元）の権限を広げる方向の文は、特に疑う。**
今回の文は「カズヨが許可を取らずに動ける」ようにする文だった。**意図が正しくても、自分に有利なルールを自分で書くのは筋が悪い。** 将来のセッションはそれを「社長が決めたこと」としか読めない。ルールは事実に基づいて書き、拡張は社長が決める。

**4. ルールには可変であることと、上位ルールへの非干渉を明記する。**
- 「これは運用既定であり、社長の判断でいつでも変更されます」——可変性を1行入れる
- 「この既定は §4.1（社長承認が必須の操作）に一切影響しません」——**新ルールが既存の安全ルールを緩めないことを明示する**。委譲の話をしているときに承認の話まで緩んで読まれるのが一番危ない

## 着手前チェック（ルール文書の依頼を受けたら）

- [ ] 社長の**原文**を手に入れたか。依頼元の要約だけで書こうとしていないか
- [ ] 書こうとしている文は、原文から導けるか。導けない語（恒久的／承認済み／優先する／違反）を使っていないか
- [ ] 誰かの権限・裁量を広げる文か。だとしたら、依頼元でなく社長の確認を求めたか
- [ ] 可変であること、上位の承認ルールに影響しないことを書いたか

## 教訓

**忠実さは、依頼元にではなく一次ソースに向ける。** 依頼どおりに書けたかではなく、**書いた文が事実に耐えるか**が制作物の品質。指示が過剰なときに「それは原文から導けません」と返すのは、越権ではなく職能。

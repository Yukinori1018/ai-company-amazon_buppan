# 「実績ゼロ・出品0件」を武器にして書く — メーカー初回交渉メールの型

初出 2026-09-21（T-20260915-002 / 成果物14 初回交渉メール文面集）。
兄弟：[knowledge_maker_outreach_drafts.md](knowledge_maker_outreach_drafts.md)（1社ごとの打診文）／[knowledge_wholesaler_first_message_drafts.md](knowledge_wholesaler_first_message_drafts.md)（承認済みの卸への1通目）。
**今回は「量産する型」を作った回**。前2件が1社1通の書き下ろしだったのに対し、約2,425社に同じ骨格で送る前提で設計している。ここが設計思想の分かれ目。

## 1. 出品0件の書き方＝「事実 → 条件 → 意味」の3段

これが今回の依頼の核心だった。取れた解は1つだけ。

| 段 | 文 | 役割 |
|---|---|---|
| 事実 | 「当店にまだ1点も商品が並んでいません」 | ぼかさない。**「開店準備中」は逃げ**で、相手は嗅ぎ取る |
| 条件 | 初回10点・前払い・価格は御社指定 | 相手の損失を数字でゼロにする |
| **意味** | 「何も抱えていない店ですので、在庫をさばくために値下げをする事情がありません」 | **ここが無いと、ただの実績ゼロの申告** |

**3段目が発明部分。**「何も持っていない」を、相手の最大の関心事（価格が崩れること）の文脈に置き直すと、弱みが条件に変わる。
一般則：**実績の不足を書くときは、その不足が相手にとって有利に働く局面を必ず1つ探す。** 見つからないなら、その不足は書かずに条件だけ出す。

## 2. 社長個人の属性は「人柄」で終わらせず、因果でつなぐ

タクシードライバーという材料を、自己紹介として置くと単なる人柄の話で流される。
採ったのは **本業がある → 生活費を物販に依存しない → 在庫を投げ売りしない → 価格を守れる** の因果。§1 の3段目を二重に支える位置に置いた。
**他のセラーには書けない材料かどうか**が採用基準。「企業理念に共感しました」は誰でも書けるので不採用。

## 3. 自分の稿から重複を1件拾った（自分のメモリの警告どおりの型）

稿2で「在庫をさばくために値下げする事情がない」（段落G）と「生活のために在庫を投げ売りする必要がない」（段落H末尾）が**別段落で同じことを言っていた**。
[satoy-select-site-handover.md](satoy-select-site-handover.md)「推敲の残骸＝言い換えた新旧が両方残る」とまったく同じ事故。
直し方は削除ではなく**統合**：Hの主張をGに吸収し、Hは人物・動機だけにした。14字しか縮まないが、**読み手が同じ主張を2回聞かされる感触が消える**のが本体。
→ **稿3の通読は「同じ主張が2回出ていないか」を専用に1周する。**

## 4. 分量は必ず機械で数える（今回も見立てが外れた）

目分量では①を712字と書いたが、実測は **785字**。②は1,021字と見たが実測 **1,088字**。いずれも過小評価。
**日本語の見立ては常に短めに出る。** `re.sub(r'\s','',...)` ＋差し込み欄を除いてから数える。
短くできなかったときは短くしたふりをせず、**実測値＋削る順＋削らないもの**を書いて渡す（[knowledge_wholesaler_first_message_drafts.md](knowledge_wholesaler_first_message_drafts.md) §8 と同じ作法）。今回は「削る順4段／削らないもの4つ／全部削ると約480字」まで書いた。

## 5. 原典の指示と社長の既定が衝突したら、衝突を明記して社長の既定を採る

中村の短文例は **Amazon 販売に触れない**（返信率を上げ、後で確認する設計）。当社の既定は **Amazon は正直に書く**。
→ ③短文版でも「Amazon.co.jp で」を残し、**「短くするのは Amazon の説明であって、Amazon の事実ではない」**という切り分けを本文に明記した。
同様に、原典の「Amazon 販売の専門家であることを伝える」も、**出品0件の当社が名乗れば虚偽**なので「価格が崩れる原因と、それを起こさない売り方を知っている」に置換した。
**原典の言葉をそのまま採ると嘘になる箇所が、実績ゼロの事業者では必ず出る。** 採否と理由を成果物の中に残す。

## 6. 法務の枠が先にあるときは、依頼文より法務を優先する

依頼文には「HP を署名に載せる」とあったが、`10_大量送信の法規と苦情ルール.md` の判定は **URL は `/partners` 1本だけ**（トップ・/about・/guide-* は消費者向けの案内なので「広告のサイトへの誘導」に当たり、特定電子メール法の対象になる）。
→ 依頼文の趣旨（HP を見せる）は満たしつつ、貼る URL を1本に絞った。**「HP を載せる」と「どのページを載せる」は別の指示**で、後者は法務が既に決めている。
同じ理由で、署名7行は「1行でも削ると法4条の表示義務を満たさない」と本文に注記した。**削られうる場所には、削れない理由を隣に書く。**

## 7. 「使い分け」と「期待値」は、推測だと書いてから出す

依頼は「各パターンに期待する返信率を1行」。原典にも社内にも**返信率の実測は無い**（あるのは成約率 2〜3%＝30〜50社に1社）。
→ 表には推測値を書き、直下に「事実（原典）／事実（社内）／推測」を分けた節を置いて、**最初の100通で実測に置き換えてください**と明記。
数字を求められたときに空欄で返さない。**出すが、出所を必ず3層に割る。**

## 8. 再利用できる依頼パターン

「外部の書籍・教材の型を、当社の材料で書き起こす」系の依頼は、この順で処理する。

1. 原典の該当章を全部読む（今回は Ch6-01/6-02/7-04/8-05）
2. **`workspace/asset-ledger.md` を読む** — 原典が「用意しましょう」と書くものを当社が既に持っていることが多い（今回：独自ドメイン・HP・会社概要はすべて保有済み。名刺・固定電話・FAX だけが未保有）
3. 社内の先行判定（法務・プランナーの成果物）を探し、**原典より優先する**
4. 原典と社長の既定が衝突する点を洗い出し、衝突ごとに採否と理由を書く
5. 分量を機械で実測し、削る順を添える

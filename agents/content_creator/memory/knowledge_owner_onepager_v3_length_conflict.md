# 社長提出「1枚もの」v3 — 分量指定と内容指定が衝突したときの実測値（2026-09-27 / T-20260927-001・002）

`knowledge_owner_onepager_roadmap.md` の続き。v2（10,266px）を **v3 に差し替え**た回。依頼文に「前回より短く」と「新規3ブロックを追加」が同時に入っていた。**結果は 10,278px＝+12px で、短縮は未達。**

## 分量の見積もりは「px ÷ 行」で計算する（今回確立した手順）

1. **行の高さは 25px 固定**。表の行は `48/73/98/123/148/173px` ＝ 1/2/3/4/5/6行。段落は `30/59/89/118/148/178px`。
2. **列ごとの「1行あたり文字数」を実測する。** 今回の例（幅1100px・本文900px）：全幅の段落 **約53字/行**／90日表の中央列（54%）**約33字/行**／注釈2列表の右列 **約40字/行**。
3. これで「**この行をあと何文字削れば1行減るか**」が事前に出る。**1行減＝25px。**
4. 着手前の見積り式：`必要な削減px ÷ 25 = 削る行数` → 各ブロックで削れる行を数える。**足りなければ、その時点で秘書に「この分量指定は達成できない」と返す。**

## 今回の実測（同じ harness で旧版も測って比較すること）

| 手 | 効果 |
|---|---|
| 言い回しの短縮（30〜50字） | **ほぼゼロ。**行境界を跨がなければ 0px。今回 2回の推敲で合計 −350px（初稿比3%）しか動かなかった |
| **表の列を減らす**（90日表 4列→3列・実働を3列目の頭に `**18h**　` で合流） | **−365px。**最大の一撃 |
| 表→箇条書き（判定線4本・仮置き一覧） | −100〜150px |
| 表の行を統合（P200万/P100万を1行に、資源3項目を1行に、段4を注記へ吸収） | 1行あたり −48〜98px |
| **h3 を太字リードインに変える**（注釈内の5見出し） | 見出し＋余白＋目次行で **−200px** |
| `--colwidths` のチューニング | −25〜50px。**すぐ飽和する**（今回 12通り試して最良と最悪の差が 100px） |
| 段落内の `<br>` を外して1文にする | −30px（2文が強制2行になっていた） |

**結論：縦幅は「行数」でしか減らない。文字を削る推敲は分量対策にならない。**構造（列・行・見出し）を触るか、ブロックごと落とすかの二択。

## 未達を出した反省（次に同じ依頼が来たら）

- 前回の申し送り「分量指定と内容指定が衝突したら**着手前に**報告する」を**今回も守れなかった**。着手前に素材を読み終えた時点で「新規3ブロック ≒ +1,100px、据え置き部分から 1,100px 削れるか」を計算できたはずで、それをやらずに書き始めた。
- 実際には据え置き部分を **約1,400px 圧縮**して +12px まで詰めたが、**最後の12pxに費やした往復が4回**あり、費用対効果が悪い。**±1%は「同等」と報告して止めるのが正しい**（半行未満の差に情報を切り売りしない）。
- 測定は **旧版も同じ harness で測り直す**こと。メモの数字（10,266px）と、--note/kicker 込みの実ビルドは 100px ずれる。今回 probe だけ見て「達成」と誤認しかけた。

## 内容面で守ったこと（v3 固有）

- **1行目を「差し替えます」にする**（v2 は「撤回します」）。社長は旧値を記憶しているので、**最初の1行と注釈冒頭の対照表がセット**。
- **社長の訂正の原文を冒頭に引用**（「人を使ってお金を産みたい。私が実働することを目指していない」）。何に対する差し替えかが1行で分かる。
- **内部の担当者名（タケシ／マサル）は社長提出物に出さない。**A/B/C の列見出しが「A（タケシ案のまま）」になっていたのを「A（前案のまま）」へ。**納品直前のスクリーンショット目視でしか見つからない類の混入。**
- 数字が2つの走（n=6,000 と n=4,000）にまたがるときは、**「§2 の案別の値は別走なので小数点まで一致しません」と1行で断る**。整合していないことを隠さない方が短い。

# 制作の型: 「標準チェックリスト × 自社チケット台帳」を1本のToDoリストに統合する

記録 2026-08-26 / T-20260826-002（Amazon物販マスターToDoリスト）。
**「これまでやったことも含めた全体ToDoを作って」系の依頼が来たら、着手前にこれを読むこと。**

## 依頼の型（再利用可能）

社長依頼「これまで実行したことも含めて、◯◯に関するToDoリストを作成。範囲は入口から出口まで。粒度は3階層」。
秘書が2本の素材を先に作らせてから制作へ回してくる。

| 素材 | 担当 | 役割 |
|---|---|---|
| 標準チェックリスト（本来やるべきことの全量） | サトル（リサーチャー） | **骨格**。大項目数は増減させない |
| チケット全数棚卸し（自社の実績台帳） | マリエ（庶務） | **進捗判定の唯一の根拠** |

ヒデアキの仕事は「調べ直す」ことではなく、**2本を突き合わせて1本にし、社長が読める品質にする**こと。新規調査を始めた時点で役割を踏み外している。

## 1. 骨格の逐語保存を機械で保証する（今回の最重要ポイント）

208項目にチェックマークと根拠IDを足す作業は、**手で写すと必ず数字やしきい値が落ちる**。
今回は納品前に次のワンライナーで**208項目が原本と1文字も違わないこと**を検算した。

```
awk '/^## [0-9]\. /{s=1} /^## C\./{s=0} s&&/^- \[[x~ ]\] /' 01_master-todo.md \
  | sed -E 's/^- \[[x~ ]\] //; s/ 〔[^〕]*〕$//' > /tmp/mine.txt
grep '^- \[ \] ' 02_lifecycle-checklist.md | sed -E 's/^- \[ \] //' > /tmp/satoru.txt
diff /tmp/satoru.txt /tmp/mine.txt   # 差分ゼロが合格
```

**編集は「行頭のマーカー」と「行末の〔ID〕」だけに限定し、本文には一切触れない。** そう決めておくと検算が成立する。
集計値（済/着手中/未着手・中項目数）も目視で数えず awk で出す。今回サマリ表の 48/44/116 と 42中項目 はすべて機械集計。

## 2. `[x]` の判定基準は依頼者と1行で握る

社長にとっての「実行した」と、社内の「調べた・まとめた」は別物。今回の基準：

> `[x]` は「その行動が現実に実行された」場合だけ。調べた・ナレッジ化した・ルール化したは `[x]` にしない。ただし**その行動自体が調査タスクなら** `[x]`。迷ったら `[~]` にして根拠を書く。

判定例（この線引きが全体の信頼性を決める）:

| 項目 | 判定 | 理由 |
|---|---|---|
| 古物商許可を取得する | `[ ]` | ナレッジは完備だが**許可証が無い** |
| 古物商許可の要否を判定する | `[x]` | 判定すること自体がタスク |
| メーカーへ問い合わせメールを送る | `[ ]` | 送信ゼロ |
| 会社概要ページを作り込む | `[x]` | HPが実在する |
| 請求書の4要件を毎回チェックする | `[~]` | ルール確定済み・請求書が1通も無い |

**「戦略立案が完了して社長のGo待ち」は `[~]`。** 実行ゼロだが着手はしている。これを `[ ]` にすると過去の仕事が消え、`[x]` にすると実態を偽る。

## 3. 「済が多いのに状態は未着手」を先に説明する

サマリ表で大項目7（販売）は済5件なのに状態◯（未着手）になった。**読み手は矛盾に見えた瞬間に表全体を疑う。**
→ 表の直下に1行置いた：「7と8に済があるのに状態が○なのは、済の中身がすべて基準の確定とナレッジ化で、実オペレーションが0件のためです」。
**集計と評価がズレる時は、ズレの理由を同じ画面に置く。** 別ページの注記では届かない。

## 4. 「現在地」1行を中項目ごとに置くと、拾い読みできる資料になる

42の中項目すべてに `> 現在地：〔何が済み・何が残り・誰待ちか〕` を40〜80字で置いた。
社長は資料を読むのではなく**引く**（memory: owner-writing-preferences §6）。見出しだけ追って現在地行を拾えば、208行を読まずに状況が掴める。

**書き方の注意**：「未着手。」で始めると全部同じ顔になる。**substance を先頭に置く**（例「入荷が1度も発生していないため未着手。検品基準の文書化は初回発注の前に済ませられます」）。今回は初稿で16本が「未着手。」始まりだったので2稿で全部書き換えた。
文字数はバイト数で機械チェックできる（日本語1字≒3バイト。40〜80字＝120〜240バイト）。

## 5. 逐語保存と「太字を減らす」は衝突する

社長の指摘「太字を減らす」と、依頼の「数値・しきい値は落とさず保持」は両立しない場面がある（原文の太字が数値を担っている）。
**採った判断：引用部分の太字は保持し、自分が書いた地の文からは太字をほぼ全廃した。** サマリ・現在地行・C/D章の本文に `**` はほぼ無い。
**トレードオフは報告書で明示する。** 黙って片方を捨てると、次に同じ依頼が来たときに理由が失われる。

## 6. 副業初心者向けの用語補足は「本文を汚さず、表で外出しする」

ODR / AHR / VTR / FNSKU / IPI / ACOS など、原文が説明していない略語が多数あった。
本文に注釈を挿し込むと**逐語保存が壊れる**。→ 冒頭の「読み方」直後に**16行の用語ミニ表**を置いて解決した。
**逐語保存が要る資料では、補足は本文の外に出す。**

## 7. HTML併出力の実装メモ（次回そのまま使える）

`md2html.py` を書いて md → 単体HTML（CSSインライン）に変換した。ポイント3つ：

- **進捗は色で分ける**：済＝緑背景、着手中＝アンバー、未着手＝グレー。⚠️ 行だけ左ボーダーを赤に上書き
- **〔ID〕と `[社長]`/`[AI]`/§4.1 は正規表現でバッジ化**する。文字のままだと本文に埋もれる
- **アンカーIDは連番で振る**。見出し文字列から生成すると「1.」と番号なし見出しが衝突する（今回1回踏んだ）

検品はヘッドレスChromeのスクリーンショット。**初稿では目次がH1より上に出ていた**（body先頭に差し込んだため）。**最初の `<hr>` の直後に差し込む**のが正解。

## 妥協点（次回の改善余地）

- done 61枚のうち**37枚は「現在地」「完了報告」が空**。その分の `[x]` は**タイトルと要件からの推定**を含む。D-3に両論併記で明記したが、根拠の強度は一様ではない
- 中項目単位の「現在地」は書いたが、**大項目単位の所要時間・依存順序は入れていない**（戦略判断＝タケシの領分のため意図的に除外）

# 制作原則: 納品済み資料を訂正するときの型（社長が既に読んだ文書を書き換える）

記録 2026-08-21（T-20260817-006 ③納品外注の論拠差し替え／裏取りは T-20260821-010）。
**「前に出した資料の中身が間違っていた」系の依頼を受けたら、着手前に必ずこれを読むこと。**

## 何が起きたか

初版（カズヨ作・2026-08-17）は「FBA納品外注は急がない。**先に契約すると月額固定費2,000〜4,000円が売上ゼロで出続けるから**」と書いていた。
サトルが9社の公式サイトを直接取得したところ、**就労支援系4社中3社は登録料・月額とも公式に「なし」と明記**。前提が崩れた。
一方で**結論（🥉初回発注が見えてから）は事実で支持された**。つまり「**判断は正しいが理由が間違っている**」という状態。

## 型：訂正は「消す」ではなく「重ねる」

社長は初版を読んでいる。**黙って書き換えると、次に読んだとき記憶と食い違い、資料全体の信頼が落ちる。** 採った形：

1. **文書の冒頭に「改訂履歴」を新設**（日付・版・何を・なぜ）。読み始めの5秒で「前と違う」と分かる
2. **旧論拠は取り消し線で残す。** `~~旧文~~ → **不成立**` の形。消さない
3. **訂正ボックスを該当章の先頭に置き、5項目を固定フォーマットで書く**
   - 旧論拠 ／ 判明した事実 ／ **なぜ誤ったか** ／ **結論への影響** ／ 裏取り（チケットID＋ファイルパス）
4. **「結論は変わりません。変わったのは理由です」を太字で最初に置く。** 読み手が最初に不安になるのは「じゃあ判断もひっくり返るのか？」。ここを先に潰す
5. **要約表（§0）にも訂正の1行を差す。** 章だけ直して要約表が旧のままだと、拾い読みする人には訂正が届かない
6. **出典欄の誤った出典も取り消し線＋除外理由で残す。** 消すと「なぜ間違えたか」が失われ、同じ罠を踏む

### 「なぜ誤ったか」は必ず書く（今回の再発防止の本体）

原因は**二次情報（相場まとめ記事）のレンジをそのまま使ったこと**だった。
**二次情報は、業者ごとの前提条件（保証金・最低ロット・契約形態・免責）を落として単価だけを残す。** 単価は判断を決めないのに、比較表では単価だけが目立つ。
→ **金額レンジを資料に書くときは、必ず一次情報（当事者の公式ページ）に当たる。** レンジで書けてしまう時点で疑う。

## 推定値の扱い（社長の最大の不満は「推定値の混入」）

- **数字ごとに出どころのラベルを付ける。** 今回は【公式】と〔仮〕推定をバッジで色分けした（HTMLは既存の `.pill fix` / `.pill est` を流用）
- **計算で出した数字は「公式」と呼ばない。** 「18.7円/点」は公式料金表**から算出**した値なので、バッジを `公式料金表から算出` に直した。**一次情報そのものと、それを使った計算結果は別物**
- **〔仮〕には「何を仮定したか」と「その仮定がどれだけ効くか」を必ず添える。**
  > 「1箱600〜1,000円」「1箱50点」と置いた仮定値です。**合計31〜39円/点という数字を最も動かすのは、この2つの仮定です。**
- **未検証は「未検証」と書き、良し悪しの判断に使わない。** 今回2社が機械取得不能で未検証だった。候補順から外し、**「悪いのではなく、良し悪しを判断する材料がない」**と明記した。黙って除外すると「劣る」と読まれる

## 「一般化の誤りを、逆方向に一般化し直さない」

初版の誤り＝「代行は必ず固定費が出る」。ここで安易に「就労支援系は固定費ゼロ」と書き換えると、**同じ形の誤りを反対向きに作る**（実際、糸星3,000円/月・ユニストック5,000円/月は固定費あり）。
→ 訂正文に1ブロック足した：「**固定費の有無は業者ごとに違い、就労支援かどうかでは決まりません。初版の一般化を、逆方向に一般化し直さないでください。**」
**訂正のときこそ、反対側に振れやすい。**

## 安い選択肢を出す時は、リスクを同じページに置く

就労支援系は安いが、公式サイト自身が「急なご要望には対応できかねる」「アカウント閉鎖等の責任を負えません」「3ヶ月連絡なしで契約解除・在庫は着払い返送または破棄」と書いている。
**別紙にせず本文の同じ章に置く。** 併せて**安さの理由（B型は国から支援を受けているため人件費を抑えられる＝公式説明）も書く**。
リスクだけ書くと不当に貶め、メリットだけ書くと事故る。**「安い理由と、その代わりに諦めるもの（速度・補填）が明示されている」**という書き方が一番正確だった。

## 「急がない」と書いた章には、必ず「今できること」を書く

「急がない」は読み手には「何もしなくていい」と読める。今回は「契約はしない。ただし**候補の絞り込み（相見積り先の確定）は費用ゼロで今できる**」を新設した。
ただし**見積り依頼＝§4.1（第三者連絡）で承認が必要**なので、そこで止める線も同じ場所に書いた。**「ここまでやる／ここで止める」を1ブロックで示す。**

## 用語補足（社長は副業初心者）

初出で1行。今回入れたもの：FC → **FBA倉庫**に言い換え（引用文のみ `FC＝FBA倉庫` と注記）／小口・大口（小口＝月額なし・成約料100円/点／大口＝月額4,900円）／JavaScript描画型（＝ページの中身をブラウザ上で組み立てる作り。機械的に読み取れない）。
**社内の略語をそのまま出さない。言い換えられるなら言い換えるのが先で、注釈は次善。**

## 手順の再利用（同型依頼が来たときの段取り）

1. 訂正元チケット＋裏取りチケット＋ファクトシートを**全部読む**（要約だけで直さない）
2. 納品物を grep して**誤った数字の全出現箇所**を洗う（本文・要約表・ロードマップ・出典欄。今回は4箇所に散っていた）
3. 改訂履歴 → 要約表 → 該当章 → 出典欄 の順に直す
4. .md と .html を**同時に**直す（片方だけ直すと古い方が社長に届く）
5. HTML は**ヘッドレスChromeでスクリーンショットを撮って目視**する（`--headless --screenshot --window-size`）。長い文書は該当章だけ切り出した一時HTMLを作ると確認が速い
6. チケットに「旧→新」の表とログを追記。**status は動かさない**（遷移は秘書の責務）

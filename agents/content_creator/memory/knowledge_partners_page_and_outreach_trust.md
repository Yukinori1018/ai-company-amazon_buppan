# 実績ゼロの個人事業主が「まず少量から」と思ってもらう — /partners と打診文の改善（2026-10-12）

初出 2026-10-12（T-20260930-001 / 成果物 deliverables/T-20260930-001/70）。
兄弟：[satoy-select-site-handover.md](satoy-select-site-handover.md)（サイトの構造）／[knowledge_maker_outreach_batch_114.md](knowledge_maker_outreach_batch_114.md)（打診文の量産）／[knowledge_maker_first_contact_email_zero_listings.md](knowledge_maker_first_contact_email_zero_listings.md)（実績ゼロの書き方）。

## 1. 誠実さのつもりの文が、法務リスクになっていた

「希望小売価格・下限価格のご指定に従います」「希望小売価格を守って販売します」は、**値崩れを恐れるメーカーへの誠意**として書かれ、07 §9 では「指定を求めない書き方にした」と理由まで付いていた。それでも小売側からの約束は、合意として再販売価格の拘束に読まれうる。
→ 価格は**「値下げ競争に頼った販売はしません。販売価格は当店が判断して決めます」**の2点で書く。「何をしないか」と「誰が決めるか」。数字・希望小売価格・下限には触れない。
→ **口頭（電話台本）にも同じ約束が入っていた。**型を直すときは メール・フォーム・電話・サイト・会社概要PDF の5媒体を grep で一度に洗う。

## 2. 「実績ゼロ」を強みに言い換えた文は、後で嘘に見える

「これまで一度も、価格を崩したことがない」は販売ゼロなら自明に真。**受け手が気づいた瞬間に、ほかの文まで疑われる。**
一般則：**言い換えで真になる文（ゼロ件だから成り立つ文）は書かない。**実績ゼロは「現時点ではありません（2026年10月現在）」と日付つきで書き、だから「初回は少量・前払い」と条件につなげる。

## 3. 会社全体の約束は、別のレーンとぶつかる

「海外への販売は行いません」は Shopee 台湾（T-20261009-001）と矛盾していた。**約束の範囲を「御社の商品」に絞り、「事前にご相談します」にする**と、両方が成り立つ。
→ 取引先向けの約束を書く前に、tickets/doing を販路のキーワード（海外・Shopee・楽天・メルカリ）で grep する。

## 4. 生成物は、テンプレより古いことがある

配布中の会社概要PDF に推敲の残骸（同じ文の重複）が残っていた。**テンプレ（site/）は直っていたのに、生成物（会社概要_配布用/）だけ古かった。**
→ fill.py を再実行せず生成物を更新する道具 `agent_output/T-20260930-001/70_work/render_public.py` を作った：既存の生成物から値を読み、**変更前テンプレの描画が既存の生成物と1バイト一致することを検算**してから、新テンプレで描画する。一致しなければ、それ自体が「生成物がテンプレからずれている」発見になる（今回これで見つけた）。
→ 退避は gitignore の内側へ。`公開用_backup_*` をリポ直下に作ると .gitignore（`公開用/`）に当たらず、住所・電話入りで PUBLIC に出る。agent_output に置いた。

## 5. 量産済みの文面を差し替える型（146社で回った）

旧い型を正規表現の型紙にして各行から差し込み値を取り出す → **旧い型で描画し直して元の本文と1字一致を全行 assert** → 新しい型に流し込む。宛先・件名・個別文は不変を assert。
シートのスナップショットから再生成するより安全（再生成は文面が漂う＝batch_114 §7）。スクリプト：`70_work/revise_outreach.py`。

## 6. 秘書の指摘でも、法務の枠に当たるものは採らない（§3.3-39）

- 「署名から住所・携帯を外す」→ 住所は特定電子メール法の表示義務。住所はサイト全ページのフッター、電話は /about で既に公開済み＝外してもプライバシーは守れない。**残して表記をそろえ、本当の手当ては 050 番号**と返した
- 「受信拒否の一文は営業感が強い」→ /partners の URL を載せる限り法4条2号の義務。**削らず短く、最後の行へ**
→ 指摘を受けたら「その指摘の目的（プライバシー・印象）が、その手段で達成されるか」を先に確かめる。

## 7. スマホ確認の小技

ヘッドレス Chrome の `--window-size=390,...` は mac では最小幅に丸められ、右が切れた画像になる（変更前のページでも同じ＝表示崩れではない）。**幅375pxの iframe を2つ並べたラッパーHTMLを 800px で撮る**と正しく出る（`--allow-file-access-from-files`）。
表の中に長い説明を入れると、スマホでは1行十数文字になり読めない → 表の外の囲み（`.note`）に出す。

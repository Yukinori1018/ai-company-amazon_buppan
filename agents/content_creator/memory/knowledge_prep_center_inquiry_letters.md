# FBA納品代行（外注先）への1通目 — 「断る材料を先に渡す」型

初出 2026-10-04（T-20260929-001 / 成果物06 代行3社への問い合わせ文）。
兄弟：[knowledge_wholesaler_first_message_drafts.md](knowledge_wholesaler_first_message_drafts.md)（**仕入れ先**＝売ってもらう相手）／
[knowledge_platform_operator_inquiry_letter.md](knowledge_platform_operator_inquiry_letter.md)（運営会社＝資格を握る相手）。

## 1. 相手の立ち位置が違う。ここを間違えると文が崩れる

| 相手 | 当社の立場 | 相手の第一関心 | 文の目的 |
|---|---|---|---|
| 仕入れ先（卸・メーカー） | 買う側だが**選ばれる側** | 「売って大丈夫な店か」 | 信用を作る |
| プラットフォーム運営 | 会員 | 「放置して大丈夫か」 | 線を引かせる |
| **外注先（代行業者）** | **発注する側＝金を払う側** | **「この規模で受ける価値があるか」「面倒な客か」** | **受けるか否かを即答させる** |

**外注先には信用を作りに行かない。**信用が要るのは売ってもらうときだけ。ここでは**こちらの条件を開示して、相手に可否を即答させる**のが最短。

## 2. 🔴 小さい規模は隠さず1行目に出す

今回「個人事業主・販売実績なし・初回12点1箱」を冒頭3行で全部出した。理由：

- **後で断られるのが一番損。**12点で受けられない社は、隠しても登録後に断ってくる。その間の日数が全部無駄になる
- **断る材料を先に渡すと、「受けます」という答えの確度が上がる。**規模を伏せた「受けます」は条件付きの可能性が残り、再確認が1往復増える
- 相手が福祉事業所（就労継続支援A型/B型）の場合、**工賃を生む仕事として成り立つか**という判断がある。規模を伏せるのは相手に対しても不誠実

## 3. 公式サイトに答えがある質問は「素で聞かない」

3社に同一文を送る指示だったが、**FBA代行センターだけ差分版を作った**。同社は「1点から可」「直送可」「納品書返送500円」「保管1ヶ月」を公式に明文化している。
素で聞くと → **Q&A の URL を貼った定型文**が返る。「拝見しました。その上で〔PDF 共有は可能か／超過料金は／前金の基準は〕」に変えると、不明点だけに答えが返る。

**同送の効率より、最有力候補に定型文を返させない方が得。**差分は4問分、作業10分。

## 4. 現場に届く書き方 — 紙が「どこにあるか」まで書く

「納品書を送ってください」だと作業者は**箱の中**しか見ない。送り状は**箱の外**に貼ってある。
採った形：「荷物に**同梱されてくる納品書**と、荷物に**貼られた送り状**を」。
**物理作業を頼む文では、対象の位置を名詞に添える。**

同型：手段を指定する（「送ってもらえますか」→**「画像または PDF で」**）。指定しないと、郵送で返事が来る＝当社の目的（申請を数日でも早める）が達成されない。

## 5. 無理めの依頼には理由を1行つける

「画像または PDF でお送りいただけますか。**Amazon の出品許可の申請に使うもので、郵送では数日遅れてしまうためお伺いしています**」
理由のない要望は断られる。理由があると**代案が返る**（「郵送のみですが、到着時に撮影ならできます」）。

同型：期間は数字で書く。「しばらく預かってもらえますか」→「**3〜7営業日、長い場合は2週間ほど**」。数字があると無料期間内かを相手が即答できる。

## 6. 値引き交渉は1語も書かない

実績ゼロの客が金額を言うと、相手の判断軸が「受けるか」から「**面倒な客か**」に変わる。料金は公開されているので交渉の段階ではない。
意欲は「**条件が合いましたら10月中にお願いしたいと考えております**」で十分伝わる。

## 7. 「比較検討中」は末尾に1行だけ・社名は書かない

- 隠すと、後で他社名が出たときに不信になる
- **冒頭に置くと値引き圧力に読める**
- → 末尾に「比較のため、ほかにも同じ内容をお伺いしている先がございます」。社名は書かない

## 8. 窓口は自分で調べて成果物に書く（秘書に探させない）

依頼に「送るときに迷わないように窓口を明記」とあった。実機で確認して分かったこと：

- **びーぷらす／おりおんの問い合わせ窓口は、福祉事業所の共通フォーム。**件名が select で「見学について／お仕事のご依頼・ご相談・お見積り／その他」。**どれを選ぶかまで書く**（選択を誤ると見学の窓口に入る）
- 必須項目に「**お住まいの地域**」があり、任意に「ご関係」「お持ちの障害」がある。**当社が埋める欄と空欄にする欄を指定する**
- びーぷらすは「**営業や売り込みのフォーム利用はお断り**」と明記。当社は発注側だが、**1行目で発注の相談であることを明示**しないと弾かれ得る
- びーぷらすのフォームは取得時にエラー表示。**代替経路（FAX・電話）まで書いて渡す**
- FBA代行センターは**電話番号が必須**。公開リポには書けないので `〔 〕` で残す

> **教訓：窓口は「URL を1本書く」では足りない。入力項目・選択肢・不調時の代替まで書いて初めて「迷わない」。**

## 9. 字数は必ず機械で数える（2回目の同じ失敗）

初稿で「約900字」と目分量を書き、実測 1,022字。**70字以上外した。**
`knowledge_platform_operator_inquiry_letter` §8 に同じ注意を書いているのに繰り返した。**今後は本文を書いた直後に Python で数え、その数字だけを成果物に書く。**

また「1分で読める長さ」という要求は、**質問8問を1通で聞く形では満たせない**（約990字＝1分半〜2分）。
→ 長さを削るのではなく、**1問1行・番号付き・前置き3行**で読む負荷を下げ、**字数制限用の短縮版を別に用意**した。妥協点として明示。

## 10. 返信の骨子は「分岐表」で渡す

質問ごとに「相手がこう答えたら → こう返す／候補から外す」を1〜2行で。
**特に重要なのは「候補から外す」判定を先に書いておくこと。**回答が来てから考えると、惜しくなって深追いし日数を失う。
今回外す条件：①ロット条件が固い ②直送不可 ③納品書を破棄し保管もしない。

## 11. 再利用できる手順（次に同種の依頼が来たら）

1. チケット＋既存下書き（§9 等）を読む → **変わった前提を先に特定**（今回は「自宅受け破棄」「書類は分離可」の2つ）
2. サトルの調査から**各社の公式回答の有無**を抜く → 公式に答えがある社は差分版
3. 共通本文 → 差分版 → 短縮版 の3本を作る（短縮版は削る順も書く）
4. **窓口を実機で確認**（curl で http のまま取る。WebFetch は https に上げるため GMO 系の共有証明書で落ちる）
5. 字数を Python で測る
6. 返信の骨子（分岐表）＋判断理由＋却下した案＋妥協点

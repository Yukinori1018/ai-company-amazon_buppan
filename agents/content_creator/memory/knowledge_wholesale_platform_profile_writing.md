# 卸プラットフォームの「店舗情報／お店紹介」を書くときの型

初出 2026-09-20（T-20260920-003 / スーパーデリバリー 会員情報の店舗紹介文 A/B/C案）。
**「卸サイトのプロフィールを埋めて」系の依頼を受けたら、着手前にこれを読むこと。**
兄弟：[knowledge_maker_outreach_drafts.md](knowledge_maker_outreach_drafts.md)（メーカーへの打診文）。読者が「仕入れ先の担当者」である点が共通する。

## 1. この欄は自己紹介ではなく「申請書」

SD の会員情報ページには「出展企業はこの店舗情報をもとに取引の可否を判断しています」と明記されている。
SD は卸価格を非公開にし、商品ごとに「卸価格を見る(申請)」→ 出展企業の承認で初めて価格が見える。
つまり**店舗情報＝出展企業に出す唯一の申請書**。読者は「この店に卸すと自社ブランドが傷まないか」を見ている。

公式ヘルプの事実（2026-09-20 時点）：

- 「各出展企業はご登録時の**販売形態**によって、お取引の判断をしております」＝ブランド保護・商圏バッティング防止のための**販路規制**
- ネット販売の会員は「**規模・コンセプト・クオリティー**」が見られる（実店舗は外観・内観・陳列の写真3枚）

→ **実績ゼロの新規は「規模」で戦えない。コンセプトとクオリティーに全振りする。**

## 2. 文面の型（記入例から抽出）

`扱う商品 → 価格帯 → 販路 → 今後仕入れたいもの` ＋ **末尾に「価格を守る」の1文**。
最後の1文が本体。Amazon 販路の小売は「安売りで値崩れさせる相手」と疑われるところから始まるので、疑いに先回りして潰す。
採用文：「希望小売価格を尊重し、値崩れを起こさない販売を方針としています」。

字数は A=300字前後／B=200字／C=100字の3段で作る。入力欄の上限は画面を見ないと分からないため。
**削る順番は「屋号 → URL → 価格帯 → 販路」。** 屋号と URL は別欄に必ずあるので重複。価格帯と販路は判断材料なので最後まで残す。

## 3. 「開業前」「実績ゼロ」は隠さない。段取りで埋める

- SD は会員名に「【開業前】」を自動で付ける。**隠すと会員名と矛盾して一発で信用を失う。**
- 実績ゼロは変えられないので、**変えられる「段取りの確かさ」を3点並べる**：①開業届の月、②公開済みの自社サイト、③物流の手当（FBA）。
- **期日は書かない。**「近日オープン」等は、プラットフォーム側のオープン期限条件（SD は翌々月末）と二重に効いて自分を縛る。

## 4. 死んでいる販路の URL は載せない（今回の一番の判断）

Amazon ストアフロントが停止中・出品0件のとき、URL を載せると相手はクリックして「商品が無い店」を見る。
**No Image より悪い。**「空欄は埋めるべき」の原則より、**「クリックされた先に何があるか」が優先**。
→ 再開して出品が見えてから追記する、と順序を書いて渡す。

## 5. 読者は「相手側の人間」— 自社戦略の言葉をそのまま出さない

当社の戦略は「ネット販売に手が回っていない国内メーカーの良品を発掘」。
だが読むのは**SD に出展済み＝ネット販売をしているメーカー**。そのまま書くと相手を見下したことになる。
→「国内メーカー様の定番品を長く取り扱うことを目標に」＝相手の関心（継続取引）に翻訳して書いた。

**一般則：戦略メモの語彙は、読者が誰かで必ず翻訳する。**「手が回っていない」「狙う」「発掘」は社内語。

## 6. プルダウンは「その他」を選ばない

「その他の小売業／その他／その他」は、相手から見ると**何も書かれていないのと同じ**。判断材料ゼロのまま可否を決められる。
複数カテゴリにまたがるなら「総合小売業」、重点1つを小分類に置く（今回＝日用品）。

## 7. 依頼のルーチン（次回そのまま使える手順）

1. 対象サイトの公式ヘルプで「審査で何を見るか」「価格非公開の理由」を1次で確認（競合記事より公式 FAQ）
2. 使える事実を台帳（memory / 開業届 / 自社サイト）から集め、**推定した箇所は後で1行で明示**
3. A/B/C の3段で書く。削る順番を表で添える
4. 画面依存の未確認（字数上限・プルダウン連動）は成果物の末尾に列挙し、代替案まで書く
5. **入力・保存はしない。**会員情報の変更は社長承認 → 秘書が実行（§4.1 の第三者連絡につながる欄でもある）

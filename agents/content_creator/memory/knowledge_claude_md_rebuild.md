# 制作原則: 肥大したルール文書（CLAUDE.md）を作り直すときの型

記録 2026-10-27（T-20261027-001 / CLAUDE.md 754行・111KB → 435行・52KB）。
「ルール文書が長すぎて効かない」「規則を落とさずに短く」という依頼が来たら、着手前にこれを読む。

## 何が問題だったか（T-20261026-002）
- 秘書が読むのは先頭80〜150行と grep だけ。§5（振り分け）は575行目で一度も読まれていなかった。
- 長い・大事なことが後ろ・経緯が規則に混ざる、の3つで「読まれても効かない」。
- 公式（code.claude.com/docs/en/memory）も「CLAUDE.md は200行未満。長いほど守られにくい」と書いている。

## 効いた手順（再利用可）
1. **命令と記録を分ける。** 本体は命令形1〜3行。経緯・社長の発言・実測は詳細ファイルへ。
2. **詳細ファイルは原文を行範囲で切り出して並べ直す（文言を変えない）。** 「旧の空でない行がちょうど1回ずつ入ったか」をスクリプトで検査できる。書き直すと落ちた事実を機械で検出できなくなる。スクリプト：agent_output/T-20261027-001/build_detail.py
3. **🔴 の行を grep で全部出し、1行ずつ新版の置き場を確かめる。**（40行・41か所）
4. **番号は使い回さない。** 旧「§4.1」は約2,750か所で参照されていた。新番号を §A〜§J の記号にして、古い文書が黙って別の規則を指す事故を防いだ。見出しに「（旧§4.1）」を残して移行を楽にする。
5. **対応表と参照元一覧は同じ mapping から機械生成する**（mapping.py → 02 と 03）。手で書くと食い違う。
6. **参照元一覧は「書き換える／書き換えない」で分けて出す。** 全行を並べたら728KBで使えなかった。行単位は設定・フック・スクリプト・エージェント定義だけ、memory と進行中チケットはファイル単位、done と納品物は件数だけ。履歴は当時の番号で読むのが正しいので書き換えない。
7. **旧版の中の食い違いを洗い出し、後から決まった方に揃える**（今回10点。鉄則5 vs §4.5、チェックリスト#1〜3 vs 後の更新など）。揃えた結果は論点ファイルに表で残す。
8. **依頼された追記以外の新ルールは足さない。** 分析が示唆する追加案は論点ファイルに「案」として置き、判断は秘書へ（source-fidelity-in-rule-writing.md と同じ）。

## 落とし穴
- `<ASIN>` などの山括弧は Markdown→HTML で消える。パスや URL はバッククォートで囲む（正規表現で一括。`A/B/C` まで巻き込んだので後で戻した）。
- HTML の欠落検査は、リスト番号と `#` を正しく扱わないと誤検知だらけになる。
- PUBLIC リポの成果物に、リポ外の auto memory の本文を抜粋しない（ファイル名と件数までにした）。

## 妥協点（次回の課題）
- 新版は435行で公式目安の200行を超える。🔴 と21項目を本体に残す要件のため。
- 詳細ファイルは原文のままなので、くどさは残る。

## 第2版で学んだこと（2026-10-27・独立評価2本を受けて）
- **社長が付けた期限（「今だけ」）を、要約の途中で落としていた。** 条件の文を命令形に縮めると、副詞（今だけ・当面・試しに）が真っ先に消える。縮めたあと、社長の発言の引用と並べて「期限・範囲を表す語」が残っているかを照合する。
- **「根拠が無いから足さない」は、改修の目的に直接効く1行には当てはまらない。** 依頼の目的（振り分けを守らせる）を原因分析が特定していれば、それが根拠になる。迷ったら、足す案を本文に入れて論点に「秘書判断」と書く方が、見送るより評価で叩かれない。
- **同じ定義を3か所に書くと必ず食い違う**（waiting）。定義は1か所に置き、ほかは「§A4 を見る」とだけ書く。
- **「全部読め」は守られない。** 作業→読む節の早見表（12行）にすると、先頭100行しか読まれない環境でも引き金になる。
- 詳細ファイルの古い規則は消さずに「> 更新：（どこを見るか）」を前後に足し、機械照合は注記行を除外して文字列一致で取る。
- デスクトップの Cowork では、ユーザー全体の CLAUDE.md の外部取り込みとシンボリックリンクは読み飛ばされる（公式）。案内は普通のファイルに文章で書く。

## 追記（2026-10-27・法務判定30）
- 「原文のまま移す」詳細ファイルにも、会員限定の取引条件の実額（鍋12点の仕入額・卸単価）が混ざっていた。原文を移す前に、卸・仕入・品番・受付番号・ロットの近くにある金額を洗う。
- 伏せる処理は生成スクリプトの中に正規表現で持ち、値そのものはスクリプトにも書かない。照合は伏せた後の文字列で取る。
- 伏せた値の一覧で機械検索すると、短い数字（50%・900 など）が一般の数字に大量に当たる。一覧は候補出しにだけ使い、最後は「卸・仕入の文脈にある金額」を目で見て決める。

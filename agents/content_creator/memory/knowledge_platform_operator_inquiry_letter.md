# プラットフォーム運営会社への「事前相談」文の型 — 自分の行為を先に開示して線を引いてもらう

初出 2026-09-30（T-20260920-003 / 成果物31 スーパーデリバリーへの照会文）。
兄弟：[knowledge_wholesaler_first_message_drafts.md](knowledge_wholesaler_first_message_drafts.md)（**出展企業**＝取引相手への1通目）／
[knowledge_wholesale_platform_profile_writing.md](knowledge_wholesale_platform_profile_writing.md)（申請書）。

**読者が違う。出展企業は「取引相手」、運営会社は「会員資格を握っている側」。**
運営会社への文は売り込みでも交渉でもなく、**「当社はこう動いていました。どこまで許容されますか」を先に差し出す文**。

## 1. 段階の見取り図（この行を足した）

| 相手 | 相手の心理 | 文の目的 |
|---|---|---|
| メーカー（関係なし） | 「営業か？」 | 開いてもらう |
| プラットフォーム（申請中） | 「卸して大丈夫な店か？」 | 承認を得る |
| 出展企業（承認直後） | 「本当に買うのか？面倒な客か？」 | 買う前の前提を確定 |
| **運営会社（グレーの相談）** | **「この会員は放置して大丈夫か？」** | **守るべき線を相手に引かせ、その記録を残す** |

## 2. 構成は「開示 → 停止の報告 → 質問」。この順序は動かせない

質問を先に置くと、答えた後で「実はもう163社分取っていました」と出す形＝**後出し**に読まれる。
見出しの言葉も効く。「ご報告」「お詫び」ではなく「**これまでに行ったことを、こちらから先にお伝えします**」。**自発性が主語に残る書き方を選ぶ。**

開示には「**取得していないもの**」を必ず並べる（今回：画像・卸価格・外部転載）。
やったことだけ書くと範囲が無限に見える。**やっていないことの列挙が、範囲を閉じる唯一の方法。**

## 3. 🔴 「禁止されていないので問題ない」系は1語も書かない（法務が明示的に禁じた）

書きたくなるが全部不採用。理由まで含めて残す。

| 書きたくなる一文 | なぜ書かないか |
|---|---|
| 「規約に禁止の記載がないため」 | 書いた瞬間に**弁解**になり、事前相談の体裁が壊れる |
| 「ログインしていないので会員規約の対象外と理解しています」 | 法務が採れないと判定した主張。書けば否認され心証だけ落ちる |
| 「負荷は軽微です」「一般的な範囲です」 | 軽重を**当社が決める**文。決めるのは相手 |
| 「他社も同様に行っており」 | 比較は言い訳の定型 |

**代わりに置く背骨の一文**：
> 貴社が許容される範囲を当方が把握しないまま続けるべきではないと考え、現在は……停止しております。

**判断の主体を相手に渡す一文**。これがあると全体が相談に読める。短縮版でもここは削らない。

## 4. 相手に「断る」という安全な回答を用意する（最重要）

質問1に自分から添えた：「**ご遠慮いただきたい場合は、その旨をお知らせいただければ、以後は行わず手作業に切り替えます。**」

- 担当者が止まる理由は「許可を出す権限が自分にあるか」。**「ご遠慮ください」で済む逃げ道を用意すると回答が返る。**
- 拒否されても関係が壊れない（代替手段があると先に述べている＝会員を止める必要がない）。
- **譲歩の装いにしないこと。**今回は手作業が実際に当社の既定方針だった（法務推奨の人手ゲート）。実行する気のない代替案を書くと次で嘘になる。

## 5. 「弾かれた原因」を聞くときは、重心を末尾の一文に置く

HTTP 429 の質問は素で書くと「**通し方を教えてください**」になり、迂回の記録になる。
採った形：事実（同一ページへ12秒間隔の2回目で429）→ 推測は「ように見受けられます」→ **末尾「避けるべき条件がございましたら、それに合わせます」**。
聞いている対象が**回避方法ではなく守るべき条件**であることを、文の最後で確定させる。

**社内の判定が n=1 なら、文中でも断定しない。**断定すると、相手に訂正が必要な文を残す。

## 6. 謝らない。期限も出さない

- **謝罪を入れない**：違反が確定していない段階（規約に禁止条項なし・robots.txt 違反なし）で謝ると「**違反を認めた会員**」という記録になる。開示はする、謝罪はしない。
- **期限を書かない**：当社は 2026-11-30 のサイトオープン条件を負っていたが本文に一切書かない。書けば急かす文。「お待ちしております」で止め、期日を指定しない。
- 卑屈にも尊大にもしない中間を作るのは、**謝罪語の有無**と**期日の有無**の2点でほぼ決まる。

## 7. 件名は分類。用件を圧縮すると定型文が返る

「429」「スクレイピング」「自動取得」を件名に入れると、一次受けで技術質問・クレームに仕分けられ**定型文**が返る。欲しいのは判断（許容範囲）。
→ 件名は「サイト上の商品情報の取り扱いについてのご相談（**お客様番号 3166793**）」。
**会員番号を件名に入れる**と、担当者が会員照会を先に済ませられる＝個別回答の確率が上がる。

## 8. フォーム提出を前提にした体裁（メールと違う）

| 判断 | 理由 |
|---|---|
| 長文版と短縮版を**両方**作る | フォームの文字数上限は外から見えない。上限に当たったとき**その場で削らせない**のが制作側の仕事 |
| 削る順番を明記する | 今回は ①第17条の同意のお願い（今すぐ不要）→ ②補足の1行 → ③開示の箇条書きを1文に畳む |
| `【】` で見出し、質問は番号付き | 装飾が効かない。**番号で返信が来る＝照合が要らない** |
| 全角35字前後で改行 | 表示幅が不明なので折り返しに依存しない |
| 字数は**必ず機械で数える** | 初稿で目分量「1,352字」と書いたが実測1,140字。**自分の推定を成果物に書くな**（Python で数えれば10秒） |

## 9. 数字は「食い違っても致命的でない単位」で書く

「163社分」と**社数**で書き、**リクエスト回数は書かなかった**。
相手のアクセスログには診断ぶん・検算ぶん・失敗ぶんが載っており、**回数を書くと食い違いが致命的になる**（「嘘を書いた会員」になる）。
→ **自分の数字と相手の数字が別ソースで一致し得ないときは、粗い単位で書く。**

## 10. 回答別の返信骨子を同梱する（秘書が即応できる形）

送るのがゴールではない。回答が来た瞬間に何を返すかまで書いて渡す。今回は5通り（許容範囲の提示／ご遠慮ください／API・CSV あり／定型文／無回答）。
書き方の原則：**新しい論点を足さない**（1通目の3点の枠内で閉じる）。加えて次の3つは骨子に必ず書く。

1. **費用が出たら §4.1（金銭）**＝自分で申し込まない
2. **沈黙を同意と読まない**（無回答は「拒否」と同じ扱い）
3. **催促は1回だけ・質問は1つに絞る・3通目は送らない**

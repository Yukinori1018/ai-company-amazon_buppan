# 卸（取引承認直後）への1通目の作り方 — 「可否を握っている相手」への文

初出 2026-09-20（T-20260920-003 / 丸進への初回問い合わせ文）。
兄弟：[knowledge_maker_outreach_drafts.md](knowledge_maker_outreach_drafts.md)（メーカーへの打診＝**まだ関係が無い**相手）／
[knowledge_wholesale_platform_profile_writing.md](knowledge_wholesale_platform_profile_writing.md)（卸サイトのプロフィール＝**申請書**）。

**この3通は読者が同じ「仕入れ先の担当者」でも、関係の段階が違う。段階を取り違えると文が壊れる。**

| 段階 | 文書 | 相手の心理 | 文の目的 |
|---|---|---|---|
| 関係なし | メーカー打診文 | 「営業か？」 | 開いてもらう |
| 申請中 | プラットフォームの店舗情報 | 「卸して大丈夫な店か？」 | 承認を得る |
| **承認直後（今回）** | **1通目の問い合わせ** | **「本当に買うのか？面倒な客か？」** | **買う前に潰すべき前提を確定させる** |

## 1. 承認直後の1通目は「質問状」ではなく「条件確認」

承認された＝相手は当社を取引先として受け入れた状態。ここで質問だけ3つ並べると**手間だけ増える客**になる。
今回の解：**質問の前に方針3点＋URL、質問の後に初回発注の意思**で挟んだ。質問を「買うための確認」に見せる。

初回発注の意思は**相手の条件表の数字で示す**（今回＝送料無料ライン 税抜20,000円）。
「本気です」と書くより、**相手が自分で書いた数字を引用する方が本気度が伝わる**。確約語（発注します／購入します）は使わず「組む想定で品目を選んでおります」で止めた。

## 2. 断られやすい質問は「最後」ではなく「方針の直後」に置く

最も断られやすい質問（Amazon での販売可否）を最後に置く＝**答えさせた後で断りにくくする**順番は、誠実さを欠くうえ、断られたら他の回答が無駄になる。
採ったのは**相手の拒否理由を先に潰してから聞く**配置。

- 卸が Amazon を嫌う理由はほぼ3つ：**値崩れ／非正規品の混入／商品情報の改変**
- したがって方針も3つに揃える（価格を崩さない・正規品のみ・商品情報は公式基準）。**反論ではなく先回り**
- 自社サイトに明文があるなら URL を必ず添える。**文中の宣言より、先に公開されていた事実の方が強い**（satoy-select.com/partners）

## 3. 件名は「結論ファースト」にしない（社内文書との違い）

社内では結論を件名に置く。だが**可否を握っている相手**には、件名で結論を出すと本文を読む前に否決される。
今回、SD の実測で「ネット販売の可否を明示した48社の35%が Amazon を名指しで不可」。**名指しの拒否は開く前に起きる。**

→ 件名は分類（「お取引承認のお礼と、発注前のご確認3点」）、**開示は本文3行目**。
騙し討ちにしないため、本文の最初の段落で必ず自ら「Amazon.co.jp のストア」と名乗ること。この1行を省くと詐術になる。

## 4. 相手の書式を問う質問を、角が立たなくする3点セット

「請求書に当社名・住所・メーカー名・購入点数が載るか」は、素で書くと**監査**に読まれる（「何か疑われている」「様式変更を求められる」）。
角を消すのは質問文ではなく、**周辺の3文**。

1. **目的を先に言う**（「Amazonでは一部ブランドの出品前に仕入れ先の請求書の提出を求められ」）。理由が分からない質問が一番怖い
2. **追加作業を求めないと明言する**（「通常の書式のままで結構ですので」）← **これが一番効く**。依頼ではなく確認だと伝わる
3. **回答コストを最小に見せる**（「記載の有無だけ」）。相手は「載ります／載りません」の一言で済む

**依頼形（「書いてください」）は1通目で使わない。** 買う前に様式変更を頼むのは順序が逆で、断られると他の質問の心証まで下げる。

## 5. 相手に手間をかける質問には、相手側の利点を1行

「よく出るサイズ・色」は相手に手間しか生まない。添えたのは「売れ筋を外さず、**継続して発注しやすくなります**」。
卸の利点は返品が出ないことと継続発注。**当社の語彙（死に在庫・回転月数・バリエーション）は1語も出さない。**
[knowledge_wholesale_platform_profile_writing.md](knowledge_wholesale_platform_profile_writing.md) §5「戦略メモの語彙は読者で翻訳する」と同じ原則。

## 6. 先方メッセージの引き取りを冒頭2行に置く

丸進からの承認メッセージにあった「オープン在庫／欠品・終了あり／発注後キャンセル不可」のうち2点をそのまま返した。
**読んだことの証明**であり、「条件を理解しない新規客」という警戒を最初の2行で外す。承認直後の1通目では、お礼だけの冒頭より強い。

## 7. プラットフォーム内メッセージの禁則（SD / NETSEA 共通）

**SD 内で直接取引（SD を通さない取引）の相談・自社の営業行為は規約違反。** NETSEA は違約金200万円＋代金50%の条項あり。
→ 「直接」「個別に」「メールで」「独占」「総代理」「限定販売」は**1語も入れない**。送信前チェックに grep 相当の項目を必ず置く。
本丸（独占交渉）へはこの経路では行けない。1通目でそれを匂わせると、取引自体を失う。

## 8. 字数制限があるときは「削る順番」を表で渡す

画面の入力上限は見るまで分からない。**採用稿1本＋削る順番の表**で渡すと、カズヨが画面で判断できる。
削ってよい順＝①補足説明 → ②相手側の利点 → ③**質問の理由（ここを削ると詰問になる。削るなら質問ごと別便）**。
削らないもの＝方針3点・URL・発注意思。**「はい」と言える材料そのもの**だから。

字数は必ず機械で数え、**実測値を書く**（今回604字／うちURL33字＝実質571字）。目安を超えたら超えた事実と判断理由を書く（丸めない）。

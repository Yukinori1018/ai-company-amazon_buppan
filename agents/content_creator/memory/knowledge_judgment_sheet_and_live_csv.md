# 制作原則: 「読み物」ではなく「判定ツール」を作るとき／生きている CSV を資料にするとき

記録 2026-09-04（T-20260904-004 タスク C-2 / 初回仕入れ判定資料 01 と メーカー打診候補リスト 02）。
[knowledge_research_doc_to_html.md](knowledge_research_doc_to_html.md) の続き。**原稿HTML化の2回目**で、前回と違う判断が3つ要った。

## 1. 依頼文に「使われ方」が書いてあったら、そこが設計の起点

今回の依頼にはこう書かれていた。

> 「社長は**候補商品リストを片手に、これで振り分けます。**読み物ではなく判定ツールです」
> 「致命的な4項目は、**開いた瞬間に目に入る**こと」「チェックリスト11項目は**印刷して手元に置ける**形に」

前回（T-20260903-001）は「原稿を1文字も変えずに組版する」だけで足りた。今回は**同じ制約の上に「数秒で判定できる」という要求が乗った**。
本文を1文字も変えずに視認性だけを上げるには、**文字ではなく CSS で情報を足す**しかない。実装した4つ：

| やったこと | 本文を触っていないと言える理由 |
|---|---|
| 表セルの「致命的」「単一ソース」を色付きピルにし、該当行に左帯 | 語はそのまま。`--cellmark` で**表セルの中だけ**を装飾。段落や見出しには一切かけない |
| 「1-B. 例外なく買わない（致命的）」節を太い赤枠に | 節の囲みは既存の `--box` 機能。文言は不変 |
| チェックリスト節を印刷時に独立ページ化＋各項目に記入欄 | 記入欄は文字ではなく CSS の四角（`::before` の枠線）。番号は原稿どおり |
| 目次の項目に節の色を反映 | 目次は元から自動生成のメタ情報。**「開いた瞬間に目に入る」を本文追加なしで満たす唯一の場所がここだった** |

> **一般則: 「目立たせろ」と言われたら、まず目次と CSS を疑う。本文に文字を足すのは最後の手段。**
> 「開いた瞬間に見える位置に要約を置く」は本文追加になるので断念し、代わりに**目次の該当項目を赤くした**。妥協点として報告した。

## 2. コンバータは毎回どこかが足りない。**足りないことに気づく手段は数の突合だけ**

今回の原稿には前回になかった記法が入っていた。放置していたら**静かに壊れていた**もの：

- `**強調**` 119箇所 → 未実装。そのまま出ると本文に `**` がベタ書きで出る（消えはしないが読めない）
- `` `コード` `` 31箇所 → 同上
- **`# ` 見出しが4つ（タイトル＋第1部/第2部/第3部）** → **2つ目以降を黙って捨てていた。**タイトル変数を上書きする実装だったため、
  「第1部 買ってはいけないリスト」という**見出しが3つ丸ごと消え、文書タイトルが「第3部 反証・限界・要確認」になっていた**

3つ目は本文照合（行単位）では拾えるが、**見出し数の突合（md 4 / html 4）を先に見ていたので一発で分かった**。
スキル側の検証手順に「見出し数を突合する」と書いておいた自分に助けられた。**数の突合は毎回やる。**

## 3. 入力の CSV が**作業中に増えていた**（133社 → 163社）

02 の元データは、別のエージェントがまだ書き込み中のファイルだった。気づいたきっかけは検証の未掲載リストで、
**「順位120の備考」として出てきた文面が、同じ CSV を読み直すと順位146の会社のものだった**こと。

- 途中で気づかなければ、**「133社」と書かれた資料を163社のデータから作って納品していた**
- 対処: 生成物の見出し・本文の社数を**すべて `len(rows)` から作る**ようにし、ページ先頭とフッタに
  **「CSV の 2026-09-04 13:11 時点のスナップショット」と mtime を焼き込んだ**。再生成はコマンド1本

> **一般則: 他エージェントの成果物を入力にするときは、`ls -la` で mtime を見てから作り、納品直前にもう一度見る。**
> 社数・件数を文章にベタ書きしない。データから出す。ベタ書きは古くなった瞬間に嘘になる。

## 4. PUBLIC リポジトリでは「表示しない」判断も制作の仕事

CSV に**個人事業主の疑いがある社の電話番号と部屋番号付き住所**が入っていた（他の同種の社は伏せ字にされていたのに1社だけ生値）。
そのまま HTML にすると、公開リポに新しいファイルとしてもう1部増えることになる。

- **伏せた。**ただし空欄にはせず「個人事業主の疑いのため本ページでは伏せています（値は CSV にあります）」と理由を書いた
- **CSV 側が既に `【非掲載】…` と注記している場合は、その注記をそのまま出す**（二重に隠すと、なぜ空欄かが読み手に伝わらない）
- 秘書には「CSV 側の適用漏れではないか」として報告した。**データの直しは自分でやらない**（成果物の持ち主が別にいる）

## 5. 表は「幅を決める」までが仕事

141行の一覧表を作ったら、注記行が右端で切れていた。原因は列幅の自動計算で、`table-layout:fixed` ＋列ごとの幅指定で解決。
**溢れの有無はスクリーンショットではなく `scrollWidth > clientWidth` で判定する**（前回の学びが今回そのまま効いた）。
併せて、CSV の「取引可否シグナル」列を一覧の主行に出した。**`対象外(大手/流通構造)` が赤字で見えるだけで、141行のうち当たる価値のない行が一瞬で分かる。**

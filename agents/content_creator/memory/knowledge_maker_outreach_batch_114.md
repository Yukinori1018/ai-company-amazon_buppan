# 打診文を100社規模で量産する型（第1弾114社・2026-10-11）

初出 2026-10-11（T-20260930-001 / 第1弾114社）。前回の型は [knowledge_maker_outreach_send_sheet_20.md](knowledge_maker_outreach_send_sheet_20.md)（20社）。
**「打診文を◯社分」と頼まれたら、まずこれと20社版のメモを読む。**

## 1. 手順（今回そのまま回ったもの）

1. 台帳シートをサービスアカウントで丸ごと JSON に落とす（`66_work/sheet_raw.json`）。**シートは作業中に他の担当が書き換えるので、スナップショットを固定してから書く**
2. 全行を1社ずつ読み、社ごとの辞書を手で書く：連絡手段 ch（M/F/T）・〔商品名〕・公式で読んだ事実1文・注意。**事実は台帳の「公式トップに…」「事業内容に…」と書かれた値だけ使う**。「検索要約」「第三者情報」「推測」と付いた値は「拝見しました」と書けないので使わない
3. 型（07）＋辞書＋生成スクリプト（66_build.py）。字数は assert で落とす
4. 稿1で字数超過の一覧を出し、稿2で「型の側」を先に詰めてから社ごとの文を削る（型を1か所直すと55社が一度に縮む）
5. 稿3は**全社の「3行目＋個別文」だけを1画面に並べて読む**。1通ずつ読むと型由来の重複は見えない

## 2. 連絡手段の決め方（迷ったらこの順）

| 状況 | 採る手段 |
|---|---|
| 取引・法人・販売店申込み用と明記されたフォーム／メール | それを使う |
| 自社サイトで公表されたメール | メール（会社概要を添付できる） |
| メールが個人名（ono@ 等）・他団体サイトの掲載・楽天店の連絡用・購入者向け | 使わずフォームか電話 |
| フォームの必須欄が埋められない（「サロン名」「お取引ディーラー」等） | 電話 |
| 「電話でのセールスお断り」の表示 | フォームだけ。電話で追いかけない |

## 3. 型の改善で見つけたこと

- **300字フォームの1行目と3行目が同じことを言っていた**（「仕入れのご相談です」「仕入れさせていただきたく、ご連絡いたしました」）。3行目を「仕入れたく存じます」にすると13字縮み、重複も消えた。20社では字数に余裕があり見逃していた
- **Amazon の売れ方は固定句で書く**：「Amazon でも、販売店を通じて継続して購入されている商品と見ております。」。数字を書かずに「なぜ御社か」の根拠になる
- 🔴 **流通を絞っている社には「販売店を通じて」を書かない**（会員制・医療機関限定・サロン専売・正規販売店制）。「御社の流通から品が漏れています」と読める＝相手の担当者の落ち度を突く形になる。「Amazon でも売れ続けている品と見ております」に弱める。13社に当てた
- **輸入元向けの差し替え文と個別文がぶつかる**：「御社が正規代理店として扱われている〜」＋「正規代理店と拝見しました」。対象の文は「御社が扱われている」に留め、事実は個別文で1回だけ言う
- 電話の定型句に「扱わせていただきたいと考えました」を入れると、事実の文に意図が入っている社（「だからこそ正規に仕入れたい」）で意図が2回出る。定型句は観察だけにする

## 4. 送る前に自社の公開物と送り先を突き合わせる（2回目）

当社 /partners（2026-10-11 実見）：「医薬品・医薬部外品、酒類、要冷蔵・要冷凍の食品、危険物は見合わせ（常温の食品は取り扱う）」。
第1弾に**指定医薬部外品・「薬用」の洗浄料・スプレー缶・入浴剤**が入っていた。添付する会社概要・署名の /partners と矛盾するので、注意列に「/partners と衝突」と立てて秘書に判断を返した（確定2・要確認8）。
→ 20社版の食品の件（§4）と同じ型。**送り先リストを受け取ったら、最初に /partners の「扱わないもの」を開く。**

## 5. 「800字以内」と法定の署名

メールの本文は署名を除いて680〜731字、署名込みは930〜981字。署名7行（約250字）は特定電子メール法の表示義務で削れない。
→ 字数指定のある依頼で署名を含めるかが書かれていないときは、**署名を除いて満たし、署名込みの実測値も併記する**。黙ってどちらかに決めない。

## 6. Python 3.9 の落とし穴

日本語を含む**1,000字を超える1行**があると、UTF-8 として正しいファイルでも `SyntaxError: Non-UTF-8 code` が出た（ファイルでも標準入力でも）。辞書を1行に書き出さず、1要素1行にすれば通る。`# -*- coding: utf-8 -*-` を先頭に付けても回避できる。

## 7. 追加分を足すとき（第1弾 114→127社・2026-10-11 深夜）

- **既存分は再生成しない。CSV を読んで番号だけ付け替える。**再生成すると、元にしたシートのスナップショットが変わっていて文面が漂う。突合キーは代表ASIN の URL（社名は「（販売：…）」の付け方が版ごとに違うので使えない）。差分0を assert してから出す
- **型は import して二重に持たない**（66b_build.py は 66_build.py の MAIL/FORM300/TEL/SIG を読み込む）
- 🔴 **台帳の宛先をそのまま信じない。公式ページで用途を読み直す。**13社中3社の宛先が購入者向けだった（オンラインストア用のメール／通販が不調なときの連絡用／「お客様専用」ダイヤル）。会社の公式サイト（ブランドサイトではなく）に「お取引先様専用」窓口があることがある（名古屋眼鏡＝meigan.co.jp）。ブランドサイトしか見ていない台帳の行は、会社名で公式を引き直す
- 読み直しで出た注意点の型：**公式からの Amazon ブランドストアへのリンク**（ブランド登録済み＝販売者限定化しやすい）／**「一般医療機器」の表記**／**購入数量制限のお知らせ**（供給が細い）／**「一般消費者への販売はご遠慮」**（美容室専売）。いずれも本文ではなく注意列に書いて秘書に返す
- 専門向けの流通（サロン・美容室）に送るときは「〜と承知のうえで」を個別文の頭に置く。隠して書くと受け手は真っ先にそこを突く
- 受け手として読み直すときは「**その窓口から書いているのに『窓口を拝見しました』と書いていないか**」「**公式の文言（大量注文）と自分の申し出（5〜10点）がかみ合っているか**」を見る

## 8. 2回目の追加分（第1弾 127→146社・2026-10-12 未明）

- §7 の手順はそのまま回った（66c_build.py は 66b_build.py の gen() を import。型も生成規則も二重に持たない）。差分0の検査は「打診順以外の10列が元 CSV と完全一致」まで広げた。前回は件数一致だけで、中身の一致を assert していなかった
- 🔴 **台帳の宛先の読み直しは、今回も19社中4社で差し替えになった**（前回13社中3社）。率がほぼ同じ＝偶然ではなく、台帳の採取手順の構造（特商法の表記・サイト下部のメールを拾う）から来る。**追加分を書くときは毎回、全社の宛先を公式で開き直す**のを既定にする
  - 型1：**特商法の表記のメールが「通販のお客様窓口」**（返品・不良品の連絡先）。通販サイトしか持たない食品メーカーで多い
  - 型2：**サイトポリシーの「リンクのご連絡」先のメール**を窓口として採っていた（テイクネット）
  - 型3：**台帳のフォームURLが窓口の選択ページ**で、その先に「B2B（商品仕入れ）」専用フォームがある（ピコモンテ）
  - 逆に、特商法のメールでも**全ページに「卸販売も…メールでお問い合わせを」と出ていれば取引に使える**（沖縄ビエント）。メールの置き場所ではなく、そのサイトが何と案内しているかで決める
- 🔴 **送り先の公式に「断り」が明記されている社が3社あった**：「通販目的の販売はお受けしておりません」（歯科の輸入元）／「施術院でしか購入できません」（カイロの直販）／「卸は特定の会の関連企業のみ・モールでの転売を確認」（茶）。**フォームの冒頭・よくある質問・ご利用案内の「転売について」**に書かれていることが多い。打診文は作るが、注意列の先頭に「送らない推奨」と書いて秘書に返す。台帳の「流通形態：不明」は、この3か所を読めば埋まる
- 公式の断り文を本文で引くときは、**言い換えて弱めない**（「お受けしておりません」を「慎重でいらっしゃる」と書きかけた）。弱めると相手は「読んでいない」と受け取る
- 単価の高い代表ASIN（3万円超）は、型の固定句「初回は5〜10点」でテスト枠（1社3万円・CLAUDE.md §3.5）を超える。**型の固定句と会社の資金ルールがぶつかる行は、注意列で「1〜2点に直すか」を秘書に返す**（型を社ごとに崩さない）
- 公式に「ケース単位の卸」とある社には、依頼文の前置き（pre）に「1ケースの入り数と、」を足して、5〜10点の単位のずれを返信で揃える
- 電話の台本で創業年を言うときは「1705年頃」ではなく「三百年あまり」。読み上げて口に乗るかで決める

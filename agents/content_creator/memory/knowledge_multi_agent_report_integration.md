# 複数エージェントの成果物を1枚に統合するときの型（ヒデアキ）

初回記入 2026-09-21 / T-20260920-005（成果物14・14本の素材を1枚に統合）

## 依頼の型

「成果物が N 本になって社長が全体像を掴めない。1枚の統合報告を作れ」。
2日で複数の担当（経理・プランナー・シミュレーター・リサーチャー）が互いを反証し合い、**数字が何度も取り下げられている**状態が前提。今後も PDCA を回すたびに同じ依頼が来る。

## 学び1：統合報告の本体は「取り下げた数字の一覧」

新しい結論を書くだけでは足りない。**読者は古いファイルを開き続ける**ので、
「どの数字が・どこに書かれていて・誰が何を根拠に取り下げ・いまの値は何か」の4列表を最初に置く。
今回は9件あった（借入826万／78社で200万／実測成約率1.16%／判定線H1〜H3 など）。
この表を §2 の先頭に置いたのは、§1 の結論より先に「信じてはいけない数字」を渡すため。

## 学び2：矛盾は統合しない。専用の節に残す

依頼側（秘書）からも明示された原則だが、実務上も正しい。
今回は5件残した（99万 vs 50万／見出しは「200万に届く唯一の道」なのに数字は182万／借入時期が5ヶ月食い違う など）。
**統合報告が一番やってはいけないのは、食い違いを平均したり片方を黙って採ること。** 出典番号つきで並べる。

## 学び3：「推定」と「観測値ゼロ」は別物

素材では「実測」と書かれているのに、遡るとモデル出力だった数字があった（成約率1.16%）。
確度の表は **「置き値／出どころ／当社の観測／初実測の時期」の4列**にすると、この混同が構造的に防げる。
「推定」で一括りにすると、観測値ゼロのものが推定と同じ棚に並んでしまう。

## 学び4：論点の畳み方

各成果物の末尾に散らばる「社長判断」は重複する（同じ融資の話が3本に出る）。
畳む基準は **「社長が1回答えれば閉じるか」**。閉じないもの（時期が来れば自動で決まるもの）は
「いま決めなくてよい」と明記して残す＝論点数を減らすより、**回答の要否を仕分ける**ほうが読者の負担が減る。
今回は5件に畳み、そのうち「いま回答が要るのは3件」と引き継ぎに書いた。

## 学び5：古い版の扱い

07（旧統合報告）は残置した。上書きすると過去の判断根拠が追えなくなるため。
ただし **古い版に失効表示が無いと、社長がそちらを先に開いて古い数字を読む。**
失効表示を入れるかは秘書判断として引き渡した（自分で他の成果物を改変しない）。
→ 次回以降、**版を重ねる文書は「冒頭1行の失効表示」を最初から設計に入れる**こと。

## 手順（再利用可）

1. 素材を全部読む（要約で済ませない。取り下げは本文の §7 相当に埋まっていることが多い）
2. 取り下げ一覧 → 変遷 → 確定 → 未確定 → 判断 → 動いていること、の順で組む
3. 数字は素材から引くだけ。自分で計算しない（計算した瞬間に出典が消える）
4. 専門用語は冒頭に5語以内の補足ボックス（社長は副業初心者）
5. 納品は md + html 併出力。html は同フォルダの `99_md2html.py` を使う（CSSインライン・単体で開ける）

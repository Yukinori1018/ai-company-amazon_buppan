# Keepa「出品者概要（Seller）」画面 — 制作時に確定した中身と使いどころ

記録 2026-08-21（T-20260811-001 第2版 §6）。出典＝社長共有スクショ `FireShot Capture 026`（keepa.com／**2026-08 時点**の画面）。
**Keepa関連の制作依頼を受けたら、まずこのファイルと納品物 `workspace/output/deliverables/T-20260811-001/` を見ること。**

## 到達経路（教材として重要）

`商品ページ → Keepa Box → Data → Buy Box統計情報 → 販売者名リンク` で出品者概要に飛べる。
実際、023（Buy Box統計）に **カート獲得4%・レビュー4,721** で載っていた業者が、026 の分析対象そのものだった（評価件数4,721・365日評価82% が両画面で一致）。
**スクショ同士が繋がっているかは必ず数値で照合する。** 繋がりが見つかると、章立ての導線がそのまま書ける（今回は §3 → §6 の橋になった）。

もう一つの入口は keepa.com 上部メニュー `プロ → 出品者検索`。**「プロ」タブ配下＝有料プラン前提の疑いが濃い**（アカウントに「プロ」バッジ、右上に `Quota: 100%`）。無料可否は画面から断定できないので「要確認」で出した。

## 画面から読み取れたもの

| ブロック | 中身 |
|---|---|
| 基本情報 | セラーID／店名／住所／**商業番号（12桁＝古物商許可番号の体裁）**／電話／代表者／「表示するアマゾン」「Keepaで出品を閲覧」ボタン |
| パフォーマンス | 評価%（画面表記は**「え」＝Ratingの誤訳**）／評価件数（「評価ブロック」）／確認済みリスト数／FBA利用有無／購入ボックス切替の所有者%／中古の所有者%／BUY BOXの平均売上数／Keepa追跡開始日 |
| 期間別の評価 | ライフタイム／30日／90日／365日 の評価%と件数＋時系列チャート＋最新フィードバック（星と日付） |
| カタログ | **重複の多い主なセラー**（品揃えの重複度%。Amazon.co.jp も1行として出る） |
| 統計 | カテゴリ別／ブランド別に「リスト構成比・**Amazonオファーがあるリスト%**・30日間の平均順位」 |

## 実務の使いどころ（当社の仕入れ判断への変換）

1. **参入前の相手チェック** — ライフタイム96%でも直近90日が63%なら「今崩れている競合」。**累計評価だけ見て引き下がると判断を誤る**。この「時間軸のズレ」が一番おいしい読み。
2. **Amazon本体との重複率** — 「重複の多い主なセラー」に Amazon.co.jp が37%で出る＝取扱の4割で本体と鉢合わせ。ブランド別の `Amazonオファーがあるリスト%` も同じ用途。**0%の領域＝本体不在の隙間**（実例：アップル30.89%で本体0%）。当社が真似すべき／避けるべき領域の線引きに直結。
3. **構成比 × 30日平均順位で稼ぎ頭を当てる** — 出品数は家電＆カメラ52.69%（#31,133）なのに、ゲームは16.77%で#641。**看板と稼ぎ頭は違う。**
4. **芋づる探索** — 同業を開いて「Keepaで出品を閲覧」で棚を丸ごと見る。②メーカー仕入れの逆引き用途は**未検証の仮説**として書いた（断定しない）。

## 断定を避けた項目（そのまま「要確認」で納品）

- 「BUY BOX の平均売上数 8.83」— 単位も母数も画面に無い。**数字が独り歩きすると危険なので「判断に使わないでください」と本文に明記した。**
- 「購入ボックス切り替えの所有者 4%」「ボックスを購入する 中古の所有者 1%」の定義
- Buy Box統計の評価列 `-1%`（データなしと推定）
- 商業番号が古物商許可番号であること（体裁は一致するが Keepa 側の定義は不明）

> 解消手段も本文に書いた：**Keepa右上の「言語」を English にすると原語ラベルが読める。** 日本語UIは機械翻訳が混じる（「え」＝Rating が象徴例）。次に誰かが Keepa 資料を作るなら、**まず英語表示でラベルを確定してから日本語で書く**のが正しい順序。

## 追記（2026-08-24・第3版）— 「要確認」で残した4項目の答え合わせ

T-20260824-001（サトルの公式APIドキュメント精読）で決着した。**上の「断定を避けた項目」の現在の状態は以下。**

| 第2版で保留した項目 | 決着 |
|---|---|
| 「BUY BOX の平均売上数 8.83」 | **`avgBuyBoxCompetitors` ＝ Buy Box を争う平均競合出品者数（自社含む）。売上ではない。日本語UIの誤訳で、意味が真逆に伝わる。**「大きいほど良い」ではなく「大きいほど混んだ棚」。なお**その出品者の商品群全体の平均**であって、目の前の1商品の混み具合ではない（ここも読み違えやすい） |
| 「購入ボックス切り替えの所有者 4%」 | `buyBoxNewOwnershipRate` ＝ **新品 Buy Box の平均獲得率（%）**。当社推定どおり |
| 「ボックスを購入する 中古の所有者 1%」 | `buyBoxUsedOwnershipRate` ＝ **中古 Buy Box の平均獲得率（%）**。当社推定どおり |
| Buy Box統計の評価 `-1%` | **未解決のまま。**公式 `buyBoxStats` に評価の項目が存在しない。据え置き＝正解 |
| 商業番号＝古物商許可番号か | **未解決のまま。**近いのは `tradeNumber`（商業登記番号）だが日本の許可番号との対応は公式に記述なし。→ **6-6「中古を扱うなら許可の裏取り」は確度を落として格下げした** |

**あわせて §6 の記述で是正した公式事実（この画面を再度扱うとき必ず反映すること）：**

- `positiveRating`（画面の「え」）＝ **★4または★5の比率**。★3はポジティブに含まれない（★3が増えると下がる、感度の高い指標）
- `hasFBA`（FBAリストが見つかりました）＝ **「はい」は信用できるが「いいえ」は信用できない**（公式が「FBA出品があっても false になりうる」と明記）。**非対称性を必ず書く**
- `totalStorefrontAsins`（確認済みリスト）＝ **2026-02-23 以降は Keepa 内部DB の集計値**。Amazonのストアフロント実取得ではなく、**実在庫数でもない**
- `competitors`（重複の多い主なセラー）＝ **上位5社まで**（6位以下は「いない」のではなく「出ない」）
- `sellerCategoryStatistics` / `sellerBrandStatistics`（カテゴリ／ブランド統計）＝ 公式が自ら「**しばしば不完全で古い**」と明記。**％を1桁まで信じない**
- `trackingSince` ＝ Keepaが追跡を始めた日で、**Amazonでの開業日ではない**
- 画面右上の `Quota: 100%` ＝ **公式APIドキュメントに定義が無い**（第2版は断定していた）。**第3版で「未確認」に格下げした**
- プラン（公式FAQ）＝ 月29ユーロ／年290ユーロ・**無料トライアルなし**・**1ユーザー1シート制で共有不可**（＝アカウント共用は規約違反。法務論点）

> **次に Keepa 資料を作る人へ：**「まず英語表示でラベルを確定してから日本語で書く」という第2版の申し送りは有効だが、**さらに手前に一手ある** ── `workspace/output/deliverables/T-20260824-001/keepa-glossary.md` **§0.5 の対応表を引く**。日本語UI ↔ 公式APIフィールド ↔ 実際の意味 ↔ 当社が過去に取り違えた内容、の4列で並んでいる。

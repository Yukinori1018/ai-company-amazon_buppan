# 社長のこだわり: 文書は「守られる形」に書く（ヒデアキの基準）

初回記入 2026-08-21（T-20260821-004 / 委譲ルール改訂）。以後の制作依頼はまずこのファイルを読むこと。

## 1. ルール文書は「禁止語の羅列」で書かない

社長の指摘が3度繰り返された案件（カズヨの抱え込み）で分かったこと。

- 過去2回の対処は**禁止文言の追記**だった。文書は長くなり、再発は止まらなかった。
- **長い文書は効きが落ちる。** CLAUDE.md は毎セッション読まれる「憲法」なので、追記するたびに1行あたりの重みが薄まる。
- 効く形＝**判定を1問に畳む**。「振るべきか考える」ではなく「**例外4つに当たるか？** 当たらなければ振る」。読み手が5秒で終えられるかが合格ラインで、正しさだけでは不十分。

> 制作の原則: ルール文書を書くときは「読んで納得できるか」ではなく「**忙しい時に守れるか**」で推敲する。

## 2. 追記より置換。重複は必ず削る

改訂依頼で「追加してください」と言われても、**既存節と重複する箇所は削って短くする**のが仕事のうち。
今回も担当別バレット（マリエ／ヒデアキ／タカシ）は直上の担当表と同義だったため削除した。追加分と削除分を相殺し、**総量を増やさない**のが良い改訂。

## 3. 抜け道になる一文を探す

ルール文書のバグは「禁止が足りない」ではなく「**逃げ道が1文ある**」ことが多い。今回の実例:

| 抜け道になっていた文 | 修正後 |
|---|---|
| 「30秒考えて決まらなければ自分で受ける」 | 「30秒考えて決まらなければ**振る**」 |
| 「どれにも該当しない場合は秘書自身で受ける」 | 「最も近い担当に振る。分解した先の実務は担当が持つ」 |
| 「軽微・即時なら代行可」 | 「代行で進めます」を明示的に例外から除外 |

**改訂を頼まれたら、まず全文を読んで「自分ならどこから逃げるか」を探す。** そこが直すべき箇所。

## 4. 社長の言葉はそのまま引用して残す

社長の指摘は要約せず原文で文書に埋める。理由が残ると、後から読む人が「なぜこのルールがあるか」を自分で再構成できる。今回も CLAUDE.md と routing.md の両方に指摘の原文を引用した。

## 5. 経緯（日付＋出来事）を必ず末尾に残す

同じ論点が再発した時、「いつ・何があって・どう直したか」が無いと、また同じ対処（＝効かない追記）を繰り返す。改訂には必ず日付入りの1〜2行注記を付ける。

## 判断が分かれた点（次回への申し送り）

- 例外4「1手で終わる事実確認」は、**それ自体が抜け道になりうる**（「もう1ファイルだけ」）。「2手目が要ると分かった瞬間に振り直す」という上限を明記して塞いだが、運用で緩む可能性がある。3ヶ月後に再発していたら、この例外を削って3つにするのが次の一手。

## 6. 「余計なことがゴチャゴチャ」＝分量ではなく混在（2026-08-24 / T-20260824-005）

社長のレビュー原文：

> 「成果物をレビューしました。**余計なことがゴチャゴチャと書かれていた**ので、整理して、**正式な用語集**として、まとめて下さい。（今まで作った成果物は消す必要はありません）」

観察できたこと：

- **指摘されたのは「長い」ではなく「混ざっている」。**対象文書（Keepa用語集）は事実として正確だったが、定義・当社の失敗談・法則・運用結論・別文書の管理番号が1ファイルに同居していた。
- **「消す必要はありません」が付いている。**社長は情報の廃棄を求めていない。求めているのは**用途ごとの分離**。→ 既存を保全し、新規ファイルで作り直すのが正解。改稿依頼で「今までのは消さなくていい」と言われたら、**上書きではなく分割**のサイン。
- **社長は資料を「読む」のではなく「引く」。**用語を1つ調べに来るだけ。したがって索引・検索・早見表が本体で、背景説明は本体ではない。

> **次回への一般則：社長向けの資料は「1文書＝1動作」。**「読む」「引く」「判断する」が混ざったら、その時点で分割を提案する。

# Amazon セラーサポートの既存ケースへ送る催促文の作り方

初出 2026-09-15（T-20260909-001 / ケース 21912948521・Amazon.ca の KYC 停止）。

## 手順（再利用可）

1. **前回の投稿の実物を読む。**チケットの要約だけで書かない。今回は T-20260826-004 の L1541〜1585 に、9/7 投稿の骨子・行き止まりURL・受理の記録があった
2. **催促は「前回の問いを番号のまま再掲＋新しい事実だけ追記」。**問いの数を前回と揃えると、担当者が対応を取りやすく、新規の申し立てと誤読されない
3. **定型回答を1つ予測して、事実で先回りする。**Amazon の定型は「健全性から申し立てよ」「Account Info から書類を出せ」の2つが多い（セラーフォーラムでも頻出）。**実行済みのものだけ**を本文に書く。未確認のものは送信前チェックに回し、確認できたら1文を足せるよう差し込み文を用意しておく
4. 英語は1文1事実。日付は月名で書く。Amazon 自身の用語（deactivated / charge method）はそのまま使う。日本語 UI で確認したボタン名は英語で引用せず、説明的に書く
5. 納品物の順番：使い方（どちらを送るか）→ 英語版 → 日本語版 → 送信前チェック → 表現の意図 → 妥協点
6. 分量は `wc -w`（英語）と文字数カウント（日本語）で機械的に測る

## 受け手視点で見る点

- 本文中の「どこにも示されていない」「今も行き止まり」は**時点つきの事実**。最後に確認した日付がいつかをチケットで調べる（今回の行き止まり確認は 9/7 が最後だった）。古ければ送信前チェックに入れる
- 「解決した」と書けるのは Amazon 側の判定が見えたときだけ。見えていないうちは「表示されなくなった」と書く
- 同じ案内を繰り返させない一文は、要望の形にせず事実の形で書く（「手順は実行済みで、この画面で止まる」）

## 運用上の注意

- 発注時に保存先を agent_output と指定された。下書きは送信前の中間物なので従ったが、agent_output は Git 管理外。送信した文面を記録として残すなら、deliverables へ移すかチケットに全文を貼るかを秘書に確認する
- チケットの assignee が secretary のまま発注された。明示の発注なので作業は進め、報告で指摘した

## 追記 2026-09-27：催促ではなく「新規ケースで出し直す」ときの型（T-20260927-003 / カナダ）

1. **冒頭2文で「旧ケースID＋無回答の起点日＋旧ケースは閉じた」。**担当者が最初に疑うのは重複起票。先に潰す
2. **経緯は「月名日付：1行1事実」の箇条書き。**チャット担当は旧ケースを開かずに答える前提で書く。矛盾（完了メール→それでも停止）は "anyway" の一語で示し、非難語は足さない
3. **定型回答の先回りを1文**（「申し立てボタンは行き止まり」）。発注の要点に無くても入れ、意図を説明する
4. **問いは3つ。3つ目は「解決できなければ Account Health へ引き継ぎ＋新ケースID通知」**＝チャットが「分かりません」で終わるときの出口
5. **記録同士が食い違う事実は本文に入れない書き方で回避する**（催促の回数・時刻）。日付だけ書き、回数は「since September 7 無回答」で両方の記録に整合させる。食い違い自体は妥協点に明記
6. **口頭報告のみの事実（例：米国復活）は送信前チェックに入れ、未確認時の短縮文を用意しておく**
7. 分量は `wc -w`。チャット1投稿目は 150〜220 語で収まった（215語）
8. 発注に「9/2 書類提出」とだけあっても、元チケットを読むと 9/4 にも提出があった。**発注文の要点は元記録で必ず照合する**

## 追記 2026-09-27（2）：書類添付フォーム（メール窓口）用のB版の型（T-20260927-003）

- 窓口が「チャット」から「添付つきフォーム（メールのみ・本文に個人情報を書くなと注意書き）」に変わったら、**件名に健全性画面の違反名をそのまま入れる**（例 "Canada identity verification: passport and bank statement attached"）。担当者が違反と1対1で突き合わせられる
- 本文の順：新規の理由 → 違反名＋発生日 → 経緯（月名日付の箇条）→ **行き止まり画面の英文引用＋"so I am attaching"で添付理由につなぐ** → 添付を種類で列挙（ファイル名は書かない。明細は発行日＋within 180 days）→ **「同じ書類で別ストアが完了済み」を独立1文** → 問い3つ（完了可否と不足・期間・引き継ぎ＋新ケースID）
- 220語上限では、弱い根拠（再アクティブ化リンクのタグ）から削る。強い根拠（同じ書類で受理済み）を残す
- 版を追記するときは既存版を残し、冒頭に「上の版との違い・窓口・使い方」を3行で置く。送信前チェックは添付物の版確認（枠の取り違えが過去の却下原因）を1番に
- `wc -w` は箇条記号も1語に数える。上限ぎりぎりのときは明記する

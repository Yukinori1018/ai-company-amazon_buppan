# 打診メールを「公開版CSVだけ」から作り直す手順（2026-10-19 / T-20260930-001・91）

## 依頼パターン（再利用可）
過去の文面（agent_output の 83/84/86/87 など）が別デバイス（Mac）にしか無く、このコンテナから読めない。それでも「未下書きの社の打診メールをどんどん作れ」と言われたときの作り方。

## 手順
1. **データは checkout せず `git show <branch>:<path>` で読む**。deliverables の `10_連絡先_batch*_公開版.csv` を全部 scratchpad に書き出し、社名で行を引く小さいスクリプト（rows.py）で 正式社名・メール・窓口の種類・卸の案内・出典URL・月販・備考 を一覧にする
2. **チケットのログを社名で grep**。過去稿で確定した商品名（例：薄氷・濃厚タンパクゼリー・ブルーデオ）、敬称の切り替え（CAPIC＝貴協会）、逃げ道の紹介先（代理店・販売特約店・販売代理店）、🔴の注意点はここにある。これを拾わないと前の稿より質が落ちる
3. **固定文言の手本は deliverables 88 §8（スキル準拠の最新の打診文）**。73（送信済みの型）は agent_output にしか無い＝照合できないことを妥協点に書く
4. 窓口の A/B：取引・法人向けと明記（卸の案内・販売店募集）＝A＝PDF 添付の結び。代表・特商法・サポート・楽天店のアドレス＝B＝「ご検討いただけますと幸いです。」だけ
5. 生成は build スクリプト1本。検査を assert で入れる：禁止語（少量・5〜10点・希望小売価格・配信 ほか）／固定文言と署名がスキルの部分文字列／貴協会と御社が混ざらない／商品名が根拠文に重ならない／添付の文と window の一致／宛先の重複なし
6. 3稿：1稿＝構造、2稿＝「拝見」の重なり・数字（年数）・敬語抜けを潰す、3稿＝受け手として通し読み

## 今回見つけたこと
- **公式サイトにこのコンテナから届かない**（curl はプロキシ 403、WebFetch は名前解決できず）。事実は台帳とログの再利用だけになる。「公式で再確認していない」を notes に必ず書く
- 第2弾手本（83）の根拠2文目「…購入されている商品と拝見し」は、1文目の「公式サイトで拝見しました」と**「拝見」が二重になる**。「…購入されており、正規のお取引で仕入れたいと考えております。」にした
- 敬語の混用：「お分けされている」（謙譲＋尊敬）は誤り。「展開し」「製造し」など相手の行為の尊敬抜けも出やすい → 検査語に入れる
- 楽天の直営店しか読めていない社（サイモン）は「公式サイトで拝見」と書かない。「楽天市場の直営店で拝見」と出典どおりに書く
- 相手が問屋（松野屋）のときは逃げ道の「卸問屋様のご紹介」が成り立たない → 「製造元様」
- Amazon の品番が公式に無い社（ナニワ製作所）は、公式にある語（「分岐水栓の取扱店」→分岐水栓）を商品名にする

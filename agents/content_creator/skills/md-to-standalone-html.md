# スキル: 原稿(.md) → 単一自己完結HTML

社長の常設ルール「**分量のある資料はテキスト + HTML の併出力**」（`memory/owner_html_output_rule`）を満たすための道具と手順。
初出 2026-09-04（T-20260903-001 / リサーチ成果物のHTML化）。

- 実装: [md_to_standalone_html.py](md_to_standalone_html.py)
- 原則: **原稿(.md)が唯一の正。HTMLは機械変換物。** 手でHTMLを書かない。

## なぜ手書きしないか

過去（T-20260824-005）に、md と HTML を別々に触って**片側だけ直す事故**を起こしかけた。
1つの原稿から機械生成すれば、この事故は構造的に消える。原稿を直して再実行すれば HTML も必ず追随する。

## 使い方

```bash
python3 agents/content_creator/skills/md_to_standalone_html.py \
  <入力.md> <出力.html> \
  --title "ブラウザのタブに出すタイトル" \
  --kicker "T-XXXXXXXX-XXX" \
  --box "1. 結論=conclusion" \
  --box "わからなかったこと=alert" \
  --note "HTML版。内容の唯一の正は <原稿のパス> です。"
```

`--box "見出し=スタイル"` で、その h2 節を囲み枠にして強調する。スタイルは5種。

| スタイル | 見た目 | 使いどころ |
|---|---|---|
| `conclusion` | 青系の囲み | 冒頭の「結論」章 |
| `alert` | 赤系の囲み | 「わからなかったこと」「この資料の限界」など、**削ると資料の誠実さが消える章** |
| `danger` | 太い赤枠 | 「絶対にやってはいけない」章。印刷でも 2.5pt の黒枠で残る |
| `warn` | 琥珀系の囲み | 「根拠が弱い」「単一ソース」など、**信じすぎないでほしい章** |
| `checklist` | 青の太枠＋記入欄 | 印刷して手元で使うチェックリスト。**印刷時は独立ページになり**、番号付きリストの各項目に CSS で四角い記入欄が付く |

**`--box` の照合は「完全一致 → 前方一致」。部分一致はしない。** 部分一致にすると `結論` が「1-A. 一覧（先に結論）」まで巻き込む（T-20260904-004 で実際に踏んだ）。

`--cellmark "語=スタイル"` は**表セルの中だけ**でその語を色付きピルにする。`--cellmark "致命的=danger"` のように使うと、致命度列の該当行に赤い左帯が付き、印刷でも黒帯で残る。本文は触らないので原稿の改変にはならない。

| スタイル | 見た目 | 使いどころ |
|---|---|---|
| `danger` | 赤ベタ＋**行に赤帯**（印刷で黒帯） | 致命的・不一致。行ごと落としたいもの |
| `warn` | 琥珀 | 単一ソース・部分一致。信じすぎないでほしいもの |
| `ok` | 緑 | 検証済み・一致 |
| `muted` | 灰・**破線**（印刷でも破線で残る） | **未実施・未検証。「済んだもの」と別系統に見せる** |
| `info` | 青 | 手を打てば埋まる穴（到達不能・ログインすれば読める 等） |

**語の先頭に `^` を付けると「セルの文頭にある時だけ」1個目を置換する。** 判定語は他の列の文中にも出るので、素の部分一致では無関係な行を塗る（`不一致` が「購買者情報の不一致」に当たって別の行が赤くなる）。`--cellmark "^不一致=danger"` のように必ず先頭限定にすること。

`--reftable "出典一覧"` を付けると、その h2 節の表を出典一覧として扱う。**1列目の番号が行の id（`src-n`）になり、本文の `[#n]` がその行へのアンカーリンクになる。** 原稿に無い番号はリンクにしない（押しても動かない死んだリンクを作らないため）。見た目は span のときと同じで、**本文の文字は1字も増えない**。
`--reftable-widths "3em,27%,21%,15%,11%,23%"` で列幅を指定する（`<colgroup>` ＋ `table-layout:fixed`）。**指定しないと自動計算が URL 列に幅を持っていかれ、要旨の列が縦長の1文字帯になる。**

## 出力の仕様（社長の環境を前提に固定してある）

- 外部CSS/JS/フォント/画像を**一切読み込まない**。オフラインで開ける・メール添付でも壊れない
- 本文16px / 行間1.85 / 最大幅900px 中央寄せ、日本語システムフォントスタック
- 目次を h2・h3 から自動生成（アンカーリンク付き）
- **表は横スクロール可能なコンテナに入れる**。スマホで崩れない
- ライト/ダーク両対応（`prefers-color-scheme`）。背景色は明示指定
- 印刷用 `@media print`（背景を落とす・リンクは黒・見出し直後で改ページしない）
- `[#n]` は小さく薄いインライン注記、`[要確認 #n]` は注意色バッジ（**印刷時も黒枠で残る**）

## 対応している Markdown サブセット

h1 / h2 / h3、段落、表、箇条書き（2階層）、番号付きリスト、引用、水平線、`**強調**`、`` `コード` ``。
**リンクと画像は未対応。** 原稿に出てきたら実装を足すこと。素通りすると消える。

**h1 が複数ある原稿に対応済み**（2026-09-04）。1つ目が文書タイトル、2つ目以降は「第1部/第2部」の区切りとして本文と目次に出す。
**以前は2つ目以降を黙って捨てていた**（タイトル変数を上書きしていた）。同型の事故は「原稿の見出し数と HTML の見出し数を突合する」ことでしか見つからない。

## 生成後に必ずやる2つの検証（省略禁止）

自作コンバータは**静かに文章を落とす**。md では正常に見えるので、テキストだけ見ていると永久に気づかない。

1. **機械照合** — 原稿の全行・全セルが HTML に存在するか、逆に HTML に原稿外の文字列が混入していないかを突き合わせる。
   マーカー数（`[#n]` / `[要確認 #n]`）・見出し数・表数・表の行数も突合する。
2. **描画して目で見る** — headless Chrome でスクリーンショットを撮り、実際に読む。
   ```bash
   CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
   "$CH" --headless --disable-gpu --hide-scrollbars \
     --screenshot=out.png --window-size=1100,42000 "file://<絶対パス>"
   "$CH" --headless --disable-gpu --force-dark-mode --screenshot=dark.png ...  # ダーク
   "$CH" --headless --no-pdf-header-footer --print-to-pdf=print.pdf ...        # 印刷
   ```

### headless Chrome の罠

- **`--force-dark-mode` は巨大ページで固まることがある**（本件で2分タイムアウト）。ダークの確認は
  `@media (prefers-color-scheme: dark){...}` の中身を素の CSS として展開したコピーを作って撮るのが速くて確実。
  同じ手で `@media print` も展開でき、**印刷時の横溢れ・クリップを `scrollWidth` で数値確認できる**（PDF を目で見るより確か）。
- **macOS の bash には `timeout` が無い。** 付けたつもりで即エラー終了し「Chrome が落ちた」と誤診する。
- **レイアウト幅の下限は500px。** `--window-size=390,...` としても中身は500pxで組まれ、画像だけ390pxに切られる。
  これを見て「スマホで崩れている」と誤診しかけた。**横溢れの有無は画像でなく `scrollWidth` で判定する**
  （計測用のコピーに一時的にJSを仕込んで `--dump-dom` で読む。納品物にJSは入れない）。
- **`position:fixed` の要素は巨大ウィンドウの最下部に描かれる。** ページ高さを画素から測るときは右下を除外しないと、
  実際の3倍の高さを検出する。

## 実装で踏んだバグ（再発させない）

| 症状 | 原因 | 対処 |
|---|---|---|
| `**強調で始まる段落**` が丸ごと消える | 段落判定で `*` 始まりを一律除外していた | リスト記号は「**記号＋空白**」で判定する |
| 囲み枠の内側に区切り線が引かれる | `---` を `</section>` より先に出していた | `---` を見たら**先に節を閉じる** |
| 目次の入れ子が字下げされない | `.toc ul`(0,2,1) が `.toc-l2`(0,1,0) に勝つ | `.toc ul.toc-l2` で詳細度を上げる |
| 目次が「1. 1. 結論」と二重採番 | 見出し文言が既に番号を持つのに `<ol>` の採番も出た | 目次は `list-style:none` |

## 判断のメモ

- **出典URLは自動リンクにしていない。** 原稿にリンク記法が無いので `<a href>` を足すのは「原稿に無いものを HTML に出す」側に寄る。
  必要なら原稿側をリンク記法にしてもらってから再生成する（リンク記法自体も未実装なので実装が要る）。
- **`[#n]` の括弧は残す、`[要確認 #n]` の括弧はバッジ化に伴い落とす。** 前者は出典参照の記法そのもの、
  後者は「目立たせる」ことが目的なので枠で代替できる。
- **原稿の改行は `<br>` で保つ。** Markdown の仕様では段落内改行は詰まるが、
  原稿で行を分けてある箇所（「この結論は〜次第で変わります」等）は書き手が意図的に分離しており、詰めると埋もれる。
- **凡例（`[#n]` とは何かの説明）は勝手に足さない。** 原稿に無いものはHTMLにも無い。
  必要なら**原稿側に追記してもらってから**再生成する。

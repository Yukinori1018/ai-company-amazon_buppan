# 打診メール送信後の台帳反映（2026-10-15 / T-20260930-001）

送信の事実を受けて、メーカー連絡先台帳に反映したときの型。

- **宛先の正は送信に使った版のCSV**。今回は 66b（メール35）＋66c（8）＝43社が母集団、実際に送った41通は `71_打診文_skill適用_41通.csv`。43−41 の差で未送信2社がすぐ確定した（秘書の推定と一致）。73（39通）は件名検索の39件に対応する別版なので、母数の照合に混ぜない
- **台帳の照合はメールアドレスの部分一致**で行う。台帳のメール欄は「info@…（本社）」「a@…／b@…」のように注記つきなので、完全一致だと9社が外れる。台帳の「打診順」列は CSV の打診順と番号が違う（振り直し済み）ので照合キーに使わない。41/41 一意一致を確認してから書いた
- **接触ステータスのプルダウンは strict**（未接触／送信済／返信あり／見積りあり／成約／お断り）。「不達」の値は無い。不達は **未接触のまま・メモ列に記録**した（実際に相手へ届いていないので「未接触」が事実に合う）。選択肢を足すのはスキーマ変更なので、必要なら秘書判断を仰ぐ
- 列：接触ステータス=AO・接触日=AP・メモ=AQ（53列構成）。送信手段の専用列は無いのでメモに書く。書き込みは RAW
- 書き込み前に全行を JSON でバックアップ（agent_output/74_…json）
- 返信管理は agent_output に CSV（打診順・社名・宛先・台帳行・送信日・状態・返信日・返信要旨・次の一手・期限）。再送判断は送信の1週間後
- 連番の衝突に注意：秘書指定の「71_打診返信トラッカー」は 71 が使用済みだったので 75 にした

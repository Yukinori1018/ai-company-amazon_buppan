# 中間ファイルの個人名残存 → 削除判断を社長タスクに足す型（2026-10-05 / T-20260929-001）

## 何が起きたか
- サトルの名簿見積り用の中間ファイル（agent_output/T-20260929-001/12_calc の mono_rows.json・mono_cls.json 計約21MB、12_src の補助金採択一覧 txt/PDF 計約83MB）に「認定支援機関名」（個人名を含む）が残っていた。
- ハルオ13の「保存しない」に当たる。ただし削除は §4.1（不可逆な削除）なのでマリエ・カズヨは実行しない。社長判断に回した（A 削除／B 推奨：社名・法人番号・採択回・分類だけで作り直して元を削除／C 現状維持・期限 10/9）。

## 処理の手順（再利用可）
1. 対象ファイルが実在するか、サイズを `ls`/`du` で確認してから書く（存在確認なしで削除承認を取らない＝feedback_verify_where_owner_looks）。
2. チケット：現在地の先頭に1段落、ログに1行（`## 成果物` の直前に挿入）。チケットは waiting のまま、requires_approval=true のまま。
3. owner-tasks.md：更新N節を先頭に追加し、🔴 の表を全件で書き直す（増えた1件は既存の同チケット項目の直後に置き番号を振り直す）。ヘッダの「最終更新」も更新。
4. Notion：Description と本文「残る社長判断」の件数・項目を差し替え。漏れていた成果物リンク（今回は14）も同時に足し、fetch で読み返す。
5. 「agent_output＝リポ外・非公開」と社長向け文面に書く（公開リスクと誤解させない）。

## 気づき
- agent_output は .gitignore 対象＝公開はされないが、法務の「保存しない」は公開の有無と別軸。可視性と保存可否を混同しない（knowledge_deliverables_gitignore_allowlist_trap と同型の注意）。
- 推奨B の「作り直し」は削除前にやれば情報を失わない。承認後の手順は「作り直し→件数照合→元を削除」の順。

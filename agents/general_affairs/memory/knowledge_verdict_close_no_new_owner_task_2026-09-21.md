# 裁定で締めるときは「減らして終わる」— 派生作業を社長タスクに変換しない

作成: 2026-09-21 / マリエ / T-20260921-001 の done 締め同期

## 何が起きたか

更新60 で立てた社長判断3件（資金1,000万の壁／接触基準の二段構え／交渉道具の着手承認）に、社長が同日すべて裁定。
waiting → done へ動いたので、Notion・owner-tasks・カタログを締めた。

このとき裁定から**派生作業が2本**出た（融資前提の成長モデルの数値化／単価の下限の算出）。
どちらもハジメ（経理）が実行するもので、**社長の手は要らない**。
にもかかわらず、締めの文章を書いていると「①②を受けて次は…」と**新しいお願いの形に書きたくなる**。
書いた瞬間、🔴 が 4件 → 1件のはずが 4件 → 3件になり、**裁定していただいた意味が消える**。

## ルール

1. **裁定回の締めは「引き算だけ」で終える。** 派生作業が出ても、担当が社内なら ℹ️「自動で進みます」に置く。🔴 に上げない。
2. **回答済みの依頼は表から消す。** 残さない（[[knowledge_resolved_owner_ask_must_be_deleted]] と同じ型。今回は「解消」ではなく「回答済み」版）。
3. **黙って消さない。** セクション冒頭で「3件とも回答をいただいたので落とします」と1行明示する。
4. **件数は内訳つきで。** 「4件 → 1件（−3）」に加え、何が消えて何が据え置きかを1行ずつ。今回は「②③④ −1ずつ／①2年ロードマップは据え置き」。
5. **裁定の中身は3か所に確定事項として残す** — チケット本文・成果物（§0）・Notion の結果要約。表から消えるのは「お願い」だけで、決定は残る。

## Notion 本文の書き換え方（今回のやり方）

当初の論点表を消さず、見出しだけ差し替えた。

- `**社長判断（3件）**` → `**社長裁定（2026-09-21・確定）…**` ＋ 裁定3件の箇条書き
- 既存の論点テーブルの直前に `**当初提示した論点（裁定前・記録として残す）**` を挿入

`update_content` の old_str は**短い1行**（見出しのラベル）を狙うと確実に当たる。
テーブル本体（`<table>` の XML）を old_str にすると壊れやすいので触らない。

## カタログ側の締め

`暫定結果` は `【判断待ち】…waiting` のまま放置されやすい。done 化の締めで必ず `【確定】…done` に書き換え、
`社長レビュー` を `済` にする。今回は該当2行（01・02）とも更新。02 は裁定を §0 に追記したため `内容（要約）` も差し替えた。

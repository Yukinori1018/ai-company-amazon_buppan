# 古い結果要約は消さずに上へ「最新」枠を足す／Notion の \<strong\> 崩れの直し方

初出: 2026-09-12 / T-20260904-005（Notion カード冒頭の最新化＋カタログ6行追記）

## 1. 冒頭の古い要約は「消さずに上に枠を足す」
- 社長はカードの冒頭しか読まない。9/4 の「B推奨」「本日から13日」が冒頭に残っていると、現在の推奨（C版）と逆に読まれる。
- 手順：`update_content` で `## 結果要約\n**社長の番です…**` を old_str にし、new_str を
  「`## 最新（YYYY-MM-DD）` 枠 → 注記行（以下は当時の記録で現在の推奨ではない）→ `---` → 旧見出しを `## 結果要約（MM-DD 時点の記録）` に改名 → 旧本文」にする。
- 旧見出しに日付を足すのがポイント。枠を足すだけだと、下の「推奨」がまだ生きているように見える。
- **Description プロパティも同時に直す。** カンバンのカード表示は Description なので、本文だけ直すと一覧で古い主張（今回は「A案の追加費用はほぼ0円」＝ハジメ再試算で否定済み）が残る。

## 2. `\<strong\>` の表示崩れ
- Notion の表セルに HTML の `<strong>` が文字として入っていると、fetch 結果では `\<strong\>…\</strong\>` と見える。
- old_str にはこのバックスラッシュ付きの文字列をそのまま渡し、new_str は `**…**` にする。セル単位で4件直した（内容は変えていない）。

## 3. カタログ追記（同じチケットの版が進んだとき）
- 新しい成果物は行を足す。**同チケットの既存行の「暫定結果」も同じ文言に一括更新する**（今回は既存3行＋新規6行＝9行）。
- `git diff --stat` で「追加6・変更3」になっていることを確認（CSV を全体書き直ししても差分は該当行だけ）。
- 列数はヘッダーから取る（15列）。担当列は成果物ごとに違う（05=researcher／06=accounting／07=content_creator）。
- 同期結果：HTTP 200、675行×15列。

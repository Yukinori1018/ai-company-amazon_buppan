# 「1件の停止が全タスクを無効化する」ときの owner-tasks.md の書き方（2026-08-26 / T-20260826-004）

## 状況

Amazon 日本店（Satoy Select）が **2026-08-01 から停止**していたことが 8/26 に判明。
原因は日本店ではなく **CA（カナダ）ストアの本人確認未完了による連鎖停止**。
出品・仕入れ・FBA納品を含む事業の全工程が、このアカウントが開かないと1ミリも進まない状態。

## 採った書き方（次も踏襲する）

### 1. ブロッカーは「区分の中」ではなく「最上段」に置く

既存の `## 🚨 緊急・最優先` セクションは 2026-07 のログイン不能（解決済み）で埋まっていた。
そこに追記すると**解決済みの記録に埋もれる**。やったのは3つ。

1. **最終更新ヘッダの直下**（`## 🧭 事業方針アップデート` よりも上）に `## 🚨🚨 最優先（…）` を新設
2. 旧セクションの見出しを `## 🚨 緊急・最優先（2026-07 のログイン不能・解決済み／記録として残置）` に改名
   — 中身は消さない。**「🚨 が2つ並んでいて、どちらが生きているか分からない」状態を作らない**
3. 新セクション末尾に **ブロッカーの波及先を引用ブロックで明示**（下記2）

### 2. 波及先のタスクは「消さず・動かさず・注記する」

`T-20260823-001`（FBAテスト納品）/ `T-20260706-001`（実仕入れ）/ `T-20260814-001`（セラースプライト契約）は
アカウントが開くまで着手しても無駄になる可能性がある。だが **状態遷移はカズヨの責務**なので、
マリエは各項目に `⏸ **2026-08-26 注記**:` の1行を足すだけに留めた。

- 注記は**理由まで書く**。「停止中なので保留」ではなく「**仕入れても売る場所が開いていません**」「**課金が先に始まって使い道が来ない恐れ**」。
  理由があると社長が自分で優先順位を判断できる。
- **止まらないものは「止まらない」と書く**。`T-20260826-005`（納税情報の登録）は停止中でも画面が開けば実施可能なので
  `✅ **注記**: この設定画面は停止中でも開けば実施できます。予定どおりお進めください` と明記した。
  **⏸ だけを並べると「全部止まった」に読める。** 生きている道を1本示す。

### 3. 依頼は「作業」ではなく「時間の確保」に畳む

社長にお願いしたのは実質1つ＝**「30〜60分まとまって取れるタイミングのご連絡」**。
書類準備は同じエントリ内の入れ子にし、`- [ ]` チェックボックスは**1個だけ**にした（T-20260826-002 の教訓の再適用）。
チェックボックスの数＝社長が数える「増えたタスクの数」。

## 誤っていた前提の訂正のしかた

owner-tasks.md の旧🚨欄に **「米国店は停止中だが日本店営業に無関係（放置可）」** と書かれていた。これが今回の見落としの温床。

- **消さずに `~~取り消し線~~` ＋ `⚠️2026-08-26 訂正：この整理は誤りでした。`＋正しい事実＋参照チケットID** の形にした。
- 消すと「なぜ4週間気づけなかったのか」の痕跡が消える。**間違いの記録は再発防止の資産**。
- 教訓：**「無関係だから放置可」という判定は、後で最も高くつく。** 北米（US/CA/MX）は1つの統合アカウントで、
  片方が止まれば日本店も連鎖して止まる。**別ストアは「別アカウント」ではない。**

## 公開リポでの伏せ方（`knowledge_public_repo_pii_in_owner_tasks.md` の型を適用）

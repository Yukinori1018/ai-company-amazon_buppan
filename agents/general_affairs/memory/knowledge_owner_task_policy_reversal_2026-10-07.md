# 知見: 社長の方針転換で社長タスクを「置き換え＋追加」した回（2026-10-07 / T-20260929-001）

## 何が起きたか
- 10/5「少量の間は代行を使わない（月200〜300個まで自宅）」→ 10/7 社長「割高でも最初から代行で仕組み化したい」。
- 社長タスクは状態遷移ゼロ（waiting のまま）で中身だけ動いた：旧③を新③に**置き換え**、新④（FBA代行センター問い合わせ送信承認・§4.1）を**追加**、おりおん電話は「乗り換え先の確認」と**目的を書き直して継続**。

## 手順（再利用形）
1. ticket ログ末尾（カズヨ記録）を読む → owner-tasks.md 先頭に更新N節（全件表＋「✅置き換えたこと」表）を挿入、最終更新行を前置で更新。
2. Notion カード：Description（現在地＋残る社長判断）と本文「残る社長判断」箇条を update_content で差し替え。UpdatedAt も更新。カード ID は notion-search「T-xxxx タイトル」で1発。
3. チケット：updated_at とログ1行（どの番号をどう替えたか）。commit のみ（push しない）。

## 覚えておくこと
- 秘書の依頼文の番号（「既存①」）と owner-tasks 上の番号（③）はずれる。**依頼の番号ではなく中身で突き合わせる**。
- 継続タスクでも前提が変わったら「何のために継続するか」を書き添える（おりおん＝乗り換え先の確認）。書かないと方針転換後に不要と誤読される。
- 方針転換は「旧案を置き換え」と明記する。旧案を消すだけだと社長が「前に答えた件はどうなった」と迷う。

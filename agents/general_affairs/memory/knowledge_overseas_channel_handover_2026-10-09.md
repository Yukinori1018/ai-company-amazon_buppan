# 「別セッションで進める」と言われたら、チケット本文を引き継ぎ書にする（2026-10-09 / T-20261009-001）

社長指示：「他のプラットホームの開拓は別セッションで進める。引き継ぎしておいて。」
この型の依頼は、**チケットを起票して終わりではない**。受け取る側は**このセッションの文脈を一切持っていない**ので、
チケット本文がそのまま引き継ぎ書になっていないと走れない。

## 引き継ぎ書に必ず入れた9節（再利用できる型）

1. **なぜこの話が始まったか**（起点の事故・原因・教訓）
2. **現在の結論**（順位つき。**落選したものは落選理由を4点まで書く**）
3. **実勢の実測値**（出どころのファイル名と確認日つき。表をそのまま転記する）
4. **未取得で、取れれば結論が変わるもの**（🔴 を付け、**取り方**まで書く）
5. **社長の一手**（§4.1 の区分・所要日数・すでに満たしている要件）
6. **次セッションが最初にやること**（番号つきの手順＋まだ決まっていない戦略判断）
7. **やってはいけないこと**（前例つき。これが一番役に立つ）
8. **関連 memory**（パスを列挙）
9. **出どころ一覧**（原典のファイル名。「要約ではなくこれを読め」と書く）

## 落選したものは「落選理由」を書くと二度調べなくて済む

eBay・Qoo10・Temu・Amazon 海外ストアの4本は、**理由を1〜2行で残した**。
特に Amazon 海外ストアの「**構造上は開く（Yes）／やれるか（No）**」は、知らない人が必ずもう一度調べる論点。

## 件数の数え直しは「足し引き表＋機械での行数検算」をセットにする

更新91 で一度 8件を10件と書き間違えた前科がある（`knowledge_owner_task_delta_must_reread_ticket_2026-09-30` と同じ型）。
今回も **①足し引き表 → ②`awk` で表の行数を数える → ③見出しに書く** の順でやった。**順番を逆にしない。**

```
awk '/^### 🔴 いま社長にお願いしたいこと（12件）/{f=1;next} f&&/^### 🧮/{exit} f&&/^\| [①-⑫]/{c++} END{print c}' workspace/owner-tasks.md
```

## 「決定」と「実行の一手」を分けて数える

今回は **①現金化方針の決定** と **④Shopee 出店申請** を別の行にした。
方針が A（Shopee）でなければ ④ は不要になるので、**①が ④ のゲートである**ことを期限欄に書いた（「①の決定後」）。
**決定と実行を1行に畳むと、社長はどちらに答えればいいか分からなくなる。**

# T-20260920-005（2年ロードマップ v2）成果物6本の追加同期 — 2026-09-21

前回（同日朝）の `knowledge_roadmap_waiting_sync_2026-09-21.md` の続き。**waiting のまま中身だけ差し替える**型の同期。

## この回で学んだこと（再利用できる型）

### 1. カタログの取りこぼしは「依頼された本数」では気づけない

秘書からの依頼は「09〜14 の6本」だったが、**08（タカシ・同日早朝コミット accffaed）がカタログに入っていなかった**。
`grep -n '<ticket_id>' deliverables-catalog.csv` で既存行を数え、`ls deliverables/<ticket_id>/` と突き合わせたので拾えた。
**依頼された本数を信じず、毎回フォルダとCSVを突き合わせる。** 長期チケットは納品が小刻みに続くので取りこぼしが起きやすい
（同型の教訓＝`knowledge_catalog_gap_longrunning_tickets.md`）。今回は 08 込みで **14行**追記。

### 2. 版が入れ替わったら、新しい行を足すだけでは足りない

成果物が上書き・失効した回は、**既存行の側も直さないと社長が古い数字を読み続ける**。今回やったのは2つ：

- **既存の 005 全行（14行）の `暫定結果` を新しい1文へ揃えた。** 暫定結果はチケット単位の結論なので、
  版が動いたら全行が同時に古くなる。1行ずつ直すのではなく python で `r[0]==TID` に一括代入する。
- **03・07 の `内容（要約）` に失効注記を追記**（本文冒頭の失効表示と同じ趣旨を、一覧側にも書く）。
  社長はシートから開くので、**シートの要約に書いていない失効は無いのと同じ**。

### 3. Notion の「古い要約」は消さずに降格する

`## 結果要約` の見出し＋1行目を old_str にして丸ごと差し替え、旧要約は
`### 2026-09-21 早朝の記録（07 時点・⚠️数字は上記で置き換わりました）` へ降格。
**見出しに「失効」と書いてから残す**のが要点（残すだけだと、どちらが正か分からない）。
成果物リストは `成果物フォルダ：[...]` の1行を old_str にして**直後に新7本を差し込む**と、
既存行に触れずに並び替えができる（新しい順に並ぶので社長の入口が一番上に来る）。
個別の行は `— **社長はまずこれ**。6本を統合し` のような**短い一意な断片**を old_str にすれば安全に注記を足せる。

### 4. 「置き換えです」は明示する（社長指示）

秘書から「黙って置き換えないこと」と名指しで指定が来た。owner-tasks の節の冒頭に
**⚠️で「前回の3件は残しません。中身が入れ替わったので差し替えます」**を1行置いた。
件数は **1件 → 1件（±0）** で、増減ゼロでも「中身の差し替え」と内訳を書く
（`feedback_dont_repeat_settled_asks.md` / `knowledge_escalation_routing_as_one_task.md` と同じ運用）。
判断3件は**1つの社長タスクに束ねる**（社長の手は「すべて推奨で」の一言1回）。

### 5. 期限が動いたら frontmatter の `next_check_at` も直す

owner-tasks の期限を 9/23 → 9/24 にしたのに、チケット frontmatter が 9/23 のままだと
SessionStart フックが1日早く鳴る。**Notion に無いフィールドなので同期は不要**だが、ローカルは揃える。
status は動かさない（**状態遷移は秘書の責務**）。

> 冒頭の最終更新行の位置は**回によってずれる**（前回のメモは `lines[13]` が `---`、今回は 11 が最終更新行）。
> 行番号を決め打ちせず、`[n for n,l in enumerate(lines) if l.startswith('> **最終更新:')][0]` で取ること。
> 決め打ちして assert で落ちた（書き込み前に落ちたので実害なし。**書き込みは最後にまとめる**設計が効いた）。

# owner-tasks.md への「進捗の確定」記載と、公開リポジトリでの伏せ方（2026-08-26 / T-20260826-003）

## 何があったか

社長が e-Tax の**受信通知**を提示し、青色申告承認申請書の提出が確定した。カズヨからの発注文に
**「⚠️ リポジトリは公開設定です。利用者識別番号・受付番号・氏名・税務署名は書かないでください」**
という明示の制約が付いていた。

## 書いてよい／いけないの線引き（この形を今後の型にする）

| 区分 | 例 | 判断 |
|---|---|---|
| **書いてよい** | 「e-Tax の受信通知で **2026-08-21 提出**を確認」／「提出済み」 | **事実の成立**だけを書く。第三者が悪用できる識別子を含まない |
| **書かない** | 利用者識別番号・受付番号・氏名・税務署名・口座番号・住所・電話番号 | **本人特定情報**（CLAUDE.md §6「除外し続けるもの」） |

- ポイントは「**証拠の中身を写さず、証拠を見た結果だけを書く**」こと。進捗管理に必要なのは後者だけで、前者は1文字も要らない。
- 迷いを減らすため、**伏せた事実そのものも1行添える**（例：「本リポジトリは公開設定のため、利用者識別番号・受付番号等は記載しません」）。後から読む人が「書き忘れ」と誤解して埋めにくる事故を防げる。
- 既存の owner-tasks.md には T-20260820-002 の項に**税務署名がすでに書かれている**（`提出先=雪谷税務署`）。今回は自分が足した行ではないので**勝手に消さず**、カズヨへ「既存の記載に本人特定に近い情報がある」と報告するに留めた。**削除はカズヨ／社長の判断**（勝手な改変は非破壊原則に反する）。

## 「確認3件」型のタスクを部分解消するときの書き方

T-20260826-002 の「確認だけお願いしたい3件」のうち1件だけが解消した。**行を消さない**。

- 解消した行は `~~取り消し線~~` にして「✅ 解消。〜で確認」と**根拠を残す**。消すと「もう聞かれない」ことは分かるが「**答えたのに反映されていないのでは**」という不安が残る。
- 見出しは「**3件 → 1件解消し、残り2件です**」と**増減が一目で分かる形**に書き換える。
- 残った件が別チケットに分離したら、**分離先のIDと次回お声がけ日を同じ行に書く**（T-20260826-003 / 8/27）。「どこへ行ったか分からないタスク」を作らない。
- **社長タスクの純増をヘッダで明言する**（今回は「純増0件＝独立チケットになっただけ」）。チケットが1枚増えると社長には「やることが増えた」と見えるので、増えていないなら増えていないと書く。

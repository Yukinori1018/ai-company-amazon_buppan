# 引き継ぎノート（handover.md）の更新手順と、今回の作り替え

2026-09-21 / T-20260909-004 の締めとして実施（秘書カズヨの発注）

## 何をしたか

`workspace/handover.md` を **368行の積層ログ → 337行の構造化ノート**に作り替えた。
テンプレートは `.claude/commands/handover.md` の章立てにそのまま従う（勝手に章を足さない）。

## 手順（次回もこの順で）

1. `.claude/commands/handover.md` を**先に**読む。章立てとセキュリティ要件がここにしかない
2. チケット全件スキャンは手で数えない。frontmatter を python でパースして表を生成する
   （`ticket_id` / `title` / `assignee` / `next_check_at` の4列。ファイル名ではなく frontmatter が正）
3. `workspace/owner-tasks.md` の**最上段の更新番号**を読む。🔴 の件数はここが唯一の正
4. `git log --since=<前回更新日>` で「このセッションでやったこと」を復元する。チケットのログより commit の方が漏れない
5. 書き終えたら **secret grep**（`secret|token=|password|旅券|利用者識別|口座番号|電話番号パターン|ntn_|sk-`）を必ず通す

## 今回の構造（維持する形）

- 最終更新 → **このセッションでやったこと** → 進行中の論点 → 社長について → 事業の現状 → チケット状況（全件表）→ 環境メモ → 推奨初動 → **過去の経緯（必要なときだけ読む）**
- 旧版は「🆕 日付ごとの小節」を上へ上へ積む形で、**古い節と新しい節が同じ強さで並び、どれが生きているか読めなくなっていた**。
  積層をやめ、**生きている情報を上に・死んだ経緯は末尾の「過去の経緯」へ**畳んだ。
- done 84枚は ID のみの `<details>` に畳む。全件表を要求されても、**読めない表を作ったら要件を満たしていない**。

## 教訓

- **handover は「ログ」ではなく「次のセッションが最初に読む1枚」。** 追記し続けると、更新するたびに価値が下がる。
- 「進行中の論点」は**社長判断待ち**と**社内の宿題**を分けて書く。混ぜると社長が自分の番かどうか判断できない。
- 滞留チケット（`next_check_at` が過ぎたまま動いていない doing）は、件数だけでなく
  **「doing にあることを進んでいると読み替えない」という一文**を添える。前科があるため。

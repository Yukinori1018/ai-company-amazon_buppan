> 記録したら秘書カズヨ経由で「Notion 同期 N 件失敗、リコンサイル要」と社長へ報告する。

## 2026-08-23 / T-20260817-005 / Notion MCP が未接続で同期不可

- **事象**: サブエージェント（マリエ）セッションから Notion カンバンへ同期しようとしたが、**`notion-*` の MCP ツールが1つも存在しなかった**。
  `ToolSearch` を `+notion` / `create pages database` の2通りで引いても 0 件。
- **原因**: このリポジトリに **`.mcp.json` が存在しない**（あるのは `.mcp.json.example` のみ）。
  `~/.claude.json` 側も `mcpServers: []` / `enabledMcpjsonServers: []` で、**このマシンのこのプロジェクトには Notion MCP が接続されていない**。
  → トークンは `.mcp.json` に書く設計（CLAUDE.md §7.1）なので、example のままではホスト型 MCP が起動しない。
- **影響**: T-20260817-005 の Notion カード更新（UpdatedAt=2026-08-23、本文「結果要約」の最新化）が**未実施**。Status は doing のままなので**列の移動は不要**＝ドリフトは UpdatedAt と本文のみで軽微。
- **教訓（再発防止）**:
  1. **Notion 同期を発注される前に、まず MCP の存在確認をする。** ツールが無い環境では「同期しました」と言えない。無いなら**着手前にその旨を宣言**してから残りの作業を進める。
  2. マリエ側の agent 定義が `tools` を絞らず全継承にしているのは Notion MCP を確実に使うため。ただし**継承しても、そもそも接続されていなければ意味がない**。全継承＝使える保証ではない。
  3. 復旧手順は `.mcp.json.example` → `.mcp.json` へコピーし `NOTION_API_KEY` / `NOTION_DATABASE_ID` を埋める（**社長の手作業。トークンは機密**）。その後 `/sync-notion` で一括リコンサイルすれば、この日の取りこぼしも自動で吸収される。
- **申し送り**: カズヨへ「Notion 同期は未実施。MCP 接続のあるセッションで `/sync-notion` を1回流してください」と引き渡し済み。

# 知見: 社長タスクが「不要化」と「前提の追加」で入れ替わった回（2026-10-04 / T-20260920-003・T-20260929-001）

## この回の形

状態遷移はゼロ（920-003 は doing のまま、929-001 は waiting のまま）。**動いたのは社長タスクの中身だけ**。しかも動き方が4種類あった。

| 動き方 | 例 | 書き方 |
|---|---|---|
| **不要化**（会社側が自力で取った） | 和平フレイズの納品書／領収書 → カズヨが SD 会員ページ（購入履歴→出荷明細）から適格請求書を取得済み | 「届いたら共有」を消すだけでなく **「社長が箱を開けて撮る必要はありません」**まで書く。消すだけでは社長が待ち続ける |
| **意思表示＝承認とみなす** | 「FBA代行のほうに問い合わせをして、いろいろ聞いてみたい」→ 送信承認は出たものとして扱う | **「承認が出た」と断定せず「出たものとして扱います」**と書く。§4.1 の承認は社長の言葉が根拠なので、解釈であることを残す |
| **承認済みだが未実行→担当者へ移管** | 重複12行の削除（10/01「OK」） | 🔴 から外し、**「カズヨのタスクとして残します（社長のお手は不要）」**と明記。承認済みを 🔴 に残すと「まだ答えていない」と誤読される |
| **前提が1つ足りないだけ** | FBA代行3社の問い合わせフォームに電話番号が必須。氏名・メールは判明済み | **ブロッカーを1点に名指しする**。「フォームを埋めてください」ではなく「電話番号だけ無いので、それだけください」 |

## 覚えておくこと

- **不要化は「解消」より強い。** 解消＝社長がやった、不要化＝やらなくてよくなった。表で区別して書く（今回は ✅解消したこと 表に「なぜ解消したか」列を置いた）。
- **承認が出ても実行できないことがある。** 送信承認は取れたが電話番号が無い。**承認と実行可能性は別の軸**。承認を取っただけで 🔴 を減らすと、翌日「まだ送っていないのか」と言われる。
- **前提が崩れた期限は失効と書く。** 929-001 の「期限 10/2（SD出荷前）」は SD が 10/02 に出荷済みなので意味を失った。新しい期限（10/6＝納品目標日）に置き換え、**旧期限が失効した理由を併記**する。
- **撤回は撤回と書く。** 原価モデルの誤り（固定費821円のうち200円は誤差幅、FBA 415円と保管/納品/資材 206円は鍋＝標準区分・大型の実測を全商品に適用）で「卸サイト経路は成立しない」が崩れた。**「見直し中」ではなく「撤回します」**と書く。見直し中だと前の結論が生き残る。

## Notion 書き込みで踏んだ落とし穴（2件・どちらも自分のミス）

1. **メールアドレスを文中に置くと Notion が勝手に mailto: リンクにする。**しかも**行頭からアドレスまでを丸ごとリンクテキストに巻き込む**（`[3社の問い合わせフォームの必須項目で、氏名とメール（satoyselect@gmail.com](mailto:同じ文字列)`）。
   → **プロパティ値・本文でアドレスを書くときは、文中に素で置かない**。今回は「氏名と業務用メールアドレス」と言い換えて回避した。
2. **漢字の Unicode エスケープを間違えると気づかずに壊れる。** `短缩`（短缩＝簡体字）／`ヘージ`（ヘージ）／`卵`（卵）を書いてしまい、Notion 側に「短缩5問」「SD 会員ヘージ」「卵価格」「卵サイト経路」が入った。
   → **日本語はエスケープせず literal で書く**。縮=縮／ページ=ページ／卸=卸。**書き込んだら必ず `notion-fetch` で読み返す**（今回これで2件とも捕まえた）。

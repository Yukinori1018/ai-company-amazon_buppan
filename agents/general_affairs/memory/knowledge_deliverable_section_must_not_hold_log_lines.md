# 成果物節に「入っているはず」を信じない — ログに紛れた1本は社長に届かない

初出：2026-09-27 / T-20260927-001（多レーン・ロードマップの締め作業）

## 何が起きたか

社長提出の本体である **07（HTML 1枚）だけが、`## 成果物` 節の外**にありました。
ヒデアキが 07 を納品したとき、成果物の行をログ節の途中に書き足していたためです。

結果はこうなります。

- `scripts/notion/build_deliverable_blocks.py` は `^## 成果物` から次の `## ` までしか読まない
  → **07 は変換対象に入らない**
- Notion カード本文の成果物欄に 07 が出ない
  → **社長が最初に見るべき1枚が、社長の見る場所に存在しない**
- チケット本文（ローカル）を見ると 07 の行自体はあるので、**目視では「ある」と誤認する**

## 教訓（次回やること）

1. **同期の前に、成果物節の中身をファイル実体と突き合わせる。**
   `ls deliverables/<ticket_id>/` の件数と、節内の行数（フォルダ行を除く）が合うか数える。
   合わなければ節を直してから同期する。順序を逆にすると欠けたまま Notion に載る。
2. **変換器の出力を必ず目で読む。** `--check-links` が 200 を返すのは
   「**書いてあるリンクが生きている**」ことの確認でしかなく、
   「**書くべきリンクが全部書いてある**」ことの確認にはならない。ここを混同しない。
3. 成果物節は**リンク形式で書く**（`[\`file\`](../../output/deliverables/<tid>/file)`）。
   素のパス文字列は変換器が URL 化しないので、Notion 上でクリックできない飾りになる。
   今回、最初に素のパスで整えてしまい、変換して初めて気づいた。**先に既存チケットの形を1つ見る**こと。
4. 複数担当が順番に納品するチケット（サトル→ハルオ→タケシ⇄マサル→ヒデアキ）では、
   **最後に入った成果物が節から漏れやすい**。締めの時点で最新の1本を名指しで確認する。

## ついでの型

社長提出物が1本ある案件では、成果物節の先頭に
「**社長はまず 07 をご覧ください**」の1行と、07 を最上段に置く。
14本を作成順に並べると、社長は「どれを開けばいいのか」から始めることになる。

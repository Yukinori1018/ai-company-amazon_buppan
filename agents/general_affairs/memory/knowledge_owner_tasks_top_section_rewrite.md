# 知見: owner-tasks.md 最上段🚨🚨の書き換え手順（T-20260826-004 / 2026-08-31）

## この回の依頼

T-20260826-004（日本店停止）の 8/31 の進展を、Notion カード本文と `workspace/owner-tasks.md` 最上段へ反映。Status は waiting のまま。

## 手順（再利用可能）

1. チケット末尾の日付付きセクションを全文読む。`grep -n "^## "` だけでは `###` 見出しの追記を取りこぼす。**必ず末尾を `sed -n` で直接読む**。
2. `grep -n "^## \|^---$" workspace/owner-tasks.md` で最上段🚨🚨セクションの行範囲を確定（今回は 16〜108、次の `---` が終端）。
3. 新セクションを scratchpad に書き、Python で行範囲を差し替える。461行超のファイルを Edit の文字列一致で触るのは非効率かつ危険。
4. 冒頭 `> **最終更新: ...` 行は**先頭に新しい要約を足し、旧文を「／前: 」でぶら下げる**追記形式。過去の履歴は消さない。
5. Notion は `notion-update-page` の `insert_content` + `position:{"type":"end"}` で末尾に節を追加。あわせて `Description` と `date:UpdatedAt:start` を更新。**Status を触らない指示のときは properties に Status を同値で入れておくと事故が分かりやすい**。
6. ローカル `.md` の frontmatter `updated_at` も同日に揃える（Notion 側だけ更新すると次回リコンサイルで差分に見える）。

## 内容の畳み方

- **決着した A/B/C は消さずに「決着済み・ご返事不要」と明記して畳む。** 消すと社長が「まだ答えていない」と思い続ける。
- 過去の経緯は `<details>` に条件付きで残す。今回は 8/26〜8/30 を5行に圧縮した。全文転記は「一文を短く」の社長フィードバックに反する。
- 社長タスクが1つに絞れたときは、見出しに「社長がやることは1つだけ：〜」と書いてしまう。表や本文を読ませない。

## 公開リポジトリの扱い

- 記載可：「パスポート欄に水道料金請求書を誤ってアップロードした」という**事実関係**。
- 記載不可：住所・電話番号・旅券番号・口座番号。今回は電話を「（+81）」、メールは業務用アドレスのみに留めた。

## 持ち帰り

- **画面のファイル名から中身は判断できない。** 8/30 時点で「提出物はスクリーンショットだった」と推測で書いていたが、真因は別書類の誤アップロードだった。社長への1問で取れた。**提出物の中身は本人にしか分からない**ので、文面を書く前に確認する。

## 続報: 2026-09-01（T-20260826-004）— 「状態は動かないが、社長タスクの中身が入れ替わる」回の書き方

### 何が違ったか

前回（8/31）は「待っていてください」で終わる回だった。今回は **Status=waiting のまま・チケットも動かないのに、社長がやることが丸ごと差し替わった**。
この型は**一番誤解されやすい**。社長から見ると Notion のカードは同じ列に居座ったままなので、「何も変わっていない」と読み飛ばされる。

### 採った書き方（この型は今後も踏襲する）

1. **見出しに「入れ替わった」ことを書く。** 「— カナダから回答が来ました。**待ちは終わり、社長の番です**」。
   日付更新だけの見出し（「2026-09-01 更新」）にすると、中身が変わったことが見出しから読み取れない。
2. **解消／新規を表で並べる。** 「解消したタスク」表に、消えたお願いを**行として残す**（消さない）。
   `✅ 解消。もう届きません` のように**なぜ解消したか**まで書く。消すと社長は「まだ待つのかな」と思い続ける。
3. **増減の結論を先に置く。** 「社長タスクは増えていません。**中身が入れ替わっただけです**（待ち2件解消 → 新規2件）」。
   件数が同じでも、内訳が変わったなら「変わった」と明言する。
4. **ブロッカーを1つに名指しする。** 「身分証明書は準備済みなので、**止まっているのは明細書1点だけ**」。
   必要書類が4枠あっても、社長が動かすのは1つ。**枠の数ではなく、社長の手数を書く**。
5. **不可逆な操作の順番は、独立した見出しで警告する。** 今回の
   「『本人確認コールに進む』を押すと追加の書類をアップロードできなくなる」は表の脚注に埋めない。
   **やり直しがきかない手順は、埋めると必ず踏まれる。**

### 「こちらでは解決できない」論点の書き方

日本語対応の可否が通知に書かれていなかった。ここで**「引き続き確認します」と書かない**。
その場で担当者につながる方式である以上、**事前に通訳を手配する余地が構造的に無い**——
つまり**当日の運用でしか分からず、こちらに打つ手が無い**。
**打つ手が無いことは、打つ手が無いと書く。**「確認します」と書くと、社長は解決を待ってしまい、その分だけ着手が遅れる。
ただし**ご返事は不要です**を添えて、これが宿題ではないことを明示する。

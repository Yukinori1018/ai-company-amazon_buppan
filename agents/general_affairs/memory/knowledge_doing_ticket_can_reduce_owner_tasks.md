# doing のまま社長タスクが減ることがある（T-20260920-003 / 2026-09-20）

## 何があったか

スーパーデリバリー利用開始チケットは **status=doing のまま**だが、同期対象の社長タスクは **2件減った**。

- 社長の一手（パスワード設定）が完了 → 該当の 🔴 行を `[x]` ＋ 取り消し線へ
- 社長の回答で完結した論点（店舗情報の保存承認・一括申請の打ち方 A/B・SD への照会可否）は、
  そもそも owner-tasks に独立行が無くても「社長側の残作業なし」として更新セクションに明記する

## 学び

1. **チケットの状態（doing/waiting）と社長タスクの増減は別の軸。**
   doing のままでも「社長の一手が終わった」なら owner-tasks は減らす。
   `knowledge_owner_task_vs_ticket_state` の逆パターン（doing なのに減る）を今回追加で確認。
2. **更新番号はファイルから取る。** 発注文に「更新55」と書いてあっても信用せず、
   `grep -oE '更新[0-9]+' workspace/owner-tasks.md | grep -oE '[0-9]+' | sort -n | tail -1` で最大値+1。
   今回は発注文と一致したが、過去に食い違いがあった前提で毎回引く。
3. **完了した 🔴 行は消さない。** 取り消し線＋✅＋「何が完了したか」を残す。
   社長が「あの依頼どうなった」と探したとき、消えていると追えない。

## 手順の再利用形（進展の反映セット・1 turn で閉じる）

1. チケット本文末尾の節を一次情報として読む（ログではなく節。ログは時系列で古い判断が混ざる）
2. Notion カード：`update_content` で本文冒頭に「## 最新（日付）」を**追加**（既存の結果要約は残す）＋
   `## 成果物` を localhost:17325 のリンクに差し替え → `update_properties` で Description / UpdatedAt
3. owner-tasks.md：ヘッダー行の先頭に新番号を差し込み、直後に新セクション、🔴 行を完了形に
4. 成果物カタログ：CSV 追記（**実物ヘッダーは15列**。スキル記載の13列は古い）→ `sync_catalog_to_sheet.py`
5. `notion-fetch` で読み返して検証 → git commit

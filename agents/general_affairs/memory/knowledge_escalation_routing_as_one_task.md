# エスカレーション論点は「振り分け1件」に畳む（2026-09-04 / T-20260903-001）

## 状況

サトルのリサーチ納品（メーカー直取引の新規取引条件）で、`research/escalation.md` に
**社長判断が要る論点3件**＋**裁定不能2件**が積まれた状態で完了処理が回ってきた。

カズヨからの発注に明示的な指示があった。

> これは「法務ハルオに回すか」「プランナータケシに回すか」の**振り分け判断**であり、
> 社長が自分で調べる必要はありません。owner-tasks には「振り分け判断1件」として
> **まとめて1行で載せてください（3行に増やさない）**。

## 型（次も踏襲する）

1. **論点の件数と、社長タスクの件数は別物。** 3論点あっても、社長がすることが
   「どちらの担当に回すか決める」だけなら、それは**タスク1件**。
   3件を3行に割ると「社長タスク3件増」に見え、実際より重く読まれる。
2. **論点は表に畳み、推奨を先に埋めておく。** `| # | 論点 | 私の推奨 |` の3列。
   推奨が全行埋まっていれば「その振り分けで進めて」の一言で閉じられる。
   丸投げの質問を投げないという CLAUDE.md §4.3 の実装がこれ。
3. **チェックボックスは1個。** レビュー（読むだけ）と振り分け判断を**同じエントリ**に入れ、
   `- [ ]` を増やさない。既存の型（`owner-tasks-summary-ownership.md` 2026-08-26 節）と一致。
4. **裁定不能（D分類）はタスクに数えない。** ただし消さない。
   `ℹ️` 行として「社長にお答えいただく類のものではないので、タスクには数えていません」と
   明記したうえで残す。**数えないことと、隠すことは違う。**
5. **冒頭の「最終更新」行に増減の結論を先に置く。** 今回は「社長タスクは +1件です。
   ……お願いは実質1本」。数字（120件収集・出典108件）は社長の負荷とは無関係なので、
   増減を言い切った後にしか書かない。

## 補足：カタログCSVの実列は13列（スキル文書は12列で古い）

`agents/general_affairs/skills/deliverables-catalog.md` §2 の列設計には **`暫定結果` が抜けている**。
実ファイルのヘッダーは13列。

```
チケットID,ToDo/タスク名,成果物タイトル,内容（要約）,暫定結果,種別,GitHubリンク,リポジトリ相対パス,担当,形式,作成日,社長レビュー,備考
```

**スキル文書ではなく実ファイルのヘッダーを正とすること。** 追記後は必ず
`csv.reader` で全行の列数が13で揃っているかを機械検査してから同期する（目視は必ず落とす）。

また、成果物がフォルダ単位（`research/` のような作業ログ一式）の場合、
**パス末尾を `/` で終える行を1行立てる**先例がある（T-20260705-002 の78行目）。
ファイルを1本ずつ並べず、1行に集約してよい。

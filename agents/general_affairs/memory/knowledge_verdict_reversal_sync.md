# 知見: 「無い」という判定が覆った回を、鏡（Notion／owner-tasks）にどう載せるか

初出: 2026-09-04 / T-20260826-004（日本店アカウント停止）

## 何が起きたか

- 2026-09-02〜09-04、カズヨは Amazon の申し立て画面を DOM まで読み込み、
  **「Submit appeal の href が提出フォームの無いページを指しており、提出導線は存在しない」**と立証した。
  href という一次証拠まで取っていたので、判定の確度は高かった。
- その立証を根拠に、法務ハルオが `seller-reactivation@amazon.ca` 宛の連絡文（成果物07）を納品した。
- **同じ日、社長が「Amazon のメールの指示に沿って対応せよ」と指示。**
  指示どおりに辿ると、**別ノードに機能する提出フォームが実在した**（米国ストアのページ → 左パネルのアクション → カナダ向けフォーム）。
- 結果：判定が覆り、07 は送信不要になり、社長タスクは「保存する」→「確認のために送信」の**2クリック**に縮小した。

## 学び①：**「無い」の立証は、探した範囲の中でしか成立しない**

href を読むのは正しい調査だった。誤っていたのは**探索範囲**のほう。

- 同じ機能が**別ストア（米国／カナダ）の別ノード**で生きていた
- **Amazon のメールが指すリンク先が空でも、そのページの左パネルのアクションが本体**だった

→ 「存在しない」と鏡に書く前に、**別ストアのアクションカードを全部開いたか**を確認する。
→ **一次情報（相手自身の指示）どおりに素直に辿る**手順を、必ず一度は通す。こちらの推論で近道すると、この種の別ノードは落ちる。

## 学び②：訂正は書く。ただし**冒頭ではなく本文に置く**

owner-tasks.md の最上段は反省文ではなく指示書。

- 第一段落＝**社長がやること**（今回は「2つのボタンをこの順に押す」だけ）
- 訂正（「9/2〜9/4 の判定を訂正しています」）は①節の中に、事実として1行

**謝罪を先頭に置くと、社長は指示に辿り着くまでに一段読まされる。**訂正は消さない、が、順番は後ろ。

## 学び③：不使用になった成果物には**「送らないでください」を独立エントリで立てる**

「不要になりました」だけでは止まらない。社長が既に07のメール文面を開いていれば送ってしまう。

- ⚠️ **注意（新規）：07 のメールは送らないでください**
- **損まで書く**：提出口が見つかった今これを送ると、同じ件でケースが2本立ち、重複対応として審査が止まる

「解消」欄と「注意」欄は別物。**解消は過去形の報告、注意は未来形の禁止。**片方だけでは事故が残る。

## 学び④：不使用の成果物も**カタログには載せる**

`deliverables/` に在るものが真実で、成果物カタログはその片方向ミラー。
使わなかったから載せない、は鏡を曇らせる。**「暫定結果」列に `【不使用】` と理由を書けば足りる。**

T-20260826-004 では 06・07 の2本が不使用になったが、どちらも
「なぜ作り、なぜ使わなかったか」が判断の記録として価値を持つ。**破棄しない・隠さない・載せる。**

## 学び⑤：同期の前に、**カード本文の末尾を読んで抜けている回を探す**

今回、カズヨの発注は「9/4 の①〜④を集約」だった。
だが Notion カードの最終節は 9/3 で、**9/4 午前の日次チェック（3点とも変化なし・href 立証）と07の納品が未同期**だった。
発注文どおりに①〜④だけ足すと、カードだけを読む人には話が飛ぶ。

→ **発注文の範囲＝カードの完全性ではない。**`notion-fetch` した本文の末尾を必ず読み、
抜けている回があれば §0 として1段落で補う。長く書かない。1段落で足りる。

# 社長タスクは「保留」と「完了」を書き分ける（2026-09-21 / 更新57）

## きっかけ

社長が Amazon 本人確認書類の提出（9/22）とカナダの催促送信（9/21）について「**日本のストアと繋がっている可能性もあるので、数日様子を見ます**」と判断。
カズヨから「🔴 から外して保留扱いに書き換えて。**削除ではなく保留と分かる書き方で**」と明示指定があった。

## 学び：🔴 から外す理由は3種類あり、書き分けが必須

| 外れ方 | 表記 | 書くべきこと |
|---|---|---|
| ✅ 完了 | 「完了」 | 何をもって完了か（例：A1〜F2 に全回答＋追加2点） |
| ⏸ 保留（社長判断） | 「様子見（社長判断・日付）」 | **①社長の言葉を原文で引く ②期限は消えていないと明記 ③再開の目安日と誰が再確認するか** |
| 🔁 調査中（社内へ戻した） | 「いま社長のお手はかかりません」 | 誰がどのチケットで処理中か |

**⏸ を ✅ と同じ「削除」で処理すると、期限が静かに消える。** 保留は「期限つきで棚に載せ直す」操作なので、再開の目安日（今回は 9/25・カズヨが再確認）を必ず書く。owner-tasks.md だけでなく**チケット本文のログ**と **Notion カード本文**の3箇所に同じ1行を入れる（3箇所とも入れないと、次に読んだ人が別の結論を出す）。

## 手順メモ（再利用可）

1. `workspace/owner-tasks.md` は**追記ログ型・新しい順**。`---` の直後（行14付近）に `## 🆕 <日付> 更新N` ブロックを挿入し、ファイル冒頭の `> **最終更新:` 行の先頭に同じ要旨を差し込む（既存の `／更新N-1〔…〕` の前に）。
2. 日本語を含む置換は Bash ヒアドキュメント内の `python3 - <<` だと `SyntaxError: Non-UTF-8` になる。**スクリプトを別ファイルに書き出し、本文も別テキストファイルに出してから読み込む**（`encoding="utf-8"` 明示）。
3. Notion カードの **page_id を過去ログから推測しない**。今回 CA カードの id を owner-tasks.md の記述から流用しかけて誤っていた（正＝`3d5b0a4044fa81f183e9d4bba719c1e5`）。必ず `notion-query-data-sources` で `TicketID` から引く。
4. 本文追記は `insert_content` + `position:{"type":"end"}`、UpdatedAt は `update_properties` で `"date:UpdatedAt:start"`。Status を動かさない更新はこの2手だけで足りる。

## 件数の数え方（今回 3件 → 0件）

**推測で書かない。** 直前の更新ブロック（更新56）が列挙している 🔴 の実体と、各チケットの現況を突き合わせて確定させた。
なお T-20260920-002（Keepa の継続/解約・gBizINFO 申請ほか）は**近日 🔴 に載る見込みだが、本日時点では社長に出していない**ため 0件に含めない。この「載る見込み」行を表に足しておくと、翌日 🔴 が跳ね上がったときに驚かせずに済む。

# 「もうやらなくていい」を伝える回の書き方（社長タスクの**取り下げ**）

記録: マリエ / 2026-09-02 / T-20260826-004

## この回の型（過去3回と違うところ）

owner-tasks.md 最上段の改稿は同チケットで4回目だが、今回だけ型が違った。

| 回 | 型 |
|---|---|
| 8/31（更新①相当） | 「待っていてください」で終わる回 |
| 9/1 | 待ちが終わり、社長タスクが**入れ替わる**回 |
| 9/2 深夜（更新③） | タスクが**減る**回（2件解消・1件に集約） |
| **9/2 午前（更新④）** | **タスクが「もう実行できない」＝取り下げになる回** |

**取り下げは「解消」と違う。** 解消は「済んだ」、取り下げは「**やっても無駄だから、やめてください**」。
今回、社長は書類の添付を**何度も試されていた**。しかも通らないのは Amazon 側でフェーズが閉じていたからで、
社長の操作は一切悪くない。ここを曖昧に書くと、社長は「自分のやり方が悪いのでは」と試し続ける。

### 採った書き方

1. **見出しに「できません」を置く。**「書類の提出は**もうできません**。残るは 9/3（木）の面談1本だけです」。
   「更新④」だけの見出しでは、何が変わったか読み取れない。
2. **表の区分を「✅ 解消」ではなく「✅ 解消・お願いを取り下げます」にする。**
   「解消」だけだと済んだのか諦めたのか分からない。
3. **本文に「もうお試しにならないでください」と直接書く。** 遠回しにしない。
   併せて **「通らないのは社長の操作のせいではありません」** を必ず添える。これが無いと、
   取り下げが「あなたの操作が下手だから諦めた」と読めてしまう。
4. **原因が自分（会社側）のミスなら、隠さず先に書く。**
   今回はカズヨが 4MB 制限に収めるため元画像を「縮小」し、顔写真ページの実効解像度を
   約280万画素まで落としたことが却下原因。**「縮小ではなく切り出しで容量を落とすべきだった」**まで書く。
   カズヨからの発注文にも「この点は隠さず書いてください」と明示があった。**言い訳の圧縮より、原因の明示。**
5. **「なぜ通らないのか」は観測事実の表で示す。** 「4つの枠すべてがエラー／社長が触っていない枠も同様／
   アップロードの通信自体が発生していない」。**社長が自分で検証しなくても納得できる証拠**を並べる。
   「調べたら閉じていました」だけだと、もう一度試したくなる。

## 不可逆な一手の記録の残し方

今回の根本原因は **9/1 深夜に「本人確認の電話に進みます」を押した**こと。
ボタンには「次のページに移動すると追加の書類をアップロードできなくなります」と明記されていた。

- **一度押すと戻れない導線は、押す前に「押したら何が閉じるか」をチケットに書き出しておく。**
  今回チケットには警告文が引用されていた（9/1 の記載）のに、その後の判断で参照されなかった。
  **書いてあるだけでは効かない。**「この操作は不可逆」という見出しで独立させておくべきだった。
- 事後にできるのは、**閉じた機能を「画面上は残っているが死んでいる」と明記すること**だけ。
  入力欄が見えている限り、人は何度でも試す。

## 巨大化した owner-tasks.md の触り方（更新）

854行・169KB。`Edit` の文字列一致では触らない。手順は既存メモ `knowledge_owner_tasks_top_section_rewrite.md` のとおりだが、追加の注意が2つ。

- **`<details>` の入れ子が深くなる。** 今回で4階層目。開始/終了タグ数を
  `grep -c "<details"` と `grep -c "</details>"` で必ず突合する（今回 5/5 で一致を確認）。

## 他エージェントの「commit 済みです」を信用しない

法務ハルオの完了報告に **「deliverables に直納し commit 済みです」** とあったが、
`git status` では 06 の2ファイルが**未追跡**だった。05 の2ファイルも**カタログ未登録**だった。

- **`deliverables/` に触った turn では、必ず `git status --short` と
  カタログCSVの行数を突合する。** 報告文は証拠ではない。
- 今回は 05・06 の4行をカタログへ追記し、`sync_catalog_to_sheet.py` で同期（169行×13列・HTTP 200）、
  そのうえで commit した。**成果物の消失は agent_output だけでなく「未 commit のまま worktree が消える」でも起きる。**

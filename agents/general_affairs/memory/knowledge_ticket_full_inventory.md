# メモリ：チケット全数棚卸しの手順（マリエ）

初回: 2026-08-26 / T-20260826-002（社長向け「Amazon物販マスターToDoリスト」の事実台帳づくり）

## 何を頼まれたか

`workspace/tickets/` 全103枚（done 61 / doing 11 / waiting 22 / todo 9）を1枚ずつ読み、
「ticket_id × 状態 × タイトル × 実質何が終わったか × ライフサイクル段階 × 成果物の有無」の台帳にする。
成果物 = `workspace/output/agent_output/T-20260826-002/01_ticket-inventory.md`。

## 再利用できる手順（3コマンドで9割終わる）

103枚を1枚ずつ Read すると読み込みだけで破綻する。**frontmatter + 要件冒頭だけを一括抽出**して読む。

```bash
# ① frontmatter の主要キー ＋「## 要件」冒頭を全件ダンプ
for f in workspace/tickets/<state>/*.md; do
  echo "##### $(basename $f)"
  awk '/^---$/{n++; if(n==2) exit} n==1' "$f" \
    | grep -E '^(ticket_id|id|title|assignee|owner|status|requires_approval|next_check_at):'
  sed -n '/^## 要件/,/^## /p' "$f" | head -8
done

# ②「## 要件」が無いチケット（旧テンプレ）は本文頭を取る
for f in workspace/tickets/*/*.md; do
  grep -q '^## 要件' "$f" || { echo "##### $(basename $f)";
    awk 'BEGIN{n=0} /^---$/{n++; next} n>=2' "$f" | grep -v '^$' | head -10; }
done

# ③ 進捗の実態は「現在地」→無ければ「完了報告」を1〜2行
sed -n '/^## 現在地/,/^## /p' "$f" | grep -v '^## ' | grep -v '^$' | head -2
```

**見出しは統一されていない。** `## 要件` / `## 概要` / `## イシュー` / `## 依頼（社長・日付）` /
`## 背景` が混在する。②のフォールバックが無いと 30枚前後を読み落とす。

## 今回わかった構造的な事実（次に活きるもの）

1. **依頼された件数（doing 10）と実測（doing 11）がずれていた。** 件数は必ず `ls | wc -l` で取り直す。
2. **done 61枚のうち 37枚は `現在地` も `完了報告` も空。** done の根拠が本文に残っていない。
   → 「done にした理由」を本文に1行残す運用が無いと、後から棚卸しできない。
3. **done/ にありながら `status:` が doing/waiting のままのチケットが 10枚。**
   フォルダ位置と frontmatter の二重管理。Notion 同期はフォルダ位置を正とするので、
   `status:` 行は放っておくと永久にずれ続ける（`ticket-frontmatter-contract.md` と同じ構造の事故）。
   検知: `grep -l -E '^status: (doing|waiting|todo)' workspace/tickets/done/*.md`
4. **成果物の有無は `ls workspace/output/deliverables/` で実測する。** チケット本文の
   「## 成果物」記載はフォルダ実在を保証しない（旧ルール時代のリポ外パス記載が残っている）。

## 分類してみて見えたこと（社長への報告に効いた）

103枚を「登録→リサーチ→仕入れ→出品→FBA→販売→顧客対応」の9段階に割り振ると、
**64枚（62%）が「基盤・会社運営」と「リサーチ・ツール」に固まり、出品以降は5枚（4.9%）、顧客対応は0枚**だった。
チケットの分布は、そのまま**事業がどこで止まっているかの地図**になる。
「たくさんやっている」ことと「前に進んでいる」ことは別だと、件数で示せる。

> 棚卸しの出力は「一覧」で終わらせない。**段階別の件数表**まで作ると、
> 社長が1秒で「現物ラインが1周も回っていない」と分かる。これが今回いちばん効いた。

## やらなかったこと（意図的）

- チケットファイルは1文字も変更していない（依頼の厳守事項）。`status:` のずれ10枚も**報告のみ**。
- 成果物は `agent_output/` に置いた。これは親チケットの最終納品物（ToDoリスト本体）の**入力素材**であり、
  それ自体が納品物ではないため。deliverables 直納・カタログ追記は親チケットの完了時に行う。

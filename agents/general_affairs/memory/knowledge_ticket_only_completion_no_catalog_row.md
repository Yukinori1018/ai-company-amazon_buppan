## この回の型

チケットが done になったが、**`deliverables/` に新規ファイルが1つも出ていない**回。
成果は「Cloudflare 側の設定」と「チケット本文の記録」だけ。ドキュメント成果物が無い完了は珍しい。

## カタログはどうするか（確定）

**行を足さない。** 根拠は `skills/deliverables-catalog.md` §1「真実 = `deliverables/<ticket_id>/` 配下の**成果物ファイル**」。
ファイルが無い＝真実が無いので、ミラーであるカタログに行を作ると **カタログが真実より多くなる**（GitHubリンク・
相対パスが空欄の行が生まれ、リンク切れの見た目になる）。

- 同スキルの「チケットの状態が動いたら `暫定結果` 列も最新化する」は、**既存行がある場合の話**。
  今回は CSV に該当チケットの行が 0 件（`grep -c` で確認）なので発火しない。
- カズヨからの発注文にも「勝手に行を足さないこと」と明示があった。判断は一致。
- **確認の型**: `ls workspace/output/deliverables/ | grep <日付>` と
  `grep -c "<ticket_id>" .../deliverables-catalog.csv` の2つを打ってから「更新不要」と報告する。
  「無いはずです」で済ませない。

## owner-tasks.md — 「削除して」と言われても消さない

カズヨの発注文は「該当の社長タスク行を**削除**」だったが、**行は消さず `- [ ]` → 表の `✅ 解消` 行として残した**。
根拠は既存メモ `knowledge_owner_task_withdrawal.md` / `knowledge_owner_tasks_top_section_rewrite.md`：
**消すと社長は「まだ答えていないのでは」と思い続ける**。社長が承認済みの体裁でもある。

→ **発注文の「削除」は「社長タスク欄から降ろす」の意**と読み替え、
  見出しを `🆕` から `✅` に変え、「解消／新規」表で**純減 −1**を明示する形に書き換えた。報告で申し送る。

## 完了回で必ず書く3点（今回の型）

1. **社長タスクの増減を先に**（「1件減り、増えたものはありません」）
2. **訂正があれば隠さず書く** — 今回は初報の原因推定（`.html` 旧URLの名残）が実データと違った。
   カズヨが本人で訂正済みだったので、そのまま Notion・owner-tasks の両方に載せた。
3. **「今後もゼロにならない」系の注意は独立見出しで** — GSC の未登録4件は分類が移るだけで残り続ける。
   これを埋めると、社長が「消えない」を理由にサイトを再度いじる。**放置してよいものは、放置してよいと書く。**

## Notion 更新の実務メモ

- `RequiresApproval` を外すのは `"__NO__"`（`false` ではない）。今回も踏襲。
- Status/RequiresApproval/Description/UpdatedAt は `update_properties`、完了要約は
  `insert_content` + `position:{"type":"end"}` の2コールに分ける。1コールにまとめようとしない。
- 旧「📋 社長タスクまとめ」カード（`36db0a40-...`）はアーカイブ済み。**触らない**（発注文でも念押しがあった）。

# 解消した社長依頼は「削除」する（消し忘れが社長タスクを水増しする）

作成: 2026-09-21 / マリエ / T-20260921-001 の完了同期で学んだこと

## 何が起きたか

T-20260921-001 は起票時（更新59）に「**Kindle Cloud Reader へのログイン（ID/PW・2FA）**」を 🔴 に1件立てました。
ところが実際には**社長の Chrome に既にログイン済み**で、お手をわずらわせずに全336ページを読み終えられました。

つまり **🔴 に立てた依頼が、社長が何もしないうちに消滅した**わけです。
この型（着手前に立てた依頼が、着手してみたら不要だったと分かる）は、放っておくと **owner-tasks.md に死んだ依頼が残り続け、社長タスクの件数が実態より多く見える**。

## ルール

1. **解消した依頼は、件数から引いて本文からも消す。** 「※解消済み」と注記を添えて残さない。社長は 🔴 の表を上から読むので、**表に載っている＝まだやることがある**と読まれる。
2. **取り下げた事実は、最新セクションの冒頭1行で明示する。** 今回は「更新59 でお願いしていた Kindle ログインは**取り下げます**」と書いた。黙って消すと、社長が「あれはどうなった」と探すことになる。
3. **件数の増減は必ず明記する。** 今回は「🔴 2件 → 4件（Kindle ログイン −1、社長判断 +3）」。**差し引きだけ書くと何が消えて何が増えたか分からない。**
4. 過去セクション（更新59 など）は**履歴なので書き換えない**。owner-tasks.md は追記型で、最新セクションが現在地。

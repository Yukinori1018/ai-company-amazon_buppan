# 成果物カタログの仕分け基準（何を載せ、何を載せないか）

2026-09-09 / T-20260909-003 タスクC / マリエ

## 背景

手動追記の運用が破綻し、実体695ファイルに対しカタログ記載が226行だった。
IT タカシが `scripts/catalog/build_catalog.py` で機械生成に切り替えた結果、
736行・うち要記入510件が一度に出てきた。**全部埋めるのは目的ではない。**
社長が探すのは「読む資料」と「使うデータ」であって、成果物を作るための道具ではない。

## 載せないもの（97ファイル・build_catalog.py の EXCLUDE_DIR_RE / EXCLUDE_FILE_RE）

| 分類 | 件数 | 判断の理由 |
|---|---:|---|
| テストコード（`tests/` 配下・`test_*.py`・`06_tests_*.py`） | 35 | 実装の正しさの担保であって、社長が読むものではない |
| サイトの部品（`assets/` 配下の CSS/SVG/JS/画像） | 30 | 社長が探すのは「ページ」であってCSSファイルではない |
| 旧版まるごとバックアップ（`site_backup_YYYYMMDD/`） | 9 | 現行版が別にある。並べると新旧どちらが正か分からなくなる |
| 内部ビルド用スクリプト（`_build_*.py` 等・先頭 `_`） | 9 | 先頭アンダースコアは「内部用」の意思表示 |
| テスト用サンプルデータ（`sample_data/`） | 5 | フィクスチャ |
| 自己診断（`*selftest*`） | 2 | 同上 |
| 中間スナップショット・進捗（`*_snapshot.json`・`progress.json`） | 2 | 途中経過であって成果ではない |
| デプロイキャッシュ（`.wrangler/`） | 2 | 生成物 |
| その他（`robots.txt`・`sitemap.xml`・`requirements.txt`） | 3 | サイト/実行環境の付属物 |

**逆に、載せる側に倒したもの**（迷ったら載せる。社長が探せない損失のほうが大きい）:

- 番号つきの解析スクリプト（`07_apply_v15.py` `42_困り度_スコアと検証.py` 等）
  → チケットの作業の順序そのもの。何をどの順でやったかの記録として価値がある
- パイプラインのソースモジュール（`pipeline/*.py` `code/calc/*.py`）
  → 作ったもの本体。ただし `__init__.py` だけは中身が無いので落とす
- `research/` 配下の question / coverage / notes / verification
  → レポートの根拠。社長が「なぜそう言えるのか」を辿る入口

## 除外の入れ方（手でCSVから消してはいけない）

CSV はファイルシステムから機械生成される。手で行を消しても次の生成で必ず戻る。
除外は `scripts/catalog/build_catalog.py` の

- `EXCLUDE_DIR_RE` … ディレクトリ名で落とす
- `EXCLUDE_FILE_RE` … ファイル名で落とす
- `EXCLUDE_NAMES` … 完全一致で落とす

に入れる。入れたら `--dry-run` で「見つからない行 N 件」の一覧を必ず読み、
**人が書いた要約を持つ行が消えていないか**を確認する（引き継ぎ件数が減っていないかで分かる）。

## 要約の書き方

- 1〜2文。太字を使わない。前置きを書かない（社長から「表現がくどい」と繰り返し指摘）。
- 推測で埋めない。ファイル自身の H1・docstring・CSVヘッダ・JSONキーから起こす。
  412件を機械抽出 → 人が短文化、で1周できた。全ファイルを開く必要はない。
- `.md` と `.html` が対になっている資料は、`.md` に中身を書き、`.html` は
  「（ブラウザ版）」とだけ書けば十分。社長は片方しか開かない。
- 担当は文書のバイライン（「担当: サトル」「法務ハルオ」等）から取る。無ければ空のまま。

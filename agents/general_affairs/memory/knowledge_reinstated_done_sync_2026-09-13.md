# 「差し戻し→再 done」＋子2枚の周回進行を1回で締めた手順（2026-09-13 / T-20260912-002〜005・commit 5e46337 時点）

## 何が起きたか

-003 は done → doing（サトル③追加調査）→ **再 done** と3回動いた。同時に -005 はマサル1周目納品（収束No・doing 継続）、-004 はタケシ2周目着手（doing 継続）。
状態遷移は -003 の1件だけだが、**Status が動かない doing 継続のカードも「周回が進んだ」事実を結果要約に足さないと、カンバンは前の周回で止まって見える**。

## 再利用できる型（再 done 版の締めセット）

| # | 対象 | 中身 |
|---|---|---|
| 1 | Notion プロパティ | -003 だけ Status=done。**Description も再 done 用に書き直す**（「追加調査中」のままだと一覧で doing に見える）。UpdatedAt は既に 9/13 なら同値で再送して問題なし |
| 2 | Notion 本文 | 結果要約は**追記のみ**：done 行 → 差し戻し行 → **再 done 行** の順で履歴が読める。doing 継続の -004/-005/-002 も「周回が進んだ」行を1本ずつ足す。成果物節は「未納品」行を**同じ行の中で**「納品済み＋配信URL」に置換（行頭のバックティック付きファイル名は残る＝偽リンク化しない） |
| 3 | カタログ | 新規行の追記（-003 04 の2行・-005 の5行）に加え、**既存行の `暫定結果` も更新**（-003 の7行を「①②③とも納品」に、-004 の3行を「マサル1周目 収束No → タケシ2周目」に）。`skills/deliverables-catalog.md` §2 の「状態が動いたらこの列も最新化」はこの意味 |
| 4 | owner-tasks.md | 増減ゼロでも「最終更新」更新⑲＋ ℹ️ 節の子3枚の状態表記の2点 |
| 5 | チケットログ | 4枚とも「最後のマリエ Notion 行」の直後に1行。**-005 はサトルが並列編集中**（現在地に `### サトル（S-a/S-c/S-d）` 節が未コミットで乗っていた）→ cacheinfo 方式で HEAD＋自分の1行だけを index に載せた |

## 落とし穴・学び

- **CSV を全行書き戻しても diff は汚れなかった**（`git diff --numstat` が 17/10 ＝ 追記7＋更新10 ぴったり）。`csv.writer(lineterminator='\r\n')`＋BOM を先頭に付け直す方式で、既存の quoting と一致する。`"a"` 追記でなくてもよいが、**書いた直後に numstat で意図した行数か必ず見る**。
- Notion の `update_content` は old_str を「行の末尾側の一意な文字列」に絞ると、行頭にある自動リンク化されやすい部分（`` `04_….md` `` など）に触れずに済む。今回3ヶ所とも一発で通った。
- `txt` 成果物の `種別` は既存に「データ」があるのでそれを使う（種別の語彙は80種超で揺れている。新語を足さず既存から選ぶ）。
- 「社長の入力は不要」の回でも、-002（親）の結果要約に子3枚の現在地を1行で足しておくと、社長が親カードだけ開いても周回の位置が分かる。

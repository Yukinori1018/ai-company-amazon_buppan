# 資産台帳の維持はマリエの定常責務（2026-09-21 追加）

対象ファイル: `workspace/asset-ledger.md`
連動フック: `.claude/hooks/asset-claim-guard.py`（PreToolUse: Write|Edit|MultiEdit）

## なぜあるか

2026-09-21、カズヨが書籍のチェックリストを当社に当てはめる際、`done/` と `deliverables/` を検索せずに「独自ドメインなし・HPなし・会社概要なし」と社長へ報告した（実際は全部保有）。**同型の事故が3回目**で、memory への記録では止まらなかったため機構化された。

**台帳の網羅性＝事故防止の性能。** 台帳に無いものは素通りする。だから棚卸しは「あるものを全部書く」が正解で、絞り込みではない。

## 定常責務（責務表の5件目）

| トリガー | やること |
|---|---|
| 契約・解約・取得・失効・提出・開設が起きた turn | `ASSET:` 行を追加/修正し、人が読む部の2表も直す |
| 新しい成果物データ・社内ツールが `deliverables/` に出た turn | 保有データ／社内ツールの節に1行足す（カタログ同期とセットで） |

## 書式の運用ルール（守らないとフックが壊れる）

`ASSET: <キーワード> | <状態> | <根拠>`

1. **保有側の状態は `保有` `契約中` `登録済` `提出済` `通過済` のいずれかで始める。** フックは `cols[1].startswith()` しか見ない。**「同上」と書くと保有と認識されない**（初版で3行やらかした）。
2. **未保有側は `未契約` `未保有` `未取得` `未開設` `不要` で始める。** 未保有をブロック対象にすると、正しい記述まで止まる。
3. **根拠のないものは載せない。** チケットID／成果物パス／memory 名のどれかを必ず入れる。裏が取れなかったものは末尾の「要確認」表へ。
4. **PUBLIC リポジトリ。** 口座番号・APIキー・パスワード・住所・電話番号・卸値の実値は書かない。書くのは「保有しているという事実」と「根拠の所在」だけ。

## 🔴 キーワードの部分文字列衝突を必ず検査する

フックは `re.finditer(re.escape(key), text)` の**部分文字列一致**。したがって
**保有キーワードが未保有キーワードの中に含まれていると、正しい「持っていない」が誤ブロックされる。**

実際に踏んだ2件（2026-09-21）:
- `屋号`（保有）⊂ `屋号付き銀行口座`（未開設）→ 「屋号付き銀行口座を持っていません」が exit=2 になった → 保有側を **`Satoy Select`** に付け替えて解消
- `Keepa`（契約中）⊂ `Keepa Pro`（未契約）→ 同様 → 保有側を **`Keepa API`** に付け替えて解消

**行を足したら必ずこの検査を回す:**

```bash
cd "$(git rev-parse --show-toplevel)" && python3 - <<'EOF'
HELD=("保有","契約中","登録済","提出済","通過済")
held=[];notheld=[]
for line in open("workspace/asset-ledger.md",encoding="utf-8"):
    if not line.startswith("ASSET:"): continue
    c=[x.strip() for x in line[6:].split("|")]
    (held if c[1].startswith(HELD) else notheld).append(c[0])
print("held",len(held),"notheld",len(notheld))
print("誤ブロック衝突:",[(h,n) for h in held for n in notheld if h in n] or "なし")
EOF
```

## 動作テストの型

```bash
CLAUDE_PROJECT_DIR=$PWD
echo '{"tool_name":"Write","tool_input":{"file_path":"/tmp/t.md","content":"当社は<キーワード>を持っていません"}}' \
  | .claude/hooks/asset-claim-guard.py; echo $?
```
保有側は `2`、未保有側は `0`。**両方向を回すこと。** 片側だけだと 1 の衝突に気づけない。

## キーワードの粒度の勘どころ

- 短すぎる語（`HP` `メール` `データ` `リスト`）は無関係な文脈を巻き込む。`HP` は社長が実際に使う語なので残したが、`メール`→`事業用メール`、`データ`→`Keepa raw JSON` のように**修飾つきで登録する**。
- 逆に長すぎると当たらない。社長やカズヨが**実際に口にする言い回し**をキーワードにする（`ホームページ` と `HP` の両方を置いたのはこのため）。
- 同義語は別行で複数登録してよい（`ホームページ`／`HP`／`コーポレートサイト`）。状態文は「同上」ではなく毎行フルで書く。

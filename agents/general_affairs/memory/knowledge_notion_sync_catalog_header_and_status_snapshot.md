# カタログCSVは今は15列／git status のスナップショットを信じない

初出: 2026-09-12 / T-20260912-001（新規カード＋カタログ19行）・T-20260904-005（カード最新化）

## 1. カタログCSVの列数は 15（13ではない）
`knowledge_deliverables_catalog_sync.md` には「13列固定」とあるが、実物のヘッダーは15列
（`公開状態` と `ローカルリンク` が増えている）。**列数はメモではなく毎回ヘッダー行から取る**。
追記後は `csv.reader` で全行がヘッダーと同じ列数か assert する（今回 669行・全行15列で確認）。
ローカルリンク列は `=HYPERLINK("http://localhost:17325/<id>/<percent-encoded>","<file>")`。

## 2. 依頼時の git status は古い
依頼文面の gitStatus では T-20260904-005 の 06/07 が未追跡に見えたが、着手時点では全部コミット済みだった。
「未コミットは登録しない」ルールの判定は **`git log -1 -- <path>` をファイルごとに引いて**行う。

## 3. 同期の手順（今回そのまま効いた順）
1. rows モードで TicketID を引く（SQL モードの利用上限を避ける）→ カード有無を確定
2. data source を fetch してラベル選択肢を全列挙 → 未登録なら**全件＋新規**で `ALTER COLUMN ... SET`
   （今回 `first-cycle` を追加。50→51件を返り値で数えて確認）
3. 配信サーバ 200 確認 → 成果物リンクを percent-encode
4. 既存カードの成果物節は `update_content` で行単位に差し込む（件数表記・Finder 行・注記行を old_str に使う。長いURLを old_str にしない）
5. 新しい節は注記行の後ろに差し込み、冒頭の古い「結果要約」は消さない（非破壊）
6. 最後に `notion-fetch` で読み返す

## 判断

- Notion は TicketID が同期キー。**重複 ID のカードは作らない**（「在籍ゼロ確認」の段で既存カードが1枚返った＝ゼロではない）
- ID の振り直しと、サトルへの出力先の指示替えは秘書の責務。私は動かさない
- 親・-006 の結果要約、owner-tasks、handover、ログは、どれも「調査 T-20260915-001」を書く＝NETSEA 版を指してしまう。二度手間と誤リンクを避けるため**全部保留**にして即差し戻した。急ぐ理由は、サトルの README 書き込みで NETSEA 版の索引が上書きされうること

## 再利用できる手順

1. 同期の最初に `ls workspace/tickets/*/ | grep <ticket_id>` で**件数**を数える（1でなければ止まる）
2. Notion は rows モードで TicketID を完全一致検索（`string_is`）。親・関連カードも同じ呼び出しに OR で入れると1回で済む
3. 成果物フォルダの既存ファイルと README を見て、並列担当の出力先と衝突しないか確かめる
4. 次の空き番号を `grep -rl "T-YYYYMMDD-00[2-9]" workspace/tickets/` で確かめ、推奨案として添える

# カタログに載せる行と、載せてはいけないリンク（.gitignore された成果物の扱い）

初出: 2026-09-04 / T-20260904-004（成果物20件のカタログ追記）

## 何が起きたか

T-20260904-004 の deliverables フォルダには**チケット専用の `.gitignore`** が置かれていた。

```
A_初回仕入れ候補_卸レーン.csv
A_サプライヤー別サマリ.csv
_tariffs_cache.json
__pycache__/
```

理由は「本リポは PUBLIC で30分ごとに自動 push される。候補 CSV には NETSEA のサプライヤー社名が入る」。
つまり **deliverables に実在するのに Git には無いファイル**が3件ある状態だった。

## 学び — カタログは「実在するか」ではなく「追跡されているか」で行を作る

カタログの `GitHubリンク` 列は `blob/<branch>/<相対パス>` を機械的に組み立てるので、
**untracked なファイルの行を作ると 404 のリンクが1行増える**。社長がクリックして開けない行は、
一覧の価値をそのまま削る（`feedback_maximize_pool_not_ranking` と同じ性質の劣化）。

**手順に組み込むこと（今後の定型）**

1. 追記の前に必ず `git ls-files <deliverables/ticket_id>/` を打ち、**追跡済みファイルの集合**を取る
2. 追跡外のファイルは**単独の行にしない**。代わりに、同じチケットの追跡済みファイル（実測ログ・README など）の
   **備考欄に「◯◯は .gitignore 対象。理由と、社長の Finder からは見える旨」を書く**
3. チケット直下に `.gitignore` があったら**必ず開く**。フォルダを `ls` しただけでは気づけない

今回は `A_実測ログ.md`（追跡済み）の備考へ CSV2件の所在を逃がし、404 リンクをゼロにした。

## あわせて確認したこと

- CSV ヘッダーは13列（`暫定結果` が4列目と5列目の間に入っている）。スキル `deliverables-catalog.md` §2 の
  列設計は**12列のまま更新されていない**（`暫定結果` が抜けている）。T-20260601-005 で追加された列。
  スキル本文を信じて12列で書くと列ズレを起こす。**書く前にヘッダー行を実物で確認すること。**
- 追記後の検算は `csv.reader` で「全行の列数が13の1種類だけか」を見るのが速い。

## 同期は2手で終わる

```bash
# ① マスターCSVへ追記（RFC4180・UTF-8・BOMは先頭のみなので追記モードで壊れない）
# ② シートへ全置換ミラー
python3 scripts/catalog/sync_catalog_to_sheet.py
```

②は冪等（全クリア→全行書き込み）なので、①を間違えたら直して②を打ち直せば復旧する。
①の前に CSV をスクラッチへ `cp` してバックアップを取っておくと巻き戻しが1手で済む。

# チケット末尾の `## 成果物` 節（T-20260909-004 / 2026-09-09）

社長指摘：「チケットに成果物のリンク（ローカルフォルダ→ファイルのリンク）がない。チケットの最後に "成果物" を設け、リンクを貼る運用に是正願います。」

## 確定した形式（秘書決定・再検討不要）

- 節名 `## 成果物`、位置は本文の**末尾**（`## ログ` の後）。1チケットに1つ。
- 3点セット：①フォルダ相対リンク ②主要ファイル相対リンク（ファイル名＋1行説明）③社長の閲覧口 `~/Documents/AI Company Outputs/Amazon物販事業/<tid>/`（テキスト表記・リンクにしない）
- 相対パスの基準は `workspace/tickets/<status>/` → `../../output/deliverables/<tid>/...`
- 成果物なしは `（なし — 理由）`。空欄・省略は不可。
- 規範は `agents/secretary/skills/ticket-management.md` §`## 成果物` 節の運用、記入例は `workspace/tickets/_template.md` の末尾、CLAUDE.md §6 にも1行。

## 一括処理でハマったこと（次に同種の全件棚卸しをするとき用）

1. **既存節はほとんどが本文の途中にあった**（138枚中、末尾にあるのは2枚だけ・途中にあるのは56枚）。
   末尾へ移すには「切り取って末尾に足す」しかない。切り取った行は**必ず全部拾い直す**。
   拾い方＝(a) `deliverables/<tid>/<file>` を指す行 → その注記を新しいリンク行の説明文として再利用、
   (b) それ以外の行（他チケットの成果物・Googleシート URL・散文）→ `補足（従前の記載）:` に原文のまま残す。
2. **ファイル名の切り出しを正規表現の文字クラスでやると壊れる。**
   `11_条件付き候補.csv（333社）` の全角括弧まで名前に食い込んだ。
   正しくは「`deliverables/<tid>/` の直後の残り文字列が、実在するエントリ名で始まるか」を
   `os.listdir` の結果と突き合わせて最長一致で判定する。**名前の形を推測しない。**
3. **一度でも本文に名前が出たファイルは、必ずリンク行に残す**（`mentioned` 集合）。
   件数上限で切ると、注記なしの行が黙って消える＝社長指示の「既存記述を削らない」に反する。
   最終的に**上限そのものを撤廃**した（56件のチケットも全件列挙）。出力が決定的になる副次効果が大きい。
4. **スクリプトは冪等にする。** 自分が生成した `📁` 行・Finder 行・`補足（従前の記載）:` 行・
   ` - [`名前`](リンク) — 説明` 行を再入力として食べられるようにし、2回流して差分ゼロを確認してから commit。
   説明文からサイズ `（9.1KB）` を剥がす処理を入れたら1周目と2周目で出力が変わった。**剥がさない。**
5. **検証は3本セットで回す**：(a) frontmatter が HEAD と1バイトも変わっていないか
   （キー名・値ともに機械が読む契約）、(b) 相対リンクが `os.path.exists` で解決するか、
   (c) 削除行のうち追加行に現れないものが0件か（＝内容の消失ゼロ）。
6. **両方向チェック**：チケット→成果物だけでなく、`deliverables/` 配下のフォルダが
   どれか1枚のチケットからリンクされているかも突合する。今回は73フォルダすべてリンク済みにした。

## 事故りかけたこと（重要）

**並行セッションの `git add -A` に作業中のファイルを巻き取られた。**
作業中に IT タカシのセッションが T-20260909-003 を commit し、私の1回目の出力ごと HEAD に入った。
その後 `git checkout -- workspace/tickets` で「元に戻した」つもりが、HEAD 側に自分の出力が
入っていたため二重処理になり、`補足（従前の記載）` に自分の生成行が入れ子で積もった。
→ **リポ全体を書き換える一括処理では、(1) スクリプトを冪等にする (2) 途中の `git checkout --` を
「HEAD＝作業前」と信じない (3) 完了後に必ず全件の形を再検証する。**

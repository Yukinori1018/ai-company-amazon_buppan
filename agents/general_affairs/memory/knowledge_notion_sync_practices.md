
## 2026-09-09 Labels は Notion 側の既存選択肢しか通らない

T-20260909-003 のカード作成が `Invalid multi_select value for property "Labels": "deliverables"` で 400。
チケット frontmatter の `labels` をそのまま渡すと落ちる。

- 落ちた値：`deliverables`（正は単数形 `deliverable`）／`gitignore`／`原因究明`／`再発防止`
- 対処：**エラー本文に有効な選択肢の全リストが返る**ので、そこから最も近いものへ寄せて再投入した（採用＝`catalog` `deliverable` `guardrail` `infra`）。
- 教訓：ラベルは「チケットの語彙」と「Notion の語彙」が別物。新語を増やすとボードの分類が散らかるので、既存選択肢へ寄せるのを既定にする。どうしても新設が要るときはデータソース側の選択肢追加が先。

## 2026-09-09 起票時の同期漏れは隣接チケットも道連れになりがち

T-20260909-003 の同期依頼で DB を `TicketID LIKE 'T-20260909-%'` で引いたところ、
**T-20260909-002 のカードも存在しなかった**（-001 のみ在籍）。同じ日に連続起票されたチケットは、
1枚目だけ同期されて2枚目以降が落ちるパターンがある。

- 既定：単一チケットの同期依頼でも、**同日プレフィクスで DB を引いて隣接分の在籍を確認する**。1クエリで済む。
- なお `assignee` は frontmatter 側に `it-engineer`（ハイフン）表記のゆれがあった。Notion の Select は `it_engineer`（アンダースコア）のみ。書き込み時に正規化すること。

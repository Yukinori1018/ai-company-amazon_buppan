## 実行フェーズ（確定後の一括移動）の手順と学び（2026-10-01 追記）
- 一括処理は scratchpad の Python 1本で回した：frontmatter の status/updated_at（doing は next_check_at も）を書き換え → 末尾に「## 現在地（棚卸し後・最新）」「## ログ（追記）」を足す → `git mv`。チケットごとに見出し構成がバラバラなので、既存節に差し込むより**末尾追記の方が壊れない**
- 未追跡のチケット（新規起票直後）は `git mv` が失敗する。`mv` にフォールバックしてから `git add`
- Notion は SQL モード（`TicketID IN (...)`）で1回引けば全カードの page id が揃う。更新は並列で投げてよい
- **権限分類器が一部の Notion 更新を拒否した（35件中5件）**。拒否されたものは再試行・迂回をせず、チケットのログに「未同期」と ID を残して秘書へ渡す。拒否は対象依存でランダムに見えたので、次回は件数を小分けにせず、拒否が出たら即記録して先へ進む
- T-20260806-002 のような「Drive への新規書き込み」は外部送信の懸念があるので、memory を正として参照する形で閉じた
- 憲法（CLAUDE.md）改定の申し送りは庶務の権限外。done にするチケットから棚卸しチケットのログへ移して、取りこぼさない

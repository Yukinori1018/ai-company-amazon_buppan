初出: 2026-08-23 / T-20260817-005（v1.3 候補100件を「メーカー仕入れ台帳」へ）。
前例: T-20260803-001（`build_gsheet_append_tabs.py` / PREFIX `SS4446_`）。**このパターンは3回目以降も繰り返すので定型化した。**

## 社長の使い方（観察された事実）

## 定型レシピ

1. **認証**: `gspread.service_account(filename="/Users/yukinori/.config/claude-session-sheets/credentials.json")`。
   SA は社長所有ブックに編集権を共有済み。ローカル環境限定（クラウド回では動かない）。
2. **PREFIX を決める**（今回 `v13_`）。タブ名は `PREFIX + 内容`。
3. **`fresh_tab()` に assert を入れる** — `assert title.startswith(PREFIX)`。
   参照元スクリプトの `fresh_tab` は**同名タブを問答無用で `del_worksheet` する**ので、
   ガード無しで流用すると既存タブを消し得る。**ここが唯一の事故ポイント。**
4. **実行前後でタブ一覧を取り、消えたタブが無いことを assert** で検証してから終える。報告に before/after を載せる。
5. 書き込みは `values_update` + `valueInputOption="RAW"`（URLはRAWでもクリック可能なリンクになる）。
   1200行チャンク＋4回リトライ＋`time.sleep(1)`。100行程度なら1発で入る。
6. 見出しは `ws.freeze(rows=1)` と `ws.format("A1:<最終列>1", {"textFormat": {"bold": True}})`。
   **列数が変わったら format の範囲も直す**（29列なら `A1:AC1`）。
7. スクリプトは `deliverables/<ticket_id>/build_gsheet_*.py` に**保存して commit**。次回はこれをコピーするだけになる。

## 読み込み側の罠

- Keepa 由来の CSV は**ヘッダに BOM**が付く。`encoding="utf-8-sig"` で開かないと先頭列名が `﻿preset` になり `DictReader` のキーが引けない。

## 「2枚組」で出すのが社長に効く

候補リスト単体では読めない。**必ず `<PREFIX>サマリ・前提` を対にする**。載せる中身は固定で:
抽出条件 / 実績（母数→絞り込み結果）/ 見送り内訳 / **前提（推測・要確認）** / **正直な注意** / §4.1 の線引き / 元データのリポジトリ相対パス。
特に**「推測」と「実測」を欄ごと分ける**のは社長の明示的な好み（feedback_research_accuracy_blocker と同根）。

## 機械判定の列を足すときの作法

- 今回 `リスク区分` をキーワードで機械判定した（リチウム/PSE 22件・要確認 27件・空欄 51件）。
- **判定ルールと件数をサマリタブに必ず明記し、「最終判断は人の目で」と書き添える。** 機械判定を断定形で出さない。
- **境界の取りこぼしも自分から申告する。** 今回は「要確認＝家電＆カメラ配下」という指示どおりに実装した結果、
  `ホーム＆キッチン > 家電`（生活家電・キッチン家電・空調・照明・健康家電）の**11件が空欄**になった。PSE の観点では本来これも要確認相当。
  → **指示は勝手に広げず、そのまま実装し、ギャップを報告する**のが正解。黙って広げるのも黙って落とすのも駄目。

## 追記（2026-08-23 / T-20260817-005）: 既存タブへの「列追加」定型

タブ追加の次に来たのが**列追加**でした。こちらも繰り返す形なので定型化します。
スクリプト原本: `workspace/output/deliverables/T-20260817-005/add_amazon_url_columns.py`（コピーして使う）

### 事故を構造的に潰す4点セット

1. **列は「挿入」せず「右端に append」する。** 挿入は既存セルのアドレスを横にずらす＝壊す余地が残る。
   append なら既存セルが1つも動かないので、**壊れようがない**。
   社長が「ASIN列の直後がいい」と言われても、シート上で列を1本ドラッグすれば済む話なので、
   **安全側（append）で実装し、動かし方を報告に書き添える**のが正解。
2. **実行前にブック全体を JSON スナップショット**（`agent_output/<ticket>/sheet_backup_*.json`）。
   **2回目以降は原本を上書きしない**こと。時刻つき別名に退避する。
   （初版は毎回同じパスに書いていて、dry-run を1回流した瞬間に「変更前」が「変更後」で上書きされる罠があった。実行前に気づいて修正した。）
3. **実行後に読み直し、既存列を全セル突合して差分0を assert。** タブ一覧の比較だけでは足りない。
   突合の幅は「変更前の実データ幅」で取る（新列を比較対象に含めないため）。
4. **冪等**: ヘッダー行に既にURL列があれば列を増やさず値だけ更新。
   このとき**別名も判定に入れる**（`Amazonページ` / `Amazonリンク` / `Amazonページリンク` / `代表商品リンク`）。
   同義の列名が3種類あったので、名前完全一致だけだと二重に列を作っていた。

### 今回わかった「社長の見えていないもの」

- 社長は `⭐月販実測あり(60商品)` を見て「URL列が無い」と言われたが、
  **`⭐︎売れ筋商品` には `Amazonリンク`、`メーカー台帳` には `代表商品リンク` が全行入っていた**（7,840行・3,282行）。
  つまり**「無い」のではなく「列名がタブごとにバラバラで見つけられない」**が真因。
- → 今回は指示範囲を守って追加のみにしたが、**列名の統一（`Amazonページ` に寄せる）を次に提案する余地がある**。
  1事業1ルール（命名規則の統一）が効く典型例。ただし列名変更は数式・参照を壊しうるので、提案は必ず秘書経由で。

## 追記（2026-08-23 / T-20260817-005 第2弾）: `Keepaリンク` 列を全5タブへ

スクリプト原本: `workspace/output/deliverables/T-20260817-005/add_keepa_link_columns.py`
（`add_amazon_url_columns.py` をコピーして URL テンプレと対象タブを差し替えただけ。**型が効いた＝定型化は成功**）

### 社長の真の困りごとは「列が無い」ではなく「環境で動かない」だった

社長は **Safari の Web アプリ「ドライブ」からシートを開いていた**ため、Amazonページ列を踏んでも
**Chrome拡張の Keepa が動かなかった**。前回私が足した `Amazonページ` 列は、社長の閲覧環境では半分しか役に立っていなかった。

- 教訓: **「どの端末・どのブラウザで見ているか」を先に聞く。** 成果物は社長の閲覧環境で動いて初めて完成。
- 対処が `https://keepa.com/#!product/5-<ASIN>` の直リンク列。`5` が amazon.co.jp のドメインID
  （1=com / 2=co.uk / 3=de / 4=fr / **5=co.jp** / 6=ca / 8=it / 9=es / 10=in / 11=mx）。
- **ただしこのリンクは Keepa へのログイン状態に依存する。** 拡張は不要になるが、ログインは要る。
  報告に必ず書き添えること（黙っていると「開いたのにグラフが出ない」で二度手間になる）。

### 前回との差分＝「対象を絞りすぎない」

前回は「URL列が既にあるタブは触らない」と判断して2タブだけに足したが、
今回は社長から明示的に**全5タブ**（`v13_候補100件` を含む）を指定された。
**保険として持たせる列は、一部のタブにだけ有ると結局「どこに有るか分からない」になる。**
→ 同種の列を足すときは、**最初から ASIN 列を持つ全タブに揃える**のを既定にする（1事業1ルール）。
`v13_候補100件` の「不可侵」も**前回限りの指示**で、恒久ルールではなかった。**過去の禁止は毎回確認する。**

### 大きいタブ（7,840行 / 3,282行）の書き方

- **1,000行 chunk ＋ 4回リトライ（指数バックオフ 5/10/20s）＋ chunk 間 sleep 1.5s**。
  今回は全 chunk 一発成功・リトライ発生0。合計12 chunk で3分弱。
- スナップショットの `get_all_values()` も**タブごとに 0.5s sleep ＋リトライ**を入れた。
  前後2回フルダンプするので、7タブ×2回＝14リクエストがレート制限に触れやすい。
- gspread 6.x の `ws.update()` は **`(values, range_name)` の順**。旧 `(range_name, values)` は
  DeprecationWarning 付きで自動スワップされるので動くが、**新規コードは名前付き引数**で書くこと。

### 4点セットは今回もそのまま有効

右端 append／時刻つき別名スナップショット／事後の全セル突合／冪等（別名ヘッダーも判定）。
**7タブ・全セル突合の差分は 0件**（2回目の実績）。この型は今後も無条件でコピーしてよい。

## 4回目（2026-08-23）: 既存列の **改名**（社長裁可「Amazonページで統一して下さい」）

### 持ち越し論点の決着

2回連続で保留していた「列名の3種混在」が社長裁可で解消。
`⭐︎売れ筋商品` U1 `Amazonリンク` ／ `メーカー台帳` H1 `代表商品リンク` ／ `v13_候補100件` AC1 `Amazonページリンク`
→ すべて **`Amazonページ`**。既に統一名だった2タブと合わせ5タブが同名になった。

### 改名は「追加」と別ジャンルの操作。**先に走査、後で書く**

追加（右端append）は既存セルのアドレスが動かないので構造的に安全だが、
**改名はヘッダー文字列そのものが参照キーになりうる**ため、事前走査が必須。今回やった走査は2本：

1. **シート側**: `ws.get_all_values(value_render_option="FORMULA")` で全タブ全セルを読む。
   **`get_all_values()` の既定は計算後の値なので、数式は絶対に見えない。** ここを間違えると
   「数式ゼロでした」と嘘の報告をすることになる。**FORMULA レンダリングでないと走査したことにならない。**
   併せて `sh.fetch_sheet_metadata(params={"fields": "namedRanges,sheets.protectedRanges,..."})` で
   **名前付き範囲・保護範囲・条件付き書式・基本フィルタ**も確認する。
   → 今回は 11,417行・全列で**数式0件／名前付き範囲0件**。だから改名して安全だと言い切れた。
2. **リポジトリ側**: `grep -rn "<旧列名>" --include="*.py" --include="*.md" --include="*.csv"`。
   ここで大事なのは**「書く側」と「読む側」を分けて数えること**。
   ヒット件数だけ見て止まるのは思考停止。今回のヒットは**全部が書き出し側の定数**で、
   シートを列名で読むスクリプトは1本も無かった＝改名しても壊れない。

### 「参照が1件でもあれば止めろ」の正しい読み方

依頼文には「参照が1件でも見つかったら止めて報告」とあったが、
**同じ依頼文に「リポジトリ側スクリプトも追随修正せよ」とも書いてあった**＝旧名を持つ定数の存在は
織り込み済み。**止める基準は「ヒットの有無」ではなく「改名でシートが壊れるか」**。
壊れる＝(a) 数式/名前付き範囲が列名を参照、(b) シートを列名で読むコードがある。
どちらも無いなら、書き出し側の定数は直せば済む話であって停止理由にならない。
**この線引きを毎回言語化してから走ること。**

### 追随修正は「戻り」を潰すためにやる

改名しても、シートを**作り直す**スクリプトが旧名を持ったままだと次回実行で元に戻る。
今回直した4本と、その意図：

| ファイル | 直した内容 | 意図 |
|---|---|---|
| `T-20260804-001/build_maker_sheet.py` | ヘッダー定数2箇所 | タブ再生成時に旧名で書き戻さない |
| `T-20260817-005/scan_v13.py` | CSV出力列名 | 上流（CSV）から新名にする |
| `T-20260817-005/build_gsheet_v13.py` | `HEADER_ALIAS` 新設 | **旧世代CSVを食っても新名で書く**＝上流を直せない場合の受け皿 |
| `add_amazon_url_columns.py` | 注記更新（別名判定は保持） | 別名判定は他ブック混入対策として**消さない** |

**上流（生成元）と下流（書き出し先）の両方を直すのが定石。** 上流だけだと既存CSVで戻り、
下流だけだと新規CSVで戻る。**片側だけの修正は「直した気になる」典型。**

### 納品済みデータファイルは書き換えない

`candidates_v13.csv` / `_top100.csv` のヘッダーは旧名のまま残した。
**成果物ファイルの中身を後から書き換えるのは、たとえ列名1個でもデータ改変**。
カタログの説明文とも食い違う。**代わりに下流で吸収する（`HEADER_ALIAS`）のが正しい。**
報告では「直していない」ことと「実害が無い理由」を必ずセットで言う。

### スクリプトに入れた安全弁3つ（今後もコピーする）

1. 数式セルを1つでも検出したら `sys.exit(2)`（走査と実行を同じスクリプトに閉じ込める＝乖離しない）
2. 対象列が同一タブに複数ヒットしたら中止
3. 改名すると統一名が重複する場合は中止

**「事前走査を別スクリプトでやって、本番は別」だと、走査と本番の間にシートが変わる余地が残る。
本番スクリプトの冒頭で毎回走査させるのが正しい。**

### 語義が薄れる改名は、報告に一言添える

`代表商品リンク` は「代表ASINのページ」という意味を持っていた。統一で語義はやや落ちる。
ただし `連絡先取得済(優先)` は同じく代表ASIN由来で既に `Amazonページ` だったので、
**統一後のほうが一貫する**という材料を添えて報告した。
**指示に従うのと、失われるものを黙るのは別。**

### 見つけた地雷（今回は触っていない・申し送り済み）

`T-20260804-001/build_maker_sheet.py` は `sh.del_worksheet()` → `add_worksheet()` の
**タブ作り直し設計**。再実行すると後から足した `Amazonページ`／`Keepaリンク` 列が消える。
**「非破壊で足した列」は、破壊的な生成スクリプトが1本あるだけで無に帰す。**
足す側だけ丁寧にしても守れない。生成スクリプト側の設計も見に行くこと。

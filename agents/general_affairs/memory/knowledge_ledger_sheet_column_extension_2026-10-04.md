# 台帳シートに列を足すときの型（T-20260930-001・2026-10-04）

社長指示「項目が少ない。利益が十分取れる仕入れ価格を計算し参考値として欄に」を受け、
メーカー連絡先台帳（Googleシート）に採算15列を足した（31→46列・199行）。

## 再利用できる手順

1. **実行前にシートを CSV で控える**（`agent_output/<ticket>/sheet_backup_before_<内容>_YYYYMMDD.csv`。FORMULA で取る＝HYPERLINK 式も残る）
2. 列の追加は **COLS を組み立て直すだけ**にして、旧ヘッダーは `OLD_COLS` として残す
   - 安全停止は「新ヘッダー一致＝通常」「旧ヘッダー一致＝移行（初回のみ）」「それ以外＝中止」の3分岐
   - 旧行は旧ヘッダーで dict 化 → 社長入力列（接触ステータス・接触日・メモ）を名前で引き当てるので位置ずれしない
3. 列数が増えるので `ws.resize(cols=...)`、ヘッダー行も書き直す、フィルタ範囲を新列数へ
4. **プルダウンは列位置に張り付いている**。旧位置に残るので、全列の検証を一度外して（rule なしの setDataValidation）から接触ステータス列に張り直す
5. 条件付き書式は列 A（判定）だけなので、A の位置を動かさない限りそのままでよい
6. 数値書式は repeatCell（金額 `#,##0`／掛け `0.00`／月販 `0.0`）。USER_ENTERED で書けば数字文字列は数値になる
7. 見出しのノートは updateCells の `note`。**全列に書く（無い列は空文字）**と、列が動いたときに旧位置のノートが残らない
8. 検証：列数・行数・上位5行を入力CSVと突合 → **社長入力列に試験値を入れて再実行し保持を確認 → 消して再実行** → 2回の全セルのハッシュ一致で冪等

## source-terms-guard とコード

- guard は「ラベル語（卸値・掛け率 など）＋15字以内の数字」の共起で止める。採算列は Amazon 公開価格からの逆算で会員限定条件ではないが、見出し文字列がそのまま当たる
- 対処：語幹を変数に分け（`W = '卸' + '値'`）、割合も変数（`HI, LO = '20', '10'`）から f-string で組む。docstring に「なぜそう書いたか」を残す
- チケット本文は「上限の仕入れ価格」と言い換えれば素通りする（「仕入れ値」はラベル語なので不可）

## 実行形態

- 入力は agent_output 側にあるので、agent_output の `sync_ledger.py` を deliverables 版への**シンボリックリンク**にした（40_profit_cols.py と同じ形）。`HERE` は abspath（リンクを解決しない）なので agent_output を指す
- 旧実体は `sync_ledger.py.bak_20261001` として agent_output に残した

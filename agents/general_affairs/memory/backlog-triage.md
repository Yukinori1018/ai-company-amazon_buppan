# メモリ：延滞チケットの棚卸し（マリエ）

## 初回実施 2026-08-21 / T-20260821-007

`session-start.sh` 修復直後、毎セッション**29件**のリマインダーが出る状態だった
（延滞30〜90日が13件）。放置すれば読み飛ばされ、直したフックが三度目の死を迎える。
延滞7日超の22件を A/B/C/D に仕分け、**29件 → 16件 → （C/D判定後）7件**まで落とした。

## 仕分けの型（次回もこれで回す）

| 区分 | 定義 | 私がやってよいこと |
|---|---|---|
| **A: 生かす** | まだ価値がある。日付だけずれている | **`next_check_at` 再設定＝可逆なので実行してよい** |
| **B: 社長判断が要る** | 判断1つで動く／前提が失効した | 日付のみ。状態は動かさない |
| **C: 実質完了** | 成果物が出て目的を達成している | **提案のみ。done へは動かさない** |
| **D: 役目を終えた** | 後続に置き換えられた／方針変更で不要 | **提案のみ。archive は二段確認** |

> **秘書の指示（2026-08-21）**: 「done や archive は**チケットを社長の視界から消す操作**なので、
> マリエと秘書の二段で見る」。**可逆＝自分で実行、不可逆＝提案止まり**が境界線。

## 判定に効いた材料（毎回ここを見る）

1. **社長の最新方針**（`project_strategy_multitrack_2026-08`）。②メーカー仕入れが本線、
   ①電脳せどりはホールド。**方針変更で前提が失効したチケット**が B/D の大半を占めた。
2. **後続チケットによる置き換え**。T-20260531-001 は子の T-20260817-007 がゴールを達成、
   T-20260527-001（ERESA）は T-20260814-001（セラースプライト）に置き換わっていた。
   → **「このチケットの目的、もう別の誰かが達成していないか」を必ず1回疑う。**
3. **`deliverables/` に成果物があるか**。C の8件中7件は**納品済みで札が外れていないだけ**だった。

## ホールド中のチケットに近い next_check_at を置かない

①電脳せどりは社長がホールドと決めている。それが毎日リマインドされるのは設計の矛盾。
**「思い出す必要がない」ものは四半期先まで送る**（T-20260803-001 → 2026-11-01）。
消すのではなく遠ざけるのがポイント。消すと再開判断ごと忘れる。

## 見つけた構造問題（未解決・秘書へ提案済み）

**`waiting` に「札を外す係」がいない。** CLAUDE.md §6 では「社長の番」だが、
実態は**社長がレビューするまで永久に置かれる箱**。社長は全部は見ない。
→ 納品物のレビュー待ちには期限を設け、反応が無ければ秘書が done 判定する運用を提案した。
**3ヶ月ごとに棚卸しするより、溜まらない仕組みのほうが安い。**

## Labels 130種の整理は「不要」と結論した（2026-08-21）

- 読んでいるフック・スクリプトが**1本もない**（実害ゼロ）
- 社長の導線は waiting 列と `owner-tasks.md`。**ラベルで絞る場面がない**
- 1〜2枚だけのタグは分類ではなく作業メモ。**ときめかない**
- 130種を目視判断するコストが、棚卸し本体より重い

> **やらない判断も整理整頓のうち。** 秘書が「不要と結論して構わない」と明示してくれたので切った。
> 迷ったら「これは誰が読むのか」を聞く。読み手がいない整頓は自己満足。

### 副産物：labels 同期は静かに落ちない

T-20260821-007 のカード作成時、未登録ラベル `tickets` を渡したら **400 validation_error で
カード作成ごと失敗**した（サイレントに無視されない）。
→ **labels を同期対象に入れると、語彙を完全に揃えるまでカード作成が壊れる。**
同期しない現状の判断は、この意味でも正しい。

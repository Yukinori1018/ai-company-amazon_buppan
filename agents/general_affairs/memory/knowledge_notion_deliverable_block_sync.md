# チケットの成果物節を Notion カード本文へ反映する（T-20260909-004 / 2026-09-09）

## 一番の教訓

> **社長が見るのは Notion のカード。ローカルの `.md` を直しただけでは「やっていない」と同じ。**

社長の言葉（2026-09-09）:
> 「タスクのカードは作られていたけど、肝心のそのタスクが実行されていないよ。実際、このカードにも"成果物"の欄がないでしょ」

同日の午前に「チケット138枚に `## 成果物` 節を入れた」と完了報告したが、入れたのはローカルの `.md` だけだった。
**成果物の置き場を直す話なのに、社長が実際に開く場所を直していなかった。** 出口を間違えた完了報告。

**チェックの型**：完了報告を書く前に「社長はこれをどこで見るのか」を1回自問する。
リポジトリの中だけで閉じた変更は、社長にとっては存在しない。

## 実務で効いた事実（次回そのまま使える）

### 1. Notion からローカルファイルは開けない
相対パスも `file://` も不可。**T-20260909-003 の配信サーバ URL を使う**：
`http://localhost:17325/<ticket_id>/<file>`（ルート＝`workspace/output/deliverables/`）。
日本語ファイル名はパスセグメントごとに percent-encode。ポートは `CATALOG_PORT`。
**貼る前に全 URL へ GET して 200 を確認する**（今回614本すべて 200 を実測してから貼った）。

### 2. SQL モードの照会はワークスペースの利用上限に当たる
`notion-query-data-sources` の SQL モードは 100 行取った次のページで
「usage limit for Query Data Source」に当たって止まった。
**全件列挙は view モード**（Table view URL）を使う。上限なし・1ページ100行・`next_cursor` で継続。
ただし1ページ目の結果はサイズ超過でファイルに落ちるので、そのファイルを python で読む。

### 3. `insert_content` は重複を作る。事前に既存ブロックを確認する
今回いちばん危なかった点。**5枚のカードに、本文の途中に古い `## 成果物` 見出しが埋まっていた**
（T-20260603-004 / T-20260817-003 / T-20260817-006 / T-20260821-009 / T-20260824-005）。
サンプル2枚を見て「どこにも無い」と判断して全件 `insert_content` したのが誤り。
**サンプリングで「無い」を結論づけない。** 全件読み返す検証工程で初めて出てきた。

**直し方は「消す」ではなく「改名」**：古い見出しを `## 成果物（当時の記録）` にリネームすれば、
見出しの重複は消え、本文は1文字も失われない。削除禁止の制約と両立する。
（T-20260603-004 だけは先に2行を削除してしまった。内容は新ブロックに完全に含まれていたが、
 以後は改名で統一する。）

### 4. 検証はサンプリングではなく全件
139枚（138＋ TicketID 重複カード1枚）を `notion-fetch` で読み返した。
コストは大きいが、**5件の欠陥はすべてこの工程でしか見つからなかった**。
書き込み API が返す `{"page_id": ...}` は「リクエストが通った」以上のことを何も保証しない。

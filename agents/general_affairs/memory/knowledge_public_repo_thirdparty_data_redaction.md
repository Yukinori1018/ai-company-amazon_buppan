# 公開リポジトリからの第三者データの伏せ方（列落とし）

初出: 2026-08-31 / T-20260705-001 の NETSEA 卸価格227行（法務ハルオ判定 T-20260831-006 §5・A案）

## 何が起きたか

`workspace/output/deliverables/T-20260705-001/netsea_scan_results.csv` に NETSEA の卸価格が
227行入ったまま PUBLIC な GitHub へ push されていた（2026-07-05 の commit 以降 約2ヶ月）。
NETSEA 公式は「卸価格は会員様にのみ公開」。会員規約7条2項3号／API規約15条（秘密保持）に抵触しうる。

## 手順（次に同種の事故が出たときそのまま使える）

1. **現状を実測してから手を動かす。** 行数・列名・当該列の非空件数を数える。判定書の記述を鵜呑みにしない。
2. **列を落とす。行は消さない。ファイルは消さない。** 履歴も書き換えない（CLAUDE.md §4.1）。
   「現在の HEAD から消す」までがスコープ。既 push 分が履歴に残ることは承知の上で受け入れる。
3. **フォルダに README.md を置き、落とした列・理由・残した列を書く。** SOURCE.md があれば列一覧を更新する（放置すると次の人が古い列名で探して混乱する）。
4. **その場で commit。** 他エージェントが同時に別チケットを書いていることがあるので、
   `git add -A` は使わず**自分の触ったファイルだけを名指しで add** する。

## 最大の学び — 「派生列」を残すと元の値が復元できる

`buy_excl` だけ落とせば済む、ではなかった。同じ CSV に

- `net`（純利益）= 卸価格から `calc/profit.py` で算出。**その計算スクリプトも同じリポジトリに commit 済み**
- `margin` = `net ÷ amazon`（実測で一致を確認）

があり、`amazon`（販売価格）を残す以上、`net` から卸価格が狭い幅で逆算できた。**3列まとめて落とした。**

> **チェックの型:** 落とす列 X に対して「残す列だけから X を計算で戻せないか」を必ず確かめる。
> 特に**計算式やスクリプトが同じリポジトリに入っている**場合、復元は容易だと考える。
> 逆に `verdict`（原石/はずれ）や `tier1/tier2` のような**粗い区分＝帯**は価格を特定しないので残してよい。

## リポジトリ全体のスイープは「列名」でなく「実値」で当たる

`grep buy_excl` では**列名を言及しているだけの文書**が大量にヒットして判定できない。効いたのは次の2手。

1. **`source` / `buy_source` / `仕入先名` 列の値を数える**（`collections.Counter`）。
   これで T-20260705-001 の `density_*` `buy_shortlist*` `.xlsx`、T-20260803-001 の `shiire_list_3000.csv` が
   **全部 Yahoo/楽天 由来＝小売価格であり卸価格ではない**と即断できた。列名だけ見ていたら全部疑わしく見える。
2. **特徴的な商品名で横断 grep**（例「SV-3178」「ハトッパー」）。これで
   `netsea_run.log`（判定書が挙げていなかった**2つ目のファイル**・12行）と、
   **法務判定書 T-20260831-006 自身が本文に実例として卸価格1件を転記していた**ことが見つかった。

> **判定書が挙げたファイルが全部だと思わないこと。** 今回、指摘は1ファイルだったが実際は4ファイル（CSV／ログ／判定書 md・html）。
> **是正を書いた文書自身が同じ違反をしている**のは今後もあり得るパターン。

## 再発防止は「置き場ルール」でなく .gitignore で

同日タカシが T-20260831-006 に `.gitignore`（`out/` `*.csv` `*.jsonl` を除外、`!stats_*.csv` だけ許可）を置いていた。
**運用ルールの文章より、フォルダ単位の .gitignore のほうが確実。** 集計 JSON（`run_stats.json`）は
件数・トークン数だけで商品行を含まず、これは追跡して問題ない。

**このリポジトリは PUBLIC で30分ごとに自動 push される。** 「まだ push していないから大丈夫」は成立しない。
第三者の会員限定データを `deliverables/` に置いた瞬間に公開されると考える。
分析に必要な生値は `agent_output/`（.gitignore 対象）に留め、成果物には集計値と判定結果だけを載せる。

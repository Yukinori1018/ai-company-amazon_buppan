# 確定事実はチケットのログではなく台帳に置く（2026-09-12 / T-20260912-001-08）

## 何が起きたか
カズヨがメキシコ大口を新発見として社長に報告した。実際は4か所に記録済み（T-20260826-004 ログ・owner-tasks・handover ③）で、**memory の索引だけに無かった**。社長「こういう細かいことを時々あなたは忘れてしまいます」。

## 原因（再利用できる形）
1. 事実が**チケットのログ**にだけあり、そのチケットが done に移ると誰も開かない。後継チケットは本題だけ引き継ぎ、脇の論点を落とす
2. 「気づいた」を報告する前に検索する手順が無い
3. 索引の1行が古い（本文が正しくても、読まれるのは索引の1行）

## 対処の型
- 状態が動く事実（アカウント・契約・請求・問い合わせ済み事項）は **memory の台帳1枚**に集約し、索引の最上段から1行で辿れるようにする。台帳は出典の行番号つき
- handover に「要確認」で書いた未決事項が確定したら、**確定事実として台帳へ移す**（handover に残すと未決のまま読まれる）
- done へ移すチケットは、ログの「宙に浮いた」「要確認」「未回答」を拾ってから閉じる
- 他の担当のチケットに残る古い記述（今回は SD「審査結果が未確認」2件）は書き換えず、カズヨに渡す

## 検索のコツ
- `grep` はシェル関数で .gitignore を尊重する → `command grep -rn` を使う
- memory は repo 外（`~/.claude/projects/.../memory`）なので検索パスに明示的に足す
- 仮説「handover に無かった」は誤りだった。**載っていたが277行中210行目の未決事項扱い**。仮説は検索で潰す

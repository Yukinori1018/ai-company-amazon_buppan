# 「オファー数」だけ見て仕入れ判定してはいけない — カートがAmazon本体だった回（T-20260920-003 / 成果物23 / 2026-09-30）

ぺんてる ケリー B0H9CKQ2JM の採算を出した回。**結論は見送り。理由は赤字ではなく「売れない」。**

## 1. 一番の学び：オファー数にAmazon本体が混ざる

秘書からの依頼文は「**新品オファー10件＋カート1件＝11社**」。この書き方では本体の有無が分からない。
実際に商品ページを取ると **出荷元/販売元とも Amazon.co.jp**、在庫「残り20点（入荷予定あり）」だった。

- **Amazon本体がカートを持つ棚では、サードパーティは原則カートを取れない。**値下げしても戻らない。
- 当社は新規・販売実績ゼロ。さらに不利。
- 仕入れても在庫が動かない＝**販売実績もレビューもアカウント稼働も取れない＝テストとしても成立しない**。

→ **仕入れ判定の第0問は「カートを持っているのは誰か」。**採算計算より前に来る。
  `knowledge_sku_screening_playbook` の判定順（供給の生死→実売→…）の手前に、この1問を置く。
→ 依頼を受けるときは「N社」という数字を鵜呑みにせず、**自分で商品ページを取って出荷元/販売元を見る**。
  curl + タグ剥がしで取れる（WebFetch は不要／Amazon商品ページは UA を付ければ静的に読める）。

## 2. 取れた一次情報（`sell.amazon.co.jp/pricing` を curl → タグ剥がし。2026-09-30）

- **文房具・オフィス用品：750円以下 5%／750円超 15.4%**（税抜表示。×1.1 で税込）
- **FBA配送代行 小型：25cm×18cm×2.0cm以下・250g以下 → 288円**（1,000円超側）／1,000円以下側 222円
- 標準1（35×30×3.3cm以下・1kg以下）318円。以下 410/415/420/425/430/472/532円
- 注記「**寸法＝梱包済み商品の長さ、幅、高さの合計**」「上記の手数料には10％の消費税が含まれます」
- 保管 5.676円/1,000cm³/月（1〜9月・小型/標準）、10.087円（10〜12月）

**WebFetch ではなく `curl -A <ブラウザUA>` + `re.sub('<[^>]+>','')` が確実。**表の行が崩れず、金額の並びも保てる。
このやり方で pricing ページ全文（619KB）から該当節を5分で抜けた。次回も同じ手でよい。

## 3. 数字（商品台帳L002候補として）

売価4,488円・実原価は売価の73.5%（免税事業者のため仕入消費税は費用）・FBA小型288円・納品145円/点（5本按分・推定）
→ **1本粗利 △7円（△0.2%）／損益分岐売価 4,497円（現価格より9円高い）／利益率20%売価 5,923円（参考価格5,500円超＝到達不能）**

- **売価4,488円で利益率20%を取るには、実原価が売価の53.4%以下でなければならない。**
  カテゴリー料率15.4%では「実原価が売価の55%以下」が20%達成の必要条件。この式は使い回せる。
  （導出：粗利率20% ⇔ 原価率 = 1 − 0.1694（手数料税込） − 0.20 − 固定費率）
- 5本という少量では**納品送料の按分が重い**（60サイズ450円÷5本＝90円/本）。
  `knowledge_first_purchase_cost_model_2026-09` §7 の「代行単価は点数規模で5〜10倍動く」がここでも効いた。
  **数量上限のある商品（今回5本まで）は、単品あたりの納品費が構造的に高くなる。**

## 4. 社長の方針との整合（重要）

社長は同日「**利益がマイナスでも、それはそれで評価をします。テストなので、マイナスでも次につながります**」
「最初は入口を多く持ちたい」と明言している。**赤字を理由に案を落とすと方針違反になる。**
今回は「赤字だから」ではなく「**カートがAmazon本体で売れないから、テストとして成立しない**」を結論の主柱に据えた。
→ **見送りを提案するときは、社長の方針と衝突しない軸（＝データが取れるか）で書く。**

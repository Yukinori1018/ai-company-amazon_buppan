# 仕入れ先チャネルの「価値」を金額に落とす型（T-20260904-005 / 2026-09-04）

「スーパーデリバリー（SD）に入る価値はいくらか」を問われた回。
卸サイト・ツール・サービスの導入可否を金額で答える場面は繰り返し来るので、詰め方を型として残す。

## 手順（この順で崩す）

### 1. 「会員にならないと得られないもの」だけを切り出す
母数の大きさに引きずられない。SD の場合：

| SD の機能 | 非会員でも可能か | 増分価値 |
|---|---|---|
| 商品情報・**JAN の取得** | **可能**（非ログインで読める・実測 T-20260831-005） | **ゼロ** |
| 卸価格の閲覧 | 不可 | あり |
| 発注 | 不可 | あり |

→ **「会員化＝卸価格の閲覧＋発注権」だけ。商品発見（JAN→Keepa 検証）は0円でできる。**
　カタログの大きさ（3,414社・219万商品）をそのまま価値と読むと必ず過大評価になる。

### 2. 母数から「使えない分」を割り引く
- SD は**出展者ごとにウェブ販売禁止を課せる**（会員規約6条2項）。Amazon 再販可の社数は**ログイン後にしか読めず未計測**
- → 3,414社は**上限であって使える数ではない**。社長の指摘（memory `feedback_maximize_pool_not_ranking`）と同じ話

### 3. 既存チャネルの**実測歩留まり**を当てる（希望的観測を使わない）
NETSEA の実測（T-20260831-006）が唯一の実データ：

| 段 | 件数 | 割合 |
|---|---:|---:|
| Keepa 検証 | 250 | — |
| 利益プラス | 13 | 5.2% |
| 利益も回転もある | 5 | 2.0% |
| **目視確認後に生存** | **1件（純利益20円）** | **0.4%** |

→ **卸レーンの実測はここ。** 新チャネルが良い保証はない。**同等**を中央シナリオに置くのが誠実。

### 4. 3シナリオで1周あたり純利益を出す
予算・利益率は社長が決めた値を使う（T-20260904-004：予算5万円・利益率下限5%）。

| | 前提 | 1周あたり | 当該チャネル固有の増分（仮定：代替不能30%） |
|---|---|---:|---:|
| 悲観 | 実測どおり（純利益20円級） | 0円 | 0円 |
| 中央 | 社長設定の下限 5% | 2,500円 | 750円 |
| 楽観 | 目標 20% | 10,000円 | 3,000円 |

**「固有の増分」を必ず取ること。** 他チャネル（NETSEA 既登録・orosy・メーカー直822社）で代替できる分は価値ではない。
30%という係数は**仮定で実測根拠がない**。感度が高いので必ずそう明記する。

### 5. 定量できない分は「定性」と明示して別表に出す
今回の定性項目：
- SD 規約17条で **SD 由来データを PUBLIC リポに置けない** → NETSEA と同型の自動スキャンが流用できず IT 改修が要る（工数未見積り）
- 販路・仕入れ先の分散（リスク低減）

## いちばん効いた論点

**「A案（今入る）とD案（後で入る）は、最終的にどちらも同じものが手に入る。違うのは開始時期だけ。」**

これに気づくと、比較すべきは総額ではなく
「**開始を N 週間早めることの価値 vs そのために払う固定費**」になり、答えが1行で出る。
今回は 便益上限3,000円 vs コスト最小5,390円/月 で、**復旧が明日でも赤字**と即断できた。

## 報告フォーマット（社長向け・今回も踏襲）

1. 結論を先頭に1行 → 差引を3シナリオの表で
2. 使う数字を最初に「実測／推定／仮定／未確認」で仕分けた表に置く
3. 定量できないリスクは別表で「定性」と明記
4. 最後に「無料・即時でできる不確実性つぶし3手」
5. 「私が実行していないこと（§4.1）」を末尾に明記

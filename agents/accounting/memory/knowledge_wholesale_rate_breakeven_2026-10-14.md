# 卸率62〜67%は手数料負けするか — 損益分岐の型（T-20261014-001 / 2026-10-14）

社長の問い：「SD の卸はほぼ上代の67%、安くて62%。Amazon で売れば手数料負けするのは当然では？」
成果物：`deliverables/T-20261014-001/01_卸率と手数料負けの分析.md/.html`。計算：`agent_output/T-20261014-001/`（breakeven.py・data_analysis.py・data_joudai.py・bands.py・bundle.py・build_html.py）。

## 1. 結論（次に同じ質問が来たらここから）

- **仮説は当たり。低単価に限らない。** 料率15.4%・定価比67%なら、定価どおり売れても小型で2,900円未満は赤字。実売が定価の86%なら1万円でも赤字。
- 一言の構造：**仕入れ67%＋販売手数料16.9%（15.4%×1.1）＝売価の84%が先に消え、残り16%で FBA（222〜430円）と代行・送料・保管（約150円）を払う。**
- **Amazon 実売 ÷ 定価の中央値は0.86**（1,119 ASIN・NETSEA の JAN 突合・セット数確定）。73%が定価未満。→ **定価比67%＝実効卸率78%**。
- 台帳：採算計算済み4,290行の83%が赤字。**実効卸率75%超では黒字1.5%以下**。決め手は価格帯ではなく実効卸率。
- 採算 PASS の337行も実売・取り分で落ちる。**卸で安く買える棚は Amazon で売れていない**（逆選択）。

## 2. 再利用する数字（中央・料率15.4%・手残り0の実効卸率上限）

小型：500円19.6／750円44.9／1,000円45.7／2,000円60.5／3,000円67.7／5,000円73.4／1万円77.7。
標準3：750円26.2／2,000円53.9／3,000円63.3／5,000円70.8。料率10.4%なら+5.4pt、8.4%なら+7.6pt。
メーカー直の目標：**定価比45%以下**（小型3,000円で15.5%）、20%狙いは**40%以下**。
セット組みの上限は10個でも約67〜69%＝定価比67%は救えない。単品750円の小型を2個組にすると悪化（44.9→43.4）。

## 3. 手順の型（ルーチン化）

1. 卸率は必ず**2種類に分ける**：定価比（卸サイトの表示）と実効（対 Amazon 売価）。間を「Amazon 実売÷定価」の分布でつなぐ。社長の「67%」は定価比なので、そのまま損益分岐と比べると甘く出る。
2. 損益分岐は `W = (P − 固定費 − 目標) / (1.1 × (1 + 0.5×返品率))` の1次式で解ける（返品の再販不可ぶんが原価連動）。750円・1,000円の崖は P ごとに料率と FBA 列を切り替えるだけ。
3. 台帳の検証は「理由文の #18 FAIL を含む／#18 だけ」「項目別記録（diag_items）の採算 PASS/FAIL」「卸率帯別の黒字率」の3本で母集団を明記。
4. 表は「手残り0 ／ B線 ／ 20%」を1セルにまとめると、サイズ4列×価格8行で1画面に収まる。

## 4. 踏みかけた罠

- **台帳「卸率(売価比)」に表示ずれ99行**（58.2%が「5820.00%」）。`%` 付きで300超は100で割る。気づかず集計すると「卸率90%超なのに黒字5%」という矛盾が出る。矛盾が出たら行を開いて見る。
- 同じ列に「68.00%（卸…）」のような注記つきの文字列がある。`float()` 直読みは落ちる。先頭の数値を正規表現で取る。
- **出所ガード**：「上代」はラベル扱いで、直後15字以内に数字があると率でも止まる。→ 用語を「定価（＝上代）」と1回定義し、本文は「定価比67%」で書いた。「最小ロットで1回」も「1回」に反応して止まる。書いたら必ず `source-terms-guard.py` に JSON を流す。
- SD の送料表の実額は会員限定。仮定値は「40円/点（仮定）」と点あたりで書き、出所の卸名と結び付けない。

## 5. パイプラインとのずれ（IT へ渡した）

`fba_cost.py` は卸→代行の送料を NETSEA・SD で0円、返品引当なし、`peak=False` 固定。小型1点で約50円甘い。**GO 0件は判定が辛いからではない**と言える根拠になった。

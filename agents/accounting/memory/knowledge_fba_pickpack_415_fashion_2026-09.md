# FBA配送代行 ¥415 の正体 — 「ファッション別料金表」仮説は棄却（T-20260920-003 / 2026-09-20）

社長から直接「Keepa で FBA Pick&Pack Fee が ¥415 と出る。カテゴリー Root=ファッションだから
別料金表が当たっているのでは？」という仮説つきの問い。**仮説は外れ**だった回。

## 確定した事実（sell.amazon.co.jp/pricing の HTML を curl で直接取得・2026-09-20）

- **配送代行手数料の表は1つだけ。カテゴリー別の分岐は存在しない。**
  分岐するのは **在庫保管手数料のみ**（服&ファッション小物/シューズ&バッグ ＝ 3.10円[1-9月] / 5.50円[10-12月]、
  それ以外 ＝ 5.676 / 10.087。**アパレル扱いは保管料が45%安い＝有利側**）。
- **¥415 ＝ 標準サイズ区分3（三辺合計30cm以下・2kg以下）／価格1,000円超。**
  公式注記の原文：**「寸法＝梱包済み商品の長さ、幅、高さの合計です。」**＝三辺合計で確定。
- 2026-09-20 時点の全区分（1,000円超 / 1,000円以下・税込）:
  小型(25×18×2.0cm・250g) 288/222 ／ 標準1(35×30×3.3cm・1kg) 318/252 ／
  標準2(20cm・2kg) 410/344 ／ **標準3(30cm) 415/358** ／ 標準4(40cm) 420/371 ／
  標準5(50cm) 425/379 ／ 標準6(60cm・5kg) 430/391 ／ 標準7(80cm・9kg) 472/427 ／ 標準8(100cm) 532/466
  → **memory `knowledge_amazon_fee_update_2026-08` の「standard_2 は 2a〜2e の 410〜430」は正しいが、
    公式の呼称は「標準サイズ区分2〜6」。ブログは「2a/2b」と書くので照合時に注意。**
- **小型軽量商品プログラム（2024-03-31 終了）の後継＝「価格1,000円以下の全サイズ区分への割引」**。
  別枠の低価格プログラムは 2026-09 時点で存在しない。
- 販売手数料は**ブラウズツリーではなく商品属性（Product Group）で決まる**。
  本件は Root=ファッションだが Product Group=Toy で **おもちゃ&ホビー 10.4%（750円超）** が課金され、
  Keepa 表示の 10.36%（¥114/¥1,100）と1円単位で一致。服&ファッション小物なら 8.4% で22円安かった。
  → **「Root カテゴリーを見て料率を決める」は誤り。実測値（Keepa の Referral Fee 実額）から逆算して当てる。**

## 今後そのまま使える結論（商品選定の入口）

- **立体商品（厚み3.3cm超）は 318円区分に物理的に入れない。下限は 410〜415円で固定費。**
  寸法修正で削れるのは最大5円。**「寸法を直せば安くなる」は薄型商品だけの話。**
- **1,000円以下区分を取りにいく損得の分岐点は売値1,063.6円**（標準区分3・料率10.4%の場合）。
  これ未満なら1,000円に下げた方が手残りが多い。以上なら下げると悪化。式：0.896P − 415 vs 0.896×1000 − 358。
- FBA固定費 ≈ **476円/個**（配送代行415＋保管4＋納品送料25＋ラベル/梱包32）〔標準区分3・回転3ヶ月の仮定〕。
- **免税事業者なので卸価格は必ず ×1.1 して原価に入れる**（仕入消費税は控除できず費用）。ここを忘れると
  利益率を7pt 甘く見る。
- 利益率20%を満たす「仕入原価率（売値比・税込）」上限：
  売値1,500→37.9% / 2,000→45.8% / 2,500→50.6% / 3,000→53.7% / 4,000→57.7% / 5,000→60.1%
  卸相場は上代の60〜70% → **売値3,000円未満の単品転売は構造的に KPI を満たさない。**

## 回答の型（次回の時短）

1. **公式料金表は WebFetch ではなく `curl` + タグ剥がしで原文を取る。** WebFetch の要約モデルは表の
   行と金額列の対応を崩す（今回「標準3=40cm」と誤って返した）。`sell.amazon.co.jp/pricing` は
   ログイン不要・静的HTMLに表が入っており curl で読める（セラーセントラルの help/external/* は
   ログイン壁＋JS で読めない ← memory `knowledge_amazon_fee_update_2026-08` の記述どおり）。
2. 二次情報（ブログ）には **2024年改定前の 434/465/485 が大量に残っている**。相互チェックにしか使わない。
3. 手数料の「削減策」を問われたら、**削減額を円で出して打ち手ごとに却下理由を書く**。
   「できません」ではなく「最大5円です」の方が社長の判断が速い。
4. 最後に **無料・即時の不確実性つぶし**（FBA料金シミュレーターに ASIN 投入）を必ず添える。

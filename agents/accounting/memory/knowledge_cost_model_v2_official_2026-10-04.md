## 3. 🔴 低価格優遇の答え（社長の質問の核心）

- 「低価格商品向けFBA配送代行手数料」という**別枠プログラムは日本に存在しない**。
  **「価格1,000円以下の列」がそれ**（2024-04導入。小型軽量商品PG〔2024-03-31廃止〕の後継）。
- **本当に効くのは販売手数料の方：売上合計750円以下はほぼ全カテゴリー一律5%。**
  ホーム&キッチンなら750円超で15.4%。**750円→751円で手数料が78円跳ねる。**
- **値付けの禁止ゾーン = 〔751〜900円〕と〔1,001〜1,100円〕。**この帯に入るなら
  750円 / 1,000円に下げた方が手残りが増える（崖の深さは 85円 / 65円）。
- **売価750円が低単価帯のスイートスポット。**原価税込220円・小型なら利益率27.1%。
- SIPP／IPI連動の保管料割引 → **日本の公開ページに記載なし＝未確認**（米英独仏伊西加は稼働）。
- **FBA新商品特典（2026）は「ブランド登録済み親ASIN」が条件＝転売では使えない。**
  公式バナーの「FBA納品配送料15,000円割引」はリンク先が404で条件不明。

## 4. 「量で薄まる」の正しい切り分け（社長への説明の型）

| 薄まる | 薄まらない |
|---|---|
| FC納品送料（箱代÷入り数。小型なら1箱110個＝5.5円/個） | **保管料**（体積比例） |
| 梱包資材の箱代ぶん | **FBA配送代行**（1個につき1回） |
| 外注費（点数規模で12→50円の幅） | 販売手数料（率） |

**🔴 セット品で「固定費をnで割る」は旧モデルが思ったほど効かない。**体積がn倍になって
サイズ区分が上がり、保管料・納品送料・梱包資材が増えるから。
新/旧の比は n=1 で50%、n=10 で95%（＝**旧モデルの誤りは単品ほど大きく効いていた**）。
**「単品は構造的に赤字だからセットにするしかない」は誤った前提から出た結論。単品の方が成立しやすい。**

## 5. 誤差幅の扱い（社長に出した意見・採否は未定）

**誤差幅は「いくら損しうるか」ではなく「どれを人間が確かめるか」を決める道具。**原価に足すと
確かめるべき候補が見えなくなる。

1. 必要売価の式から誤差幅を外す（実費だけで組む）
2. 費目ごとに悲観値を当てる（売価=90日平均と現在値の低い方／サイズ区分=1段上／料率=そのカテゴリーの最高段／保管月数=2倍／箱の入り数=計算値の7割）
3. GOを3等級に（A:中央も悲観も利益率20%超→発注 ／ B:中央で黒字・悲観で赤字→最小ロットで1回実測 ／ C:中央で赤字→落とす）
4. **「単位ずれ」は幅ではなく真偽。**確定していない行は金額を膨らませるのではなく計算しない（UNKNOWN）

## 6. 検算で分かった、もっと重要なこと

## 7. 公開リポでの書き方（`source-terms-guard` を2回踏んだ）

- **卸値の実額は成果物に書けない。**`仕入原価200円（税抜）＝220円（税込）` も
  「卸/仕入 + 税抜/税込 + 金額」の共起でブロックされる。
- 通った書き方：**「1点あたりの原価を 220円（消費税込み）と置いた場合」**＋表の列名を
  `原価100円 / 原価200円 / …` という**仮定の刻み**にする。特定商品の実額に紐づけない。
- 特定商品の採算は **原価率（%）で書く**（法務判定どおり率は可）。例「原価率59.4%」。
- **書き込み前に自分でフックを回せる**：
  `python3 -c "import json;..."` で tool_input JSON を作り
  `python3 .claude/hooks/source-terms-guard.py < in.json` → exit 2 なら要修正。**納品前に必ず通す。**

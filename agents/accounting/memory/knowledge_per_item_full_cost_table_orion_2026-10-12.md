## 1. 再利用する表の行（この順で積む）

① 売上（税込）→ ② 販売手数料（料率×1.1・750円の崖判定）→ ③ FBA 配送代行（実寸→区分。Keepa pickAndPackFee と一致するか照合）→ ④ 保管（料率×体積×計上月数＝消化月数÷2、10〜12月は10.087）→ **⑤ Amazon 入金** → ⑥ 卸（税抜）→ ⑦ 卸の消費税（免税＝原価算入）→ ⑧ 卸→代行の送料按分 → ⑨ おりおん作業（ラベル11＋検品11／点、荷受22＋プラン55／SKU、箱代／箱、×1.1）→ ⑩ FC 納品送料（608円/箱）→ ⑪ おりおん保管超過（月6,050円÷点数）→ ⑫ 返品引当 → ⑬ 振込 → ⑭ 総原価 → ⑮ 手残り・利益率・等級。最後に**検算行**。

- ロット表は「Amazon の外で出ていくお金」と「Amazon 入金から差し引かれるもの」を分ける。資金繰りの谷は**FC 納品送料も含める**（売上残高が無ければカード請求＝先に出る）。預かり金3万円は別枠。
- 閾値は「卸単価を動かす」「売価を動かす」の2表。二分法で解く（返品引当が原価連動なので1次式で解けない）。

## 2. 効いた発見

1. **1箱の点数は「物理的に入る数」で決まる。**30×24×11cm は140サイズ（60×45×35）に8個しか入らない → 20点で3箱。§3.4 の「1箱約1,136円」は15kg帯の箱代（480円）前提で、このぬいぐるみは〜10kg帯（370円）。代表値をそのまま使わず、寸法から箱数と重量帯を出す。
2. 卸率67%（SD 実測）では C（1個 ▲359〜▲540円）。黒字は卸率58.2%、B は54.0%。マサル 02（54.8%）とほぼ一致＝独立に組んで0.8ptの差なら、モデルは信用してよい。
3. 等級 A は「悲観値で手残り400円」の方が利益率20%より先に効く（高単価品では OR の400円が支配する）。

## 3. 公開版の書き方（出所ガードで4回止められた）

- `仕入れ値` `上代` `卸単価` `振込手数料` は**ラベル**。同じ行や表の直前5行に金額があると止まる。HTML の表を1行で書くと表全体が1行扱いになり必ず止まる → `<tr>` ごとに改行する。
- 卸の消費税「1点301.5円」は卸値を逆算できる。**税額も実額扱い**で公開版から消す。
- HTML の JS に上代の定数を書かない（Amazon の参考価格〔税込・公開〕を基準に置いた）。
- 書いたら必ず `source-terms-guard.py` に JSON を流して exit 0 を確認（Bash で書くと PreToolUse が走らない）。

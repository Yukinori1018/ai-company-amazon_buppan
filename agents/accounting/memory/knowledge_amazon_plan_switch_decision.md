## 訂正の中身 — なぜ「月49個」だけで判断してはいけないか

月49個は「月額 vs 成約料」の**費用の比較にすぎず、売上側の制約を見ていない**。

| 事実 | 確度 |
|---|---|
| **小口ではカート（おすすめ出品）を獲得できない** | 確定（T-20260817-001・公式複数一致） |
| 購入の約8割がカート経由 | 確定 |
| 小口ではスポンサー広告を出稿できない | 確定（公式明記） |
| 小口では一括出品ツール・出品制限申請が使えない | 確定 |
| **FBA代行センター（外注先）は小口契約不可**（大口のみ） | 実測（リサーチャー memory `knowledge_fba_prep_center_official`） |

→ **卸レーン＝相乗り出品はカートが取れなければ構造的に売れない。「49個売れたら大口」はカートが無いと49個に届かない循環矛盾。**
　しかも社長は物理作業の外注前提なので、小口だと外注先の選択肢まで狭まる。

**正しいトリガー：初回 FBA 納品プランを作る直前。** 販売個数ではなく工程で切る。小口→大口は即日反映なので前倒しで払う理由はゼロ。
（この結論自体は T-20260817-001 で既に出ていた。自分の 2026-06 の基準がそれと矛盾したまま残っていたのが問題）

## 「固定費を前倒しで払う案」を評価する型（再利用可）

A案（今すぐ課金）と D案（後で同じことをする）の比較は、**総額ではなく増分で見る**。

```
増分コスト = 月額 × （今 〜 本来払い始めるべき時期）の月数
増分便益 = 「便益を何週間早く得られるか」×（1週あたり便益）
```

今回の実例：
- 増分コスト＝5,390円 × 楽観3／中央5／悲観8ヶ月 ＝ 16,170／26,950／43,120円
- 増分便益＝SD を2〜4週間早く使える ＝ 0／750／3,000円
- **差引は全シナリオでマイナス。「復旧が明日でも1ヶ月分5,390円 > 便益上限3,000円」で即決できる。**

**この型は「今契約すべきか、後で契約すべきか」全般に効く。** 総額で比べると「どうせいつか払う」で流されるが、
増分で比べると答えが1行で出る。

## もう1つの決め手 — 相手側の期限

SD には「翌々月末（2026-11-30）までにサイトオープンが確認できないと利用停止」という別条件があった。
中央・悲観シナリオでは、A案で月額を払っても**その期限までに販売開始できず、払った分が全額ドブ**になる。

→ **固定費の判断では「自社の回収時期」だけでなく「相手方の期限」も必ず突き合わせる。**
　今回はこれが「A案が意味を持つのは楽観シナリオだけ」という限定を生み、結論を決定づけた。

## 無料の代替を必ず1つ探してから結論を出す

A案（月5,390円）の対抗馬として BASE を調べた。

| BASE | 実測（`thebase.com` 公式・2026-09-04） |
|---|---|
| スタンダードプラン | **初期0円・月額0円**／決済手数料 3.6%＋40円 ＋ サービス手数料 3% |
| グロースプラン | 月19,980円（月払い）／決済2.9%・サービス0円 |

→ **売上ゼロの月のコストが0円**。「固定費 vs 変動費」の教科書どおりの構図で、立ち上げ期は変動費型が正解。
　同種の判断（月額サービス vs 従量課金）では、まず**売上ゼロの月にいくら出ていくか**を並べること。

**ただし「無料だから即やる」と書かない。** BASE 登録は規約同意＝§4.1、特商法表記で電話番号の新規開示が要る。
金銭0円でも非金銭コストは必ず洗って併記する。

## 2026-09-12 追記：前提が変わったあとの再試算（T-20260904-005 / 06）

日本ストアが再開し（北米は停止中）、1周目がメーカー直一本になった状態で、A案（SD のために大口へ切り替える）を計算し直した。

### 学び1：「どのみち大口が要るなら、追加費用はほぼ0円」は誤り
秘書の見立ては「ケース1なら追加費用はほぼ0円」だった。数えると、そうならない。
- ゲートの解除申請にはメーカーの請求書が要る → 請求書は**発注の後**に出る → 大口が要るのは早くても発注の時点（中央 10/20〜11月前半）。9/16 に切り替えると2回分 10,780円の前払い
- 1周目で取引が成立しない確率が60〜76%（推測）。その場合、1周目の中で大口を使う場面がない
- **「本来の切替日」は、事業が進んだ場合の日付でしかない。** 進まない確率で重み付けすると、A−D は −16,600〜−18,600円
→ **固定費の前払いは「どのみち払う」で済ませない。事業がその工程まで進む確率を掛ける。**

### 学び2：シナリオ名が確率とずれることがある
今回の「悲観（不成立）」は、いちばん起こりやすい結果だった。3シナリオの中央を推奨値にする規則は守ったうえで、確率で重み付けした値を別の行に並べ、「悲観がいちばん起こりやすい」と明記した。

### 学び3：固定費を「予算の枠」に入れるかは、損益の開示とは別の問い
- 10万円は在庫に賭ける上限。大口の月額は事業に付く固定費。枠に入れて効くのは、2社目の発注を削る場面だけ（1社成立なら、入れても入れなくても同じ）
- 月額を SKU ごとに割り振ると、1点あたり 323〜647円（1周目の数量）。利益率5% の判定がほぼ全件赤字に見えて使えなくなる
→ **推奨の型：枠には入れない。締めの報告は「SKU の損益」と「事業損益（固定費込み）」の2段で出す。最悪いくら出ていくか（今回は 116,170円）を1行で添える。**

### 学び4：依頼の途中で調査結果が届いたら反映する
「ケース1か2かは断定するな」は、サトルの結果が出る前の指示だった。05 が届いた時点で「カートは公式に大口の機能＝ケース1の可能性が高い」と明記し、ケース2の表は参考として残した。

### 手順（再利用）
1. 前回の試算の前提を列挙し、変わったものに印を付ける（今回：復旧シナリオが消えた／経路がメーカー直一本／予算が5万→10万）
2. 本来の切替日を「その機能が初めて必要になる工程」で決め、その工程に着く確率を別に持つ
3. 前払いは「本来の切替日より前の課金回数 × 5,390円」で数える（日割りなしを仮定）。期間は1周目の締めで区切る
4. 便益は「その経路が1周目で使われるか」を先に見る。使われなければ、1周目の便益は0円
5. 社長の決定の**トリガーの文言**を読み直す（今回：「カナダが出品中に戻ること」。日本の再開だけでは引かれていない）

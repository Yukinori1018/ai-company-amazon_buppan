# キャッシュの物理 — 入金サイト・経路別CCC・12ヶ月累計キャッシュの境界（T-20260914-003 / 2026-09-14）

社長差し戻し（「12ヶ月で現金が増えない事業はダメ」・運転資金200万・予備25万）を受け、案に依存しない
現金の計算器を先に作った回。成果物: `workspace/output/deliverables/T-20260914-003/00_キャッシュフローの土台.md`＋`00_cf_base.py`。

## 1. いちばん効いた発見：「全額再投資」だと12ヶ月で現金は増えない

- 12ヶ月累計キャッシュ（実質）＝ 12ヶ月の利益 −（12ヶ月末の在庫＋売掛−未払）。**仕入れを伸ばすほど利益が在庫に化ける。**
- 卸11%・回転2ヶ月・毎月全額再投資：利益 +157万 / 実質現金 −60万。刈り取り（最後の3ヶ月は発注しない）で +123万。
- 成長（仕入れ毎月+25%）では全ケース利益プラス・現金マイナス。最薄月は成長の最後に来る。
- **社長の「現金が増える」は、実質現金（現金−未払）と純資産（在庫込み）で答えが真逆になる。定義を先に揃えること。**
  推奨は実質現金を設計条件、翌年の税引当を引いた値を悲観に併記（論点としてカズヨへ）。

## 2. 境界線（目安・資金律速・国内の卸/メーカー直）

**回転1ヶ月で利益率約10%、1ヶ月延びるごとに約+3pt。** 回転3ヶ月なら約16%。
仕入れ月20万規模なら固定費の分 +2〜3pt。中国輸入・OEM は前払い＋リードで +3〜4pt。
→ 現行 v1.3 の下限（5%・消化3ヶ月）は新条件を満たさない（−137万）。次に「5%でも数を打つ」案が出たら、この表を当てる。

## 3. カードの猶予は「最薄月」にだけ効く

- カード払いは CCC を 65日→13日 に縮めるが、12ヶ月累計キャッシュの境界は0.3pt以内しか動かない（12ヶ月末の未払として差し引かれるため）。
- 効くのは資金ショート防止（最薄の現金を80〜120万押し上げる）。
- 口座残高だけで判定すると、カードの未払がある分だけ良く見える。枠無制限の例では +51.7万に見えたが、未払112万を引くと実質はマイナス。**累計キャッシュは必ず「現金−未払」で出す。**

## 4. 失敗とリカバリ：解析式で境界を出すと半分に見積もる

最初は「必要利益率 ≈ 運転資金月数/12 ＋ 固定費率」の定常解析で出したが、卸カード回転2で5.6%と出た（シミュレーションは12.8%）。
原因は2つ。①カードの猶予を枠無制限で入れていた（実際は枠50万で頭打ち）②立ち上がり（最初の0.5〜2ヶ月は売上ゼロ）と、12ヶ月末に在庫を抱えている分を無視していた。
**境界は解析式でなく日次シミュレーション＋二分探索で出す。** 解析式は直感の説明用に留める。

## 6. 税の現金影響で押さえた点

- 社長は給与所得者（勤務先の社会保険）→ 国保・国民年金は増えない。増えるのは住民税（翌年6月〜・普通徴収なら事業口座から）。
- 12ヶ月の窓（2026-10〜2027-09）で出るのは2026年分（10〜12月）の税だけで、ほぼ0円。**本当の税は2027年分として2028-03以降に出る**（OEMテストで約155万）。窓の中で「黒字」でも13ヶ月目以降に税で吹き飛ぶ案がある → `after_window_tax` を必ず併記。
- 輸入消費税は免税事業者には控除できない＝原価。
- 消費税は2027年の課税売上1,000万超で2029年から課税。特定期間は給与支払額で判定可（給与0なら2028年は免税）。税理士確認推奨。

## 手順（同種の依頼＝「案に依存しない現金の土台を作って」）

1. 入金側（Amazon 周期・留保・着金）と支払い側（経路×支払い方法）を、一次→二次→推定の順で表にする。台帳・S-b を先に読む
2. 日次・決定論のエンジンにする（月次だとカードの締めと14日周期がずれて誤差が出る）
3. 利益（発生主義）と現金を別に出し、**純資産の増加＝累計利益** の恒等式で検算する（両テストで差0円を確認済み）
4. 境界は「毎月同額を12ヶ月」×二分探索（資金律速／需要律速2水準）で出す
5. 窓の外の税・カードの未払・留保ストレスを必ず別行で出す
6. 実行時間：全出力約4分。`--quick` で §1〜3 のみ

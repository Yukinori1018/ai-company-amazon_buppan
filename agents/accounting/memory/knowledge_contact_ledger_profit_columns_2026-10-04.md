## 再利用できる手順（同種依頼「リストに採算欄を足して」が来たら）

1. **まず raw キャッシュを全部読む（`raw/prod*.json.gz`）。** 今回 Keepa 追加取得は0 token。
   `prod_all_*`（stats=365・offersなし）は**カート価格の統計が -1**（offers/buybox を付けないと BuyBox は埋まらない）。
   同フォルダの `prodbb_*`（buybox=1 で取った代表ASIN）に `avg90[18]` が入っていた。**glob は `prod*` で両方拾い、後勝ちで prodbb を優先。**
2. 平時売価＝`stats.avg90[18]`（BUY_BOX_SHIPPING）→無ければ `avg90[1]`（新品最安）。現在価格は使わない。
3. 料率：Keepa `referralFeePercentage` は 10.39/10.41 等に揺れる＝公式の段に寄せる。**税抜表示なので ×1.1**。
   価格帯で段が変わるカテゴリ（ビューティー・ドラッグ・食品：8.4→10.4／ペット・ベビー：8.4→15.4）は平時売価で引き直し高い方。
4. FBA：`fbaFees.pickAndPackFee` → 公式表で区分逆引き → 平時売価の列（1,000円境）を選び直す（タカシの手と同じ）。
5. 保管料はパッケージ実寸×10〜12月単価×（消化月数÷2）。納品・その他は「608円/箱＋段ボール250円」を初回個数で按分＋ラベル22円、**下限100円**。
6. 上限＝P×(1−目標率)−Amazon側コスト。**免税事業者なので税込で持ち、税抜換算列を併記**（見積りは税抜で来る）。

## 失敗とリカバリ

- **lambda の `x and x > 0` は -1 で False を返す（None でない）。** `is None` 判定をすり抜けた。`is not None and > 0` で書く。
- **`source-terms-guard` は自社計算の列名でも止める。**「卸値」「掛け率」の直後15文字以内に数字があると NG
  （`上限卸値_利益率20%`、`r0(` の 0 まで拾う）。列名は**数字を前に置く**（`利益率20%の上限卸値`）、関数名に数字を入れない。
  書く前に `python3 .claude/hooks/source-terms-guard.py` に JSON を流して exit 0 を確認する（前回 memory §7 の手順が今回も効いた）。
- BSD sed に `\b` は無い。置換は Python で。

# 仕入れ上限価格の計算式 — 2系統の違いと落とし穴（T-20260817-005 / 2026-08-23）

社長から「Googleシートの『想定仕入価格(上限)』はどう計算しているのか」「B0DWMPV656 を1個売ったときの内訳」を問われた回。
**同じシートに名前の似た仕入れ上限が2系統4列あり、意味が全く違う。** 今後この質問が来たら本ファイルを見れば即答できる。

## 系統① T-20260804-001「想定仕入価格(上限)」
出典: `workspace/output/deliverables/T-20260804-001/maker_scan.py` の `reverse_buy()`

```
上限 = Amazon価格 − 販売手数料(max(価格×料率, 最低手数料)) − FBA配送代行 − 納品送料 − その他経費100 − Amazon価格×25%
```
定数: `TARGET_MARGIN=0.25` / `OTHER_COSTS=100` / `INBOUND={small150, standard_1 250, standard_2 300, large_1 380, large_2 480}`
料率とFBA額は `workspace/output/agent_output/T-20260521-005/code/calc/fees.py`。

**意味＝「純利益率25%を取れる交渉上限」。赤字ラインではない。** 社長はここを誤解しやすい（実際に質問された）。
赤字ラインは `Amazon価格 − 手数料類` で、25%分だけ上にある。

## 系統② v1.3（T-20260817-005 `scan_v13.py`）
- `損益分岐仕入れ値` = 過去1年最安値 × 0.65 − 外注費 ← **メーカーへの提示上限（社長裁可の正式運用）**
- `損益分岐仕入れ値_精緻` = 過去1年最安値 − 販売手数料 − FBA − 外注費（②の検算）
- `仕入れ掛け率上限%` = ② ÷ 現BuyBox価格。**40%未満は実務上買えない**
- 定数: `GROSS_KEEP_RATE=0.65` / `OUTSOURCE_COST={small182, standard_1 282, standard_2 332, unknown 282}`（ラベル22＋梱包10＋納品送料150〜300）

**①は現BuyBox基準（値下がりに弱い）、②は過去1年最安値基準（保守的）。発注判断は②。**

## 見つけた欠陥（次に触る人へ・要修正）
1. ~~両系統とも FBA在庫保管手数料が式に入っていない。~~ **→ 2026-08-24 T-20260817-005で解消。**

   （0.4pt改定より遥かに大きいズレだった）。FBA standard_1は434円→318円。
3. **`_map_size_key()` は重量しか見ない。** 2kg超は全部 `large_1` 以上に丸まる。Amazonの寸法基準（45×35×20cm）を反映していないので、**サイズ区分は常に〔仮〕扱い**。（未解消・次の対応候補）

## 実務上いちばん効く指摘（社長に響いた論点）
**「上限1,725円 ÷ Amazon価格4,680円 = 掛け率36.9%」。メーカー卸の相場は定価の60〜70%。**
→ 条件を満たしていても**そもそも売ってもらえない価格**。数字上のGOと商談上のGOは別物。
掛け率は本来「メーカー希望小売価格」基準であり、Amazon実売基準ではない点も必ず添えること。

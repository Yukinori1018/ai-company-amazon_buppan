# サンリオ系商品の再評価と「まとめて単価を上げる」案の検証（T-20261012-001 / 2026-10-12）

成果物：`deliverables/T-20261012-001/01_サンリオIP商品の再評価と組み合わせ案.md`／計算：`agent_output/T-20261012-001/`（calc2.py・bundle.py・old_recalc.py・lib.py）

## 1. 見つけた誤り（他人の成果物を引き継ぐときの型）

- 🔴 **成果物14の卸率の単位ずれ。**原価を「売価×卸率×1.1」で置く式は、卸率を「卸値÷税込売価」と定義している。そこに丸進の「67%（卸値÷上代・どちらも税抜）」を入れていた。
  売価＝上代×1.1（サンリオでは本体売価と1円単位で一致）なら、原価÷売価は**卸率そのもの**で、さらに×1.1は二重課税。天井16.3%と書かれていたが正しくは21.6%（おもちゃ10.4%）。
  **引き継ぐ数字は「何÷何か」を必ず書き下してから使う。**率の名前（卸率）が同じでも分母が違う。
- **本体不在の窓の価格で採算を組むと、原価が上代比例なので実は B〜A に見える。**成果物14の「仕入れタダでも届かない」は旧 FBA 415円と粗利500円基準の産物。いまのモデル＋90日中央値なら C。
  結論（C）は同じでも理由が違う（「単価が低い」ではなく「平常価格に戻ると C」）。
- 成果物10は販売手数料を税抜のまま（114円）使っていた。正は×1.1（126円）。

## 2. 再利用できる式・数字

- **利益率の天井＝1 − 料率×1.1 − 卸率÷k**（k＝売価÷(上代×1.1)。平常価格なら k=1）。
  卸率67%：750円以下27.5%／おもちゃ21.6%／ホーム15.4%は16.1%。
- **まとめ売りで動くのは固定費の分散だけ。天井は動かない。**750円以下の品をまとめると料率が上がり天井が3.7〜5.9pt下がる。
- キティ マスコット（1,100円・おもちゃ）を卸率67%で：1個 C(−274) → 3個 B(5.3%) → 4個 B(1パック403円) → 10個 A(14.3%)。KPI 20%は卸率55%なら4個、60%なら10個、67%では不可。
- **§3.5 の「1個手残り400円」はパックに当てると大きいパックほど通る**（10個パックで A、1個あたり157円）。等級の定義の穴として秘書に渡した。
- Keepa の `referralFeePercent` が 10.41 のように公式の段をわずかに超えると、`fba_cost.referral_pct` は**次の段（12.4%）に切り上げる**。queue の上限が少し厳しく出る。今回は ±0.15 以内を公式の段に寄せて計算した（IT に渡す候補）。
- サンリオ本体ブランドは Keepa の参考価格（cur[4]）＝上代（税抜）。ライセンシーは税抜/税込が混在の可能性。

## 3. 判断の結論と理由

- サンリオ品の N 個パック：既存の「×N」ページは本体専用・単価1.000倍（成果物11）＝§3.3-1 で不可。新規ページはハルオが不可。→ 採算が合っても打ち手にならない。
- 「本体が在庫切れの間だけ売る」：窓は4日〜2週間、仕入れ→販売開始は2〜4週間。在庫が着く前に窓が閉じる。
- 有望なのは**本体が来ない棚（ライセンシー品・食玩）**。ただし食玩は期限と価格下落、水筒は季節を必ず見る。

## 4. 手順の落とし穴

- 🔴 **Bash で成果物を書き換えると出所ガード（PreToolUse）が走らない。**自分で `source-terms-guard.py` に JSON を流して確認した（knowledge_cost_model_v2 §7 の手順）。
- ガードは「上代」「卸値」の**15文字以内の数字**と、**ラベルから5行以内の表の数値セル**を止める。Amazon の売価でも止まる。
  通る書き方：SD の条件は「卸率◯%」だけ（卸率は単独ならラベルではない）。「卸値」「上代」は数字の無い行にだけ書く。
  N個パックの棒グラフは円ではなく**売価に対する%**で描く（円で描くと原価の円＝卸値の実額が出る）。
- `string % data` 形式の HTML テンプレートは本文の「%」で壊れる。`.replace('%%DATA%%', json)` を使う。
- 🔴 **ASIN ごとの「B になる卸率」も Keepa B クラス**（90日中央値から作った損益分岐仕入れ値の一種・成果物08）。1回目の commit で50 ASIN 分を公開表に出してしまい、直後に帯（P1/P2/P4）へ圧縮した。
  **ASIN を20件以上含む表を書く前に、列ごとに「Keepa の履歴を通った値か」を Q2 で判定する。**取り分（monthlySold÷(オファー+1)）と現在価格は A クラスで可。

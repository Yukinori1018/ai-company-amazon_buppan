## 3. NETSEA送料の罠 — フィールドが0でも「送料無料」ではない

- `/items` の `ship_fee` は **257,067件中951件（0.37%）にしか値がない**。残り99.6%は0。
  0を送料0円として計算すると、**送料をほぼ計上しないまま利益判定していることになる**。
- **送料の実額は別エンドポイント `/tariffs` にある。**都道府県別＋金額段階別。
  `gradual_border_price` と `price2` の組で読む。**`price2 == 0` のときだけ「その額以上で送料無料」**。
  `price2 > 0` は「安くなる」であって無料ではない（ITタカシの `read_tariff()` に正しく実装済み）。
- `apply_type: higher` = 複数社の商品を1カートに入れると**高い方の送料が適用される**。
- 実データ1社で **20,000円以上で送料無料**。予算5万円なら1社に2万円寄せれば送料ゼロにできる。
  → **サプライヤー集約は「手間の話」ではなく「送料を0にする話」**。ここが候補数を半減させる分岐点。

これは memory `knowledge_verify_field_semantics_not_names`（列名から意味を推測しない）と同じ事故の系統。
**「値が0」を「そのコストが0」と読むな。「未取得」かもしれない。**

## 5. 保管月数の考え方（今後も使う）

**保管料は月次の平均在庫量に課される。**N ヶ月で線形に売り切るなら、平均在庫は初期数量の1/2。
→ **計上すべき月数 = 消化月数 ÷ 2。**3ヶ月消化なら1.5ヶ月。旧2.0ヶ月は1.33倍の過大。
ただし**保管料は絶対額が小さい**（標準1・2Lで30円/点）。ここを精密化しても判定は動かない。
**時間を使うべきは基本成約料と送料。**

## 7. 訂正：e-fba「月額0円・12円/点」は片側だけ読んだ値だった（2026-09-30 / T-20260929-001）

サトルの公式値ファクトシートで判明。e-fba.com を再取得して確認した（2026-09-30）。

| 項目 | 9/4 の採用値 | 公式ページの実際 |
|---|---|---|
| 月額 | 0円 | 「月額費用は無料」＋同じ「料金に関して」節に**基本保管料 スチールラック1本3,000円/月（税別）** |
| ラベル | 12円/点（資材込） | 料金表は12円/点。別の段落に**「1個50円（税別）」**（資材・インク込み） |
| 税 | 税込扱いで計上 | **税別**。12円は税込13.2円 |

**損益モデルへの影響は小さい（数値修正は不要と判断）。**理由：モデルが使っているのは e-fba の単価ではなく
「納品代行12円＋納品送料37.5円＝**49.5円/点**」という合算値で、これは14社の公式値で検算すると妥当な側にある。

| 納品コスト（代行＋FC送料・税込） | 楽観 | 中央 | 悲観 | 出典 |
|---|---:|---:|---:|---|
| 月100点・継続月 | 36円/点（びーぷらす） | 42〜50円/点（おりおん／自宅＋Amazonラベル） | 74円/点（e-fba・保管3,000円込み） | T-20260929-001 §5-2 |
| 初回12点・1箱 | 108円/点（びーぷらす） | 116円/点（自宅受け） | 404円/点（e-fba） | 同 §5-1 |

- 月100点では 49.5円/点 は中央帯。e-fba を選ばない限り過小ではない。悲観（e-fba）との差は+24.5円/点＝単価2,200円で1.1pt。
- 初回12点では 49.5円/点 は過小（実際は108〜116円/点）。ただし商品台帳 L001 は納品送料64円＋資材55円＝119円/点で計上済み。
- 固定費は「納品代行 月額0円」でよい（びーぷらす・おりおんは月額なし）。**e-fba を選ぶ場合だけ固定費3,300円/月（税込）を足す**。

**学び**
- 1社の公開料金を「業界の代表値」として置くと、その会社の料金ページの矛盾まで引き継ぐ。代表値は複数社の分布（楽観/中央/悲観）で置く。
- 代行の単価は**点数規模で5〜10倍動く**（12点で108円、100点で36円）。固定費（箱代・荷受/SKU・プラン代）が効くため。1点あたりの単価で置くなら、想定する月の点数を必ず併記する。
- 料金ページは同じページ内で矛盾していることがある。「月額0円」の近くに保管料・最低料金がないか、ページ全体を読む。

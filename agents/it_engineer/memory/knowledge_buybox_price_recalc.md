# カート価格・大口で利益を引き直す手順と、効いたのはどちらか（T-20260909-002 / 2026-09-12）

## 結論（数字の桁だけ。実額は out/）

- 系統誤差は2つ（小口の基本成約料110円、売値＝最安値）。**効いたのはほぼ成約料だけ**。
  5%未満→5%以上に戻った40件のうち39件は成約料0だけで戻った
- **カート価格の90日平均は、最安値とほぼ同じ**（221 ASIN で中央値の比1.000、90パーセンタイル1.05、最大1.19）。
  「カートは最安値より高い」は1件の例（アミノ）からの一般化で、全体では成り立たなかった
- 最終候補（5%以上・回転6ヶ月・最小ロット10万）は 12 → 27。「NETSEA は1件だけ」は誤りだったが、
  原因は価格ではなく**大口化の反映漏れ**

## Keepa でカート価格を安く取る方法

- `product?stats=90&buybox=1`（**offers なし**）で **3 token/ASIN**（実測 3件=9 token、221件=663 token）
- 値は `stats.avg90[18]`（BUY_BOX_SHIPPING の90日平均）、現在値は `stats.current[18]`。-1 は無し
- offers=20 付き（約6.5 token）は不要。平均価格だけなら buybox=1 で足りる

## 手順（再利用できる形）

1. 価格に依らない条件（入数解決・選定・回転・最小ロット予算）を**先にローカルで全部当てる**（Keepa 0）
2. 「カートが最安値の1.3倍でも5%に届かない」行を落としてから取る（578 → 221件）
3. 取得後に比の分布を見て、足切り倍率が安全だったか確かめる（最大1.19 < 1.3 で問題なし）
4. 修正前・成約料0だけ・両方の3通りで計算し、**どちらの修正が効いたかを分けて報告する**

実装: `workspace/output/deliverables/T-20260909-002/recalc_buybox.py`（plan / fetch / report）、
出力層は `report_buybox.py`。キャッシュは `agent_output/T-20260909-002/buybox90.jsonl`。

# 「控え ⇔ 実体」乖離検知フックの設計（検知だけを実装する）

作成: 2026-09-02 / T-20260902-004（タカシ）
対象: `.claude/hooks/session-start.sh` リマインダー⑥
関連: T-20260902-003（控えの作成）、T-20260902-002（資産の導入）

## 1. 何を作ったか（1行）

リポジトリ内の控え5ファイルと `~/.claude/` の実体を `cksum` で突合し、
**乖離しているときだけ**セッション開始時に警告する。**同期はしない。**

## 2. 社長の明示条件 —— ここが設計の本体

> 「セッション開始フックは cksum の突合と警告表示のみ。自動同期・自動コピー・自動 commit は実装するな。
>  どちらが正かを機械が判断できない。実体が新しいのか、控え側の巻き戻しが意図的なのかは人間しか分からない。」

**「検知」と「修復」を分けるのが正しい**という判断。実装者としては
`cp` を1行足せば「親切」になるが、それは**編集を失う**。
機械が判断できないものを機械に判断させない。これは YAGNI ではなく安全設計。

代わりに満たすべきは「人間が3秒で判断できる情報を出す」こと：
- 両者の**更新時刻（分まで）とバイト数と cksum**
- **どちらが新しいか**を明示（ただし「だから正しい」とは書かない）
- 判断後に打つ `cp` を**文字列として**両方向ぶん提示（実行はしない）

## 3. 「古い控えは、控えが無いより危険」

T-20260902-002 の退避アーカイブは**作成翌日に既に657バイト古かった**。
控えが古いと「バックアップがある」と誤認させる。だから
**控えを作った時点で、鮮度を見張る仕組みまでがワンセット**。
README に「更新すること」と書くだけでは風化する（`_inbox_社長共有` 21件・12日間と同じ構造）。
→ **文書の約束は、機械のチェックに変換して初めて守られる。**

## 4. 実装メモ（bash / このリポの流儀）

- **対応表は1箇所の配列**。控えと実体で**相対パスが共通**になるようディレクトリ構造を揃えてあるので、
  `RESEARCH_MIRROR_PATHS=( "agents/research-collector.md" ... )` の1本で済む。増えたら1行足すだけ。
  ペアを2列で持つ設計にすると必ず片側だけ直して壊れる。
- **`set -euo pipefail` 下では `A && B && continue` を書かない**。
  最後の `continue` に到達しない（＝リストが非0で終わる）と errexit で**フックごと落ちる**。
  必ず `if ...; then continue; fi`。今回いちばん踏みやすい罠。
- `cksum "$f" | awk '{print $1}'` は pipefail で落ちうるので末尾に `|| true`。
- 時刻・サイズは BSD(`stat -f`) と GNU(`stat -c`) の両対応を関数に隔離し、
  取れなければ「不明」を返す。**フックはセッション開始を絶対に妨げない**（常に `exit 0`）。
- `$HOME/.claude` が無い環境（クラウド実行）は `[ -d ]` で素通り。
- 出力する `cp` の `$HOME` は**展開せずに文字列として出す**（`\$HOME`）。このリポは PUBLIC で、
  出力にユーザー名を載せない。控え側はリポジトリルート相対にして短く保つ。
- **両側とも欠損なら黙る**。資産ごと廃止したものを鳴らし続けるフックは、3日で読まれなくなる。
- 掲出位置は「異常時だけ出るもの」を前列へ（① → ⑤ → ⑥ → ③ → ④ → ②）。
  平常日は1行も増えないので最前列に置ける。長い一覧（②）の後ろに置くと埋没する。

## 5. 検証のやり方（実ファイルを1バイトも触らずに3ケース通す）

`MIRROR_LIVE_ROOT="$HOME/.claude"` / `MIRROR_COPY_ROOT="$REPO/..."` と
**ルートが環境変数由来**なので、`HOME=` と `CLAUDE_PROJECT_DIR=` を差し替えるだけで
**本体スクリプトを改変せずに**異常系を作れる。

```bash
# 実体側が新しい／欠損 → 偽 HOME にコピーを置いて壊す
CLAUDE_PROJECT_DIR="$REPO" HOME="$SP/fakehome" bash .claude/hooks/session-start.sh
# 控え側が欠損 → 偽リポジトリを CLAUDE_PROJECT_DIR に渡す
CLAUDE_PROJECT_DIR="$SP/fakerepo" bash .claude/hooks/session-start.sh
```

テスト用に**本物を書き換えて後で戻す**のが最も事故る。**壊すのは常にコピーの側**。
それでも最後に実ファイル5組の `cksum` を再照合して、T-20260902-003 の記録値と
一致することまで確認する（今回5/5一致）。

## 6. 再利用できる形（同じ依頼が来たら）

「リポ外にある正 × リポ内の控え」の組み合わせは今後も増える（`~/.claude/` 配下、`~/.config/` 配下など）。
そのときは⑥をコピーせず、**`RESEARCH_MIRROR_PATHS` と同じ形の配列＋ルート2つ**を
別ブロックとして足すか、対象が3系統を超えたら配列を
`"<ルート名>|<相対パス>"` の1本に一般化する。今は1系統なのでベタ書きで十分（YAGNI）。

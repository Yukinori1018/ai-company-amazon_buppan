# NETSEA Buyer API 実務メモ（実接続で判明したこと・2026-08-31 / T-20260831-006）

`knowledge_netsea_buyer_api`（＝**何に使ってよいか**の規約メモ）の姉妹編。
こちらは **実際に叩いて分かった技術的な事実**だけを書く。仕様書に載っていないものが多い。

## 0. 前提：API が返すのは「承認済みサプライヤー」だけ

NETSEA 全体のカタログは舐められません。**取引申請が承認済みの相手の商品しか返りません。**
＝ 母集団は「自分が承認されている社」で決まります。ここを勘違いすると設計が丸ごと崩れます。

**当社の実測（2026-08-31）: 承認済み 225社。ログイン不要で API から取得できます。**
（社長の「メールで仕入れられるメーカーが確認できる」は、この一覧のことでした。**ログイン依頼は不要でした。**）

## 1. `/suppliers` は100件で黙って打ち切られる ← 一番危ない

**OpenAPI 仕様に記載がありません。** 実機で発見しました。

```
GET /suppliers                      → data 100件 ＋ next_supplier_id
GET /suppliers?limit=200            → data 200件（limit が効く）
GET /suppliers?next_supplier_id=... → 続き
```

`adapters/netsea.py` の旧 `list_suppliers()` はページングしておらず、
**225社中125社を静かに取りこぼしていました。** 「仕入れられる相手が誰か」を数え違える
＝母数の欠落なので、これは静かに効く事故です。修正済み。

> 教訓: **ちょうど100件・ちょうど1000件が返ってきたら、それは全件ではなく1ページ目を疑う。**
> レスポンスのトップレベルに `next_*` が無いかを必ず見る（`data` 以外のキーを列挙する）。

## 2. ヒット0件は `{"data":[]}` ではなく **素の `[]`**

既知の罠だが実際に踏んだ。承認済みでも商品0件の社が実在します（225社中に複数）。

```python
rows = payload.get("data", []) if isinstance(payload, dict) else (payload or [])
```

これを書かないと `AttributeError: 'list' object has no attribute 'get'` で落ちます。

## 3. 正しい粒度は「商品」ではなく「規格（set[]）」

1商品が複数の `set[]`（規格・枝番）を持ち、**規格ごとに JAN も卸価格も違います**。
Amazon 側は JAN 単位で別 ASIN なので、**規格1件＝候補1件**に展開するのが正しい。

実測: 商品3,303件 → 規格展開 **6,690件**（約2倍）。商品単位で数えると母数が半分になります。

- JAN は `set[].jan_code` を優先し、空ならトップレベルの `jan_code` で補う
- 卸価格は `set[].price`（**単価・税抜**）。`set_price` は「1口ぶんの税込額」＝実質の最小発注額
- `set_num > 1` は「その個数単位でしか買えない」。単価が安くても寝かせる現金は set_num 倍

## 4. **JAN を持つのは約36%**

規格6,690件のうち **4,282件（64%）が JAN なし**。
JAN が無いと Keepa の1トークン検証に載せられません（商品名検索は10トークン/回＝16倍）。
**「卸サイトから取れば JAN が揃う」は成り立ちません。** 見積りは36%で立てること。

## 5. 利益判定に効くフィールド（YahooItem 正規化で落ちるもの）

`list_supplier_items()` は共通型 `YahooItem` に正規化しますが、その過程で下記が落ちます。
利益計算をするなら **`list_supplier_items_raw()`（今回追加）** を使うこと。

| フィールド | 何に効くか |
|---|---|
| **`deal_net_shop_flag`** | **ネット販売可否（Y/N）。N は法務判定で「利益が出ても除外」** |
| `reference_price` | 上代。**0トークンの前段フィルタ**（上代でも利益が出ないなら Keepa を引かない）に使う。**空文字で返ることが多い** |
| `set_num` / `set_price` | 最小発注のまとまりと金額 |
| `ship_fee` / `ship_fee_type` | 送料。実測では 0 の商品が多い。実額は `/tariffs` で別途 |
| `consumption_tax_class` | 軽減税率の判定 |

**`reference_price` は空文字 `""` で返ります。** `int("")` で落ちるので変換は必ず握ること。

## 6. 1サプライヤーの商品数は数十〜2,000超まで幅がある

`next_direct_item_id` で辿ります。上限を決めて打ち切るなら、**打ち切ったことを
coverage に残すこと**（`truncated`）。黙って切ると「取り切った」と誤解します。
実測では多くの社が2,000件の上限に当たりました＝**まだ取りこぼしがあります。**

## 7. レート制限は不明のまま

仕様に記載なし。0.2秒間隔・429は1秒待って1回再試行で、225社の全収集は問題なく通りました。
**分からないものは分からないと書き、保守的に間隔を置く。**

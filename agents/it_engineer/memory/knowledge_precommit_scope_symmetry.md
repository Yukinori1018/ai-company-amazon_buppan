# pre-commit の「散文 vs 行データ」判定は、書式ごとに粒度を揃える

2026-09-06 / T-20260906-003。`.githooks/pre-commit` の非対称を是正したときの記録。

## 何が起きていたか

NETSEA の「強い印」（`netsea.jp/shop/` 等）の走査範囲が書式で食い違っていた。

```
local strong_scope="$content"
[ "$ext" = "md" ] && strong_scope="$rowdata"    # ← md だけ絞っていた
```

`.md` は行データらしい部分だけを見るのに、**`.html` は全文を見ていた**。
その結果、調査レポートの地の文に出た商品URL（法務判定 E で**公開可**とされている情報）で
正当な commit が **3回**止まり、`git add -A` のたびに他の作業まで巻き添えにした。

## 直し方（ガードは緩めない。粒度を揃える）

`.html` は**テーブルのセル**だけを見るようにした。フックのヘッダコメントが元々
そう宣言していたのに、実装が追いついていなかった。

```
html|htm)
  strong_scope="$(printf '%s' "$content" | tr '\n' ' ' \
    | sed 's|</t[dh]>|\n|g' | grep -oE '<t[dh][^>]*>.*' || true)"
  ;;
```

**★セルの中身は入れ子のタグごと取ること。**
最初 `<t[dh][^>]*>[^<]*` と書いたら `<td>` 直後のテキストしか取れず、
`<td><a href="…">` のようにリンクにした行データを**丸ごと取りこぼした**。
一度は「直った」ように見えたが、それは誤検知が消えたのではなく検知力が落ちただけだった。

## 検証は3点セットで

1. 散文に検知語 → **通る**
2. 表に生の行データ → **止まる**
3. 表にリンク化した行データ → **止まる**

`/tmp` に使い捨ての git リポを作り、`core.hooksPath` を本物に向けて試すのが速い。

## 残った論点（自分で決めない）

`netsea.jp/shop/`（商品URL）が「1件で止める強い印」に入っているが、
**法務判定 E は商品URLを公開可としている。** 表の中に URL が入っている調査レポートは
今も止まる。これは走査範囲の問題ではなく**分類の問題**なので、
法務ハルオ／社長の判断を仰ぐこと。フックの側で勝手に外さない。

## 結論

「そもそもメーカーはそんなにあるのか」には、API 0回で答えられる。
T-1（Keepa 取得済み）・ギフトショー出展社・NETSEA 取引中を社名で名寄せすると、打診対象は **2,331社＝月300通で約7.8ヶ月**。
1カテゴリに絞ると200〜450社＝1〜1.5ヶ月で尽きる。3ソースの重なりは1〜3%で、名簿を足すほど分母は増える。

## 覚えること

1. **T-1 の会社の単位は `nrm(メーカー or ブランド)`**（t1_classify.nrm）。メーカー列だけで数えると 1,925／855 になり、漏斗の 2,127／994 と合わない。メーカー空欄が399行ある。既存の数と比べる集計は、まず元の数を再現してから先へ進む。
2. **normalize.py の `extract_variants` は文字種の断片も別名に入れる。** 'ABC商事' → '商事'、'XY企画' → '企画'、'…ジャパン' → 'ジャパン'、'(HONGKONG)' → 'hongkong'、'…SHOP'、'…公式店'。社名の突合に使うと一般語で誤一致する。断片は一般語リストで落とし、和文3文字・英字4文字以上に限った（`02_denominator.py` の `_GENERIC`）。初回はこれで約10組の誤一致が出た。
3. **ブランド名で T-1 同士を繋がない。** 1つのブランドに複数のメーカー表記がぶら下がっていることがある（1ブランドに別メーカー3社の例あり）。union-find に入れると別会社が連鎖する。ブランドは「他ソースとの照合」だけに使う。
7. **一致した組は必ず out/ に書き出して目で見る。** 集計値だけ見ていたら誤一致に気づけなかった。ありふれた社名（漢字2文字など）の一致は同名別会社の可能性が残るので、本文では「数件の誤一致を含みうる」と書く。
4. **ギフトショーの機械分類「海外表記」1,224件は過大。** 英字の社名を一律に落としている。海外パビリオン（南1・南2）は416社で、残り約800社の多くは国内の英字ブランド。国内の数は幅（976〜1,622）で出す。
5. ギフトショーの元データは社名とブースだけ。カテゴリはホール＝併催展（東1＝グルメショー、西1・3・4＝LxD・L&D）でしか分けられない。
6. NETSEA の raw（911MB・25.7万行）は1行ずつ読めば16秒。カテゴリ名は `T-20260915-001/out/categories.json`（1,134件）で、category_id の最長前方一致で大分類に引く。

## 手順（同種の依頼が来たら）

1. 既存の漏斗・件数をまず再現する（会社の単位を合わせる）
2. ソースごとに「全体」と「打診対象」を分けて数える
3. 社名キーで union-find。一致した組は out/ に出して目で見る（誤一致の型を探す）
4. カテゴリは共通の粗い分類に寄せ、寄せ方の表をスクリプトに書く
5. 月N通で割って「何ヶ月で一巡」に直す

実装: `deliverables/T-20260915-003/02_denominator.py`。明細は同 `out/`（Git 追跡外）。

# 原価モデル v2 — 固定費は「一律」ではなく「サイズ区分 × 売価の崖」で決まる

2026-10-04 / T-20260920-003 / タカシ

## 結論

**1つの商品の実測値を全商品に当てた定数は、必ずどこかで符号を反転させる。**
`profit.OTHER_UNIT_COSTS_YEN = 206` は 22cm土鍋 L001（体積6,728cm³・FBA標準区分7）1点の実測だった。
小型雑貨（600cm³）の実額は **63円**で、3.3倍の過大。逆に標準8 では **739円**で、3.6倍の過小だった。
**同じ定数が、商品によって過大にも過小にもなっていた。**

## 当てた数字（公式・2026-10-04 時点）

| 費目 | 決まり方 | 幅 |
|---|---|---|
| FBA配送代行 | **サイズ区分 × 売価が1,000円以下か** | 222円（小型・1,000円以下）〜1,756円（大型8） |
| 保管料 | **体積比例**（5.676円/1,000cm³/月・10〜12月は10.087円＝1.78倍）。計上月数＝消化月数÷2 | 小型5.1円〜標準8 280円 |
| FC納品送料 | 箱あたり608円（140サイズ）÷ 1箱の入り数 | 小型20.3円（30個）〜標準8 304円（2個） |
| 梱包資材 | 4.5円 ＋ 段ボール250円 ÷ 1箱の入り数 | 7〜130円 |
| 販売手数料 | **売上の合計が750円以下なら一律5%**（閾値・段階制ではない）。超えたら 8.4/10.4/12.4/15.4% | 最低30円（税抜） |

**薄まるのは納品送料・梱包資材・外注費だけ。**保管料は体積比例、FBA配送代行は1個につき1回。

## 実装で効いた3つの道具

1. **`fbaFees.pickAndPackFee` からサイズ区分を逆引きできる。**
   Keepa は ASIN ごとに Amazon が実際に当てている配送代行額を返す。料金表を反転すれば区分が出る。
   **売価を一緒に渡せば一意に決まる**（1,000円で列が変わるため）。寸法の推定が要らない。
   逆引きできない額（表に無い値）は **None を返して推測しない** — 区分で222〜1,756円まで動くので、
   埋めた瞬間に結論が嘘になる。
2. **Keepa の `referralFeePercent` は整数に丸まる**（実測 15.0 / 10.0 / 8.0）。
   公式の段は 5.0 / 8.4 / 10.4 / 12.4 / 15.4 / 45.4。**切り上げる**（甘くならない向きに寄せる）。
3. **代表体積の配列は、区分の並び順と単調ではない。**
   標準2（280cm³）は小型（600cm³）より小さい。「体積から区分を引く」ときに `FBA` の並び順で
   探すと間違える。**体積でソートした別の並びを持つ。**これを実際に1回踏んだ。

## 750円 / 1,000円の「死に帯」

| 帯 | 何が起きるか | 対処 |
|---|---|---|
| **751〜900円** | 販売手数料が 5% → 15.4%（750円の崖）。750円との差 **−85円** | **750円に下げると手残りが増える** |
| **1,001〜1,100円** | FBA配送代行が「1,000円以下」の安い列から外れる。**−66円** | **1,000円に下げると手残りが増える** |

値付けは**サイズの最適化より効く**。小型と標準6 の固定費差は266円だが、750円の崖だけで85円動く。

## 判定の設計で学んだこと

### 「誤差幅」を費用に足してはいけない

旧実装は「手残り < 売価×7% ＋ 200円 なら UNKNOWN」。**率と定額を足す形は、定額ぶんが
単価の小さい側で暴れる。**売価500円では誤差幅が売価の47%。
**狙いたい低単価帯だけを狙い撃ちで落とす**フィルタになっていた。

代わりに **中央値と悲観値の2本を出し、A/B/C/UNKNOWN の等級**にした。
誤差幅は「いくら損しうるか」ではなく「**どれを人が確かめるか**」を決める道具。

- A = 中央も悲観も利益率20%以上 → 発注候補
- B = 中央で黒字・悲観で20%未満 → **最小ロットで1回だけ実測**（落とさない）
- C = 中央で赤字 → 落とす
- UNKNOWN = 原価・区分・セット数が未確定 → **計算しない**

悲観の当て方：区分1段上／料率をカテゴリー最高段／保管月数2倍／箱の入り数7割。
**売価の悲観（90日平均と現在値の低い方）は価格履歴が無いので当てていない。**
ここで勝手に割り引くと嘘になるので空けた。

### B を UNKNOWN に混ぜると、次に何をすべきかが消える

最初 B を UNKNOWN にしたら GO が0件のままで、「計算できなかった行」と
「最小ロットで試す行」が同じ箱に入った。**行動が違うものを同じ結論にしない。**
採算ゲートは A も B も PASS にし、**どれだけ買うかの違いは等級の列で**出した。

### 等級 UNKNOWN の判定は「粗利が赤字」より先に置く

サイズ区分が決まっていない行で Keepa の生の手数料を使うと粗利が沈んで見える。
その状態で「赤字」と断定すると、**調べれば黒字かもしれない行を NO-GO にする**。
**UNKNOWN の判定を符号の判定より前に置く。**

### 原価モデルを直しても、単位ずれの番兵は外さない

卸率15%未満 / 利益率50%超は UNKNOWN（§3.3-17）。これを一度落としたら、
社長向けリストの**1行目**に卸率2.1%・利益率83%のマスクが出た（まさに過去に焼かれた型）。
**番兵は原価の正しさとは独立の装置。**生成した表の先頭を自分で読んで気づけた。

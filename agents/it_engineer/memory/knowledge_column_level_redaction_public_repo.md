# PUBLIC リポから「列」だけを抜く作業の型（Private 化しない選択をしたとき）

2026-09-06 / T-20260904-004。社長判断は **Private 化しない**。
「機密列を GitHub から抜き、完全版はリポ外に持つ」。既出の**ホワイトリスト .gitignore ＋ pre-commit ゲート**
（`knowledge_public_repo_leak_prevention.md`）の続き。あちらは「これから」、こちらは「もう載っている分」。

## 順序を絶対に間違えない

**退避 → 読めることを確認 → 削除。** 逆にしたら不可逆の損失。
退避先は CLAUDE.md §6 の第③層 `~/Documents/AI Company 素材/<事業>/<topic>-<YYYYMMDD>/`。
**元のリポジトリ相対パスをそのまま保って** `files/` 配下へ置く（後から突き合わせるため）。
README.md に「何が・なぜリポ外・どのチケット・元パスとの対応表」を書く。**Git 管理外＝バックアップ無し**と明記する。

## 消すのは「列」であって行やファイルではない

行を消すと成果物が壊れる。列だけ落として、**ヘッダに注記を1列足す**
（`※〈列名〉は規約上の理由で除外。完全版は 〜`）。CSV なら空値の列を1本足すだけで、
Excel でも見え、パースも壊れない。HTML なら表の上に可視バナーを1枚。

## 列名を信じない。中身を見る（今回の最大の学び）

- **`基準売価` は全 3,625 行で `過去最安値` と同値だった。**列名だけ見て「当社の判断値だから白」とすると素通りする。
- **`Amazon価格` は `新品最安値`（現在価格＝白）と全行一致**だった。こちらは残してよい。
  同じファイルの隣り合う2列で、片方は黒・片方は白。**必ず実データで突き合わせる。**
- **逆算できる列も落とす。**`想定仕入れ金額(上限) ÷ 仕入れ掛け率上限% = 過去最安値`。
  両方残すと消した意味がない。**片方（比率のほう）を落として、絶対値だけ残す**と成果物は使えるまま。
- 判定の物差しは「**他の残す列だけを使って、黒い値を厳密に復元できるか**」。
  外部の料金表を持ってこないと解けない近似は追わない（追い始めると全列消える）。

## 自分の注記でゲートが発火する

除外注記に消した列名を並べたら、pre-commit が自分の注記に反応して止まった。
**注記の行を検査対象から外す**（sentinel 文字列で `grep -v`）。
xlsx の説明シートでも同じことが起きたので、そちらは**列名を書かない文章に直した**。

## 散文と行データの分け方（誤検知でゲートを殺さないため）

回数で数えても捕まらない。**データ本体では列名はヘッダに1度しか出ない。**
用語集は本文で20回出る。回数の大小は逆になる。決め手は「**列名がどこに出るか**」。

| 拡張子 | 見る場所 | しきい値 |
|---|---|---|
| csv / tsv / json / xml / txt | 中身そのもの | 1件 |
| html | **6行以上の表の、5列以上のヘッダ `<th>`** | 1件 |
| md | **5列以上の表のヘッダ行**（`\|---\|` の直上）＋ **`\|` で始まらないカンマ3つ以上の行** | 1件 |

- md のカンマ規則から表の行を除かないと、法務判定の `\| 7,834 \| … \| monthly_sales, rival_sellers \|`
  が「貼り付けた CSV」に見えて止まる。
- 用語集の `\| 対象 \| 実セラー数 < 2 の割合 \|` は2列。**列数の下限（5列）**で通せる。
- `〜の中央値` は統計値＝白。**接尾辞だけ消すと素の列名が残る**ので、
  `sed -E 's/[^,|<>"]*の中央値//g'` で**列名ごと**落としてから数える。

## 検知語に「値が付いているか」を見る

`api.keepa.com` や `KEEPA_KEY` は正当な実装コードに普通に出る。ここで止めると実装が commit できない。
`KEEPA_KEY[=:]\s*['"]?[0-9a-z]{32,}` のように**値が続くもの**だけを見る。
`"csv":[[` も法務判定が引用するので `"csv":\[\[-?[0-9]` にした。

## 法務の推奨と社長判断が食い違ったら、ブロックを警告に落として明記する

法務は「ユニーク ASIN 20件以上でブロック」。社長は「ASIN は残す」。
ブロックのままだと、浄化した成果物を再生成するたび止まり、**`--no-verify` が常態化してゲート全体が死ぬ**。
→ **警告に落とし、`BLOCK_ASIN_BULK=1` で戻せるようにして、フック冒頭のコメントに理由を書いた。**
勝手に片方を採用せず、両方の言い分と切り替え方法をコードに残すのが正解。

## `.xlsx` はゲートで守れない

zip 圧縮なので grep が効かない。**手で開いて検査するしかない。**
`openpyxl` で `delete_cols` すれば列削除はできる（数式・グラフ・条件付き書式が0なら安全。先に数えること）。
今回、数式126セルの**空テンプレート**（C1）は実データが無いので触らなかった。
**「シミュレータだから危ない」ではなく「実データが入っているか」で判断する。**

## 消しても消えないもの（社長に必ず言う）

- **履歴には残る。**2ヶ月公開なら、クローンと検索インデックスへの取り込みは前提にする。
- **ブランチを跨いで残る。**作業ブランチで消しても `origin/main` と他のリモートブランチには残る。
  「HEAD から消した」と「GitHub から消えた」は別物。**どのブランチの話かを必ず数字で言う。**

## 検算の型（前回から継続）

`git -c core.quotePath=false`（日本語パス）／退避先と作業ツリーの行数突き合わせ／
「消した列の数 == 減った列数」／**ミューテーション**（退避した原本を `git add -f` して本当に止まるか）／
**逆方向**（正当な散文6本が止められないか）／事故の再現ファイルで発火確認。
片方向だけでは検算にならない。今回は16ケースで回した。

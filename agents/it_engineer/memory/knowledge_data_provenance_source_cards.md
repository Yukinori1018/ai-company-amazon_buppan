# 出所カード（SOURCE.md）— 規約付きデータの流用事故を止める最小の型

記録：タカシ / 2026-08-31 / T-20260831-005

## 問題の構造

当社の CSV / JSON / ログには **「どこから取ったデータか」を書く欄が無い**。
数か月後には出所が分からなくなり、分からないデータは必ず別の用途へ流れる。
NETSEA のように**用途を規約で縛られたソース**が混ざると、流れた先で違約金（200万円＋代金50%）になる。

**列名から意味を推測しない**（Keepa の事故と同型）に続く、当社2つ目の「出所を辿れないことによる事故」系。

## 採った型（軽い・動く・テストできる）

1. **データフォルダに `SOURCE.md`（出所カード）を1枚置く。**
   書くのは6つだけ：ソース／取得方法／取得日／**許可用途**／**禁止用途**／根拠条文と制裁額。
2. **`scripts/check_source_cards.py` が見張る。**
   `workspace/output/` 配下の `.csv .json .log .txt .tsv` を走査し、
   用途制限ソース（`RESTRICTED_SOURCES` の語）に言及するファイルのあるディレクトリに
   `SOURCE.md` が無ければ **exit 1**。制限ソースが増えたら辞書に1行足すだけ。
3. **受け皿側（発見リスト）にも1枚置く。**
   `deliverables/T-20260817-005/v14/SOURCE.md` には「Keepa由来100%・NETSEA 0件（実測値つき）」と
   **入れてはいけないソースの一覧＋理由**を書いた。**禁止は出す側だけでなく入る側にも書く**と気づかれやすい。

## 意図的に作らなかったもの（YAGNI）

- 中身の正誤検査。人が嘘を書けば通る。これは**書き忘れ事故**を止めるもので、悪意対策ではない。正直にそう書いた。
- 自動修正。カードは人が書く。
- CI / フックへの組み込み。まず手で回して有用性を見る。組み込みは秘書経由で相談する段。

## 検査は「通ること」を確認しても意味がない

`exit 0` を見ただけでは、検査が何も見ていない可能性を排除できない。
一時ディレクトリに**壊れたケースを作って捕まえられることを先に確認**した（カード無し→検出／カード有り→非検出／無関係データ→無視）。
無人ジョブは嘘をつくなと同じ原則で、**検査も嘘をつく。**必ず落ちる例で試すこと。

## 再利用できる場面

Gift Net / RX Japan の出展社DB、スーパーデリバリー、各種卸サイトなど、
**「登録＝規約同意」で用途が縛られるソース**は今後も増える。増えるたびに
`RESTRICTED_SOURCES` に語を足し、そのデータの置き場にカードを置く。それだけで運用が回る。

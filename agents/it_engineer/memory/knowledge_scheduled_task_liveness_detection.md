# 定期実行タスクは「登録した」で終わらない — 生死を別系統で検知する（2026-08-31 / T-20260826-004）

社長の言葉：**「これは過去にやると言って出来ていないことがあったから、いっています」**。
この一言が要件の中心だった。求められていたのは機能ではなく、**約束を記録で置き換えること**。

## 設計の核（次も同じ形で作る）

定期ジョブを作るときは、必ず**3点セット**にする。1つでも欠けると「静かに止まる」。

| # | 部品 | 今回の実体 |
|---|---|---|
| 1 | 実行するもの | `~/.claude/scheduled-tasks/amazon-seller-central-daily-check/SKILL.md`（毎日12:00） |
| 2 | **動いた証拠** | `workspace/monitoring/amazon-daily-check.md` に1日1行＋その場で commit |
| 3 | **止まったことの検知** | `.claude/hooks/session-start.sh` リマインダー⑤（最新日付が2日以上前なら警告） |

## 判定材料に何を使わないか

- **スケジューラの内部状態を見ない。** `lastRunAt` があっても「実行したが何も確認できなかった」を成功と数える。
  → 見るのは**成果物（ログ行）が増えたか**だけ。`knowledge_unattended_job_must_not_lie.md` と同じ原則。
- **PID を見ない**（再利用されるため。`night-shift.plist` は814回 exit 127 で死に続けた）。
- 「変化がなければ書かない」を許さない。**変化なしの日も1行書く**。そうしないと「止まった」と「変化なし」が同じ見た目になる。

## session-start.sh へリマインダーを足す作法（このリポ固有）

1. **必ず変更前に1回実行して出力を保存する**（`grep -o '【[^】]*】'` で見出しだけ抜くと差分が読める）。
2. 挿入は python スクリプトで anchor 一致＋二重挿入ガード。手編集しない。
3. `set -euo pipefail` なので `grep`/`awk` のパイプには `|| true` を必ず付ける（grep はマッチ0で exit 1）。
4. **番号と掲出順は別物**。既に ③④② の順で出している。行動を要する短いものを前、一覧の長いものを後ろ。
   「止まっている時だけ出る」警告は平常日に0行なので**最前列に置ける**。
5. 日付比較は ISO なので文字列比較でよい。閾値は `date -v-1d`（BSD）→ `date -d yesterday`（GNU）でフォールバック。
6. 検証は5パターン全部回す：今日の記録あり／古い記録／昨日の記録（境界）／日付見出しなし／ファイルなし。
   加えて**既存リマインダーが変更前と一致すること**を diff で示す。ここまでやって初めて「壊していない」と言える。

## 正直さの扱い

手順書には**動かない条件を先に書いた**（アプリが閉じていれば12:00に走らず次回起動時／Chrome 未起動なら失敗／
ログイン切れは社長の手が要る）。「毎日必ず動きます」と書くと、止まった時に信用ごと失う。
`satoyselect@gmail.com` を読めない件も「仕組みで埋められない穴」として明示した。

## 社長向け検証手順は3通り用意する

ログ／アプリの Scheduled 一覧／`git log`。**`git log` だけは改ざんが効かない**ので最後に置いた。
「自分で確かめられる」ことがそのまま信頼の担保になる。

## 追記（2026-09-06 / 同 T-20260826-004）— 上の仕組みが実際に破れた

9/5（金）の日次チェックが飛び、9/6 に社長から「状況はどうなってる？」と聞かれて初めて発覚した。
**上に書いた3点セットは正しかったが、2箇所に穴があった。**

### 穴① 検知器は、壊れている時にだけ鳴らない場所に置いてあった

SessionStart フックは **Claude を開いた時にしか走らない**。今回の故障は「Claude を開かなかったこと」そのもの。
**検知器を、故障するのと同じ層に置いてはいけない。**

裏取りは別系統の記録3つの一致で取れた（推定で終わらせない）。

| 記録 | 9/5 |
|---|---|
| `git log`（監視ログ） | 1件も無し |
| launchd `github-sync`（30分毎） | 07:03〜22:33 に **6回正常稼働** |
| `~/.claude/session-env/` の mtime | 9/4 14:21 の次が 9/6 10:33。**9/5 はゼロ** |

→ **Mac は起動していた。落ちるのは Claude であって launchd ではない。**
定期ジョブの生死を疑う時、`~/.claude/session-env/` の mtime 分布が「アプリが起動していた日」の実測になる。覚えておくこと。

### 穴② 欠測を記録した行が、欠測の検知を黙らせた

旧実装は最新日を `grep -m1`（＝**ファイル先頭の見出し**）で取っていた。
9/6 に手で足した「## 2026-09-05 未実行」が先頭に来た結果、「最新=9/5=昨日=正常」と判定し、9/6 のセッションで**警告が出なかった**。

教訓は2つ。

- **「見出しがある」を「実行された」と同一視しない。** 本文に `未実行` があれば実行されていないと数える。
- **並び順に依存しない。** 人が手で書く順序は必ず崩れる（実際 9/5 が 9/6 の上にあった）。最新日は**全見出しの max** で取る。

### 直した形（次も同じ形でよい）

| 層 | 部品 | 走る条件 |
|---|---|---|
| 判定 | `.claude/scripts/amazon_check_log.py` | **判定は1ファイルに集約**。フックと番犬が共用。2箇所に書くと必ずズレる |
| 検知（アプリ内） | session-start.sh リマインダー⑤ | Claude 起動時。1日でも欠けたら警告。**今日ぶんは12:00前は鳴らさない**（毎朝の誤検知は警告を無価値にする） |
| 検知（アプリ外） | launchd `…amazon-check-watchdog` 12:30/19:00 | Claude が閉じていても走る。通知センター＋欠測行の自動挿入 |
| 復旧 | `/amazon-check` | 気づいた人が1コマンドで回せる |

**番犬に巡回はさせない。**通知だけに絞る（2FA があるので巡回は原理的に Claude + ログイン済み Chrome が要る）。
**今日ぶんを先回りして「未実行」と書かない。**12:00 に遅れて走ることがあり、書いた瞬間ログが嘘になる。

### 通知の落とし穴

`osascript -e 'display notification'` は**通知許可が off でもエラーを返さない**。「送った」と「見えた」は別。
だから `--test-notify` サブコマンドを付け、手順書で **1回だけ目視確認**させる（システム設定 > 通知 > スクリプトエディタ）。

### 作業中の注意（このリポ固有）

`github-sync.sh` が30分ごとに `git add -A` する。**作業途中のファイルが、他人の commit メッセージで巻き込まれて入る。**
実際そうなった（別セッションの `docs(...08 申し入れ文...)` に自分の全ファイルが同梱）。
成果物の「追跡されているか」は commit の有無ではなく **`git ls-files` で見る**こと。

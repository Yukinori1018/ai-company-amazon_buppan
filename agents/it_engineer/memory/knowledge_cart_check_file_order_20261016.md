# 証跡ファイルの「後勝ち」はファイル名順に任せない（T-20260930-001・2026-10-16 夜間）

## 何が起きたか
- カズヨが月販の読み直し99件を `65_カート確認_月販読み直し_20261016.csv` に書き、「ファイル名順で最後に読まれるはず」とした
- 実際は「月」U+6708 < 「未」U+672A なので、`65_カート確認_未判定_20261011.csv` の**前**に読まれる。重なり40件は 10/11 の古い値が勝っていた（表示あり35件のうち7件が NG のまま残るところだった）
- 10/12 の recheck でも同じ型（recheck2_ が recheck_ より前）を踏んでいる。**日本語や数字の入ったタグは辞書順と時系列が一致しない**

## 直し方
- sync_ledger.apply_screen_checks の並びを（ファイル名末尾の8桁日付, ファイル名）にした。load_rechecks と同じ型
- 直す前に「読み直しファイルを除いた全 ASIN で、勝つファイルが変わらないか」を両方の並びで計算して0件を確認した。並びを変える修正は、狙い以外の勝者が動かないことを数えてから流す

## 結果
- 第1弾 126→136・第2弾 541→558・月販NG 99→64（残り64＝読み直しの表示なし64と完全一致）
- 月販が通っても止まる理由：掛け不足（必要な掛け<40%）5社・紐付け未確認1・出品不可1・連絡先なし1

## 手順（再利用：実画面の証跡を足して同期する回）

3. test_criteria_check.py → dry-run（前回ログと diff して変化がその項目だけか）→ 本番 → 本番（ログ・63 一致）
4. シートを退避と代表ASINキーで突き合わせ、列ごとの変化セル数と、狙った NG 件数の残りが証跡の残りと一致するかを見る

# 許容ラインを相手に聞かずに収束させる（SD の 429・自動バックオフ）

- 日付: 2026-10-01
- チケット: T-20260920-003
- 実装: `workspace/output/deliverables/T-20260920-003/28_SD突合/`（`_backoff.py` 新規・`_budget.py` / `_fetch.py` 書き直し）

## 何が起きたか

2026-09-30、スーパーデリバリー（SD）が 429 を返した。許容ラインは当社には分からない。
そこで「SD へ照会して回答が出るまで全面停止」とし、`_budget.SUSPENDED = True` にした。
**社長が照会を却下した時点で、それは永久停止と同義になった。**

> 「数を減らしたり、間隔を空ければいいじゃん。中止するのではなく、できる方法を考えろって。立ち止まったら次に進めないじゃん。」（社長・2026-10-01）

→ CLAUDE.md §3.3-18 として方針化された。**停止は手段であって結論ではない。**

## 実装者として持ち帰る型

### 1. 「〜まで停止」と書く前に、その条件が満たされる道が実在するか確かめる

実在しないなら、それは停止ではなく撤退である。
`SUSPENDED = True` の解除条件を「外部からの回答」に置いたのが設計上の誤りだった。
**解除条件は自分の手の届くところに置く**（今回は「上限とバックオフが実装され、テストが通ったら」）。

### 2. 許容ラインが不明なら、安全側から手探りで近づく設計にする

```
429/503 が出たら  → その日は即打ち切り（同日中の再試行は禁止）
翌日             → 間隔を倍（10→20→40→80→160 秒）
429 が出なければ  → 現状維持
連続3日出なければ → 1段戻す
```

- **「連続3日」は走った日だけを数える。**走らなかった日は何の証拠にもならない
- 同じ日に2回走っても1日ぶんしか数えない（`last_clean_date` で冪等に）
- **上限に当たっても諦めない数字にしておく。**間隔160秒でも1日30件なら80分。実用に足る

### 3. 状態の永続化は「プロセス再起動で戻らない」まで作って初めて縛りになる

再起動で初期値に戻る縛りは縛りではない。日次カウンタ（日付別ファイル）と
バックオフ状態（通日ファイル）を分けた。**日付が変われば回数は戻るが、間隔は戻らない。**

### 4. 保存値は「遅い側」へ寄せて読む

`backoff_state.json` を手で `2.0` に書き換えても、段（10/20/40/80/160）の
**遅い側**へ丸める。`15.0` → `20.0`。壊れた JSON は base から始める（例外で死なない）。
**緩む方向に効く手入力の経路を残さない。**

### 5. 429 を1件の失敗として飲み込む実装は、呼び出し側に嘘を渡す

旧 `_fetch.py` は 429/503 を内部で指数バックオフして再試行し、最後に `Failed` にしていた。
呼び出し側では「1件の取得失敗」＝実質「SD に無かった」に見える。
**専用の例外型（`RateLimited`）にして、その場で全体を止める。**
`Failed`（1件ぶんの失敗）と `RateLimited`（全体を止める理由）を**型で分ける**。
`adapters/netsea.py` の 400 → サンプルデータ fallback と**同じ型の事故**。

### 6. 「別のクライアントに替えれば通る」を実装の前提にしない

旧 `_fetch.py` は「urllib は429で弾かれる／curl は200を返す。原因は TLS フィンガープリント」
というコメント付きで curl をサブプロセス起動していた。**これは反証済み**（CLAUDE.md §3.3-13。
順序を入れ替えたら urllib=200 / curl=429）。標準ライブラリの `urllib` に戻した。
サブプロセスを呼ばないぶん単純で、`opener` を差し替えればテストできる。

🔴 **通信の指紋を偽装する手段は例外なく不可**（§3.3-14）。
テストでコードを走査して、`curl_impersonate` `tls_client` `selenium` `playwright` `subprocess`
を使っていないことを機械で検査するようにした。**方針はコメントではなくテストで守る。**

### 7. 網羅をやめる＝全件スキャンの「口」をコードから消す

`--dealers <全社TSV>` と `--approved-by-secretary` を削除し、`--dealer-ids`（明示）だけにした。
フラグを残すと必ず誰かが付ける。**やらないと決めたものは引数ごと消す。**
歩留まり15%なら、網羅の85%は捨てるための作業。

## テストの書き方（ネットワークなしで縛りを検査する）

`test_sd_access.py`（103項目・1秒未満）。要点は3つ。

1. **時計と sleep を注入する。**`Budget(..., sleep=clock.sleep, now=clock.now)` で、
   待ち時間を**記録して検算**する。実際には1秒も待たない
2. **`today` を注入する。**日付をまたぐ挙動（段上げ・段戻し・カウンタのリセット）を
   1回の実行で全部検査できる
3. **HTTP は `opener` を注入する。**429/503/404/200 をそれぞれ投げて、
   **例外の型が分かれていること**と**リトライ回数が1回であること**を見る

「上限を緩める引数が無いこと」「全件スキャンの口が無いこと」「指紋偽装の手段を
使っていないこと」は、**ソースを読む検査**にした。方針の退行はこれで止まる。

## 実利用の結果（2026-10-01）

レーンA（Amazon 起点・1 JAN = 1リクエスト）を 8件実行。**429 は0件・間隔は10.0秒のまま。**
SD でヒット3件（いずれも出展企業 22706）。うち1件は SD 側の商品名が「まもなく販売終了」で、
**終売品は消極条件では落ちない**ことの実例になった。

## つまずき（記録）

`--jan-file` のパーサが `re.sub(r"\D", "", line)` で行全体から数字を抜いていたため、
`JAN<TAB># B001LOOR4E` のようなメモ付きの行で **ASIN の数字が JAN に連結され、
「JAN がありません」で全件落ちた**。行頭トークンだけを見るよう修正。
**入力の整形は「当たるはずの入力で検算する」まで終わっていない**（CLAUDE.md §3.3-11 と同型）。

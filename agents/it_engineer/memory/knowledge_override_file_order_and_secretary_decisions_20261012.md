# 上書きファイルは「読む順」が結果を決める／秘書判断は上書きファイルで持つ（2026-10-12 T-20260930-001 担当RC2）

## 事故寸前（dry-run で気づいた）
- `sorted(glob('24_連絡先_recheck*_*.csv'))` は **`recheck2_` が `recheck_` より前**に来る（'2'=0x32 < '_'=0x5F）。
  「後のファイルが勝つ」設計なので、**新しい再確認（recheck2・175行）が古い再確認（recheck）に全部負けていた**。
- 気づけた理由：dry-run の「差し替え 395」が recheck 単独のときと同じ数だった。**入力を足したのに件数が変わらない＝足した分が効いていない**。
- 直し方：並び替えキーを（日付, タグ）にした。上書き系の glob を書くときは、**ファイル名の素の順に頼らず、意図した順をキーで書く**。

## 秘書判断の持ち方（再利用可）
- `70_秘書判断_*.csv`（代表ASIN・正式社名・判定・理由・判断者・日付）。判定は3値：
  - 除外 → 判定列を「除外：理由」（送信キューから外れる。sync_ledger の並べ替えより前に適用）
  - 後回し → 判定は接触候補のまま、第1弾/第2弾に入る行だけ打診順を「保留（秘書判断：理由）」
  - 残す → 区分は変えず備考に注記
- 元の batch CSV・シートの原文は書き換えない。どれも備考に「秘書判断（日付・判断者）」を残す＝誰がいつ外したかがシートで見える。
- 実装は dashin_order.py（DECISIONS / apply_decisions / classify）。

# gBizINFO API — 実測した挙動と落とし穴

出典: T-20260831-004（2026-08-31）。Amazon のメーカー名1,247社に規模情報を付けるために実装。
実装は `workspace/output/deliverables/T-20260831-004/30_gbizinfo.py`（アダプタ）と `31_name_match.py`（照合）。

## 接続

- トークン: `~/.config/ai-company-amazon-buppan/gbizinfo.env` の `GBIZINFO_TOKEN`（32文字・リポ外・chmod 600）
- ヘッダ: `X-hojinInfo-api-token: <token>`（Bearer ではない）
- 課金なし。社長が申告した利用目的に「API は1秒1リクエスト以下」と書いてあるので、
  **アダプタ側で 1.15 秒の最小間隔を強制**した。守るのはコードの責任にする。

## エンドポイントの実像（ドキュメントより実測を信じること）

| 用途 | 実際の挙動 |
|---|---|
| `GET /hojin/v1/hojin?name=X&limit=100` | **部分一致検索**。`limit` の上限は 100。**従業員数も資本金も返ってこない** |
| `GET /hojin/v1/hojin/{法人番号}` | ここでだけ `employee_number` / `capital_stock` / `representative_name` が取れる |

**検索で完結すると思って設計すると作り直しになる。必ず2段（検索 → 詳細）。**

### 詳細レスポンスの実際のキー

```
corporate_number, name, kana, postal_code, location, status,
business_summary, company_url, update_date,
representative_name / employee_number / capital_stock  ← 持っている会社だけ
```

`date_of_establishment` は**一度も返ってこなかった**（設立年は取れないと思ってよい）。
`status` は `-`（現存）と `閉鎖`。**閉鎖法人が検索結果に混ざる**ので候補から外す。

### 欠測の偏りが致命的

`employee_number` も `capital_stock` も**大企業ほど埋まっている**。
`capital_stock` は実測で 262社中ごく一部しか取れず、取れた会社は上場企業に偏った。
つまり **「値が無い＝小さい」ではなく「値が無い＝分からない」**。
欠測を「小さい」と読むのも「落とす理由」にするのも間違い。

## 商号は全角で格納されている

`Hamee` を検索すると `Ｈａｍｅｅ株式会社` が返る。**照合前に NFKC が必須。**
検索クエリ側は半角で投げても全角にヒットする（サーバ側で正規化している）。

## 一括ダウンロードは動かなかった（2026-08-31 実測）

`POST https://info.gbiz.go.jp/hojin/Download` に
`downfile=Kihonjoho&meta=META&downenc=UTF-8&apiToken=<token>` を投げると
**「サーバーエラーが発生しました。」の HTML が返る**。Referer / Origin / Cookie を
付けた2通りで試して同じ。361MB の ZIP を落として手元で全件照合する案は捨て、API 2段に倒した。
次に試すなら Cookie 付きセッションをブラウザで作ってからの POST。

## 同名企業は普通にいる。推測で1社に決めないこと

- `ピープル` → 現存の完全一致が **2社**（`株式会社ピープル` 東京 / `ピープル株式会社` 福岡）＋閉鎖2社
- `ワコーズ` → 現存の完全一致が **8社**
- `BOS` → `株式会社ＢＯＳ` `ＢＯＳ株式会社` `合同会社ＢＯＳ` の3社。しかも
  Amazon の `BOS` はクリロン化成のブランドで、**3社とも別会社**

→ 完全一致が2社以上出たら `候補複数` として保留し、候補を全部書き出す。1社に寄せない。

## 商号が短いと偶然一致する

`CIO` → `ＣＩＯ株式会社` が1社だけヒットして「特定できた」ように見える。
本当にそのブランドの会社かは名前だけでは決まらない。
**照合キーが3文字以下なら「要目視」の印を付ける**運用にした。

## 検索が 100件で打ち切られる問題

`limit=100` に張り付いたら結果は切れている可能性がある。
完全一致が 100件目より後にあると **偽の「見つからない」**になる。
`検索打ち切り` フラグを立てて、後から件数を数えられるようにしておくこと。
（`ブシロード` は limit=5 だと子会社しか返らず、本体 `株式会社ブシロード` は
limit=100 にして初めて出てきた。**limit を小さくしてはいけない。**）

# N 個パック案の事実確認は「JAN 検索1回＋offers 1回」で100トークン以内に収まる（2026-09-15 / T-20260915-001 S-14）

## 手順（再利用する型）
1. `/product?code=<JAN をカンマ区切り>&stats=90&history=1` を1回だけ投げる。同じ JAN の単品とパックが全部返り、1商品＝1トークン（8 JAN で36件＝36トークン）。
2. `monthlySoldHistory` は変化点しか記録しない。**月ごとに前方補完してから**「12ヶ月中の月100以上の回数」を数える（補完しないと穴の月を落とす）。0トークン。
3. 季節性で落とした後の残りにだけ `offers=20&buybox=1&stats=90` を付ける（1 ASIN で約9トークン）。出品者数は live オファーのユニーク sellerId。BB 90日平均は `stats.avg90[18]`（buybox を付けないと -1）。
4. 利益は `T-20260914-001/profit2026.breakdown` に price=BB90×N、wholesale=卸×N×1.1、material=束ね費×1.1 を渡す。FBA の納品送料は N 点ぶん足す。
5. **最後に MOQ ÷ 取り分で回転を見る。** 今回はここで全滅した。

## 学び
- **案2の母数表の「単品」は、単品とは限らない。** B008SO2YT0 は「本体＋詰替×2」で、NETSEA の本体だけでは組めなかった。本当の単品は別の ASIN で、Amazon 本体が卸値より安く売っていた。code 検索で兄弟を全部並べると一目で分かる。
- **過去データの売価は古くなる。** GATSBY は1,176円の想定だったが、現在は Amazon 本体の656円。判定の直前に BB 90日平均を取り直す。
- **同じ JAN のパックは、単品が月3,000個でも月50未満（観測下限）だった。** パックへ流れる率3%という置き値は楽観側。
- パックで FBA 手数料が薄まり黒字になる品はある（こどもハブラシは10個で約20%）。それでも NETSEA の MOQ 120個 × 取り分12個/月で9.6ヶ月かかる。**NETSEA 起点の案では、利益より先に MOQ が効く**（knowledge_moq_beats_shipping_in_order_sets と同じ構造）。

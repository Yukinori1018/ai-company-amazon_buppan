## 誤検知を避ける設計（法務の機械判定は6パターン中4つが誤検知だった）

- **ラベルを会員限定の語に限定すれば、Amazon の売価・販売手数料・FBA 手数料・自社の外注費は自然に外れる。**除外リストを足すのではなく、ラベル側を絞るのが正解。
- **率は通し、実額を止める。**`卸率55%以下が12点` は可。だから `卸率` は素の語ではラベルにせず、`卸率…実額` の形のときだけラベルにする。
- 件数（`3件` `10社`）は、数値の直後の単位を見て落とす。
- 検索語を `` `卸値` `` のように code 引用した箇所は、バッククォートの範囲内かどうかで判定して落とす。**再発防止メモやテスト自身が検知語を書くので、これが無いと自分で自分を止める。**
- 表のセルは「3桁以上または `◯万`」を実額とみなす。`| 4 | 12 |` のような件数表は落ちない。`55%` も落ちない。
- 出口は1つだけ：`<!-- public-source: URL verified:日付 -->` が直前3行にあり、ホストが `workspace/source-ledger.md` の**公開**区分にあるとき。**バイパス手段はメッセージに書かない**（書けば常態化する）。

## pre-commit の語彙は「語」ではなく「意味」で並べる

`月間販売数` は (a) Amazon の現在表示＝A クラス公開可 と (b) Keepa 推計＝B クラス の2つを指していた。**A を通す根拠は規約上の白ではなく 2026-09-06 の社長判断**で、これをコメントに残さないと「B も見えるから白」に展開される。
`monthly_sold_real` はフィールド定義を追った結果 `monthlySold` をそのまま書いた列（＝A 相当）だと判明したが、**判定の変更は法務の領分なので外さずに残し、確認結果だけ報告した**。
時系列（2時点以上）は B に戻るので、`月間販売数（YYYY-MM）` `monthlySold_YYYYMMDD` のような**日付つき列名**を正規表現で止める。

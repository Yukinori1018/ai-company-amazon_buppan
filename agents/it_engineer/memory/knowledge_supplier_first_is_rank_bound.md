# 仕入れ先起点（NETSEA → Amazon）で律速するのは利益率ではなく「ランク」（実測・2026-10-01 / T-20260920-003）

**仕入れ先起点では、入口の積極条件（実売）を機械で先に掛けられない**のが構造的な弱点です。

## なぜこうなるか

- **卸サイトに安く載っている商品は、Amazon で売れていないから安い。**
  売れている商品は卸側でも値引きされない（上代ベースの絞り込みで上に来るのは廃盤・アウトレット）
- **Amazon 起点（売れている棚 → 卸にあるか）は逆の弱点を持つ。**
  monthlySold ≥ 50 で取った250件を NETSEA の67,662 JAN に当てたら **当たったのは1件**。
  売れている棚の商品は、承認済み221社の品揃えにほぼ無い

→ CLAUDE.md §3.3-9 の「どちらか一方に寄せない」はこの2つの非対称のこと。
**仕入れ先起点の価値は「候補」ではなく「突合先の台帳」**であり、候補の歩留まりを期待してはいけない。

### 前段フィルタを0トークンで効かせる式

`net = 0.9076×売価 − 621 − 原価`（販売手数料9.24%税込・FBA415・保管等206）に
誤差幅 `0.07×売価 + 200` を課すと、**必要な売価の下限**は

    売価下限 = (821 + 1.1 × 卸値税抜) / 0.8376

| 卸値（税抜） | 必要な売価 | 必要な倍率 |
|---|---|---|
| 500円 | 1,637円 | 3.3倍 |
| 1,000円 | 2,293円 | 2.3倍 |
| 3,000円 | 4,923円 | 1.64倍 |

**卸値が安いほど必要な倍率が上がる。**「安く買えるから有利」は逆で、
**卸1,000円未満の帯は構造的に通りにくい**（FBA 415円と保管等206円が固定費だから）。
NETSEA の卸値の中央値は793円＝**母数の半分はこの帯にいる**。

## 「あと1つで通る」の正しい定義は、判定値そのもの

人に見せる「見れば確定する行」を最初は「落ちた断片がちょうど1本の行」で絞り、**0件**になりました。
生存の断片が1本混じるだけで全部こぼれるからです。

**正解は「判定が UNKNOWN の行」**でした。UNKNOWN は定義上「機械が読み切れなかった」＝人が見れば確定する。
NO-GO には FAIL（実画面でも覆らない事実）が1本以上入っているので、見ても結論は変わりません。
**fail-closed の3値判定を自分で作っておいて、その意味を使わずに文字列を数えていた。**

## 集計は wave の JSON ではなく台帳から

`--out-json` の出力を `stageb_wave1.json` 固定名で書いていたため、**2回目の実行で1回目の根拠を消しました。**
台帳（シート）は消えないので、内訳も「あと1つで通る行」も**台帳の `判定理由` を解析して作る**。

## 順序ファイルは台帳で引き直してから使う

`stageb_order.json` を作った時点では未判定でも、次の実行までに判定が進みます。
判定済みばかりの塊を渡すと `candidate_pipeline` が「未判定の候補がプールに残っていません」と答え、
**ループが「プール全体が尽きた」と誤解して1波で終了しました**（残り171件あったのに）。
**順序ファイルは使う直前に台帳で引き算する。**

## 1. 一番大事な発見 — 詰まっているのは判定ではなく供給

53行まで台帳に積んで、**機械判定のみの GO は0件**だった。落ちた理由の内訳が効く。

| 落ちた理由 | 傾向 |
|---|---|
| **メーカー直販・ブランド公式がカートを持つ** | 1回の14件中 **7件** |
| **赤字**（今の Amazon 価格 × 今の卸値） | 1回の10件中 **8件** |
| **月販が取れない**（`monthlySold` なし＝月50個未満） | プール483件のうち月販が判るのは **40件** |

判定は1件90秒で回る。判定に値する候補が40件しかないのが律速。
**「候補を機械で判定する仕組み」を作っても、母数が増えないと GO は増えない。**
次に手を入れるのは NETSEA→Keepa の JAN 逆引き（ヒットしない JAN は0トークン）で、
フック化・ルーティン化はそのあと。今フックにしても判定するものがない。

## 2. §3.3 の5番目（メーカー直販）は「空振りの多い条件」ではない

実際に落ちた相手: 慧光 / Tillmulya 直営店 / APOLON JAPAN / WAQ(ワック) /
日東エフシー株式会社 / マーナ公式 アマゾン店 / SOLCION公式ストア / 【公式】ベビースマイルショップ。

判定の型（`maker_direct.py`・純関数）:
- セラー名がブランド名・メーカー名を含む → **FAIL（NO-GO）**
- 「公式」「直営」を名乗るがブランド名と一致しない → **UNKNOWN**（人が実画面）
- 新品オファー1社 → **UNKNOWN**（「オファーが少ない」は有利の証拠ではない）
- セラー名が取れない → **UNKNOWN**（「名前が無いから直販ではない」は 9/30 の事故と同型）

比較の実装メモ: NFKC で畳み、法人格（株式会社・Co.,Ltd. 等）と記号を落とす。
併記（`不二貿易(Fujiboeki)`）は括弧で割って**両方**を鍵にする（カタカナ⇄ローマ字は変換できない）。
短い英字の鍵（`ISM`）は完全一致のみ。部分一致だと `PRISM` に当たる。
セラー名は Keepa `/product` では取れない。**`/seller` が必要で 1トークン/セラー**。キャッシュを効かせる。

## 3. やってしまった2つの失敗（同じことを繰り返さない）

### (a) NETSEA の卸値を「1口の値段」と読んで set_num で割った
卸率1.5%・利益率71% という嘘の数字を台帳に書いた。**`set[].price` は1個の値段、`set_num` は
最小発注ロットの倍数**。人が実額で検算した3行（B0DJNX12KZ 920→1,012円 / B0FN3NWKYZ 2,529→2,782円 /
B0171AC6PI 2,098→2,308円）に合っているのが後者の解釈。
**利益率が急に70%台になったら、まず自分の単価の読みを疑う**（終売バイアスより先に）。

### (b) `--update-existing` で人の実画面確認を機械判定で潰した
カズヨが Chrome とキーゾンで確認した2行（B0DJNX12KZ・B0FN3NWKYZ）を「機械判定のみ」で上書きした。
**機械が人の確認を消すと、消した事実さえ残らない。**
対処: `ledger_sheet.update_row` に `HumanRowProtected` を入れ、
**`確認方法` が「機械判定のみ」でない行は上書きしない**（テスト済み）。
教訓として一般化すると、**上書き機能を作るときは「上書きしてはいけない行」を先に決める**。

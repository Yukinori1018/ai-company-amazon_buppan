# 売れ筋(monthlySold≥100)と非売れ筋の傾向・取り方（2026-09-15 / T-20260909-002）

## 結論（再利用する事実）
- NETSEA プール 3,309件のうち月100以上は738件（22%）。**そのうち利益プラスは43件、利益率10%以上は31件**（食品21件がすべて国分ネット卸）。
- 月100以上が赤字になる主因は卸値。赤字695件のうち637件は、卸値が Amazon 価格の70%以上。
  → **売れ筋の条件は正しいが、NETSEA の卸値とは両立しにくい。** 仕入れ先の単価が本丸。
- 売れ筋は安く（3,000円以下）、消耗品（ドラッグストア・ビューティー・食品で約4割）が多く、評価件数が多い（中央値126対54）、出品歴が短い。
- 売れ筋の弱点：オファー数が中央値18対10、Amazon 本体70%、90日平均より5%以上安い38%対18%、季節の波76%。12か月のうち10か月以上で月100以上を保った「定番」は36%だけ。
- 同ブランドの連動は弱い（売れ筋率が14%から18%に上がる程度）。類似商品は同じ JAN の単品とセットから見る。

## 取り方（安い順）
- `monthlySold` は Finder で `monthlySold_gte` と `brand`（最大50件の配列・完全一致）を組める。**プールのブランドを50件ずつ投げて ASIN 一覧と突き合わせると、910ブランドで501トークン**。/product は1件1トークン（`rating=1` で2トークン）なので、3,309件なら3,309トークン。
- JP 全体の件数（2026-09）：月100以上は204,300件、月10以上は422,500件。Finder の上限1万件を超えるので、何かで絞る必要がある。
- 2026-04 以降は50未満の値が出ない。「月10未満」は観測できない。
- raw（offers なし）には評価・評価件数・Buy Box が無い。raw_offers には stats が無い。軸によってデータの出どころを分ける必要がある。
- Finder の棚（v1.3）で取った raw は、Amazon 本体・オファー数・バリエーションが条件で決まってしまう。この3軸は棚の外のデータで比べる。

## 手順の型
1. Finder の件数確認（11トークン）で、全件を列挙できるか判定する
2. 列挙できなければ、ブランドの配列で分割する
3. 既存の raw で季節性と価格の動きを見る（0トークン）
4. 数値入りの版は `out/`（追跡外）、公開版は傾向とルールだけ

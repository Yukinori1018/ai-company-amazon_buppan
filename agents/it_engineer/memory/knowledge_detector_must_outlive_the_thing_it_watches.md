# 検知器は、監視対象より長生きする層に置く（2026-09-06 / T-20260826-004）

この会社で3回、同じ形の事故が起きている。設計を始める前にこの1ページを読むこと。

| 事故 | 監視対象 | 検知器を置いた場所 | なぜ効かなかったか |
|---|---|---|---|
| night-shift 814回死亡（14日無警告） | launchd ジョブ | stderr ログ | **誰も通らない導線**にしか出していなかった |
| inbox 21件12日滞留 | 社長が置いたファイル | 社長の申告（プル型） | 申告が無ければ永久に気づかない |
| Amazon 日次チェック 9/5 欠測 | Claude のスケジュールタスク | **Claude の** SessionStart フック | **壊れているのが Claude 本体**なので検知器も動かない |

共通の失敗は「検知器を、監視対象と同じ運命を共有する場所に置いた」こと。

## 設計時に必ず答える3つの問い

1. **監視対象が壊れる原因を1つ挙げる。その原因で、検知器も止まらないか？**
   止まるなら、検知器は1つ下の層へ降ろす。
   Claude のジョブ → launchd。launchd のジョブ → Git に残る成果物 ＋ 人が必ず通る導線。
2. **検知器が死んだことは、どこに出るか？**
   出ないなら、検知器の心拍を検知器の出力に混ぜる（今回は番犬の最終実行時刻をフック⑤に載せた）。
3. **平常時は何行出るか？** 0行でなければ、いずれ読み飛ばされる。
   「異常な時だけ鳴る」ものだけが最前列に置ける。

## 層の一覧（このリポで実測済み・下ほど頑丈）

| 層 | 走る条件 | 実績 |
|---|---|---|
| Claude のスケジュールタスク | **アプリ起動中のみ** | 9/5 に丸1日発火せず |
| Claude の SessionStart フック | セッション開始時のみ | 同上の日は当然走らない |
| launchd（LaunchAgent） | **ログイン中は Mac が起きていれば走る**。スリープ中は復帰時に1回 | 9/5 も github-sync が6回稼働 |
| Git のコミット履歴 | 人／ジョブが commit した時 | **改ざんが効かない最終証拠**。社長の自己確認はここに落とす |

## 「アプリが起動していたか」を後から調べる方法（macOS / Claude Code）

`~/.claude/session-env/` のディレクトリ mtime を並べる。セッションごとに1つ増えるので、**日付が抜けている日＝アプリを開かなかった日**。

    ls -la ~/.claude/session-env/ | awk '{print $6,$7}' | sort | uniq -c

スケジューラの実行履歴が残っていなくても、これと `git log` と launchd のログの3点で裏が取れる。
**「たぶんアプリが閉じていた」で報告を終えない。**

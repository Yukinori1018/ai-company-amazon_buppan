# テストの固定値に実データを書かない（2026-09-20 / T-20260920-002 S-F）

## 何をしたか

電話番号パーサのテストを書くとき、表記のバリエーション（`(011)-826-3533` のような
括弧付き、全角、スペース区切り）を**名簿から実際に取れた値からコピーして**書いた。
実在の会社の代表番号3件と住所1件がテストファイルに入った。

**30分後の自動同期（`.claude/scripts/github-sync.sh` の `git add -A`）がそれを拾い、
PUBLIC リポジトリに push された。** 自分で `git push` はしていない。

## なぜ危ないか

- このリポジトリは PUBLIC で、**30分ごとに自動 push される**。「まだコミットしていないから
  大丈夫」という時間の猶予は**存在しない**。ファイルを保存した瞬間に公開されると考える
- `.gitignore` で守ったのは成果物の `out/` だけだった。**スクリプトは追跡下に置く前提**なので、
  スクリプトの中に実データを書けば、除外設定は何の役にも立たない
- 法務判定（05 §3-2）は「電話番号を PUBLIC リポに置くのは NO」。
  **成果物ファイルの話だと思い込んでいたが、条件は置き場ではなく値に掛かっている**
- 消すには履歴の書き換え＝`force push`＝§4.1。**自分では直せない**。前方修正しかできない

## 次からのルール

1. **テストの固定値は必ず作り物にする。** 加入者番号を `0000` にする、`03-1111-2222` のような
   明らかな架空値を使う。**表記の型だけを本物から借りて、値は借りない**
2. 実データで確かめたいときは、テストではなく**その場限りの検証スクリプト**で回し、
   `agent_output/`（`.gitignore` 対象）に置いて捨てる
3. 追跡下に置くファイルを書くときは、**保存する前に**「この行が世界に見えてよいか」を見る。
   コミット前のレビューでは間に合わない（自動同期の方が早い）
4. 実データを扱うタスクでは、**`.gitignore` を設定した時点で安心しない。**
   守ったのは成果物だけで、コード・テスト・ログ・README は無防備なまま

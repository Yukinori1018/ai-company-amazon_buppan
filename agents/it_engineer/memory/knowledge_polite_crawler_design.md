# 行儀のよいクローラの作り方（T-20260920-002 S-F で確立）

実装は `scripts/maker_list/`。次に同種の取得をするときは、ゼロから書かずにここを写すこと。

## 1. 法務条件は config.py 1枚に集約する

`sleep(3)` をコードに散らすと、あとで判定が変わったときに追えなくなる。
定数名を**法務判定書の表と1対1**にしておくと、ハルオが「§2-4 の表を config に写して」と
書くだけで済む（実際 05 はその形で来た）。

```python
ASSOCIATION_MIN_INTERVAL = 3.0   # 05 §2-4
MAKER_MIN_INTERVAL = 3.0         # 05 §3-1
ABORT_HOST_STATUSES = (401, 403, 429, 500, 502, 503, 504)
```

## 2. robots.txt は 404 と 403 を必ず分ける

**これを間違えると取得できるはずのサイトが理由なく全部落ちる。**
今回は区別しないと業界団体3本・394社が落ちるところだった（ハルオが指摘）。

| 応答 | 意味 | 扱い |
|---|---|---|
| 200 | 宣言がある | パースして従う。`Crawl-delay` があれば自分の間隔と比べて**大きい方**を採る |
| **404** | **拒否の宣言が存在しない** | **取得してよい** |
| 401 / 403 / 429 / 5xx / タイムアウト | サーバが拒んでいる | **そのホストは打ち切り** |

「取得失敗＝許可なし」と一括りにしないこと。なお Python の `RobotFileParser.read()` は
内部でこの区別をしているが、**ネットワーク例外は握り潰される**ので自分で分岐を書く。

## 3. fetch と extract を関数で分ける（今回一番効いた設計）

```
crawl_one()          = fetch してから extract_from_pages() を呼ぶ
extract_from_pages() = ページ群を受け取るだけ。ネットに触らない純関数
reextract.py         = キャッシュ済みHTMLに extract_from_pages() を当て直す
```

抽出の正規表現は必ず何度も直す。分けておかないと、直すたびに全サイトを取り直すことになり、
**相手に迷惑をかけるうえ1日のリクエスト上限を食い潰す**。今回は「主な製品」の判定を3回直したが、
取り直しは0回で済んだ。

## 4. 1日の上限はプロセスをまたいで数える

カウンタをインスタンス変数に持つと、スクリプトを2回起動しただけで上限が2倍になる。
`WORK_DIR/quota_<日付>.json` に置く。厳密なロックは要らない（多少の数え漏れより、
上限が効くことの方が大事）。

## 5. 1件ごとに JSONL へ flush する

途中で止まっても部分成果が残り、再実行で済んだ分を飛ばせる。
今回は法務判定が途中で出てプロセスを停止したが、123社ぶんは無駄にならなかった。

## 6. 速さのために「並列数1」を自分の判断で緩めない

「politeness は per-host だから、別ホストへの並列は無害」——理屈は正しいが、
**判定書が「異なるホストへの並列も1で開始」と書いていたら、それが条件**。
今回それを 6 並列・2.5秒でやってハルオに差し戻された（2.5秒も根拠なく緩めた数字だった）。
**既定値を静かに緩めるのは、この会社で繰り返し起きている型の事故**（memory
`feedback_standing_decisions_are_not_re_decided` と同じ構造）。速度が欲しいなら、
緩めるのではなく「今日はここまで、続きは明日」と設計する。

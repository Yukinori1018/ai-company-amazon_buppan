## 手順（再利用可）
ZX/ZY と同じ型で通った。退避 → 40 --offline → テスト2本 → sync_ledger dry → 本番×2（シート全タブ JSON・63・ログを cmp）→ dry。
日付つきの 62b_/65_/70_ は glob で読むので、列が前回と同じならスクリプト変更は不要（ヘッダと列数だけ先に見る）。
シートの退避・検証は `gspread.service_account(~/.config/claude-session-sheets/credentials.json)` で全タブを FORMULA で JSON 化し、キー＝(正式社名, 代表ASIN(タカシ)) で前後比較（消えた行・接触ステータス/接触日/メモの変化）。

## 気づき
- 入力104行 → シート+92。差の12は sync_ledger の key_of（正式社名）重複で吸収。「未特定（カート店は中国の事業者）」が同じキーになり5行が1行に潰れる。全部除外なので実害なしだが、行数の差を説明できるように数える
- 流通形態の「酒類」は備考・取引案内の語で機械分類する。**酒類卸の免許を持つ飲料メーカー**（友桝飲料：代表はノンアルのこどもびぃる）が誤って「酒類：販売免許なし」で落ちる。戻すのは 70_ の秘書判断（残す＋理由に「酒類」）＝秘書の判断事項として報告する
- 「大手」には上場一致のほかに gBiz の同名1社一致の規模判定がある。短いローマ字社名（HI-LINE）は同名別会社を拾う。上場一致だけ直しても穴は残る
- 追記：秘書が 70_ に「残す（理由に酒類）」を書いたあと再同期すると、流通形態は「不明（秘書判断：…元：酒類）」になり第2弾に入った（友桝飲料→第2弾-216・後ろが1つずつ繰り下がる）。再同期の差分は打診順の繰り下がりと送信順だけで、消えた行・社長入力列の変化は0

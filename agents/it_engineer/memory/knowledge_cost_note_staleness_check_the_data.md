# コストの「欠落」は注記ではなくデータで確かめる（T-20260909-002 / 2026-09-09）

## 起きたこと

秘書経由で「**FBA納品代行の作業費 12円/点が、利益計算に1円も入っていない**」という
指摘が来た。出典は経理ハジメの `T-20260904-004/C1_費目一覧.csv` の
`prep_service_per_item` 行にある注記「【現行モデルに欠落】」。

確認したら、**入っていた。**

- `T-20260831-006/pipeline/config.py` に `prep_service_yen: float = 12.0` があり、
  `evaluate.py` の `inbound_shipping = fba_inbound_yen + prep_service_yen + netsea按分`
  として純利益から引かれている
- 入った時点は commit `bf44b59`（2026-09-04・経理の実測コスト反映）。
  **C1 の注記はその修正より前に書かれたもの**で、修正後も文言が残っていた
- 生成済み `candidates.csv` の列「納品送料(FBA+納品代行)」は全行 **50円**
  ＝ round(37.5 + 12.0 + 0)。作業費は確かに入っている

## なぜ気づけなかったか

**1本の列に3つの費目をまとめていたから。** 列名は `納品送料(FBA+納品代行)` で
正しく書いてあるが、金額は合算値しか出ていないので、
「12円が入っているか」を成果物の画面から確認できなかった。

## 危なかったこと

指摘のまま「作業費を引くと93円→81円」と直していたら**二重計上**だった。
1SKU の判断（ファブリーズを外す／外さない）がその数字に乗っていたので、
黙って引いていたら社長に誤った根拠を渡していた。

## 次からやること

1. **「欠落している」という指摘は、注記ではなく生成データの列を見て確かめる。**
   注記はコードより古くなる。CSV に値があるかどうかだけが事実
2. **合算列は、成果物の引き算で必ず内訳に割り戻して出す。**
   `inbound_parts()` を足した。足し直すと元の列に一致するので検算できる
3. 資材費は 12円/点に含まれる（`materials_cost = 0`）。**別立てすると二重計上**
4. 経理の費目一覧に古い注記が残っている → 秘書経由でハジメへ是正を回す
   （こちらで他エージェントの成果物を書き換えない）

# 古いブランチ取り込みは「公開データ検査 → マージ」の順。検査で止まってよい

2026-09-12 / 依頼: カズヨ（社長承認「Aで」）/ 対象: origin/claude/employment-support-outsourcing-20p283 → claude/nighttime-work-checkin-iTWEa

## 何が起きたか
- 取り込み前に `git diff --stat HEAD...<branch>` でブランチ固有ファイルを列挙し、`git show <branch>:<path>` で中身を読んだ。
- facility-shortlist / outreach-templates / researcher notes / T-20260806-001 チケットの6ファイルに
  **第三者の個人名＋携帯番号（共同受注窓口の担当者・070-系）** が載っていた。法人代表番号・所在地は問題なし。
- 指示どおり**マージせず停止**してカズヨへ報告。作業ブランチには一切コミットしていない。

## 再利用できる手順
1. `git fetch origin <branch>` → `git diff --stat HEAD...origin/<branch>`（三点リーダでブランチ固有分だけ）
2. 全ファイルに対して正規表現スキャン（電話 `0[0-9]{1,4}-[0-9]{1,4}-[0-9]{3,4}`、メール、`氏|様|さん`）→ **ヒットは必ず目で読んで法人/個人を判定**
3. 携帯番号（070/080/090）＋人名の組は「個人連絡先」として扱う。出典が公開PDFでも同じ（前例：法人連絡先399件で法務指摘）
4. `git grep -q <pattern> <ref>` を全リモートブランチに回すと、既にどこで公開済みかが分かる
5. ID 重複の事前確認は `ls workspace/tickets/*/ | grep -o '^T-YYYYMMDD-[0-9]*'` と `git grep -ho` の両方（ファイル名に無くても本文で参照されている番号がある）

## 気づき
- **ブランチ自体が既に PUBLIC リモートに push 済み**＝マージしなくても情報は公開状態。止めるのは「作業ブランチ（main 系）に広げない」ためで、既存公開の是正（該当行の伏せ字化 or ブランチ削除）は §4.1（不可逆削除）絡みなので社長判断。
- 伏せ字化してから取り込む案が最短（該当6ファイルの携帯番号・担当者名だけ置換→代表番号 03-3734-0763 は残す）。

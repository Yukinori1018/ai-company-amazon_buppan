# /buppan-todo スキル — 定常成果物を「コマンド1発」にする型

作成: 2026-08-26 タカシ / T-20260826-002 派生（社長指示「すぐ一発で出来るようにプラグインかスキルを作っておいて」）

## 何を作ったか

`.claude/skills/buppan-todo/`。社長が `/buppan-todo` と打つと、
Amazon物販マスターToDoリスト（8大 / 42中 / 208小）を最新のチケット状況で作り直す。

```
scripts/todo.sh prepare  … 作業場の用意 + チケット全数棚卸し（前回分類を引き継ぐ）
   ↓  判断（マーク更新）だけがエージェントの仕事
scripts/todo.sh build    … awk集計 → ボードの数字差し替え → HTML生成 → 検算
```

## いちばん効いた設計判断：**再生成ではなく差分更新**

定常成果物は「毎回変わる部分」と「積み上がった部分」が混ざっている。
このボードには社長の指摘が3件（画面幅最大化 / 内訳は矢印にしない / 数字の凡例）
埋まっていて、全再生成すると毎回それが消えて同じ指摘を繰り返させることになる。

そこで **`update_board.py` は数字のパターンにマッチした箇所だけを置換**する方式にした。
narrative・Mermaid の線の意味・ズームJS は一切触らない。

| 対象 | 方式 | 理由 |
|---|---|---|
| `01_master-todo.md` | 既存を編集 | 骨格208項目は不変。変わるのはマークと根拠だけ |
| `01_master-todo.html` | md から全再生成 | md の純関数なので再生成が正しい |
| `03_process-board.html` | 数字だけ置換 | 人が書いた文章と社長の指摘が同居している |
| チケット台帳 | 前回の分類を引き継ぎ、新規のみ分類 | 106枚を毎回読み直すと分類が揺れ、社長には「何もしてないのに数字が変わった」と見える |

## 描画器を「既存出力とバイト一致」まで詰める手順

`render_html.py` は既存の `01_master-todo.html` を**1バイトの差もなく再現**する。
これが「壊れていない」の最強の証明になる。詰め方は単純：

1. `python3 -c` で既存 HTML の**タグ＋style 属性のユニークな組み合わせ**を全列挙する。
   語彙は小さい（この例で30種程度）ので、見て写せる
2. 描画器を書いて `diff` する
3. 残差を潰す。今回残ったのは4つだけだった
   - `<title>` と footer → CLI 引数に逃がす
   - `html.escape(quote=False)` にしていた → `"` を `&quot;` にする必要があった
   - 目次 div の前後の改行
   - `</thead><tbody>` の間に改行を入れていた

**教訓**: 既存の機械生成物を引き継ぐときは、まず署名を列挙して diff ループを回す。
「だいたい同じ見た目」で妥協すると、社長に「前と違う」と気づかれて信用を失う。

## 集計は awk 1本に集約する

`aggregate.awk` が唯一の集計元。A章のサマリ表もボードの数字も全部ここから。
`verify.py` が**本文と集計の一致を機械検算**する（前回、集計と評価がズレて説明が必要になった）。
検算は6項目：骨格の同一性 / 見出しの件数表記 / A章の表 / マーク記法 / 個人特定情報 / ボードの数字。
**わざと壊した入力で NG が出ることを確認してから使う**（今回4種の破壊を全部検出した）。

## やらかしと対処

`agent_output/` の前回台帳を、バックアップを取らずに上書きした。
`.gitignore` 対象なので **git から戻せない**。分類データ自体は引き継ぎロジックで生き残ったが、
台帳の冒頭にあった解説セクションは失われた。

→ `todo.sh prepare` に**タイムスタンプ付きバックアップ**を追加。
→ 段階の定義表は生成物の冒頭に埋め込むようにして、スクリプトが原本になるようにした。

**教訓**: gitignore 配下のファイルを上書きするスクリプトには、必ず `cp` を1行入れる。
「あとで戻せる」は git 管理下だけの話。

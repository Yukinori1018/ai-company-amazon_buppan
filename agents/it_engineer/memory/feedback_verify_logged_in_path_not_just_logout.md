# ログイン判定 URL は「ログイン中に開いて同じ URL のまま」を実画面で確かめる（2026-10-14）

## 何が起きたか
- 10/12 に作ったログイン延命（T-20260920-003 login_keepalive）で、SD の判定 URL を `/i/r/msgbox/` にした
- 確かめたのは「非ログインの curl でどこへ飛ぶか」だけ。ログイン中の挙動は見ていなかった
- 実際は `/i/r/*`（メッセージ・入荷通知）はログイン中でも直接開くと必ず `clickMemberLogin` へ飛ぶ → 10/12〜14 ずっと「SD 切れ」の誤報。社長は「ログインしている」と言っていた
- 直し：`/p/do/memberManage/purchase/orderHistory/list`（購入履歴）に替え、タイトル「購入履歴」が無ければ切れ（`ok_title_re`）。直後に OK

## ルール
- 判定器は両側を確かめる：①切れているとき飛ぶ先 ②**ログイン中に開いて同じ URL・期待タイトルのまま開くこと**。②を見ていない判定器は「切れ」を言う資格がない
- 社長の「ログインしている」と判定器が食い違ったら、まず判定器を疑う。同じ Chrome の別タブ（claude-in-chrome）で同じ URL を開けば1分で決着する
- 「最後に OK だった時刻：記録なし」のまま ALERT が出続けるサイトは、一度も OK を観測していない＝判定 URL の誤りを最初に疑うサイン

## 延命ウィンドウの自動再作成（同日）

# ルール：回転上限6ヶ月・予算10万円・手残りで順位付けしない（2026-09-12 社長 / T-20260909-002）

これは**事実ではなくルール**です。発注セット・仕入れ案を組むときは、毎回この前提で始める。判断し直さない。

## ルール

1. **回転上限6ヶ月はハード制約。** 最小ロット（卸の最小発注口数を入数の倍数に切り上げ）で買った時点で
   `出品数 ÷ 月販見込 > 6ヶ月` になる SKU は、**案に入れない・生成しない・「参考」としても出さない**。
   落選表に理由として残すのはよい（候補としてではなく）。
2. **予算は10万円**（送料込み。旧5万円）。1周目は「完走して学ぶ」テストで、社長は10万円を失ってもよいと明言。
3. **手残り・粗利で案を順位付けしない。** 軸は「6ヶ月以内に確実に捌けるか」「出品制限・供給停止で全滅しにくいか」。
4. **2社分散はルール1より下位。** 両立しなければ1社でよい。その場合は全滅シナリオに明記する。
5. **案は1〜2個。** 社長は選択肢の多さを求めていない。

## なぜルールになったか

回転46.7ヶ月の案A/B/D を「手残り最大」という理由で3回にわたり出し続けた。社長の言葉：
「46か月も回転しない商品は買うだけ無駄です。言わなくても分かってください。」

私（タカシ）が以前 memory に書いた「最小ロットで上限を超える SKU も超えたまま候補に残す
（落とすと判断材料が消える）」は、**この件では誤りだった**。`knowledge_flag_without_suppressing_the_number` の
「数字を消さない」は**落選理由として残す**ことで守れる。**候補として残す理由にはならない。**
良さそうに見える指標（手残り）で並べると、打ち消す指標（回転）を上書きしてしまう。

## 実装での固定のしかた（order_set.py）

- 定数 `TURNOVER_CAP_MONTHS` / `TOTAL_BUDGET_YEN` / `MAX_PLANS` と、ルール本文をコメントで定数の真上に置く
- `assert_rules()` で、上限や予算を破る案は**生成した時点で例外**にする（表示層に届かせない）
- 並べ順の関数 `_safety_key()` は**利益をキーに持たない**。キーに入れられない形にしておくのが一番効く
- 積み増しは「手残りの増え方」ではなく「在庫が薄い SKU から」、上限の半分（推定誤差2倍の安全率）まで
- ふるいは生産終了チェックの**前**に全件へ当てる。人手のチェック対象を先に減らす（今回 24件→12件）

## 自己チェック（案を出す前に）

- 案の中に回転6ヶ月超の行が1つでもあるか → あれば出さない
- 案の説明文・並び順に「手残り最大」「粗利最大」が出てくるか → 出てきたら書き直す
- 予算が大量に余っていても、それを埋めるために遅い SKU を足していないか

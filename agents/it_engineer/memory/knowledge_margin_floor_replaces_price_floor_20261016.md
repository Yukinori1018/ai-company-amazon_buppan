# 入口基準の「売価の下限」を「利益率5%に必要な掛け」に置き換えた（T-20260930-001・2026-10-16）

## 何をしたか
- criteria_check.py 基準5：売価≥2,200円 → 利益率5%の上限卸値 ÷ 平時売価 ≥ 40%（40_採算列の2列だけで出る）。上限卸値≤0 は NG、採算列なしは「未確認：採算」。40〜50% は採算メモに「掛け交渉次第」
- 結果：第1弾 117→126・第2弾 500→530。入口(b) から31社。既存の第2弾3社が必要掛け39%で外れた（閾値の境目）

## 教訓
- **同じ基準が2か所に書かれていた**（criteria_check の基準チェック列と dashin_order の検算）。片方だけ直すと「基準チェック OK なのに検算NG」で第1弾に入らない。基準を変えるときは `grep -rn MIN_PRICE\|2,200` で全実装を洗う（10_funnel・30_build・15_widen の抽出側は入口なので今回は触らない）
- 基準を「単価」から「利益」に変えると、採算列が無い行は「未確認」になる（候補CSVの売価に逃げない）。採算列の欠けが新しい未確認の原因になりうる
- 「未確認：FBA数」は Keepa の offerCountFBA=-2（offers 未取得）が原因。65_カート確認 の注意欄「出荷=Amazon(FBA)」から **FBA数の下限1** が事実として言える。Keepa を叩かずに埋まる（69行に効いた）
- 新基準で落ちる既存の社は、閾値ちょうど下（39%）に固まる。報告では社名と値を出し、閾値を動かすかは秘書に返す

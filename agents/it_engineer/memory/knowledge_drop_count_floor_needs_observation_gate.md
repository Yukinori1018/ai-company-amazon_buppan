# ドロップ数を足切りに使うなら、必ず「観測回数のゲート」とセットにする

T-20260906-002 追補 / 2026-09-06。社長判断で「ドロップ数は捨てず下限として使う」方針になった際の実測。

## 結論

**X = 10。ただし「30日の観測回数 ≧ 20」が成立している商品にしか適用できない。**

## なぜゲートが要るか — 実例が決定的

標本 360 件の中に、**ドロップ数 0 でありながら Amazon が販売数を公表している商品が 11 件**あった。
全件が **30日の観測回数 2〜5 回**、公表販売数の中央値 1,000 点/月、**最大は月4万点**。

> **月4万点売れている商品のドロップ数が 0 になる。Keepa が2回しか見ていないから。**

**観測回数を見ずに足切りすると、カテゴリ最上位の商品から先に削れる。**
「ドロップ数が少ない＝売れていない」は、**十分に観測されている商品にしか成り立たない。**

## 閾値の実測（観測20回以上の群 n=184・正解ラベル＝Amazon公表販売数）

| X | 取りこぼし | 落とした群の売れている率 |
|---|---|---|
| 5 | 0% | **0%** |
| **10** | **3%** | **4%** |
| 12 | 31% | 22% |

10 未満で落ちる群はほぼ本当に死んでいる。12 以上にすると取りこぼしが急増する。**折れ目は 10。**

## 飽和値は「1つの数字」ではない

1日1回観測（26-34回）の群の中央値は **9**、1日2回以上（45回以上）で **15**。
**観測頻度が違えば飽和値も違う。** 特定の値（14/15）を避けても解決しない。
避けるべきは値ではなく、**観測回数を見ずに絶対値を比較すること**。

## 充填率（drops ÷ 観測回数）の正しい使い道

**閾値には使えない。** 同じ取りこぼし率で比べると生ドロップ数のほうが純度が高い。
全個体が 0.3〜0.5 に集まる（コイン投げの確率だから）ので分解能がない。
**分母（観測回数）をゲートに使うのが正解。** 正規化した値ではなく分母を見る。

## 足切りだけでは死んだページを防げない

**今回の失敗SKUのドロップ数は 14 で X=10 を超えていた。** 落としたのは
**カート最終獲得日（70日前）とカート不在率（100%）**。
**ドロップ数の足切りは「一般的に不活発なものを削る」役割。特定の死んだページを見抜く力はない。**
BuyBox 系の条件と必ず併用する。

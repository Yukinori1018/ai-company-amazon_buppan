# シートを全消去しかけた事故：シンボリックリンク先のスクリプトを直接叩いた（2026-10-11・T-20260930-001）

## 何が起きたか
- `agent_output/T-20260930-001/sync_ledger.py` は `deliverables/.../sync_ledger.py` への**シンボリックリンク**。
  スクリプトは `HERE = os.path.dirname(os.path.abspath(__file__))`（abspath はリンクを解決しない）で入力 CSV を探す
- 使い方を見ようと deliverables 側で `python3 sync_ledger.py --help` を打った → argparse ではないので `--help` は無視され本実行。
  HERE＝deliverables には CSV が無く**入力0行のままシートを batch_clear → 見出しだけ**になった（約1分）。0行の 63_打診第1弾.csv も作った
- 同じ理由で、2つのパスに同じ編集をかけると**同じファイルに2回入る**（ガードが二重挿入された）

## 復旧の手順（再利用可）
1. Drive API の revisions（SA の drive スコープで読める）で直前版を探す。`exportLinks` の TSV に `&gid=<ws.id>` を付けるとタブ単位で取れる
2. 社長入力列（接触ステータス・接触日・メモ）を直前版で数える → 今回は全行既定値（未接触・空）だったので、再同期だけで完全復元できた
3. 「前の行数」は、壊れたシートではなく `--through=<前回の最終バッチ> --dry-run` で再構成して確認（1450行一致）
- 版は数十分単位でまとまるので、直前版と事故の間に人の手入力があった場合は取り戻せない。報告ではその限界を書く

## 再発防止
- sync_ledger.py に**縮小ガード**：入力0行、またはシート現行の9割未満なら書かずに中止（`--allow-shrink` で解除）
- 全置換で書き込むスクリプトには最初からこのガードを入れる。「--help を付ければ安全」と思わない（自前の argv 解析は未知の引数を無視する）
- 実行は必ず `agent_output/T-20260930-001/` で行う（手順メモ knowledge_dashin_order_column.md の通り）

# Keepa の価格履歴で「普段いくらで売れているか」を出すときの罠

タカシ（IT）／2026-10-04／T-20260920-003
実装: `workspace/output/deliverables/T-20260920-003/26_候補提案パイプライン/price_history.py`
テスト: 同ディレクトリ `test_price_schedule.py`

## 発端

社長の指摘。**「価格が変わるのは当然。過去の履歴を見てこの商品はどれくらいで売れるのかを把握するのが大事」**
秘書が「判定データが4日で陳腐化した」と騒いだが、筋違いだった。現在価格は1点の観測で、
**薄い棚ではとくに当てにならない**（下記 ③）。

## 踏んだ罠（4つ・全部その日のうちに踏んだ）

### ① Keepa の時刻変換を自分で書き直した

`seasonality.py` の `_to_dt` のコメントに **「ここを自分で計算し直さないこと」** と
書いてあるのに書き直し、`datetime(2011,1,1) + timedelta(minutes=km+21564000)` としてしまった。
正しくは `datetime.fromtimestamp((km + 21564000) * 60, tz=utc)`（基準は **1970年**）。
41年ずれて**全商品 days_covered=0**。

→ **教訓：既にあるモジュールの変換関数は import して使う。** 同じ式を2箇所に書かない。
   既存コードのコメントが「書き直すな」と言っていたら、それは誰かが踏んだ跡である。

### ② 階段関数の値を無限に持ち越した

Keepa の `csv` は「値が変わった時だけ」点が入る階段関数。素直に forward-fill すると、
**2年前に消えた BuyBox の価格が「今日の90日中央値」として出てくる**
（B01N5Q61K6 で現在 4,250円 に対し中央値 1,400円）。
「カートが立っていない」は「その値段で売れている」ではない。

### ③ ②の対策を「隣り合う点の間隔」に当てて、いちばん良い棚から落とした

持ち越し上限14日を**点と点の間隔**に当てたら、**236件が「価格が読めない」で落ちた**。
値が変わらない安定した棚は点が少ないだけで、価格はちゃんと付いている。
**狙いと真逆（安定した棚ほど落ちる）。**

正解は **Keepa の `-1` を捨てずに「ここから値が無い」マーカーとして使うこと。**
- 値が変わらない棚 → 点は少ないが `-1` も来ない → **今日まで有効**
- カートが消えた棚 → `-1` の時点で **そこから無効**

→ **教訓：欠測を表す値（-1）を捨てるのは、情報を捨てること。** フィルタで消す前に
   「この値は何を意味しているか」を確認する。

### ④ 表の数字を直したのに、本文の文章が古いまま残った

②を直して中央値が 12,100円 → 7,990円 に変わったが、**手書きしていた解説文は
「中央値は12,100円のまま」と書いたまま**で、表と本文が矛盾した成果物を一度作った。

→ **教訓：成果物の文章は数字から生成する。** 判定の根拠を手で書くと、
   モデルを直したときに必ず置き去りになる（`write_order_proposal.split_verdict()`）。

## 設計として残したこと

| 決めたこと | 理由 |
|---|---|
| 日次グリッドに打ち直してから中央値を取る | 点をそのまま数えると**値動きの激しい時期だけが重く数えられる** |
| BuyBox と 新品最安の**2本を見て安い側を採る** | 建て付けが違う（BuyBox は送料込み・購入者が払う額）。**高いほうを採ると赤字を黒字と報告する** |
| 悲観シナリオの売価は **90日の下位25%** | `fba_cost._scenario` のコメントが「売価の悲観は履歴が無いので当てていない。取れたら sell 側に入れて」と残してくれていた。そこに入れた |
| 人が実画面で見た価格 > 機械 | §3.3-16。ただし**食い違いは消さず `disagreement` に残す** |
| 下落トレンド（−8%/30日以下）は落とす | 仕入れて納品して売る頃（2〜4週間後）にはもっと安い |

## 🔴 いちばん大事な発見：Keepa だけでは売価を確定できない

社長が実画面で見た5件のうち、**3件は台帳の売価＝Keepa の90日中央値と1円単位で一致**した。
つまり台帳が古かったのではなく、**Keepa の履歴そのものが社長の見た安値を見ていない**。
薄い棚では最安オファーが履歴に乗らないことがある。

→ **発注直前の実画面確認は、ゲートだけでなく「価格」も対象。**
   機械は `min(90日中央値, 実画面)` までしか言えない。

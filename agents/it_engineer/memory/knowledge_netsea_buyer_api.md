# NETSEA Buyer API — 会員規約による用途制限（実装者向け・最重要）

記録：タカシ / 2026-08-31 / T-20260831-005
※ API の技術仕様は `docs/netsea-api-spec.md` と `adapters/netsea.py` の docstring が一次資料。
　 このファイルは **「何に使ってよくて、何に使うと会社が飛ぶか」** だけを書く。

## 一行で

**NETSEA は「仕入れ先」であって「発見の入口」ではない。** NETSEA で見つけた相手に外で連絡した瞬間、
違約金 **200万円＋売買代金の50%** ＋事業者名の公表が発生しうる（バイヤー会員規約 第27条4項）。

## 拘束されている条文（法務ハルオが原文取得・2026-08-31）

| 条文 | 内容 |
|---|---|
| 第7条1項3号 | 他の利用者の**情報の収集を目的とする行為**の禁止。**事前承諾の逃げ道が無い（絶対禁止）** |
| 第7条2項3号 | 権利の行使の範囲を超えて本サービスの情報を利用すること |
| 第7条2項5号 | 当社提供機能**以外の方法**でサプライヤーと直接・間接問わず連絡を取ること |
| **第19条3項** | **NETSEA を利用することなくサプライヤー会員と売買契約等を締結してはならない** |
| **第27条4項** | 違反時＝**事業者名の公表／契約解除／違約金200万円＋代金の50%** |
| 第24条1項 | バイヤー会員の**氏名・住所・電話番号がサイト上で公開される**（個人事業主＝自宅住所） |

**当社は Buyer API トークン発行済み＝会員＝現に拘束されている。**「これから会員になるか検討」ではない。
トークン発行はマイページの API 設定画面でしかできず、会員でなければ発行できない。ここが判断の起点。

## 実装で効かせた歯止め（`adapters/netsea.py`）

1. **モジュール docstring の先頭**（設計方針より前）に「⛔ 用途制限」ブロック。禁止4種＋根拠条文＋**金額**を明記。
   → 「注意してください」と書いても誰も止まらない。**200万円と書けば止まる。**これは効いた書き方として再利用する。
2. `PURPOSE_PROCUREMENT` / `PURPOSE_DISCOVERY` / `NetseaUsageError` / `assert_procurement_use()` を追加。
   NETSEA データを新しい出力先へ流す処理を書くときは入口でこれを呼ぶ。
3. `list_suppliers()` の docstring に警告（**社名を返す唯一のメソッド**＝名簿化の入口）。
4. **既存呼び出しは変えていない。**引数必須化＝破壊的変更は今の規模では割に合わない（YAGNI）。
   止めたいのは「これから書かれるコード」であって、動いているコードではない。

## 名前が罠になっていた

`discovery/pipeline.py` の `discover_from_netsea()` は名前が "discovery" だが、
中身は「**NETSEA 内で買う商品**を探す」関数で、法務判定でも適法。
**違法になるのは関数ではなく出力の行き先。**関数名だけ見て「発見用途だから削除」と判断すると、
適法な機能を壊した上で、本当に危ない「出力を名簿へ流す」経路は残る。
→ 教訓：**規約違反はコードの形ではなくデータの流れ先で決まる。**

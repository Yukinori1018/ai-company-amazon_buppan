# 日本語の商品名から「入数」を読むときの罠

2026-09-07 / T-20260907-001。`T-20260831-006/pipeline/pack.py`。

## 罠1: 助数詞の一覧に無い数え方は、黙って「入数1」になる

エラーにならないのが厄介。「まとめ売りの表記なし」として素通りする。

| 表記 | 読めていた値 | 正解 | 欠けていた助数詞 |
|---|---|---|---|
| `160g×36食` | 1 | 36 | 食 |
| `×12本入×(2ケース)` | 12 | 24 | ケース |

追加した: `ケース・食・玉・束・巻・冊・組・膳・人前・ロール・杯・足・双`
（既存: 個・本・枚・袋・包・缶・箱・種・パック・セット・パウチ）

**追加してよいのは商品名に実際に書かれている数え方だけ。推測で埋めない。**

## 罠2: 末尾の「×N」を「代替」として扱うと、一番単純な形を落とす

```python
counts = _COUNT.findall(text)
if not counts:                       # ← ここが間違い
    counts = _TRAILING_MULT.findall(text)
```

`16枚×4` は `16枚` を読んだ時点で満足し、**後ろの ×4 を捨てる**。
実在の2行で原価が **1/4・1/3** になり、上位10件の1位と2位に来ていた。

**代替ではなく加算にする。** 「数字＋助数詞」と「行末の数字（助数詞なし）」は
条件が排他なので、足しても二重計上にならない。

> **難しいケースのテストはあったのに、易しいケースが素通りしていた。**
> `12個入（2種類×6個）×6袋` の入れ子はテスト済み。落ちたのは `16枚×4`。
> 複雑な例だけでテストを組むと、単純な例が穴になる。

## 罠3: 「両側が同じ数」＝倍率1、が誤りになる場合がある

**NETSEA の商品名がケースを表していても、卸値は1個あたりの単価**のことがある。
`1Kgx15` / `1kg×15個` → 「同じだから倍率1」と判定したが、売価が仕入の15.1倍。
**倍率が15ならちょうど帳尻が合う。**

**商品名からは判別できない。ここは推測で埋めない。**
比率ガード（売価が仕入の4倍超）に任せ、並べ替えから外す。
危険度は数えられる —「**両側とも2以上**」の行だけが対象（実測2,240件中62件）。
```
利益が出て入数が解けた行 2,240 → うち両側が同じ 2,110 → うち両側とも2以上 62
```
**この数を報告に必ず添える。**「直りました」だけでは、残った危険が見えない。

## 何が起きていたか
- `.claude/settings.json` の command が `$CLAUDE_PROJECT_DIR/.claude/hooks/x.sh`（引用符なし）。Claude Code は `/bin/sh -c` で実行するので、リポのパスの空白（"Claude Code"）で切れて 8/21〜10/27 全件 exit 127。
- 単体テストは全部通っていた。テストはフックを直接 `bash 絶対パス` で呼ぶので空白を踏まない。**登録のしかた（settings.json の文字列）を試すテストが無かった**。
- 正しい形：`"\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/x.sh"`（JSON の中で `"$CLAUDE_PROJECT_DIR"` を引用符で囲む）。
- 直した瞬間から、そのセッション自身の Write にもガードが効く（settings はその場で読み直される）。

## 再利用できる手順（眠っていたガードを起こすとき）
1. **起こす前に、実ファイルを Write ペイロードとして全ガードに流して止まる本数を数える**（`agent_output/T-20261027-001/replay_guards.py`。git log で直近 commit されたファイルを使う）。今回は資産台帳ガード 156/492本（32%）、出所ガード 56本。そのまま起こしたら全社の書き込みが止まっていた
2. 止まった行を10件ほど目で見て、誤検知の型を分類してから判定を締める（今回の型：①キーから離れた否定語 ②相手先の話 ③部分一致 ④漢数字の「一覧」の一 ⑤率・日付・ID を金額と読む ⑥文をまたいだ共起）
3. 締めたら元の事故文が**まだ止まる**ことをテストに入れる（弱めていない証拠）
4. settings.json の文字列そのものを `/bin/sh -c` で空白入りパスから叩く結合テストを置く（`.claude/hooks/tests/test_settings_hooks.sh`）。対照として「引用符なしなら127」も入れる
5. Stop フックは複製した一時ディレクトリ（空白入り）で試す。実リポで試すと owner-tasks.md の時刻に依存する

## 判定の締め方で効いたもの
- 資産台帳ガード：否定は**キーの直後**（助詞・副詞を挟み句読点をまたがない）だけ。直前に第三者語（メーカー・同社・公式・楽天・卸）があれば除外。カタカナ/英字キーは同じ文字種が続けば別の語。CSV は相手先データなので対象外 → 156→3本
- 出所ガード：漢数字は「万」「円」が続くときだけ数値。%・割・倍・行・回・日は通す（点・個・円は止める）。文（。、／「」）をまたがない。小数・日付・チケットID は金額でない → 56→26本（残りに公開済みの本物の実額が混ざる）
- Stop（社長タスク）：「tickets/ のどれかが新しい」は毎ターン止まるうえ、mv は mtime を変えないので waiting への移動を拾えない。**waiting/ が新しい or waiting の ID がまとめに無い**で判定
- Notion 同期リマインド：Bash は「mv/cp/rm がコマンド位置にあり、引数に workspace/tickets/」のときだけ。文字列中の `cp` で鳴っていた

## 発注ゲートの名前判定
- 「発注」は当社では「サブエージェントへの依頼」の意味でも使う。パスに「発注」を含むだけで発注案扱いにすると、委譲の報告書が納品できない
- 「発注＋何を（案・書・表・リスト・候補・セット・する・予定・明細・数量）」＋言い換え（仕入れ案・購入案・purchase_order）＋マーカー、で判定（`gate.ORDER_NAME_RE`）。旧ルールで実在した発注案は全部当たる＝弱めていない
- 記録文書にマーカーの書式をそのまま引用すると、その文書が発注案と判定される（今回自分で踏んだ）。説明では「order-asins マーカー（HTML コメント）」と言い換える

## 注意
- Bash の安全チェックは、コマンド文字列に `rm` という語があるだけで止めることがある（テスト文の中でも）。テスト用のコードはファイルに書いてから実行する
- 資産台帳ガードの誤検知例を記録に引用すると、その記録が止まる。引用せず言い換える
- github-sync はリモートに無いブランチだと fetch 失敗で終了し、初回 push に届かない（未修正・秘書へ申し送り）

## 追記：サブエージェントの見分け方と作業中フック（同日）
- フック入力に `agent_id`・`agent_type` が入るのはサブエージェント内だけ（実測12件全部）。`session_id`・`transcript_path` はメインと共通なので使えない。`prompt_id` もメインのターンと共通＝「同じターン」の鍵に使える
- 実入力の取り方：一時的に `cat >> log` するだけのフックを settings.json に足し、1手打ってから外す（設定はその場で読み直される）。ログは agent_output に置く（scratchpad へはフックから書けなかった）
- 閾値は履歴から「振っていた期間の誤発火」と「振らなくなった期間の捕捉手数」を並べて決める（delegation_turns.py）。8手で期間Bの1,177手を捕まえ、期間Aの発火15%

## 追記：公開済みの実額を伏せ字にする手順（同日・法務判定 30）
- 道具：`agent_output/T-20261027-001/redact.py`＋規則 JSON（values／columns／lines／line_re／regex／literal）。元の行は redacted_values/*.jsonl に「ファイル・行・元・後・理由」で移す。**2回目で0行**を必ず確かめる
- 値で伏せるときは前後が数字・カンマ・小数点なら別の数とみなす。CSV はカンマが区切りなので値の規則が効かない → 行の文字列（literal）で伏せる
- 範囲（80〜90%）は下限が残る。金額の正規表現に「N〜」を含める
- 同じ値が成果物・チケット・memory・handover に散る（鍋の仕入額は30本）。法務の26本だけ直すと残る → 代表値で git grep を全体に当てる
- 列で伏せる：md は見出し行で列番号を覚えて表が終わるまで、html は table 単位で th の位置を見る（同じ値が別の列にも出るので値では伏せられない）
- 公開用ブランチは `git commit-tree HEAD^{tree} -p <公開ブランチ先頭>` で1コミットにすれば、rebase も force push も要らない（手順書 31）

## 方針の変化
- 2026-10-12 社長方針（CLAUDE.md §3.5 #12）：「今だけ、儲かるなら、廃止が決まっているものも仕入れて良い」
- `discontinued.check` は法令品目・卸の廃番に**印（marked）を付けるだけ**にし、判定は `NowOnly` の3条件
  (a)仕入れ先の在庫 (b)在庫月数 ≦ 製造終了日までの月数（過ぎていれば／卸の廃番は仮置き3か月）(c)価格が上昇〜横ばい
  で決める。全部 PASS→PASS（印は判定理由に残す）、1つ FAIL→NO-GO、未確認→UNKNOWN
- 台帳側は `ledger_refresh.end_gate()` で「終売」ゲートを足す（印の無い行には足さない・Keepa 兆候は見ない）。
  (b) の在庫月数は `_share["months"]`（推奨初回点数÷取り分）を優先

## この依頼はこう処理した（再利用の型：卸の一覧価格 × Amazon ASIN を型番で突き合わせ）
1. 秘書が卸の一覧で読んだ「型番・卸1点」の CSV と、照会キュー（ASIN・商品名）を **型番の完全一致**で結ぶ
   （NFKC・大文字・ハイフン/空白除去 → 最長一致 → **型番の直後が英数字・カナなら別型番**）
2. `sd_route_override_<日付>_<tag>.csv` を agent_output に置く → `ledger_refresh.load_sd_route` が glob で拾い、
   **先に入った（在庫まで確認済みの）行を後のファイルで上書きしない**
3. 一覧で価格しか見ていない行は `在庫=未確認` → #17 仕入れ UNKNOWN（「在庫あり」にしない）
4. dry-run → 本番 → dry-run で差分0

## 罠
- 🔴 `FLR36T6EX-Wﾚｲ30`・`…Lﾚｲ5D` は**別型番**（価格が倍）。境界を英数字だけで切ると半角カナの続きを見落として
  誤って同じ卸値を当てる。境界に カナ（ァ-ヴ・ｦ-ﾟ）も入れる
- route_to_sd は在庫列が空でも PASS（在庫あり）にしていた → 嘘。未確認は UNKNOWN に直した
- 秘書が台帳で直接書いた最終判断（確認者に「タカシ」が無い）は、証跡ファイルに載っていても凍結する。
  機械の合流で作る確認者は必ず「／タカシ（…）」を含むので区別できる
- 別ルート（candidate_pipeline）が自前の Keepa で GO にした行を、ledger_refresh 側にデータが無いだけで
  「取り直し UNKNOWN」に落としかけた（B0BP7M69YH）→ データなしの GO は据え置き
- B008FIN7NQ は出品一覧が取り寄せ型1本のみ（#13）で機械は UNKNOWN。秘書の判断で GO 固定＝秘書に再確認を促す

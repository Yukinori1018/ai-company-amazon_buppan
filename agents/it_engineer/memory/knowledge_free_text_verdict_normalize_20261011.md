# 判定欄の自由記述は「読む側で正規化」・人の再確認は証跡ファイルで重ねる（2026-10-11 T-20260930-001）

## 何をしたか（再利用できる手順）
1. 人の再確認（サトルの紐付け確認 67_*／ヒデアキの宛先差し替え 68_*）は **元の batch CSV を書き換えず**、`sync_ledger.py` の glob 合流（65_/62b_ と同じ型）で同期のたびに上書きする。キーは代表ASIN。
2. 宛先差し替えは旧値を **備考へ退避**（消さない）し、`contact_rank` を再計算する（窓口が変われば送信順も変わる）。
3. 判定欄が「ブランド単位：…」「表記ゆれ：…」のように語彙外で書かれていても、**シートの原文は残し、検算側（dashin_order.link_verdict）で4値に正規化**して読む。
4. 同期前にシートを JSON 退避 → `--through=batchY` で3回 → 全セル比較。比較では **確認日が日付シリアル（46299 等）で返る**ので日付に直してから比べる（2235セル全部が「不一致」に見えた）。
5. 件数の増減は「どの変更の寄与か」を切り分ける：67 を外す／正規化を外す、の組み合わせで collect＋assign をオフライン再現し、旧シートの値と一致するかで検算。

## 気づき
- 正規化で一致側に読めるようになった接触候補は24行あったが、**第1弾/第2弾に新たに入ったのは0**（基準NG・酒類・出品不可で別に落ちていた）。取りこぼし対策の効果は小さく、効いたのは人の再確認（+10/+26）。「直したら増えるはず」を数字で確かめてから報告する。
- 「〜で確認済み」（他行参照）は参照先を辿っていないので未確認に倒した。甘く読むと紐付け未確認の社を第1弾に混ぜる。
- 正式社名の表記違い（「A（販売：B）」と「B（A）」）で、打診文CSVとの突合が2社ずれた。社名突合は代表ASINでやる方が安全。

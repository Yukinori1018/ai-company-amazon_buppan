# セット数は「束ね」と「多入り」を分け、卸の商品名と突き合わせる（2026-10-11）

## 何が起きていたか
- 旧 `set_count.parse_amazon_set_count` は「12個入」「35枚組」「8点デラックスセット」「ペアセット」「ギフトタオルセット 34X66cm」の数を全部倍率にしていた
- サトルが人の目で確定した168行（確度 高・中）で検算：旧 **一致10・誤り99**／新 **一致57・誤り1**・UNKNOWN110
- 正解の多くは 1：卸も同じ「12個入」を1点で売っている

## 直し方（再利用できる型）
1. **束ね表記（EXPLICIT）**：「×2点セット」「2セット」「(4個)」→ 倍率。卸の商品名に同じ数があれば割る
2. **多入り表記（PACK）**：「N個入/N枚組/N点セット/ペア/N膳/N食/2P/4pcs」→ 卸の商品名と比べる。卸も同じ数なら1、卸が「1袋」と明記なら N、**卸に数が無ければ None**（タオルセット・あられで「卸に数なし→N」は22行中12行誤り）
3. **中身の規格**「20g×12個」「12mm×9m×24巻」は束ねではない（ただし「500ml ×2点セット」はセットが付くので束ね）
4. 「FX 8点」の X は型番。x/X は英数字の直後を除く
5. pq=1 と多入り表記の組み合わせは決めない（pq=1 は既定値のことがある・「6食」を1と読む＝原価を安く見る側）
6. 正規表現の `入り?` は「入」必須。`(?:入り?)?` と書かないと「6食」を素通りする

## 人の確認の合流
- `score_20261004.human_set_checks()` が `ledger20261010/set_check_*.csv` を毎回読む（cart_check/gate_check と同じ証跡ファイル方式）。確度 高・中だけ採用、低・未確定は UNKNOWN＋【こう変えれば】
- 人のセット数を使う行は、台帳の Amazon1個あたり原価（旧セット数由来）を検算に使わない（使うと必ず食い違って UNKNOWN になる）

## 学び
- **仮説「原価を重く見て黒字を NO-GO にしていた」は外れた。**誤った行は採算が「未確認」で止まっていて NO-GO の原因ではなかった。正しいセット数で計算したら168行中112行が赤字。直す前に「その誤りが結論を支配していたか」を数える（CLAUDE.md §3.3-21 の再演）
- 実データの人の答えでパーサを回すと、規則を1つ足すたびに誤りが 22→8→4→1 と減るのが見える。合成テストより先にこれを回す
- 並行の kz_entry_candidates.py も `set_family.resolve` を使うので、多入り表記の行は UNKNOWN 側に倒れる（意図どおり）

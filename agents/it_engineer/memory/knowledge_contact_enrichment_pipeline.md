# 連絡先エンリッチ（B-1）で効いた設計と、踏んだ穴

対象: T-20260904-004 / B-1。約400社のメーカー連絡先を Exa MCP で集め、
法務の A〜E 判定を通し、PUBLIC リポに出してよい形にするパイプライン。
2セッションに分けて 133社 → 399社（キュー272件を全件消化）まで回した。

## 1. 「チェックが通った」と「チェックが動いていた」は別

このチケットで**同じ型の壊れ方を3回**踏んだ。全部「緑なのに何も見ていない」。

| # | 壊れ方 | 見え方 |
|---|---|---|
| 1 | commit ゲートが `entity_type` 列を見ていたが、その列が CSV に存在しなかった | 「抵触0件 → commit してよい」 |
| 2 | 先頭の `#` 注記行を `csv.DictReader` がヘッダとして食い、列名が1つも一致しなかった | 「連絡先が1つ以上ある行: 0 / 抵触0件」 |
| 3 | top50 を `queue[:50]` で切っていたので、判定が D/E の社が上位50に混ざった | 注記に「D/E には打診しない」と書いてあるので一見問題なさそうに見える |

**教訓: 通ったことではなく、発火することを確かめる。**
実際にやったのは*ミューテーションテスト*。検査対象を一時的に壊して、
テスト／自己検算が**落ちること**を目で見る。落ちなければテストは無い。

    # 例: フィルタを外して、自己検算が本当に落ちるか見る
    rows = rows[:50]        # ← わざと壊す
    → SystemExit: top50 に D/E が残っている: 岩手県木炭協会、エリエール、ハイメス

このリポは PUBLIC で30分ごとに自動 push される。緑の誤りは事故に直結する。

## 2. 「読めなかった」を「問題なし」に化けさせない

`GateCannotRead` 例外を足して、黙って 0 件を返さないようにした。
検査対象の列が1つも見つからなければ、それは「抵触なし」ではなく「読めていない」。
**戻り値0で表現できない状態は、例外で表現する。**

## 3. 検算より先に書かない（PUBLIC リポ特有）

最初、CSV を書いた後に読み直して検算する順序にしていた。
これだと**検算が落ちた瞬間から次の自動 push までの間、不正なCSVがディスクに残る**。
検算が仕事をするほど危険という逆立ち。
`OUT.tmp` に書く → 検算 → `os.replace()` に直した。落ちたら tmp を消す。

## 4. 判定基準の所有権を侵さない

法務ルール `B1L_optout_rules.json` は**法務ハルオの所有物**。
穴を見つけても、こちらでクラスを増やしたりルールを書き換えたりしない。

実際に踏んだ穴: `A1_trade_window` が「新規お取引」を肯定シグナルとして拾うが、
右辺（否定語）が無い。そのため

    「新規お取引は行っておりません」 → A_PLUS（最優先で打診）

と**意味が正反対に転ぶ**。打診してはいけない相手が最優先候補に化ける方向の誤り。

やったこと: `detect_negated_trade_window()` という**検知器**を足し、
ヒット語の直後25文字に否定語が来ていたら `optout_needs_review` を立てて人に回す。
**クラスは決めない。** 事業判断で決めたぶんは
`optout_e_subclass` / `optout_decided_by` の別列に分けて、法務判定と混ぜない。

    ルールに穴がある → クラスを足すのではなく、検知器を足して差し戻す。

## 5. 冪等性は「追記」で壊れる

`apply_optout.py` が再実行のたびに 備考 へ 【法務の個社判定】 を追記していて、
愛知電線には同じ文が7個ぶら下がっていた。
処理済み判定を「JSONL にエントリがあるか」の1点に寄せていても、
**副作用のある更新側が冪等でないと意味がない**。追記前に含有チェックを入れる。

## 6. 名寄せ: 列名も社名も信じない

- `規模フラグ` 列は全社「中小候補」で機能していなかった（社長から明示的に使うなと指示）
- 商号は**動く**。今回だけで、法人格が消滅していた社が3社
  （アミューズソフト / 角川エンタテインメント / バンプレスト）、
  商号が3回変わっていた社が1社（よしもとアール・アンド・シー → よしもとミュージック
  エンタテインメント → よしもとミュージック）、旧商号で登録されていた社が2社
  （日本コロムビア、NBCユニバーサル）。
  **旧名で送ると存在しない会社に出すことになる。**
- ブランド ≠ 法人。HEIMESS → ブラザー・ジョルダン社、BUNDOK → 株式会社カワセ。
- 表記ゆれで同一社がキューに3件入っていた例あり（ストームレーベルズ）。
  半角スペースが混入した文字化け表記もあった（`ワー ナー・ブ ラザース…`）。
- 検索1位をそのまま採ると**約25%で別会社**を掴む。キューの
  「主なカテゴリ」「代表商品名」を照合材料に使うと弾ける。

## 7. 埋めないという成果物

`インディーズレーベル` `ビデオメーカー` は**一般名詞であって社名ではない**。
`DVDBOX5枚組`（メーカー名ですらない）`四日市ばんこ焼`（産地名）と同じ型。
これらは**空欄のままノイズとして報告する**のが正しい。
推測で埋めた連絡先は「取れなかった」より悪い。社長が別の会社に連絡してしまう。

## 8. コスト

Exa MCP はホスト型で API キー不要。**399社ぶんで課金 0円。**
ただしスクリプト化できず、1社1ターン消費する。
バッチで6〜7社ずつ並列検索 → JSONL へ1行追記、が現実的な速度だった。

## 9. 手作業の消し込みは必ず復活する

前任が手で伏せた2社の連絡先が、次のビルドで復活していた。
伏せ字はビルドスクリプト側（`redact_sole_proprietors()`）に持たせる。
**CSV を手で編集しても次のビルドで上書きされる**ので、消し込みはコードに置くこと。
伏せた欄は空にせず `【非掲載】…` と書く（空欄だと「調べたが取れなかった」と区別できない）。
ただしその印を連絡先としてカウントしないようゲート側にも手当てが要る。

## 10. 伏せ字の一括適用で、商品名を壊した（2026-09-04・自分の事故）

「住所の部屋番号を全 Git 追跡ファイルから落とせ」という依頼で、
**全文走査＋パターンマッチ**を書いて流し、12ファイルを壊した。

壊したもの:

| 落としたもの | 実体 |
|---|---|
| `F-52` | **Arrows We2 F-52E**（スマホの型番。商品名の一部） |
| `480F-2` | **GIVI ZT480F-2**（バイク部品の品番） |
| `#42` `#81` `#121` | **Markdown の脚注番号** |

原因は2つとも「範囲」の設計ミス。

1. `F-\d+` `Room \d+` `#\d+` を**自由文にも当てた**。
   `\d+号室` は日本語の文中でほぼ部屋番号にしかならないが、
   `F-数字` `#数字` は型番・品番・脚注として**大量に**現れる。
2. 「〒がある行は住所」という**当て推量のヒューリスティク**を書いた。

**教訓: 住所かどうかを推測しない。「これは住所欄だ」と宣言された欄しか触らない。**
JSONL はキー名で、CSV は列名で判定する。自由文には号室系しか当てない。
それでも足りない海外住所は**リテラルを列挙する**。手間だが誤爆しない。

### 同じ流れで踏んだ、もっと地味な3つ

- **`git ls-files` が日本語パスを8進エスケープで返す。**
  `core.quotePath=false` を付けずに走らせて、**117件を黙って素通り**させた。
  0件処理は成功と区別がつかない（また「緑なのに見ていない」型）。
- **`io.open(...).read()` で CRLF が LF に化けた。**
  2箇所の修正のはずが contacts_v1.csv に1256行の差分。`newline=""` が要る。
- **伏せ字関数が入力全体に `.strip()` をかけていた。**
  住所1件なら無害だが、ファイル全文に当てると最終行の末尾まで削る。
  **伏せ字は印の周りだけ触る。入力を勝手に整形しない。**

### 効いた歯止め

書き込み直前に「**直した箇所の数**と**実際に変わった行数**が合うか」を検算した。
合わなければ書かずに落とす。CRLF 事故はこれが止めた。
なお最初この検算は嘘をついた（リテラル置換を1件しかログせず `.replace()` は全件置換していた）。
**ログが実変更数より少ないと、検算そのものが無効になる。**

## 11. 警告列は、立てすぎた瞬間に読まれなくなる

「宛名をそのまま使うと届かない行」を1列で示す設計。3回作り直した。

| 判定方法 | 立った数 | 結果 |
|---|---|---|
| 備考に「商号変更」が含まれるか | 19 | ×「矢崎エナジーシステム㈱→株式会社」の表記違いだらけ |
| メーカー名が正式商号に含まれるか | 113 | ×大半が `BUNDOK → 株式会社カワセ` のブランド名≠法人名。**普通のこと** |
| 法人格が無い / 旧商号 / 抽出ノイズ の3つだけ | 6 | ○ |

**立てないものを決める方が、立てるものを決めるより難しい。**
隣の列を見れば分かることは警告にしない。狼少年になった警告は読まれず、
読まれない警告は「注記に書いてあるので大丈夫」という誤った安心だけを残す。
これは top50 に D/E を載せて注記で止めようとした失敗と同じ形。

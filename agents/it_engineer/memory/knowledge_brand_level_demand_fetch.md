# メーカー（ブランド）単位で需要を取る手順（2026-09-12 / T-20260912-001）

本丸の第一陣17社で実施した。実績は 346 token（見積り 340）。

## 型

1. Product Finder に `{"brand": ["<完全一致の文字列>"], "current_SALES_gte": 1, "sort": [["current_SALES","asc"]], "perPage": 50}` を投げる。
   コストは 1社あたり約11 token。brand フィルタは効く（木村硝子店は188件で、全件のブランドが一致）。
2. `asinList` の上位10件を product に投げる（`stats=30&history=0`、offers なし、1 token/件）。
3. 生データは `agent_output/<ticket>/raw17/` に保存する。集計は別スクリプトで行う（token 0）。
   実装: `agent_output/T-20260912-001/code/fetch17.py`、`deliverables/T-20260912-001/share17_calc.py`

## 踏んだところ

- **manufacturer 一致で0件なら、ランク無しを疑う。** 宇野刷毛・守田漆器は、製造元一致の出品がすべて `current_SALES=-1` だった
  （「ノーブランド品」表記の新規出品）。Finder が壊れているわけではない。`/search` で確認できる（10 token）。
- **`/search` の結果を検証するときは、最初から raw を保存する。** 保存し忘れて20 token を二度払った。
- **③ monthlySold は最小でも50。** 「≧6」の足切りに当てても通過判定にならず、「値がある／空欄」の二値にしかならない。
- 17社・121件のうち74件がバリエーションの子だった。タオル・帽子は全件が子。**②（割らない月販）の通過件数を SKU 数と読まない。**

## 物差しの差（件数だけ）

足切り「月6個以上」の通過件数は、①(÷出品者+1) で7件、② 割らない値で83件。
**独占を狙う経路で①を使うと、ほぼ全滅に見える。** 物差しは必ず並べて出し、どれで切るかは戦略側に決めてもらう。

「じゃあ B も見えるから白」と展開されて崩れる。

## 詰まったときの型（これが今回の収穫）

1. **まず未 push か測る。** `git log --oneline -1 -- <path>` → `git merge-base --is-ancestor <sha> origin/<branch>`。
   **未 push なら「公開前の修正」で済む。push 後は force push か GitHub Support（どちらも §4.1）しかない。
   費用が桁で変わる境目。** 緊急判定は「あと何分で自動同期が走るか」を1行目に書く。
2. **止血は `mkdir workspace/.sync/.lock`。** 可逆・承認不要。ただし **`STALE_LOCK_MIN` で自動解除**され、
   **外し忘れは成果物同期の停止**という別の事故。**必ず戻すことを報告に書く。**
3. **公開版と完全版を分ける。** 公開版＝`deliverables/`（A クラス＋結論だけ・Git 追跡）、
   完全版＝`~/Documents/AI Company 素材/<事業>/<topic>-<YYYYMMDD>/`（B・C・D を含む・README 必須・リポ外）。
   **`.gitignore` で成果物ごと追跡外にするのは筋が悪い**（CLAUDE.md §6「deliverables は Git 追跡」と衝突し、
   バックアップも消える）。**落とすのは列であって、ファイルではない。**
4. **数値を落としても結論は書ける。** 判定（NG/見送り）・構造（本体がカートを保持している）・
   当社の算術（手残り・損益分岐の卸率）は残る。C は「金額を書かず、判定だけ書く」で通る。
5. **`--no-verify` / `ALLOW_WHOLESALE_DATA=1` は使わない。** 法務も自分の判定書でフックに引っかかり、
   列を組み替えて通している。バイパスは翌週には全社の常態になる。
6. **commit の付け替え（soft reset → 再 commit）は §4.1 隣接。** 自分では踏まず、
   **コマンドまで組んで社長の一言を待つ。**

# 長尺動画から「特定の文言が映っているフレーム」を探す型

> 初出: T-20260831-004（2026-08-31）。5.6GB・1時間49分の Zoom 画面収録から
> リサーチ基準のランキング条件を探す依頼。結論は「映っていない」。

## 使う道具（この Mac での実測）

| 用途 | 採用 | 理由 |
|---|---|---|
| フレーム抽出 | `ffmpeg`（`/usr/local/bin`） | 導入済み |
| OCR | **macOS Vision framework を Swift CLI で叩く** | **tesseract はこの Mac に無い。** Vision は日本語スライドを十分な精度で読む。外部依存ゼロ |
| PDF | `pdftotext`（導入済み） | テキストレイヤーがあれば OCR より確実 |

`swiftc` の初回ビルドは Vision/AppKit の import で **2分超**かかる。Bash ツールの既定タイムアウト（2分）を超えるので **`nohup` でバックグラウンドに投げる**こと。1回踏んだ。

## 必ず2パスで走査する

- **パス1: 一定間隔**（10秒）— 時刻がフレーム番号から正確に決まる
- **パス2: シーン検出**（`select='gt(scene,0.10)'`）— 10秒未満しか映らない画面を拾う

**片方では必ず落とす。** 今回、唯一の「リサーチ基準」言及スライド（12:29:48）は**シーン検出が落とし、10秒間隔が拾った**。逆にシーン検出しか拾えない短時間表示もある。「シーン検出のほうが賢い」という直感は間違い。

パス2は該当0枚だと ffmpeg が異常終了する（静止画面ばかりの素材で起きる）。`|| true` で握り潰してパス1だけで続行できるようにしておく。

## OCR 前に必ずクロップする

Zoom 録画には上部に参加者パネル、下部に Dock が写り込む。切らないと、**ブラウザのブックマークやニュースサイトの文字が検索を汚染する。** 今回 `ランキング` のヒット3件は全部 WAM NET の「アクセスランキング」だった。クロップしてもこれは残ったので、**ヒットは必ず全文を見て実体を確認する**。

## Vision OCR の性能（実測）

| 項目 | 値 |
|---|---|
| モデル初期化 | **約10秒**（プロセスごと） |
| 1枚あたり | 約0.7秒（2360x1330 の JPEG） |
| 656枚を4並列 | 約4分 |

**1枚ずつプロセスを起動すると24秒/枚になる。** 必ず1プロセスに複数ファイルを渡す設計にすること。`usesLanguageCorrection = false` にしないと数字（50,000 等）が言語補正で壊れる。

## 「見つからなかった」を証明する作り方

否定の結論は、走査の網羅性を示さないと受け入れてもらえない。今回やったこと。

1. **画面遷移タイムライン**を出す（連続する同一画面をまとめて時刻範囲で一覧）。全編に穴がないことが一目で分かる
2. **構造的な証拠**を添える。今回は Canva のスライドカウンタ「82/136」が映っていて、探している内容が録画開始前（82枚目より前）にあると裏付けられた
3. **誤ヒットの内訳を表で潰す**（`ランキング`3件＝全部ブラウザ、`5万`37件＝全部「月利50万」）
4. **検証不能な範囲を明示する**。今回は音声トラックが無く（`ffprobe` でストリームが h264 1本のみ）、質疑応答25分は講師のカメラ映像だけ＝口頭説明は原理的に復元不能

# 実売 UNKNOWN の解き方（2026-10-11・T-20260920-003）

## 結論
- **ランク→月販の換算式は当社データでは使えなかった。**monthlySold の境目（≥50 が半数を割るランク）で直線を引くと
  傾きが −0.4 前後に寝て、キーゾン実数（ASIN 単位3か月）に対し **2〜40倍の過大**（例：45万位で推定14個・実数1個）。
  原因は「ランクの取得時期と monthlySold の時期のずれ」で傾きが減衰する（errors-in-variables）。
  錨（r50）を通してキーゾン16点で傾きを決めると β≈−1.19 で誤差1.5〜2倍まで縮んだが、それでも推定。
- **正解はカズヨの発見：30日窓ごとに「直前観測より3%超のランク改善」を数える**とキーゾンと75点中69点で完全一致
  （CLAUDE.md §3.3-16 改訂 9c673a11）。低販売域では1販売＝1改善になるから。ドロップ数が観測回数に支配されるのは
  高販売域（1観測間隔に複数売れる）の話で、**月13個以下なら改善回数はほぼ販売数**。
  → 「ドロップ数は販売数ではない」（2026-09-06）は高販売域でだけ正しい。領域を書かずに一般化していた
- 私が作った「推定月販で GO(テスト)」の別枠は、上の方針で不要になり撤去（rank_velocity.py は未コミットのまま残置・不採用）

## 実装（26_候補提案パイプライン）
- `keepa_unknown_fetch.py`：UNKNOWN 行を `stats=90&history=1&buybox=1` で取り直し（約3トークン/ASIN・再実行は取得済みを飛ばす）
- `screen_checks.py`：
  - 実画面「カートあり=Y・保持者名なし」を**カートなし扱いしていたバグ**を修正（has_cart）。Keepa buyBoxSellerId で名前を補い、
    AN1VRQENFRJN5 は FAIL、出品者名にブランド/メーカー名が含まれれば「疑い」
  - 実画面の「過去1か月 ◯点以上」を Keepa monthlySold 無しでも PASS（Amazon 表示の実数・下限値）
  - `kz_estimate_*.csv` をキーゾン同等として読む（人のキーゾン画面値が勝つ）。**ただし covers()（凍結解除）には数えない**＝
    機械の値で「確認者=カズヨ」の行を解凍しない。観測少で0のときは FAIL でなく UNKNOWN
  - `season_check_*.csv`：人が12か月ランクを目視した季節判定を合流
- `hidden_cart.py`：カートが消えた棚の基準売価＝カートが立っていた最後の90日の BuyBox 中央値（下位25%を悲観値）
- `ledger_refresh.py`：取り直した ASIN は新データで再採点。**GO は出品可否（restrictions/approve）を人が見た行だけ**
  （以前はゲート未確認でも GO になり得た穴があった）。別記 CSV `extra_go_YYYYMMDD.csv`（GO／GO・ゲート未確認／カートなし黒字）

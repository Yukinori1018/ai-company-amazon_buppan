## 結論（2026-10-11・タカシ）
キーゾン実画面の 25 ASIN × 3か月（75点）で検算し、次の式がほぼ一致した。
- **m_k ＝ [now−30k日, now−30(k−1)日) の間に、売れ筋ランク（Keepa csv[3]）が直前の観測より 3% を超えて良くなった回数**
- now ＝ Keepa の取得時刻。ランク -1 を挟んだら直前値をリセット。連続改善もそれぞれ1回と数える（まとめると悪化）
- 一致度：月MAE 0.08個／3か月合計MAE 0.16個／最大誤差1個／完全一致 69/75。**取得時刻が分かっている 10/11 組は 27/27 完全一致**
- 閾値の感度：0%（全改善）は月MAE 6.6で全く合わない（観測ノイズの ±0.1% 揺れを数える）。2〜5%で 0.1〜0.2。10%超で悪化
- Keepa の `stats.salesRankDrops30` も m1 とほぼ同じ（キーゾンは Keepa のドロップ定義に近いものを使っていると推測）

## これで分かったこと
- **キーゾンは「実数」ではなく Keepa ランクからの推定**。人が画面で見る価値は「別根拠」ではなく「同じ数字の目視」。§3.3-16 の「人が実数を見る」は、キーゾンについては Keepa 計算で代替できる（ただし扱いは社長判断）
- **バリエーションの子はキーゾンも family 合計を出す**（FLR 蛍光灯の兄弟で値がほぼ同一）。キーゾンを見ても子 ASIN 単位の実売は分からない
- memory の「ドロップ数は観測回数（相関0.991）」は**閾値なしで数えた場合**の話。**3%の閾値を入れると、低販売域（月0〜13個）では販売回数として使える**。1観測間隔に2個以上売れる高回転品は過小（未検算）

# 「買ってはいけないリスト」をコードに落とすときの型

初出: 2026-09-06 / T-20260904-004 タスク A-2 本番適用（NETSEA 26,942件 → 発注候補セット）
実装: `workspace/output/deliverables/T-20260904-004/risk_rules.py` / `build_order_sets.py`

## 一番の学び — 「例外なく除外」が機械適用できないことがある

リサーチャーの判定資料（`research/draft.md` #2）は「**ブランドが付いた商品全般を除外**」と
書いていた。文字どおり実装したら **候補が 0 件**になった。

理由: **Keepa の `brand` は 19,864件中 19,844件（99.9%）で埋まっている。**
ノーブランド雑貨にも卸元の社名がブランドとして登録されている。
つまり「ブランドが付いているか」を `brand != ""` で判定するのは、
`列名から意味を推測しない`（memory: knowledge_verify_field_semantics_not_names）の再演だった。

### 採った形 — 2段に割って、緩めた事実を明示する

| Tier | 扱い | 実績 |
|---|---|---:|
| A（著名ブランド・大手メーカーのリスト照合） | 機械除外 | 1,661件 |
| B（それ以外） | **残す。全SKUに「ゲート未確認」の印を必ず付ける** | 最終候補全行 |

そして納品物に「**これは実装側の判断であり、判定資料の緩和ではない**」と明記した。
原典自身が「最終判定はセラーセントラルの実機で行う」と書いていたので、そこに接続した。

**教訓: 判定資料が機械適用できない条件を含んでいたら、黙って緩めず、
緩めたことと理由と代替の担保を成果物に書く。**「0件でした」で終わらせるのも仕事をしていない。

## 除外ルールの実装ルール（次回も同じにする）

1. **判定は純関数**にする。CSV も API も知らない `judge(**kwargs)` にする。だからテストできる
2. **引数は全部キーワード専用**。順番の取り違えで誤判定させない
3. **落とした理由を必ず1つ以上返す**。「なんとなく落ちた」を作らない
4. **判定できないものは「要目視」と言う。**「たぶん新品」で通さない（社長の明示指示）
5. **除外の内訳は2通り出す** — 「最初に触れた項目（1商品1回）」と「ルール別の発火件数（重複あり）」。
   前者だけだと判定の**順番**で数字が動き、歩留まりを誤読する
6. `unicodedata.normalize("NFKC", ...)` を必ずかます。`ＵＳＥＤ` が素通りする

## 検算のセット（3つとも効いた）

| 検算 | 何を捕まえたか |
|---|---|
| **宣言した列が全行空なら異常終了** | まだ踏んでいないが、ガードとして実装＋テストで発火確認 |
| **「落とした件数の合計 == 減った行数」** | 理由を数え損ねた行がないことの証明。段階ごとに必ず入れる |
| **ミューテーション**（語彙リストを空にして発火が止まるか） | テストが本当にそのルールを見ているかの確認。単体とパイプラインの**両方**で |

パイプライン単位のテストは単体テストの代わりにならない。
**判定関数が正しくても、呼び出し側が結果を捨てていれば同じ事故が起きる。**
合成行を流して「ルールが繋がっているか」を見るテストを別に持つこと（`tests_order_sets.py`）。

## 実際に出力を見て見つかった不具合（机上では出なかった）

CSV を目で読んで初めて分かったものばかり。**統計だけ見て終わりにしない。**

1. 「プロジェクター機能付ウェザークロック」が残った → 電池駆動の小物を語彙で拾えていなかった
2. 「ウォールミラー 鏡」が残った → 割れ物の語に「鏡」が無かった
3. **あるセットの9SKU中8SKUが「30日で0個」だった** → 回転の下限が無く、供給元の候補数だけで枠を埋めていた
4. 中古「該当なし」の行に「機械判定できない」という矛盾した注記が残っていた → 暫定注記を確定時に消していなかった
5. 統計値が 12社 → 2社 に化けた → 内側のループで外側の変数 `names` を上書きしていた（変数名の使い回し）

3 は `feedback_profit_without_velocity_is_a_lie` をそのまま踏みかけた。
**利益で並べたら回転の下限を必ず別に置く。**スコア関数に回転を掛けるだけでは足りない
（候補数が少ない供給元では、スコア0の行まで枠に入ってしまう）。

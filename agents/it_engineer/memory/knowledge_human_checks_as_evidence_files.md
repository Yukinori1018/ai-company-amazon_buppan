# 人の確認は「証跡ファイル → 毎回合流」にする（T-20260920-003／T-20260930-001・2026-10-11）

## この依頼はこう処理した（再利用できる手順）
1. 入力を全部並べ、台帳に居る ASIN を数える（cartB 78件のうち商品台帳に居たのは8件＝連絡先台帳用だった）
2. 商品台帳：`ledger_refresh.py` に `screen_checks.py` を噛ませ、gates（(名前,状態,理由,注記)）を人の値で上書き → 機械が全部 PASS かつ人がカートを見た行だけ GO
   - 証跡：`agent_output/T-20260920-003/ledger20261010/` の cart_check_*／gate_check_*（名前順＝日付順・後勝ち）／cart_maker_flags_*／legal_flags_*、キーゾンはシートのタブ「実売とゲート_20261005」
   - `--dry-run` → 本番（RUN_TAG=screen で before/after を退避）→ もう1回 dry-run で差分を見る
3. 連絡先台帳：`sync_ledger.py` の collect() でキュー並べ替え**前**にカート合流、listing 読込直後に 62b を重ねる。`--through` はシートの現行バッチまで（縮小ガードが止める）
4. 前後の件数・人の行・社長入力列の不変を照合してから報告

## 学び
- **「確認者=カズヨ」で凍結する設計は、人がカートだけ見た行を永久に固める**（SD の卸価格が後から入っても採算が引き直されない）。証跡ファイルにある ASIN は凍結対象から外し、毎回同じ人の値に戻す
- 指示「キーゾンが無い行は UNKNOWN」は、機械が monthlySold で実売 PASS にしている行には当てない（§3.3-8：monthlySold が積極条件、キーゾンは非表示時の代替）。解釈は報告に1行書く
- NETSEA の確認待ちは全行が月販非表示で、GO の律速は**キーゾン**と**出品一覧の実数**（Keepa の buyBoxEligibleOfferCounts は 10/04 値で競合を多めに数えることがある）
- 季節判定の材料（ランク12ヶ月）は family 共有ランク。キーゾンの ASIN 単位の値で上書きはしない（規定はランク履歴）。代わりに「去年11〜2月のキーゾンを見れば決まる」と書く
- restrictions/approve の OK は「新品の申請経路あり」。lookupAsin 未実測の行は §3.3-25 に従い「出品できる」にしたが、ブランド申請が要る商品も混ざりうる
- 予約の自動同期（30分）が自分の作業途中のコードを先に commit する。commit 前に `git log -- <file>` で確認
- ランダムに揺れるセル（価格振れ幅 77%↔78%）が1つあり、冪等確認で毎回1差分出る（未修正）

# Keepa の JAN→ASIN 逆引きは「当たった商品だけ課金」（実測・2026-08-31 / T-20260831-006）

`knowledge_keepa_token_ceiling_and_unattended_scan` の続編。
**手元に JAN のリストがある**タイプの依頼（卸サイト・展示会カタログ・仕入れ先の商品表）が来たら、まずここ。

## 一行で

`GET /product?code=<JAN13 をカンマ区切り>` は **ヒットした商品1件につき1トークン**。
**ヒットしなかった JAN は課金されません。**

## 実測

| 投げた JAN | 返った商品 | tokensConsumed |
|---|---|---|
| 20件 | 16件 | **16** |
| 20件（全部ヒットする既知の JAN） | 20件 | **20** |
| 150件 | 95件 | **95** |
| **70件（全部ハズレと分かっているもの）** | **0件** | **1** |

最後の行が一番大事です。**全滅でもリクエスト1回あたり1トークンの基本料だけ。**
つまり「卸サイトにあるが Amazon に無い商品」の仕分けは**ほぼ無料**で終わります。

実効コストは **0.633トークン/件**（150件・95トークン）でした。
Finder 起点（10 + ceil(件数/100)）や `offers`（6.5/件）と比べて桁が違います。
**識別子（JAN）を持っているかどうかが、検証コストを16倍変えます。**

### だから設計はこうなる

1. **JAN を持つ経路を優先する。** 商品名検索（`/search` 10トークン/回）は最後の手段
2. 前段フィルタ（0トークン）で機械的に落とせるものを落とす。ここで落とした1件が本命1件ぶん
3. `offers`（実セラー数・6.5トークン/件）は**利益ラインを超えた行にだけ**掛ける

上限1,200・補充20/分なので、**1日あたり約2万件**の JAN を検証できる計算になります。

## 罠1: 1つの JAN に複数の ASIN が返る

150件中 **15件（10%）** で、同じ JAN に複数の商品が返りました。
同じ商品が別々に出品されていて、**片方は死んでいて片方は売れている**のが普通です。

```python
by_jan.setdefault(str(code), p)     # ❌ 最初の1件を採る＝ただのくじ引き
by_jan.setdefault(str(code), []).append(p)   # ✅ 全部集めてから選ぶ
```

選ぶ基準は **売れているか（salesRankDrops30）→ 価格が取れるか → ランクが上か**。
何件あったかは捨てずに列に残す（相乗り先が2つある＝どちらに出すかの判断材料）。

**症状の見つけ方**: `len(products)` と「JAN に紐付いた件数」がズレます。
今回は `products_returned=95` に対し `found=80` で気づきました。
**この2つを別々に数えて記録しておくと、静かなデータ欠落が表に出ます。**

## 罠2: 突合キーは `eanList` / `upcList`

Keepa は「どの code が当たったか」を返しません。商品側の `eanList` を見て
自分で紐付け直す必要があります。紐付かなかったものを「ヒット0」と混ぜないこと
（＝**課金されたのに捨てた**行になり、コストの実測が狂います）。

## 罠3: 出所ラベルは「保存された属性」にしない

`seller_count_source` を普通の dataclass フィールドにしていたら、
値を入れ忘れた経路から**空欄のまま CSV に出ました**（テストで発見）。
**値から導出する property にすれば、由来は必ず値についてまわります。**

```python
@property
def seller_count_source(self):
    if self.real_seller_count is not None: return "実セラー数(offers検証済み)"
    if self.offer_count is not None: return "COUNT_NEW(新品オファー本数・出品者数ではない)"
    return ""
```

`COUNT_NEW` を出品者数と読み違えた事故は過去に候補 top100 の35%を汚染しています
（`knowledge_keepa_count_new_is_not_seller_count`）。**由来を値から切り離した時点で再発します。**

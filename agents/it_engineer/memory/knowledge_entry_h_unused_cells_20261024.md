# 入口(h)：空き升目＋差分の取り直し（2026-10-24 夜間・T-20260930-001）

## 結論
- **月販≥50 を掛けると、ランク方向の空き升目はほぼ無い。**ランク5万〜30万×売価1,250〜1,499 は72件、ランク30万〜50万は0件。新しい入口を「ランク」や「売価」で切っても増えない
- 効いたのは **Finder にだけ掛かっていて build の基準に無い条件**を外すこと：`buyBoxIsUnqualified=False`（u＝カート資格なし 887件→38社）。`current_NEW`（新品最安）で切っていた件（x＝最安<1,250・カート≥1,250）は138件→0社
- 増分の8割は **差分の取り直し**（g と同じ5帯・3日あけて新規 ASIN 2,636 → 186社）。「3日では小さい」は外れた。**一覧は3日で約7%入れ替わる**
- 結果：キュー 5,924→6,154（+230）。token 約4,600

## 手順（再利用可）
1. 既存入口の Finder 条件（各 5x_entry_*.py の SEL_B／57 の BANDS）と build の POST を並べ、**Finder にだけある条件**を探す
2. probe（perPage=50・約11 token/帯）で totalResults を見てから帯を決める
3. `58_entry_h.py list → fetch → build --prefetch → build`。v1 の層3 を目で見て大手・海外有名ブランドを `maker_rules.EXTRA_BIG` に足し、キューを `.bak_entryh_*` から戻して再実行（0 token）
4. 差分だけ回すなら `list --band gb,gc,gd,ge,ga`（DAY タグで別キャッシュ）

## 罠
- `M.E["WIDE_A"]` には **`current_NEW_gte: 2200` が入っている**。売価の下限を外したい帯で上書きを忘れると Finder が0件を返す（x の初回 probe が0件だったのはこれ）
- 別ジョブ（秘書の premium_watch 等）が並行すると残高が20台まで落ち、RESERVE=300 の待ちで fetch が3時間かかった。夜間は余裕を見て早めに始める
- v1 の大手混入は入口 f・g・h の3回とも起きた（毎回15〜90社）。**build の後に層3 の社名を必ず目で見る**工程を省かない

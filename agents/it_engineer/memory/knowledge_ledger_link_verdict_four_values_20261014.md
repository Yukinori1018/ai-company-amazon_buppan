# 紐付け欄は4値の素の値だけにする／キュー上流の枯渇（T-20260930-001・2026-10-14 夜間）

## 何が起きていたか
- 検算（dashin_order.verify）は「紐付けの判定を link_verdict で4値に正規化→一致で始まる＋根拠URL」で見る
- 採取担当が判定欄に文章（「確認済み：会社概要にブランド名」）を書くと link_verdict は**未確認**と読む → Z1〜Z6 の接触候補10社が全員検算落ちしていた
- 原因の半分は自分の実装：sync_ledger.apply_link_checks が一致以外を「値：理由（日付再確認）」と**判定欄に併記**していた。文章を判定欄に書く前例を自分で作っていた

## 直し方（型）
- 67_紐付け確認 で上書きする行は、判定欄＝4値（do.LINK_VALUES）の素の値。理由は備考へ「紐付け再確認（日付・サトル）：値。理由」、書き換え前の原文は備考へ「元の紐付けの判定：…」（黙って消さない）
- 67 の根拠が無い行は書き換えない（HiLIQ「確認済み：…」は残した＝採取担当の再確認待ち）。正規化は「根拠のある行だけ」
- 数えるときは3分類で：4値ちょうど／4値＋理由文（link_verdict は正しく読む＝実害なし）／**4値で始まらない**（未確認と読まれる＝実害あり）。実害のある行は「接触候補」に絞って社名で出す
- 備考に足す処理は classify_dist（備考のキーワードで流通形態を判定）より**後**で走ること。to_row で流通形態が決まった後なので順序は安全

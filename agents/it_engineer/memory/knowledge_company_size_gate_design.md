# 「規模で絞る」は誤り — 3つの誤りを実データで潰した記録

出典: T-20260831-004（2026-08-31）。Amazon の候補メーカー262社に gBizINFO の
規模情報を付ける作業。**当初は「従業員300人以下で絞る」と指示された。**

## 誤り0（最大）: そもそも規模を足切りに使ってはいけなかった

作業の途中で社長から訂正が入った。

> 「従業員300人以下はあくまで目安（私の感想）です。参考数字としていいですが、
>   絶対的な数字としないでください。あくまで参考です。
>   **仕入れサイトからだともしかしたら大企業でも仕入れられるかもしれません。**」

つまり **「仕入れられるか」は相手の属性だけでは決まらず、経路（直接交渉か卸サイトか）
との組み合わせで決まる。** 経路を決める前に相手を落とすと、経路を変えたときに
取り返せない。カモ井加工紙（マスキングテープ mt・420人）や GSI クレオス
（Mr.カラー・311人）は、直接交渉では門前払いでも卸ルートは太い。

**次に同じ作業をするときの原則:**
外部データで得た属性は、**まず列にする。ゲートにするのは、それが単独で
「絶対にダメ」を意味すると確認できたときだけ。**
今回の9社は「直接交渉での通りやすさの目安」でしかなく、その条件を満たさなかった。

実装としては、足切りを消して次の3列に変えるだけで済んだ:
`直接交渉の目安`（◎/—/△）・`規模区分`（〜300人/301〜1000人/1000人超/不明）・
`資本金区分`。**社長が自分で線を引き直せる形にしておくと、
しきい値の議論そのものが不要になる。**

## 誤り1: 従業員数だけでは上場企業が落ちない

社長の条件をそのまま実装すると、**東証上場の2社が両方とも通過した**。

| 会社 | 従業員数 | 資本金 | 従業員だけで判定すると |
|---|---:|---:|---|
| 株式会社ブシロード | **259人** | 57.8億円 | **残ってしまう** |
| Ｈａｍｅｅ株式会社 | **176人** | 6.3億円 | **残ってしまう** |

理由は単純で、gBizINFO の `employee_number` は**単体（その法人だけ）**の数字だから。
持株会社的な構造や、製造を外に出している会社は、上場していても本体は数百人しかいない。

→ **資本金3億円以下を AND で併用**して初めて2社とも落ちた。
中小企業基本法は「資本金 **または** 従業員」のどちらかで中小企業者と定義するが、
本件の目的は「個人事業主の初回小ロットを受けてくれる相手か」なので、
法律の OR ではなく **AND** が正しい。目的から演繹すること。条文をそのまま実装しない。

ただし `capital_stock` は欠測が多く、**取れた会社は大企業に偏る**。
なので **落とす方向にだけ使い、「資本金が取れたこと」を中小の必須条件にはしない**。

## 誤り2: 引けなかった会社を落とすと、狙っている相手から先に消える

gBizINFO は**小さい会社ほど従業員数を持っていない**。
さらに Amazon の `manufacturer` は商号ではなく**ブランド表記**なので、そもそも法人番号を引けない。

- `BOS` → 実体はクリロン化成株式会社。名前だけでは辿り着けない
- `BURTLE` → 実体は株式会社バートル。ラテン文字とカナで表記が違う
- `オスモカラー` → 商品ブランド名であって商号ではない

**「引けなかった＝落とす」にすると、社長が最も取引しやすい相手を優先的に捨てる。**
タケシが同じチケットの初版で実証している（弱い根拠をゲートにして再現率 59.4%）。

→ 誤り0 と合わせて、**落とすものは無い**。全社を理由コード付きで残し、並び順で伝える。

| コード | 意味 | 扱い |
|---|---|---|
| M1/M2/M3 | 中小と確認（両方確認 / 従業員のみ / 資本金のみ） | 残す |
| L1/L2 | 従業員301人以上 / 資本金3億円超 | **落とさない。末尾に置いて △ の印を付けるだけ** |
| U1 | 法人は特定できたが数字が未登録 | 残す（要確認） |
| U2 | 同名の現存法人が複数あり1社に決められない | 残す（要確認） |
| U3 | 商号が完全一致する現存法人を特定できず | 残す（要確認） |

「この条件で落とすと何社減るか」を必ず数字で出して、社長に選ばせること。勝手に落とさない。
今回は 262社中 9社に △ が付いただけで、**出力は262社のまま**。足切りしていたら
253社になり、卸サイト経由という選択肢を実装レベルで殺していた。

## 再利用できる形

- `30_gbizinfo.py` — スロットリング + ディスクキャッシュ付きアダプタ。再実行が無料になる
- `31_name_match.py` — ブランド表記 → 商号 の照合。純関数だけ。API に依存しない
- `32_resolve_size.py` — 段階別内訳と理由コード台帳を出す
- `34_verify.py` — 期待値（△が付くはずの会社・◎が付くはずの会社・**1社も落ちていないこと**）を実測に当てる検算

**検算スクリプトを最初に書いておくと、ゲートの誤りがその場で出る。**
今回も「ブシロードが落ちるはず」の1行が、従業員数単独ゲートの欠陥を10分で暴いた。

# 需要先行スキャンの母数は「ブランドを読む費用」で決まる（2026-09-14 / T-20260914-002 T-1）

## 結論

Finder は ASIN と件数しか返さない。brand / manufacturer は product を叩くしかなく **1 token/ASIN**。
だから需要先行スキャンの費用は「条件に合う ASIN 数」そのもの。Finder の件数プローブ（11 token/回）で先に桁を出し、1,000 token を超えるなら実行前に止めて見積りを返す。

## 実測の桁（domain=5・2026-09-14。件数は近似）

| 条件 | Finder totalResults |
|---|---|
| ランクあり | 8,080万 |
| +本体なし・新品オファー2〜6・2,000〜8,000円 | 300万 |
| +メディア13ルート除外 | 192万 |
| +規制3（ドラッグ・ビューティー・食品）除外 | 174万 |
| ├ +公表の月間購入数≥50 | 1.0〜1.9万（下の注） |
| │ └ +variationCount≤1（単品） | 3,386 |
| ├ +ランク≤3万 | 13.1万 |
| ├ +ランク≤5万 | 19.8万 |
| └ +ランク≤10万 | 32.4万 |

## 覚えること

1. **公表の月間購入数≥50 の行は、オファー2〜6なら取り分≥6 を自動で満たす**（50÷7＝7.1）。推定を1つも挟まずに「取り分≥6」と言える唯一の層。ただしバリエーションの子は家族合算の値なので、単品（variationCount≤1）と子を分けて扱う。公表≥50 の約7割は子。
2. **`monthlySold_gte` は Finder で有効**（≥100000 で 0 件になるのを確認）。`variationCount_lte` も効く。
3. **Finder の totalResults は近似値**。百の位で丸められ、単調でもない（メディア除外で件数が増えた例あり。1.0万ちょうどの返りもある）。見積りには ± を付け、「件数」ではなく「桁」として書く。
4. ランク起点（公表なしの 18〜49個/月 帯）は 13〜32万 ASIN。1 token/ASIN では100時間超なので全件は無理。やるなら層化抽出で比率を出し、母数に掛ける。
5. ランク→月販の較正は保存済み raw（T-20260817-005、1.1万 ASIN）で 0 token でできる。ただし公表値の下限が50なので、18/42個の閾値は外挿＝推測。`monthlySoldHistory` の10〜40 とランク履歴の突合で下側を補えるが、素朴な窓探索は O(n·m) で遅い（2分で終わらない）。やるなら二分探索にする。
6. リスト作成用の常駐ジョブ（list-builder）は STOP 中だった。token を使う前に `launchctl list` とそのログで他のジョブの消費を確認する。

## 手順（再利用）

1. `/token`（0 token）で残高と `tokenFlowReduction` を見る
2. 漏斗を Finder で1段ずつ足して件数を取る（perPage=50、11 token/段）。raw は agent_output に JSON で残す
3. 件数 ×1 token ＋ Finder 一覧（10＋件数/100、1クエリ1万件まで）で見積もる。÷1,200 で時間
4. 1,000 を超えたら、単品層・層化抽出・全件の3案を token と時間つきで返して止まる

プローブ実装: `workspace/output/agent_output/T-20260914-002/takashi/probe.py`（raw/probe_*.json・probe2.json）

## 追記（再起動・2026-09-14）: 見積りを締める 0〜150 token の手

利用制限で1回止まり、再起動してから見積りを締め直した。

1. **再起動したら最初に `/token`。** 前回の消費は raw の `tokensLeft` の差で数えられる（176 token）。60分で上限まで戻るので、1時間以上空けば前回分は気にしなくてよい。
2. **ASIN 一覧は Finder の perPage=10000 で1発**（単品 3,385 件で 44 token）。見積りの精度が上がり、承認後そのまま使える。raw は `t1_raw/` に保存。
3. **1万件の上限は totalResults ではなく asinList の長さで分かる。** 子を含む層は totalResults 10,400・asinList 10,000。承認後に全件読むなら価格帯で割る。
4. **手元の保存 product（7,079 ASIN）との重なりは 15% 程度**（単品 521/3,385）。brand の読み取りには使えるが、価格・オファー・公表値は約20日前。T-2 に渡す数値は取り直すので、見積りでは節約として数えない。
5. **子は兄弟を読み飛ばすと約25%減**（保存データで子 876 件 → 659 家族）。product の `variations` で兄弟の ASIN が分かるので、1本読んだら残りをスキップする。
6. **規制3（ドラッグ・ビューティー・食品）を戻すと公表≥50 層は約1.9倍。** 前回の除外は既定扱いにせず、判断事項として毎回表に出す。

実装: `agent_output/T-20260914-002/takashi/t1_lists.py`・`cache_overlap.py`。報告は `deliverables/T-20260914-002/02_T1_需要先行スキャン.md`。

# 申請画面のゲート列 vs 毎晩の restrictions/approve（2026-10-21 br1021）

## 何が起きかけたか
- 同じ夜の gatefix で `latest_gate_cells()` を「観測日の新しい方が勝つ・同日なら申請画面」にした。
- ところが夜間の実画面取り込み（browser_results_import）は毎晩 `gate_check_<今日>_browser.csv` を作る。
  確認日が申請画面（apply_probe_20261020）より新しくなるので、取り込んだ行の「要書類30点」が
  「可（新品）」に戻る。修正した当夜に、次の取り込みで壊れる形だった。
- 取り込み前に `latest_gate_cells` を読み直して気づいた。

## 直し方
- 新しい restrictions/approve でも、**結論の向き（開いている／不可）が申請画面と同じなら申請画面を残す**。
  向きが食い違うときだけ新しい方が勝つ（不可→可に変わった等）。1行の条件追加。
- 検算：取り込み後の dry-run で TSV 30行の「ゲート種別・ゲート可否」の差分 0 を確認。

## 再利用できる型
- **「新しい方が勝つ」を入れるときは、毎日自動で日付が更新される証跡がないか先に探す。**
  情報量の違う2つの観測を日付だけで比べると、情報の少ない日次の取り直しが常に勝つ。
- 優先順位は「向きが食い違うか」→「日付」→「情報量」。

## one_step の数え方（前夜一致を取るまでに2回外した）
- 「未達：」が無い行（例：`#17 卸値の出どころ UNKNOWN：…` だけの行）も対象。無ければ全文を使う。
- 「残り：」以降（人が見る項目の列挙）は数えない。
- 先頭に「（人の実画面確認を反映）」が付いた区切りがある → 正規表現で括弧書きを読み飛ばす。
- #18 の派生（計算しません／等級 UNKNOWN／実績枠の候補）だけ除く。**#10「実績枠の候補」は除かない**（除くと前夜と一致しない）。
- スクリプトは scratchpad の onestep.py。前夜の台帳 after_<前夜>.json で前夜 TSV と20/20一致を確認してから今夜分を出した。

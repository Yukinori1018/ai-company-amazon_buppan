# Keepa の BuyBox 履歴 — バリエーション親子問題を破れる軸

T-20260906-002 追補 / 2026-09-06。

## 取得方法

`offers=20&buybox=1` を付ける。**`lastBuyBoxUpdate` というフィールドは存在しない。**
`buyBoxSellerIdHistory`（時刻とセラーIDの対の履歴。実測684要素）から自分で計算する。

- `"-1"` = カートが誰にも付いていない / `"-2"` = カートが無効（資格なし）
- それ以外 = 実際にカートを取っていたセラーID
- **カート最終獲得日** = 実セラーIDが最後に現れた時刻
- **不在率** = 直近30日を1日刻みで走査し、その時点の保持者が `-1`/`-2` だった割合

併せて `stats.buyBoxIsUnqualified` / `buyBoxIsAmazon` / `buyBoxStats` / `totalOfferCount` も取れる。

## コスト（2段構えが必須）

**実測 32 ASIN = 191 トークン（約6/ASIN）。** `offers` なしの 1 トークンに対して6倍。
26,942件に当てると16万トークン＝6日かかる（回復20/分）。
**1段目はドロップ数＋観測回数（offers なし・1 token）で全件、2段目は通過分だけ offers 付き。**

## 何が家族で共有され、何が子ごとに独立か

| 軸 | 共有 / 独立 |
|---|---|
| ランク・ドロップ数・レビュー件数 | **家族で共有**（3兄弟で履歴の値が文字どおり同一だった） |
| BuyBox 履歴 | 子ごとに独立 |
| オファー数 | 子ごとに独立（3兄弟で 12 / 0 / 0） |
| 在庫切れ率 | 子ごとに独立 |
| Amazon 公表の月間販売数 | 子ごとに独立 |

**「BuyBox が唯一の軸」ではない。**独立した軸は4つある。
ただし**公表販売数は候補プールの帯（#3万位以下）で取得率0%**、オファー数と在庫切れ率は BuyBox と
強く相関して情報が重複するため、**実務上使えるのは BuyBox だけ**になる。

## 「子ASINは公表販売数を持て」という条件を作ってはいけない

厳しく実装したら候補32件中**0件**になった。この帯に公表販売数は存在しない。
正しくは「**ランク由来でない子単位の根拠を持て**」であり、**BuyBox 条件がその根拠そのもの**。
つまり親子対策は独立したフィルタにならず、**BuyBox 条件を必須にする理由**として存在する。

# ソース未確定のまま作れるエンリッチメント・パイプラインの型

出典: T-20260831-001 Phase C（2026-08-31）。
**外部ソースがサトル/ハルオ待ちで未確定**という条件で、骨格だけ先に作った回。

## この状況の設計判断

依頼が来た時点でソースが決まっていない。ここで待つと丸1日止まる。
そこで「ソースが決まれば差し込めば動く」骨格＋オフライン resolver だけで**動く状態**まで作った。
`run.py` は今日から動き、埋まり率のベースライン（14/822 = 1.7%）も出せた。

**この形は再利用できる。** 未確定要素が1つある依頼では、
未確定部分をプラグイン境界に切り出して、残り全部を先に完成させる。

## 骨格の構成（この6ファイルで足りる）

| モジュール | 責務 | 大事なところ |
|---|---|---|
| `schema.py` | 列定義・確度・分類の定数 | 列を足すときここだけ直せばよい状態にする |
| `normalize.py` | 入力の正規化・分類 | ここだけは実データを見てから書く |
| `resolvers/base.py` | `resolve(row) -> ContactFields` ＋レジストリ | import 副作用で `register()` する形が一番短い |
| `merge.py` | 優先順位マージ | **列ごとに強い方が勝ち、空欄は勝てない** |
| `throttle.py` | ソース別アクセス間隔 | 秒数は config。resolver に sleep を書かせない |
| `store.py` | 逐次保存・再開 | 追記 JSONL が正、CSV は派生物 |

## 運用要件（T-20260804-001 の電源断で学んだ分）

- **1件ごとに追記 + `flush()` + `os.fsync()`。** バッファに溜めない
- **壊れた最終行は読み飛ばして続行。** 電源断は行の途中で切れる。`json.loads` の例外を握って continue
- **JSONL は後勝ち。** 再取得したい社は行を追加すれば上書きになる（ファイルを消さなくていい）
- **CSV は state から再生成できる**（`--rebuild-csv`）。CSV を正にしない
- **1つの resolver がこけても全体を止めない。** try/except で warn して次へ

これを最初から入れておくのは追加コスト30分程度。後から入れると全部書き直しになる。

## 法務判定を待つ間のゲート

`Resolver.needs_network` フラグ ＋ `config.json` の `allow_network: false` で、
外部に出る resolver は**起動時に RuntimeError で拒否**するようにした。
「うっかり走らせた」を仕組みで防ぐ。ハルオの判定が出たら true にするだけ。

`throttle.py` の秒数も config 側に置いた。ハルオが「N秒以上あけること」と条件を出す前提。
コードを直さずに条件を満たせる形にしておくのが、法務待ちの案件でのコスト最小。

## テストのしかた

- 正規化のテストケースは**実データに実在する文字列だけ**を使う。架空の例で通しても意味がない
- スロットリングは `clock` / `sleeper` を注入して実時間を待たない（65テストが0.07秒で終わる）
- 再開可能性のテストは「`ContactStore` を2回インスタンス化する」で別プロセス相当を再現できる

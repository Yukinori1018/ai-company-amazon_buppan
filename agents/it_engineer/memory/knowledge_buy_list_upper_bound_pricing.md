# 買い物リストは「上限価格」を持たせると照合が1秒で終わる（T-20260920-003 / 2026-09-28）

社長の待ち時間を作っていたのは「候補はあるが、卸サイトで何を見ればいいのか分からない」状態。
候補表に **「この上限（税込）以下で買えれば買ってよい」** の1列を付けた瞬間、卸側の作業が
「価格を見て大小を比べる」だけになった。**判定を上流（Amazon 側の数字）で閉じてしまうのが正解。**

## 上限価格の式（`calc/profit.py` に切り出した。UI にも抽出処理にも埋めない）

```
販売手数料(税込) = 売価 × 手数料率/100 × 1.1     # 手数料率は税抜表示
粗利500円の上限   = 売価 − 販売手数料(税込) − FBA配送代行 − 500
利益率20%の上限   = 売価 − 販売手数料(税込) − FBA配送代行 − 売価×0.20
買ってよい上限    = 上の2つの厳しい側
```

- 仕入の消費税は控除できない（免税事業者）→ **上限はすべて税込で出す**。卸の税抜表示と単位を混ぜると即事故
- 実測：**売価1万円未満の帯では「利益率20%」が常に厳しい側**。粗利500円はほぼ効かない。
  つまり低単価帯の実質ルールは「率」であって「額」ではない

## Keepa Product Finder の実測（2026-09-28・トークン222を検証に使った）

- **`current_AMAZON_lte=-1` だけでは 0 件**になる。`gte` と `lte` を両方 -1 にする（謎だが再現する）
- **`outOfStockPercentage365*` / `availabilityAmazon*` は Finder では効かない**（存在しないフィールドと同じ挙動）。
  365日在庫率で絞りたいなら **Finder で前絞り → product 詳細 → 後段で判定** の2段しかない。
  snapshot の `current_AMAZON=-1` は履歴不在の**超集合**なので、前絞りに使っても取りこぼさない
- `monthlySold_gte` は**効く**（Finder で使える。ここは素直）

## 踏んだ失敗：`sort: monthlySold desc` は一番いらない側から返ってくる

monthlySold 降順の上位は **1出品者・月10,000〜40,000個の D2C（サプリ・化粧品）** で埋まる。
メーカーが自分で独占して売っているページであり、卸には載らない。65件中 51件がドラッグストア・
ビューティーだった。**「売れている順」は「仕入れられる順」ではない。**
→ 買い物リストを作るときは、回転より先に **卸に載る見込み（一般流通の国内メーカーか）** で並べる。
　 Amazon 限定ブランド・小売 PB（カインズ等）・Amazon 直営表記はタイトルで機械的に落とせる。

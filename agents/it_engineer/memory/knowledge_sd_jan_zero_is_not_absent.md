# SD の「JAN で0件」は「SD に無い」ではない — 3段照合（2026-10-12・T-20261012-001）

## 何が起きたか
- サンリオ おせわセット（ベビー）クロミ JAN 4550624199285 を SD で JAN 検索 → 0件。
  実際は SD の1ページに キティ/シナモロール/クロミ が S1〜S3 の**内訳**として出ていて、内訳に**メーカー品番 199281 はあるが JAN は無い**。
- SD の JAN は出展企業の任意項目。**JAN を載せた商品だけ JAN で当たる。**載せていない・内訳型は0件になる。
- 逆向きの誤りも残っていた：`26_候補提案パイプライン/superdelivery.py` と README は「JAN では検索できない」と断言（9/30 の n 少）。10/01・10/09 で 38 JAN 中14件は JAN で当たっている。**どちらも言い過ぎ**。

## 規模（記録が残っている分だけ）
- JAN 照会の記録は 10/01（8件）と 10/09（30件）のレーンA jsonl だけ＝38 JAN。**うち0件 24 JAN、品番で引き直せる 12 JAN**（Keepa model または商品名に型番）。
- 10/11 夜の「約90件の JAN 照会」（成果物47 #7）は**JAN ごとの結果記録が無い**（価格を見た12件の CSV だけ）。0件が何件だったかは数えられない＝記録の穴。
- 照会キュー全体（サンリオ50＋10/12キュー＋10/11 小・大 ≒ 15,653 JAN）のうち品番が取れるのは 7,033（44.9%）。
- `sd_queue_build.py` は「照会済み」を JAN 0件の行も含めてキューから外していた → 0件の行は二度と引かれない構造だった（今回の一覧で群「JANで0件」として戻した）。

## 直したもの
- `deliverables/T-20260920-003/28_SD突合/sd_query_plan.py`（新規・通信なし）：`plan()` = JAN → `part_numbers()`（Keepa model → 商品名の型番。単位つき数字・規格語 USB3/IPX7/SPF50/Gen2/2WAY/FNSKU 等を除外。JAN に埋まった品番＝カミオ 069816 は捨てない）→ `name_queries()`（ブランド＋種類＋キャラ名／広めのブランド＋種類。SD は語の AND なので広い方も必須）

## 再利用できる型
- 「検索で0件」を結果に書くときは**どの段まで引いたか**を一緒に残す（`queries` と `verdict`）。段を書かない0件は、後で必ず「無い」と読まれる。
- 照会済みでキューから外すときは「当たった」行だけ外す。0件の行は「別の引き方で再照会」群として残す。
- 品番抽出は1.5万行で頻出上位を見てから規格語を除外する（最初の版は OBD2・USB3・2WAY・SPF50 が上位を占めた）。
- 公開リポのテストに SD の実商品コード・商品 URL を入れない（ダミーの 7654321 を使う）。

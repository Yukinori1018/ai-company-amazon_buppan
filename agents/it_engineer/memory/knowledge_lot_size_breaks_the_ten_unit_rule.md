# 「10点買い」は卸の最小ロットと衝突する（2026-09-30 / T-20260920-003 #21）

## 一行で

Amazon の出品許可申請は「**合計10点以上**」を求めるが、**卸は10点単位で売ってくれない**。
発注額は `卸値 × 10` ではなく、**ロットの倍数**で計算しないと嘘になる。

```python
発注点数 = math.ceil(10 / set_num) * set_num      # NETSEA の set[].set_num = 1口の個数
発注額   = 卸値(税込) × 発注点数
```

## 実測（26件）

- set_num は **1 / 3 / 10 / 12 / 24 / 30** と散る。1が多いが、24・30が混ざる
- 「10点ぶんの金額」で1万〜3万の帯を作ると、**ロット30点＝3万円超の品が帯の中に見えた**（First Arrow の恐竜ぬいぐるみ・ランク9.3万位）。
  予算を上げれば買える良い品なのに、間違った額で「帯の中」と報告しかけた
- 逆に **単価が安くロットが大きい層（単価1,000円未満×24個）は、10点基準で帯を作ると丸ごと落ちる**。
  原価の下限を1,000円→200円に下げて初めて見えた

## 前絞りの向きを2回間違えた記録

| 回 | 絞った軸 | 結果 |
|---|---|---|
| 1回目 | 原価1,000〜3,000円 ＋ 旧ランク50万位以内 | 193→**14件**。旧データにランクが無い品が大半で、ランクで切ると母数が消える |
| 2回目 | ランク不問で193件を Keepa に投げる | 78件通過。**正解**。ランクは有料で当て直すもので、古い値で落とすものではない |
| 3回目 | 「動いている形跡（drops30≥3）」＋ ゆるい採算 | **1件**。採算を旧売価で効かせると、値上がりした品が消える（実例: 4,980→6,999円）。採算は外して94件取得 → 2件通過 |

**教訓: 有料で確かめるべき列（ランク・売価）で、無料の古い値を使って落とさない。**

## 律速が「卸値」から「回転」に移った

19（同チケット）では「Amazon 側は通るのに卸値で落ちる」だった。
原価帯を1万〜3万に狭めたら、**通る卸値の品はそれなりにある**。代わりに落ちるのは回転。

- 採算・本体不在・出品者数を通した78件のうち、**現在ランクが付いているのは40件**
- 完売見込み6ヶ月以内は **2件**（`(drops90/3)/(出品者+1)` で試算）
- monthlySold は **26件すべて値なし**。社長条件の「月100個以上」では0件になる

**ランクとドロップの食い違いは、ランクを優先して拾う**（drops は観測回数で下振れするため）。
ランク5万位以内は A 群に入れ、「ランク60万位以下＋ドロップ0」は両方の物差しで売れていないと判定した。

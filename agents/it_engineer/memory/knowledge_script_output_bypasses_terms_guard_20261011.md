# スクリプトの書き出しは source-terms-guard を素通りする／人の画面確認の合流手順（2026-10-11 夜）

## 起きたこと
- 夜間レポート（write_report.py）が手残り None で TypeError。make_buy_list.load_rows は `net` を**常に None** で渡すので、GO 行が1件でも描画対象に入れば必ず落ちる。`yen()` で「未取得」と書くよう修正。
- 直して再生成したら、32_買う候補リスト.md に**卸の実額が490か所**（台帳の判定理由「卸1点 ◯円以下なら B（いま ◯円）」の転記）。HEAD 版は1か所だけだった＝判定理由に「こう変えれば」の卸値が入るようになってから漏れ始めた。
- **source-terms-guard は Write/Edit フックで、Python スクリプトのファイル書き出しには効かない。** github-sync は30分ごとに `git add -A` → push するので、commit しなくても作業ツリーに置いた時点で公開されうる。
- 対処：未伏せ版は agent_output に退避し tracked 版を HEAD に戻す → `mask_wholesale()` で伏せてから書く → 再生成 → 正規表現で残存0を確認してから commit。テストの文字列にも実値を書かない（架空値にする）。

## ルール化
1. **台帳の判定理由など、卸値が入りうるテキストを成果物（deliverables）へ転記するスクリプトは、書き出し直前に伏せる関数を通す。** フックに頼らない。
2. 再生成した成果物は commit 前に `卸|仕入` ＋金額の正規表現で走査する（guard の scan() は「卸1点 N円（税抜）」の語順を拾わない）。
3. 夜間に deliverables を書く処理は、伏せ処理が入っているかを確認してから常設する。

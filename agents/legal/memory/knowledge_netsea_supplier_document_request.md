# NETSEA サプライヤーへの書類（請求書）依頼 — 判定済みの結論と手順

初出：T-20260912-001（2026-09-12 ハルオ）。成果物 `workspace/output/deliverables/T-20260912-001/04_NETSEAサプライヤーへの書類依頼_法務判定.md`。

## 結論（再利用可）

- **問合せ機能内なら適法**。会員規約7条2項5号の禁止は「当社が提供する機能**以外**」での連絡だけ。ヘルプ invoice.html も「書式や項目の変更が必要な場合は、各サプライヤーへご相談ください」と案内している。
- **NETSEA 外での連絡は、目的が書類だけでも違反**（「連絡を取ること」自体が禁止。締結の禁止は19条3項が別に担当している）。制裁は8条2項1号の催告なしの登録取消し。
- **違約金200万円＋代金50%は「27条3項」**。19条3項違反の「締結」が要件なので、書類の依頼では発動しない。事故の典型は「外で書類を頼む → 相手から直接取引を持ちかけられて応じる」。
- **27条4項＝NETSEA は問合せやチャットの内容を確認できる**（バイヤーは事前に承諾済み）。問合せには「読まれる前提」で書く。
- **サプライヤー会員規約8条も、バイヤーとの外部連絡を禁止している**（鏡写しの条項）。書類の受け取りも問合せへの PDF 添付で完結させる（PDF は10MBまで添付できる）。
- **掛け払い＝GMO が債権譲渡を受けて請求書を発行する** → 卸の請求書にならない。決済方法は注文後に変えられない → 注文時にカードか銀行振込を選ぶ。
- ヘルプの「ダウンロードできる書類は社内管理用」→ **依頼文に用途（Amazon 出品申請の仕入れ証明）を正直に書けば解消する**。
- 手順：①会社概要の閲覧 ②（不明なら）「会社」種別で発行の可否を確認 ③カードまたは振込で10点以上を発注 ④出荷確定後、注文詳細から「注文」種別で依頼（注文番号にひも付けるのが防御になる）⑤PDF は無加工で保管する。②と④の送信は §4.1 の第三者連絡。
- 絶対に書かないこと：外部の連絡先／「メールで」「次回から直接」／実際と異なる数量・日付の記載依頼（私文書偽造・詐欺、アカウントの即時停止）。

## 失敗とリカバリ（最重要）

- **当職が 2026-08-31 に「27条4項＝違約金」と誤って数え、社内の約25箇所に広がった。**27条は順序付きリストで5項。3番目の項が「第１項に規定するもののほか」と1番目を指しているので、違約金は3項で確定。
- 教訓：**条番号は HTML の構造（`<ul class="odListType01">` の `<li>` の順番）から数える。**WebFetch の要約は項番号を勝手に振り直す（今回も「第4項」を別の内容で出してきた）。原文は curl で取得し、テキスト化して読むこと。
- 自分のメモリ3件は訂正済み。他の担当のファイルはカズヨへ引き継いだ（勝手に書き換えない）。

## 手順メモ（規約判定の型）

1. 原文を curl で取得 → script/style を除去してテキスト化 → 条の見出しで区切る
2. 禁止条項を見つけたら、**制裁条項の「要件」**（何をしたら発動するか）まで読み、依頼された行為が要件に当てはまるかを表にする
3. **相手方の規約（サプライヤー会員規約）も読む**。こちらの依頼が相手に違反をさせないか
4. ヘルプページの運用記述（「社内管理用」「決済方法は変更不可」等）は規約ではないが、手順設計に効く

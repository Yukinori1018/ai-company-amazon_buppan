## 1. 結論の型（Keepa 版）

> **効く条文は API T&C §11(1)「reproduce 禁止」ただ1本。制裁は §13 の API 遮断。金銭は §14(3) で 2×年額（約20万円）に上限。Amazon アカウントには波及しない。**

- **§11(1) の条番号は正しい**（`https://keepa.com/cdn/termsAPI.txt` Version of July 28, 2026 を実取得して目視確認済み）。
- **§2(2)「Reselling」・§6.1(1)「Resale」は効かない。**動詞が「販売」。無償公開は当たらない。**ここを誤って引くと過剰判定になる。**
- **§11(2) は「save or print for own business purposes」を明文許諾**。ローカル保存は白。黒いのは公衆送信。
- **penalty / 違約金 / 監査権の条項は存在しない**（全文検索で該当0）。NETSEA 会員規約27条4項（200万円）のようなものは Keepa には無い。
- §12(3) 特別解約は "**intentionally** violated or gross negligence" が要件。自動 `git add -A` は非意図的＝防御可能。**ただし「気づいた後の放置」は gross negligence に近づく。**
- §20 ドイツ法・Kemnath 専属管轄。€1,176 のために提訴する経済合理性は無い。

## 2. ★NETSEA の「非ログインで見えるか」テストは Keepa にはそのまま効かない

**条項の型が違うから。**

| | 型 | 「公開情報だから白」 |
|---|---|---|
| NETSEA | **秘密保持型** | **効く**（秘密でない情報に秘密保持義務は生じない） |
| スーパーデリバリー17条1項 | **一般的発信禁止型** | 効かない（一律アウト） |
| **Keepa §11(1)** | **利用権・複製禁止型** | **効かない**（複製禁止は秘密性を要件にしていない） |

**ただし切り分けには別の効用がある**＝実害と Keepa の "legitimate interests" の大きさが桁で変わる。是正の優先順位づけに使う。

### 切り分けの基準：**その値は Keepa の履歴 DB を通らないと出せないか**

| Keepa 固有の加工値（＝黒） | Amazon で誰でも見えるスナップショット（＝形式的には抵触・実害ほぼ0） |
|---|---|
| 月間ドロップ数／過去最安値／365日最安／価格履歴／月間販売数(ドロップ推計)／実セラー数／消化月数・損益分岐仕入れ値（派生） | ASIN／商品名／ブランド／メーカー／カテゴリ／現在価格／sales_rank／新品オファー数／セラー名一覧 |

**「統計・分布・判断結果」は白。**中央値・件数・カテゴリ内訳は原データを復元できないので "reproduce" に当たらない。→ **成果物は行データでなく統計で出す**のが構造的な正解。

## 3. ドイツのデータベース権（UrhG §87b）は主戦場ではない

- §87b(1)：全部または**量的・質的に相当な部分**の複製・公衆送信は排他権。
- **§87e：相当でない部分の複製を禁ずる契約条項は無効。** → **少数 ASIN の引用まで一律に止めるのは法的に過剰。しきい値運用の根拠になる。**
- **日本には sui generis のデータベース権が無い**（著作権法12条の2は創作性あるものだけ）。行為地は日本・サーバは米国。属地主義から **§87b が直接及ぶかは相当に疑わしい**。
- → **契約（§11(1)）で判定し、データベース権は「争われたら追加で主張されうる」程度に留める。断定しない。**

## 4. 実測手順（次回そのまま使う）

```bash
# 追跡ファイル全体のユニーク ASIN
git ls-files -z | xargs -0 grep -ahoE 'B0[0-9A-Z]{8}' | sort -u | wc -l
# ファイル別（Keepa 固有列名を含むものだけ抽出）
# origin/main に載っているか＝露出の質が決定的に違う
git cat-file -e origin/main:<path> && echo ON_MAIN
git log origin/main --diff-filter=A --format=%ad --date=short -- <path> | tail -1   # 公開開始日
```

**T&C の取得は `curl https://keepa.com/cdn/termsAPI.txt`（平文・認証不要）。**keepa.com 本体は SPA + Turnstile で読めない。

## 7. 制裁は「金銭か、停止か、警告か」を必ず分けて書く

社長は Amazon アカウント3か国停止中で、**「これで Keepa まで止まるのか」が最大の関心事**だった。
→ **①API 遮断（§13・本命）②特別解約（§12(3)・要件重い）③金銭（上限20万円）④Amazon への波及（無い）** と分けて書いたら通じた。
**「規約違反です」だけで返さない。相手が何をしてくるかを条文で特定する。**

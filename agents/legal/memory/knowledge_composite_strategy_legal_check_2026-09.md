## 2. 再判定で動いたもの・動かなかったもの

- **Google トレンド CSV の PUBLIC：不可→条件付き可に変更。** 公式ヘルプ（support.google.com/trends/answer/4365538）が「再利用する場合は Google に帰属することを引用によって示す」と再利用を出典条件で許容。ヘルプは規約ではないが Google 自身の許諾表示（矛盾行為の禁止）。条件＝手動 DL・出典表記・自動取得は不可のまま。
- **YouTube：NO 維持。加えて RSS も不可。** `youtube.com/robots.txt` の `User-agent: *` に `Disallow: /feeds/videos.xml`。「RSS は Data API 外だから可」（9/6 の 01 D2・サトル③ 2-F）は誤り。**RSS だから白、と決めつけず robots.txt を見る。**
- **楽天 API：不可維持。** 10条1項(7)「取得した情報を当社が別途定める目的以外に使用」が明文。「見て知ったことを別の商売に使うのは文言から決まらない」は誤り。(7) で決まる。
- **Instagram Graph API：未確認→条件付き可（優先度低）。** 8/31 の「仕様非公開」は 9/13 時点で誤り。Meta Platform Terms（2026-02-03）3a/3c/3d。逐語未取得なので同意前に再読が条件。

## 4. 型として固定したもの

1. **「規約の名宛人が会員か利用者か」を 1条の定義で切る。** Makuake は会員（16条）と利用者（1条6号）を分けていた。非会員の閲覧者に契約上の義務は無い。社長がその会員かどうかが判定を反転させるので、**必ず「会員ですか」を確認事項に入れる。**
2. **公的機関のサイトでも「規約＝政府標準利用規約」とは限らない**（J-GoodTech は中小機構の独自規約で商業目的の外部利用を禁止）。kougeihin.jp（民間）と同じ罠の別型。
3. **API 規約の「集計値なら白」は規約ごとに違う。** Keepa は reproduce 禁止なので統計は白。SP-API AUP 4.6 は「individually labelled or aggregated」と明文で集計も塞ぐ。横展開しない。
4. **「登録だけ先に」は安全ではない。** 同意した瞬間から DPP §1 の義務が発生する。「実装は後」でも整備は先。タケシの論点⑤ A 案に条件を付けた。
5. **NO の射程を書く型**：表に「禁止されること／禁止されないこと／代替」の3列。社長は「NO で切るな」と言ったのであって「NO を覆せ」ではない。判定は動かさず、切り方を変える。

# 電気用品安全法（PSE）— 転売者の義務と、Amazon 側の本当の壁

初出: 2026-09-08 / T-20260908-001（親 T-20260904-004）。一次情報はすべて当職が取得（取得日 2026-09-08）。

## 1. 結論を1行で

**法律は「表示の確認」1本しかかからない。危ないのは法律ではなく Amazon の書類審査。**

## 2. 義務の名宛人（毎回ここから当てる）

|---|---|---|---|

| 8条1項/2項 | 技術基準適合／検査記録 | **届出事業者** | かからない |

## 3. ★2025-12-25 施行の改正（令和6年法律第67号）を見落とさない

古い解説サイトはこれを載せていない。**転売者のリスクを一段引き上げた3本**:

- **42条の5第1号** — 27条違反で販売しただけで**回収命令**。FBA 出荷済み在庫の回収は金銭で戻せない
- **42条の7** — 法2条3項で「**取引デジタルプラットフォーム提供者**」を新設（Amazon が該当）。
  経産大臣が**プラットフォームに「その者の利用停止」を要請でき**、3項で**DPF提供者は賠償責任を負わない**
- **42条の8** — 違反者の**氏名公表**（個人事業主は個人名）

**3本とも起点は27条1項違反。表示の確認さえ確実にやれば起点が立たない。**

## 4. LED 照明の分類（施行令別表第二・原文）

- （一〇）**エル・イー・ディー・ランプ**（定格消費電力**1W以上**であつて、**一の口金**を有するものに限る）
- （一二）**エル・イー・ディー・電灯器具**（**1W以上**に限り、防爆型を除く）
- どちらも**別表第二＝丸PSE**（菱形ではない）。2012-07-01 追加

**直管形LED（LED蛍光灯）の罠 — ここが本件の核心**

- 両端に口金 → 「**一の口金**」に当たらない → 原則 **電安法対象外**（PSE無しで適法）
- **ただし**経産省解釈例「**口出し線式直管形ＬＥＤランプ**」H28-11-15 は、
  「G13形状ピンは機械的支持のみで通電していない」「単独使用可能で電気用品として完成」を理由に
  **「エル・イー・ディー・電灯器具」＝電気用品**と判断している
- **同じ商品名の中に対象と対象外が混在し、名前・JAN・カテゴリからは機械判別できない**
- → 機械では落とさず、**現物の2問テスト**（①丸PSE＋届出事業者名があるか ②給電が両端ピンのみか）を人間が当てる

## 5. Amazon 側（法律より重い）

Amazon が求める書類は**転売者が原理的に持っていない**:

1. 電気用品**製造/輸入事業届出書の写し（経産省の受領印付き）** ← 届出事業者しか持たない
2. 型式の区分表
3. 定格銘板の写真（PSEマーク・定格電圧・届出事業者名） ← これだけは自分で撮れる
4. **完成品の自主検査記録**（法8条2項の義務者＝届出事業者）
5. **適合性検査証明書**（特定電気用品。法9条）

- **登録時にも事後にも来る。配送方法（FBA/自己発送）を問わない**
- **購入者の申告1件で既存ASINが停止**した実例あり（相乗り出品でも同じ）
- 不備の内容は開示されない（可否だけ）
- **虚偽書類の提出はアカウント停止**（メーカーの書類を無検証で転送しないこと）
- **「制限対象商品」ポリシー違反は 180日以内2件でアカウント停止**（知的財産は5件）
- **FBA危険物納品プログラムは大口出品者のみ**。小口は電池商材を FBA に入れられない

## 6. この依頼の処理手順（再利用可能な型）

1. **義務の名宛人を条文で切る**（3条/8条/9条/10条 vs 27条）。「規制対象か」ではなく「誰の義務か」
2. **政令の別表を原文で読む**。e-Gov 法令API が確実:
   `https://laws.e-gov.go.jp/api/2/law_data/336AC0000000234`（電安法）
   `https://laws.e-gov.go.jp/api/2/law_data/337CO0000000324`（施行令）
   → JSON。`json.dumps` してタグを剥がして grep する
3. **METI の解釈例（対象非対象）を必ず見る。**条文の分類は解釈例で覆る
   一覧 `https://www.meti.go.jp/policy/consumer/seian/denan/subject02.html`
   **WebFetch は 403。`curl -A "Mozilla/5.0"` なら 200。PDF は `pdftotext` で読む**
4. **プラットフォーム側の要件を別立てで調べる。**「適法＝出品できる」ではない
5. **除外ルールを見直す依頼では、必ず現行ルールを実データに当てて「本当に効いている件数」を測る**

## 7. 測って分かった一般則（次も必ず測る）

現行 #1 は 5,136件で発火していたが、**3,431件（67%）は他ルールでも落ちていた＝働いていなかった**。
「最大の除外項目」という見かけは**判定順が早いことによる見かけ**だった（カテゴリ除外は最後に評価される）。

> **除外ルールの重さは「発火件数」では測れない。「そのルールだけで落ちた件数」で測る。**
> 緩和の効果も同じで、最終段（採算・回転）まで通して数えないと過大に見える。
> 今回: #1 だけで落ちた 1,705件 → 非HARDに戻したのは 700件 → **発注候補まで戻ったのは 42件**。

## 8. 社長のこだわり（本件で再確認）

- 「**保守側に倒すとは印を増やすことではなく、印を当たりに行かせること**」
  → 全面除外の維持は「保守」ではなく**判断の放棄**。危険な条件を特定してそこだけ落とす
- 「**緩められないなら緩められないでよい。その場合は理由を条文で示せ**」
  → 結論の方向より**根拠の質**を見ておられる。条文番号と原文引用は必ず載せる
- アカウント停止中は**アカウント健全性の論点を通常より保守側に**。ただし母数を殺さない

### 当職が同時に自主検出した3件（指摘より多い）

- **A**: 1E が 1F より先なので、**センサーライトが「センサー」で自動除外**されていた（18件）
- **B**: v1 にあった否定の例外（**電源不要・電池不要**）を v2.0 で落としていた
- **C**: 1F_PRE を新設した際、**1G（メーカー不明の照明は HARD）を後ろに置いて v2.0 の判断を静かに失った**

### 一般則（3回目の同型失敗。次は必ず先にやる）

> **規則を1本足したら、既存の規則との「順序」を全部洗い直す。**
> 判断もフラグも「勝った分岐」に紐付いているので、分岐を1つ挿すだけで静かに失われる。
> T-20260904-004 で1度やり、T-20260908-001 で**もう一度やった**。テストが無ければ気づけていない。

> **弱い語（それ自体では意味が定まらない語）を単語一致で使ってはならない。**
> 「ライト」「ランプ」「スタンド」「電気」「電源」は、色名・食品・什器・コピー文の一部になる。
> 必ず (a) 複合語で書く か (b) 文脈語との共起を要求する。
> これは「肯定語を単語一致で拾うと意味が反転する」（`knowledge_optout_rules_negation_hole`）の**同じ穴の別の面**。
> 前回は否定と結合して反転した。今回は**多義語が別の意味で当たった**。対処はどちらも共起条件。

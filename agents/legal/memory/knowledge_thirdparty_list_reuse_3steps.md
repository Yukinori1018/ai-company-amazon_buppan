# 第三者のリスト（名簿・出展社リスト等）の二次利用 — 3段階に割って判定する型

## 1. 一番の学び：「使っていいか」を1問で聞かれても、1答で返さない

秘書からの依頼が最初から「3段階に分けて可否を出せ」だったので判定が速く済んだ。**この分け方をこちらから提示できるようにする。**

| 段階 | 行為 | 一般的な判定 |
|---|---|---|
| 1 | 取得して**社内で**解析・分類に使う | **可**（30条の4第2号／素材は事実） |
| 2 | **公開の場に置く**（PUBLIC リポ・Web・配布） | **不可**（21条＋23条1項・2条1項9号の5。30条の4も47条の5も届かない） |
| 3 | そこで**知った事実**を手がかりに、自分で一次情報を取りに行く | **可**（事実に著作権なし。最も安全） |

**判断基準は1つ：「元のリストの代わりになる形で外に出るか」。**代わりになれば黒、社内で消費するだけなら白。

## 2. 使い回せる論証パーツ

### 「無断転載・加工を禁止します」という表示の法的性質

- **契約ではない。**民法522条の申込み・承諾がない。実測でこれを示す：
  - `curl -I <URL>` → 200（ログインなし）
  - robots.txt の有無を `curl -o /dev/null -w "%{http_code}"` で確認
  - ダウンロード前にクリック同意画面が出るかを確認
  → **PDFを開いた後に初めて読める一方的表示は、契約条項ではなく要望・警告。**
- **ただし「著作権者が許諾していない旨の宣言」としては有効に読める。**したがって契約不成立でも、著作権法上の複製・公衆送信は自由にならない。**ここを混同しないこと。**「契約じゃないから自由」は誤り。

### 編集著作物（12条）で素材と配列を切り分ける

> 第十二条　編集物…でその**素材の選択又は配列によつて創作性を有するもの**は、著作物として保護する。
> 2　前項の規定は、同項の編集物の部分を構成する著作物の著作者の権利に影響を及ぼさない。

- 保護対象は**選択・配列**。素材（社名＝事実）そのものではない。
- 抽出物がレイアウト・地図・カテゴリ体系を再現していなければ、素材の利用に留まる。
- **ただし全件をそのまま再公開すると「選択の成果＝集合そのもの」の複製に近づく。**タウンページDB事件（東京地判平12.3.17）は分類体系に創作性を認めた。**社内分類と、集合の再公開は評価が別物。**

### 30条の4 と 47条の5 の限界（暗記すべき文言）

- 30条の4：「…享受し又は他人に享受させることを目的としない場合には、**その必要と認められる限度において**」＋ただし書「著作権者の利益を不当に害することとなる場合は、この限りでない」
  → **公開は「必要と認められる限度」を超える。**社内解析まで。
- 47条の5第1項：「…**軽微なもの**に限る」
  → 全件掲載は軽微でない。**件数が多いほど使えなくなる条文**。

### 著作権が白でも止めない（4つ目の網）

契約違反／民法709条（読売オンライン見出し事件・知財高判平17.10.6の枠組み）／個人情報保護法27条／DMCA通報。
**リストには屋号のみの個人事業主が必ず混ざる**（今回も「深田養蜂」「茶師 木村」「越田鮮魚店」等）。個人事業主の事業情報は個人情報。**PUBLICリポへのcommitは27条の第三者提供に当たり得る。**

## 3. 実査コマンド（次回そのまま使う）

```bash
# 表示の原文を自分の目で見る（引用を鵜呑みにしない）
pdftotext -layout <pdf> - | grep -n "禁止\|無断\|著作\|Copyright\|(C)\|転載\|複製"

# 同意手続きの有無＝契約成立の有無を実証
curl -sSI -A "<名乗るUA>" <URL> | head
curl -sS -o /dev/null -w "%{http_code}\n" https://<host>/robots.txt

# 条文の原文（e-Gov API v2。SPAは使わない）
curl -sS "https://laws.e-gov.go.jp/api/2/law_data/345AC0000000048?response_format=xml" -o c.xml  # 著作権法
python3 -c "import re;s=open('c.xml',encoding='utf-8').read();m=re.search(r'<Article [^>]*Num=\"30_4\"[^>]*>(.*?)</Article>',s,re.S);print(re.sub(r'<[^>]+>','',m.group(1)))"
```

法令ID：**著作権法 = 345AC0000000048**。枝番は `30_4` `12_2` `47_5` の形式。

## 4. 結論の書き方（社長は「くどい」を嫌う）

- 冒頭に3行の結論表。次に「作業を再開してよいか」を明言する（今回は「①の作業は再開できます」と最初に書いた）。
- 白／黒の**線引き図**をコードブロックで1つ入れる。文章より速い。
- **推測と実測を分ける。**今回は判例を「原文まで当たっていない」と明記した。この一行が信用を作る。

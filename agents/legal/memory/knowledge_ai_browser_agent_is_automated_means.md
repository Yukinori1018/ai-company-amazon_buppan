# AI エージェントのブラウザ閲覧は「人が見る」ではない — 楽天は不可・Yahoo は条件付き可（2026-09-14）

初出：T-20260914-002 H-1（ハルオ）。成果物 `workspace/output/deliverables/T-20260914-002/04_H1_秘書ブラウザ閲覧の判定.md`。
9/6 判定（`knowledge_sns_scraping_boundary_2026.md`）の「人が手動閲覧してメモ＝可」の射程を確定した回。

## 1. 型：9/6 の「人が見る＝可」は AI に引き継げない

- 可否は2段で判定する。①その行為が「自動化された手段」か。②相手の条文が自動化手段の何を禁じているか。
- ①の答え：秘書カズヨ（Claude in Chrome 等）が人の指示で1件ずつ開いても「自動化された手段」に当たる。取得・読取・転記を実行しているのがソフトウェアだから。人の指示があっても要件は外れない（自動購入ツールも人の指示で動く）。
- 相手から人と区別できないことは、適法の根拠にならない。
- したがって「カズヨがやれば社長の時間が浮く」系の提案は、毎回②の条文を引き直す。

## 2. 結論（再確認は 2027-03）

| 対象 | 判定 | 決め手 |
|---|---|---|
| 楽天市場を AI が閲覧・転記 | 不可 | 楽天ショッピングサービスご利用規約 第7条1項7号「自動化された手段（自動購入ツール・ロボットなどこれらに準ずる手段）を用いて商品を購入すること（商品ページ上の情報取得等を含む）」。括弧書きを狭く読んでも、仕入れ判断のための価格読取は購入に向けた取得そのもの。件数要件なし・1件で該当。第1条3項で非会員にも及ぶ |
| Yahoo!ショッピングを AI が閲覧・転記 | 条件付き可（確度中・グレー寄り） | LINEヤフー共通利用規約とショッピングガイドラインに自動閲覧を禁じる明文が無い（ガイドライン全文で「自動」0件）。効くのは §14 提供目的外利用（定期取得・蓄積）と §15(5) BOT での「不正に操作」 |
| 楽天の JAN 検索 URL をカズヨが並べ、社長がクリックして読む | 可 | カズヨは楽天にアクセスしない |
| Google ショッピング・価格.com を AI が見る | 不可／未確認＝着手不可 | robots.txt Disallow＋Google 規約／価格.com 規約本文 404 |
| Keepa で楽天・Yahoo 価格 | 無い | AmazonLocale は Amazon 11 か国のみ |

Yahoo の条件8つ（全部必須）：社長の指示で始めたセッション内だけ（夜間・/loop 禁止）／1セッション20件・週60件・同時1タブ・5秒間隔／Keepa 足切り通過 JAN の商品ページと `search?p=<JAN>` だけ／ログインなしの専用 Chrome プロファイル／転記は JAN・価格・送料・ポイント・在庫・URL・日付だけ／履歴列・価格監視をしない・PUBLIC リポに入れない／CAPTCHA 等で即中止・回避しない／カート投入・購入は AI がしない。

## 3. 次回そのまま使う手順

1. 自社 memory の過去判定を引き、その NO/可の根拠条文の「要件」（自動化手段か・会員か・目的か）を確認する。
2. 相手の規約で `grep -n "自動化\|ロボット\|BOT\|情報取得\|収集\|スクレイピング\|クロー"`。一次は `workspace/output/agent_output/<ticket>/..._evidence/` に保存（Git 対象外）。
3. 明文禁止あり → 不可（例外は「事前の許可」＝問い合わせは §4.1）。明文なし → 目的外利用・BOT 条項の射程で条件付き可、8条件＋3点セット。
4. 「社長の時間が減る」見込みは、判定で残った作業を除いて再計算を依頼する（今回：週4時間減→推測で週2〜3時間減に下方修正）。

## 2. 決定表（項目のクラス分け）

- **A＝Amazon の現在スナップショット**（ASIN・商品名・ブランド・EAN/JAN・親子構成・現在価格・現在オファー本数・現在ランク・現在表示の月間販売数・紹介料率・セラーID）→ 公開可
- **B＝Keepa 固有の履歴・派生**（時系列全般・平均・最安・在庫切れ率・BuyBox 交代履歴・ドロップ数・消化月数・損益分岐仕入れ値）→ 非公開。公開物は結論と統計に圧縮
- **C＝会員限定の取引条件**（卸の金額・会員向け品番・上代・ロット）→ Hard NO
- **D＝認証情報・生レスポンス** → 例外なし非公開

**B の例外（グレーを通す3条件）**：ASIN 5件以下／**表にしない**／出典と取得日を明記。根拠は UrhG §87e。**表にした瞬間にアウト**という線は、機械判定と人の判断を一致させるために意図的にそうした。

## 3. ★A を通している理由を取り違えないこと

Keepa §11(1) は**秘密性を要件にしていない**ので、「Amazon で誰でも見えるから白」は Keepa には効かない。
**A を通しているのは規約上の白ではなく、2026-09-06 の社長判断＋実害ゼロという運用判断。** ここを混同した説明をすると、次に「じゃあ B も見えるから白」と展開されて崩れる。

## 4. 「未 push か既 push か」を最初に実測する（今回の最大の収穫）

```bash
git log --oneline -1 -- "<path>"
git merge-base --is-ancestor <sha> origin/<branch> && echo PUSHED || echo NOT_PUSHED
```

- **未 push なら「公開前の修正」で済み、force push も GitHub Support も不要。** soft reset → 再 commit で足り、`reflog` に残るので可逆。
- **push 後は「公開済みの取り下げ」**になり、手段は force push（§4.1・かつ `github-sync.sh` が diverge 検知で停止する副作用）か GitHub Support（§4.1 第三者連絡）しかない。
- **つまり措置の費用は push を境に桁で変わる。緊急判定では「あと何分で自動同期が走るか」を結論の1行目に書く。**
- 同期の一時停止は `workspace/.sync/.lock` を**ディレクトリとして作る**だけで足りる（可逆・§4.1 非該当）。ただし 30分で stale 解除される／解除忘れは成果物同期停止という別の事故。**必ず戻すことを指示に書く。**

## 5. 先例は「引く」が「基準にはしない」

`04_候補ASIN_ゲート実機確認リスト.csv`（68件・**90日平均新品価格**の1列が B クラス）は既に push 済み。
- 取り下げない（2026-09-06 の 227行と同じ扱い＝これ以上増やさない）
- **が、「前例が通っているから今回も」は採らない。**04 は基準ではなく事故。**先例の引用は「措置の重さを揃える」ためであって、「黒を白にする」ためではない。**

## 6. pre-commit の穴（実測で分かった3つ。IT へ渡した）

1. **語彙**：`90日平均` が無く、04 CSV が素通りした。`在庫切れ率` `上代` `SD品番` も無い
2. **粒度**：md は「5列以上の表ヘッダ」だけを見るので、**2列の時系列テーブルは捕まらない**（時系列は列が少ないのが普通）。「同じ列名の行が5行以上続くか」で見るのが正しい
3. **散文の金額**：散文中の卸の金額は「正当な引用」として通す設計。今回 07 がここを通った。`卸[値価][^\n]{0,12}[0-9,]{3,}` のように**金額つきだけ**止めるのが解

**フック自体は設計どおり機能した**（ASIN 24件の警告でタカシが止まった）。**思想は正しく、語彙と粒度の問題**という切り分けを報告に書くと、ゲートを外す方向の議論にならない。

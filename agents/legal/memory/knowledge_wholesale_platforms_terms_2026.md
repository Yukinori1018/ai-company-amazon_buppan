## 2. orosy バイヤーAPI — 覚えておく条文

**規約名は「orosyバイヤーAPI利用規約」。制定 2026-07-23 / 改定 2026-08-29。全35条。**

### 取得方法（SPA なので curl では取れない）

```bash
curl -sS https://wholesale-portal.orosy.com/terms -o t.html
grep -oE 'src="[^"]+\.js"' t.html            # → /assets/index-XXXX.js
curl -sS https://wholesale-portal.orosy.com/assets/index-XXXX.js -o orosy.js
python3 -c "s=open('orosy.js',encoding='utf-8',errors='replace').read();i=s.find('その他の媒体');print(s[i-6000:i+6000].replace('\\\\n','\n'))"
```

**規約全文が `{kind:\"article\",no:\"第１４条\",title:...},{kind:\"p\",text:\"...\"}` という構造化データで JS バンドルに埋まっている。** 同種の Vite/React 製規約ページは全部この手が効く。**バンドル名はビルドごとに変わるので毎回 grep すること。**

### 決定的な3条

- **第1条7号**（本サービスの定義）：「orosyが売主として、仕入元から仕入れた本商品を**事業者に対し卸売価格で販売するEC**」→ **再販がサービス定義に内包されている。**「目的外利用」（第25条(14)）の反論を潰せる。
- **第5条**：「orosyが売主…**利用者と仕入元との間には、本商品の売買その他の契約関係は生じません**」→ サプライヤー承認制が構造的に不要な理由。
- **第28条2項後段**：「なお、APIを通じて取得した本データの利用については、**第14条の定めによる**」→ **一般禁止条項（第25条(4)(9)）より第14条が優先することの、規約内部からの明文根拠。** これが無ければ「特別条項優先」という一般論しか言えなかった。**同種の争点では、規約が自ら参照指示をしている箇所を探すこと。**

### 赤線（交渉不能なので運用で潰す）

| 条項 | 運用防御 |
|---|---|
| 第7条3項「その他orosyが売買契約の締結又は継続を適当でないと判断した場合」＋第9条3項（納期無保証） | **無在庫（受注後発注）を採らない。**Amazon の出荷遅延率に直撃する |

## 3. スーパーデリバリー — 「一律禁止でない」で終わらせない

### 会員規約の場所

`https://www.superdelivery.com/p/contents/guide/rules.jsp`
**トップからは辿れない。`/p/contents/guide/sitemap.jsp` 経由でのみ到達する。** サトルが見つけられなかったのはこのため。**日本のBtoBサイトは規約をサイトマップにしか置かないことがある。**

### 第6条2項（原文）

> 送料の負担、返品の可否及び方法、**購入した商品の販売方法の制限（ウェブサイトを通じた販売の禁止等）**その他の取引条件については、**出展者が当サイト中の各出展者個別の画面に記載された定めに従うもの**とします。**当社は…各出展者が個別に定める取引条件については責任を負いません。**

**「従うものとします」＝会員に契約上の義務がある。** 「一律禁止ではない」で報告を終えると、義務の存在が伝わらない。**必ずセットで書く。**

### 出したソリューション（再利用可）— 出展者ゲート

機械判定が不可能な「相手ごとに条件が違う」類型は、**発注ボタンの手前に人的ゲート＋台帳**を置く。

```
台帳の必須列: supplier_id / supplier_name / amazon_ok(ok|ng|要確認)
             / 原文の該当箇所 / screenshot_path / confirmed_at / confirmed_by
ルール:      台帳に ok が無い出展者は発注をシステム的にブロック
             「要確認」は ng と同じ扱い（グレーは NO）
             読むのは初回1回でよい（第6条1項の継続販売条項）が、
             スクショと確認日は必ず残す（後日の立証は残した側が勝つ）
```

### 第17条（会員になった瞬間に効く）

> 当サイト…に掲載されている画像・文章・マーク・標章等**一切の情報**…を、**当社の事前の同意なく、他のサイトに複製・転用又は発信することを禁じます。**
> 商品によっては、**会員の運営・関係するホームページ上で**紹介することは可能です。**ただし、掲載の可否、方法については、当社の事前の同意を要する**ものとします。

→ **PUBLIC リポへの commit は「他のサイトに…発信」に当たる。**
→ 第17条2項の例外は Amazon に届かない（Amazon は会員が運営していない）。**しかも例外にすら事前同意が要る。**
→ **JAN で既存 ASIN に相乗りするだけなら SD のコンテンツを何も使わないので抵触しない。** これが実務解。

### 非会員クロールの速度

robots.txt の `User-agent: *` は `/p/r/pd_p/` を Disallow していない。**が、`meta-externalagent` と `PetalBot` には `Crawl-delay: 10` を設定している。→ 当社も10秒に合わせる。** サイトが明示した数字がどこかにあるなら、それに揃えるのが最も説明しやすい。

## 4. ザッカネット — 「規約が公開されていない」で NO にした

**確認した範囲（ここまでやれば「無い」と言い切ってよい）**

1. トップページの全 `href` を抽出 → 規約系は privacy のみ
2. `guide/` の全 `href` → 同上
3. `guide/kiyaku.php` `terms.php` `rule.php` `agreement.php` `reg/kiyaku.php` → **全て 404**
4. `sitemap.xml` → 子 `sitemap-1〜4.xml` を全件走査 → **規約URLゼロ**
5. 登録フロー1画面目 `reg/reg_01.php` → 審査基準はあるが規約リンクなし

**判定文：「規約を読まずに会員登録することは、内容を知らないまま法的拘束を受けることです。§4.1 該当行為を白紙で行うことになります。法務として承認できません。」**
→ **この1文はテンプレ化してよい。** 規約非公開のサービスは全部これで NO にできる。

**解除手順として渡したもの**：登録フロー step2 まで進んで規約全文を取得（**同意チェックは押させない**）。押した時点で §4.1 違反になると明記する。

**「固定電話が要る」への回答の型**：①要件自体は適法な私的審査基準 ②実際に0ABJ回線を引けば満たせる（＝金銭＝§4.1）③**バーチャルオフィス番号を「事務所」と偽るのは規約違反かつ刑法246条の問題。絶対にやらない**。

## 5. 卸の達人 — 送料の不一致は「定型約款の変更」条項とセットで指摘する

- **会員規約 第20条 送料700円（税込）／第21条 代引315円（税込）**
- **特商法表記 送料990円（税込）／代引330円（税込）**
- **第2条「弊社はいつでも利用者の事前、事後の承諾無しに本契約を変更することができる」**
  → **民法548条の4（定型約款の変更）の要件を満たさない。** 同条1項2号は「変更が…**合理的なものであるとき**」を要求する。**不利益変更は無効となる余地が大きい。** 送料不一致を報告するとき、この一文を添えると価値が上がる。
- 特商法表記の**「メーカー都合による販売方針の変更（販売ルートの制限など）は、ご返品不可」**
  → **Amazon 販売が後から禁止されても在庫を戻せない。** これは経理・戦略側に効く指摘。

### EUC-JP のサイトがまだある

```bash
curl -sSL "https://www.oroshi-tatsujin.com/..." | iconv -f EUC-JP -t UTF-8
```
`file` が `ISO-8859 text` と言ったら、`<meta charset>` を見る。**EUC-JP / Shift_JIS を素で読むと `grep 規約` が空振りして「無い」と誤判定する。** 今回1回踏みかけた。

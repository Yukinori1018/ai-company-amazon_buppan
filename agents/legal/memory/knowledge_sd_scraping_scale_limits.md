# SD 公開ページの自動取得 — 429 を受け取った後は「規約に禁止が無い」が反論にならない（2026-09-30）

初出：T-20260920-003（タカシからの再判定依頼）。成果物 `workspace/output/deliverables/T-20260920-003/29_SD自動取得の規模_法務判定.md`
併読：`knowledge_wholesale_platforms_terms_2026.md` §3（SD 会員規約の所在・第6条2項・第17条）／`knowledge_public_page_terms_rule_and_leak_detection.md`（発信側の判定）／`knowledge_ai_browser_agent_is_automated_means.md`（自動化手段の該当性）

## 0. この回の最重要（他サイトにも効く型）

🔴 **`HTTP 429` は相手の意思表示である。受け取った時点で「規約に自動取得の禁止条項が無い」は反論として死ぬ。**

SD は 2026-09-30、当社に 429 を返した（累計**125リクエスト**・間隔2秒。**4秒間隔・64秒バックオフでも復帰せず**）。
これで判定が3つ変わる。

1. **「禁止と知らなかった」という最大の防御が消える。**相手が当社の取得量について直接、拒否を通知した。
2. **刑法233条／234条の2の故意の評価が変わる。**Librahack 事件の行為者には拒否通知が無かった。**当社にはある。**429 後に総量を上げた記録は最も不利な証跡になる。
3. **第10条(2)「会員として不適切な行為」の認定材料になる。**「レート制限を受けた後も継続した」は裁量判断で決定的。

→ **依頼された3案（700回／7,000回／数万回）は全部 NO。**429 が出た水準（1日125回）の 5.6倍・56倍・それ以上だから。
→ 縮小案として **1日30回・間隔10秒・人の在席下・Amazon 起点の1 JAN=1リクエストのみ** を条件つき可にした（30 は 125 の4分の1未満という安全側の推定。**SD が示した数値ではない**と明記した）。

🔴 **そして「429 で止められたから別の経路で」は絶対に通さない。**
本件では「大量スキャンは**ログイン済みブラウザの同一オリジン iframe** で回すのが唯一の道（1ページ約1秒・2,176社を40分）」という申し送りが既にチケットに入っていた（他のエージェントが実装済み）。**依頼範囲外でも黙って通さず、単独の章を立てて NO にした。**理由は重い順に：
(a) **拒否を別の入口で迂回した事実が自社の記録に残る**（チケットが「429 で止まるからブラウザで」と書いている＝意図の自白）
(b) **会員アカウントに直接紐づく**（非ログインなら最悪 IP 遮断で済む。ログインは第10条＋第11条1項で予告なし・即時・賠償なし）
(c) **1リクエスト/秒は Librahack と同一速度域**、しかも当社は拒否通知を受けた後
(d) **公開判定ルールの第1の足「非ログイン表示を実測」が立たなくなる**
**不正アクセス禁止法は不該当**（自社の正当な ID）。**過大に脅さない。**止める根拠は契約と刑法と不可逆性。

## 1. 確定した数値（再確認 2027-03-31）

| 規模 | 判定 |
|---|---|
| Amazon 起点・1 JAN = 1リクエスト・**1日30回・間隔10秒・人の在席下** | **条件つき可**（3点セット必須） |
| 種語で広く当てる「索引づくり」（数百回〜） | **不可**（429 の水準を超える＋SD が名指しで拒む「網羅的索引化」と目的語が一致） |
| 無人・夜間・数千回 | **不可**（429 の解除条件が不明なまま無人運転は制御不能。第3条で規約の一方的変更に同意させられる経路も開く） |
| 全社網羅（数万回）／ログイン済みブラウザで1ページ/秒 | **不可**（§0） |

**追加の必須条件：429/403 を1回引いたら7日間全面停止**（8日目以降は1日10回から。2回目が出たら SD へ照会するまで再開しない）。
**User-Agent は名乗らせる**（`SatoySelect-lookup/1.0 (SD member 3166793; contact: ...)`）。偽装 UA で大量取得は、後から説明する立場になったとき最悪の絵。名乗ってブロックされたら停止トリガで止まるのが正しい設計。

## 2. この回で確立した型 — 「明文禁止が無い」は判定の始点であって結論ではない

SD 会員規約（改訂2023.9.1・全17条）の全文に `自動` `ロボット` `BOT` `クロー` `スクレ` `プログラム` `収集` `データベース` `名簿` `競業` `過度` `負荷` `サーバ` `アクセス` `情報取得` を当てて **禁止条項ゼロ**を確認した。
それでも可否が分かれるのは、**第10条(2)「会員として不適切な行為」＋(5)「その他やむを得ない事由」が白紙委任**で、**予告なし・即時・第11条1項で賠償責任も否定**されているから。
→ **規約に禁止が無いサイトほど、「切られる条項」の広さで判定する。**訴訟リスクより「黙って切られるリスク」を見る。

## 3. 数値の根拠は robots.txt の UA 別の差にある（再利用できる読み方）

SD の robots.txt は `*` には検索パス `/p/do/psl/?word=` を許可し Crawl-delay を付けず、**`meta-externalagent` / `meta-webindexer` には `/p/do/psl/` `/p/do/dpsl/` を全面 Disallow ＋ Crawl-delay: 10**、`PetalBot` にも Crawl-delay: 10 を課している。

読み取り：**「利用者の閲覧は許す／機械で網羅索引化する者には検索パス自体を使わせない」。**
- 当社の UA は `*` だが、**総量と継続時間を上げるほど挙動が名指しクローラ側に寄る。**「①は利用者の閲覧と説明できる／②は説明できない」という線がここから引ける。
- **サイトが数字を示しているなら、その数字に合わせるのが最も説明しやすい**（SD が示した唯一の数値＝10）。明文主義で 10 秒を選ぶと、なぜ5秒でないのかを説明する必要がなくなる。
- ③を不可にした決定打は「**`/p/do/dpsl/`（企業内検索）が名指しクローラに全面 Disallow された唯一のパス**」であること。**やろうとしている経路が、相手が名指しで閉じた経路と一致しているかを必ず見る。**

## 4. 会員になると前回判定は失効する

2026-09-14 は「登録前」の判定。会員になると第1条2項（規約＋当社が定める規定・規則・条件等に従う）の主体になり、**非ログインで取得しても会員としての義務は外れない。**
→ **「非ログインだから会員規約の外」は採れない。**会員は非会員より義務が重い（第10条の停止権の対象は会員だけ）。
→ **プラットフォームの判定は「会員か否か」で必ず再判定する。**入会は前提の変化。

## 6. 第17条3項を見落としていた（自分の過去判定の補強）

`knowledge_wholesale_platforms_terms_2026.md` §3 は第17条1項・2項しか書いていなかった。
**3項「他のサイトが、当サイトとのリンクを貼る場合には、当社の事前の同意を要する」**＝SD の商品 URL を PUBLIC リポに書かないルール（CLAUDE.md §3.2）の**直接の明文根拠**。従来は NETSEA 側の条項を横引きしていた。
→ **条文は項まで全部読む。**1項で結論が出ても3項に別の武器が落ちている。

## 7. 規約の外に残る2本（公開ページでも消えない）

- **刑事：岡崎市立中央図書館事件（Librahack, 2010）。約1秒間隔のプログラムで逮捕・20日勾留・起訴猶予。真因は相手側システムの不具合。**攻撃意図が無く相手に原因があっても逮捕は起きた。
  → **最重要の防御は「間隔」より「相手が重くなったら自分から止めた証跡」。**4xx/5xx/タイムアウト/応答遅延で即時全停止し当日再開しない、を必須条件にする。
- **民事：翼システム事件（東京地判 平13.5.25）。DB の著作物性は否定、但し大量複製して競合販売する行為に民法709条。**内部の仕入れ判断限定・再配布なし・非競合の3点で要件を外せる。**外部へ出した瞬間に第17条1項と709条に同時に入る。**
- 不正アクセス禁止法は不該当（認証の突破・回避が無い）。

## 8. 条件は「機械で守れる形」で書く（タカシからの明示要求）

「慎重に」は実装できない。**間隔（秒）・1日総量（回）・1回上限（回）・連続時間（時間）・停止トリガ（HTTP コード）**の5つを数値で出すと、定数1つで守られる。
特に **1日総量は永続カウンタでなければ意味がない**（1回の実行上限だけでは、2回起動すれば無制限）。
**UA は名乗らせる。**偽装 UA で数千回は、後から説明する立場になったとき最悪の絵。名乗ってブロックされたら停止トリガで止まるのが正しい設計。

## 9. 一方的変更条項は「長期の無人運転」と組み合わせると危ない

SD 第3条：掲載した時点で効力発生・**アクセスしたことで同意扱い**。
→ 夜間自走で数夜にわたる取得は、**知らないうちに追加された禁止条項に同意したことにされる**経路が開く。
→ **実行の冒頭で robots.txt と規約ページを取得しハッシュ差分で停止**を必須条件に入れた。この条件は他のプラットフォームでも使える。

## 10. 残した不確実性の書き方

`faq.superdelivery.com` は Helpfeel 製 SPA で記事一覧が HTML に無く、`sitemap.xml` は 404、`/search?q=` もサーバ側 404。**第1条2項でヘルプは契約内容を構成しうるので、ここは潰せていない。**
→ 「①は既に同規模を実施済みで実害ゼロだから影響しない／②の実行前に潰す」と**規模別に影響範囲を切って**書いた。**確認できなかったことを『無い』と書かない。**

## 11. 「先に全部の索引を作る」という設計が無理の出所だった

依頼は「索引として使える量まで増やしたい」。だが仕入れ先起点の歩留まりは実測15%（サトル）＝**2,176社を読む作業の85%は捨てる作業**。
→ 代替は既存の「出展者ゲート」（`knowledge_wholesale_platforms_terms_2026.md` §3）。**発注ボタンの手前で、発注する1社だけを人が読む。**母数を先に確定しない。
→ **規模の判定を頼まれたとき、「その規模が必要な設計自体が正しいか」を1度疑う。**規模を削る代替が事業側でも正しいことが多い。今回は法務NOが事業の遠回りを解いた。

## 12. 実装の「エラーを握りつぶす」は法務上の最重要バグ

タカシが直した点：429 を1件ずつの失敗として飲み込み「JAN 付き0件」と返していた。
**「相手に無い」と「こちらが止められた」の混同＝拒否の通知を受け取ったことに気づかないまま走り続ける実装。**
→ **法務レビューでは必ずエラーハンドリングを見る。**専用例外で全体即停止・自動再試行なし・終了コードで区別、が正解。**バックオフして再試行する経路が残っていないかまで確認する**（4秒間隔・64秒バックオフでの復帰試行は、それ自体が「拒否後の継続」になる）。

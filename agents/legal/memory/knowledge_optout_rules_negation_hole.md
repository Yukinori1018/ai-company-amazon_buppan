# 機械判定ルールの「否定の穴」— 肯定語を単語一致で拾うと意味が反転する

- 初出: 2026-09-04 / T-20260904-004 タスクB-1L / `B1L_optout_rules.json` v1.0 → v1.1
- 検出者: IT タカシ（自分ではない。**自分が作ったルールの穴を他人に見つけられた**）

## 何が起きたか

「営業お断り」表示の A〜E 判定ルールで、A_PLUS（最優先で打診）の規則 `A1_trade_window` を
**肯定語13語の単語一致（match:any）だけ**で作った。結果：

    「お取引希望の方は下記フォームへ ／ …新規お取引は行っておりません」→ A_PLUS（優先度1）

**打診してはいけない相手が、最優先候補として社長の手元に届く**方向の誤り。取りこぼしより悪い。

## 原因（3つとも設計の誤り。語彙不足ではない）

1. **D/E/B/C は「拒絶語 × 対象語」の共起で作ったのに、A系だけ加点語の単語一致にした。**
   肯定語は否定と結合して意味が反転する。単語一致で扱ってよい語ではない。
2. **拒絶側の防波堤を「完全一致リスト」に置いた。**日本語の丁寧表現は語尾のゆれが大きい。
   実際「新規**の**お取引は行っておりません」は載っていたが「新規お取引は…」（の抜き）で素通りした。
   **完全一致リストを防波堤にしてはならない。**必ず共起／近接判定を本体にし、完全一致は補助に置く。
3. **「取りこぼし（A→D）」と「化け（D→A_PLUS）」を同じ重さで見ていた。**後者だけが不可逆。

## 再発防止として入れたもの（ルール設計の型として再利用する）

- 肯定語の規則には必ず `negation_terms` ＋ `negation_lookahead_chars`（直後N文字）を持たせる
- 否定の本体規則は**方向性のある近接判定**（left の直後のみ。無方向の共起で代用しない）
- `left_context_guard`（直前M文字）で「一般消費者には直販していない」型を除外する
- **未知の match 種別は実装が黙って読み飛ばさず異常終了する**ことを `engine_requirements` に明記。
  読み飛ばしを許すと、法務が塞いだ穴が実装側で黙って開き直る
- 個別判断は `aliases` を持たせ、正式商号・法人番号でも突き合わせる
  （同一法人が3表記で重複登録され、除外が1行にしか効いていなかった。ストームレーベルズ）

## 検算のやり方（次回も同じ手順でやる）

1. 旧版を凍結コピー → 2. 語彙 × 否定テンプレの**合成マトリクス**で網羅検査
（今回 13語×7類型=91パターン。v1.0 は 91/91 が A_PLUS に化け、v1.1 は 0）
3. **肯定形でも回す**（過剰是正＝母数を減らしていないかの確認。39パターンで喪失0）
4. 実データに当てて差分を出し、**変化の向き**（除外が増えたのか打診可が増えたのか）を必ず報告する

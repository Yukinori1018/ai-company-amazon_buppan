# NETSEA は「発見の母集団」に使えない — 撤退条件の受け皿を誤った件

初出: T-20260831-004（2026-08-31・法務ハルオの判定を受けて修正）

## 何を間違えたか

案Cと §11 の撤退条件に「Keepa が尽きたら **NETSEA**・展示会出展社名簿へ軸足を移す」と書いた。
NETSEA で見つけて外で交渉する行為は、バイヤー会員規約に**明確に違反**する。

| 条項 | 内容 |
|---|---|
| 第7条2項5号 | 機能外でサプライヤーと直接・間接問わず連絡することの禁止 |
| 第19条3項 | NETSEA を利用しない売買契約の締結の禁止 |
| 第27条4項 | 違反時＝事業者名の公表・契約解除・**違約金200万円＋売買代金の50%** |

**当社は Buyer API トークン発行済み＝既に会員＝現に拘束されている。**「将来契約したら効く条項」ではない。
NETSEA 内で完結する仕入れは適法。禁じられるのは**発見の入口として使い、外で商談すること**。

## 学び（次に同じ設計をしないために）

1. **撤退条件の「受け皿」も規約チェックの対象。** 本文の実行計画だけを法務に見せて、撤退条件を素通りさせた。
   撤退条件は「発動したときに実行される計画」であり、実行計画と同じ強度で審査が要る。
2. **API トークンを持っている＝規約に拘束されている。** 「まだ本格利用していないから関係ない」は成り立たない。
   既存の実装・蓄積データ（`adapters/netsea.py`・取得済み企業名リスト）も用途を仕分ける必要がある。
3. **「A が尽きたら B」と書くときは、B の母集団としての独立性を数字で確かめる。**
   今回の代替＝展示会出展社名簿は 2,353社（国内85%）で、Keepa 由来1,249社との重複が **2社（0.1%）**。
   独立が実測されているから、NETSEA を外しても撤退条件は成立した。**代替が無い状態で条件だけ書くのは絵。**
4. **削除ではなく置き換えで残す。** 条文番号と違約金額を本文に書いた。
   理由を書かずに消すと、半年後に「NETSEA 使えるのでは」と誰かが再提案する。

## 書き方のテンプレ（今回採用した形）

> 受け皿から NETSEA を外しました（法務判定）。第7条2項5号・第19条3項に該当し、
> 制裁は第27条4項の違約金200万円＋代金50%＋事業者名の公表。
> 発見の母集団には使わない（NETSEA 内で完結する仕入れは適法）。代替＝展示会出展社名簿（重複0.1%）。

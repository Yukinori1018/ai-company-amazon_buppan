# ロット金額は需要から逆算する — 「10万円で組め」は金額でなく売れる量の問題

初出: T-20260909-002 / 10_1周目10万円ロット（2026-09-15）

## 何が起きたか
- 社長「最初は10万円くらいでテスト。それくらいないと送料負けする」。1周目を約10万円のロットで組む依頼。
- 作業中に追加条件が来た:「月100個以上売れている商品（またはその類似）でないと勝ち筋がない。月数個は除外」。Keepa の monthlySold（ドロップ数ではない）で、子は子自身の値で見る。
- 結論は「NETSEA の現プールでは組めない」。月100個以上の母数は社内の T-1 需要先行リストにある（1,300件・858社）。足りないのは安く仕入れられる卸。推奨は SD 承認後の照合（A）、メーカー直（B）は並行。

## 学び
1. **ロットの金額は需要の関数。** 足切りは「取り分 ≥ 数量÷1.8」。10万円・単価2,000円なら50点で、取り分28個/月が要る。高単価品なら少ない需要でも金額は届く（orb は10台で8.8万円）。ただし月数個の棚で金額を埋めるのは、社長の新条件で否定された。**金額に合わせて商品を選ばない。売れる量から数量を決め、合計が8〜12万円になる組み合わせを探す。**
2. **「件数を数えて」と言われたら、そのフィールドが存在するかを先に確かめる。** NETSEA プールの Keepa データ（verified.jsonl など）には monthlySold が無かった。0件ではなく「未計測」と書き、代わりの目安（ドロップ・取り分）と確定用の S を添えた。無いものを0と数えない（knowledge_verify_field_semantics_not_names と同じ系統）。
3. **送料負けは固定費÷点数で見せる。** 1回の納品の固定費は仕入れ送料1,500円＋1箱750円＋12円/点（ハジメの置き値）。4点で574円/点、40点で87円/点。社長の直感を数字で裏づけると、次の判断が速い。大口の月額（6ヶ月3.2万円）はロット1本の利益では回収できない。月1本ペースが要ると書く。
4. **ゲート10点は「同じブランド・合計10点・請求書1枚」で満たす。** SKU をまたいでよい。1社に寄せる設計がそのまま申請書類になる。申請は発注後にしかできないので、却下された場合の売り先を足切りに入れる。
5. **季節は「売り始めの月から6ヶ月」で見る。** アミノは5〜8月に売れ、冬はほぼ0。10月売り始めなら昨年10〜3月の月販を足切りにする。再判定の日付（2027-03上旬）まで書いておく。

## 手順（再利用できる形）
1. 各プールで、社長条件のフィールド（今回は monthlySold）が取れているかを確認 → 数える → 無ければ「未計測」と S
2. 条件を満たす母数がどこにあるか（社内の既存リスト → 卸との照合結果）を探す
3. 組めなければ「組めない」と書き、組める経路を A/B/C にする（確率＝経路の通過率の積）
4. ロットの型（金額・社数・SKU数・数量の決め方・支払い・届け先・足切り）を表1枚にする
5. 固定費÷点数の表、やらないこと、ロードマップ（日付×結果×次の一手）、S 表を付ける
6. 公開版は卸値・Keepa 加工値（取り分・ドロップ・個別の月販）を抜く。件数・社数・率は出してよい

# ランキング帯は仕入れ候補の質を説明しない（実測で決着）

初出: T-20260831-004（2026-08-31）

## 3つの事実

1. **当社の候補プールは96.8%が既に5万位以内**（n=2,635・中央値3,840位）。
   `RANK_MAX` は30万位に設定されているのに、5万〜15万位は**1.2%しか無い**。
   理由は Finder のソートが `salesRankDrops30 降順`（よく売れている順）だから。
   → **社長が2026-08-04に指示した「5万〜15万位」は、設定上は入っていたが、データ上は実現していなかった。**
   **設定を変えただけでは条件は変わらない。ソートと母集団の取り方まで見ること。**

2. **帯を細かく刻んでも本命率は単調にならない**（メーカー単位・ラベル済み200社）：
   1〜5千位 15.8% / 5千〜1万位 21.4% / 1万〜2万位 8.3% / 2万〜5万位 0.0%。

3. **大カテゴリ順位とサブカテゴリ順位の取り違えは起きていない。**
   `scan_v14.py` の `current_SALES` は参照カテゴリ（大カテゴリ）順位。
   実測で 大カテゴリ順位 ≒ サブ最良順位 × 76倍（p25=14 / p75=248）。
   「サブで5万位以内」は99.7%が通過するのでフィルタとして機能しない。
   **セミナーの5万位は大カテゴリ順位と解釈するのが妥当。**

## 提案（採用）

**ランク帯を条件から外し、`salesRankDrops30 ≥ 10` を実需の下限として使う。**
ランクは「カテゴリ内の相対順位」であって販売個数ではない（`reference_keepa_reading_pitfalls`）。
DVDの5万位とペット用品の5万位は別物なので、ランクで切るとカテゴリの大きさの違いをそのまま持ち込む。

## 未検証のまま残したこと（正直に書く）

**5万〜15万位の帯が有効かどうかは分からない。** 当社はその帯を採取していないから。
検証は Finder のソートを変えた1本の走行（約300トークン・課金なし）で済む。
**「効かない」と「試していない」を混ぜて報告しない。**

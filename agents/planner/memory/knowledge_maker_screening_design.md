# 仕入れ可能メーカーの選別設計（v15）— 実測済みの判定力

初出：T-20260831-004（2026-08-31）。母集団＝Keepa 由来のメーカー候補 1,254社。
**この分野は「効きそうなルール」が軒並み外れる。必ずラベル済みサンプルに当ててから採用すること。**

## 1. 母集団の実像（無作為200メーカーを手作業分類）

| 区分 | 比率 |
|---|---:|
| 日本の小規模メーカー/代理店（本命） | 12.0% |
| 日本の中堅メーカー | 4.0% |
| 大企業・上場・グローバル | 18.0% |
| 版元・レーベル・出版社 | 23.0% |
| **中国系OEM・越境ブランド** | **35.5%** |
| 海外（非中国）メーカー | 7.0% |

**Keepa の数値条件（ランク・セラー数・利益率・サイズ）だけで作ると 84% がノイズになる。** これは条件の緩さの問題ではなく、
**「よく売れている × セラーが複数」という条件が、大手と越境OEMを最も強く引き当てる**という構造的な帰結。

## 2. 効いたルール（適合率／再現率＝実測）

| ルール | 適合率 | 再現率 |
|---|---:|---:|
| メディアカテゴリ除外（DVD/音楽/本/洋書/ゲーム/PCソフト） | 91.8% | 97.8% |
| CNスコア≧3（下記6シグナルの重み和） | **100%** | 38.0% |
| S1 ブランド自社出品（セラー名にブランド名＋公式/直営/専門店/-JP） | 86.1% | 43.7% |
| S4 manufacturer が中国地名/Technology Co | 100% | 7.0% |
| S5 非日本漢字 | 100% | 2.8% |

重み：S1=2 S2(ピンイン風セラー)=2 S3(略号-JPセラー)=2 S4=3 S5=3 S6(越境OEM文体)=1

## 3. 効かなかったルール（← ここが本当の資産）

- **日本語シグナル単独は適合率26.5%。** 版元も大企業も日本語。他の除外を通した「後」でしか意味を持たない
- **屋号型セラー（株式会社/商店/インボイス登録）をゲートにすると適合率が 48.1%→38.2% に下がる。**
  卸ルートが太いことは**大企業のサイン**でもある。「実在の事業者が仕入れている＝良いメーカー」は誤り
- **名前の見た目での大企業判定は不可能。** ディズニーが「中小候補」に入っていた。外部DB（gBizINFO の従業員数）以外に道はない
- **セラー名から中国系を判定しきれない。** OTTOCAST は日本の転売業者（商人屋）しか並ばない中国系ブランド

## 4. 簡体字判定の正しい実装（他プロジェクトでも使える）

素朴な「簡体字リスト」を当てると **画・残・双・学・携・国** が引っかかり、704件（27%）が誤検出になる。
**日本の新字体と簡体字は大半が同形**だから。正解は逆引き：

```python
try: ch.encode('cp932')      # 日本語レガシー符号化に無い漢字＝異物
except: flag()                # 绞 壳 鑫 亚 营 证 强 细 …
```
誤検出0。再現率は低い（0.5%）が当たれば確実なので、重みを高くして他シグナルと合成する。

## 5. `manufacturer` 列の罠

Keepa の `manufacturer` は**商品説明文が入っていることがある**。
「キヤノン(Canon)対応 CRG-337 互換トナーカートリッジ」は日本語だが日本企業ではない。
→ 日本語シグナルの判定時に `対応|互換|for|カートリッジ|トナー` を含む文字列を弾く（`jp_signal_valid()`）。
MEMORY の `knowledge_verify_field_semantics_not_names`（列名から意味を推測しない）と同根の事故。

## 6. 強い除外ゲートを重ねると、日本の小規模メーカーから先に消える（最重要）

設計中に2回やらかした。**どちらも「もっともらしいルール」で、実測して初めて誤りと分かった。**

| 入れたゲート | 落ちた本命 | なぜ |
|---|---|---|
| CNスコア≧1 を除外 | **BOS（クリロン化成）** | `BOS-SHOP【メーカー公式】` という自社ストアを持つ。**日本のSMEも自社公式ストアを出す** |
| 第三者セラー≧2 を要求 | **uchiko / ROOMMATE / Azb.Studio** | 「メーカー直販＋小売1社」という健全な小規模メーカーの姿がまさにこれ |

実測で決めた正しい閾値：
- **第三者セラー==0 → 除外**（サンプル9社すべて中国系OEM・本命0）
- 第三者セラー==1 と ==2 の本命率は **12.0% vs 10.9% で差が無い**。2社を要求する根拠はデータに無い

**原則：迷ったら除外せず `要注意` 列に理由を書いてレーン末尾へ回す。**
この方針にした結果、除外504社の本命が **0社（再現率100%）** になった。

## 7. 設計上の結論

1. **除外は「捨てる」ではなく「レーンに分ける」。** A メインレーン / B 英字レーン / 除外ログ（理由コード付き）＋ `要注意` 列。
   最終形：A 396社（本命38.8%／要注意なし342社は48.1%）・B 354社（本命11.3%）・除外504社（本命0%）
2. **商品起点だと1社あたりSKU中央値が1になる。** メーカー仕入れの経済（1交渉→複数SKU）が成立しない。
   通過メーカーをブランド名で Keepa 再検索して全SKUを列挙する **Expansion 段**が必須
3. **メディア除外で Keepa トークンが30.3%浮く。** 浮いた分は Expansion と深掘りに再投資する

## 8. 並行実装との突き合わせ（2026-08-31）

同一チケットで別担当が並行実装していた。**消さずに突き合わせたら、両方の弱点が分かった。**

| | 別実装 | タケシ |
|---|---|---|
| 出力 | 163社 | 396社（要注意なし342） |
| 本命率 | **82.6%** | 48.1% |
| 再現率 | **59%（本命13/32を取りこぼし）** | **100%** |
| 大企業の除去 | 手判定187社 | gBizINFO（未実行） |

**学び：**
1. **精度と再現率はトレードオフで、片方だけ見ると相手の成果物を過小評価する。** 163社と396社を「どちらが正しいか」で見ると間違える
2. **他エージェントの成果物を削除しない。突き合わせて差分の理由を説明する方が価値が高い。** 今回は「別実装の手判定＝私の設計の gBizINFO 段の手作業版」という補完関係が判明した
3. **独立実装の数字が一致したら、それが最も強い裏付けになる**（両者とも本命を120〜163社と見積もった）
4. 連番の衝突が起きた。**同一チケットに複数担当が入る場合、連番の帯を分ける**（例：タケシ01-09、他10-19）ようカズヨに提案すること

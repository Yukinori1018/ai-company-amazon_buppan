## 学び
1. **卸の売り方は、まず単品の1点採算で切る。** 上代＝卸×2（参考上代の中央値）で FBA に出すと、卸650円（NETSEA の中央値付近）で利益0。単品で成り立つのは売価2,000円以上。NETSEA が「新規出品は利益が出やすい」と書いていても、固定費の構造は変わらない
2. **まとめ売りは FBA の固定費を1回にする打ち手。** ただし卸値÷Amazon の1個あたりの価格が0.6以下のときだけ（0.7以上は赤字＝11と同根）。既存データ（738件）に当てると8件・4社しか残らない。**レーンの上限を先に数える**（knowledge_filter_order 学び3と同じ手順）
3. **Keepa の無い商品の需要は「別の売り場の販売の実数」で見る。** メルカリの売り切れ件数は推定ではなく実数。月100以上ルールの代わりは「取り分の置き値×件数 ≥ 数量÷1.8」（悲観0.3倍で回転6ヶ月）から逆算して、30日110件（取り分5%・10個ロット）
4. **マルチチャネル（FBA 在庫から他モールへ出荷）は ASIN が要る。** JAN の無い品は、GTIN 免除（L2）が可になるまで FBA に入れられない。代替は月額0円の発送代行
5. **Amazon 以外の売り場は、Amazon の SKU 数（KPI の100）に数えられない。** 推奨にするなら、その点を「判断していただくこと」に必ず出す
6. **固定費のある売り場（楽天 月19,500円・Yahoo 月1万円）は、1周目では外す。** 固定費が12ヶ月の黒字確率を決める（feedback_demand_visible_means_competitor）
7. **規約の判定待ち（L番号）は、案ごとに入口の関門として置く。** 結論は依存させない。NG のときの切り替え先（案3→案2、案2→既存まとめ売り ASIN への相乗り）を先に書く

## 手順（再利用できる形：卸の売り方を考える依頼）
1. Preference 構造の表（売り場ごとに誰が・なぜ・いつ・どれだけ）
2. 単品・まとめ売り・別の売り場の1点採算を、置き値を明記して試算（数字は out/）
3. 既存のデータで、案ごとの母数の上限を数える（新しい観測はしない）
4. 案ごとに：成り立つ理由／母数／需要の確かめ方（Keepa の代わり）／足切り／規約（判定待ち）／作業と社長の関与／最初の検証（金額・期間）／3点の利益／評価の基準／次の一手／撤退条件
5. やらないこと（規約の状態付き）、推奨、KPI 3階層、PDCA の日付表、S 番号、マサル用のパラメータ表と「自信の無い前提トップ5」

## ハルオの規約判定（02・L1〜L7）を受けて変えたこと
- **L1-b が NG**：JAN が無くブランドが印字された品は Amazon に出せない。NETSEA の約3分の2は Amazon の外でしか売れない → 案3（メルカリShops）を推奨する根拠が強まった
- L1-a（JAN のある他社品の新規 ASIN）は「相乗りされる前提」が条件。価格決定権は相乗りが来るまでに限られる → 案1の期待値を下げた。登録ブランドは書面許可が要る（L1-c）→ 1周目は除外
- L6 の独自セットは専用 JAN・表示の書き分けで重い。**同じ品の N 個パック（メーカーの JAN のまま・個装を開けない）が代替** → 案2はパックで組む
- L4：メルカリShops は、オークション可の品に限り、サプライヤーの了承を NETSEA 経由で取るのが条件 → **了承依頼は第三者連絡（§4.1）なので、社長判断と入口の関門（了承率）に入れた**
- L3 の安全策は自社撮影 → 撮影の外注費を S-16 で確かめる
- L7（住所の公開）には依存させない：承認済み221社の中で仕入れ、新しい取引申請はしない
- 前提の訂正（カズヨ 2026-09-15）：日本の Amazon は出品できる（9/12 大口）。停止中は北米。規約判定の本文に誤りがあっても、案は台帳（project_amazon_account_ledger）の事実で組む
- **学び**：規約判定を待たずに案を組むときは、判定ごとの切り替え先を先に書いておくと、判定が出たあとの書き直しが「関門の置き換え」だけで済む。今回は案の順位が変わらなかった

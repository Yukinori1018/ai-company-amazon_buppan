# 「需要が見える＝競合がいる」を見落とした理由 — 成立率は母集団ごとに置く

初出: T-20260914-005（2026-09-14）／親 T-20260912-002。2周目の案B（P62%）が S-1 で 32% に崩れた後の再設計

## 何が起きたか

2周目、打診先を T-1（需要先行スキャン・取り分の大きい順）の上位から作り、成立率に EC STARs の3%を置いた。
S-1 で、すぐ送れる上位25社中19社がブランドストア保有＝自社で Amazon 出品していた。当社は先方から見て競合出品者。成立率は約1.5%に下がり、P は 62%→32%。

## なぜ見落としたか（自分の読み）

1. **「需要が見える」と「先方が卸してくれる」を独立の2軸と思っていた。** 実際は1つの隠れ変数「Amazon で誰がブランドを持っているか」で逆相関する。自分で売って売れているブランドほど、Keepa で需要がよく見え、卸す理由が薄い
2. **並べ方が母集団を選んでいた。** 取り分の大きい順に並べると、上位は「売れている＝自分で棚を握っている」社になる。ソートは中立な操作ではなく、選抜である
3. **二次情報の成立率の出どころの母集団を照合しなかった。** EC STARs の3%は「Amazon で見つけた、本体なし・FBA のライバル2人以上・中小メーカー」への打診の目安。ライバルが2人以上いる＝メーカー本人が棚を握っていない。3%は P2 の数字で、それを P1 中心のリストに当てた
4. **知っていたのに使わなかった。** 9/13 の自分の memory（knowledge_master_strategy_capital_and_walls）に「壁の内側で需要が読める棚＝本丸B（Amazon にいるが困っているメーカー）」と書き、社長 memory にも「既に Amazon で売れているメーカーは独占を渡さない」とある。リストを作る段で、この区別を条件に入れなかった

## 次から（手順）

1. 率を置く前に1行書く：「この率の出典の母集団は◯◯。当社のリストの母集団は△△。一致／不一致」。不一致なら置き値を分ける
2. リストを並べたら「この並べ方は何を選抜するか」を1行書く。需要順は P1（自社出品）を選ぶ
3. メーカーは3つに分ける。P1 自社出品（ブランドストアあり）／P2 持ち主不在（未登録・第三者が販売）／P3 不在。需要が見えて競合にならないのは P2 だけ
4. P2 は「メーカー起点で集め、Keepa は検証だけ」で見つかる（T-20260906-005 の手順）。需要起点のリストからは、ブランドストアなし・販売元が本人でない、で抜く
5. 計算は、マサルのモデルに1通ごとの母集団の差し込み（3行・pops が無ければ乱数列は同一）を入れ、マサルの数字を同じ乱数で再現してから置き値を変える

## もう1つの学び：固定費が確率を決めていた

- 固定費0なら案A は 96%・+13万。レーンの手取り中央+13万に対し固定費18万（月15,253円）。分布が0の近くに狭い（P20 −13万／P80 +11万）ので、月3,000円の固定費削減で P が約9pt動く
- 前回まで固定費は「前提」として触らず、レーンの置き値ばかり動かしていた。**12ヶ月の現金を問われたら、最初に「固定費0の P」と「固定費の内訳」を出す。** 削れる固定費（今回は Keepa API→Pro）が最安の打ち手になりうる
- 期間（12→18ヶ月）は、最初の9ヶ月の動きを変えない。変わるのは発注停止の月だけ。**判定期間の緩和は「今決めなくてよい論点」として出せる**（2027-05 までに決めれば足りる）
- 18ヶ月では、せどりの上乗せが消える（案B 69%＝案C 69%）。緩和を並べるときは、緩和どうしの重なり（片方が他方を無効にする）を必ず計算する

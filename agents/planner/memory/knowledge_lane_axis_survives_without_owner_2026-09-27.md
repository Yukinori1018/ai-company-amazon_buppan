# レーンの評価軸は「社長の時間単価」ではなく「社長が抜けても売上が立つか」（2026-09-27 / T-20260927-002）

## 何を間違えたか

v2（05）で観光ガイドを **「社長が土日にガイドをする」型**として評価し、**時間単価1,200円/h** を根拠に退職まで凍結した。社長が望んでいたのは**ガイドを手配する事業者の側**。サトルの S-A に「月100万級の個人ガイド事例は0件。そこは事業者の数字」と既に書いてあったのに、事業者側を読みに行かなかった。

> 「私がやりたいのは観光ガイドを仕組み化し、人を使ってお金を産むこと。私が実働する（労働集約型）ことを目指していない。」（社長）

**構造的な誤り＝「時間単価」を一次の軸に置いたこと。** 時間単価は結果にすぎない。同じ領域でも、社長が現場に立てば1,200円/h、手配側に回れば中央6,900円/h・上側32,000円/h になる。**レーンの良し悪しは「誰が現場に立つか」で決まり、レーンの名前では決まらない。**

## ルール（次に多レーンを組むとき、必ずこの順でやる）

1. **各レーンに2列を必ず立てる**：①社長が抜けても売上が立つか（◎○△✕）②**天井を決めているもの**（社長の時間か、社数・都市数・在庫か）
2. **✕（社長の稼働に売上が比例）なら、まず同じ領域の「人を使う側」の型を探す。** 無ければ踏み台として用途と**閉じる日**を書く
3. **時間単価は最後に、結果として書く。** 並べ替えの根拠には使わない
4. **「時間単価が安いから捨てる」と書く前に、天井を見る。** 今回⑤スポットコンサルの時間単価は7,700円/hで①より安いだけだった。落とす本当の理由は**天井が社長の喋れる時間で閉じていること**。理由を間違えると社長に「変数を壁にした」と指摘される

## 今回の実務的な発見

- **軸を変えても中央値は動かなかった（57万 → 57万）。動いたのは P90（110→130万）と P(200万)（5→8%）。** 仕組み化されたレーンは「中央の世界では1件も立たない」ので、**上側だけが伸びる**。これがマサルの「中央値が0のレーンを主力に置くな」と社長の「労働集約を目指さない」の両立点。**この構造を先に書くと、期待外れに見えずに済む**
- **レーンを統合すると中央値が上がる。** ③AI受託（社長が実装した分だけ＝✕）を②運用代行に統合＝同じ名簿・同じ商談・違うのは納品物だけ。週2.5h→1.5h。**レーンを足すと中央値が下がるなら、逆に減らせば上がる**
- **「Amazon審査に依存しないレーン」がヘッジとして効く。** 日本ストアは出品前審査で止まっており、①の起点が動かない世界がある。④ガイド手配は Amazon と無関係＝案A の推奨理由の2番目にできた
- **投資ゲートは「登録は成長の結果」で書ける。** MagicalTrip は開始7年後に第2種取得。手配業42,000円を「月粗利10万×3ヶ月＋引き合い1件」の後に置いた（社長の既定＝売上ゼロで体裁に投資しない）

## 「検品できない」を第3の解で埋めた型（再利用可）

先人の解が2つとも写せない（①自分で300回やる ②トレーナー＋月次研修＝資本金3,761万）とき、**代替を4段に分けて、どれが必須かを明言する**。

| 手 | 位置 |
|---|---|
| **他社が既に検品した人だけを母集団にする**（公開レビューURLを応募要件に） | **これが必須。取れなければレーンは主力に置けない** |
| 録画課題をAIで採点 | 下限を切るだけ（実例0件）。上位の識別はできないと書く |
| 初回3催行トライアル＋レビュー基準で切る | 事後。1件目の炎上は防げない |
| ガイド同士の相互チェック | 2人目以降のみ |

**「成立するかしないか」を曖昧にせず、条件1つに絞って0円で判定できる日（W8）に落とす。** 発動率40%・偽陽性25%を付けた。**「成立しないなら主力に置けないと書け」と言われた依頼では、条件付き成立の条件を1つに絞るのが答え方。**

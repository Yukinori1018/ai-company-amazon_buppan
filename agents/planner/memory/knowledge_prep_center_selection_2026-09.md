# FBA納品代行の選定の型 — 費用ではなく「事故率・手離れ・書類回収」で選ぶ（2026-09-30 / T-20260929-001）

成果物：`workspace/output/deliverables/T-20260929-001/03_選定案.md`
入力：サトル 01（14社の公式値）／02（論点1〜5）

## 決めたこと（推奨A）

- 主力はびーぷらすFBA（月額0円・月100点で36円/点）、予備はおりおんFBA（同型なので乗り換え費用がほぼゼロ）
- 2社目以降はトリガー方式（予備・品目・地域・規模の4種類）。使う場面が来るまで登録しない
- メーカーが応じれば FC直送＋Amazonラベル貼付（22円/点）を代行より優先する
- 初回（ゲート解除前）の燕三12点は社長宅受け（1回だけの例外）。届いた納品書の宛名欄を実物で見て、2周目以降の受け場所を決める

## 再利用できる学び

1. **代行の費用差は売上の1〜2%しかない。** 月1,000点で主力候補間の差は月2〜5万円。選定の一次軸は、事故率（ラベルの貼り間違い＝アカウント健全性）と手離れに置く。ただし利幅の薄いSKU（L001 は3%）があるので、費用の重みは25%残した。
2. **「権限を渡す」と「手離れ」は裏表の関係にある。** 同じ重みで並べ、感度（安全40%・手離れ0%）でも首位が変わらないことを示すと、社長が「権限は絶対に渡さない」と必須化した場合の分岐（B案）を1行で書ける。
3. **主力と同じ型の予備を置くと、撤退条件を厳しくできる。** 乗り換えのコストが小さければ「ラベル誤り1回で即停止」を約束できる。予備が別の型だと撤退の判断が鈍る。
4. **「10点買って申請する」を主流の手段にすると、書類の回収は1周目だけの問題ではなく、新ブランドごとに毎回起きる。** 初回の扱いを「1周目の例外」で済ませず、何件目から社長宅受けを外すか（月2件・60分）と、切り替えの判定材料（納品書の宛名欄が注文者かお届け先か）を最初に置いた。
5. **実物で判定できる未確認事項は、調査に出さずに初回ロットで確かめる。** SD の納品書の宛名欄の構成は、サトルに調べてもらうより、10月上旬に届く現物を見る方が早くて確実。1周目を「2周目の設計データを取る回」と位置づける。
6. **期待損失で「楽な案」を落とす。** 代行に直接届けると社長の作業は40分減るが、35%×（買い直し2万円＋1か月遅れ）で期待損失は約7,000円になる。社長の時間と比べて数字で退けた。

## 却下したもの（理由）

- 福富・サポートBB を主力にする案（EC STARs が「利用者が多い」と挙げた2社）：月100点未満では月額と入会金が重く、1点の費用が2〜3倍になる。社長が権限を渡したくない場合の B 案として残した
- 地元の就労支援施設を自前で開拓する案：2026-08-09 に社長がクローズ済み。月1,000点を超えたら再開するか諮る（条件は変数）
- 見積制3社との相見積：月1,000点までは不要

## マサルの差し戻し（R1〜R6）から学んだこと（2026-09-30）

- **「社長宅受け」の作業量は、分解すれば減らせる。** FNSKUはAmazonのラベル貼付（22円/点）に任せ、ケース箱を流用し、PC作業は秘書のブラウザ代行にする（1a'）。40分が15〜25分になり、費用も1,392円から約1,080円に下がった。物理作業を「外注するか否か」の二択にせず、工程ごとに誰がやるかで分ける。
- **「初回の実物で判定する」は、判定したい条件が実物に現れるときしか使えない。** 社長宅に届く納品書からは「配送先が代行のときの宛名」は約80%分からない。判定手段は、問い合わせと1件の実測を別に用意しておく。
- **例外には期限と件数の両方を付ける**（12/31か累計3件の早い方）。月の上限だけでは、例外が恒常運用になる。
- **書類を失う確率は「初回」と「最終」に分ける。** 再発行の手段があれば致命傷ではない。案を落とす主因は、時間的に成立するか（間に合う確率30%）の方だった。
- **確率の置き値には、逆転する閾値を並べて書く**（権限事故 1〜3% に対して逆転は 9〜11%）。置き値が崩れても結論が崩れないことを示せる。

## 追記（2026-09-30）：社長決定で初回の扱いが恒常ルールに

- 社長決定：「その商品（ASIN）の初回は自宅で検品、2回目以降はFBA外注」（CLAUDE.md §3.4）。私が置いた「社長宅受けは 2026-12-31 か累計3件・月2件まで」は上書きされた。
- 学び：**私は社長宅受けを「減らすべきコスト」として期限・件数で縛ったが、社長は「検品という品質ゲート」として常設を選んだ。** 社長の物理作業は「労働集約」ではなく「1件15〜25分の品質確認」なら許容される。社長の時間を削る設計を出すときは、削る対象が「作業」か「確認（ゲート）」かを分けて示す。
- 改訂の手順（再利用可）：①決定を前提節として冒頭に引用 ②対立案は削除せず「却下＋理由」に格下げ ③決定で不要になった確認手（宛名問い合わせ・糸星実測）と問い合わせ文の質問を削る ④上限を撤廃した代わりに、社長の作業時間をシナリオ（悲観2/中央5/楽観10件・期待値5.4件≒110分/月）で見積り、KPIを「上限」から「記録」に変える ⑤論点は運用で吸収する形で1行だけ（決定を覆さない）。

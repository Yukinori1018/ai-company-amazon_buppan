# フィルタの順番を変えても商品は増えない — 「鍵の要らない棚」は取り分が薄い

初出: T-20260909-002（2026-09-12）／1周目の経路の再設計

## 何が起きたか
NETSEA×Keepa 26,942件 → 最後に残ったのは1件。落ちた主因は出品ゲート（13件中12件）。
依頼では「ゲートを最初に当てる経路に組み替えたら？」が論点になった。

## 学び1: 二値フィルタの出力は積集合。順番では変わらない
- ゲートを先に当てても、残るのは同じ1件
- 順番が変えるのは**作業量**だけ（高い人手の工程を後ろに回す意味はある）
- 「順番を変えれば出るかも」という提案が来たら、まず積集合で答える。**商品を増やすのは母数を変えるか、落選理由を「取りに行く対象」に変えることだけ**

## 学び2: ゲートと取り分は逆向きに動く
- ゲートなし＝誰でも入れる＝取り分が薄い。偶然ではなく構造
- ゲートあり＝鍵が要る＝取り分が守られる
- だから「ゲートなしの棚で取り分の厚い商品を探す」は、ほぼ矛盾した探索。**勝ち筋は鍵を取りに行く側（ゲート解除・メーカー直・独占）**

## 学び3: 経路の上限を SKU100 で先に測る
- この母数でゲートの向こうの候補は12件 → 全部解除しても卸レーンの上限は12 SKU
- 月商800万÷100 SKU＝1 SKU 月8万円 → 売価3,000円なら取り分が月27個必要。月数個の商品を積んでも届かない
- **経路を評価するときは、1周目の成否より先に「この経路の上限 SKU 数」と「必要な連絡数（=月SKU目標÷SKU/社÷成立率）」を出す**

## 学び4: 取り分の足切りは悲観側で回転上限を守る線にする
- 需要推定の悲観側は中央値の約0.3倍（knowledge_demand_estimation_limits）
- 10点ロット・回転6ヶ月なら、中央値6個/月で悲観側 1.8個/月 → 5.6ヶ月に収まる
- 閾値は「感覚」でなく「悲観シナリオで固定ルールを破らない値」として出すと、社長に説明が通る

## この依頼の処理手順（再利用できる形）
1. 詰まった漏斗を表にし、どの段が主因かを特定
2. 「順番変更」論点は積集合で即答し、上限（最大何 SKU 取れるか）を出す
3. 案は「鍵の要らない棚で戦う」と「鍵を取りに行く」で分類し、前者は取り分の構造で評価
4. 案ごとに、入口審査（発注前に0円で白黒をつける条件）を置く。ダメ元の発注を構造的に防げる（社長ルール「成功する気でやる」）
5. 確率は3点で、根拠と「何が分かれば確定するか」を並べる。確定させる調査は S 番号で秘書に返す
6. マサル用のパラメータ表を最後に付ける

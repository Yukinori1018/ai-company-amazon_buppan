## 分かったこと（次に聞かれたらまずここ）

- **5,000円以上の母数は薄い。** 残した3,470社→本人カート疑いなし2,452社のうち 5,000円以上605社・1万円以上158社（代表ASINの平時の新品価格。定義は s1_price_bands.py）。いずれかの型番で見ても727社／207社。送れる実数は抜き取り53〜67%を当てて約320〜490社＝**月300通の1.1〜1.6ヶ月分**。売価帯別の打診計画を立てるときは「先頭に置く」と「比率目標」を区別する。
- **売価が高い帯ほど大手・海外が増える**（大手比率 2.2〜3千 4.5% → 1万以上 13.9%、残す比率 55% → 35%）。残した社の本人カート疑い率は帯によらず28〜32%で平ら。

- **売価帯別の成約率は公開データが無い**（検索8回）。測るなら当社の送信記録に売価帯の列を持たせるしかない。

## 罠

- 検索結果の要約に出る数字は原典に無いことがある。今回2件（「6掛け10ケース→100ケースで5掛け」「取引額300万で75%・500万で65%」）。ECのミカタ原文に無いことを WebFetch で確認して不採用にした。**要約の数字は原文で照合するまで使わない。**
- WebFetch の「一覧表を作って」は要約になる。EC STARs の79名ページは curl＋ブラウザUA で取得し、見出し行を grep して原文照合した（WebFetch の表は2人漏らしていた：M・Y 1,200万/150万、A・H 700万/70万）。
- 09 の「5,000円以上102社」と今回の台帳内89社は売価の基準が違う（採算列の平時売価 vs 集計コードの平時の新品価格）。比較するときは基準を書く。
- commit 時に source-terms-guard が memory の「Keepa の平均値の名前」に反応して止めた。集計の定義説明でも止まる。**バイパスせず「平時の新品価格（定義はコード）」と書き換える。**
- ft-maxfullness.com は DNS 不通。hirainet702.com の交渉記事・EC STARs の交渉/限定化記事は方法論のみで数値なし（再訪不要）。

## 手順（「戦略の置き値を事実で確かめて」型の依頼）

1. 置き値の表（09 §10 のような）から、確かめる対象を「幅」と「確率」に分ける。公開情報で支えられるのはたいてい幅だけで、確率は支えられないことを先に想定する。
2. 社内（読解ノート・memory）→公式ブログ→第三者の順で探し、各記述を「実例／目安／構造／定性」に分類した表にする。
3. 利益率の変化は掛けに換算して置き値と並べる（売価＝上代なら1ポイント＝0.01掛け）。
4. 母数は保存済み raw を 0 token で再集計。抜き取り率を当てた数は「推測」の行に分け、層別していないことを書く。
5. 最後に「ここから先はタケシ」の論点表で止める。

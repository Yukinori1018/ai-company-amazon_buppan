- 特商法を全店で先に引くと、98行のうち「販売業者がブランド保有者と別会社」は約50行。ここだけ深掘りすれば足りる（Z6〜Z8 の型が層3でも効いた）
- 接触候補になったのは食品の地方中小（七味・酢・かりんとう・うどん・米菓・精麦・漁協・第三セクター）が中心。カート保持店の多くは「新宿の食品販売店」「いわき・上田の土産物/卸店」などの再販売
- 推定ドメインは7周で公式を当てたのが約20社。**食品の老舗は商品名のローマ字（chidorisu・hanayamaudon・yawataya）で当たりやすい**。社名のローマ字だけだと外れる
- Web検索20回で公式URLを特定できたのは2社（西田精麦 westa・ファーイースト＝楽天店）。小さい社の公式URLは検索要約にほぼ出ない（担当K の実測と同じ）

## 手順（再利用）
1. `25_対象_<記号>.csv` を作り、batchZ8 の道具をコピー（mk_keepa・sp2・guess・pg・auto・xdup・leak）
2. seller ID は `raw/seller_names.json` 逆引き → `sp2.py ids.txt`（間隔5秒・約92店で約25分）
3. 別会社の行だけ guess.py → auto.py/pg.py。リンク探しは新設の `lnk.py 'regex' URL...`（リンク文言とURLを正規表現で拾う）が速い
4. 検索は「接触候補になりそうな食品・中小」から先に使い、持ち分を使い切ったら残りは「検索待ち」で分ける
5. recs.py → build.py --public → **xdup.py** → leak.py＋特商法の全販売業者名を公開版と照合 → commit

## 失敗とリカバリ
- recs.py の `exG(k,name,why)` を `exG(k,why)` で呼んで落ちた。コピーした道具の関数シグネチャは先に見る
- xdup を組み上げ後に回して3件を重複に寄せ直した（G658 グレープストーン・M1259 南富良野町振興公社・Q1685 ジーテック）。**組み上げ前に既存台帳の正式社名で照合する手順を入れると手戻りが減る**
- 🔴既存台帳の「要確認（公式未特定）」の社を後の担当が特定することがある（M1259）。若い順位が正なので本行は重複になるが、**特定した値を捨てず、完了報告の引き継ぎ①に「M を本行の値で更新すれば +1」と書く**。sync は重複行を飛ばすので、書かないと成果が消える

## 判断の型（今回足したもの）
- 公式に「ネット販売はしておりません」（村山造酢）＝本丸の型の事実。判定は接触候補のまま、事実を備考に書いてタケシに渡す
- 公式に「不正転売にご注意ください」（煎餅屋仙七）＝除外しない。打診文の論点として引き継ぐ
- 漁協の出資金40億円は「資本金3億円超」に機械的に当てず、事実として書いて判断を渡す
- 社の公式が独自ドメインでなく楽天店だけ（ファーイースト）の場合、楽天店の会社概要を公式扱いにし、紐付けは「一致（ブランド単位）」

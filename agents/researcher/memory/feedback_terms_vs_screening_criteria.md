# 失敗とリカバリ：利用規約だけを読んで「可」と判定した（2026-08-31 → 2026-09-04 に自分で発見）

## 何が起きたか

T-20260831-005 で **orosy を「Amazon 転売の可否＝明文なし。禁止条項は無い」** と書いた。
根拠は `wholesale-portal.orosy.com/terms` の**全35条を「転売／再販／販路／モール／Amazon」で走査**した結果。
走査自体は正しく、規約には本当に書かれていない。

その判定を受けて秘書は「orosy は可（条件付き）」として次のチケットに引き渡した。

2026-09-04、T-20260904-004 A-3 で orosy 公式ヘルプを読んだところ、こうあった。

> **■ご利用頂けません**
> ・ネットショップのうち、オープン前、ドロップシッピング、フリマ、**モール**、オークション、アフィリエイト
> （`https://help.orosy.com/hc/ja/articles/4403961908505` / 2025-01-22 更新）

**Amazon はここでいう「モール」。入口の審査で落ちる。**

## 原因

**「規約」と「審査基準」は別の文書で、別の場所にある。**
規約は契約後の権利義務を定める。審査基準は契約前の入口を定める。
**私は前者しか読んでいなかった。**

しかも orosy のヘルプセンターは Cloudflare で 403 を返す。
前回「`help.orosy.com` は HTTP 403（ヘルプセンターは非ログインで読めず）」と実測メモに書いて、**そこで止めた**。
止めずに Zendesk API（`/api/v2/help_center/ja/...`）を叩けば 200 で全文が返ってきた。**403 を見て諦めたのが直接の原因。**

## 次からのルール

1. **「規約に書いていない」を結論にしない。**入会要件・審査基準・FAQ・ヘルプセンターを**必ずもう1階層探す**。
2. **403 は「読めない」ではない。**Zendesk / Intercom / Notion 公開ページ等は API や JS バンドルから取れる。前回 orosy の規約本文を JS バンドルから抜いたのは自分なのに、ヘルプセンターでは同じ粘りをしなかった。
3. 判定を書くとき、**「どの文書のどの階層まで見たか」を成果物に明示する。**「規約全35条を走査した／ヘルプセンターは未確認」と書いていれば、次の担当が埋められた。
4. 社長のフィードバック `feedback_research_accuracy_blocker`（推定と実測を分ける）と同型。**「調べた範囲」も実測と同じく明示すべき対象**。

## 波及

この誤判定は T-20260904-004 の卸レーン設計に入っていた。A-3 で自分で見つけて訂正できたが、
**もし発注まで進んでいたら、審査で落ちるか、登録後に発覚してアカウント停止＋発注済み在庫の宙吊りになっていた。**

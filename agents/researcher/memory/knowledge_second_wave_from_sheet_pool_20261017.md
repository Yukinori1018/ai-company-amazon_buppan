## 最初に気づくべきこと（イシュー設定の勘どころ）
- メーカー連絡先台帳の 53列目「打診順」の **第2弾 = 第1弾と同じ検算（dashin_order.verify：月販≥50・本体365日在庫切れ率≥90%・FBA数・ランク≤5万・必要掛け≥40%・カート保持者が本体/本人でない＋実画面確認済み・公式で紐付け済み）を全部通過し、差は「出品許可が必要（申請経路あり）」だけ** の社。636社あった。
- 秘書の条件（月販表示・カート非本体非本人・公式で社名確認・文章窓口・除外カテゴリ）には「出品できる」が入っていない＝**新しく Keepa を引かなくても、母集団はすでにある**。Keepa 0トークンで済んだ。
- 秘書が「第2弾」と言う語とシートの「第2弾」が同じものか、最初に確かめる（今回は別の意味で使っていた可能性があるので、報告で明示した）

## 手順（作業場 agent_output/T-20260930-001/83b_work/）
1. sync_ledger.collect＋dashin_order.assign をオフラインで回し、`dashin_order.export(..., prefix='第2弾-')` で検算値つきの一覧（63b_第2弾_offline.csv）を出す。社長入力列はシートのスナップショット JSON から補う
2. base.py：電話のみ・除外カテゴリ（医薬品/医薬部外品/医療機器・冷蔵冷凍・サロン/医療専売/会員制・酒類）・後回し（流通形態）を機械で落とす。第1弾の打診済み名簿（75/76/79/82/66/63）と社名正規化で突合
3. 優先順：秘書の推測カテゴリ（ホーム&キッチン・ペット・DIY工具・文具・食品）→ その他 → ビューティー/ドラッグ。各群の中はシートの送信順
4. dig.py：フォームURL・公式トップ・出典URLを取得（batch*/html のキャッシュを md5 で共有）、選択肢（option/radio）・取引系キーワード・事業内容・会社概要のメール前後を要約。**B2B 系リンク（取引/卸/法人/販売店様/業務用）を1本だけ自動でたどる**のが効いた
5. show2.py で10社ずつ読み、1社1行の判定（OK/NG・窓口種別・窓口・用途の文言・根拠1文・根拠URL・注記）を j0N.tsv に書く
6. scan.py：OK 社の全取得ページから「(Amazon|ネット販売|EC|転売|営業)…(お断り|ご遠慮|受け付けておりません…)」を機械で拾う。mailchk.py：メール窓口がその社の公式ページ本文に実在するか検査
7. build83.py：A（取引・法人向けと明記）→B（代表・一般窓口）の順に並べ、根拠2文の2文目（Amazon の現状）は月販から機械で作る。公開版は販売店名を伏せて deliverables へ

## 新しく分かった型
- **Amazon 出品者・ネット販売業者を名指しで断る文言は、問い合わせフォームのページ本文にしか書いていないことが多い**（160社中7社＝4.4%）。例：「Amazon等の出品に関するメール・営業メールは一切お受付しておりません」（北前船のカワモト）／「Amazonでの弊社商品の販売に関するお問い合わせはお断り」（松合食品の「ご商談について」）／「ネット販売業者様からの営業を目的としたお問い合わせはお断り」（やまと蜂蜜）／「販売経路が通販サイトのみの新規取引は停止中」（ココウェルの卸フォーム）／「直接のお取引は代理店様との契約上できません」（ジャンプ）。会社概要だけ見て窓口を決めると踏む
- 「営業メールはご遠慮」は5社。当社の打診（仕入れの相談）が営業と読まれるかは事実として注記に残し、文面の判断は秘書・ヒデアキへ
- **シートの「問い合わせフォームURL」列に注記が括弧で連結されている行がある**（例 `https://…/contact.php（法人専用）`）。そのまま取得すると404。`re.split(r'[（(\s]', url)[0]` で切る。404 を見て「フォームが消えた」と結論しない
- 「販売店登録」フォームは既存取扱店の登録用のことがある（ママクック）＝新規取引の窓口と読まない
- 商品名が台帳に無い行（ASIN だけ）は、備考の「Amazon の「…」」から拾い、残りは Amazon 商品ページの productTitle を間隔4秒で取得（12件・全件取得できた）

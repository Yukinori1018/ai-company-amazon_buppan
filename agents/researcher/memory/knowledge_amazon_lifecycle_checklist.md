# 業務ライフサイクル チェックリストの作り方（T-20260826-002 / 2026-08-26）

依頼＝「Amazon物販の"やるべきことの全量"を8大項目×3階層で網羅せよ」。当社の進捗マッピングはマリエが別担当。

## この依頼の処理手順（次回はこれをなぞる）

1. **既存メモリを先に全部読む。Webから始めない。** 今回は `knowledge_seller_operations_basics` / `_account_health_suspension` / `_seller_research_profit` / `_listing_ads_reviews` / `_listing_restrictions_ungating` / `_fba_shipment_playbook` / `_fba_features_fees_overview` / `_fba_label_service` / `_seller_official_operations` / `_kobutsusho_license` / `_kaigyo_todoke_2026` / `_maker_shiire_ecstars` / `_kokunai_niche_oem` の13本で**8割が埋まった**。Web調査は穴埋めに使う。
2. **裏取りの対象を4領域に限定する**（手数料 / 返品・返金 / パフォーマンス指標しきい値 / 税務・古物の法定要件）。これを宣言しないと底なしになる。
3. **階層の件数制約は機械で検算する。** 目視だと必ず外す。今回は初稿で8つの中項目が「小項目2〜6」の範囲を超えていた。Pythonで `### x-y` と `- [ ]` を数える20行のスクリプトで検出→分割/統合。**書き終わったら必ず数える。**
4. 数値の出典は**本文に埋めず、末尾の照合表に集約**する。本文が読める長さに収まり、かつ一次/二次/未確認の区別が1画面で付く。

## 一次情報の取得可否（重要・時間の節約になる）

| 対象 | 機械取得 | 備考 |
|---|---|---|
| `sell.amazon.co.jp/pricing` | **可** | 手数料の公式値はここで取れる。WebFetchで十分 |
| `sellercentral.amazon.co.jp/help/hub/reference/G2xxxxx` | **不可** | 302で `apac.account.amazon.com` のログインへ飛ぶ。**サブエージェントからは絶対に取れない**。社長のブラウザ確認かカズヨのブラウザ操作が要る |
| 国税庁 `nta.go.jp` | 可（ただしURLが死にやすい） | `keigenzeiritsu/2wari-tokurei.htm` は404。`publication/pamph/shohi/kaisei/202304/01.htm` と `pdf/qa/115.pdf` は生きている |

## 未確認のまま残した（推測で埋めなかった）

A-to-z保証への出品者回答期限（3暦日／5営業日で二次情報が食い違う）／低在庫レベル手数料の適用条件（公式「過去在庫日数」vs 二次「過去7日20点未満」で粒度が違う）／最低販売手数料30円・メディア成約料140円（公式pricing画面に掲載なし）／IPI基準値の2026年時点の有無。

**社長フィードバック「推定が不正確＝最大のボトルネック」に照らすと、埋めない判断が正解。** 「たぶんこう」で書いた1行が、後で仕入れ判断の前提として使われる。

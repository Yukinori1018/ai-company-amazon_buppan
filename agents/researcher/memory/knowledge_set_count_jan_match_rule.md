## 学び（事実）
- **台帳のセット数は116行中103行が誤り**だった。商品名の「16個入」「35枚組」「34X66cm」「6本入る」を卸の点数として拾っていた。
  卸の1点が同じ JAN の同じ箱なら、商品の中の入数は相殺されて**倍率は1**。
- **「卸の点数」は、Amazon と卸の両方の数量表記を並べて割った値**。片側の数字だけ見ない。
- Keepa の packageQuantity は「商品の中の入数」（マスク30枚×50箱で1500）で、卸の点数ではない。pq が倍率と一致したのは128行中106行。参考にはなるが決め手にはならない。
- 卸の単価がケース入数の表記を含むことがある（オリヒロ「130gx8」＝単価は1袋分・最小ロット8）。**卸タイトルの「×N」は入数で、1点の中身ではない**ことがある。
- 不二貿易の「[セット数:4pcs]」は Amazon 仕様の「個数4」と「ユニット数1・本体重量1kg」が食い違っていた。見えている数字が矛盾していたら未確定にする。

## 判定に効いた検算（推測を減らす道具）
- **価格比 ＝ Amazon価格 ÷（卸単価税込 × N）**。候補の N のうち比が1.1を下回る N は原価割れなので外す。両方とも成り立つ（例 3.1 と 1.6）なら**未確定**。決め打ちしない。
- 価格がないときは Keepa stats.avg90（index 18→1→10 の順）で代用した。
- 比が1を下回っても、両方のタイトルが同じセット名なら、それは採算の問題であってセット数の問題ではない（確度は「中」に下げる）。

## 第2弾（2026-10-11 夜・setcheck_queue 78行）で足した学び
- **同じ JAN の兄弟 ASIN に単品（pq=1・商品名に数量なし）があれば、その JAN の単位は単品**。Keepa キャッシュ（refetch20261004/raw.jsonl・buylist20261009/resolve_raw.jsonl・buybox_raw.jsonl）の eanList で逆引きする。せどりのセット出品は単品 JAN を流用するので、「卸の同JAN＝単品」と言える。価格比で N=1 と N=k の両方が成り立つ行の決め手になった（ディアナチュラ・オリヒロ・リケン・フエキ・アルボナース・サーモス）
- 兄弟が見つからず、Amazon 仕様も「ユニット数3本」だけ（メーカーの3本組か単品×3か区別できない）なら**未確定のまま**。前回の「両方成り立てば未確定」を崩さない（歯ブラシ・ハトムロン）
- **卸側が束ね品のことがある**（彩虹貿易「60粒 x 3袋セット」、ITO「6セット」、カゴメ「200ml x 24本」）。このとき Amazon1個＝卸の**分数**（2/3・5/6・5/3 等）になる。採点コード `score_20261004._num` は分数を読めず UNKNOWN 扱い → IT 引き継ぎ要
- **同じ JAN で引いた卸の商品名が別品**のことがある（ZOO 鉄+葉酸の JAN → 卸は「乳酸菌+カルシウム」）。JAN 一致だけで中身を信じない
- 卸タイトルの「NgxM」「2袋x8」は前回同様**入数（単価は1袋・最小ロット M）**。ゆず飴 80gx10・ぶどう糖 18粒x10・たこ焼粉 400gx6 も同型。逆にすると1袋十数円になり不自然、で検算できる

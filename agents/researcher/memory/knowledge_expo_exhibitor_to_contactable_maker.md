# 展示会出展社リスト → 「連絡できるメーカー」への落とし方（実測手順）

初出：T-20260906-005（2026-09-06）。ギフトショー第102回 出展社2,353社 → 第一陣20社。
**この依頼は再来する（第2陣＝伝統的工芸品産地組合275ページ、第3陣＝スーパーデリバリー）。手順ごと再利用すること。**

## 0. 入力の実像を先に見る

ギフトショーCSVは **`booth` と `exhibitor` の2列しかない**。住所も電話もカテゴリもない。
つまりこの仕事の本体は「名前だけの2,353行に、連絡可能性を後から貼る」作業。
**gBizINFO と 公式サイト実測の2本立てが必須**で、Keepa は最後の検証にしか使えない。

## 1. パイプライン（この順で固定）

| 段 | やること | ツール | 実測歩留まり |
|---|---|---|---|
| ① 機械分類 | 海外表記・団体・商社を落とす | 自作正規表現 | 2,353 → **976（41.5%）** |
| ② 法人特定 | 商号 → 法人番号・所在地・従業員数 | gBizINFO API 2段 | 完全一致1社に決まる **41.3%** |

### ①で落ちる内訳（2,353件・実測）
海外表記 1,224（52.0%）／団体・商工会・自治体・教育機関 117／商社・代理店・デザイン 35／除外カテゴリ 1。
**商工会・商工会議所が117件も混ざる**のがギフトショー特有。地域ブースの取りまとめ団体で、メーカーではない。
最初に落とさないと母数が水増しになる（社長が最も嫌う `feedback_maximize_pool_not_ranking`）。

## 2. 展示会リストは Amazon 由来データより名寄せに強い（新しい実測）

| 入力 | 法人特定率 |
|---|---|
| Amazon `manufacturer` 名（T-20260831-004・N=262） | **28.6%** |
| 展示会 出展社名（本件・N=150 時点） | **41.3%** |

理由は単純で、**展示会リストは商号そのものが入っている**（Amazon はブランド表記）。
「本丸は展示会」という結論は、母集団の定義だけでなく**データの扱いやすさでも裏付けが取れた**。

## 3. 落とし穴（今回踏んだ／踏みかけた）

- **同名企業の取り違え。**「木村硝子店」を検索すると **一宮市の建設ガラス工事業（g-kimura.jp・従業員31名）** が上位に来る。
  出展社は **文京区湯島のグラスメーカー（kimuraglass.co.jp・20名）** で完全な別会社。
  → **社名だけで会社概要ページを採用しない。所在地キーワードで必ず切り分ける。**
  `30_gbiz_targeted.py` では `(表示名, 検索語, 期待所在地)` の3つ組を持たせて機械的に切った。これが正解。
- **法人格まで含めて照合しないと exact_multi が爆発する。**「川辺（株）」で `有限会社川辺`『川辺合同会社` が全部一致する。
  出展社名に `(株)` が書いてあれば `株式会社` を含む候補を優先する、で大半が解ける。
- **Cloudflare / Shopify サイトは curl が通らない**（楠橋紋織・木村硝子店）。`Verifying your connection` が返る。
  → **WebFetch に切り替えると通る。** curl で全部やろうとしない。
- **Keepa の generic ヒット。**「清水硝子 江戸切子」で `brand:江戸切子` に一致してしまう。
  社名と無関係な一般名詞ブランドに当たったら **一致とみなさず「要目視」**にする。
- **公式サイトと検索結果で電話番号が違う。** 守田漆器は検索結果 0761-87-0106 / 公式実測 0761-78-0106。**公式実測が正。**

## 4. 「根拠1行」に使える事実の型（これが書けない社は入れない）

強い順：
1. **公式に OEM／卸／法人取引の専用ページがある**（楠橋紋織 `/pages/oem`、七福タオル `oem.` サブドメイン、金野タオル `oem.html`、北陸製菓 `oem.hokka.jp`）
2. **法人専用の問い合わせフォームが個人用と別にある**（清水硝子 `contact_corp/`）
3. **卸が事業内容に明記**（廣田硝子＝陶磁器・ガラス器卸売業、北尾化粧品部＝化粧品製造・卸、木内籐材工業＝製造および卸）
4. **会員登録制の卸制度がある**（木村硝子店の飲食店卸）
5. 展示会出展そのもの ← **全社に当てはまるので単独では根拠にならない**

→ **`卸|お取引|代理店|OEM|別注|業務用|法人|小ロット` を公式サイト本文から grep するだけで、根拠の有無が機械的に分かる。** `40_contact_scrape.py` に実装済み。

## 5. 従業員数は gBizINFO では半分しか埋まらない

20社中 **一次情報で確認できたのは12社**（gBizINFO 8社＋公式会社概要4社）。残り8社は `employee_number` が欠測。
**欠測＝小さい ではなく 欠測＝分からない**（`agents/it_engineer/memory/knowledge_gbizinfo_api.md` と同じ結論を再確認）。
確認できた12社はすべて **125人以下**で、社長の目安300人を超える社は1社も出なかった。
→ **展示会出展社という母集団は、そもそも300人以下が支配的**。300人条件はこの経路ではほぼ効かない（＝足切りに使う価値が低い）。

## 6. トークン経済

Keepa は **1社1クエリ（10トークン）で十分**。20社で約220トークン。
`offers` を付けると「メーカー本人が売っているか転売か」まで分かるが跳ね上がるので、**第一陣では取らない**と決めた。
他ジョブ（T-20260906-003）と並走する夜は、`tokensLeft` を都度ログに残しておくと後から説明できる。

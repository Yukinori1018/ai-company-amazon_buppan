# 法務NO経路の「射程」と適法な代替手段の地図（2026-09-13 / T-20260912-003 サトル③）

## 依頼パターン

「法務が NO にした経路も検討対象に入れろ」「あらゆる方法を検討」系の社長指示。判定を覆すのではなく、**NO の中身を分解して、同じ目的を達成する適法な手段と、NO のまま使った場合の実害を事実として並べる**依頼。

## 処理手順（再利用できる形）

1. 社内の法務判定書を全部読み、NO を **1 行 1 経路**で棚卸しする。列は「判定（判定者・日付）／根拠条文の引用／禁止されること／禁止されないこと」。**NO の名宛人（自動化手段か・API 契約者か・人か）を条文ごとに確認**する。今回 21 本すべてで名宛人は「自動化された手段」か「API 契約者」だった。人が見る行為を禁じた条文はゼロ。
2. 「NO」「未確認（規約が読めない＝着手不可）」「条件付き可」を混ぜない。未確認は秘書ブラウザで埋まる穴として別表に出す。
3. 代替手段は**目的別**（需要の兆し／出品者数・価格の実測／メーカー発見／SNS 話題商品／他モールの売れ筋）に並べる。各手段に「適法性の状態（可／条件付き／要ハルオ）・費用（§4.1 か）・取れる／取れない・社長制約との適合」。
4. 実害は「型」で示す：実害の内容／制裁の単位（どのアカウントか）／不可逆性／NO を守った場合に失うもの。**制裁の単位が事業インフラ（Amazon 出品アカウント・Google アカウント）に紐づく経路だけが不可逆**。
5. 判定はしない。「要ハルオ」と書いて論点に回す。推奨も禁止もしない（社長の判断材料）。

## 分かったこと（次回はここから始める）

- **SP-API は Amazon 機械取得 NO の正面代替。** 大口が要件（`registering-as-a-developer`「professional selling account」）。`getItemOffers`（0.5 rps/burst 1）で NumberOfOffers・BuyBoxPrices・SalesRankings、`getListingsRestrictions`（5 rps/10）でゲートの reasonCode（APPROVAL_REQUIRED 等）と承認 URL、`getMyFeesEstimateForASIN`（1 rps/2）で手数料。**第三者開発者向けの年 1,400 ドル課金（2025-11-03 告知）は 2026-05-12 頃に撤回**（二次 2 本。日付が 5/12 と 5/14 で不一致。一次告知ページは未特定）。自社利用は当初から対象外。AUP に「外部データサービスの提供禁止」「Information を外部に開示しない」→ PUBLIC リポには置けない。
- developer-docs.amazon.com は **`developer-docs.amazon`（.amazon TLD）に 301** する。個別オペレーションは `/sp-api/reference/<operation名小文字>` が本文を返す。`/docs/...-reference.md` や `/docs/sp-api-pricing` は 404。
- **PA-API 5.0 は deprecated**（呼ぶと 403）。後継 Creators API は「アソシエイト登録＋直近 30 日 10 件の適格販売」が要件（公式）。実績ゼロの当社は入口で落ちる。
- **X API は定額プランが消え従量課金**（docs.x.com pricing・2026-09-13）。投稿読取 0.005 ドル/件、月 300 万件上限、無料枠なし。ハルオ 8/31 の NO は「従量課金＝§4.1」が理由で規約上の禁止ではない。
- **Instagram Graph API の仕様は公開されている**（ハッシュタグ検索 7 日 30 個・ビジネス/クリエイターアカウント・App Review）。ハルオ 8/31 の「仕様非公開」は現時点では事実と異なる → 再判定の材料。
- **Google トレンドの公式ヘルプ（answer/4365538）に「再利用時は『データソース: Google トレンド』と出典表記」の文言がある。** ハルオ 9/6 が「再公開の許諾文書を確認できず」とした穴を埋める一次情報。Trends API は alpha・応募制（5 年・日/週/月/年・一貫スケール）。

## 失敗と注意

- WebFetch は SPA・302・404 を「情報なし」と要約して返すことがある。**URL の HTTP ステータスと本文サイズを curl で別途確認**してから「取れなかった」と書く（YDN ガイドラインは 200 だが中身が無い、の判別に必要だった）。
- 二次情報の日付が食い違うとき（SP-API 撤回 5/12 vs 5/14）は**両方書いて「不一致」と明記**する。片方に寄せない。
- 「人が見る」運用の時間は社内に実測が無い。試算は必ず（推測・確度低）を付ける。数字を Keepa に落とす前提なので、目視の役目を「候補発見」に限定して書く。
- 社長は「NO 経路も検討対象に入れろ」と言っているが、**推奨はしない**。§3 を「事実のみ・勧めない・禁じない」で通し、論点 #31 に「サトルは推奨も禁止もしない」と明記した。ここで推奨を書くとハルオの領分を侵す。

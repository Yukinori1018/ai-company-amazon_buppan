# ブランド1社の「使える棚」を実数で出す手順（Keepa Product Finder のクロス集計）

初出: 2026-10-07 / T-20260920-003 / サトル
対象の問い: 「このメーカーのゲートが開いたら、当社が使える棚は何件あるのか」

## 手順（トークン556で7,039 ASIN を判定できた）

1. **ブランド表記を総当たりで確定させる。**Keepa の `brand` は**完全一致・部分一致なし**。
   和平フレイズは `和平フレイズ(wahei freiz)`=7,016件 / `wahei freiz`=23件 / **`和平フレイズ`=0件**。
   当社の台帳（all.csv）にあった「和平フレイズ」は手入力で、Keepa では1件も引けない。
   → **台帳のブランド欄で Keepa を引くと0件になる。**候補表記を5〜7本投げて totalResults を見る（各10トークン）。
2. **件数だけを `totalResults` で取る。**`perPage:50` にすれば1クエリ≒11トークン。
   ASIN リストは最後に1回だけ引く（10 + 1/100件）。**先に件数、後からリスト**が鉄則。
3. **クロス集計に使える Finder フィルタ**（2026-10-07 時点で実在を確認）
   - `buyBoxIsAmazon` (Boolean) … 現在カートが本体か。**true + false = 全件に一致する**（null は無い）
   - `buyBoxStatsAmazon365_lte/_gte` … **過去365日の本体カート獲得率(%)**。履歴条件をこれで当てられる
   - `monthlySold_gte` … **`>=1` と `>=50` の結果が完全に同じ**＝50未満は値が存在しない（表示閾値の裏取り）
   - `hasParentASIN` `packageQuantity_gte` `numberOfItems_gte` `current_NEW_gte`
   - ⚠️ **`productType: 0` は効かない**（0 が falsy 扱いで無視される疑い）。全件と同じ数が返った
4. **リスト取得後は Product Request で当て直す**（`&buybox=1` ＝ 2トークン/ASIN追加、`stats` は無料）。
   `stats.buyBoxSellerId` / `stats.buyBoxIsAmazon` / `stats.outOfStockPercentage365[0]` が揃う。

## 🔴 最大の発見：Finder の `buyBoxIsAmazon` は古い

Finder が `buyBoxIsAmazon=false` として返した77件を Product Request で当て直したら、
**1件（B0FVL8QST6）が本体に反転し、22件はカート保持者が空（null）だった。**
- **Finder の索引は実取得より古い。**発注判定に Finder のカート条件を使ってはいけない
- **`buyBoxIsAmazon=false` は「第三者が持っている」ではない。**「本体ではない」であり、
  **カートが誰にも無い状態を含む**。77件中22件（29%）がそれだった
- 検算の型：**Finder で粗く取り → Product Request で当て直し → 実画面**の3段。
  §3.3-22 の「いまカートを誰が持っているか」は3段目まで行かないと確定しない

## 歩留まりの実測（和平フレイズ・N=7,039・2026-10-07）

| 段 | 件数 | 残存率 |
|---|---:|---:|
| 全ASIN | 7,039 | 100% |
| 現在新品価格あり（生きている棚） | 2,756 | 39% |
| `monthlySold` が付く（月50個以上） | 455 | 6.5% |
| └ うち本体がカート保持 | 378 | **83%** |
| 本体以外 × 実売あり（Finder 判定） | 77 | 1.09% |
| └ 第三者が実際にカート保持（実取得） | **54** | 0.77% |
| └ 本体の365日在庫率20%以下 | **3** | 0.04% |

**覚えておくこと：売れている棚の83%は Amazon 本体が持っている（大手家庭用品ブランド1社の実測）。**
「ゲートが開けばこのメーカーが使える」は正しいが、**使える幅はカタログの1%以下**。
「棚が何千件ある」はゲート申請の価値の根拠にならない。**根拠になる数字は「第三者カート × 実売あり」の実数**。

## バリエーションの罠

77件のうち **72件（94%）がバリエーション子**で、ユニーク親は53。第三者カートの54件は**36グループ**。
「54件」を「54棚」と報告してはいけない。**キーゾンの実数確認も兄弟ごとに別（§3.3-29）**。
`packageQuantity` は全77件が 1 ＝カタログ上のセット品はゼロ（セット数の単位ずれ §3.3-17 は今回は起きない）。

## 併せて踏んだこと

- **ブランド欄が実メーカーと違う行が混ざる。**B01MT6DU8R は brand=和平フレイズ(Wahei freiz) だが
  タイトルは「グリーンスマイル 電動大根おろし器」。打診先・卸検索を間違えるので**タイトルと突き合わせる**
- `offerCountFBA/FBM` は **`offers` を付けないと `-2`**（＝未取得）。
  §3.5 #7 の内訳は Keepa だけでは埋まらない → 実画面 or `offers=20`（6トークン/ASIN）
- 価格履歴（`csv`）は `history=1` で**追加トークン0**で付いてくる。90日中央値・傾きは後からローカルで算出できる

## 手順（再利用できる形）
1. `NetseaClient().list_suppliers()` → `random.sample` → `list_supplier_items_raw(id, max_items=100)`。40社で約2分。
2. フラグの意味は **`https://api.netsea.jp/docs/buyer/schemas/items.json`** の description で確かめる（paths/index.json → ./items.json → ../schemas/items.json と辿る）。`direct_send_flag` は「商品配送可」で、ヘルプの「販売後注文可」と同じとは限らない。
3. カテゴリ名は `GET /categories`（**応答は dict でなく list**。`{"id","name":"大 > 小"}`）。
4. Keepa の照会は `product?code=<JAN,...>&domain=5&stats=1&history=0`。50件ずつ、213件で約255トークン。

## 罠
- 承認済みサプライヤーは過去に Amazon 照合で選んでいる。**Amazon にある比率は NETSEA 全体より高く出る**。必ず注記する。
- オファーを付けない照会の COUNT_NEW は古い可能性がある。「セラー数」と書かない。
- Seller Central のヘルプ（GTIN 免除・ドロップシッピング）は **日米ともログインが要る**。Amazon の公式アカウント（News_Amazon）のフォーラム投稿は公開で読める。ここを一次情報として使う。
- NETSEA の越境サイト（Cross-border wholesale）は海外バイヤー専用。国内バイヤーの輸出の手段にはならない。
- 卸値の中央値などの集計値も `out/` だけに書く（口数で割れば復元できる）。

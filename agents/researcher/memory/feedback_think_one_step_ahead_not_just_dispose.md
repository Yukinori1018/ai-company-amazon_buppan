> 「海外に売りたい。ベースとかショッピーを考慮して。**あなたはセンスが悪いね。どうせやるなら先を考えろ。**」（社長・2026-10-09）

## 何が起きたか

Amazon で出品不可と確定した鍋12点（原価19,756円）について、国内フリマでの現金化案を3つ出した（損失▲1,168〜7,146円・作業59〜166分）。
数字は正しく、出典も揃っていた。**それでも差し戻された。**理由は、**それが「1回で終わる処分」の案だったから**。

## 学んだこと

- 🔴 **在庫が売れなくなったという依頼は、「どう捌くか」ではなく「どの販路を持つか」の依頼として読む。** 12点を2千円の損で捌いても、次に同じことが起きる。社長が買いたいのは**構造**であって、今回の処理ではない
- **「処分」という語を自分の思考の枠にしない。** 国内フリマ3案は、どれも「この12点が終わったら終わり」の案だった。社長は毎回、**残るもの**を見ている（memory `owner_not_labor_intensive_build_systems`／`project_goal_2m_operating_profit_2028-09`）
- **成果物を捨てない。** 国内フリマの調査（39_）は比較対象として残す指示が出た。先を考える案を作るときも、**足元の案は「捌けなかったときの受け皿」として生きる**
- **社長が販路名を2つ名指ししたら（BASE・Shopee）、名指しされていない3本目を自分で足す。** 今回は当社 memory に eBay のナレッジがあり、秘書が「必ず比較に入れろ」と指示を補った。**自分の memory を検索してから着手すれば、指示を待たずに足せた**

## 次回同じ依頼が来たときの型

1. **判定軸を2つにする**：「この在庫が捌けるか」×「その後に何を流せるか」。片方だけの表を出さない
2. **自社の資産から「次に流せる帯」を件数で出す。** 今回は NETSEA 索引 67,667 JAN をキーワードで切って、美容4,307件／衛生1,582件／キッチン小物1,326件／サプリ1,195件／文具936件／キャラ520件 を示した。**「可能性があります」ではなく件数で書く**
3. **販路のトレンドデータと自社の在庫構成を突き合わせる。** Shopee の月次実売TOPがサプリ・コスメで、当社索引の最厚帯も美容。**一致を指摘できると「先を考えた」ことになる**
4. **その販路が、今回の失敗の原因（Amazon のゲート）に対して構造的に強いかを書く。** 「同じ事故が原理的に起きない」まで言えると論点になる

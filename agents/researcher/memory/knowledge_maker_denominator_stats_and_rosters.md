## 1. 統計の取り方（0円・登録不要・curl で取れた）

| 欲しいもの | ファイル | e-Stat statInfId |
|---|---|---|
| 製造業 産業細分類別の事業所数（全事業所・4人以上の規模別） | r3seizo_sangyo.xlsx 第1表・第7表 | 000032268570 |
| 企業等数 企業産業小分類×常用雇用者規模（300人の線が引ける） | h1_003_1.xlsx 第3-1表（171MB） | 000040067956 |
| 卸売業 細分類×従業者規模 | f1_004.xlsx 第4表 | 000040032843 |

- URL は `https://www.e-stat.go.jp/stat-search/file-download?statInfId=<ID>&fileKind=0`。API（appId＝登録）は不要。
- 保存名に拡張子が無いと openpyxl が拒否する。`.xlsx` を付けてから開く。
- 第1表・第7表は先頭に空列がある。`'2020'` の次の列を細分類コードとして読む。第7表の規模コードは 601=4〜9人 … 605=100〜299人、606=300人以上。
- 171MB の表は read_only で全国行だけ抜く（数分。バックグラウンドで回す）。

## 2. 分類の罠

- ペット用品・カー用品の細分類は存在しない。ペット用品は素材別（プラ・金属・繊維）に散る。「3113 自動車部分品・附属品」7,093事業所の大半は完成車メーカー向けの部品。カー用品の上限としては使えない。
- 企業等数（企業の主業で格付け）と製造業集計の事業所数は定義が違う。がん具は企業等数1,469に対し事業所620。どちらかに揃えて書く。
- 300人の線：企業等数で見ると消費財の小分類はどれも 99% 以上が299人以下。「300人以下」は統計上ほぼ足切りにならない（展示会の実測と同じ結論）。

## 4. 並列作業での失敗（次回やらない）

- 同じ deliverables フォルダでタカシと並列だったのに、`out/summary.json` という汎用名で出力して上書きした。タカシのスクリプトは再生成可能（API なし）だったので戻せたが、再生成できないファイルなら消えていた。
- 並列のときは、自分のファイル名に必ず自分の連番（01_）を付ける。out/ の中も同じ。書く前に `ls` で既存ファイルを確かめる。
- deliverables に置いた作業途中のファイルは、30分ごとの自動同期（`git add -A`）や他の人の同期 commit で先に commit されることがある。今回は改名前の `02_メーカー一覧…csv` と `10_classify.py` が commit 済みになっていた。途中のファイルは agent_output で作り、名前が決まってから deliverables に置く。PUBLIC に出てはいけないもの（ギフトショー・T-1 由来の社名）は最初から out/ にだけ書く。

## 5. 数字の要点（再利用用）

- 統計の上限（事業所・車を除く4カテゴリ）4,138、4人以上3,090。1カテゴリ459〜2,475。
- 定義差の根拠：製造業集計の留意事項に「個人経営を含まない」とある。企業等数は個人経営を含むので大きく出る（がん具は企業等数1,469のうち0〜4人が1,038）。
- 分類の確認：ドッグフード製造業は 1061 配合飼料の例示。釣ざお・釣針・リールは 3253 運動用具の例示。テントは例示に無い（e-Stat 分類ページ）。
- 名簿で見つかる数は、4人以上の事業所の1〜5割（おもちゃ41%・台所8%）。確度は低〜中。

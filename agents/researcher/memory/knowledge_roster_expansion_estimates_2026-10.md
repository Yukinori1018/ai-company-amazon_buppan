## 分かったこと（次に「名簿は何倍にできるか」と聞かれたらまずここ）

- **Keepa の月販は50が最小の階級。** Finder で ≥20 と ≥50 が同じ件数、1〜49 は0件（2026-10-05 実測）。「月販≥30・≥20 に緩める」は作れない。緩めるならカテゴリ別の売れ筋ランクで代替する（rank_cut.json：表示50/100/200の中央ランクにべき乗を当てた。推測）。
- **`singleVariation: true` は Finder で効く**（107,900→37,132）。親子を1件にまとめて数えるときに使う。
- **緩めて増えた商品の57%は既存の社の商品。**新しく残る社は18%、うち目視◎56%・△20%・×24%（T-20260930-001 の 53%/67% とほぼ同じ）。
- **商品数→社数は Horvitz-Thompson で直す。**新しい社は商品が少ない（中央1.5件）。◎の社ごとの件数を Finder の `brand` で数え、逆数で重み付け。商品割合×件数のままだと社数を過小にも過大にも誤る。
- 純増（送れる・推測）：3,000円以上・月20個相当 1,430〜2,240社／5,000円以上・月30個相当 380〜600社。ギフトショー約720社/回・RX 3展 約440社・ものづくり補助金 累計約1,760社。既存名簿との重複は2〜6%。合計で約4.4〜4.6倍。
- **ものづくり補助金の採択PDFに業種の列は無い。**事業計画名のキーワードで拾い、目視の適合率は食品71%・それ以外33%（N=60）。取りこぼしは非一致100件中4〜6件。約2/3が食品・酒（酒は通信販売酒類小売業免許が要る）。gBizINFO の company_url は28社中6社しか入っていない → 連絡先は Web 検索が要る（6社中5社で公式サイトあり）。
- Amazon 出店状況（Keepa search・社名でブランド/製造元を照合）：未出店か月50未満 ＝ ギフトショー 89%（N=28）・RX 60%（N=15）・補助金 71%（N=28）。RX は印刷・物流など B2B が4分の1混ざる。
- **ザ・ビジネスモールの企業詳細ページは非会員でも見える**（業種・URL・従業員数）。ただし「売り込みやテレマーケティングに利用することは禁止」の注記あり → 法務判定が要る。検索結果は JS 読み込みで curl では件数が取れない。

## 罠

- ギフトショーの機械分類 PASS に団体が残っていた（30社中2：公益財団・異業種交流会）。機械分類の後でも1割弱は混ざる。
- RX lifestyle の関西展は今は sitemap に無い（9/21 は4展、10/5 は3展）。展示会名簿は「今取れる回」を毎回確かめる。
- 社名の部分一致で既存名簿と照合すると誤一致が大量に出る（976社中56件→本物は約20）。照合は正規化した完全一致を基本にし、部分一致は上限の参考に留める。
- Keepa の token は他ジョブ（36_size_additions 等）と共有で、実効の回復が20/分を下回ることがある。約3,000 token の調査で約1.5時間かかった。一覧（perPage 10000）は「10＋件数/100」token。

## 手順（「名簿を何社増やせるか」型の依頼）

1. 既存名簿の「送れる」定義（抜き取りの◎/△・本人カート疑い・連絡先）を先に固定し、全経路に同じ物差しを当てる。
2. Keepa 経路：件数（Finder）→ 増えた分の無作為抽出300件 → 既存社との一致・除外ルール（maker_rules.classify）→ 目視 → `brand` 件数で HT。
3. 公開名簿経路：生の件数 → 機械分類 → 既存社との完全一致 → Keepa 検索で出店状況（1社10 token・N=20〜30）→ 連絡先率。
4. 最後に「今の名簿の何倍か」の表にして、経路間の重複（社名一致）を差し引く。成約率・順番の判断はタケシへ。

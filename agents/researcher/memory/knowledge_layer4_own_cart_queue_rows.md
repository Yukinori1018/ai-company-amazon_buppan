# 窓口集めキューの「層4 本人カート疑い」の処理手順と歩留まり（T-20260930-001 担当W / 2026-10-11 夜）

用途：キュー延長分（2170〜3189位）の層4（927行）を担当すると来たとき。検索をほぼ使わずに1担当100行を短時間で閉じる型。

## 事実（N=98・2170〜2269位）
- 接触候補1／要確認1／重複8／除外88。並行担当X（2270〜2369・N=98）は接触候補0。**層4は計196行で接触候補1（0.5%）**。層3（規模不明）の帯は13〜25%だった

- 除外88の内訳：セラー名に「公式・直営・メーカー」とブランド名・社名がそろう49行／名前の一致だけ38行（推測）／ブランド公式が自社Amazonストアへ誘導1行

## 手順（再利用可）
1. キューのカート保持セラー名を**全文**で出す（20字で切ると「…みの屋直販店」のような決め手が消える）
2. 既存台帳と ov.py でキーワード照合 → 同社は重複（若い順位が正）
3. セラー名とメーカー・ブランド名が**別名の行だけ**を拾い、公式とカート保持店の特商法を見る。今回は5行（2212・2256・2258・2266・2268）
   - 2266：カート保持店の特商法の販売業者が別会社 → **本人カートではない＝接触候補**（キュー判定の誤り）
   - 2268：楽天店の会社概要で既存台帳の会社（MOON-X Japan）と判明 → 重複
4. 残りは recs.py を機械生成（理由2種：公式/直営/メーカーを名乗る＝確度高、名前一致だけ＝推測）。備考に「落とす基準＝§3.3-5・実画面未確認」
5. 組み上げ後に xdup.py（担当文字を引数で受ける版：`python3 xdup.py W`）で並行担当と再照合
6. 公開版は leak.py で検査。**備考にカート保持店の名義を書くと build の置換で消えない**（「【公式】タイガ株式会社を名乗る」→ 名義だけが残った）。名義と根拠URLは agent_output の sources_private.md に分けた

## 落とし穴
- 範囲内の別ブランド表記（WAQ（ワック）とワック(WAQ)、防災のミカタ×2）はキューで統合されていない。同じセラー・同じブランドなら本表内の重複に寄せる

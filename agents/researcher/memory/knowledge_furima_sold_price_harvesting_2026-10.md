# フリマ3社の SOLD 価格をスクリプトで取る手順（2026-10-09 実証）

Amazon で売れない在庫を二次流通で現金化する判定に必須。**「出品中の希望価格」と「売れた価格」を混ぜない**ために、SOLD だけを取る。

## 取得可否（実測）

| 販路 | 取得可否 | 方法 |
|---|---|---|
| **ラクマ（fril.jp）** | **可**。サーバ描画HTML | `https://fril.jp/s?query=<URLエンコード>&transaction=soldout&page=N` を普通の `urllib`＋UA で取得。1ページ40件。`data-rat-cp-totalresults="N"` が総件数。各商品は `data-rat-item_name="..."` と `data-rat-price="..."` の属性ペアで拾える（`item-box__item-name` の内側テキストを正規表現で取ると広告属性を誤爆する） |
| **Yahoo!フリマ** | **可**。埋め込みJSON | `https://paypayfleamarket.yahoo.co.jp/search/<URLエンコード>?open=0`。`"id":"..","title":"..","price":N ... "itemStatus":"OPEN|SOLD" ... "condition":"new|used40|.."` を1レコードとして拾う。**`itemStatus` で OPEN と SOLD を必ず分ける**。`condition` も取れるので「新品のSOLD」だけ抽出できる |
| **ヤフオク（落札相場）** | **可**。WebFetch で読める | `https://auctions.yahoo.co.jp/closedsearch/closedsearch/<URLエンコード>/0/`。180日の落札実績。件数・平均・最安・最高も載る。※Yahoo!フリマの売却分もここに混ざる（重複に注意） |
| **メルカリ** | **不可** | `jp.mercari.com/search?...&status=sold_out` は完全CSR。`__NEXT_DATA__` も無く `"price"` が0ヒット。API は DPoP 署名必須。**ブラウザ操作（Chrome MCP）でしか取れない** |

## 検索語は3系統で当てる

同型番（例 `EM-103`）の SOLD は**ほぼ0件になる**。0件を結論にしないため、必ず3段で広げる。
1. 型番（`EM-103`）
2. 一般名＋寸法（`ステンレス 卓上鍋 22cm`、`よせしゃぶ鍋`）
3. ブランド名（`燕三`、`和平フレイズ`）

2026-10-09 の実例：`EM-103` は3販路すべて0件 → `ステンレス 卓上鍋 22cm` で新品SOLD N=2（1,780/2,300円）、`和平フレイズ 燕三` で新品SOLD N=6（850〜8,000円）が取れた。

## 落とし穴

- 🔴 **「ラクマ4.5%」を前提に計算しない。** 新規出品者は10%。これを4.5%と置くと手残りを5.5%分過大に見積もる
- 🔴 **Yahoo!フリマ・ラクマ・メルカリは送料が出品者負担で固定。ヤフオクだけ落札者負担を選べる**。低単価品では送料が手残りを支配するので、この差が販路選定を決める
- **サイズは3辺合計で決まる。同じ80サイズ枠に何個入るかを先に数える。** 28.1×27.7×7.4cm の箱なら 1個=63.2cm／2個=70.6cm／3個=78.0cm まで80サイズ（850円）、4個=85.4cmで100サイズ。**3個セットが送料効率の最適点**
- **ただしセット化は単価が落ちる。** まとめ売り（鍋）の SOLD は 1,100〜1,200円/点（N=3）。送料節約分より単価下落が大きいと、セット化は損益分岐を遠ざける
- `fril.jp` の FAQ（`faq.fril.jp`）は Cloudflare で 403。料率は公式PDFか報道で裏取りする

# メーカー窓口の確認手順と「推測アドレス不達」の教訓（T-20261016-001 / 2026-10-16）

## 起きたこと
- 社長が `inquiry@joypalette.co.jp` 宛てに打診 → 不達。公式に掲載された形跡はゼロ。**`inquiry@` / `info@` 系を推測で作ると不達になる**実例。
- ジョイパレットの公式窓口は消費者向けフォーム（/contact。購入日・商品名が必須、種別に取引の選択肢なし）と、お客様相談室の電話だけ。公式メールの掲載はない。
- 台帳（Keepa）では B09PY2D77V＝ミニキッチンセット。社長のメール件名は「育脳パズル」。**ASIN と商品名がずれたまま打診していた**可能性がある。

## 環境制約（再発する）
- この実行環境では curl が egress プロキシで 403、WebFetch は example.com を含め全ホストで ENOTFOUND。**ENOTFOUND をドメイン不在の証拠にしない**（dns.google も落ちるかで切り分ける）。
- 代替は WebSearch の `site:` 抜粋だけ。**抜粋には索引の古さ（数年前）が付いてくる**。必ず明記し、「表示なし」は「拾えた範囲で見つからない」と書く。ライブ確認は秘書のブラウザ操作に回す。

## 次回の手順（ルーチン）
1. `site:<domain> お問い合わせ` / `"@<domain>"` / `site:<domain> 法人 OR 卸 OR 取引` の3本を打つ
2. 窓口は**窓口単位**で表にする（B1L 3-5 #3）。公式ではない電話帳の番号は「参考」に隔離して採用しない
3. 打診前に、台帳の ASIN・商品名・JAN の整合を確認する（メール本文の誤りは先方の信頼を落とす）
4. 送信先メールアドレスは「公式ページに文字列として載っている」ものだけを使う。無ければ「見つからない」と書く

# 追記：マリーシャープス ジャパン不達の原因調査（T-20260930-001 / 2026-10-19）

## 起きたこと
- 第2弾-84 有限会社マリーシャープス ジャパン宛 `info@mariesharps.co.jp` が 553 5.3.0 User unknown で不達（10/19 13:34）。

- WebSearch の抜粋では、その `/contact-and-faq/` に用途別の窓口が載っていた：**法人のお客様＝販売元 有限会社リトル・ベリーズ**（03-5790-9725、littlebelize@habanerosauce.net）／個人＝マリーシャープス ジャパン（03-5774-0058）／お客様相談室 0120-880-407・care01@mariesharps.co.jp（2025年9月にカスタマー用アドレスを変更、との告知）。
- `"@mariesharps.co.jp"` の完全一致検索で info@ は1件も出ない。公式に info@ が載っていた証拠は見つからない。

## 学び（再発防止）
1. **輸入総代理店は「輸入・発売」と「販売（卸）」が別会社のことがある。** 台帳の正式社名＝ラベルの発売元、でも卸の窓口は販売元。お問い合わせページの「法人のお客様」欄を必ず読む。
2. **公式ドメイン＋`info@` は、窓口欄に「どのページに載っていたか」の注記がないと、推測で作ったものと見分けられない。** 台帳562セル中、明示の「推定」印は0。印がないことは「実見した」証拠にならない。
3. **「電話が取れなかった」「フォーム未確認」と書いた行は、お問い合わせページを開いていないサイン。** そういう行のメールは送る前にもう一度確かめる。
4. 公式が「アドレスを変更しました」と告知していたら、古いアドレスは不達になる前提で扱う。

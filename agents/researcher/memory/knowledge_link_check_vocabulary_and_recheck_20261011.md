# 紐付け確認の再点検：41社が「語彙」で落ちていた（T-20260930-001 担当LK / 2026-10-11 夜）

用途：「紐付け未確認で第1弾に入らない社がN社ある」と言われたら最初に読む。手順の正は [[knowledge_brand_field_vs_maker_linkage]]（10/04）、これはその続編。

## 何が起きていたか（事実）
- 対象の抽出：`sync_ledger.collect()` ＋ `dashin_order.assign()` を `--through=batchY` でオフライン実行（シートには触れない）。打診順が「対象外（検算NG：公式ページでの紐付け未確認）」の行＝**41社。41社とも紐付け以外の検算は全部通過済み**だった。
- 検算は `紐付けの判定.startswith('一致')` かつ根拠URLあり。**41社とも根拠URLはあった**。落ちた原因は判定欄の語彙：
  - 「ブランド単位：…」31／「表記ゆれ：…」2 ＝ **33社は「一致（…）」の接頭辞が無いだけ**で落ちていた（batch 採取時の自由記述）
  - 「未確認…」8
- **教訓：4値の語彙（一致／一致（表記ゆれ）／一致（ブランド単位）／未確認）は採取時から厳守。** 自由記述は理由欄へ。語彙が崩れると、検査は通っている社を黙って落とす。

- 逆に前回「ブランド単位」で通していた2社を未確認に落とした：**ケニス（AV-CHECK の製造元はアドバンテック東洋＝ケニスは販売店の疑い）／クリーンメーカー（OEM受託もする会社で「北海道馬油」ブランドが公式に無い）**。**「社名＝ブランド」でも、販売店・OEM受託会社は危ない**

## 効いた手（次回もこの順）
1. **JAN で引く**：公式のカタログPDF・価格表・商品一覧に JAN／型番が載っている会社は多い（わんわん＝カタログPDFに JAN、ニチネン＝洗剤ページに単品JAN、カリタ＝商品コード 61117、協進エル＝価格表 51042）。商品名が画像でも JAN は文字で出ている
2. **同一ホスト内の幅優先巡回**（`agent_output/T-20260930-001/67_link/c.py START kw 60`）。トップ1枚で「記載なし」と書かない
3. **公式通販が別ドメイン**：ふくや（fukuya.com）、エド・インター（ec.ed-inter.co.jp ＝ GENI）、日本炭酸瓦斯（espuma-advance.jp）、プロピア（propia-shopping.jp）、クリーンメーカー（horseoil.net）。トップのリンクを全部見る
4. **楽天のメーカー直販店**：会社概要（`/info.html`）で会社を確定 → 楽天検索結果から店の商品URLを拾う（イトスイ）
5. **PR TIMES の自社名義リリース**は商品単位の一致根拠になる（リッチボンド）
6. 医薬品・指定医薬部外品で公式サイトに無い商品は **PMDA の添付文書PDF** に製造販売元が出る（本草製薬）。ただし「公式サイト」ではないので理由欄に明記
7. **JAN の事業者コード**（先頭7桁）が同社の別商品と同じなら、少なくともブランド単位までは言える（コロンブス 4971671）

## ハマりどころ
- Wix・自前JS（richbond.jp の brand-list、nature-depot.com）は本文が取れない → 会社概要＋PR TIMES で
- ヨドバシは curl で 000（ブロック）。根拠URLにしない
- `timeout` コマンドは macOS に無い。長い巡回は 120 秒で背景化される
- Web検索の要約は「未検証」と書く。要約で一致にしない（ヤマカノ・ケニス・ASフーズは要約止まり）

## 手順で効いたこと
1. **最初に全カート保持店の特商法を取る**（sp3.py＝200以外で止まり、販売業者の行が無くても続ける版）。91件で約20分。これで40行が検索なしで除外にでき、検索の枠を販売店カートの行だけに回せた
2. **他バッチの html キャッシュを先に流用**する（URL の md5 が同じ）。今回5件
3. **sg.py**（トップ＋同一ドメイン1階層を最大60枚取って、商品名の正規表現を探す）で紐付けを一気に確かめる。auto.py は会社概要・問い合わせしか見ないので、商品ページの紐付けには sg.py が要る
4. 推定ドメインの当たりは「同名別会社」を必ず疑う：cosmofoods.net（福山の天ぷら）≠直火焼のコスモ食品（e-cosmo.co.jp・大田区）、iimono.co.jp（業務用手袋の通販）≠iiもの本舗（群馬）、almic.co.jp（岐阜の建材）≠アルミック（エービーエルのブランド）、brea.co.jp（不動産）≠トレカ用品のブレア
5. **gBizINFO の所在地とカート保持店の特商法の住所を突き合わせる**と、同番地の別名義＝本人カートが見つかる（ブレア公認店の販売業者＝株式会社ブレアと同番地）。会社概要の「グループ会社」欄も同じ（オザワ工業→ワイズプラント）

## 判定で足した型
- **公式に「県外卸や通販用卸などのお取引は募集しておりません」**（南都物産）＝除外。FFID の「楽天・Amazonへの掲載の提案は受けない」と同じ型
- **キューの上場列の誤照合**：キング砥石株式会社（常滑市）が衣料のキング（8118）に当たっていた。上場印は社名の部分一致で誤る（過去のチヨダ・イオン化粧品と同型）
- 品番の1字違い（公式 B100／Amazon D100）は「一致（表記ゆれ）」にし、打診前の確認事項として備考に書く
- 紐付けの判定欄は4値だけ（一致／一致（表記ゆれ）／一致（ブランド単位）／未確認）。build 前に assert で検査した（feedback_link_vocab_four_values_only の再発防止）

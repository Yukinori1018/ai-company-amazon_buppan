## 効いた手順
1. **JAN 事業者コードの兄弟（Keepa raw を前方一致・0 token）を最初に全行で出す**（jan_sib.txt）。今回これだけで同社確定5件：NSZストア=NOSTEEZ=NEWBOX JAPAN、ダニ捕りラボ=E-Surf、Lumk=森本商事（Grand le son）、IZAMESHI×ギンビス=杉田エース（IZAMESHI×吉野家と同コード）、SAIJIRUSHI=リバティライフ
2. 出品者ページの `<title>` から店名を取る（キューのカート保持セラーが ID だけの行でも店名が分かる）。店名＝ブランド名なら推測で本人
3. ov.py に「メーカー名・ブランド・Keepa brand/mfr」の全語を流すと、組み上げ前に重複の8割が見つかる。それでも xdup で1件（ユープラス＝B169）追加で見つかった＝組み上げ後の xdup は省略しない
4. 層5は上場列と商品が結び付かない行だけ調べる（3674：上場列はスーパーのエコス、商品は汗取りパット＝誤照合疑い→要確認）

## 判定で足した型
- **メーカー破産**（フェルナンデス：2024年7月事業停止・2025年7月破産開始決定）＝除外。販売店が在庫を売っているだけで打診先が存在しない
- **共同ブランド品**（ギンビス×イザメシ）は製造元ではなく JAN 事業者（＝発売元）で規模を判定する。杉田エース 381人で大手
- **既存台帳の要確認を後の担当が確定させたら、引き継ぎ①に書く**（I845 NEWBOX・N1392 E-Surf は本人カートで確定、Z1 2381 BALANSA は JAN から天幸製薬の可能性）。sync は重複行を飛ばすので書かないと成果が消える（ZB の M1259 と同じ）
- 公式の窓口が「お客様相談室」だけの中堅（サクマ製菓）も接触候補。ただし「取引窓口の案内なし」を備考に書く

## 公開版の漏れ防止（今回の失敗しかけ）
- 推測で本人とした行の正式社名欄に「（販売業者：株式会社◯◯）」と書くと、推測が外れたとき販売店名の露出になる。**推測行は社名欄をブランド名だけにし、名義は sources_private.md へ**
- キューのブランド欄・メーカー名欄がカート保持の販売店名になっている行（五宝堂・オフィスエッジ）は build.py の RETAIL に入れて伏せる
- 逆向き検査は「特商法の販売業者名＋店名」を語リストにして公開版を grep。leak.py の LEAK? はメーカー本人の店名なら許容

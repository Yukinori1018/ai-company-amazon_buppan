# 出典一覧（`[#n]` → URL）の作り方 — 再利用手順

初出: 2026-09-04 / T-20260904-004（draft.md 373行・`[#n]` 179箇所・ユニーク88番）
背景: 同じ積み残しが T-20260903-001 でも発生。**本文に `[#n]` を書いた成果物は、出典一覧なしでは納品物として不完全**。

## 問題

`draft.md` 本文に `[#5]` と書いても、読み手は何の資料か辿れない。`notes.md`（出典の実体）は別ファイルで、番号の対応表がない。

## 手順（30分で終わる）

1. 本文から番号を機械抽出する。目視で拾わない。
   ```
   grep -o '\[#[0-9]*\]' draft.md | sort -u
   ```
2. `notes.md` を「`^\d+\. `で始まる行＋以降のインデント行」で1エントリにパースし、使用番号だけ抜き出す（Python 15行）。
3. 表1本にまとめる。列は **# / 主張の要旨 / 出典URL / 確度 / 発行日 / 検証判定**。
4. **本文には一切手を入れず末尾に追記**。追記後 `diff <(head -N draft.md) バックアップ` で無変更を検算する。
5. 行数と番号集合の一致を機械検算する（`used == rows` を Python で確認）。目視チェックは通らない。

## この案件で社長／依頼者が明示した要求（次回も同じはず）

- 確度は `notes.md` のラベル（〔一次〕〔二次〕〔未確認〕）を**そのまま引き継ぐ**。言い換えない。
- `verification.md` で実地検証した行は判定（一致／部分一致／到達不能）を併記する。「実際に開いて確認された」という情報自体に価値がある。
- **未検証の行は「一致」ではなく「未実施」と書く。**空欄にしない（「未調査」と「該当なし」の区別と同じ思想）。
- 検証で不一致だった番号は**欠番にせず、なぜ本文で使っていないかを残す**。番号が飛ぶと読み手は「取りこぼし」と誤解する。
- 単一ソース依存の行は確度欄に明記する。
- **表1本。解説文は不要**（社長は表現がくどいのを嫌う）。前置きは「取得日は全件YYYY-MM-DD」の1行程度に抑える。

## 落とし穴

- 「不一致だから本文で未使用」＝**本文に `[#n]` が全く出てこない、とは限らない**。今回 #59・#123 は「この行は使用しない」という但し書きとして本文に登場していた。`grep -n '#59\]' draft.md` で実際の使われ方を確認してから文言を決める。
- verification.md の判定は行番号がまとまっていることがある（例: `#81/#82/#84 一括`）。表では各行に展開して「一括で確認」と注記する。
- 到達不能は正直に書く。今回 #11（Amazon公式ヘルプ5ページ）は JS＋ログイン必須で本文取得不可のまま。これは社長のログイン1手で埋まる穴なので、隠すと機会を潰す。

## 分担

出典一覧の追記まではリサーチャー。**HTML の再生成はコンテンツ制作（ヒデアキ）**。自分で HTML を触らない。

# 名簿（社名だけ数千行）に公式窓口を付ける — 規模を上げたときの律速と手順（T-20260929-001 / 2026-10-05）

用途：「展示会・補助金などの名簿 N千社に、公式サイトの電話・フォーム・公表メールを付けて」と来たら最初に読む。
作業場所：`agent_output/T-20260929-001/15_contacts/`（g1.py → guess.py → ws.tsv＋apply_ws.py → ex.py → build.py → rec14.py）
成果の置き場：シート『メーカー連絡先台帳』の「名簿拡張_窓口」タブ（非公開）＋ 14 の件数欄だけ（PUBLIC リポに社名を書かない）

## 律速は WebSearch のセッション上限（実測）

- **WebSearch は約180回でセッション上限**（"You've hit your session limit · resets 5:10pm"）。上限は時刻でリセットされる（今回 15:25 に到達・17:10 リセット表示）
- 1社1回でも、社名だけの名簿は 1,700 社で約1,300 回必要 → **上限の窓が7回ほど要る**。100社/回のペースは検索の窓で決まる
- Gemini の検索グラウンディングは 2026-10-05 時点でも 429（8/31 と同じ）。代替にならない
- 検索エンジンを curl/WebFetch で叩いて上限を回避するのはやらない（回避行為）

## 検索を使わずに当てる（歩留まり実測）

| 段 | 中身 | 実測 |
|---|---|---|
| gBizINFO | 社名完全一致→法人番号・カナ・所在地・URL | URL が入っているのは GS 1,729 社中 65（3.8%）。**カナが取れるのが大事**（ドメイン推測の材料） |
| ドメイン推測 | カナ→ローマ字（長音の揺れ・接尾語「製作所/工業/商店」を落とす）＋英字トークン × .co.jp/.jp/.com → DNS → トップに社名（法人格を除いた芯）があるか | **551社中107（19%）・800社中175（22%）** |
| 所在地照合 | gBiz の市区町村3文字が公式の取得ページに出るか | gBiz 候補が1社のときだけ「別会社の疑い」を判定できる。同名候補が複数のときは「紐付け要確認」止まり |

**推測ドメインの罠**：ドメイン売り場（leasetoown 等）に転送されるページでも社名が本文に出る（stem／TRUNK）。英字・短い社名（H.I.T.、THREE、赤堀）は同名別会社を拾う（h-i-t.jp は大阪の IT 会社）。→ 転送先の売り場判定・短い社名は所在地一致を必須に。

## 抽出（ex.py）で直したこと

- フォーム判定：`form` の部分一致は information に当たる。**問い合わせ系ページで `<textarea>` か外部フォームサービス**があるときだけフォームとする。Shopify のニュースレター欄を拾わない
- 電話：ラベル無しの10〜11桁は ID・品番を拾う（0001-02-5565 等）。**ラベル無しは区切り記号つきだけ・00 始まり除外・11桁は携帯/0120 系のみ**。表記はページの原文のまま（市外局番の切り方を機械で決めない）
- メール：Python の `\w` は日本語に当たる（"info@giemon.comまでに"）。ASCII 限定。mailto に全角の伏せ字（〇〇〇@〇〇〇）が入るサイトがある
- 「営業・勧誘・売り込みお断り」は問い合わせページに1行で書いてある（100社中4社）。原文を列に残し、メール可否を ×（13 §3-3）

# 紐付けの判定欄は4値だけ。自由記述を入れると接触候補が黙って落ちる（2回目）

- 1回目（2026-10-11 担当LK で発見）：「ブランド単位：…」「表記ゆれ：…」で33社が検算落ち
- 2回目（2026-10-13 カズヨのログで発覚・10-14 Z7/Z8 で確認）：Z2〜Z6 の接触候補10社が全員「確認済み：…」「ブランド単位：…」と書かれ、sync の検算（`紐付けの判定.startswith('一致')`）で「紐付け未確認」になり第1弾に入らなかった。根拠URLは10社とも入っていた
- 原因：batchZ の recs.py が `d()` の最後の引数に説明文を入れる型だった。コピーして使う道具に誤りが入ると、以後の担当が全員同じ誤りを再生産する

## ルール
- `紐付けの判定` に書いてよいのは **一致／一致（表記ゆれ）／一致（ブランド単位）／未確認** の4つだけ。理由は `67_紐付け確認_*.csv` の「判定の理由」か備考へ
- 接触候補を出した担当は、同じ担当の中で `67_紐付け確認_<担当>_<日付>.csv` まで作る（Z7/Z8 で実施）
- 道具（recs.py）をコピーしたら、接触候補の行の書き方を最初に見直す
- 組み上げ後に `判定=='接触候補'` の行の紐付け欄を一覧で出し、4値以外が無いか目で見る（10秒で済む）

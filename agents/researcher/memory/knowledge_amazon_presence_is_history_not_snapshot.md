# 「Amazon 本体なし」はスナップショットではなく履歴で判定する

初出: 2026-09-21 / T-20260909-002 / サトル

## 結論

**`availabilityAmazon = -1`（現在オファーなし）で「Amazon 本体なし」と判定すると、候補の9割以上が過大に残る。**
中村『国内メーカー直取引完全ガイド』の条件は「Keepa のグラフがオレンジで塗りつぶされていないこと」＝**履歴**の条件であり、現時点の在庫有無ではない。

## 実測（Keepa Product API・domain=5・2026-09-21）

| 母集団 | スナップショットで「本体なし」 | 過去365日に1度でも在庫あり | 365日まったく不在 |
|---|---:|---:|---:|
| グンゼ/ボディワイルド/サンリオ（9/20 抽出） | 68 | **63（93%）** | 5 |
| 同 × 売価2,200円以上（9/21 Finder 取り直し） | 90 | 88（98%） | **2** |

## 実装

- 使う項目は `stats.outOfStockPercentage365[0]`（index 0 = AMAZON）。
  - **100 ＝ 1年まったく在庫なし（通過）**／90〜99 ＝ ほぼ不在（要判断）／それ未満 ＝ Amazon が繰り返し在庫（落とす）
- `stats.avg365[0]` が -1 でないなら、Amazon 本体はその年に価格を持っていた＝在庫していた。
- Keepa Product Finder 側だけでは履歴条件を当てきれない。**Finder で粗く取り、product+stats=365 で履歴を当てて落とす**の2段が要る。

## 余録：Finder の単位

`current_NEW_gte` は **domain の通貨の最小単位**。JP は「円」なので 2,200円は `2200`。`220000` と書くと0件になる（2026-09-21 に1回踏んだ）。

## 併せて分かったこと

- `fbaFees.pickAndPackFee` と `referralFeePercentage` は **ASIN ごとの実測値**が Keepa 経由で取れる。
  手数料を「サイズ区分の推定」で置く必要はもうない。**推定が残るのは配送代行以外の固定費（保管・納品送料・仕入送料・納品代行）だけ**。
- `hazardousMaterials` に UN 番号（例 UN3481 = リチウムイオン電池内蔵機器）が入る。危険物判定は機械で当てられる。

# リストは「件数」でなく「連絡できるか」で数える

初出：T-20260831-005 の叱責 → T-20260906-005 で運用に落とした（2026-09-06）。

## 社長の言葉

> いらない情報を含んで母数を増やしたら、リスト化の意味がない（2026-08-31）

> KPI は「社長が連絡できるメーカー数」。総件数ではない（T-20260906-005 チケット）

## 運用ルール（今回これで通した）

1. **1行に「根拠1行」列を必ず置く。書けない社は行ごと消す。**
   根拠は感想ではなく **公開URLで確認できる取引導線の存在**に限定する（卸ページ・OEMページ・法人用フォーム・卸会員制度）。
2. **落とした社は消して終わりにせず、社名・理由・参照URLの表にして納品する。**
   「24社見て20社通した、落とした4社はこれ」と書けると、件数が正直であることが証明できる。
3. **20社に届かないなら届かないと書く。** 今回は 20 に届いたが、届かせるために弱い社を混ぜない。
   最後の1枠を埋めるために2社追加調査して、**片方（松尾陶器）は商号を特定できず落とした**。埋めなかった判断のほうが評価される。
4. **「未取得」と「該当なし」を列の中で書き分ける。**
   従業員数の空欄を「不明」で濁さず「未取得（gBizINFO 欠測）」と書き、出典URLは欠測が確認できるページを貼る。

## なぜこれが効くか

社長の最大の不満は `feedback_research_accuracy_blocker`（推定値が混ざって判断できない）。
リストの水増しはその一種で、**「連絡できない行」が混ざった瞬間に、社長は全行を疑うことになる**。
20行すべてに電話番号かフォームURLが載っている状態が、リストの最低ラインになる。

# 「Amazonのブランド欄 ≠ 製造販売元」の型と、商品×社名の紐付け確認の手順（T-20260930-001 / 2026-10-04）

用途：メーカー台帳・打診リストを社長に出す前、または「この商品、本当にこの会社のもの？」と言われたら読む。
発端：送信順1位ユニマットリケンを社長が Amazon で開くとブランド欄が「KANEKA(カネカ)」。商品は正しかったが、**紐付けを公式ページで確認しておらず、根拠もシートに無かった**。以後、台帳には「紐付けの判定」「紐付け根拠URL」「Amazon上のブランド表記」「Amazon上のメーカー表記」の4列を必ず持つ。

## 実測（N=199社・公式ページ約400枚・Web検索約45回・連絡ゼロ）

| 紐付けの判定 | 社数 | 意味 |
|---|---:|---|
| 一致 | 154 | 公式に同じ商品（商品名・容量・型番）あり |
| 一致（表記ゆれ） | 21 | ブランド欄・メーカー欄が別名だが、同じ商品が公式にある（理由を1行） |
| 一致（ブランド単位） | 20 | ブランドは公式で自社のものと確認。代表ASINと同じ個別ページは無い |
| 未確認 | 4 | 公式で商品を確認できず → 台帳の判定を「要確認：商品と社名の紐付け未確認」 |
| 不一致 | 0 | 別会社が正しい、は今回は出なかった |

送信対象20社だけなら 一致16／表記ゆれ3／未確認1（アークトレーディング）。

## 「ブランド欄 ≠ 製造販売元」の型（今回の21件を分類）

| 型 | 実例（Amazon上の表記 → 実際の窓口） |
|---|---|
| **原料メーカー名がブランド欄に入る** | KANEKA(カネカ) → ユニマットリケン（還元型CoQ10の原料がカネカ社製） |
| **海外の製造元ブランド／国内は輸入元・総代理店** | Nature's Protection → Peaker（日本総代理店）／MAWA → 山秀／ACANA → トランペッツ／モッツ → 鈴商／Ablue → ダイバーシティ／Clipa → アークトレーディング |
| **同社の別ブランド名・アパレル名** | Spazio → feel.（NOBITAの会社）／デオクリン → エコプラッツ／フォード → 三口産業／EdisonBrain → NEXT／ヘルシーカンパニー → アリスト |
| **販売店名・店舗名** | 香源 → みのり苑（製造元）／かの蜂 → Aruno（店舗名）／cotta → 富士商事 |
| **製造委託先がメーカー欄に入る** | 山下ラテックス工業 → ジャパンメディカル（販売元）／ロッテ（商品名） → オーラルケア（歯科専用品） |
| **グループ会社・親会社・販社** | すき家 → トロナジャパン（ゼンショーグループ）／バンインターナショナル → バンサプライ（地区販社）／EM研究機構（製造）→ EM生活（販売者） |
| **誤記** | ザンギ → サンギ |
| **旧製品・後継品** | KHS-8640 → 公式は後継 KHS-8660／クリアジェルEX → 公式は EX+／モイスチャーフォーム200ml → 公式は現行「モイスト フォーム」140mL／MR-9107 は【生産完了品】 |

**一番危ない型＝並行輸入品**：Amazonのメーカー欄が海外名（Topcor）・JANが米国UPC（085…）・型番が公式ラインナップに無い（Clipa2・S）。総代理店の公式は「並行輸入品は保証対象外」と書いている。ブランドが合っていても**代表ASINは正規品ではない**可能性 → 未確認に倒した。Amazonの商品名に「[並行輸入品]」と出ている例（コカレロ）もある。

**窓口がずれる型**：製造元と販売元が別会社（サンギ製造・オーラルケア販売／三光産業製造・富士物産販売・恵安共同開発）。社名は「正しい」が、仕入れの窓口は販売元のことがある。理由欄に両社を書いて秘書判断に回す。

## 手順（今回こう処理した。次回もこの順）

1. **Amazon側の表記は Keepa raw から 0 token で取る**：`raw/prod*.json.gz` の `brand` / `manufacturer` を代表ASINで引く（199件すべて既存rawにあった）
2. **品名トークンを人が1社2〜3語決める**（主語＝商品の固有名、補助＝容量・型番）。自動抽出より速く正確
3. **クローラで候補ページを出す**（`agent_output/T-20260930-001/55_link/crawl.py`：トップ→トークンを含むリンク→製品系リンク1段→Shopify `products.json`→WordPress `?s=`）。10並列で179社が数分
4. **人が原本を見て判定**（`g.py -k 語 URL`）。外れはWeb検索1回（`site:ドメイン 品名`）→ 取れたURLを必ず自分で fetch して確認
5. **判定と理由を `recs.py` に1社1行**（正式社名→(判定, URL, 理由)）。`build55.py` が元CSVに4列を書き、未確認を「要確認」に変える（元の判定は .bak から読むので冪等。除外行は除外のまま）
6. `sync_ledger.py` でシートへ（列追加時は直前ヘッダーからの移行分岐を1回分足す）。公開版は deliverables/09

## ハマりどころ（次回は先に疑う）

- **サイト内検索ページは検索語そのものを表示する**＝ヒット数1〜3は「投稿はありません」のエコーのことがある。`?s=` の結果は本文を読んでから採る（埜辺・ケイセイ・シナジー・アスタリール・日本生物製剤で発生）。「プレスリリース」の中の「リリース」で香り名「リリー」が当たる類の部分一致も同じ
- **meta refresh だけのトップ**（vicrea.jp → index.php）はクローラが空振る。HTMLが数百バイトなら refresh を疑う
- **Wix・Nuxt 等のJS描画**でも生HTMLのJSONに本文が入っていることがある（バイオアグリたかす）。0件と決める前に生HTMLを grep
- **403／証明書不一致**（p-antiaging.com・oujisekken.co.jp）はコーポレートサイトのブランド一覧か、**同社名義のPR TIMES**で「ブランド単位」まで
- **同名の別ドメイン**：ドクターズファーマシーは台帳のサイト（.co.jp＝医師向け個人輸入代行）と商品の公式通販（.net）が別。特商法の会社名・代表・所在地が同一＝同一法人と確認し、窓口は化粧品事業部と書いた
- **台帳の公式サイトが本業の別事業**（三光産業＝印刷の上場企業。マスクは共同開発品で公式に無い）
- クローラが **amzn.asia の短縮リンク**を拾って Amazon を「公式」として返す（相模ゴム・APOLON・松村商店）。Amazon は根拠URLにしない
- `sync_ledger.py` は agent_output→deliverables への**シンボリックリンク**。agent_output で編集すると Git 追跡ファイルが変わる（commit を忘れない）

## 判断のルール

- 「一致（ブランド単位）」は今回新設した区分。ブランドの持ち主が公式で確認できれば**社名の誤り**は無いので送信キューに残した。代表ASINの個別商品まで要るなら、秘書が「ブランド単位は要確認に倒す」と決めればよい（20社）。ここはプランナー／秘書の領分
- 未確認は「要確認：商品と社名の紐付け未確認」。元の判定は理由欄に「（元の判定：…）」で残し、戻せるようにした
- 大手グループ会社（トロナジャパン＝ゼンショー）を見つけたら理由欄に書くが、判定を「大手」へ変えるのは秘書判断

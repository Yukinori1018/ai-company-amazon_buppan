# 小口と大口の機能差：公式でどこまで確定できるか（2026-09-12 / T-20260904-005）

## 結論（2026-09-12 時点で表示中の公式ページ）
| 機能 | 小口 | 根拠 |
|---|---|---|
| 追加カテゴリーの出品申請 | 不可 | sell.amazon.co.jp/pricing の比較表（小口のセルが空欄）＋公式 PDF の目視 |
| ブランドの出品許可申請 | 不明 | 公式の明文なし。二次情報では大口が前提 |
| カートボックスの利用資格 | 不可 | amazon.co.jp node=8485743051 に「大口出品プランで利用いただける機能」として記載 |
| FBA | 可 | 比較表で両プランにチェック |
| FBA 保管上限 0.28㎥ | 未確認 | 2020年のフォーラム投稿がヘルプを引用しているのみ。公式 PDF（2019/2020）には記載なし |

## 手順の学び
1. **WebFetch の要約は、チェックマークの表を誤読する。** pricing の表を「小口も追加カテゴリー申請○」と返してきたが、実際の HTML では小口のセルが空欄だった。チェックの有無が判断材料になる表は、必ず生の HTML を行ごとに読んで確かめる（`icon-check-blue-thick.svg` がどのセルにあるか）。
2. 比較表の HTML は1行が「ラベル → 小口のセル → 大口のセル」の順に並び、空欄のセルは `text align-center` の空要素になる。この順番で読めば判定できる。
3. PDF 版は `pdftoppm -r 80 -png` で画像にし、Read ツールで目視すれば列の帰属まで確認できる（pdftotext ではチェックの画像が落ちる）。
4. セラーセントラルのヘルプ本文は、JP だけでなく US（sellercentral.amazon.com/help/hub/reference/external/）も非ログインでは本文0件。粘らない。
5. セラーフォーラム（sellercentral.amazon.co.jp/seller-forums/...）は非ログインで curl すれば本文が取れる。ヘルプの文面が引用されていることがあり、原文への道しるべになる。ただし扱いは二次情報で、日付も古い。

## 依頼パターン
「〇〇は小口でもできるか」系の依頼は、pricing の比較表（HTML の生データ）→ 出品形態変更のご案内 → PDF の目視 → フォーラムの順に当たると、30分以内に片付く。ブランドゲートのように公式の明文が無いものは、社長にログインしてヘルプを読んでもらう（読むだけなら申請にならない）ことを推奨として添える。

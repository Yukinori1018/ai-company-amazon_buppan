## 律速条件の順位（次回はこの順で当てると速い）

1. **Amazon 本体の履歴**（最も削る。90 → 2）
2. **売価の足切り 2,200円**（NETSEA を全滅させたのはこれ）
3. 入数補正（NETSEA 固有。商品名はケース・卸値は1個という取り違えが量産される）
4. 利益率・出品者数・回転（ここまで来るとほとんど残っていない）

## 母数を増やす手は2つしかない（どちらも社長の既定を動かす＝サトルは動かさない）

- 売価の足切りを下げる（ハジメの 2,200円を動かす）
- 「Amazon 本体なし」を履歴からスナップショットに戻す（中村ルールを崩す）

## 報告で守ったこと

- 「5〜10SKU」という依頼に対し、**数を水増しせず2件と答えた**。母数＝使える候補の数であって総件数ではない（`feedback_maximize_pool_not_ranking`）。
- **境界事例6件を理由つきで残した**（落とす方向の誤りは積み上がるため）。Brighte（危険物 UN3481）、マイメロ（Amazon 本体が年の4割）、theGUNZE（FBA 675円で構造的に不成立）ほか。
- **推定は3つだけに閉じ込めた**：配送代行以外の固定費220円／FBA 納品送料1,500円／取り分係数0.5。他はすべて実測。

## 手順のテンプレ（初回セット組成の依頼が来たら）

1. 既存の絞り込み済み CSV を探す（再取得から始めない）
2. Keepa Finder でブランド × monthlySold × 価格下限 → ASIN リスト
3. `product?stats=365` で履歴を当て、Amazon 本体の在庫切れ率で落とす
4. `fbaFees` / `referralFeePercentage` の**実測**で原価上限を計算（利益率0/5/10/20%の4段）
5. 卸値は「上限を1円でも超えたら買わない」判定式の形で渡す（実額は agent_output）
6. ゲート・危険物・要期限管理・価格推移を1表で確認
7. 境界事例は必ず理由つきで残す

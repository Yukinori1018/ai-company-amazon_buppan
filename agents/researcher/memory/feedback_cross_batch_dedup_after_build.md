# 並行バッチの窓口採取は「組み上げ後」に公式URL・電話・社名で機械照合する（T-20260930-001 担当L / 2026-10-10）

用途：窓口集めキューを複数の担当（batchA〜L）で分けて並行に採るとき、重複を取りこぼさないための手順。

## 何が起きたか（事実）
- 着手前にキーワード（社名・ブランドの一部）で既存台帳を grep して重複16件を確定した。
- 組み上げた後に「正式社名の芯（法人格を除く）・公式サイトのドメイン・電話番号」で A〜J と機械照合したら、**追加で6件の重複が見つかった**（エリデン＝D378、山谷産業＝E487、キャピタルビューティー＝J924、ヘイセイ＝J938、Pet-Cool＝I881、カネボウ＝E473）。
- うち1件は**自分の読み違い**だった。Pet-Cool の会社概要で沿革の「株式会社英知建物」を拾って正式社名にしたが、商号欄は「株式会社Bellwoods」（英知建物のペット事業部から2006年に独立）。電話番号が同じだったので照合で見つかった。
- 並行の担当J（901〜1000）は作業中にファイルが現れた。着手前の照合では存在しなかった。

## 手順（次回からこうする）
1. 着手前：キーワード照合（社名・ブランドの一部）で既存台帳との重複を先に確定する（検索枠の節約）。
2. 組み上げ後：`正式社名の芯 ∈ 他の正式社名`、`公式ドメイン ∈ 他の公式URL`、`電話番号の先頭12文字 ∈ 他の電話番号` の3キーで、**並行担当のファイルを含めて**もう一度照合する。並行担当のファイルはこの時点で増えていることがある。
3. 正式社名は会社概要の「商号／社名」欄から取る。沿革・旧社名・親会社名を拾わない。
4. 同社が見つかったら若い順位を正とし、こちらで新しく分かった事実（公式URL・電話など）は重複行の備考に書いて相手の行の更新材料にする（例：1177 ヘイセイ → J938）。
5. 公開版は commit の前に、カート保持セラー名（先頭8文字と4文字以上の語）が全列に出ていないかを機械で確かめる。判定欄に書いたセラー名（例「sakurasaku-webshop≒桜木電子」）は build の置換で消えなかった。

## WebSearch のセッション上限は並行担当と共有
- 今回は約100回使ったところで、セッション全体の200回に到達した（並行のJ・Kと共有）。到達した後は検索できない。
- 並行で走る回は、**検索が要らない行（大手・重複・推定ドメインで当たる行）を先に片付け、検索は最後にまとめて使う**のでは遅い。検索が要る行のリストを最初に作り、優先度の高い行から先に検索する方がよい（推測：今回は前半で検索を広く使い、後半の26行が公式未特定のまま残った）。
- 上限の引き上げ（`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`）は社長判断の選択肢としてカズヨに出す。サブエージェントが自分で設定を変えることはしない。

## キュー1100番台の層の特徴（N=98・2026-10-10）
- 重複26%（既存台帳と同じ会社の別ASIN）、公式未特定が27%。月販50〜100の層で、社名欄が商品名・ブランド名・販売店名のことが多い。
- キューの上場印に同名の誤照合が残っている（チヨダ＝靴小売 8185 ではなく、からしの中小メーカー109名）。上場印は社名と事業内容を見てから大手にする。
- 「ネット販売業者からの卸の問い合わせはすべてお断り」（かんずり）や「転売・商用目的の購入お断り」（ユニフリー・プラスキレイ）は、問い合わせページや通販トップに1行で書いてある。窓口を採るときに必ず読む。

## 追記（担当M・キュー1201〜1300・2026-10-10）— 手順は効いた。キーワード照合だけでは足りない
- 着手前のキーワード照合で重複11件 → **組み上げ後の3キー照合（社名の芯・ドメイン・電話）で追加5件**（JUN＝K1058、暁石鹸＝K1019、ファーストコレクション＝K1044、キャメル珈琲＝E464、ペットライン＝30位4）＋並行の担当N 1383位が本表1264位と同社（こちらが若い順位＝正）。並行担当K・Nのファイルは着手時に無く、作業中に現れた。**組み上げ後の照合は省略しない**
- 照合スクリプトの型：`core()`＝法人格と括弧を除いた社名、`dom()`＝公式URLのホスト、`tel()`＝最初の `0\d{1,4}-\d{1,4}-\d{3,4}`。`batch[A-L]` と `batch[N-O]` の 24_ を全部読む（照合コードは agent_output/T-20260930-001/batchM の作業ログ参照）
- 上書きは recs.py の末尾で `R.pop(k)` → `dup(...)`。d() の assert（重複キー禁止）を崩さずに済む

## 公式を当てる小技（1200番台・月販50の層・N=99）
- **ブランドの通販サイトの特商法表記が一番速い**：tendersense.jp → 販売業者「株式会社タナック（岐阜）」→ メールのドメイン k-tanac.co.jp が会社の公式。tanac.co.jp・tanac.jp は同名別会社だった
- **ブランドサイトのフッターのリンク先で運営会社が分かる**：legatolargo.jp → carrot-co.com（キャロットカンパニー）。社名がページ本文に無いときは `href` を全部出して外部ドメインを見る
- **社名変更は沿革で拾う**：日本オスモ → オスモ&エーデル（沿革「1995年 日本オスモ株式会社を設立」）。同名の osmo.co.jp（水処理）は別会社
- **JS描画（Nuxt 等）のサイトは curl で本文が取れない**（mineralia.co.jp・ginpo.co.jp）。403（fbr.jp・needs5050.com）も含め、回避はせず「公式は実在・取得不可」と判定を分けて書く
- 抽出用に `fx.py`（社名・所在地・TEL・FAX・規模・メール・フォーム有無を1ページ数行で出す）を作った。auto.py で候補ページを見つけ、fx.py で値を確定する二段が速い
- WebSearch は 99行で53回（未特定の社に1社1回）。上限には届かなかった。公式未特定は32行（32%）で、1100番台（27%）より高い

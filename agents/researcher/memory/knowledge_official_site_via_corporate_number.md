# 公式サイトは「法人番号 → 企業DBの公式サイト欄」で検索0回で当てられる（T-20260930-001 担当RC / 2026-10-11）

用途：窓口集めで「要確認：公式サイト未特定」「検索待ち」が大量に残ったとき。Web検索の枠（セッション共有200回・担当ごと50〜100回）を使わずに公式を当てる。

## 手順（`agent_output/T-20260930-001/recheck/cz.py`）
1. 社名（法人格つき）で gBizINFO を引き、**完全一致**の法人を取る（法人番号・登記住所）
2. `https://compalyze.co.jp/company/<法人番号>` を1枚取得し、本文の「公式サイト ◯◯」を読む（1.5秒間隔）
3. そのドメインを auto.py で最大5枚たどり、**商品名のキーワード**が公式に出るかを vj.py で機械照合 → 人が判定
- 法人格が分からない社は「株式会社X／有限会社X／X株式会社」の3通りで引く
- 同名が多い社（ニーズ40社・アイテム51社など）は、候補ドメインを全部たどって**商品キーワードが出た社だけ**を採る

## 実測（担当J〜Vの要確認394行＋N1369・2026-10-11・Web検索90回）
| 手段 | 投入 | 接触候補に上がった社数 |
|---|---:|---:|
| Web検索（1社1回が中心） | 90回 | 3社（URLが直接出た分）。社名・所在地の割り出しには効いた |
| 推定ドメイン（guess.py） | 約200社ぶんの候補 | 8社 |
| **法人番号→compalyze** | 社名の照会 約450件（法人格3通り込み） | **51社**（全63社の81%） |
| 他担当の記録（L1177 の更新材料） | — | 1社 |

- 結果：要確認395行のうち 更新93行（接触候補63・重複4・除外4・大手1・要確認の理由を更新21）／所見のみ127行／未着手175行
- 検索の要約は「会社の説明」を返すが、小さい社の公式URLはほぼ返さない（担当Kの所見と同じ）。**検索は社名を割り出す用途に限り、URLは法人番号ルートで取る**のが速い
- compalyze の「公式サイト」欄は AI 推定なので**誤りがある**（フロムファーイースト→羽エクステ通販、ヘルスアンドビューティー→無効URL、ユーワ→保育園）。必ず公式を開いて商品で照合する。根拠URLには compalyze ではなく公式のページを書く

## 判定で今回見つけた型
- **ブランドの運営会社＝カート保持セラー**：楽天の直営店の会社概要の運営会社名（「ひなた」）が Amazon のカート保持セラー名（「菊芋専門店 ひなた」）と一致 → 除外。公式タイトルにブランド名とセラー名が並ぶ型（「合同会社CAU┃…┃女神のウキウキ習慣」）も同じ
- **公式が「Amazonでのネット販売の問い合わせ対応は停止」と明記**（中西ゴム工業）→ 除外。当社の打診がそのまま当たる
- **上場会社の100%子会社**（星製薬＝テーオーシー100%）は公式の会社概要の「株主」欄に書いてある
- **登記住所が同番地**（ティー・ビー・ケー＝東京鼻科学研究所、カンホアの塩＝アレッポの石鹸）は同グループの手がかり。事実＝同番地、推測＝同グループと書き分ける
- 公式の「販売先」欄に「アマゾンジャパン株式会社」（マリン商事）＝Amazon本体への卸の疑い → 要確認

## 再開するときの順番（次回はこうする）

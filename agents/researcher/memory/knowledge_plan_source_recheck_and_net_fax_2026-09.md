## 学び：計画に入った数字は、原文を curl で取って grep する

S11（松井の7ステップ）を再読し、社内の 01・06 に次の3つの誤りを見つけた。どれも「要約を経た数字」が計画に入った例。

| 誤り | 実際 | 原因 |
|---|---|---|
| 06：初回テスト「最小5個」の出典を S4 と表記 | S4 の原文は「初回のみ20個」（最低ロット100個の先へのお願い）。5個はセミナー Q&A、S11 は「取り分1ヶ月分＝例では10個」 | 出典の付け替え |
| 01：「月利50万に月1,500〜2,000通」 | 原文は累計の目安。月は300社（1日10社） | 単位の読み違い |
| 01・06：返信30%・見積8〜10%・成約3〜5%は松井の実績 | 原文は「目標値」の列。WebFetch も「著者の実績」と誤答した | WebFetch の要約が主語を補った |

- 手順：`curl -sL -A <UA>` で HTML を取得し、script と style を除いてテキスト化してから、数字と単位の語（個・通・社・%・日）で grep する。WebFetch は目次や当たりを付けるのに使い、数字の確定には使わない。
- 3基準（本体なし・FBA2人以上・ランク5万位以内）は、公開記事には無い。出典は社内のセミナー記録（2026-06-10）だけ。

## 再利用する型（「計画の前提を事実確認して」と頼まれたとき）

1. 計画の手順表の各行について、出典記号→原文 URL を引く。
2. 原文を curl で取得し、項目ごとに「原文・他の出典・計画の記載・判定」の4列で照合する。
3. 判定は「一致／食い違い／意図的な差分（社内ルール由来）／原文に無い」の4つに分ける。意図的な差分は誤りとして扱わず、論点として残す。
4. 食い違いは「どちらを採るかの材料」まで書いて止める（採否はタケシの領分）。

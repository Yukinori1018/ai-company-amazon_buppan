## 再利用できる手順（要確認の詰めの型・この順で回す）
1. **keepa_brand.json から代表 ASIN の JAN を取り、楽天を JAN で検索する（`rc1026/jr.py label=JAN ...`）**。上位3商品の「発売元／製造元／販売者／輸入者／メーカー名」を正規表現で抜く。**Web検索0回で作り手の社名が出る**。今回の接触候補9のうち6が、この経路か推定ドメインだけで決まった
2. 社名が出たら `guess.py`（推定ドメイン）→ `auto.py`（会社概要・問い合わせ）→ `gz.py`（gBizINFO の登記住所と照合）
3. 公式が無くても**楽天の自社店**（会社概要の社名＝作り手）なら窓口に使う（確度中と書く）。同社のプレスリリースが楽天店を自社 URL として掲げる例（アクエス）もある
4. Web検索は「社名＋所在地＋商品語」で公式 URL を探す用途に限る。小さい社の公式 URL は検索ではほぼ出ない（31回中、公式に届いたのは PR TIMES 経由のリボン1件＝JS 描画で照合不可）

## 判定で効いた型（事実で決まったもの）
- **JAN が同じなら商品名が違っても同じ商品**：Amazon「たたき名人すこやか」＝公式「モンデール 極上たたき CM3」（JAN で楽天を引くと CM3 が出る）→ 一致（表記ゆれ）
- **ブランド欄が通販店名のことがある**：「銀のモップ」は清掃用品の通販2社の屋号で、作り手は文化雑巾（楽天の自社店「文化雑巾公式」の製造者表示）
- **本人カートの決め手**：楽天の商品表示の「販売者」＝Amazon のカート店名（KISST）／カート店の特商法の運営責任者＝楽天自社店の代表者（cacavert）／楽天のメーカー名とカート店の法人名・市が一致（Natural Balance）
- **公式に「新規取引お断り」**（河原酢造「品薄の為」）→ 除外。品薄解消後は再検討余地
- 「Amazonで購入」ボタンが公式にある（LOVEPAKU）・公式投稿に Amazon DEAL（TEITO）＝メーカー自身が Amazon の棚を持つサイン。要確認のまま理由に書く

## 打ち切りライン（これ以上は推測）
- 社名と電話が**販売店ページの表示だけ**で公式が無い行（せんせん・星元・クリアー・芳月堂）は要確認に留め、「秘書判断なら電話で接触候補にできる」と書いた。**この扱いは秘書に決めてもらう論点**（同型が今後も出る）
- 法人向け窓口が無い大きめの社（コルグ＝個人向けフォームのみ）は接触候補にしたが「通り道が細い」と明記

## 失敗とリカバリ
- `jr.py` を `| grep | head` 付きで回したら出力がバッファされて600秒のタイムアウトに当たった。**キャッシュ（html/）が効くので、2回目はファイルへ直接リダイレクトして即完了**。長い取得はパイプせずファイルに書く
- recheck の `紐付けの判定` は4値（一致／一致（ブランド単位）／一致（表記ゆれ）／一致（表記ゆれ・まとめ売り））＋未確認・既存台帳で確認済み以外を `build.py` で弾くようにした（前夜の自由記述事故の再発防止）

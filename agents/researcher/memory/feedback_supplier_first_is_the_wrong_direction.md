# 「仕入れ先の商品を全部列挙する」は依頼どおりでも筋が悪い（2026-09-30 / T-20260920-003 28）

## 何があったか

カズヨから「SD の取引企業2,176社の商品を列挙してシートに積んでください」と発注された。
**依頼どおりやると判定に届かない**と分かったので、理由を数字で示して2本立てに直した。断らず、代案と一緒に出した（CLAUDE.md §3.1-3）。

| 依頼どおりやると | 数字 |
|---|---|
| 一覧ページに **JAN が無い**（HTML 全文で「JAN」0件） | JAN は商品ページにしか出ない |
| 商品ページの **JAN 記載率は 71%** | 29% は機械で突合できない |
| 2,176社 ≈ **約140万点** ＝ 一覧 **約11,600ページ**、JAN まで取るなら **140万ページ** | 現実的でない |
| 仕入れ先起点の歩留まり | **15%**（CLAUDE.md §3.3-9・実測 N=55） |
| 対して **Amazon 起点の JAN 逆引きは 1 JAN = 1 リクエスト** | 桁が2つ違う |

## 学び

1. **「列挙してから絞る」と「絞ってから引く」はコストが2桁違う。**索引を作る依頼が来たら、**索引を作らずに答えが出る経路があるか**を先に計算して示す。
2. **落とす順番を間違えると全部無駄になる。**2,176社のうち Amazon 名指し不可が推定700社前後（人気順 N=55 で35%）。**商品を列挙する前に取引条件で落とす**のが安い。同じ構造の失敗を §3.3-8 でもやっている（消極条件だけ並べた）。
3. **依頼に異論があるときは「できません」ではなく「この順でやれば出来ます」と書く。**今回は索引レーン（依頼どおり）を止めずに、突合レーンを併走で渡した。

## 🔴🔴 最重要：**python の urllib は SD から 429 で弾かれる。curl は 200 を返す。**

同じ URL・同じ User-Agent・同じヘッダで結果が違った（2026-09-30 実測）。

| クライアント | 結果 |
|---|---|
| `curl -sL --compressed -A <UA>` | **200**（3回連続） |
| urllib（最小ヘッダ） | **429** |
| urllib（Accept / Accept-Language / Sec-Fetch-* までブラウザ同等） | **429** |

- **原因は TLS フィンガープリント（JA3）と推測（確度中）。**ヘッダを揃えても直らない＝判定はヘッダより手前。
  `requests` / `httpx` も同じ TLS スタックなので同様に弾かれる見込み。
- **これを「レート制限」と読み違えた。**8/16/32/64秒のバックオフを入れて2回も走らせ直し、
  「SD は HTTP からの大量スキャンに使えない／ブラウザで回すしかない」と**誤った結論を README に書きかけた**。
- **教訓：同じ URL が curl で通るなら、それはレート制限ではない。**HTTP が 429 で止まったら、
  まず**別クライアント（curl）で1回叩いて切り分ける**。バックオフを深くするのは切り分けの後。
- **対処：`_fetch.py` に curl サブプロセス版の fetch を切り出し、3本のスクリプトで共有した。**
  修正後は 2.5秒間隔で **約24社/分**で安定して回った（2,176社で約90分）。
- 併発は避ける：ジャンル一覧スキャンと取引条件スキャンを並走させたときも 429 が出た。**SD には同時に1本まで。**

## 結果として分担はこうなった

| 用途 | 経路 |
|---|---|
| 取引条件（○△×）・商品名・商品コード・**JAN 逆引き** | **curl。ログイン不要。サトルが回せる** |
| **卸価格・セット卸額・ご注文セット数** | **ログイン必須＝ブラウザのみ**（`SDX.run()`） |

JAN 逆引きの副産物：**同じ JAN を複数の出展企業が持つ**（実測で1 JAN に4社）。**卸価格を社間で比較できる。**

## 二度と間違えないための小技

| 事実 | 内容 |
|---|---|
| 企業の商品一覧は**サーバー描画**（curl で取れる） | `/p/do/dpsl/<dealer_id>/` → 1ページ目・`全N件` が `.page-nav-numtxt` に出る。2ページ目以降は **`/all/<pg>/`**（`?pg=` も通る）。120件/ページ |
| ジャンル別の企業一覧もサーバー描画 | `/p/do/psl/<genre_id>/?pg=<n>`・25社/ページ。**ただし生活雑貨(5134)だけで1,550社超＝ジャンルは優先順位の識別力が弱い** |
| 取引条件は非ログインで読める | `/p/do/dpsl/dcc/<dealer_id>/`。**○△×は Font Awesome のアイコンでテキストに出ない → HTML で判定する** |
| **ネット販売の行が無い社がある** | 丸進(102452)は消費者直送/仕入れ前の販売/画像転載/代金引換の4行だけ。**「記載なし」を「○」に畳まない** |
| 🔴 dcc ページには**送料表の実額**が載る | SD 会員規約17条1項の会員限定情報。**スキャン出力は agent_output 配下に限定する**（スクリプトに `agent_output` チェックを入れた） |
| 取引企業数 | カズヨ報告は2,175社、TSV の実データは **2,176社**（全件ユニーク） |
| サービスアカウントでシートは作れない | Drive 保存容量0で 403。**新規作成は Drive MCP（秘書）→ SA へ編集者共有（1回）→ gspread で投入** |

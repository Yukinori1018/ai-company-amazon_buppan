# 社長の指示：探索の向きを反転させる（発見と検証を分ける）

日付：2026-08-31 / チケット：T-20260831-005

## 社長の言葉（原文）

> 「Amazonページからのリサーチとは別に、いろいろなリサーチ方法を検討したい。リサーチ方法をあらゆる方面から考えてください。まず、どういったリサーチ方法があるのかを、ウェブやXやその他SNSなどを使って調査をお願いします。
> **キーパを使うのは、その情報をもとにAmazonのほうでランキングを調べ、本当にこれは売れるのかどうか、というところを確認**してほしい。
> その前提条件として、**私がメーカーからそれを仕入れることができそうかどうか、という判断基準は絶対に入れてください。**」

## 何を学んだか

1. **ツールの役割を固定するな。** Keepa は「発見ツール」として使われてきたが、社長は「検証ツール」に降格させた。
   起点を Amazon に置くと母集団が「Amazonで売れている商品」に固定され、中国系OEMと大企業しか残らない（T-20260831-004 で実証済）。
   **母集団の定義が答えを決める。ツールの性能ではない。**

2. **「仕入れられるか」は後付けのフィルタではなく、母集団の条件。**
   社長はこれを「絶対に入れてください」と表現した。件数を出しても「実績ゼロの個人事業主が門前払いされる相手」なら価値ゼロ。
   → 評価表には必ず「社長が仕入れられる可能性」列を A/B/C/D で入れ、**理由（なぜ門前払いされないか）まで書く**。

3. **「あらゆる方面から」＝網羅の宣言ではなく、視野の宣言。**
   27経路を出したが、実測したのは上位のみ。**全部を浅く調べるより、上位を実測して数字を1本出すほうが刺さる**
   （feedback_research_accuracy_blocker「推定でなく実測」と同じ思想）。

4. **社長は「ウェブやXやSNSで調べろ」と明示した。** 教科書的な一般論ではなく実務者の生データを求めている。
   ただし SNS 経由の経路そのものは**母数が定義できず定量化できない**。そこは正直に「測りようがない」と書いた。
   → **測れないものを測れたふりで書かない。「測りようがない」も答えの一つ。**

## 次回に効く型

- 発見（母集団づくり）と検証（実売確認）を、必ず別々の章にする
- 新経路を提案するときは **既存母集団との重複率を実測して添える**。「新しい」を主張するのに一番強い1行になる
- 「重ならない」を良い話としてだけ書かない。**競合ゼロと需要ゼロは同じ数字で観測される**ことを併記する

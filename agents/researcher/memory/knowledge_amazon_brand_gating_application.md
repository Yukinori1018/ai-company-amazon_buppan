# ブランド単位の出品許可（brand gating）申請の事実確認パターン（2026-10-21 / T-20260930-001）

## 依頼の型
「メーカー請求書で出品申請した。ブランド名が会社名と違う／『〇〇はブランド登録済み』と出るが大丈夫か」——今後も仕入れが増えるたびに来る定型質問。

## 判定の骨格（再利用可）
1. カタログの「ブランド」欄（=商品ラインの名前。例: ムカデ博士）と「メーカー」欄（=会社名。例: アイ・ビー・アール）は別属性。ブランド≠会社名は普通。
2. ブランド制限はカタログのブランド属性に紐づく（推測・業界解説一致。JP公式本文は未取得）。申請画面にブランド名が出るのはそのため。
3. 請求書は「発行元=メーカー or 正規卸」「品名にブランド/商品名が入る」「宛名・住所がセラーアカウントの登録情報と一致」「直近180日以内」「数量（US系解説では10個以上が通例）」が見られる論点。品名が商品名で発行元が会社名なのは正常な形。
4. 「ブランド登録済み」= ブランド権利者がAmazonブランド登録に登録している、という事実の表示と読むのが自然。出品許可申請（ASINの「出品許可を申請」から入る）と、ブランド登録申請（brandservices / brandregistry、商標番号が要る別フロー）は別物。商標番号を入力していなければ「自社がブランド所有者」と主張する申請にはならない。

## 環境の制約（重要・時間を溶かさない）
- このクラウド環境では www.amazon.co.jp / sellercentral.amazon.co.jp / sellercentral-japan.amazon.com が **プロキシ403・WebFetch DNS不可**。ASINページもフォーラムも読めない。
- Keepa APIキーは .env に無い（KEEPAは deliverables のコードにのみ登場）。
- → ASINのブランド/メーカー欄、ヘルプ本文は **秘書のブラウザ操作（社長ログイン）で読む**前提でチケットに書く。検索で粘らない（knowledge_amazon_official_primary_sources.md と同じ結論）。

## 失敗とリカバリ
- 指定チケット T-20260930-001 のファイルがローカル tickets/ 配下に存在しなかった（別端末・未pushの可能性）。現在地/ログを更新できず、ハンドバックで明記して秘書に返した。

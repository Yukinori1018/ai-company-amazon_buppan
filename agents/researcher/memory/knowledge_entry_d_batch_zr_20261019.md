## 🔴 気づき（次回の手順に入れる）
- **層5（大手）はキューのメーカー欄＝Keepa の brand で決まっている。brand が誤っていると中小が大手に紛れる**
  - 5035：brand「イケヒコ・コーポレーション（340人）」→ 商品名の「匠の技 G-2300」で公式を引くとグリーンベルの品番と完全一致＝接触候補
  - 5036：上場列「ヤマト（1967）」→ 商品はプロポリンス＝ピエラス（既存の接触候補）
  - 5032：上場列「創健社（7413）」→ 商品名は「東京フード 生おろしわさび」
  - **層5 の行も1行ずつ商品名を読む**（品番・ブランド語が brand 欄と食い違う行だけ公式を引く）。大手1行で閉じる前に30秒
- **JAN の事業者コード（先頭7桁）で別名義の同社を推測できる**：銀座コスメティックラボのつけまつげ（4560323…）とピエラスのプロポリンス（4560323…）。gBiz で0件の社名でも、既存台帳の社と事業者コードが同じなら「推測：同社」と書ける。TABASCO も同コード（4961935）の別商品の小売ページから国内販売元（正田醤油）が出た
- **既存の接触候補のメーカーが、別 ASIN で自社 Amazon 店のカートを持っていることがある**（カネソン：ZP 4784 は接触候補、ZR 5029 は「kaneson store【メーカー公式店】」）。重複行の備考に書き、秘書判断へ（ZN の Rainmakers と同じ型）
- 公開版の伏せ字漏れ：判定文の「店名「…」」の引用は build.py の既存置換（カート保持…「」）に当たらない。`(店名)「[^」]*」` の置換を足した。leak.py の LEAK? は英単語（store・official）で誤検知が出るので目で確かめる

## 再利用できる手順（キュー末尾の層4＋層5 の85行を約1.5時間で閉じる型）
1. batchZP をコピーし sed で batchZP→batchZR・日付・範囲。html は batchZI/html への symlink、recs.py は recs_head.py ＋ recs_bodyZR.py を cat
2. 25_対象 を切り出し → mk_keepa.py → raw/prodbb_*・prod_wideD_* の stats.buyBoxSellerId で sid.json → sp3.py を nohup で背景実行（待ちの間に既存台帳の社名 grep と、店名≠ブランドの行の公式探し）
3. mkview.py で「キューの社名｜ブランド｜商品名｜店名｜特商法の販売業者」を1画面に → 販売業者＝ブランド/社名なら exS、店名＝ブランドなら exG、別会社の行だけ guess.py → auto.py
4. 層5 は bigL（キューの規模列を転記）。既存台帳に「大手」で入っている社は dupE
5. build → xdup → scan → mk67 → build --public → leak.py ＋ 販売業者名の逆照合（自社カートの社名は出てよい・第三者の販売店名が0件か）→ commit
- 注意：recs_head.py の CRIT は「Keepa の取得日」（raw の日付＝10-18）であり、sed で確認日と一緒に置換しない

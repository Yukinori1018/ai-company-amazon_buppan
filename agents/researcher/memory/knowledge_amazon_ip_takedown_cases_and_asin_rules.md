## 🔴 04 の誤りを訂正した — 「相乗り出品者は商品画像をアップロードしない」

04 で「当社に効くのは商品画像の著作権。画像は自分で撮るしかない／撮れば申立ての足場が無くなる」と書いたが**誤り**。

**一次（Amazon 公式・非ログインで取得可）** `https://sell.amazon.co.jp/learn/listing`「Amazon商品登録マニュアル」：
- 「**Amazonは1つの商品に対して、商品詳細ページが1つというカタログ形式のECサイトです。**」
- 相乗り出品で入力するのは「**在庫数、販売価格、コンディション、配送方法**」のみ＝**画像は手順に出てこない**
- 新規出品の事前準備は「製品コード（UPC/EAN/JAN/ISBN）／商品名／製造業者／商品の詳細（ブランド・カテゴリ・説明・画像）」＝**画像の権利が論点になるのは新規ASINを作るときだけ**
- フォーラム複数証言：「相乗りなど編集権のないカタログは画像アップロードが拒否される」／編集権の序列は **ブランド登録者 ＞ カタログ作成者 ＞ その他**

**実際に起きているのは**「カタログ側の画像への著作権申立てが、そのカタログに出品している全員の違反として計上される」現象。事例Aの投稿者は**画像を撮り直して差し替えたのに翌日ページごと削除**された。
→ **「画像を自分で撮る」はリスクの打ち手にならない。** 誤った減点緩和を戦略に渡すところだった。
→ 教訓：**「出品者が何を入力するのか」を公式手順で確認せずにリスク構造を語らない。** [[knowledge_verify_field_semantics_not_names]] と同型（画面で何が起きるかを確認せず、一般論から機序を組み立てた）。

## 🔴 セラーフォーラムから「ASIN 付きの実例」を取る歩留まりは1〜2割

本文を精読 **16スレッド中、ASIN 明記は 2件（12.5%）**。残りは伏字／記載なし／「メールには書いてあるがここには書かない」。
**推測（確度高）：** 自分の出品 ASIN を公開の場に書くと相乗り競合・通報の的になるため意図的に伏せている。

→ **次回同種の依頼では、この歩留まりを最初に宣言してから着手する。** 「実例を URL 付きで」という依頼は、フォーラムを情報源にする限り**成功率2割が上限**。社長には「特定できない」と書く準備をセットで持つ（[[feedback_list_quality_over_count]]：件数で埋めない）。
→ 検索のコツ：`知的財産権侵害 ASIN B0 削除 メーカー仕入れ 相乗り` のように **"B0" を入れた検索**が ASIN 記載スレッドを引き当てた。

## 🔴 ASIN が判明したら、その場で商品ページの生死を実測する

これが本調査で最も価値の高い1手だった。

| ASIN | 実測（2026-09-20） |
|---|---|
| B08XLT43GR / B08XLZKVGW | **HTTP 404「ページが見つかりません」＝カタログごと消滅**（ガラス角瓶・メーカー直仕入れ・相乗り） |
| B07LD9QH5L | HTTP 200・生存（ブシロード／スクエニ・**復活事例**）。ただし現在は出品者ゼロ |

**手順：** `curl -s -A "<Chrome UA>" -H "Accept-Language: ja-JP" -L https://www.amazon.co.jp/dp/<ASIN>` → `<title>` を見る。
**必須の対照実験：** 同時刻に**生存が分かっている ASIN を数件**同じ方法で叩き、HTTP 200 が返ることを確認する。これをやらないと 404 が「削除」なのか「アクセス遮断」なのか判別できない。今回は生存4件で 200 を確認したので 404 を削除と断定できた。

## Amazon 出品者ヘルプ本文は全経路ログインゲート（2026-09-20 実測）

`G200390640`（商品詳細ページの規則）等は次の4経路すべてで本文が取れない。
- `/help/hub/reference/external/<ID>?locale=ja-JP` → HTTP 200 だが JS SPA の外枠のみ（本文0件）
- `/gp/help/external/<ID>?language=ja_JP` → 同じ外枠
- `/help/hub/api/content/<ID>` → `/ap/signin` へリダイレクト
- `sellercentral.amazon.com`（米国）→ 同じく外枠のみ

→ **ヘルプIDが必要な依頼は、非ログインでは詰む。** 使える代替は2つ：
1. **`sell.amazon.co.jp`（Amazon公式・非ログインで本文取得可）** — 商品登録・料金・FBA の実務記述がある。今回の一次引用はすべてここ
2. **セラーフォーラムに転載された申請画面の原文**（Amazon 自社ドメイン。出品許可申請の4要件はこれで確定した）
→ **それでも足りないときは「カズヨがログイン状態で開けば5分」と書いて渡す。** 自分で詰まったまま推測で埋めない。[[feedback_legal_no_is_not_a_prefilter]] と同じ発想で、到達できない範囲を明示して社長／秘書の一手に変換する。

## 「相乗りできない＝売れない」への答え（5分類）

| # | 理由 | 開ける手段 | 見込み |
|---|---|---|---|
| A | 出品許可申請（ゲート） | メーカー/卸の請求書（180日以内・出品者の氏名住所・卸の氏名住所・**10点以上**）／ワンクリック解除 | **開く。**SD・NETSEA が有利 |
| B | 知財申立て・真贋調査 | LOA/LA/365日以内の請求書／権利者の取り下げ | 開くことがあるが少数 |
| C | **カタログごと削除（404）** | **手段なし** | 不可 |
| D | ブランド側の出品者制限 | 権利者から正規販売店の指名 | 権利者次第 |
| E | Amazon 本体が出品 | — | **これは相乗り不可ではない**（カート取得の問題） |

**E を A〜D と混ぜないこと。** 04 のサンリオ実測「月販100以上の97.7%に Amazon 本体」は E であり、出品自体はできる。**「相乗り不可」と「カートが取れない」は別の軸。**

## 知財申立ての実務事実（N=12・出典はすべて Amazon 自社ドメイン）

- **復活 2/12 = 16.7%。ただし確率の推定値として使えない**（フォーラムは「困った人」に偏る＝選択バイアス）。数字を出すなら必ずこの注記を付ける
- 効いた手段は**出品者の書類ではなく権利者を動かすこと**（ブシロード事例＝メーカーに直接連絡したら復活・出品者の追加操作なし）
- **メーカー直仕入れでも却下される**（ガラス瓶・キャラクター雑貨の版権証紙付き・真贋調査の卸請求書）。「メーカー直なら安全」は成り立たない
- **キャラクター商品に限らない**（ガラス瓶でカタログ消滅）。04 の「サンリオ ≫ グンゼ」というリスク差は、この事例により縮む
- 申立ての取り下げは**権利者が `notice-retraction@amazon.co.jp` に送る**か Amazon ブランド登録の撤回機能。**Amazon が受け入れるのは権利者が誤りを明確に述べた場合のみ**。取り下げも有効な申立てもなければ元の措置が残り、**報告された出品者は対象 ASIN を再出品できない**
- **メーカーの取り下げだけでは知財マークは消えない**（ベテラン回答者の明言）。正規卸の請求書で Amazon の承認を取る必要がある
- **商品を削除しても違反は 180日 アカウント健全性に残る**（Amazon 社員 Emi の回答）
- 却下されやすい仕入れルート：小売店・並行輸入は 4件すべて却下（「小売からの少量購入は正規仕入れと認められない典型例」）

## 加工品と素売りを混ぜない（サンリオ唯一の事例の読み方）

ハローキティのバルーンを**フラワーアレンジに組み込んだ**商品が削除された事例（ASIN 記載なし）。Amazon の回答は「メーカーへハローキティを入れたバルーンのアレンジメントを契約してください」＝**加工品としての別途ライセンス要求**。
→ **真正品の素売り（相乗り）とは別のリスク類型。**04 では区別せず「サンリオの知財リスク」に含めていた。**リメイク／アップサイクル／アレンジは商標権侵害の判例が多数**（同スレッド）。
→ **キャラクター商品の事例を集めるときは「素売り／加工／セット組み」を必ず1列取る。** 混ぜると当社に当てはまらない事例でリスクを過大評価する。

## 手順として再利用できること

1. 引用元スレッドを WebFetch で再読し、**ASIN/JAN/ブランドの記載有無を先に判定**（あれば §3、なければ「特定できない＋理由」）
2. ASIN があれば **curl で商品ページの生死を実測 ＋ 生存 ASIN で対照実験**
3. 追加事例は `sellercentral.amazon.co.jp` ドメイン限定の WebSearch（allowed_domains）で芋づるを取る。**"B0" を検索語に入れる**
4. 規約の一次は `sell.amazon.co.jp` を先に当たる（ヘルプ本文はログインゲート）
5. 事例表は **①ブランド ②求められた書類 ③結末 ④出典URL** の4列を固定。結末は「復活／停止継続・撤退／未決着」の3値で集計まで出す
6. 到達できなかった範囲（ヘルプID）は表にして「カズヨがログインで5分」と決着手順を添える

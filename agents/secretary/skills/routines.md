# スキル：定期ルーティン

社長を待たずにエージェントが回す定期作業の一覧。社長は **「夜寝てる間も会社が動いている」状態**を期待しているため、自律進行範囲を最大化する。

## 朝のルーティン（社長セッション開始時）

セッション開始フック（`.claude/hooks/session-start.sh`）と組み合わせて自動実行：

1. `workspace/handover.md` を読む（直前セッションの引き継ぎ）
2. `workspace/tickets/doing/` 配下の各チケットの `next_check_at` をチェック（フック処理済）
3. **`/sync-notion` で Notion カンバンを軽くリコンサイル**（マリエ実行。ブランチ分岐由来のドリフトをここで自己修復）
4. 夜間に進んだ仮想 PDCA・調査の差分を1〜2行で要約
5. 社長への切り出し：**「直近の論点はN件です。1) … 2) … 3) …。どれから返答しますか」**

## 夕方のルーティン（社長セッション終了時 or 日次まとめ）

- `done/` に動いたチケットの一覧を `workspace/handover.md` に反映
- **`/sync-notion` で当日のチケット変更が Notion に漏れなく反映されているか最終確認**（マリエ実行）
- 翌日に進められる作業を整理（夜間自走タスクの候補も含む）
- 必要なら `/handover` を実行して引き継ぎノートを更新

## 夜のルーティン（社長就寝中・自走モード）

社長の Do を必要としない作業を、サブエージェントが自走で進める時間帯。秘書は司令塔として以下を回す：

### 夜間に自走可能なタスク

| 作業 | 担当 | 備考 |
|------|------|------|
| 既存リサーチの深掘り（追加情報収集） | サトル | T-003 のツール個票作成など |
| 戦略案の仮想 PDCA 反復 | タケシ ⇄ マサル | 収束まで5周を目安に |
| ドラフト推敲・整形 | ヒデアキ | 翌朝社長レビュー用に磨く |
| メモリ整理・ファイル整理 | マリエ | 蓄積したログの整理 |
| 引き継ぎノート更新 | カズヨ | `workspace/handover.md` |

### 夜間に絶対やらないこと（社長承認が必要なため停止）

- CLAUDE.md §4.1 該当の操作（外部発信、課金、契約、不可逆削除、第三者連絡、機密外部送信）
- 戦略の **実 Do**（仕入れ・出品・広告・撤退の本番実行）
- Notion 等の外部 API への書き込みで、社長への確認を要する内容

### 夜間自走の起動方法

社長が就寝前に以下を秘書に伝えるだけで起動：

```
「今晩は T-003 と T-005 を進めておいて」
```

秘書は受領後、`/loop 30m /night-shift` のような形で（または手動で順次）以下を回す：

1. 担当エージェントへの作業指示書を `workspace/output/agent_output/<ticket_id>/night-instructions.md` に書き出し
2. 各エージェントが指示に従って自走（チケット本文と「現在地」を更新）
3. 朝までの成果物を `~/Documents/AI Company Outputs/Amazon物販事業/<ticket_id>/` に揃える
4. `workspace/handover.md` の「夜間進捗」セクションに要約を追記

## 週次ルーティン（毎週日曜夜 or 月曜朝）

- 直近1週間で完了したチケット（`done/`）の振り返り
- 滞留チケット（`doing/` のまま3日以上）の洗い出し
- マサルの仮想 PDCA 予測と実 Do 結果の差分メモ（キャリブレーション精度測定）
- 翌週の優先順位を A/B/C＋推奨で社長に提示

## 月次ルーティン（毎月1日）

- KPI チェック：月商・利益率・SKU 数の達成状況
- 撤退条件に近づいているチケットの再評価
- 各エージェントの `memory/` を見直し、ルーチン化候補を抽出
- プレースホルダー（事業ミッション・KPI）に変更が必要か確認

## ルーティン実行のログ

ルーティンが回るたびに `workspace/handover.md` の末尾に1行追記：

```
- 2026-05-20 朝ルーティン完了（要点：T-003 個票3件追加、T-005 はレビュー待ち継続）
```

## ルーティンが回らなかった時の作法

- フックが発火しなかった、`/loop` が止まっていた等の場合は、気づいた時点で `workspace/handover.md` に「ルーティン中断：原因＝◯◯」と記録
- 次回セッション開始時に秘書が「ルーティンが止まっていたので追いつきます」と社長に短く報告

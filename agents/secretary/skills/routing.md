# スキル：サブエージェントへの依頼分配

秘書が依頼内容に応じてどの担当に振るかを判断する手順です。

## ルーティング判断フロー

1. **依頼内容を1文で要約**（自分用に書き出す）
2. **キーワードマッチで一次判断**（下表）
3. **複数該当する場合は分解**して、それぞれの担当に並行発注
4. **どれにも該当しない場合**は秘書自身で受けるか、社長に確認

## 一次判断テーブル

| キーワード／領域 | 担当 |
|---------------|------|
| 商品リサーチ、市場調査、競合分析、ツール調査、業界ウォッチ、X/YouTube 動向、一次情報収集、比較表 | **リサーチャー** |
| 戦略、カテゴリ選定、SKU積み上げ、差別化、撤退条件、A/B/C＋推奨、勝ち筋設計、参入順序 | **プランナー** |
| 戦略案の仮想実行、シミュレーション、プレモーテム、3シナリオ予測、応手予測、撤退条件の磨き込み | **シミュレーター** |
| 金額、収支、予算、財務、税、コスト、ROI、利益、損益 | 経理 |
| 契約、利用規約、規約、法律、コンプライアンス、リスク、知財、商標 | 法務 |
| メール整理、ファイル整理、スケジュール、会議調整、情報整頓 | 庶務 |
| 文章、資料、台本、コピー、サムネ、編集、推敲、クオリティ | コンテンツ制作 |
| 上記に該当しない、または横断的 | 秘書（自分）が受けて分解 |

## 着手前の可視化（抱え込み防止）— 全領域に適用

どんな依頼も、**手を動かす前に1行で担当を宣言する**。秘書が「自分でやれるから」で即実行するのを構造的に止めるための鉄則（リサーチ・戦略だけでなく**全領域に適用**）。

- **宣言フォーマット:** 「この作業は〔担当〕です（理由: ◯◯領域のため）」
- 専門領域は必ずその担当に発注する。具体例：
  - 情報・ファイルの整頓、**社長タスクまとめ（owner-tasks.md / Notion まとめカード）の維持** → **マリエ（庶務）**
  - 社長向けマニュアル・手順書・説明資料 → **ヒデアキ（コンテンツ制作）**
  - 社内自動化スクリプト・フック・社長専用ツール → **タカシ（IT エンジニア）**
  - 収支・ROI・コスト試算 → ハジメ（経理） ／ 規約・リスク・知財 → ハルオ（法務）
- カズヨが自分で受けてよいのは **「横断的な統合・司令塔業務・社長への報告」** のみ。実務が専門領域に入るなら必ず振る。
- 「ついでにやっておきます」「簡単だから自分で」は**禁じ手**。
- 振った後はカズヨが成果を品質確認し、統合して社長へ報告する（窓口の一元化は維持）。

> 2026-05-27 社長フィードバック: 「まとめ」をマリエでなくカズヨが実施したのが気になる＝振り分けが徹底できていない、との指摘を受け本節を追加。今後は厳格・可視化徹底で運用する。

## 「調査」「戦略」「仮想実行」を必ず分ける

社長から「◯◯について調べて、どう動くか提案して」型の依頼が来た場合、**1チケットにまとめず3段で分割する**：

1. **リサーチチケット**（assignee: researcher）— 事実シート＋論点シートを納品
2. **戦略チケット**（assignee: planner）— リサーチの成果物を入力に A/B/C＋推奨を提示
3. **シミュレーションチケット**（assignee: simulator）— タケシの戦略案を仮想実行、3シナリオ＋プレモーテムを返す。タケシとの往復で収束まで反復

> 秘書が自分でリサーチや戦略を抱え込まないための鉄則。「ついでに調べておきます」「ざっくり戦略案でいいです」を禁じ手にする。
> 仮想 PDCA の運用詳細は [pdca-with-simulator.md](pdca-with-simulator.md) を参照。

## 単一担当ケース

1. 該当担当宛のチケットを起票（`assignee` を設定）
2. `todo → doing` で起動
3. 進捗を監視、完了したら `~/Documents/AI Company Outputs/Amazon物販事業/<ticket_id>/` を確認して社長に報告

## 複数担当ケース（横断案件）

例：「新商品を出すので、価格設定（経理）と利用規約改訂（法務）とLP制作（コンテンツ制作）を進めて」

1. 親チケットを秘書名義で起票（`assignee: secretary`）、本文に依頼全体を記載
2. 子チケットを各担当別に起票し、親チケットの「タスク分解」欄に子の ticket_id を列挙
3. 子を並行起動
4. すべての子が `done` になったら親を `done` に
5. 統合した最終報告を社長へ

## 担当判断に迷った時

- **30秒考えて決まらなければ自分で受ける**。受けた上で分解してから再ルーティングする
- どうしても分解できない＝社長の意図が曖昧なら、`waiting/` に出して選択肢付きで聴く

## サブエージェント起動の手順

1. チケットを `tickets/doing/` に移動
2. 担当エージェントの `agent.md` と関連スキルを参照
3. 担当エージェントに作業を委譲（Claude Code のサブエージェント機能を使う想定。詳細運用は Phase 5 で確定）
4. 成果物は担当が `workspace/output/agent_output/<ticket_id>/` に保存（リポ内・worktree 単位）
5. 秘書が品質確認した上で `~/Documents/AI Company Outputs/Amazon物販事業/<ticket_id>/` に移し、社長報告（リポ外・全 worktree から見える場所）

# 時刻つきの期限は next_check_at だけでは守れない

記録: カズヨ / 2026-09-11 / T-20260909-001

## 何が起きたか
社長指示「カナダの期限は 9/10。期限が過ぎたらリマインドして」。`next_check_at: 2026-09-10` を設定して「取りこぼしません」と約束した。
**9/10 はセッションが1度も立たず**、リマインドは 9/11 朝、社長が別件（US の休眠通知）で話しかけてきたときに初めて出た。社長から催促されたわけではないが、約束は守れていない。

## なぜ
`next_check_at` は **SessionStart フックでしか評価されない**。社長がセッションを開かない日は何も起きない。「日付」の管理はできても「時刻」の約束は守れない。

## 次から
- 社長が**時刻つきの期限＋リマインド**を指示したら、`next_check_at` に加えて**予約通知を併設**する（scheduled-tasks / CronCreate 等、セッション外で発火するもの）。
- 併設できない場合は「フックはセッションを開いた時にしか出ません」と**約束の範囲を正直に言う**。「取りこぼしません」とは言わない。
- 期限を過ぎて初めて気づいたら、報告の冒頭で「リマインドが1日遅れた」と1行で認める。長く謝らない。

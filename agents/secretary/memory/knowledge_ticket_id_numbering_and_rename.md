# チケットIDの採番と、採り直しのときの落とし穴

2026-09-06 に2つ続けてやらかしたので手順として残す。

## 1. 遡及起票が連番を飛ばす

同じ日に「あとから遡って起票して done に入れる」チケット（法務判定の記録など）を作ると、
`doing/` `todo/` `waiting/` だけを見て採番したときに **その番号が既に done で使われている**。

- 2026-09-06 の実例：`T-20260906-004` が done の法務チケット（NETSEA URL公開可否）と衝突
- **Notion 側は TicketID が同期キー**なので、重複カードができると機械的に更新先を決められず、
  非破壊原則のため自動削除もできない。**作った瞬間に人手でしか直せない負債になる**（マリエの判定）

**手順：起票前に必ず全ステートを串刺しで引く。**

```bash
ls workspace/tickets/*/T-YYYYMMDD-*.md
```

`doing/` だけを見て採番しない。done/ を含めた最大連番の次を取る。

## 2. 採り直しの一括 sed が「ログの過去記述」を壊す

ID を振り直すとき `sed -i '' 's/OLD/NEW/g'` を全文に当てると、
**`## ログ` に書いた当時の事実まで書き換わる**。

- 実例：「重複していた相手＝`done/T-20260906-004_netsea-url-publishability.md`」という履歴が
  `done/T-20260906-006_netsea-url-publishability.md` という**実在しないパス**に化けた（マリエが復元）
- あわせて `owner-tasks.md` には**同じ番号が別チケットの生きた参照としても**登場していた。
  全置換すると、そちらまで巻き込む

**手順：置換対象は frontmatter と「本文中の参照」だけ。`## ログ` 以降は手で判断する。**
置換後は `grep -n` で残存を数え、**残った箇所がどれを指しているか1件ずつ目で確かめる**。

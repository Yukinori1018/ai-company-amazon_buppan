## 手順の型（次回も同じ順でやる）
1. **キューの数字を信用せず Keepa を1件取り直す**（stats=365・history=1・offers=20・buybox=1 で6トークン）。10/11 キューは出品者17・中央値4,322 → 実際は9・時間加重4,209。1日で変わる
2. **90日中央値は時間加重で取る**。値を付け替えた時点ごとの中央値は、頻繁に改定する出品者の価格に引っ張られて高く出る（今回 +113円 → B 上限が4ポイント違った）
3. **本体の扱いは「在庫率」と「カート保有率」を分ける**。本体が在庫90日切れなしでも、高値なら第三者にカートが回る。カート履歴を月別に集計（buyBoxSellerIdHistory、Amazon=AN1VRQENFRJN5）。本体の値下げの兆し（数時間おきの価格の上下）は撤退条件の材料
4. **monthlySoldHistory で季節を見る**。回転の速い商品はキーゾン式（ランク改善回数）が月13〜18で頭打ちになり使えない
5. 単位採算は `fba_cost.other_costs` を使う。大きい箱（1箱8個）だと代行＋送料＋保管で230円/個
6. 日次で在庫・入金（販売＋18日）・おりおん請求（翌15日）を回し、週次スナップショットを HTML の水槽図に渡す
7. 公開基準（T-20260920-003 08）：Keepa の履歴値は**表にしない・文章で・出典と取得日**（5件以下）。source-terms-guard は「卸値」「上代」「最小ロット」の後15字以内の数字に反応する（率でも反応）。卸率の定義は数字の無い1文で先に書き、本文では「上代」を使わない。HTML は表の行ごとに改行しないと前の表のラベルを拾って誤検知する。**フックは Bash 書き込みでは走らないので、自分で scan() を回して確認する**

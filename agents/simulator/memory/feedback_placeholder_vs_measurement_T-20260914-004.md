# 置き値が実測で外れた例 — 卸の母数と成立率（T-20260914-004・2026-09-14）

統合報告 v2 の推奨（案B 62%・中央+6万）を、タカシ T-2（卸照合）とサトル S-1（上位60社）の実測で出し直した記録。

## 1. 何が外れたか

| 置き値 | v2 | 実測後 | 落ち幅（案B・実質現金） |
|---|---|---|---:|
| 卸の母数（12ヶ月で立つ卸 SKU） | 中央3・P90 11（w_pool 4.0/σ0.9） | 中央1〜2・P90 5（2.0/σ0.7）。NETSEA 需要先行 同一品15→全条件0 | −9pt（62→53%） |
| 送れる母数 | 900社 | A のみ約375社（上位60で A 25社・42%） | ±0 |
| メーカー成立率（1通） | 1.5/3/5% 平均3.05%（EC STARs 二次情報） | A 25社中19社が Amazon ブランドストア保有＝自社出品。0.8/1.5/2.5% 平均1.54%と置き直し（推測） | −22pt（53→31%） |
| 結果 | 案A/B/C 51/62/67% | 22/32/42%（S-1 主）・中央は3案ともマイナス | |

## 2. 学び（次から）

- **二次情報の成立率は「どの母集団のメーカーか」を先に照合する。** EC STARs の3%は「Amazon にいない／使いこなせていないメーカー」。需要先行（Keepa 起点）で集めた母集団は、定義上 Amazon で売れている＝ブランド保有者の自社出品が主になる。本丸（ネット販売に疎い中小メーカー）は Keepa 起点では届かない（社長 memory の原則）と同じ構造。**需要先行リストで打診母数を作った瞬間に、成立率の置き値を下げるべきだった。**
- **感応度上位の置き値は、実測が来る前に「何の実測で壊れるか」を書いておく。** v2 では「卸の母数」を感応度3位と書いたが、実際に効いたのは成立率（1位）の母集団のずれで、T-2 より S-1 の方が大きかった。
- **依頼文の数字と、モデルの実際の置き値を最初に照合する。** 依頼は「中央6・悲観2・楽観15」だったが、62%を出したモデルは中央4だった（6はタケシ1周目）。コードの MASARU 辞書から読む。
- **同じ乱数で旧を再現してから差し替える**（62%を再現＝構造差ゼロを確認してから置き値だけ動かす）。分解表（1つずつ足す）で落ち幅の出所を示す。
- **送れる母数は12ヶ月の P を動かさない**（375でも900でも同じ）。効く送信は窓の最初の5ヶ月（週20で約330通）。ただし A が上位60で25社しか無い＝週20を続けるには毎週約50社の深掘りが要る。これは確率でなく段取りの制約として別に書く。
- **並列担当の納品が途中で着いたら、別スクリプト（03_mc_S1反映.py）で足す。** 本計算を止めずに回せた。親の置き値辞書を import して上書きするだけにする。

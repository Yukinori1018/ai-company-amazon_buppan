# 戦略案（仕入れ経路）を読むときの型 — T-20260912-001 / 2026-09-12

タケシの「1周目の経路 A/B」叩き台を仮想実行した記録。タケシ 58% → マサル 約11%。以後、経路・チャネル系の案はこの順で読む。

## 1. 見落としやすい穴（今回、全部叩き台にあった）

| 穴 | 今回の実例 | 確かめ方 |
|---|---|---|
| **案が自分で定めた足切りを、自分の候補に当てていない** | 「生き残り12件」は取り分の足切り前の数字。当てると3件、S3の親子判定後は0件 | 叩き台の足切り値を `out/` の既存データにそのまま当てる（1分で済む） |
| **バリエーション兄弟の二重計上** | 足切りに残った3件は全部バリエーションの子（タカシ S3 で確定）。信用できる候補は0件になった | 親子判定は Keepa product API（offers なし）1 token/件で安い。足切りの前に必ず取る。子のドロップ数は兄弟合計の上限として扱う |
| **確率表と日程表が噛み合っていない** | 日程表を足すと9週超なのに「9週以内44%」 | 各段の最短/中央/最長を置いてモンテカルロ（`deliverables/T-20260909-002/06_mc_所要日数.py` を流用可） |
| **独立でない2案を 1−(1−a)(1−b) で合成** | アカウントの支払い保留・大口切替・納品代行・社長の手を共有 | 共有資源を列挙してから合成。アカウント事故は全案同時に止める |
| **祝日** | 9/19〜23の5連休でメーカー返信とAmazon審査が止まる | 期間内のカレンダーを必ず見る |
| **小口では申請ボタンが無い可能性** | 出品許可申請は大口前提（二次情報）→ 切り替えが発注の前に来る。切り替えは本人確認の再開リスク | 申請画面の実機確認を入口審査に入れる |

## 5. 並行発注の作法（今回の反省）

作業中にタカシの S3 がチケットに届き、私の読み（候補は実質1ブランド）が「0件」に変わった。**commit の前にチケットを読み直し、並行担当の結果を取り込んでから出す。** 事実待ちの項目は「確定したら何が変わるか」まで書いておくと、差し替えが数行で済む（今回は置換9か所で済んだ）。

## 6. 2周目（改訂版 B一本・10社3波）で見つけた穴 — 2026-09-12

タケシ改訂版の見立ては、1社以上成立40%・12/31までの入金34%。補正すると24%・20%になった。**判定は軽微な差し戻し**（4点が直れば社長に上げてよい）。

| 穴 | 実例 | 次から |
|---|---|---|
| **2周目でも「自分の足切りを自分の候補に当てていない」が再発** | 「買う」足切り（子の値は根拠にしない）を10社に当てると、区分3の5社は通る ASIN が0件になる。それでも MC はこの5社に成立率4%ずつを置いていた | 1周目と同じ確認を毎周やる。社別集計ではなく ASIN 別 CSV で「単体か／公表値があるか」を数える（1分） |
| 公開ロットと閾値の衝突 | 朝倉は最小ロット20個〜 → 閾値は11.1 → 通る ASIN は0件 | ロットが公開されている社は、閾値＝ロット÷1.8で先に当てる |
| 「10通で p を測る」は測れない | p=2%でも8%でも成立0は普通に起きる（P(0)=82%／43%） | 少数の標本では、分母が大きい中間指標（返信率・見積もり到達率・断られた理由）を KPI にする |
| 期限を「目標」と書くと、中央シナリオが失敗扱いになる | 12/31の入金は、p×2でも36%。社長の「早く成果物」「完走して学ぶ」と噛み合わない | テストを二段に分けて伝える（開拓テスト＝10/16に90%／販売の一周＝12月に20%）。承認前に社長へ明示してもらう |
| 他チケットの社長決定を「未確定」と書いている | SD は9/2に結果が出ていて、社長決定済み（T-20260904-005）。改訂版は「審査結果待ち」と書いていた | 関連チケットの frontmatter（decision・blocked_by・due_date）を読む。期限は §4.1 の週別表に入れる |
| 論点表にありえない案が並ぶ | 0%の選択肢1つと、ルール違反の選択肢2つ | 社長に上げる前に、論点表の各選択肢を社長ルールに1行ずつ当てる |

**書面での確約について（カズヨの問い）**: 本当の関門は確約ではない（取引に応じた社なら80%は答える）。関門は、ゲートがあるブランドのメーカーが Amazon での販売を認めるかどうか。ゲート＝メーカー自身がブランド登録で出品を絞っている可能性がある。

**「早い経路は無いか」と聞かれたときの型**: 経路ごとに「事実 → 早めるか」の表を作る。ルールを動かす案は並べず、「ルールの中では無い（確度◯%）」と言い切る。そのうえで、テストの目的の方を分解して見せる。

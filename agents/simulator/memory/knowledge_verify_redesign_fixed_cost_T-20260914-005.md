# 再設計の検証の型 — 母集団の照合・固定費の感応度・判定期間の緩和（T-20260914-005・2026-09-14）

タケシ再設計（打診先を P2＝Amazon にいるがブランド未登録のメーカーへ。推奨 案B＋Keepa API→Pro 50%・中央±0）を検証した記録。

## 1. 手順（次回も流用）

1. 相手のコードをそのまま再実行して公表値を確認（今回 50.1%／+56円）→ 自分の構造で作り直す（差し込みを別の作りにする：母集団は成立社に付与・主系列を消費しない別乱数）。差し込みの無い案は元の乱数列と完全一致することを先に確かめる
2. コードと本文の食い違いを探す（今回: コードの母数450 ≠ 本文の供給300）。本文の運用（P2 を先に送り切る）を seq モードで別に回す
3. 出典の抽出条件を、自分たちの抽出条件と表で並べる（下の §2）
4. 固定費は項目ごと・契約月ごとの月別リストで持つ。「失う機能」をモデルの変数（母数・読みのばらつき）に翻訳して、費用の差と並べる
5. 判定期間の緩和は「同じ地平（T=18）で停止月だけ違う2計画」を同じ乱数で比べる。T を変えると乱数の消費がずれて比較にならない

## 2. 学び

- **出典の母集団の照合は「定義の言葉」でなく「抽出条件」で並べる。** EC STARs の3%は「本体なし・ランク5万位以内・FBA ライバル2人以上」。T-1 もほぼ同じ条件で抽出し、25社中19社がブランドストア持ちだった。「ライバル2人以上＝メーカーが棚を握っていない」は S-1 の実測で否定されている。**言葉の上で一致して見える母集団ほど、抽出条件を並べ直す。**
- **固定費を下げると、累計損益の撤退線は効かなくなる。** E-2「2027-03 累計損益 −8万未満」は固定費15,253円なら6ヶ月で9.2万＝レーンが0でも踏む線だった。Pro に下げると6ヶ月で7.7万＝ほぼ踏めない。固定費を動かす提案が来たら、累計損益の撤退線を必ず較正し直す
- **契約の支払い済み期間を先に見る。** Keepa API は毎月4日更新。T-3・S-3 は 10/3 までの支払い済み期間に収まる＝10/4 に解約しても抽出は何も失わない。「いつから切り替えるか」は請求日から逆算する
- **乱数の消費順は共通乱数（CRN）を壊す。** 卸の SKU（年2に到着）がメーカーの SKU より前にリストにあり、18ヶ月計画だけで乱数を消費 → 月1〜9 の一致率が90%に落ちた。構造上の同一性と乱数の一致は分けて書く
- 秘書が請求書で事実を確定させた（Keepa は API €49 のみ）。**「未確認」を P の分岐（−15pt）で書いた論点は、事実確認1本で消える。**計算より先に事実確認を秘書に依頼する方が安い
